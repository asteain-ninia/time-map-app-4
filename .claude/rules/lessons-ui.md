# 画面と入力の教訓

番号は変えない。コードや文書が「開発ガイド §5.N」として参照している。

### 5.2 一時的 UI 状態は全経路で破棄する
- 正しい道: 描画プレビュー・選択中の値・ドラフト設定は、開始・確定・キャンセル・ツール切替・モード切替のすべての経路で明示的に破棄する。
- 誤った道の兆候: 破棄がキャンセル経路にしか書かれていない。前回の操作の値が次の操作の初期値に見える。残ると意図しない値で確定できてしまう。
- 確かめ方: `e2e/regression.spec.ts`（選択→キャンセル→再作成 でドラフト値が引き継がれない）、`src/domain/add/session.test.ts`（`resetSession`）、`src/domain/editing/drag-session.test.ts`。

### 5.3 操作対象は表示状態に限定する
- 正しい道: 操作の対象は現在 UI 上に表示されている要素に限定し、表示状態（リアクティブ派生状態）を基準にする。
- 誤った道の兆候: 候補や検索がプロジェクトのデータ全体を直接走査している。描画で間引いた地物が検索や候補にだけ残っている。
- 確かめ方: `src/ui/discovery/search.test.ts`、`src/ui/discovery/visibility.test.ts`（`resolveVisible`）、`src/ui/map/committed-features.test.ts`、`src/domain/add/parent-candidates.test.ts`。

### 5.4 追加・編集・複製・結合は現在の UI 文脈を第一候補にする
- 正しい道: 対象は現在の UI 文脈（フォーカス中対象・選択中対象・現在時刻・表示中要素）を第一候補にする。コレクションの先頭要素や固定デフォルトは UI 文脈が存在しない場合だけ使う。
- 誤った道の兆候: 文脈が解決できないときに黙って先頭要素や固定値へ落ちる。解決できないなら「対象なし」にする。
- 確かめ方: `src/domain/context-menu/compose.test.ts`（既定へ落ちない）、`src/domain/deletion/deletion.test.ts`（`resolveDeleteTarget`）、`src/ui/property/DeleteFeatureButton.test.tsx`。

### 5.5 依存する状態は変化時に再検証する
- 正しい道: ある状態が変化したら、依存する他の状態も検証・更新する（例: 時間が変わったら選択中要素がその時間に存在するか検証し、なければ選択を解除する）。暗黙的ルールはコードで明示的にチェックする。
- 誤った道の兆候: 時刻や表示の変更後、選択・親候補・深度の起点が消えた要素を指したまま残っている。「ふつうはそうならない」で済ませている。
- 確かめ方: `src/domain/selection/reresolve.test.ts`（`revalidateForTime` / `revalidateForDisplay`）、`src/domain/add/session.test.ts`（`revalidateParent`）、`src/domain/display/depth-focus.test.ts`。

### 5.7 完了トリガーを必ず実装する
- 正しい道: UI のフロー（開始・途中操作・完了/キャンセル）では必ず「完了」のトリガーを定義・実装し、UI から実際に呼ばれるところまで結線する。
- 誤った道の兆候: ロジック側にメソッドと単体テストがあるのに、呼び出す UI が無い（「誰も渡していない」結線漏れ）。単体テストだけが緑で、実際の操作では何も起きない。
- 確かめ方: `src/ui/shell/view-only-gate.test.tsx`（結線漏れの表）、`src/ui/map/redraw-watch.test.ts`、実操作の `e2e/context-menu.spec.ts`・`e2e/detail-document.spec.ts`・`e2e/depth-control.spec.ts`。

### 5.8 押下→移動→解放シーケンスを全パスで保証する
- 正しい道: 押下 → 移動 → 解放は全パス（クリック・ドラッグ）で状態が正しく開始・更新・終了することを保証し、押下で設定した状態は解放で必ず解除する。
- 誤った道の兆候: 移動ハンドラの中でだけ後始末や確定をしている（移動が発生しないクリックで漏れる）。押下時の準備だけで選択置換を判断している。
- 確かめ方: `src/domain/editing/drag-session.test.ts`、`src/domain/selection/reducer.test.ts`（移動なしで置換）、`src/ui/map/PointerDispatcher.test.ts`、`e2e/flows.spec.ts`。

### 5.9 排他分岐が重要処理をスキップしていないか確認する
- 正しい道: 排他的な条件分岐が他の重要な処理をスキップさせていないか確認し、選択優先順位と、同時選択/排他選択を明確に定義する。
- 誤った道の兆候: `if / else if` の早い枝に入ると、選択解除やカメラ操作の転送など別の処理まで飛ばされる。
- 確かめ方: `src/domain/selection/reducer.test.ts`（`HIT_KIND.Edge` の枝）、`src/ui/map/dispatch.test.ts`（条件の組み合わせ）、`src/ui/add/add-camera-passthrough.test.tsx`（転送が道具の入力を奪わない）。

### 5.10 選択状態は生の集合まで評価して網羅する
- 正しい道: 複数の選択状態（単一・複数・不明・空）を扱う UI では、生の ID セットをすべて評価して分岐を網羅し、仕様メッセージと表示条件を一対一で対応付ける。
- 誤った道の兆候: 派生済みヘルパーの結果だけで分岐している。持ち主の分からない ID が混ざった集合が「単一」に見える（例: `A-v0` と持ち主なしの `X-v9`）。
- 確かめ方: `src/domain/selection/context.test.ts`、`src/domain/selection/context.property.test.ts`（生の集合から独立に正解を計算）、`src/ui/property/selection-display.test.ts`。

### 5.11 構造変更操作後の選択は結果から再解決する
- 正しい道: 結合・分割・移動・削除の完了後の選択は、コマンド結果（`CommandResult` の `survived` / `created` / `deleted`）から再解決する（`reresolveAfterStructureChange`）。
- 誤った道の兆候: 構造変更の後に選択を固定で全クリアしている。次に調整すべき対象が残る操作で、選択し直しが必要になっている。
- 確かめ方: `src/domain/selection/reresolve.test.ts`、選択維持の回帰は `e2e/context-menu.spec.ts`。

### 5.12 判断用メッセージを無関係な操作で消さない
- 正しい道: 検証拒否・保存失敗など次の判断に使うメッセージを消す契機は、「同種操作の再試行」「明示的な閉じる」「成功した置換操作」など意味を持つイベントに限定する（`mayDismiss`）。
- 誤った道の兆候: 発生元と無関係なクリックやマウス操作で消している。拒否の理由をそもそも表示せず黙って何もしない。
- 確かめ方: `src/ui/discovery/errors.test.ts`（`mayDismiss`）、`src/ui/add/useAddTool.test.tsx`、`src/ui/file-ops/save-status.test.tsx`、`src/domain/context-menu/messages.test.ts`。

### 5.13 表示専用モードでは編集経路を一括無効化する
- 正しい道: 編集 UI・編集メニュー項目・編集ショートカット・右クリックを 1 つの権限判定で一括無効化する（`src/ui/shell/permissions.ts` の `canEdit`）。入口を開けたまま中身の一部だけ塞ぐ経路も、同じ `canEdit` を受け取る。
- 誤った道の兆候: 部品ごとに表示専用の個別判定を書いている。見た目だけ非表示で、ショートカットや右クリック操作が残っている。
- 確かめ方: `src/ui/shell/view-only-gate.test.tsx`、`e2e/flows.spec.ts`（鍵が閉じているあいだ道具は 1 つ残らず押せない）。

### 5.14 重なる UI は入力を受ける層も同時に設計する
- 正しい道: オーバーレイ・バックドロップ・ハンドル・モーダルは、描画順だけでなく入力を受ける層も同時に設計する。
- 誤った道の兆候: 透明な背景層が操作ハンドルや地図を覆っている。見た目は正しいのに操作が奪われる。閉じ忘れた背面の板が以後のクリックを全部奪う。
- 確かめ方: 重なった状態で背面/前面の期待操作が通ることを見る。`e2e/add-knife-camera.spec.ts`、`e2e/edit-select.spec.ts`、`e2e/regression.spec.ts`、`src/render/edit-handles-layer.test.ts`。

### 5.16 時間値は完全値で受け渡し、倍率の二重適用を防ぐ
- 正しい道: 年・月・日を分解した一部の値でなく完全な時間値を下位層へ渡す。再生速度は `playback.ts` の 1 か所で 1 tick あたりの日数へ変換し、`PLAYBACK_TICK_MS` は固定する。
- 誤った道の兆候: 速度倍率が「間隔」と「進行量」の両方に掛かっている。経度シフトのようなズーム依存の量で、部品と結線の両方がズームを掛けている。
- 確かめ方: `src/ui/timeline/playback.test.ts`（倍率の適用が 1 回）、`src/domain/basemap/longitude-shift.test.ts`、`src/ui/map/LongitudeShiftControl.test.tsx`。

### 5.24 確定ハンドラには no-op ガードを入れる
- 正しい道: blur/Enter のように値が変わらなくても発火する確定ハンドラを undo 履歴付きコマンドへ載せるときは、確定値が現在状態（baseline）と一致するなら実行しない。baseline はフォーム同期と同一ソースから導出する。
- 誤った道の兆候: 何も変えていないのに undo の項目が増える（幽霊 undo エントリ）。空文字と未設定のように、比較の前に形を揃えていない（`detail-document.ts` は書き込み時と同じ空の形で比較する）。
- 確かめ方: `src/domain/command/history.test.ts`、`src/domain/__bughunt__/time-anchor-history-undo-redo.property.test.ts`、`e2e/anchor-edit-time.spec.ts`（値が同じなら保存ボタンが押せない）。

### 5.34 コンポーネント間データ受け渡しは契約を型で明示する
- 正しい道: モジュール間の受け渡しはプロパティ名・型・構造を型定義で明示する。データ構造の全有効状態の組み合わせを描画・シリアライズ・操作の全箇所で網羅する。仕様から削除した属性は UI → 状態管理 → 永続化 → 描画の順にすべて除去する。
- 誤った道の兆候: 条件分岐を排他で書いていて、組み合わせの状態が抜ける。削除した属性が永続化や描画に残っている。
- 確かめ方: `src/domain/selection/contracts.test.ts`、`src/domain/affiliation/adapter.test.ts`、`src/domain/type-guarantees.test-d.ts`、`npm run typecheck`。属性の除去は全文検索で確かめる。

### 5.35 共有リソース更新は全依存先へ通知する
- 正しい道: 共有リソースを更新したら依存する全コンポーネントに変更を通知する（購読の一覧を保つ）。リアクティブ状態やコンテキストは、内部データが常に最新とは限らない前提で設計する。
- 誤った道の兆候: 値は変わったのに画面が古いまま。Canvas の再描画購読（WATCH 集合）に新しい状態が入っていない。
- 確かめ方: `src/ui/map/redraw-watch.test.ts`、`src/ui/discovery/log.test.ts`（診断画面がロガーを購読）、`e2e/grid-toggle.spec.ts`。

### 5.50 CSS グリッドの `1fr` は「その行のいちばん長い中身」で広がる — 窓幅に収めたい列は `minmax(0, 1fr)` にする
- 正しい道: 窓幅に収めたい列は `minmax(0, 1fr)` にし、その列の grid item に `min-width: 0` を付ける。flex item も同じく `min-width: 0` を付ける。
- 誤った道の兆候: `grid-template-columns: 1fr` のまま、折り返さない長い文字が入る行がある（オプションバーの「次の一手」に長い拒否理由を入れただけで地図セルが 940px → 2,254px、上端 y が 121 → 72 へ動いた）。行に `overflow: hidden` を書いて済ませている（中身の min-content は外へ効き続ける）。空の状態でしか測っていない。
- 確かめ方: `src/ui/shell/shell-layout.test.ts`「列は minmax(0, 1fr)」「主行の中央列は minmax(0, 1fr)」。E2E は `e2e/option-bar.spec.ts`（中身がいちばん長い状態を作って、動いてほしくない要素の矩形を比べる）。

### 5.51 「人が読める名前」と称するフィールドが、実際には内部識別子と混ざっていることがある
- 正しい道: 画面に出す前に、そのフィールドを埋める全呼び出し元の実値を列挙する（型やコメントでなく値を見る。`MERGE_COMMAND_LABEL` のような定数経由も追う）。混在していたら出さないか、出口 1 か所で写像し、表に無い値は粗い日本語へ落とす（`src/ui/shell/command-result.ts` の `commandLabelJa`、既定は「編集」）。
- 誤った道の兆候: コメントの「Human-meaningful label」を根拠に画面へ出す（実機に「元に戻せます: edit」と出た）。「全呼び出し元を列挙した」と書きながら検索結果を貼っただけ。写像表を守るテストが手書きの一覧（経路が増えても緑のまま）。直書き検査が `label:` の属性だけを見ている（実際に出ていた値は `createCompositeCommand('edit', […])` の第 1 引数だった）。全件が日本語になることしか見ていない（全部同じ日本語でも緑）。1 種類の操作だけ試して「大丈夫」と判断する。
- 確かめ方: `src/ui/shell/command-result.test.ts`。ソースの定数（`UI_COMMAND_LABEL` とドメインの各定数）を流し込む検査、属性と引数の両方を走査する直書き検査、「確定経路ごとに違う日本語になる」の 3 つ。実アプリで複数種類の操作の表示を見る。

### 5.53 「下書きが汚れている」は、種との差だけでは判定できない
- 正しい道: 「汚れているか」は種との差で判定し、例外は「自分がいま保存した」という出来事ちょうど 1 つにする（保存に成功した値を覚えておき、それと一致するときだけ黙って追従する）。「対象が変わった」と「中身だけが変わった」を別の枝に分け、前者だけ確認を出す。取り消しでドメインが巻き戻るのは黙って追従する。
- 誤った道の兆候: 種との差だけで判定している（保存が編集対象の同一性を変えると、自分で保存した直後に「入力中の内容が失われます」と聞かれる。ここでは保存で錨が 1 本増え、編集対象は地物×錨×年）。「種とも、いまの確定済みの姿とも違う」という値の比較で直している（この直し方は別の壊れ方をした: 0 年で `A → B` と打ち、移動先の確定値がたまたま `B` だと、確認なしで保存の意図が消える）。
- 確かめ方: `src/ui/property/PropertyPanel.tsx` の `dirty` と `savedValues`、`src/ui/property/PropertyPanel.test.tsx`「(b) 移動先の確定値がたまたま打ちかけと同じでも、意図は黙って消えない」。E2E は `e2e/anchor-edit-time.spec.ts`（単体の偽物は錨を増やさないので通り抜ける）。

### 5.56 `hidden` 属性は、クラスで `display` を書いた瞬間に効かなくなる
- 正しい道: クラスで `display` を書く要素には、同じファイルに `.foo[hidden] { display: none }` を併記する。または条件付きで描かない（`{open && <div…>}`）。位置の計算（`getBoundingClientRect`）を保ちたいときは前者。
- 誤った道の兆候: 閉じているはずの部品が下のボタンのクリックを奪う（`position: fixed` だと座標が決まる前は画面の左上 0,0 に居座り、見た目で気づきにくい。E2E に「`snap-options__row` がポインタを横取りしている」と出た）。`visibility`／`opacity` で隠して `pointer-events` を切っていない（§5.14 の別の顔）。
- 確かめ方: `src/ui/shell/shell-layout.test.ts`（`.option-bar__overflow-panel[hidden]`、`.rail__popover[hidden]`）、`e2e/inc5-shell.spec.ts` の `scanMapGrid`（地図セルの 5×5 走査を開閉の両方に掛ける K-2）、`src/ui/discovery/DisplayOptions.test.tsx`。新しい部品を足したら閉じた状態の走査へ加える。単体はレイアウトを持たないので重なりを再現できない（§5.49）。

### 5.58 「同じものが既に載っていればその場で差し替える」分岐は、後片付けが先に走るので通らない
- 正しい道: 一時的な登録の器では、並び順の鍵を器が持つ。鍵が初めて来たときに順序番号を配り、取り外しでは番号を捨てず、公開するときに必ずその順で並べ、器を畳むとき（道具を降りるなど）に番号も捨てる。枠ごとに「後片付けと再登録のどちらが先か」を確かめる。
- 誤った道の兆候: 「同じ鍵があればその場で、無ければ末尾へ」と書いている（React の effect のように古い後片付けが先に走る枠では、その場で差し替える枝が死んでいる）。中身を更新するたびに部品が左右に飛ぶ。「同じ鍵で登録し直す」だけの検査（実装を壊しても緑）。
- 確かめ方: `src/ui/shell/option-bar.ts` の `slotOrder`／`nextSlotOrder`、`src/ui/shell/option-bar.test.ts`（外す → 入れ直す、の順で書いた検査）。

### 5.61 下端に固定した部品は、器が低いと上の中身を覆う（`position: sticky` の裏面）
- 正しい道: 「見出し／本文／保存列」を重ねず縦 flex に並べる。入れ物は `height: 100%` の縦 flex、見出しと保存列は `flex: 0 0 auto`、本文だけ `flex: 1 1 auto; overflow-y: auto`。本文に操作部品 1 つぶんの `min-height`（`.property-panel__body` は 28px）を持たせ、外側の器は `overflow-y: auto` のまま残す（3 段の合計が器を超える窓の受け皿）。
- 誤った道の兆候: `position: sticky` で重ねたまま器の下限を決めて凌ぐ（固定部品の高さが中身で変わる限り必ず破れた。錨の無い年は保存列が 103px に育ち、1280×800 で帯 20px、1366×768 で帯 3px、26px の名前欄がどのスクロール位置でも押せなかった。0 年は帯 58px で検査をすり抜けた）。「行が見える」下限を「押せる」下限と取り違える。器に `padding-bottom` を足す（sticky は余白の内側に貼り付き、帯が 25px → 5px へ狭まった）。`scroll-padding-bottom` を足す（`scrollIntoView({ block: 'center' })` の真ん中が上の見出しの中へずれる）。可変の行を 1 行に固定して済ませる（保存列で守れなかった）。重ねるのをやめただけで本文の下限が無い（覆われないのに本文 0px、器 178px＝見出し 55＋保存列 103＋すき間 24）。`force: true` で押して済ませる。
- 確かめ方: `src/ui/property/property-layout.test.ts`（3 段の flex、重ねない、`::after` の遊びが無い）、`e2e/inc4-ledger.spec.ts`「錨の無い年で保存列が育っても、名前欄は本文の中に出て押せる」（1280×800 / 1366×768 / 800×600）。固定部品がいちばん育つ状態・いちばん低い器で `elementFromPoint` が自分を返すかと、本文の取り分を測る。重ねる作りが残る所を押すときは `e2e/helpers.ts` の `clickClearOfStickyBars`（前面に出るまで動かし、出なければ実測値を添えて落とす）。

### 5.67 共通の既定を反転したら、その既定の **副作用**に寄りかかっていた側を全部探す
- 正しい道: 既定を変えるときは、その関数の JSDoc とコメントを全文検索し、「〜も一緒にやる」「〜を兼ねる」「subsumes」「ついでに」のような言葉で寄りかかっている側を探す。寄りかかっていた側に自分で書かせ、副作用へ戻さない。書かせる中身は「自分が触ったものだけ戻す」にする（道具の取りやめは `unpromoteOwnTarget` で自分が昇格させた対象だけを元の選択へ戻す）。
- 誤った道の兆候: 既定の反転で 1 本だけ落ちたテストを「古いから直す」で片付ける（仕様の更新か寄りかかりの露出かを 1 本ずつ分ける。3 本が仕様の更新、1 本が寄りかかりだった）。寄りかかりの直しとして各コントローラの取りやめで `clearSelection()` を呼ぶ（この直し方は別の壊れ方をした: 頂点の選択も道具が触っていない地物の選択もまとめて消え、戻した）。

### 5.68 同時に載っている兄弟が「自分の担当でないもの」を空へ戻すと、あとに置かれたものほど強くなる
- 正しい道: 同じ器へ複数の部品が押し込むときは、空へ戻すのを effect の本体でなく後片付け関数でやり（React は 1 コミットの中で全部の後片付け → 全部の再実行の順に走る）、後片付けは自分が書いたぶんにだけ効かせ（`optionBar.clearChromeIfMine(writer)`）、器が持ち直されたら押し直す（`epoch` を effect の依存に入れる）。器の側に持ち主（`claim`）と代（`epoch`）を持たせ、押し込みと取り下げの非対称をなくす。
- 誤った道の兆候: 「自分が降りているなら器を空へ戻す」（構えていない 4 つの `setCommit([])` がナイフの確定ボタンを消した）。無条件で器を空へ戻す後片付け。各部品のローカルの印（`pushedRef`）だけで「自分のぶんを戻す」（試して戻した: 木の後ろの道具から前の道具へ持ち替える 10 通りで次の一手と確定欄が空になった）。後片付けへ移しただけで代を見ない（試して足りなかった: 5 道具は `active` が次のコミットで偽になるので、次の持ち主の押し込みを踏み消した）。1 つだけ載せた単体の検査。
- 確かめ方: `src/ui/shell/useToolBarChrome.ts`、`src/ui/shell/option-bar.ts`、`src/ui/shell/option-bar.test.ts`（`clearChromeIfMine`）、`src/ui/map/HandleCapNotice.survey.test.tsx`、`e2e/inc5-shell.spec.ts`「5 道具 × 選ぶ・頂点・動かす・測る の 20 通りで、対象欄と帯が残る」。全部を同時に載せた形で、押し込んだ直後に別の部品を再レンダーさせる。

### 5.69 「入り切らないものを畳む」判断で、畳んだ結果によって幅が変わる器を測らない
- 正しい道: 畳む判断は中身に依らない予算で行う。外側の器の内寸から、幅の決まった区画・部品どうしのすき間・必ず残す区画の幅を引いた残りが予算で、必ず 1 回で収束する。予算を器の `max-width` として実際に嵌める（見込みだけだと「次の一手」が 160px の見込みに 189〜204px 取り、設定欄が予算より狭くなった）。`ResizeObserver` は窓幅に追随する外側の器を見張る。
- 誤った道の兆候: 畳む部品が入っている器（`flex: 0 1 auto` のように中身で幅が決まる）の `clientWidth` を測る（畳む → 縮む → もっと畳むの輪で、測量を ON にした瞬間に読み取りが丸ごと「≫」へ落ち、1920px でも起きた）。`min-width` のある器を見張る（畳んだあと通知が来ず、一度畳んだら二度と戻らない）。狭くする側だけ検査している。
- 確かめ方: `src/ui/shell/OptionBar.tsx`（予算の計算と `ro.observe(bar)`）、`src/ui/shell/OptionBar.test.tsx`（幅を差し替えて予算を見る）、`e2e/inc5-shell.spec.ts` の「手直し D3 — 設定欄の畳み」と窓幅を 1024 → 1280 へ変える走査。「広げて戻る」を明示して見るのはレール側の `e2e/inc6-rail.spec.ts`。実測は E2E で（レイアウトの無い環境は幅が全部 0 で「全部出す」の枝しか通らない、§5.49）。

### 5.70 同じ打鍵で出した確認を、同じ打鍵で閉じると輪になる
- 正しい道: 「連打すれば必ず素の状態へ戻る」と保証した打鍵では、板を出した理由で答えを分ける。外で起きたことが原因（年が動いた・別のものを選んだ・道具や権限が変わった）なら、その打鍵は取り消して元へ戻す。利用者自身のその打鍵が原因なら、もう一度は念押しなので進める。どちらでも逆を選ぶボタンは板に出しておく。
- 誤った道の兆候: 利用者の Escape で出た板の Escape が「このままにする」（Escape → 開く → Escape → 閉じる → Escape → また開く、の輪）。規定どうしが矛盾している（同じ節が「連打で素の状態」を保証していた）。上限を決めずに連打の検査を書く（輪になっていても「いつかは終わる」と読める）。
- 確かめ方: `src/ui/shell/escape-ladder.test.ts`（8 通りの初期状態）、`src/ui/add/AddToolController.test.tsx`（局面ごと・上限 5 回、reason=escape の扱い、道具の板は「このままにする」）、`src/ui/knife/KnifeToolController.test.tsx`、`e2e/inc5-shell.spec.ts`（6 回連打で素の状態）。規定は `docs/ui-redesign/02-設計書.md` §D.4。

### 5.71 確認を出すなら、その原因になった遷移を先に済ませてはいけない
- 正しい道: 「捨てますか」の板を出す瞬間に道具・鍵・年・選択を元へ戻し、遷移は意図だけ覚えて「捨てる」と答えられてから実行する。［続ける］は何もしない。板は `*-modal-root` / `*-backdrop` / `*-dialog` の作法で本物のモーダルにし、背面の覆いで入力を遮る（遷移の種類が増えても規則は 1 つ）。

### 5.72 effect の中で自分の状態を畳む部品の後片付けは、1 コミット遅れて次の持ち主を踏み消す
- 正しい道: 器へ押し込む部品が「降りた」ことを effect で知る作り（道具・タブ・パネル・通知欄）では、後片付けが 1 コミット遅れる前提で書く。入れた側のローカルな印では「いま誰が持つか」が分からないので、守りの印は器の側に置く（現在の形は 5.77 の「書いた人」）。
- 誤った道の兆候: 地物は選ばれたままなのに対象欄が「（選んでいません）」で固まり、別の地物を押すまで戻らない（5 道具 → 選ぶ／頂点／動かす／測る の 20 通り）。「代（`epoch`）が同じなら空へ戻す」は押し直しを入れると破れる（5.77）。

- 現在の形は 5.77 を見る。

### 5.73 入力の置き場を動かしたら、その局面の打鍵を誰が受けるかを配り直す
- 正しい道: 入力欄を移す（板 → 右パネル等）ときは打鍵の受け手を配り直す。「やめる」の Escape だけは文字欄の中でも道具が受け、欄は `data-pristine` で打ちかけの有無を名乗り、空なら 1 回でやめ、打ちかけがあれば 1 度聞く。同じ局面を持つ他の道具すべてへ同じ規則を配る。規則は共有の 1 本に置く。道具ごとに書くと、次に置き場を動かしたときにまた 1 つだけ配り忘れる。いまは add / knife / drill の 3 つに `inEditable && e.key !== 'Escape'` の写しがあり、1 本化されていない。4 つ目の道具に素性入力を足すときは、先に 3 つを `shell/focus-guard` 側の 1 本へ寄せてから配る。

### 5.74 「予算で畳む」と決めたら、その予算を実際に嵌めるところまでやる
- 正しい道: 予算を `max-width` として実際に嵌め、畳む区画は `flex-shrink: 0` にして余りを隣へ渡す。畳む判断は `max(予算, CSS の min-width)` で行う（`src/ui/shell/OptionBar.tsx` の `Math.max(raw, SETTINGS_MIN_WIDTH)`）。

### 5.75 打鍵を止める関門は、打鍵ごとに書くと必ず 1 つ漏れる ―― 入口 1 か所で止める

### 5.76 器を空へ戻す仕組みを入れたら、押し込む側に「空にされたら押し直す」を持たせる
- 正しい道: 空にする権限を作ったら埋め直す義務を対で作る。器に「代が変わった」購読口（`subscribeOwner`）を置き、押し込む側は `useOptionBarEpoch` で React の値として読み、押し込みの effect の依存に入れる。中身の購読とは別の口にする（もともと空なら中身の購読は通知されない）。同型: 状態行・通知欄・パンくず。
- 誤った道の兆候: 道具も点も残っているのに対象欄が「（選んでいません）」のまま固まり、1.5 秒待っても 1 点足しても戻らない。「持ち直した側が埋める」案（中身を知るのは押し込んだ側だけなので成り立たない）。

### 5.77 共有の器へ押し込む条件は、自分の state ではなく「店の真実」で決める
- 正しい道: 押し込みの条件は「自分の `flow` かつ 店がいまこの道具だと言っている」の AND（例 `knifeArmedHoldsBar`）。後片付けは「書いた人」で守る（`setTarget(..., writer)` / `clearTargetIfMine` / `clearChromeIfMine`。考え方は差し込みスロットの token と同じ）。代は押し直しの合図にだけ使う。この組（押し直し・店の真実・書いた人）は一度に入れる。
- 誤った道の兆候: 押し直しを入れたのに条件が自分の state だけで、降りたばかりの道具が次の持ち主の中身を上書きする（分ける → 選ぶ で一瞬「手順 1/4（選んでいません）」の直後に空で固まる）。後片付けを代で守ったまま押し直す（新しい代を覚えるので古さを判定できない）。1 つだけ抜いて入れる。

### 5.78 「1 画素に何本あるか」に畳む描画は、畳む前の値を作る費用を別の契機に置く

### 5.85 押した瞬間に走る同期の確定は、1 コマ描かせてからでないと進行表示が出ない

### 5.86 「黙って外れる」を直すとき、外す手を消すのではなく、黙るのをやめる

### 5.91 「打ちかけがあるか」を焦点のある欄で判定しない ―― 焦点は押しただけで外れる

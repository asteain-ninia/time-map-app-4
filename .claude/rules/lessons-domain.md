# 中核の処理の教訓

番号は変えない。コードや文書が「開発ガイド §5.N」として参照している。

文言の表の規則は `lessons-ui.md` の §5.99 を見る（中核と本体プロセスの表も対象。`○○-messages.ts` と `○○-strings.ts` は何も読み込まない）。

### 5.1 集合演算は複数片を返す前提で扱う
- 正しい道: ブーリアン（集合）演算は複数ポリゴン・複数リングを返すものとして扱い、差分・結合・競合解決では返ったすべての片を変換する。
- 誤った道の兆候: 演算結果の先頭だけを採る `[0]`、`polygons[0]` が現れる。刃物の切断で移行中の別名 `sideA` / `sideB`（= `pieces[0]` ほか、`split-geometry.ts`）を新しいコードから読み始めたら、3 片以上で片が落ちる。
- 確かめ方: `src/domain/geometry/boolean-ops.test.ts`（結果が 2 片以上になる入力で全片が出る）、`src/domain/deletion/deletion.test.ts`（飛び地）、`src/domain/consistency/orchestrator.test.ts`。

### 5.6 状態変化の検出は結果状態で判定する
- 正しい道: 「ある状態変化が起きたら追加処理を走らせる」検出は、変異後の結果状態で判定する。
- 誤った道の兆候: 呼び出しフラグや引数の有無でゲートしている。起動条件に「この経路でだけ起きる」と書きたくなった（同じ状態変化を別経路が起こすと必ず漏れる）。
- 確かめ方: 同じ結果状態を生む他経路を列挙し、回帰テストを経路ごとに置く。実例は `src/domain/affiliation/affiliation.test.ts`（末端/集約の判別が結果状態で行われる、全下位領域消失で自動消滅）。

### 5.15 タイムスタンプはコンテキスト上の時刻を参照する
- 正しい道: 時間軸を持つデータのタイムスタンプは作中の現在時刻を参照し、システム時刻と混同しない。実時間が要る処理（バックアップ名・ログのローテーション・ID の時間源）は時計を注入して受け取る（`TimeSource`、`env.now`）。
- 誤った道の兆候: `src/domain` に `Date.now()` / `new Date()` が入る（現在 0 件）。再生の進行や錨の開始年を実時間から計算している。
- 確かめ方: `src/domain/add/proposal.test.ts`、`src/ui/add/useAddTool.test.tsx`（`anchorTime` = 現在時刻）、`src/shell/io/backup.test.ts`（新旧判定が決定的）、`src/ui/timeline/playback.test.ts`。

### 5.17 イミュータブルなエンティティ/値オブジェクトの設計
- 正しい道: 状態変更は新しい値を返す関数（`withName`、`withFillColor` など）で行い、等価性は属性値比較で定義する（`basicAttributesEqual`、`colorInfoEqual`）。`withXxx` を導入するときは全属性について必要な関数を洗い出す。
- 誤った道の兆候: 属性を足したのに `withXxx` や `...Equal` の片方が古いまま。`withXxx` のどれかを通ると透過度などの別属性が落ちる。入力の値を書き換えている。
- 確かめ方: `src/domain/attributes.test.ts`（全 `withXxx` で透過度を保持）、`src/render/vtransform.test.ts`（入力を変更しない）、`src/ui/map/multi-vertex-drag.fr80.test.ts`。

### 5.18 空配列・空オブジェクトは真値である
- 正しい道: 論理和による短絡評価のデフォルト補完に頼らず、型や状態を明示的に判定する。0 件・親なし・未ホバーも有効な状態として扱う。
- 誤った道の兆候: `x || []`、`x || {}`（現在 src に 0 件）や、配列の真偽で「あるか」を判定している。空を未設定と同一視して、分岐が逆になる。
- 確かめ方: `src/render/add-batch.test.ts`、`src/domain/add/session.test.ts`、`src/shell/io/tmap.test.ts`（添付 0 件）、`src/shell/io/backup.test.ts`（0 件で初回保存）、`e2e/grid-toggle.spec.ts`。個別の回帰のみで、書き方を止める lint は無い。

### 5.19 分岐識別子は型定義・定数・ファクトリを経由する
- 正しい道: 種別・モード名・設定キーの分岐は型定義・定数・ファクトリを経由する（`defineCommandKind`、`HIT_KIND`、`FILTER_AXIS`、網羅確認は `assertNever`）。
- 誤った道の兆候: 表示文字列や生の文字列リテラルで分岐している（`label` で分岐など）。大文字小文字差で分岐が変わる。
- 確かめ方: 新識別子を追加・改名したら、作成・表示・編集・保存・検索の全経路で同じ値を使うテストを置く。`src/ui/discovery/axes.test.ts`、`src/ui/map/context-menu-adapter.test.ts`、`src/ui/map/dispatch.test.ts`。

### 5.20 元に戻す情報は依存データも含めて過不足なく保存する
- 正しい道: 元に戻すのに必要な情報は依存データ（頂点の本体など）も含めて特定し、コマンドが構造共有の不変な値として抱える（技術方針 2.6 は Immer の作法を指すが、本番コードは `immer` を読み込まず、テストだけが使う）。状態全体を履歴の項目ごとに深いコピーしない（`history.ts`）。ID を生成するコマンドは、redo で採番し直さず初回生成 ID を復元する。
- 誤った道の兆候: redo のたびに ID が変わる。取り消した後に、形が引く頂点の本体が履歴の写しに無く、地物が丸ごと見えなくなる。
- 確かめ方: `src/domain/command/command.test.ts`（redo で同じ ID）、`src/domain/__bughunt__/time-anchor-history-undo-redo.property.test.ts`、`src/ui/conflict-resolution-weld.property.test.tsx`（履歴の写しに宙吊りの参照が無い）。

### 5.21 削除は参照掃除と連鎖剪定まで行う
- 正しい道: 削除は、残存する全要素の全（時間軸）状態から削除対象への参照を同じ操作内で掃除し、参照が消えて空になった派生要素を剪定・連鎖消滅させるところまで行う。
- 誤った道の兆候: 片方向・単一時点だけの掃除で dangling 参照が残る。子の錨に親が居ない形で掃除されず、保存前検査で止まる。
- 確かめ方: `src/domain/deletion/deletion.test.ts`、`src/domain/deletion/bundle.test.ts`、`src/domain/affiliation/affiliation.test.ts`（連鎖剪定）、`src/domain/persistence/consistency.test.ts`。

### 5.23 コマンドの execute/undo/redo は対称に通知する
- 正しい道: execute / undo / redo は同じ規約で、触れた全要素を対称に通知する。ドメインはイベントを発火せず `CommandResult.touched` を値で返し、外側の層がそれを読んで通知する。同一の状態変化を二重通知しない。
- 誤った道の兆候: 直後に手動リフレッシュを書きたくなった（通知漏れのサイン）。undo だけ `touched` が欠ける。
- 確かめ方: `src/domain/command/command.test.ts`（`touched` の厳密一致。包含判定は重複・過剰を見逃すので使わない）、`src/domain/affiliation/adapter.test.ts`、`src/domain/coloring/recolor-command.test.ts`。

### 5.25 仕様が限定した対象範囲を実装で広げない
- 正しい道: ドメインの基本ルール（排他性・整合性・階層）が仕様で対象を明示的に限定しているなら、その範囲を守り、変更前に仕様の該当節を引用する。
- 誤った道の兆候: 「対称性確保」「自然な拡張」を理由に対象を広げようとしている。直感的な拡張と感じた変更ほど、仕様の例外規定を疑う。
- 確かめ方: 変更前に仕様の節を引用する。限定を固定した個別の検査は `src/domain/consistency/orchestrator.test.ts`（末端地物限定）、`src/domain/affiliation/affiliation.test.ts`（FR-48 例外）、`src/domain/add/snap.test.ts`。
- 検査: 挙げたテストは個別の回帰だけで、規則そのものを守る検査は無い。手で確かめる。

### 5.26 編集制約はコマンド確定前にも同じサービスで検証する
- 正しい道: 編集制約（自己交差・全体重複・階層破綻・禁止条件）は、UI の候補表示と、コマンド/ユースケースの確定前の両方で同じサービスを使って検証する（`isLegalNewParent`、`validateMergePreconditions`）。拒否理由はユーザー通知とテスト可能な戻り値の両方で扱う。
- 誤った道の兆候: UI が候補を隠すだけで確定側に検査が無い。ショートカット・メニュー・undo/redo・直接呼び出しで不正状態が入る。候補の判定と確定の判定が別の式になっている。
- 確かめ方: `src/domain/__bughunt__/hierarchy-parent-aggregate-affiliation.property.test.ts`（候補と確定が同じ判定）、`src/ui/ring-hierarchy-gate.test.tsx`、`src/domain/affiliation/affiliation.test.ts`。

### 5.27 結合と所属変更は事前条件を分けて検証する
- 正しい道: 結合（合体）と所属変更（割譲・帰属等）は別概念として、共通条件（同一対象でない・有効である等）に操作種別固有の条件を加えて検証する（`src/domain/merge/precondition.ts` と `src/domain/affiliation/candidates.ts`）。所属変更では新親が対象自身とその下位すべてに含まれないことを確認する。
- 誤った道の兆候: 1 つの検証関数を両方の操作で使い回している。所属変更の検証に循環の確認が無い。
- 確かめ方: `src/domain/affiliation/affiliation.test.ts`（受け入れ基準6: 結合との事前条件分離）。

### 5.28 階層を辿る再帰サービスは循環で無限ループしない
- 正しい道: 階層（親子）グラフを辿る再帰は、壊れたデータ（循環参照・親子不整合）でも visited セットで再入を遮断する。シリアライズ層の検証とは別に runtime で二重に守る。
- 誤った道の兆候: 「読み込み時に検証済みだから循環は来ない」と考えて visited を省いた再帰を書いている。直接構築やテスト経路は検証を通らない。
- 確かめ方: 循環参照のケースで有限の結果を返すことを見る。`src/domain/hierarchy/hierarchy.test.ts`、`src/domain/deletion/deletion.test.ts`、`src/domain/affiliation/affiliation.test.ts`。

### 5.30 過少共有と過剰共有の両方を戒める
- 正しい道: 同じ判定・同じ baseline・同じ既定値処理は同じ実装を共有する。共有する前に「2 操作の制約は本当に同一か」を列挙して確認し、除外規則が操作種別ごとに異なるなら派生候補一覧を共有しない。
- 誤った道の兆候: 同じ判定が 2 か所に書かれている（過少共有）。見た目が同じピッカーだからと候補一覧を使い回す（過剰共有。例: 追加の親候補 `parentCandidates` は未作成なので自己除外が要らず、所属変更の候補とは規則が違う）。
- 確かめ方: 制約を列挙して比べ、回帰テストで弾く。個別の検査は `src/domain/display/depth-focus.test.ts`、`src/domain/feature.test.ts`、`src/domain/text.test.ts`。
- 検査: 挙げたテストは個別の回帰だけで、規則そのものを守る検査は無い。手で確かめる。

### 5.37 ID 生成はタイムスタンプ単独に依存しない
- 正しい道: ID 生成サービス（`src/domain/id-generator.ts`）を経由し、時刻に単調増加のカウンタを組み合わせ、既存データとの重複検査（`IdReservation`）を行う。バックアップ名は通し番号で同一ミリ秒を区別する。
- 誤った道の兆候: ミリ秒精度のタイムスタンプだけで ID や一時ファイル名を作っている（同一ミリ秒内で衝突する）。読み込んだデータの ID を予約に入れていない。
- 確かめ方: `src/domain/id-generator.test.ts`、`src/shell/io/backup.test.ts`（同一ミリ秒で別の番号）、`src/shell/io/save.test.ts`、`src/ui/live-unshare.test.tsx`、`src/ui/merge/MergeToolController.test.tsx`。

### 5.38 移動制約は線分交差で判定し、衝突検出と応答を分ける
- 正しい道: ドラッグの移動制約は、開始点から移動先までの線分が障害物や境界を横切るかで判定する（`constrainSlide`）。最初の接触点を求める処理（衝突検出）と接触後の残り移動の処理（衝突応答）を分ける。既存接触（t=0）は止め直さず、食い込み成分だけ捨てて接線方向の移動を許す。
- 誤った道の兆候: 移動先の点が合法かだけを見ている（細い障害物や尖りを飛び越える）。境界に沿って動かすと t=0 で止まり続ける。
- 確かめ方: `src/domain/editing/slide.test.ts`（既存接触 t=0、飛び越し防止）、`src/domain/geometry/predicates.test.ts`（`segmentsIntersect`）。

### 5.42 点の密度と、点をまとめる許容値は必ず一組で決める
- 正しい道: 形を点列へ落とす処理（曲線の分割・間引き）と、近い点を同じ点とみなす処理（吸着・スナップ・量子化）は一緒に動かす。精細にしたいときは間引き間隔と吸着許容値を一緒に下げ、閉じない隙間は行き止まりの端点だけを狙う処理を別に足す。
- 誤った道の兆候: 片方だけ変える変更。特に「隙間が閉じない」を吸着許容値の引き上げで解こうとしている（吸着は全点に一律に効き、小さい形が丸ごと潰れて消える。逆に点を細かくしても隣の点が許容値の内側に入って同じことが起きる）。面積の一致を根拠に「壊れていない」と言っている（総面積は変わらず個数だけ減る）。
- 確かめ方: 変更の前後で面・リング・独立した島の個数を数えて比べる。自動の検査は無い。実装は `../derle-map-visualizer/logic.js` の `flattenCubic` の `minChord` と `gimoza.js` の行き止まりの橋渡し（同リポジトリの `AGENT.md` に同じ注意あり）。
- 検査: 未整備。手で確かめる。

### 5.45 厳密比較で書かれた幾何述語に、新しい種類の点を流さない
- 正しい道: 「外積がちょうど 0 なら境界上」の厳密な述語は、同一の格子・頂点列から来た点だけに使う。辺の中点・補間した点・別経路で丸めた座標を問い合わせるときは、述語に許容値の引数を足し、その呼び出しだけ正の値を渡す（量子化の粒度より 1 桁小さい値が目安）。
- 誤った道の兆候: 「同じ関数だから同じように使える」と、計算で作った点をそのまま渡している。境界上の点が在／不在をでたらめに返す。既定の判定を緩めて直そうとしている（前提を満たす呼び出し側の厳密さまで失う）。
- 確かめ方: 述語の呼び出し元を列挙し、渡す点が「データに実在する頂点」か「計算で作った点」かを分類して、後者の経路を実データで突き合わせる。許容値つきの形は `../derle-map-visualizer/gimoza.js` の `onSegment(p, a, b, eps)`／`locateInRing(idx, p, eps)`。アプリ本体の `src/domain/geometry/predicates.ts` は `orient2d` の符号で厳密に判定し、固定の許容値を意図して持たない（`predicates.test.ts`）。
- 検査: 未整備。手で確かめる。

### 5.55 「その時点の全体の写し」を並べる形では、過去を直しても未来の写しが古いまま残る
- 正しい道: 履歴がスナップショットの列なら、データの形を差分へ変える（根治だが高コスト）か、書き込み側で保存した属性を「次にその属性が本当に変わるスナップショット」まで前へ引き継ぐ。止まる位置は属性ごとに独立に決め、何枚書き換えても 1 回の操作＝1 つの取り消し単位にする。引き継ぐ範囲は押す前に文字で見せる。
- 誤った道の兆候: 「1000 年で名前を直したのに 2000 年へ進むと元に戻る」を「保存が効いていない」不具合として追っている（T の保存は正しく効いている）。「同じ地物を続けて直すと起きず、他人を直してから自分を直すと起きる」。同じ対象を時刻の昇順に直すだけの検査。黙って後ろを書き換える実装。
- 確かめ方: `src/domain/editing/carry-forward.ts`・`carry-forward.test.ts`、`src/domain/editing/apply-proposal.test.ts`「兄弟を 2000 年で直したあと 1000 年で改名すると…」。予告は `src/ui/property/PropertyPanel.tsx` の `carryPreview` と `PropertyPanel.test.tsx`（A1 / A6）、`e2e/anchor-edit-time.spec.ts`。

### 5.89 時刻に区間を持つ記録を書き換えるときは、区間の境目で割り、意図した区間の外を触らない ―― 「その年より後の全部」と「その区間」は違う
- 正しい道: 書き換える区間を先に求め（例: 編集の前は居て後は居ない区間）、境目で錨を割ってから中の錨だけを書き換える（`src/domain/affiliation/interval-edit.ts` の `clearParentWithin`。後ろの片は前の片の終わりを引き継ぐ）。判定は区間の中のすべての境目の時刻で行う（削除の `interior`。`src/domain/deletion/bundle.ts`・`sweep-state.ts`）。検査は読み込みと同じ時刻の切り方で回す（`checkHierarchyOverTime`）。
- 誤った道の兆候: 「ある年より後の錨を全部」や「錨の始まりの時刻の姿だけ」で判定・適用する。実例: 1500 年で終わらせたら 1700 年の別の親の所属まで外れて殻が現れる／区間の途中から子が入るまとめ役が無関係の削除で系列ごと消える／親の存否を全部の年の和で見てその年に居ない親を通す／`applyPastEdit` の挿入が前の錨の終わりを引き継がず地物が終わりを越えて続く（B76。今は引き継ぐ）。5.21 と同型。
- 確かめ方: 単体に「後の年に別の記録がある」「区間の途中で他の系列が変わる」「終わりのある錨の途中」の 3 形を入れる（`src/domain/affiliation/interval-edit.test.ts`）。保存して開き直し修復の板が出ないこと（`e2e/inc7-fix2.spec.ts`）。

### 5.90 線で面を切るとき、線の延長で切り抜き形を作ってはいけない ―― 凹んだ面では延長が入り直す
- 正しい道: 切る相手の外周を切片の両端で 2 つに分け、切片で閉じる（切片以外は切らない）。両半分は集合演算の窓口の正規化を通して不変条件を確かめる。穴のある面は外周だけで切片を求め、できた片から穴を差し引く（穴へつなぐ仕掛けは不要）。延長で切る経路が残る形（飛び地・外周が自分に接する面・線の端が穴の中）は `cutsBeyondLine` を結果に載せて画面が言う。
- 誤った道の兆候: 開いた線を「両端を遠くまで延ばし枠を回って閉じた片側」に変える（面を横切る線の 5 割が「分断線が自己交差しています」で断られ、4 回以上横切る線は全滅／U の字の片腕の線が反対の腕まで黙って切る）。面積の合計だけを見る（余計に切っても元に戻るので通る）。「線の先の上下が別の片か」で数える（腕を切り離した正しい結果まで拾い、255 本の見かけの誤りが出た）。
- 確かめ方: 「凹みを複数回またぐまっすぐな線」「U の字の片腕だけを横切る短い線」で片の数と各片の面積を見る。実データでは「元に無い頂点が引いた区間の外の線上にできたか」を数える。断り理由は `SPLIT_REJECT` のコードで場面ごとに分ける。`src/domain/knife/split-geometry.v10.test.ts`、`split-geometry.holes.test.ts`、`e2e/knife-v10-real.spec.ts`。

### 5.92 代表点は、判定に使った点そのものを使う ―― 選び直すと境界の上を拾う
- 正しい道: 線が境界に触れる点では切片をそこで区切り（触れて戻る線は 2 本の切片）、代表点は切片の最初の区間の中点＝内側の判定に使った点そのものにする（`src/domain/knife/split-geometry.ts` の 690 行付近）。
- 誤った道の兆候: 中点で内側と判定したあと、別の処理の代表点に区間の途中の頂点を選び直す。くぼみの先 (5,5) をかすめる水平線 y=5 だけが「どの片にも入らない」で断られ、少しずらすと通る。外周を歩くと自分に接する半分が正規化で崩れる。
- 確かめ方: 「境界の頂点にちょうど触れて内側へ戻る線」と「少しずらした線」で片の数・面積が同じことを見る。`src/domain/knife/split-geometry.holes.test.ts`。

### 5.93 画面の予告とドメインに同じ判定の関数を使っても、入力の座標系がずれていれば食い違う
- 正しい道: 正規化（経度をつなぐ）を判定の関数の中に入れる（`splitsIntoManyPieces` は中で `unwrapRing` する）。呼ぶ側が整える約束にしない。
- 誤った道の兆候: 判定の関数を 1 本にして（5.29）満足し、呼ぶ側ごとに入力の正規化が違う。日付変更線をまたぐ U の字を画面は「穴があるので 2 つにしか分かれません」と予告し、実際は 3 片になる（180° を越える辺が反対側まで伸び、外周が自分と交わると判定される）。
- 確かめ方: 日付変更線をまたぐ形を保存された経度のまま判定の関数に渡す単体。`src/domain/knife/split-geometry.holes.test.ts`。

### 5.94 2 つの地物が共有する点は、1 つの出どころから作る ―― 同じ交点を 2 通りに求めると格子 1 つずれる
- 正しい道: 隣へ渡す点は片に実際にできた頂点から作る（元の辺の途中に乗った新しい頂点をその辺の切り口にする）。経路がいくつあっても出どころは片の頂点 1 つ。突き合わせに失敗したら投げる（`src/domain/editing/apply-proposal.ts:809`。検査で落ち、本番は確定を断る）。
- 誤った道の兆候: 片の側の交点（格子へ丸めた切片 P→Q 上）と隣へ渡す切り口（引いた線 a→b 上）を別々に計算し、座標の一致を前提に突き合わせる（斜めだと 1×10⁻⁷° ずれる）。失敗した点を黙って捨てる（実データの斜めの線 1,278 本中 265 本で島と海の境目に T 字が残り、確定は通り画面では見えない）。
- 確かめ方: 斜めの線（格子に乗らない座標の穴）で「隣へ渡す点がどれも片の頂点にある」と、本物の確定のあと「隣が同じ頂点 id を参照し T 字が 0」を見る。水平・垂直の線や片どうしの比較だけでは通る。`src/ui/knife/split-hole-seam.test.tsx`、`src/ui/knife/split-preservation.test.tsx`。

### 5.102 掴んだ頂点の通り道を拘束しても、頂点が引きずる辺は拘束されない
- 正しい道: ドラッグ中の軽い拘束（`constrainSlide`。掴んだ点の線分が隣の辺を横切るか・終点が隣の中か）は予告であって、確定の守りではない。確定は重なりの検出（U13 の `detectSpatial`）を必ず通す。形を変える編集の束ね（`src/ui/consistency-binding.ts` の `createLiveShapeEditBinding`）は、形の変わった面を結果の状態から集め（共有頂点なら掴んでいない隣も入る）、その面の重なりが確定済みの形より増えた組だけを止める。
- 誤った道の兆候: 「拘束が前段にあるので入りにくい」を根拠に確定の検出を省く。拘束は点の通り道しか見ないので、(1) 頂点を隣の脇へ引くと、掴んだ点は触れないのに新しい辺が隣を横切る、(2) 面の移動には拘束そのものが無い、(3) 共有頂点を引くと掴んでいない隣の面の辺が第三の面を横切る、(4) 穴の頂点を引くと穴の辺が中の島を横切り、穴が島を覆う。どれも 2026-10-31 まで記録されていた（B98）。
- 確かめ方: 拘束を抜ける形を経路ごとに作り、板が出ることを E2E で見る。`e2e/inc8e-drag-conflict.spec.ts`（面の移動・頂点・共有頂点・穴の頂点・飛び地の頂点）。単体は `src/ui/consistency-binding.test.tsx` の「共有頂点を動かして、提案の地物でない隣の面が第三の面に重なっても止める」。拘束そのものの検査は 5.38。

### 5.103 頂点の id を付け替えるなら、同じ id を引く全部の地物に、同じ座標で掛ける
- 正しい道: 付け替え（吸着の共有・分割の継ぎ目）は提案の地物の写しで終わらせず、同じ id を引く全履歴へ掛ける（`src/domain/editing/apply-proposal.ts` の `resolveShareLanding`、`applyVertexRemapToHistories`、`carryShareIntoLaterAnchors`）。行き先の座標は相手の確定済みの体を正とし、提案の座標を相手の id の体にしない。同じ輪が両方を引くなら断る（FR-32）。
- 誤った道の兆候: 「掴んだ頂点は吸着先の上に乗っているはず」を前提に、離した場所の座標を吸着先の id の体として写す（単一の頂点のドラッグの提案は乗っていない）。頂点の体だけを隣へ配って id を配らない。重なりの板に共有していた 2 面の組が出る。同じ id の体が履歴の間で食い違うと、`verticesAt` の後勝ちが履歴の順で結果を変えるので、順によっては緑に見える（実データの E2E はこれで通っていた）。
- 確かめ方: 3 面（掴む面・共有する隣・吸着先）で、離した場所を吸着先からずらして確定し、隣も同じ id を引くことと、吸着先の体が全履歴で同じことを見る。吸着先の履歴を前に置く形も入れる。`src/domain/editing/apply-proposal.share-landing.test.ts`、`e2e/inc8e-drag-conflict.spec.ts`（B100）。

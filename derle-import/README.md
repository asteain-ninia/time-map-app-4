# derle-import — デーレ界地図のインポート (2026-08-09 最新地図+階層化)

`../derle-map-visualizer` のポリゴン抽出ロジック(実物をヘッドレス Chromium で駆動)を使い、
デーレ界の国ポリゴンを抽出して time-map-app-4 の `.gimoza` に変換したもの。
旧PC(tatuk)にあった derle-import 一式はこの PC に移設されていないため、ここでゼロから再構築した。

**元データ**: `イラレ出界図BUR080809.svg`(ユーザーが 2026-08-09 に .ai から書き出した最新版。
このディレクトリに複製を置いてある)。`derle-map-visualizer` 同梱の 1/13 版ではない。
国名ラベルは 89 → 126 件に増えており、不明国の括弧付きラベルなども入っている。

**階層化** (ユーザー裁定 2026-08-09): `_州境界` レイヤーも抽出し、複数の面に分かれる国は
「集約地物 (親) + 末端地物 (子)」のツリー階層で出力する:

- **デーレ共和国** = 集約、子 63 (州名付き 30 州 + 領海 + 無名領域)
- **正統ノル王国** = 集約、子 16 (州境界線はあるが州名は無い → 地名ラベルから命名。ウサイモ島・ペレッサ・ガーミアッサ・南ケナ地方・グシアッサ・エッサ大平野)
- **ラヴィエンド・ウィル同君王国** = 集約 (同君連合 = `UNION_GROUPS` 設定で 2 国を統合)、
  子 = ウィル + ラヴィエン (構成国) + 領海 + 境界上の島など (養子)

## パイプライン (tools/)

1. `extract-polygons.mjs` — visualizer の index.html をヘッドレス Chromium で開き、
   `loadSvgText()` → `buildGraph()` → 橋渡し → `extractPolygons()` を駆動して `borders.json` を出力。
   `--states` を付けると `_州境界` レイヤーを `_国境界` に統合して抽出し、州レベルの面を
   `borders-states.json` に出力する (両方必要)。rAF を setTimeout(0) 化し描画を全 OFF にして高速化。
   - **国境の隙間の橋渡し**: 行き止まり (次数1) の国境端点を、自チェーン (3ホップ以内) を除く
     最近接点へ接続する。作図精度の問題で吸着許容値 (1.0) を超える隙間が多数実在し、放置すると
     隣国同士が 1 ポリゴンに併合される (中央イノン/東イノン、デルレイス帝国ほかで実測)。
     - 半径は既定 **2.5**、ただし**国境線の端点→国境線の点**に限り **6.0**(コルニア/バアカ
       南方の長い海上国境線は縦の区切り線が 2.6〜5.7 届いておらず、海域が閉じなかった)。
       海の中で自由に終わる共有海式の国境線が海岸線へ誤接続しないよう、大半径は国境線同士のみ。
     - **平面性の維持 (必須)**: 橋渡し線が既存の線と交差するとノードの無い交点ができてグラフが
       非平面になり、面探索が破綻する (自己交差リング → 穴が外周をはみ出す "hole-crosses-parent"
       が実測 6 件)。交差する橋渡しは棄却する (一様グリッドで近傍辺のみ判定)。実測 97 本採用 /
       5 本棄却。
     - `EXTRA_BRIDGES` で個別の大きい隙間 (ラヴィエンド西方の岬 4.41) も指定。
2. `extract-vector-basemap.mjs` — **ベクター背景地図**を抽出 (`basemap-vector.json`)。地形レイヤー
   (第一〜第五分高面) の SVG パス定義 (`d` 属性) と塗り色、海の色、viewBox↔世界矩形の対応を保持する。
   点列へサンプリングしないのは、曲線が折れ線に落ちず・データも小さいため。
   `preview-vector-basemap.mjs` で焼いた結果を目視確認できる。
   - **なぜベクターか (実測)**: 8192×4096 PNG のデコード+初回描画 = **162 ms** に対し、同じ地形を
     ベクターから焼くのは **世界全体 19.8 ms / 10倍ズーム 5.6 ms**（GPU 完了待ちを 1px 読み戻しで
     同期して計測）。**焼く方が読むより速い**うえ、拡大してもぼやけず、.gimoza も小さくなる。
   - アプリ側は画面より一回り大きい範囲を裏キャンバスに焼いて貼り、ズーム段階が変わるか
     余白を出たときだけ焼き直す（`src/ui/map/vector-base-map-cache.ts`）。
3. `raster-base-map.mjs` — 従来のラスター背景 (8192×4096 PNG)。`build-tmap.mjs --raster-basemap`
   を使う場合のみ必要。
4. `build-tmap.mjs` — 変換本体:
   - **冗長点の除去 (フル版の既定)** — visualizer は SVG パスを一定間隔 (1.2 地図単位 ≒ 11 km) で
     サンプリングするため、**元データで 2 点だけの直線国境も等間隔の点列になる**(実測: リング上の
     点の 20% が「前後の点と 10 m 以内で一直線」)。境界チェーン単位の間引きを小さい許容値で掛けて
     直線を両端 2 点へ戻す。既定 `--cleanup-epsilon=0.02`(約 190 m = 最大ズームでも画面 0.085 px
     相当なので見た目は不変)。**102,595 → 73,553 頂点 (28% 減)**。0 を渡せば無効。
   - **世界矩形** = 海色レクト `x=5.262 y=0.5 w=4243.4 h=2121.7` (これがちょうど 2:1。
     viewBox 全体 4249.288×2131.011 ではない点に注意)
   - 座標変換は lon/lat 線形写像 + **±180/±90 クランプ** (はみ出しが経度周回で反対端と
     極小重なりを作るのを防止)
   - **包含解析** — 内包ポリゴン(島・包領・内海)を外側ポリゴンの穴リング化。穴リングは
     内包側と同じ頂点 ID を共有するため末端排他が厳密に成立する
   - **国名割当** — `_国名` ラベルを「回転角×フォントサイズで求めた文字列に沿う密サンプル」
     で判定。面積 100 未満のマイクロ国家 (デルレイス帝国 = 面積7.85 の飛び国) が文字列下に
     あればそれを最優先、通常は文字列中央からの先着順
   - **地域名つき仮名** — 国名の無い地物の仮名を `_州名`/`_地名`/`_海名`/`_山岳名` から導出:
     島に地名ラベルが載っていれば直接その名 (ウサイモ島など)、その他の島は最寄り海名から
     「〇〇海の島NN」、無名海域は「〇〇の海域NN」、無名陸域は「〇〇付近の領域NN」。
     集約の子は 州名 →(無ければ)地名 →(無ければ)「〇〇領海NN」/「〇〇の領域NN」の順。
     **全 858 地物が番号だけの仮名なしで命名済み**(検証: 「領域NNN」形式は 0 件)
   - **手動割当** (ユーザー裁定 2026-08-08) — 洋上ラベル 5 件 (ピニア・テレン合議国・バアカ・
     ヤシュー・アレファクト・ニィル) は `MANUAL_LABEL_ASSIGN` の内部点座標で割当
     (ポリゴン id は再抽出で変わるため座標指定)
   - **階層化** — 面の内部点を国レベルポリゴンへ包含判定してグループ化。複数面の国は
     集約+子に (国名ラベルは親へ、子は州名ラベル/領海/連番で命名)。`UNION_GROUPS` で
     同君連合 (複数国→1集約) を定義。付随する正規化:
     - リング正規化: 橋渡しが生む「スリット付き一筆書きリング」(島を除外する自己接触) を
       検出し、往復スパーは除去・逆回りのポケットは明示的な穴リングに分解
     - 隙間吸収 (養子): 子の合併の外周に囲まれるがどの子にも属さない面 (子同士の境界上に
       挟まれた島・海の断片) を集約の子として追加領有 (共有海の島は海領域が領有する、の階層版)
   - 各ポリゴン = 末端地物 1 つ = 単一錨 (year 0 〜 open-end)。集約は 1 履歴に子と親を同梱
   - 測地系: 赤道長 **42,035 km** (derle-climate の惑星半径 1.0489 地球半径 × 40,075 km)、
     扁平率 0 (未設定のため球面近似)
5. `build-simplified.mjs` — **整合性クリーンになるまで自動で作り直す**ドライバ (フル版・間引き版の両方)。
   間引きは各リングを独立に動かすため、まれに穴が親をはみ出す (hole-not-contained /
   hole-crosses-parent)。どの面がそうなるかは幾何依存で事前に読めないので、
   「ビルド → アプリの整合性チェック → 失敗した面を `--keep-full` に追加 → 再ビルド」を
   収束するまで繰り返す(実測: フル版は 1 ラウンド・間引き版は 2 ラウンドで収束し 15 面を原型維持)。
   引数なし = フル版、`--target-vertices=N` = 間引き版。**両方ともこのドライバで作る**。
6. `diagnose-consistency.ts` / `diagnose-pair.ts` — vite-node で実行する検証補助。
7. `preview-tmap.mjs` — .gimoza を重ね描きした PNG を出力。

再現コマンド:

```
node derle-import/tools/extract-polygons.mjs            # 国レベル → borders.json
node derle-import/tools/extract-polygons.mjs --states   # 州レベル → borders-states.json
node derle-import/tools/raster-base-map.mjs
node derle-import/tools/build-simplified.mjs                          # フル版 (自動収束)
node derle-import/tools/build-simplified.mjs --target-vertices=16500  # 間引き版
node derle-import/tools/build-tmap.mjs --flat           # 旧来のフラット版が要る場合
```

## 既知の制限・申し送り

- **バアカが海域を持たないのは正しい (ユーザー裁定 2026-08-09・調査不要)**: 当初「コルニア近辺・
  バアカ・コルニア東の不明国は海上国境を持つはず」との報告を受けたが、**コルニアと東コルニア
  不明国のみ欠けており修正済み** (半径 6 の国境間橋渡しで海域が閉じた)。バアカは元地図にも
  西側・北側の海の国境線が無く (`crop-borders-only.png` で確認)、**南極圏に近い国で南限と
  コルニアとの境界だけが定まっている**ため、海岸線どまりの領域として抽出されるのが作図意図
  どおり。**直そうとしないこと** — 橋渡し半径を上げて無理に閉じると、意図的に開いている
  海の国境を誤って繋いでしまう。
- **間引き版の全周リング自動除外**: 経度全周に及ぶポリゴン (南極域) は間引くとシーム跨ぎ
  展開の解釈が変わり偽の重なりが出るため、自動で間引き対象外にしている (bbox が世界幅の
  9 割超で判定)。加えて `build-simplified.mjs` の収束ループが 15 面を原型維持するため、
  間引き版は目標 16.5k に対し約 30.5k 頂点。
- **命名衝突 1 件**: 「ジアーラ・ジアーラ内不明国」— 同一ポリゴンに両ラベルが載る。
  未割当ラベル 2 件:「（東ウィータ不明国）」「マカ」(どのポリゴンにも入らない)。
  いずれもアプリ内で改名/再割当可能。
- **橋渡し半径は経験値**: 一般 2.5 / 国境線同士 6.0。海の国境が意図的に開いている箇所を
  誤って閉じた可能性はゼロではない。境界がおかしい国があれば `extract-polygons.mjs` の
  `BRIDGE_RADIUS` / `BRIDGE_RADIUS_BORDER` / `EXTRA_BRIDGES` を調整して再生成する。
- 東西の地図端で分断された大陸は端で別地物のまま (アプリ内で合体可能)。
- 「海まで国境線」国の領海内の島は別地物のまま領有関係は未設定 (アプリの親子付けで後付け可能)。
- visualizer 側の既知問題「包領の排他」はこちらの包含解析→穴リング化で解決済み。

## アプリ側の関連変更 (2026-08-09)

実データを実機で編集して判明した UX 問題への対応。データではなくアプリのコード変更:

- **FR-110 頂点マーカー表示上限の意味を「視野内の個数」に変更**。対象ファイルは
  `src/ui/map/active-feature-handles.ts` / `src/ui/add/host-ports.ts` / `src/ui/App.tsx`。
  従来は「地物の総頂点数 > 上限」でハンドルを全抑制していたため、デーレ共和国のような
  巨大地物は既定 2000 を超えて**頂点編集が一切できなかった**(掴めるが見えない)。合成ルートが
  フレームの camera/viewport をハンドルビルダーへ渡し、視野内 (±32px) の頂点/辺ハンドルだけを
  生成・カウントするようにした。ズームインすれば視野内個数が上限を下回り、巨大地物も編集できる。
  仕様の文言「全頂点マーカー**表示**上限」とも整合。
    - 選択済み/ドラッグ中の頂点は視野外でも常に描く既存契約を維持。
    - ワールドラップ (FR-07) の replica turn も判定に含めるため、シーム跨ぎでも描画と一致。
    - `view` 未指定 (既存テスト/レガシー呼び出し) は従来どおり総数で判定 = 挙動不変。
- **FR-42 展開された集約が自分の領域を描き続けていた** (`src/domain/display/depth-focus.ts`)。
  仕様 U34 §31「d < N の集約地物は…より深い階層の描画へ降りる(集約地物自体の派生形状ではなく)」に
  反し、親の和が子の真上に重なってクリックを全部奪っていた＝**子地物を選択する手段が無かった**。
  自前形状を持たない集約が展開されたときだけ Omitted にする。子を持つ末端地物 (FR-35 中間状態) は
  自前リングを持つので従来どおり描く。
- **集約の派生形状キャッシュ / 合併アルゴリズム** (`src/domain/display/resolve-display-shapes.ts` /
  `src/domain/hierarchy/resolve-shape.ts`)。未使用エントリを捨てていたのを保持に変更 (時刻移動
  2,432ms → 51ms)、線形畳み込みだった合併を二分木化 (初回 2,323ms → 539ms)。
- **ベクター背景地図** (`src/domain/basemap/vector.ts` / `src/render/vector-base-map.ts` /
  `src/ui/map/vector-base-map-cache.ts` / `src/ui/add/host-ports.ts`)。ベースマップ資産の
  バイト列がベクター JSON ならそちらを使い、画面より一回り大きい範囲を裏キャンバスに焼いて貼る。
  ズーム段階が変わるか余白を出たときだけ焼き直す (＝実質その領域の初回のみ)。ラスターの経路は
  一切変えていない (JSON でなければ従来どおり画像として扱う)。

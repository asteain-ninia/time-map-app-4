# U34 階層深度フォーカスと表示制御

本書は実装ユニット U34 の実装指示書である。実装者（別エージェント）はこの指示書だけを読んで着手できる。前提知識は本書の中に閉じて記述する。要件・技術方針・開発作法の根拠は本文と末尾の「関連要件」「注意点・既知の落とし穴」に引用する。

本プロダクトの文書はクリーンルームとする。過去版・他プロダクト・外部の既存実装には一切言及せず、必要な制約はすべて time-map-app-4 自身の要件・技術方針として直接記述する（開発ガイド 3.1）。

## 目的

面情報のツリー階層（複数ルートを持つ森構造）に対して、メインマップ上に「どの階層深度までを実形状で描き、それより下位を集約形状（下位領域の和）に丸めて描くか」をユーザーが制御できる**表示制御の状態とロジック**を提供する。本ユニットは次を一体で実現する。

1. **グローバル階層深度スライダーによる集約表示（FR-42）**: アプリ全体に効く 1 本の「階層深度しきい値 N」をユーザーが操作でき、全地物を「階層深度 ≤ N」で集約表示する。N より深い階層は省略され、省略される階層の地物は自身の集約形状（下位領域の和）として描かれる。集約形状の解決は U08 が確立した**単一の派生形状解決判定**に乗せる（教訓 5.29）。

2. **表示モードと編集/追加モードの非干渉（FR-42）**: グローバル深度スライダーをはじめとする表示制御は、追加モード・編集モードとは独立した別軸の状態として持ち、表示制御の切替が追加/編集モードの状態や進行中操作を変化させない。逆に追加/編集モードの切替が表示制御の状態を破壊しない。

3. **個別フォーカス（FR-43）**: 選択中の地物の**縦方向領域**（その地物の上位領域すべて＋自身＋下位領域すべて＝最上位から末端まで縦に繋がる領域）だけを、グローバル深度とは別の深度で深掘り表示・強調表示する。個別フォーカスはグローバル深度スライダーと併存し、片方が他方を打ち消さない。

本ユニットの責務は「各地物を**実形状で描くか・集約形状（下位領域の和）で描くか・そもそも描画対象にするか**、および強調表示するか」という**表示決定**を、与えられた評価済みツリー状態から純粋に算出することにある。実際の描画（Canvas への塗り・線・ラベル）と集約形状そのものの幾何計算（ブーリアン和）は本ユニットの責務ではなく、それぞれ U19・U08 へ委譲する。本ユニットは「描画指示（どの地物をどの形状種別で・強調するか）」という中間表現を生成して U19 へ渡す。

## スコープ

### やること

#### 1. グローバル階層深度しきい値の状態と集約表示決定（FR-42）

- アプリ全体に効く 1 本の整数しきい値 `N`（階層深度の上限）を、UI/セッション状態（技術方針 2.5 の Zustand 層）に保持する。`N` はユーザーがスライダー（および同等の数値操作）で変更できる。
- ある時刻で評価済みの全面情報集合に対し、各面情報の**階層深度**を U08 の派生算出（最上位＝0、子＝親 +1、地物自身には保持しない）から取得し、次の表示決定を行う純粋関数を提供する。
  - 階層深度 `d < N` の集約地物: 実形状（下位領域を持つ集約地物自体の派生形状ではなく、その地物の子をさらに展開できる）として扱い、より深い階層の描画へ降りる。
  - 階層深度 `d == N` の面情報: その地物を「描画の末端」として、自身の集約形状（下位領域の和。末端地物なら自身の実形状）で描く。`d == N` の集約地物配下（`d > N`）の地物は**省略**し、単体としては描画対象にしない（親の集約形状に吸収される）。
  - 階層深度 `d > N` の面情報: グローバル表示では省略する（後述の個別フォーカスで例外的に深掘りされる場合を除く）。
- 「省略された階層の地物を自身の集約形状で描く」とは、深度 `N` の集約地物の描画形状を、その配下下位領域の和（＝U08 の派生形状解決判定の結果）として U19 へ渡すことを意味する（FR-42）。集約形状の算出・ブーリアン和は U08 に委譲し、本ユニットでは行わない。
- しきい値 `N` の有効範囲は、与えられた森全体の最大階層深度を上限とし、下限を 0（または「全地物を最上位の集約形状に丸める」レベル）とする。最大深度はツリーごとに異なってよい（FR-38）ため、森全体の最大値を範囲上限に使う。スライダーの上限が森の最大深度を超えないよう、範囲を森の状態から導出する。

#### 2. 表示制御と編集/追加モードの非干渉（FR-42）

- 表示制御の状態（グローバル深度 `N`・個別フォーカスの対象と深度・強調表示の ON/OFF）を、追加/編集モードの状態（U20 が管理するモード状態機械）とは**別軸**の独立した状態として保持する。
- 表示制御の変更（`N` の変更・フォーカス対象の変更）が、追加/編集モードの状態・選択中ツール・進行中ドラフトを変化させないことを保証する。逆に、追加/編集モードの切替が表示制御の状態（`N`・フォーカス）を破壊しないことを保証する。
- 表示制御はあくまで「見た目の集約度」を変えるだけで、**編集対象の同一性・選択状態・ドメインの真実（地物・錨・ツリー）を変えない**。深度を上げ下げしても地物の親子関係や形状そのものは不変であり、表示のみが変わる。

#### 3. 個別フォーカス（縦方向領域の深掘り・強調）（FR-43）

- 選択中の地物（アクティブ地物。なければ頂点選択コンテキストから一意に導かれる地物）を起点に、その**縦方向領域**＝「上位領域すべて＋自身＋下位領域すべて」を U08 の縦方向領域算出（循環遮断つき再帰、教訓 5.28）から取得する。
- 縦方向領域に属する地物に対しては、グローバル深度 `N` とは別の**個別フォーカス深度** `M` を適用して深掘り表示する。`M` はグローバル `N` より深くも浅くも設定でき、縦方向領域内ではこの `M` に基づく集約表示決定（上記 1 と同じ判定ロジック）を行う。
- 個別フォーカスはグローバル深度スライダーと**併存**する（FR-43）。縦方向領域外の地物はグローバル `N` の決定に従い、縦方向領域内の地物は `M` の決定に従う、という二系統の決定を 1 つの整合した表示決定へ統合する。
- 個別フォーカス対象（縦方向領域）の地物には強調表示（U19 が解釈できる強調フラグ／スタイル指示）を付与できる。強調は表示上の効果であり、選択状態・アクティブ地物の保持そのものを変えない。
- 個別フォーカスの解除（選択解除・明示的なフォーカス解除）で、表示決定がグローバル `N` のみに基づく状態へ戻る。

#### 4. 単一の表示決定への統合（教訓 5.29・5.30）

- 「グローバル深度の決定」「個別フォーカス（縦方向領域）の決定」を、各地物について 1 つの最終表示決定（描画対象か／実形状か集約形状か／集約形状なら誰の和に丸めるか／強調するか）へ統合する純粋関数を提供する。
- どの地物を集約形状として描くか・どの地物を実形状で描くかの判定は、U08 の**単一の派生形状解決判定**の結果に従う（描画・ヒットテスト・ラベル位置が同じ解決判定で動く＝教訓 5.29）。本ユニットは「どの深度で丸めるか」という選別を与え、「丸めた集約形状の幾何」は U08 の解決結果を使う。本ユニットで集約形状を独自算出・独自判定で求めない。
- 統合結果は U19 が消費できる描画指示（地物 ID ごとの「描画する／しない」「実形状／集約形状（丸め先 ID）」「強調する／しない」）として表現する。

### やらないこと

- 集約地物の派生形状（下位領域の和）そのものの幾何計算（ブーリアン和）。これは U08（および U08 が委譲するブーリアン演算ユニット）の責務であり、本ユニットは U08 の解決判定結果を消費するだけで、自前で和を計算しない。
- 階層深度の算出・縦方向領域の列挙・末端/集約の判別そのもの。これらは U08 の派生算出・循環遮断つき再帰の責務であり、本ユニットはその出力を消費する。
- Canvas への実描画（塗り・線・ラベル・強調の見た目）。本ユニットは「描画指示（中間表現）」を生成するのみで、実描画は U19 の責務。穴透過・飛び地独立・ズーム非依存サイズ・LOD・視野クリッピング等の描画規則は U19 が担う。
- 追加/編集モードの状態機械・モード排他トグル・ツールバー表示そのもの（U20 の責務）。本ユニットはモード状態を**参照しない**（非干渉の保証は「表示制御の状態をモード状態とは別軸で持ち、相互に書き換えない」ことで担保する）。
- アクティブ地物・頂点選択コンテキストの保持と遷移そのもの（選択系ユニットの責務）。本ユニットは「現在選択されている地物 ID」を入力として受け取り、そこから縦方向領域を求めるだけで、選択ロジックを持たない。
- スライダー UI コンポーネントの最終的な見た目・配置（U20 の UI シェルにマウントする。本ユニットは UI 状態と表示決定ロジック、および UI から呼ぶための薄いフック／セレクタを提供する）。
- 自動配色・スタイル決定（FR-100 / FR-101）。本ユニットは強調の ON/OFF を指示するだけで、配色アルゴリズムは実行しない。
- 時刻評価（どの錨が有効か・存在判定）。本ユニットは「ある時刻で評価済みのツリー状態」を入力前提とし、錨列の走査・正規化はしない。
- 地物の表示制御（種別・階層深度・個別地物単位の表示/非表示切替・不透明度調整・強調・検索）（FR-113）。これは別概念（地物種別や個別地物単位の表示フィルタ）であり、本ユニットの「階層深度による集約表示」とは責務が異なる。安易に同一機構へ統合しない（教訓 5.30 過剰共有の戒め）。

## 依存（dependsOn）

実装着手時点でこれらの公開インタフェースを利用する前提とし、依存先 API が未確定の場合は本ユニット内に最小の境界インタフェース（adapter）を切って後で接続し、接続時に両側テストで契約を固定する（教訓 5.33 / 5.34）。本ユニットは依存先が提供する仕組みを再実装せず、購読・利用する（単一の真実源。開発ガイド §4）。

- **U19（地物描画・派生集約形状描画・ラベル・LOD）**: メインマップへの実描画を担う描画ユニット。本ユニットは U19 が消費できる描画指示（地物ごとの「描画する／しない」「実形状／集約形状（丸め先）」「強調する／しない」）を生成して渡す。U19 は集約地物の描画形状を U08 の派生形状解決判定から取得して描く設計であり（U19 のスコープ「集約地物の派生形状描画」）、本ユニットが渡す「どの深度で丸めるか」の選別と U19 の描画が同じ U08 解決判定を共有することが本ユニットの核心要件である（教訓 5.29）。U19 の階層深度フォーカス入力（「階層深度 ≤ N の集約表示状態」）の供給元が本ユニットである。

- **U20（アプリレイアウトシェルとモード/ツールバー骨格）**: UI シェルの骨格・モード状態機械・操作性基盤を提供する。本ユニットは表示制御の UI（深度スライダー・フォーカス操作）を U20 のシェル（右サイドバーの階層/ツリー管理パネル（地物一覧）区画／表示メニュー等、配置は U20 の枠組みに従う）にマウントする。U20 は「表示モードの切替は編集・追加モードと干渉しない」ことをモード軸と表示/権限軸の分離方針として既に保証しており（U20 のモード状態機械方針）、本ユニットの表示制御状態はこの分離されたモード軸とは**別軸**の状態として、U20 が提供する UI/セッション状態ストア上に置く。本ユニットは U20 のモード状態を書き換えない。

- **U08（ツリー階層モデルと不変条件検証・派生深度・形状=和）**: `domain` 層の純粋ロジック。本ユニットは次を U08 から取得する。
  - 各面情報の**階層深度**（親子関係から派生算出、地物自身に保持しない、ツリーごとに最大深度が異なってよい）。
  - 末端地物／集約地物の判別（下位領域を持つかという結果状態での判定）。
  - **縦方向領域**（上位領域すべて＋自身＋下位領域すべて）の列挙（循環遮断つき再帰）。
  - 集約地物の**派生形状の単一解決判定**（下位領域の和。本ユニットはこの解決結果を「丸め先の集約形状」として使い、自前で和を算出しない）。
  - 森全体の最大階層深度（スライダー範囲の上限導出に使う）。

> dependsOn に挙がっていない関心事（時刻評価ロジック・集約形状のブーリアン和の実装・空間インデックス保守・カメラ入力・配色・選択ロジック）には依存しない。本ユニットは表示決定ロジック部分を `domain`（純粋関数）寄りに、UI 状態と U19/U20 連携部分を `render`/`ui` 境界に配置し、依存方向は `domain` へ内向き固定とする（技術方針 2.13）。`domain` から本ユニットの UI/描画連携を逆参照しない。

## 実装方針（技術方針に沿う）

技術方針 2.3（高頻度描画を React から切り離す）・2.5（Zustand ＋純粋ドメインコア）・2.13（層分離・依存方向内向き固定）・5.2（性能）・R5（ドラッグ中の軽量処理）に従う。

### 配置層と層分離

- **表示決定ロジック**（階層深度しきい値に基づく集約表示決定・縦方向領域フォーカスの統合・各地物の最終表示決定の算出）は、Canvas／React に依存しない**純粋関数**として切り出し、Vitest 単体で検証できるようにする（NFR 5.8 / 教訓 5.41）。入力（評価済みツリー状態・各地物の階層深度・縦方向領域・しきい値 N・フォーカス対象と深度 M）を受け取り、描画指示（中間表現）を返すのみで、外部状態を変異させない。
- **表示制御の UI/セッション状態**（グローバル深度 `N`・個別フォーカスの対象地物 ID と深度 `M`・強調 ON/OFF）は、技術方針 2.5 の薄い状態ストア（Zustand 層、U20/U16 系の UI/セッション状態基盤）に置く。React は購読のみで、地図描画の高頻度経路に乗らない（技術方針 2.3）。深度スライダーの値変更は UI 状態の更新であり、ドメインの真実（地物・錨・ツリー）を変更しない。
- 表示決定の結果（描画指示）は U19 へ渡す。本ユニットは U19 を `subscribe`／呼び出しで駆動する境界を持ち、表示制御状態が変わったら描画指示を再生成して U19 に即時再描画させる（教訓 5.5）。

### グローバル深度と非干渉（FR-42）

- グローバル深度 `N` を単一の状態として保持し、各地物の表示決定をこの `N` と U08 由来の階層深度から一意に導く。同じ「深度しきい値に基づく集約/省略判定」を、グローバルと個別フォーカスの両方で**同一実装**として共有する（過少共有の戒め・教訓 5.30）。
- 表示制御の状態は、追加/編集モードの状態機械（U20）とは別軸で持つ。両者を同一の状態キーに混在させない（型・状態キーを分離し、相互に書き換える経路を作らない）。これにより「表示モード切替が編集/追加モードと干渉しない」（FR-42）を構造的に保証する。
- 編集中（追加/編集モード進行中）でも表示制御が機能し、編集の進行中ドラフト・選択を表示制御が破壊しないこと、表示制御の変更が編集確定をトリガーしないことを設計の不変として保つ。

### 個別フォーカスとグローバルの併存（FR-43・教訓 5.30 / 5.29）

- 個別フォーカス対象（縦方向領域）の地物には個別フォーカス深度 `M` を、それ以外の地物にはグローバル `N` を適用する、という**二系統の決定を 1 つの最終決定へ統合**する純粋関数を実装する。統合は「地物が縦方向領域に属するか」で適用する深度を選び、選んだ深度で同一の集約/省略判定（上記の共有実装）を走らせる形にする。
- 縦方向領域の境界（フォーカス対象の上位領域や下位領域）で、グローバル決定と個別決定が矛盾しない統合規則を一意に定義する（例: 同一地物に対し両系統が異なる決定を出した場合、縦方向領域内は `M`、外は `N` を採るという優先規則を明示）。この優先規則を単体テストで固定する（教訓 5.29 の規約固定）。
- 集約形状で描くと決まった地物の**幾何**は、必ず U08 の単一派生形状解決判定の結果を使う。本ユニットは「丸める／丸めない・誰に丸めるか」の選別のみを担い、丸めた集約形状の和は U08 に委譲する。描画・ヒットテスト・ラベル位置が同じ解決判定で動くこと（教訓 5.29）を、U19 と本ユニットの間の契約として固定する。

### 性能（NFR 5.1 / 5.2 / R5）

- 表示決定の再計算は、深度しきい値の変更・フォーカス対象の変更・選択時刻の変更・カメラ変更（視野依存の省略がある場合）のいずれかで走るが、毎フレーム全件再計算しないよう、表示制御状態が変わったときにのみ描画指示を再生成し、U19 の再描画ループ（requestAnimationFrame 集約、U19 のスロットリング）に乗せる。
- スライダーのドラッグ中は高頻度に `N` が変わりうるため、ドラッグ中は軽量に描画指示を更新し（重い再計算を避ける）、必要に応じて U19 のスロットリング（描画更新頻度設定 FR-110）に合流させる（技術方針 R5）。集約形状の幾何（U08 の和）はドラッグ中に毎回再計算せず、U08 側のキャッシュ/解決判定を再利用する前提とする。
- 5,000 オブジェクト規模（NFR 5.2）でも、表示決定（各地物への深度比較と縦方向領域メンバシップ判定）が O(n) 規模で済むよう、縦方向領域は集合（Set）で保持してメンバシップ判定を定数時間にする。親子走査の再帰は U08 の循環遮断つき走査基盤を経由する（教訓 5.28）。

### 層をまたぐ契約の固定（教訓 5.33 / 5.34）

- U19（描画指示の型）・U20（UI 状態ストアの状態キー・マウント先）・U08（階層深度・末端/集約区別・縦方向領域・派生形状解決の API）から受け取る型・構造を型で明示し、偶然の構造一致に頼らない。依存未確定の段階はアダプタ境界を切り、接続時に両側テストで固定する。
- 描画指示（地物 ID ごとの描画する/しない・実形状/集約形状（丸め先 ID）・強調）の構造は、本ユニット（供給側）と U19（消費側）の両側テストで一致を固定する。

### 文言・エラー処理

- 表示制御に関わる UI 文言（「階層深度」「集約表示」「個別フォーカス」等）は日本語のみで、文言を定数モジュールへ集約する（FR-115 / 技術方針 5.5）。i18n 抽象は設けない。
- 範囲外の深度値（負値・森の最大深度超過）を受け取った場合は有効範囲へクランプし、UI で無効な入力を即時に弾く。例外はユーザーフレンドリーな日本語メッセージで扱う（FR-117）。

### テスト（開発ガイド 1.9 / NFR 5.8）

- 表示決定の純粋関数（集約/省略判定・縦方向領域フォーカス統合・最終表示決定）を実装と同時に Vitest で単体検証する。
- 「表示制御を変えてもモード・選択・ドメインの真実が不変」「グローバルと個別フォーカスの併存」「集約形状の丸め先が U08 解決判定と一致」を回帰テストとして固定する。
- U19・U08 との契約（描画指示の型・派生形状解決の共有）は両側テストで固定する（教訓 5.33）。

## 受け入れ基準（テスト可能な形で列挙）

各基準は、可能な限り表示決定の純粋関数の Vitest 単体テスト、UI 状態フックのテスト、または U19/U08 連携の両側テスト（および必要に応じて Playwright for Electron の E2E）で検証する。実描画に依存する確認は、本ユニットが生成する描画指示（中間表現）を対象に検証する（教訓 5.41）。

1. **グローバル深度スライダーで階層深度 ≤ N の集約表示ができ、省略階層が集約形状で描画される（FR-42）**
   - グローバル深度 `N` を与えると、階層深度 `≤ N` の地物が描画対象になり、`> N` の地物は単体としては描画対象から省略されることを、描画指示で確認できる。
   - 深度 `N` の集約地物が、その配下下位領域の和（U08 の派生形状解決判定の結果）＝自身の集約形状で描かれる（描画指示の「集約形状・丸め先」が当該集約地物を指す）ことを確認できる。
   - `N` を変更すると（増やす／減らす）、集約表示の度合いが追従して変わり、`N` を森の最大深度まで上げると全地物が実形状（末端は自身の形状、集約はその時点の派生形状）で描かれることを確認できる。
   - `N` の有効範囲が森全体の最大階層深度から導出され、範囲外の値はクランプされることを確認できる（ツリーごとに最大深度が異なる森でも範囲が破綻しない）。

2. **表示モード切替が編集/追加モードと干渉しない（FR-42）**
   - グローバル深度 `N` の変更・個別フォーカスの設定/解除を行っても、追加/編集モードの状態・選択中ツール・進行中ドラフトが変化しないことを確認できる（表示制御状態とモード状態が別軸であることをテストで固定）。
   - 追加/編集モードを切り替えても、表示制御の状態（`N`・フォーカス対象・深度 `M`・強調）が破壊されず維持されることを確認できる。
   - 表示制御の変更がドメインの真実（地物の親子関係・形状・錨）を変えず、編集確定をトリガーしないことを確認できる（深度変更前後でドメイン状態が不変）。

3. **個別フォーカスで縦方向領域を別深度で深掘り/強調できる（FR-43）**
   - 選択中の地物を起点に、その縦方向領域（上位領域すべて＋自身＋下位領域すべて）が U08 の縦方向領域算出から取得され、その範囲内の地物に個別フォーカス深度 `M` が適用されることを確認できる。
   - `M` をグローバル `N` より深く設定すると、縦方向領域内だけがより深い実形状まで展開され（深掘り）、縦方向領域外はグローバル `N` の集約表示のままであることを描画指示で確認できる。
   - `M` をグローバル `N` より浅く設定した場合も、縦方向領域内は `M`、外は `N` の決定に従うことを確認できる。
   - 縦方向領域の地物に強調指示が付与され、フォーカス解除（選択解除等）で強調と深掘りが解除されてグローバル `N` のみの状態へ戻ることを確認できる。

4. **グローバル深度と個別フォーカスが併存する（FR-43）**
   - グローバル深度 `N` と個別フォーカス（縦方向領域・深度 `M`）の両方が設定された状態で、縦方向領域内の地物は `M`、縦方向領域外の地物は `N` の決定に従う 1 つの統合された表示決定が生成されることを確認できる。
   - 縦方向領域の境界（フォーカス対象の上位/下位）で両系統が異なる決定を出すケースで、定義した優先規則（縦方向領域内は `M`、外は `N`）どおりに一意な決定が出ることを確認できる（規約をテストで固定・教訓 5.29）。
   - 一方（`N` または `M`）だけを変更しても、もう一方の効果が消えない（併存が維持される）ことを確認できる。

5. **集約形状の解決が U19 と同じ判定を共有する（教訓 5.29）**
   - 本ユニットが「集約形状で描く」と決めた地物の幾何が、U08 の単一派生形状解決判定の結果であり、U19 が描画・ヒットテスト・ラベル位置算出に使う形状と同一由来であることを、両側テストで固定できる（描画される集約形状とヒットテスト/ラベルの形状がドリフトしない）。
   - 集約形状（下位領域の和）が飛び地的に複数片になる場合も、全片が描画指示に反映され、片落とし（先頭片だけ採用）が起きないことを確認できる（教訓 5.1）。
   - 本ユニットが集約形状の幾何（ブーリアン和）を独自算出していない（U08 解決判定の結果のみを使う）ことを、設計上の不変として保つ。

6. **回帰・非機能**
   - 表示決定の純粋関数が副作用を持たず、同一入力に同一出力を返す（純粋性）。入力の評価済みツリー状態・縦方向領域集合を破壊的に変更しない。
   - 表示制御の UI/セッション状態が Zustand 層に置かれ、地図描画の高頻度経路（React 再レンダリング）に乗らないことを設計の不変として保つ（技術方針 2.3）。
   - 5,000 オブジェクト規模で表示決定が O(n) 規模で完了し、縦方向領域メンバシップ判定が定数時間（Set）で行われることを確認できる（NFR 5.2）。
   - 地物の表示制御（FR-113）や種別フィルタと、本ユニットの階層深度集約表示を同一機構へ統合していない（過剰共有の戒め・教訓 5.30）ことを設計上の不変として保つ。

## 関連要件（FR-id）

- **FR-42**（should）: グローバル階層深度スライダーで全地物を「階層深度 ≤ N」で集約表示でき、省略される階層の地物は自身の集約形状（下位領域の和）として描画する。表示モードの切替は編集・追加モードと干渉しない。本ユニットが直接達成する。
- **FR-43**（could）: 個別フォーカスとして、選択中地物の縦方向に繋がる領域（上位領域すべて・自身・下位領域すべて）だけを別の深度で深掘り表示・強調表示でき、グローバル深度スライダーと併存する。本ユニットが直接達成する。

本ユニットが土台／前提として関わる（直接の達成責務は依存ユニット側にある）要件:

- **FR-38**（must）: 階層深度は派生値（最上位 0・子は親 +1）で、地物自身に保持せず親子関係から算出。最大深度はツリーごとに異なってよい。本ユニットは U08 が算出した深度を消費し、深度しきい値の範囲導出に用いる。
- **FR-35**（must）: 集約地物は形状属性を保持せず、形状は下位領域の和集合として実行時算出。本ユニットは集約表示で「集約地物を自身の派生形状で描く」決定を行うが、和の算出は U08 に委譲する。
- **FR-34**（must）: 面情報は複数ルートの森構造で階層管理。本ユニットの深度集約表示・縦方向領域フォーカスは森構造の上で動く。
- **FR-71**（must）: 時間変更に応じてメインマップ上の全地物状態を即時更新。本ユニットの表示決定は「評価済みツリー状態」を入力前提とし、時刻変更時は新しい評価済み状態に対して描画指示を再生成する（評価そのものは時間モデル側）。
- **FR-82**（should）: 選択状態に応じた視覚的フィードバック。本ユニットは個別フォーカスの強調指示を U19 へ渡すが、強調の見た目は U19 が描く。
- **FR-115**（must）: UI 表示言語は日本語のみ。表示制御の文言も日本語で定数集約する。

関連する非機能要件: NFR 5.1（高頻度の深度変更・再描画のスロットリング合流、React 描画経路との分離）、NFR 5.2（5,000 オブジェクト規模での表示決定の O(n) 性能）、NFR 5.8（表示決定ロジックの純粋関数化によるテスト容易性）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

### 適用宣言（AI 作業開始ゲート, 開発ガイド 1.6）

着手前に以下の教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として宣言してから実装すること。引用と適用宣言を省略して着手してはならない。

- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」**（引用: 「形状を『子の和として導出する』派生形状では、描画・ヒットテスト・派生サービス・選択など複数経路を、同じ形状解決判定で動かす。判定条件のドリフトは『描画されているのに選択できない』『ラベル位置が描画と違う』等の対概念矛盾を生む。判定を共通関数/共通中間表現へ集約し、規約自体を単体テストで固定する。」）。**適用**: 本ユニットは「どの深度で集約形状に丸めるか」の選別だけを担い、丸めた集約形状の幾何は U08 の単一派生形状解決判定の結果を使う。本ユニットで集約形状を独自算出・別判定で求めない。集約表示する地物の選別と、U19 の描画・ヒットテスト・ラベル位置が同じ U08 解決判定を共有することを受け入れ基準 5 で両側テストで固定する。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / 開発ガイド §4「単一の真実源」** — 適用: 「深度しきい値に基づく集約/省略判定」はグローバル深度と個別フォーカス深度で**同一実装を共有**する（過少共有の戒め）。一方、本ユニットの「階層深度による集約表示」と、地物の表示制御（FR-113）や種別フィルタは制約・対象が本質的に異なるため、見た目が似たトグル UI でも安易に同一機構へ統合しない（過剰共有の戒め）。共有前に「2 つの制約は本当に同一か」を列挙確認する。受け入れ基準 1・4・6 で固定する。

- **教訓 5.13「表示専用モードでは編集経路を一括無効化する」 / FR-42（表示モードと編集/追加モードの非干渉）** — 注意: 本ユニットの「表示制御（階層深度の集約表示）」は、U20 が扱う「表示専用（閲覧）権限」や「追加/編集モード」とは**別軸**の概念である。三者（追加/編集モード・編集可否権限・階層深度表示制御）を混同して同一状態に詰め込むと、深度を変えただけで編集が無効化される等の干渉が起きる。表示制御状態をモード軸・権限軸とは別軸で保持し、相互に書き換えない（FR-42 の「干渉しない」）。受け入れ基準 2 で固定する。

- **教訓 5.25「仕様が限定した対象範囲を実装で広げない」** — 適用: FR-42 は集約表示の対象を「全地物の階層深度 ≤ N」とし、省略階層を「自身の集約形状（下位領域の和）」で描くと限定している。「分かりやすさのため省略階層を非表示にする」「集約形状の代わりにバウンディングボックスで描く」等の直感的拡張を加えない。集約形状は必ず U08 の派生形状（下位領域の和）を使う。受け入れ基準 1・5 で固定する。

- **教訓 5.1「集合演算は複数片を返す前提で扱う」** — 適用: 集約形状（下位領域の和）は飛び地的に複数片・複数リングになりうる。U08 から受け取った全片を描画指示に載せ、配列の先頭片だけ採用する片落としをしない。受け入れ基準 5 で複数片の全反映を固定する。

- **教訓 5.5「依存する状態は変化時に再検証する」** — 適用: グローバル深度 `N`・個別フォーカス対象/深度 `M`・選択時刻（評価済み状態）・選択地物（縦方向領域の起点）のいずれが変わっても、表示決定を再生成し U19 に再描画させる。とくに「選択地物が時刻変更でその時刻に存在しなくなった」場合、縦方向領域の起点が無効になるため、個別フォーカスをグローバル `N` のみへ安全にフォールバックする（選択が無効になったら個別フォーカスを解除する）。受け入れ基準 3 でフォーカス解除の挙動を固定する。

- **教訓 5.28「階層を辿る再帰サービスは循環で無限ループしない」** — 適用: 縦方向領域（上位領域すべて＋下位領域すべて）の列挙は親子グラフを辿る再帰であり、壊れたデータ（循環参照）でも無限ループしてはならない。本ユニットは U08 の循環遮断つき走査基盤（`visited` セットで再入遮断）を経由して縦方向領域を取得し、自前で無防備な再帰を書かない。

- **教訓 5.10「選択状態は生の集合まで評価して網羅する」** — 適用: 個別フォーカスの起点となる選択状態（アクティブ地物あり／頂点選択コンテキストが一意／所有者不明／空選択）を生の状態まで評価し、起点が一意に定まらない場合（複数地物・所有者不明・空）は個別フォーカスを適用せずグローバル `N` のみで描く、という分岐を網羅する。受け入れ基準 3 で「起点なし時はグローバルのみ」を固定する。

- **教訓 5.33 / 5.34（層をまたぐ契約・コンポーネント間契約を型で明示）** — 適用: U19（描画指示の型）・U20（UI 状態ストアの状態キー・マウント先）・U08（階層深度・末端/集約区別・縦方向領域・派生形状解決の API）との契約は文字列の偶然一致に頼らず、共有型・型付きラッパー・両側テストで固定する。依存先 API が未確定なら本ユニット内に境界インタフェース（adapter）を切って未確定部分を局所化し、接続後に両側テストで固定する。

- **技術方針 2.3（React 再レンダリングと地図描画の分離）** — 注意: 深度スライダーのドラッグ中に表示決定を React state に持たせて再レンダリングを誘発すると、5,000 オブジェクト規模で 60FPS（NFR 5.1）が破綻する。表示制御状態は Zustand 層に置き、表示決定の再生成と再描画は U19 の requestAnimationFrame 集約ループに合流させる（技術方針 R5）。受け入れ基準 6 で「React 再レンダリング経路に乗せない」設計不変を保つ。

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」** — 注意: 個別フォーカスは一時的な表示状態である。選択解除・明示的フォーカス解除・選択地物が無効化（時刻変更で非存在）のすべての経路でフォーカス状態を破棄（グローバル `N` のみへ復帰）し、次の操作へ古いフォーカスを引き継がない。受け入れ基準 3 で固定する。

- **クリーンルーム（開発ガイド 3.1）** — 注意: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-42 / FR-43 ほか）・技術方針として直接記述する。

- **検証不能になった範囲は別手段で補う（教訓 5.41 / NFR 5.8）** — 注意: 実描画（Canvas）・U19/U08 連携・UI ストア更新など E2E 寄りで検証しづらい範囲は、表示決定ロジックの純粋関数化・アダプタ分離・モックで単体テスト対象にして補い、未検証のまま放置しない。

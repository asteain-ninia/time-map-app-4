# U02 時間モデル(正規化)と暦設定の純粋ロジック

## 目的

本アプリは歴史を時間軸に沿って網羅的に視覚化・追跡するツールであり、地物の経時的状態は「歴史の錨」によって特定時刻に定義される（FR-54）。錨の前後関係・継続期間・存在判定はすべて時間値の大小比較と差分計算に帰着する。これらの計算を UI の表示精度（年のみ／年月／年月日）や暦法に左右されず一貫して行うため、時間を単一の整数基準へ正規化する純粋ロジックが必要である。

本ユニットは `domain` 層に、時間点（年は必須、月・日は任意で未指定可）を一貫した整数基準値へ正規化し、また逆変換する関数群を実装する。紀元前（負の年）の解釈、月日未指定時の既定補完（1月1日）、時間比較・期間長計算・状態継続判定を、すべて正規化表現に基づいて副作用なく行えるようにする。暦設定（初期実装はグレゴリオ暦）を引数として受け取り、将来の独自歴拡張に備えて暦法に依存しない共通インタフェースを確立する。

この時間モデルは、後続ユニットが扱う歴史の錨（錨列の昇順管理・非重複・状態継続判定）、タイムライン UI（数値ジャンプ・年月日入力欄・存在期間入力）、時間依存データの即時更新の共通土台となる。

## スコープ

### やること

- 時間点を表す型の定義（年は必須、月・日は任意。未指定を「値が無い」状態として型で表現する）。
- 正規化値を表す型の定義（一貫した整数基準値。U02 内で完結する不透明な数値表現とする）。
- 暦設定を表す型と、初期実装としてのグレゴリオ暦設定の定義（年間日数・月構成・うるう年規則を暦設定が保持し、計算関数はすべてこの設定を引数で受け取る）。
- 時間点 → 正規化値 への変換関数（正規化）。月・日が未指定の場合は暦設定に基づく既定値（1月1日）を補完して整数基準へ落とし込む。紀元前（負の年）を正しく扱う。
- 正規化値 → 時間点 への逆変換関数（年・月・日の完全値を返す）。
- 2 つの時間点（または正規化値）の前後比較関数（より前・同時・より後の三値判定）。
- 2 つの時間点（または正規化値）間の期間長計算関数（正規化表現に基づく差分）。
- ある時間点が指定区間（開始時刻・終了時刻）に含まれるかを判定する状態継続判定関数。錨の継続規則（ある開始時刻からその区間の終端直前まで継続する／終端を含まない半開区間）を正規化表現で表現する。
- 年・月・日を分解せず完全値型として受け渡すための入力構築ヘルパー（部分値の単独受け渡しを禁止し、倍率の二重適用を構造的に防ぐ）。
- 入力された時間点が暦設定上妥当か（月が範囲内・日がその月の範囲内・粒度の整合）を判定する検証関数。
- 上記すべてに対する Vitest 単体テストと fast-check プロパティテスト。

### やらないこと

- タイムライン UI コンポーネント・年月日入力欄・未指定トグルの実装（U02 はその計算基盤のみを提供する。UI 層は別ユニット）。
- 歴史の錨そのもののデータモデル・錨列管理（昇順整列・重複解消・再編）の実装（U02 は錨列が利用する時間計算プリミティブのみを提供する。錨列ロジックは別ユニット）。
- 独自歴（地球暦と異なる暦法）の具体実装。U02 は暦設定を引数化して将来拡張に備えるが、初期実装はグレゴリオ暦のみとする。
- 永続化・シリアライズ・Zod スキーマ・IPC 境界検証。
- 再生制御（タイマー・速度倍率の日数換算）の実装。U02 はそれが将来依存する期間計算・換算の純粋関数を提供するに留める。
- Electron / React / Canvas / Zustand への一切の依存。

## 依存（dependsOn）

- **U01**: 本ユニットは U01 が確立する `domain` 層の基盤（プロジェクトのディレクトリ層分離、TypeScript strict 構成、`domain` がフレームワーク非依存で Vitest 実行できる土台、テスト・ビルドの実行導線）の上に実装する。U02 の成果物は U01 が用意した `domain` 層の配置規約に従って置くこと。U01 が共通の型ユーティリティ・ブランド型・等価比較ヘルパー等を提供している場合はそれを再利用し、重複定義を避ける（単一の真実源）。

実装着手時に U01 の成果物（`domain` 層のディレクトリ構成・既存の共通型・テスト設定）を確認し、本ユニットの型・関数の配置と命名をそれに整合させること。

## 実装方針

技術方針（`docs/技術方針.md`）に従い、以下を厳守する。

- **純粋関数・フレームワーク非依存**: 本ユニットは `domain` 層に閉じた副作用のない純粋関数群として実装する。Electron・React・Canvas・Zustand・I/O・現在時刻（システムクロック）への参照を一切持たない。これにより Electron/React 抜きで Vitest 単体実行できる（技術方針 2.13・5.4、NFR 5.8）。
- **TypeScript strict 全有効**: `strict`・`noUncheckedIndexedAccess`・`exactOptionalPropertyTypes`・`noImplicitOverride` を前提とする。月・日の「未指定」は `exactOptionalPropertyTypes` の取り違えを避けるため、`undefined` の混入に頼らず明示的に表現する（後述「注意点」）。配列・月構成テーブルへのアクセスは `noUncheckedIndexedAccess` を満たすよう境界を検査する。
- **不正状態を表現不能にする**: 判別共用体・ブランド型を用い、「部分値だけが渡される」「正規化値と時間点を取り違える」「未正規化の値で比較する」といった不正状態を型で排除する。正規化値は時間点と区別できる別型（ブランド付き）とし、生の `number` と混同させない。
- **暦設定の引数化**: すべての時間計算関数（正規化・逆変換・比較・期間長・状態継続・検証）は暦設定を引数で受け取り、暦法定数（年間日数・各月の日数・うるう年規則）を関数内にハードコードしない。これは将来の独自歴拡張（要件 7.1）に向けた共通ロジック化であり、初期実装ではグレゴリオ暦設定を渡す。
- **単一の真実源**: 月日未指定時の既定補完（1月1日）・紀元前の符号解釈・半開区間の境界規則は、それぞれ一箇所で実装し、比較・期間計算・状態継続判定はその共通実装を経由する。同じ判定を複数箇所に分散させない（開発ガイド 4. 単一の真実源）。
- **完全値での受け渡し**: 年・月・日を分解した一部の値だけを下位層へ渡さず、完全な時間値（型）で受け渡す（後述 受け入れ基準・FR-70・教訓 5.16）。
- **整数基準への正規化**: 正規化値は浮動小数（小数年など）の中間表現を用いず、暦設定に基づく一貫した整数基準で表現する。すべての時間比較・期間計算・状態継続判定は正規化された整数表現に基づいて行う（FR-72・FR-70）。

### 想定する型・関数の構成（命名は実装時に U01 の規約へ整合させる）

以下は実装の指針であり、識別子名は U01 の既存規約・既存共通型に合わせて決定してよい。意味（責務）は維持すること。

- 時間点型: 年（必須・整数・負値可）と、任意の月・日を保持する。月・日は「未指定」を区別できる形で保持し、未指定の場合に部分的な日付（月のみ指定で日が未指定など）の妥当性ルールも型または検証で扱う。
- 正規化値型: 整数基準値を表すブランド付き型。生の `number` と相互代入できないようにする。
- 暦設定型: 各月の日数テーブル・うるう年規則・年間日数を提供する。グレゴリオ暦の具体設定を 1 つ用意する。
- `normalize(timePoint, calendar)`: 時間点 → 正規化値。月・日未指定は 1月1日 を補完。
- `denormalize(normalized, calendar)`: 正規化値 → 時間点（年・月・日の完全値）。逆変換は補完後の完全値（年月日すべて確定した形）を返す方針を採り、往復一致は「補完後の時間点」を基準に保証する（後述 注意点）。
- `compare(a, b, calendar)`: 前後比較（-1 / 0 / +1 など三値）。
- `duration(from, to, calendar)`: 期間長（正規化表現の差分。基準単位を一意に定義する）。
- `isWithin(point, startInclusive, endExclusive, calendar)`: 状態継続判定（半開区間 [start, end) ）。終了時刻が無い（開区間）場合の扱いも定義する。
- `makeTimePoint(...)` 等の完全値構築ヘルパー: 年必須・月日任意を 1 つの値として組み立て、部分値の単独受け渡しを構造的に禁止する。
- `validate(timePoint, calendar)`: 暦設定上の妥当性検証（無効な月・日・粒度を検出し、テスト可能な戻り値で拒否理由を返す）。

## 受け入れ基準

以下はすべてテスト可能な形で満たすこと。テストは実装と同時に作成する（開発ガイド 1.9）。

1. **正規化往復の一致（紀元前・うるう年・月日未指定）**
   - 時間点 → 正規化値 → 時間点 の往復で、補完後の時間点が元の補完後時間点と一致することを単体テストで確認する。
   - 紀元前（負の年）を含む時間点で往復が一致する。
   - うるう年（グレゴリオ暦規則: 4 で割り切れ、100 で割り切れる年は除き、400 で割り切れる年は含む）の 2月29日 を含む時間点で往復が一致し、平年の 2月29日 は検証で無効と判定される。
   - 月・日未指定の時間点は、正規化時に 1月1日 が補完され、逆変換で 1月1日 を持つ完全値が得られることを確認する（往復は補完後の完全値を基準に一致する）。

2. **前後比較・期間長計算の正しさ（正規化表現に基づく）**
   - 任意の 2 時間点について、前後比較が三値で正しく、同一正規化値は同時（0）を返す。
   - 期間長計算が正規化表現の差分に基づき正しい（年境界・月境界・うるう年をまたぐ差分、紀元前→紀元後をまたぐ差分を含む）。
   - 比較・期間長・状態継続判定が、暦設定を引数で受け取った同一の正規化ロジックを経由していることを、テストで確認できる（同じ入力に対し関数間で矛盾しない）。

3. **状態継続判定の半開区間性**
   - 開始時刻は区間に含まれ（境界含む）、終了時刻は含まれない（半開区間 [start, end)）ことを境界値テストで確認する。これは「ある錨の状態は開始時刻から次の錨の開始時刻直前まで継続する」という規則（FR-55）に対応する。
   - 終了時刻が無い場合（開区間）の判定が定義どおり動作する。

4. **fast-check によるプロパティテスト（境界網羅）**
   - 紀元前（負の年）・錨境界（区間の開始/終了ちょうど）・月日未指定の各境界を網羅する生成入力で、以下のプロパティが常に成り立つことを検証する:
     - 往復不変: `denormalize(normalize(x)) === 補完後の x`。
     - 比較の全順序性: 反射律・反対称律・推移律が成り立つ。
     - 期間長と比較の整合: `a < b` ならば `duration(a, b) > 0`、`a == b` ならば `duration(a, b) == 0`。
     - 状態継続の単調性: 区間内の任意点が真、区間外（終了時刻以降を含む）が偽。
   - 生成器（年・月・日・うるう年・未指定トグル・暦設定）は、本ユニット内（または U01 の共通生成器がある場合はそれ）の共有モジュールとして定義し、各プロパティで再利用する（技術方針 R7）。

5. **完全値での受け渡し（教訓 5.16 の適用）**
   - 時間値は年・月・日を分解せず完全値型で受け渡す。API は部分値（年だけ・月だけ等）の単独受け渡しを型レベルで受け付けないことを、型テスト（コンパイル不能となるべきパターンの記録）または構築ヘルパー経由の単体テストで確認する。
   - 期間・換算系の関数で同一の倍率（または基準単位）を二重適用しないことを、関数の責務分離（基準単位の定義箇所が一意であること）と単体テストで確認する。

6. **副作用のない純粋関数として Electron/React 抜きでテストできる**
   - 本ユニットのモジュールは Electron・React・Canvas・Zustand・I/O・システムクロックを import しない。
   - Vitest 単体テストが `domain` 層単独で実行・全パスする。同一入力に対して常に同一出力を返す（決定性）。

## 関連要件（FR-id）

- **FR-65** (must): 特定の時間（年、オプションで月・日）を数値で直接入力してジャンプできる。年を基本単位とし、月・日レベルの精度を扱い、負の年数を紀元前として解釈・表示する。— 本ユニットは年必須・月日任意の時間点型と、紀元前（負の年）の正規化・逆変換・表示可能な完全値返却を提供する。
- **FR-67** (should): 年・月・日を独立した数値入力欄として提示し、月・日には「未指定」のトグルを設け、未指定なら当該粒度の情報を保持しない。入力値の妥当性は暦設定に基づき検証し無効値は即時エラー表示する。初期実装はグレゴリオ暦を前提とする。— 本ユニットは月日未指定（情報を保持しない）の表現と、暦設定に基づく妥当性検証関数を提供する（UI 表示は別ユニット）。
- **FR-70** (should): 存在期間入力はタイムラインと同じ入力コンポーネントを共有し、年必須・月日任意という粒度を統一する。時間変更通知は常に年・月・日を個別値で配信し小数年などの中間表現を使わない。すべての時間操作は暦設定と整合する共通の時間計算ロジックを経由する。— 本ユニットがその「共通の時間計算ロジック」であり、小数年を使わず整数基準で正規化し、完全値（年・月・日）で受け渡す。
- **FR-72** (must): システム内部では時間を一貫した基準で正規化して処理し、UI では年のみ・年月・年月日の各精度で表示・編集できる。全ての時間比較・期間計算・状態継続判定は正規化された時間表現に基づいて行う。— 本ユニットの中核要件。正規化・比較・期間計算・状態継続判定を整数基準で提供する。

（関連: FR-55 の錨継続規則に状態継続判定が対応する。FR-68/FR-69 のステップ・再生は将来別ユニットだが、月日未指定時の既定値補完=1月1日 と年間日数換算の基盤を本ユニットが提供する。）

## 注意点・既知の落とし穴

着手前に、以下の関連教訓を引用し、本ユニットへの適用を宣言してから実装すること（開発ガイド 1.6 AI 作業開始ゲート）。

- **教訓 5.16「時間値は完全値で受け渡し、倍率の二重適用を防ぐ」**: 「年・月・日を分解した一部の値だけを下位層へ渡さず、完全な時間値を受け渡す。再生処理では、速度を表すのが『間隔』か『1 tick あたりの進行量』かを一箇所に決め、両方へ倍率を掛けない（二重適用防止）。」
  - 適用例: 公開 API は完全値型のみを受け取り、年だけ・月だけの部分値を単独で受け取る関数を作らない。期間換算の基準単位（正規化値 1 が表す時間量）を一箇所に定義し、複数関数で別々に倍率を掛けない。

- **教訓 5.18「空配列・空オブジェクトは真値である」**: 月・日の「未指定」を、論理和による短絡評価（`month || 1` 等）で既定補完してはならない。`0`（年 0 = 紀元 1 年境界の扱い、または月 0 などの無効値）が偽値として誤って既定へ落ちる。未指定は型・状態で明示的に判定し、補完は専用の正規化経路でのみ行う。
  - 検出: 年 0・月 0 相当・日 0 相当の入力で既定補完が誤発火しないことを単体テストで確認する。

- **教訓 5.15「タイムスタンプはコンテキスト上の時刻を参照する」**: 本ユニットは純粋ロジックであり、システム時刻（`Date.now()` 等）を一切参照しない。時刻はすべて引数として渡される時間点・正規化値から導く。
  - 検出: モジュールがシステムクロックを import/呼び出ししないことを確認する。

- **教訓 5.19「分岐識別子は型定義・定数・ファクトリを経由する」**: 暦設定の選択（グレゴリオ暦／将来の独自歴）は文字列直書きで分岐せず、型・定数・ファクトリを経由する。

- **紀元前（負の年）の年 0 規約を一意に決める**: 暦の慣習では「紀元前 1 年の翌年が紀元 1 年で、年 0 は存在しない」流儀（天文学的でない）と、「年 0 が存在する」天文学的流儀がある。本ユニットでは内部正規化の連続性・単純性のため**年 0 を許容する天文学的連番**を採用し、UI 表示での紀元前ラベリング（負年の表示変換）は別ユニットに委ねる。採用した規約をコード上の単一箇所（暦設定または定数）に明記し、往復・比較・期間計算すべてがその規約に従うことをテストで固定する。規約を変える場合は全関数とテストを同一変更単位で同期する（開発ガイド 5.31/5.32 の精神）。

- **往復一致の基準は「補完後の完全値」**: 月日未指定の時間点は正規化で 1月1日 が補完されるため、逆変換は元の「未指定」を復元できない（情報が補完で確定する）。よって往復一致の判定基準は「正規化前に既定補完を適用した完全値」と「逆変換結果」の一致とする。テストでこの基準を明示し、未指定そのものの復元を期待しない。未指定という粒度情報の保持（FR-67）は時間点型側で保持し、正規化はあくまで計算用の確定値を生む、という責務分離を守る。

- **半開区間の境界を一意に定義する**: 状態継続判定は [start, end)（開始含む・終了含まない）とする。これは FR-55「開始時刻から次の錨の開始時刻直前まで継続」に対応する。境界ちょうど（point == start, point == end）の真偽をプロパティテストの明示ケースに含める。比較関数・状態継続判定が同じ正規化値ベースで矛盾しないこと（単一の真実源）を保証する。

- **`noUncheckedIndexedAccess` 下の月構成テーブルアクセス**: 各月の日数を配列・テーブルで持つ場合、月インデックスのアクセスは `undefined` 可能性を型が示す。範囲外月は検証関数で先に弾き、正規化・逆変換では検査済みの値のみを使う。境界外参照をコンパイル時に排除する。

- **`exactOptionalPropertyTypes` 下の任意属性**: 月・日の任意性を `month?: number` として `undefined` 代入に頼ると取り違えが起きやすい。未指定を判別可能な明示表現（専用の不在マーカー、または `month` キー自体の不存在を厳密に扱う設計）にし、「未指定」と「無効値」を混同しない。

- **浮動小数を使わない**: 期間計算・正規化に小数年や `number` の累積加算で誤差が出る方式を使わない。整数基準（暦設定で定義した最小単位の整数倍）で計算し、丸め誤差由来の比較不一致を排除する（FR-70「小数年などの中間表現を使わない」）。

- **テスト fixture は実体を経由する（教訓 5.39）**: 暦設定・時間点をテストで構築するときは、リテラルで型を満たすのではなく構築ヘルパー／実体生成を経由し、属性欠落の沈黙通過を防ぐ。

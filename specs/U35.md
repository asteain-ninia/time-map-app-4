# U35 競合解決モーダルUI(ミニマッププレビュー)

本書は実装ユニット U35 の実装指示書である。実装者（別エージェント）はこの指示書だけを読んで着手できる。前提知識は本書の中に閉じて記述する。要件・技術方針・開発作法の根拠は本文および末尾の「関連要件」「注意点・既知の落とし穴」に引用する。

本プロダクトの文書はクリーンルームである。過去版・他プロダクト・外部の既存実装には一切言及しない。必要な制約はすべて time-map-app-4 自身の要件・方針として直接記述する（開発ガイド 3.1）。

## 目的

歴史の錨の追加・編集を確定しようとした際、整合性維持プロセス（U13）が **空間オーバーラップ（地図全体の末端地物同士の重なり）** を検出したときに表示する、専用の **競合解決モーダルダイアログ UI** を構築する。

本アプリのドメインの基本ルールとして、末端地物（形状を持ち下位領域を持たない面情報）同士は地図全体において決して重ならない（境界の接触は重なりに含めない）。ユーザーの編集がこのルールに違反する結果を生むとき、整合性維持プロセスは編集確定を一時停止し、検出した全競合箇所を構造化データとして UI へ引き渡す。本ユニットは、その構造化データを受け取り、ユーザーが各競合をミニマッププレビューで確認しながら解決方針を選び、全競合に方針を指定し終えたら確定（適用）を依頼する、という対話フローを画面上で実現する責務を負う。

具体的には次を一体で実現する。

1. 空間オーバーラップ検出時に専用の競合解決モーダルを表示し、編集確定を一時停止していることをユーザーに伝える（FR-62）。
2. 検出された全競合箇所（作中時間＝時間点または時間範囲・関連する双方の末端地物の表示名・競合種類）をリスト表示する（FR-62）。
3. 各競合に対し、ミニマッププレビューで重なり状況を確認しながら、解決方針（どちらの末端地物を優先し、もう一方をブーリアン演算で差分調整するか）を選択できるようにする（FR-63）。
4. 全競合に解決方針を指定するまで確定（適用）ボタンを無効化し、部分確定を許可しない。適用結果は単一のアンドゥ・リドゥ操作の対象となるよう、U13 へ一括適用を依頼する（FR-63 / FR-73）。
5. 初回ユーザー向けのガイド（このダイアログの読み方・操作手順の説明）を表示する（FR-118）。
6. モーダルとその背面・ミニマップ・リストが重なる構造であることを踏まえ、**入力を受ける層**を描画順と同時に設計し、前面 UI が必要な操作を奪わず、かつ確定前に背面の編集操作が漏れ通らないようにする（開発ガイド 教訓 5.14）。

本ユニットは「競合解決の対話 UI」に責務を限定する。競合の検出・解決方針の適用（差分ブーリアン調整）・単一アンドゥ単位での確定といったドメイン処理そのものは行わず、U13 が供給する構造化データを表示し、ユーザーの選択を U13 へ返すブリッジに徹する。

## スコープ

### やること

- **モーダルの起動と編集確定の一時停止表示（FR-62）**
  - U13 の整合性維持プロセスが「競合あり・要方針指定」の結果（後述「U13 から受け取る入力契約」）を返したとき、専用の競合解決モーダルを表示する。
  - モーダル表示中は編集確定が一時停止されている状態であることを、文言と UI 状態で明示する。モーダルを開いている間、背面（メインマップ・ツールバー・タイムライン等）の編集操作・確定操作が走らないようにする（後述「重なる UI の入力層」）。
  - モーダルの起動契機は「U13 がプロセス結果として競合ありを返したこと」だけに限定し、UI 側でデータソースを直接走査して独自に競合を判定しない（教訓 5.3 / 5.6）。

- **全競合箇所のリスト表示（FR-62）**
  - U13 から受け取った競合箇所リストの **全件** をリストとして表示する。各行は少なくとも次を表示する。
    - 競合が成立する作中時間（時間点、または時間範囲）。年は基本単位、必要に応じて月・日精度、負の年は紀元前として表示する（FR-65 / FR-72 の時間表示方針に整合）。
    - 関連する双方の末端地物の表示名（2 件）。
    - 競合種類（本フローのスコープでは「末端地物同士の空間オーバーラップ（末端重なり）」）。
  - リストは片落としなく全件を表示する。複数の競合が同時に存在する場合も、漏れなく全行が現れること（教訓 5.1 の精神を表示側にも適用、教訓 5.18 空配列＝真値）。
  - 各競合行の解決状態（方針未指定／方針指定済み）を視覚的に区別して表示し、未指定が残っている件数が一目で分かるようにする。

- **ミニマッププレビュー（FR-62 / FR-63）**
  - 各競合について、当該競合に関わる 2 つの末端地物と重なり領域を、競合箇所周辺に拡大した小さなプレビュー地図（ミニマップ）として表示する。プレビューはユーザーが「どこで・どの地物同士が・どの程度重なっているか」を把握し、解決方針を判断するための参考とする（FR-63）。
  - プレビューは、当該競合が成立する作中時間における 2 地物の形状と重なり領域を描く。U13 が競合箇所に保持する重なり領域の幾何情報・2 地物の形状（または形状の参照）を入力として用いる。
  - 選択中の解決方針（どちらを優先するか）に応じて、優先地物・差分調整で削られる側・調整後に残る領域をプレビュー上で見分けられるよう描き分ける（描き分けの具体表現は実装で定めてよいが、穴は常に透過・飛び地は本土同様という面情報の表示規則を崩さないこと。FR-21）。
  - ミニマップ描画は U19 が確立する地物描画の規則・部品を再利用する（後述「実装方針」）。本ユニットでミニマップ用に独自の面塗り規則（穴の塗りつぶし・飛び地の別色化・連結線の付与など）を作らない（FR-21 / 教訓 5.30 過剰共有の戒めと、規則の単一の真実源の両立）。

- **解決方針の選択（FR-63）**
  - 各競合行に対し、解決方針を選択する UI を提供する。解決方針は「優先する末端地物（2 件のいずれか）を選ぶ」ことで定まり、選ばれなかった側がブーリアン演算で差分調整される（優先地物との重なり領域を差し引かれる）対象になる。
  - 選択は競合ごとに独立して行え、選択結果は当該競合の解決状態（指定済み）へ反映され、リスト表示・ミニマッププレビュー・確定ボタンの有効/無効に即時連動する。
  - 一度選んだ方針を選び直せる（指定済み→別の優先地物へ変更）こと。変更時もプレビュー・状態表示が追従する。
  - 解決方針の選択値は、U13 が要求する解決方針の形（対象競合の識別子・優先地物 ID・調整対象地物 ID）へ写像して保持する。優先地物 ID と調整対象地物 ID は当該競合の 2 地物から決定論的に導く（優先＝選択した側、調整対象＝もう一方）。

- **全競合解決までの確定抑止と単一アンドゥ単位での適用（FR-63 / FR-73）**
  - 「適用（確定）」ボタンは、**全競合に解決方針が指定されるまで無効** とする。未指定が 1 件でも残る間は確定操作を発火させない（部分確定の禁止）。
  - 全競合に方針が揃った状態で適用ボタンが押されたら、収集した全解決方針を U13 へ渡し、一括適用＝単一アンドゥ単位での確定を依頼する。本ユニットは差分ブーリアン調整・空間再検出・コマンド確定を自前で行わず、U13 へ委譲する（後述「依存」）。
  - U13 が「差分調整の結果さらに新たな競合が出た（要再指定）」を返した場合に備え、本ユニットは U13 から返ってきた更新後の競合リストで表示を再構成し、ユーザーに再度方針指定を促せること（収束ループは U13 が管理し、UI は最新の競合リストを反映する役）。U13 が「収束失敗（拒否）」を返した場合は、その日本語メッセージをユーザーに提示する（FR-115 / FR-117）。
  - キャンセル経路を用意する。キャンセル時は編集確定を取りやめ（一時停止していた編集案を確定しない）、本ユニットが保持していた一時的 UI 状態（選択中の方針ドラフト・プレビュー状態など）を全経路で破棄する（教訓 5.2）。キャンセルでドメイン状態を変更しないこと（U13 へ適用を依頼しない）。

- **初回ユーザー向けガイド（FR-118）**
  - 競合解決モーダルの読み方・操作手順（「重なりが見つかったため確定を保留している」「各競合で残す側を選ぶ」「もう一方は重なり分が自動で削られる」「全件を選ぶと適用できる」等）を説明する初回ガイドを表示する。
  - ガイドは少なくとも初回表示時に提示し、以降は抑制できる（再表示する手段も用意する）。ガイドの表示/抑制状態はアプリ全体の UI 設定として扱う（プロジェクト固有データには持たせない。境界は後述）。
  - ガイド文言は日本語のみ（FR-115）。

- **重なる UI の入力層の設計（教訓 5.14）**
  - モーダル本体・背面バックドロップ・競合リスト・ミニマッププレビュー・ガイド・確定/キャンセルボタンが重なり合う構造であることを前提に、描画順（z 順）だけでなく **入力を受ける層** を同時に設計する。
  - 背面バックドロップは、モーダル外（メインマップ・ツールバー・タイムライン等）への入力を確定前に奪い・遮断する役を担う（編集確定の一時停止を入力層レベルでも保証する）。一方で、モーダル内部の操作要素（リスト行の選択、方針選択コントロール、ミニマップの操作、ボタン）が、上に重なる透明層・装飾層に入力を奪われず確実に届くようにする。
  - 透明な層が必要な操作ハンドルやコントロールを覆って操作不能にしないことを、入力到達のテストで確認できる構造にする。

- **文言とアクセシビリティ**
  - すべての UI 文言（タイトル・列見出し・ボタン・ガイド・エラー）は日本語で定数モジュールへ集約する（FR-115、技術方針 5.5 の i18n 抽象なし方針）。
  - キーボード操作（フォーカス移動・確定/キャンセルのショートカット相当）でも一通り操作でき、モーダル表示中はフォーカスがモーダル内に留まる（背面へフォーカスが抜けない）こと。

### やらないこと

- 空間競合検出アルゴリズム・空間インデックス（RBush）の実装・末端地物ペアの重なり判定（U10 の責務。本ユニットは検出結果を表示するだけ）。
- 差分ブーリアン演算そのものの実装（優先地物との重なり領域を調整対象から差し引く面の差分計算。U06 の責務。本ユニットは「優先／調整対象」を U13 へ渡すだけ）。
- 整合性維持プロセスの固定順序オーケストレーション（編集案生成→時間整合性検証→空間競合検出→競合解決→一括確定）・収束ループの管理（U13 の責務）。本ユニットは U13 のプロセス結果を表示し、ユーザーの解決方針を U13 へ返すブリッジに徹する。
- アンドゥ・リドゥの二重スタック・コマンド適用機構・単一アンドゥ単位での確定の実体（U12／U13 経由の責務）。本ユニットは「全方針を渡して一括適用してほしい」と依頼するだけで、確定の不可分性を自前で保証しない。
- 時間整合性（錨列の昇順・非重複・有効期間）の検証（U09／U13 の責務）。本フローは空間オーバーラップ競合に限る。時間制約違反は U13 が別途「拒否」として返すため、本ユニットは（受け取った場合のみ）その日本語メッセージを提示する程度に留める。
- メインマップ本体（中央の地図描画）の描画・カメラ制御・無限横スクロール・経度シフト（U19／U17／U05 の責務）。本ユニットが用意するのはミニマッププレビューであり、メインマップは描かない。
- 末端地物以外（集約地物・線情報・点情報）の競合表示。空間排他は末端地物同士のみが対象であり、対象範囲を広げない（FR-26 / FR-27、教訓 5.25）。
- 分割確定後のプロパティ継承先選択モーダル（FR-93）など、別フローのモーダル。これらは別ユニットの責務であり、本ユニットは空間競合解決モーダルに限定する。
- ドラッグ中のリアルタイム衝突判定・エッジ滑り（FR-28 / FR-89）。これは「操作確定時のフル整合性」ではなく別系統の責務。

## 依存（dependsOn）

実装着手時点でこれらの公開インタフェースを利用する前提とし、未確定の場合は本ユニット内に最小の型境界（アダプタ）を切って後で接続し、接続時に両側テストで契約を固定する（教訓 5.33 / 5.34）。層をまたぐ契約（状態キー・関数名・データ構造）は偶然の一致に頼らず共有型・両側テストで固定する。

- **U13 — 整合性維持プロセスの骨格（固定順序オーケストレーション）**
  本ユニットの中核データ供給元かつ適用依頼先。U13 は次を提供する前提とする。
  - **プロセス結果（判別共用体）**: 「確定済み」「競合あり・要方針指定」「拒否（理由つき）」のいずれか。本ユニットは「競合あり・要方針指定」を受けてモーダルを表示する。
  - **競合箇所（Conflict 相当）**: 競合成立時間（時間点または時間範囲）・関連地物 2 件の ID と表示名・競合種類（末端重なり）・プレビュー用の重なり領域の幾何情報を持つ構造化値。本ユニットはこれをリスト行・ミニマップ描画の入力に用いる。
  - **解決方針（Resolution 相当）の受理**: 対象競合の識別子・優先地物 ID・調整対象地物 ID を持つ値の集合を受け取り、「方針適用と再評価」を実行する関数（概念: `(現在状態, 編集案, 解決方針集合) → プロセス結果`）。本ユニットは全競合に方針が揃った状態でこれを呼び、結果（確定済み／さらに競合あり／拒否）を表示へ反映する。
  > U13 の入出力契約（編集案・競合箇所・解決方針・プロセス結果の型）に依存する。本ユニットはこれらを再定義せず、U13 が公開する型を import して使う。U13 未確定時は U13 仕様（U13.md の「成果物・公開インタフェース」）に沿った型インタフェースを本ユニット内のアダプタに先に定義し、その型に対して UI とテストを実装する。

- **U20 — アプリレイアウトシェルとモード/ツールバー骨格**
  本ユニットのモーダルが嵌まる UI シェルと共通操作性基盤を提供する。U20 は次を提供する前提とする。
  - **ドラッグ可能パネル/モーダルの器**（複数同時表示・前面化 z 順を扱う枠組み）、**重なる UI の入力層の層構造**（オーバーレイ・バックドロップ・モーダルと中央マップ入力レイヤの描画順＋入力層の設計、教訓 5.14）。本ユニットはこの器・層構造の上に競合解決モーダルを載せ、独自に重なり層を再発明しない。
  - **ツールチップ**・**キーボードショートカット基盤**・**日本語文言の定数集約**の方針。本ユニットのガイド・操作ガイドツールチップ・ショートカットはこの基盤に乗せる。
  - **UI/セッション状態の薄いストア**（U20 が依存する状態管理基盤）。本ユニットのモーダル開閉状態・選択中方針ドラフト・ガイド表示状態などの UI 一時状態は、この状態管理基盤の上に置き、ドメインの真実を二重に持たない。

- **U19 — 地物描画（点/線/面・穴透過・飛び地独立・派生集約形状・ラベル・LOD）**
  ミニマッププレビューで地物（末端面・重なり領域）を描くための描画規則・部品を提供する。U19 は穴の透過・飛び地の独立描画・スクリーン基準のサイズ固定（FR-17 / FR-21）等の規則を確立しており、本ユニットはミニマップ描画でこれらの規則・描画部品を再利用する。本ユニットでミニマップ専用の面塗り規則を独自に作らない（FR-21 / 教訓 5.30 / 教訓 5.29 派生形状・描画規則の単一の真実源）。
  > 本ユニットのミニマップは、U19 の描画規則に、競合解決固有の入力（当該時刻の 2 地物形状・重なり領域・優先/調整対象の描き分け指示）とミニマップ向けの局所カメラ変換（競合周辺へのフィット）を与えて描く。U19 の描画コマンド生成（中間表現）を再利用できる形に接続する。

> dependsOn に挙がっていない関心事（競合検出・差分演算・時間検証・コマンド確定の実体）には依存しない。本ユニットは `ui` 層（React）に属し、`domain` を内向きに参照するのみで、`domain` から逆参照されない（技術方針 2.13 の依存方向）。ミニマップ描画で `render` 層（U19）を利用する際も、`ui → render` / `ui → domain` の内向き方向を守る。

## 実装方針（技術方針に沿う）

技術方針の採用スタック（TypeScript strict・React 18・Canvas 2D 描画層・Zustand＋純粋ドメインコア・層分離）と依存方向ルールに厳密に従う。

### 配置と層分離

- 本ユニットのコードは `ui` 層（React）に属する。モーダル・リスト・方針選択コントロール・ガイドは React の関数コンポーネントで構築する（技術方針 2.3 の「業務 UI・モーダルは React」方針）。
- ミニマッププレビューの地物描画は U19 の描画層（`render`、Canvas 2D / `MapRenderer` 規則）を利用する。高頻度描画を React の再レンダリングサイクルに載せない規律（技術方針 2.3）に従い、ミニマップの実描画は命令的描画層へ委譲し、React 側は描画境界（マウント先コンテナ・寸法・描画対象データの差し替え）を扱うに留める。ただしミニマップは静的に近い小領域であり、メインマップのような毎フレーム高頻度更新ではないため、再描画はプレビュー対象（選択中競合・選択中方針）が変わったときに限る（無駄な再描画をしない、教訓 5.5 依存状態変化時のみ再生成）。
- UI/セッション状態（モーダル開閉・選択中競合・選択中方針ドラフト・ガイド表示状態）は U20 の状態管理基盤（薄いストア）に置く。本ユニットでドメインの真実（地物・錨・ツリー）を持たない（技術方針 2.5）。

### データの流れ（単方向）

- 入力: U13 のプロセス結果（競合あり・要方針指定）。本ユニットはこれを **唯一の真実源** として表示を組み立て、UI 側でデータソースを再走査して独自に競合を作らない（教訓 5.3 操作対象は表示状態に限定 / §4 単一の真実源）。
- 内部状態: 競合ごとの「選択中の優先地物（＝解決方針ドラフト）」。これは確定までの一時 UI 状態であり、確定（適用依頼）成功・キャンセル・モーダル再構成のすべての経路で破棄/再設定する（教訓 5.2）。
- 出力: 全競合に方針が揃ったとき、解決方針集合を U13 の「方針適用と再評価」へ渡す。結果（確定済み／さらに競合あり／拒否）を受けて、モーダルを閉じる／競合リストを再構成する／日本語エラーを提示する、のいずれかに分岐する。

### 確定の抑止と単一アンドゥ単位（FR-63 / FR-73）

- 「全競合に方針指定済みか」は、派生済みのヘルパー結果（例: 残件数）だけでなく、各競合の方針ドラフトの **生の有無** を全件評価して判定する（教訓 5.10 / 5.18 空配列・空集合は真値）。「未指定 0 件＝適用可」を取り違えない。
- 適用は U13 への単一の依頼として行い、本ユニットは差分調整・確定を分割実行しない。単一アンドゥ単位での確定の不可分性は U13／U12 が保証する。本ユニットは「全方針を一度に渡す」ことでその前提を崩さない（教訓 5.22 確定まで共有データを破壊的に更新しない＝UI 側で部分適用を先行させない）。

### 重なる UI の入力層（教訓 5.14）

- モーダルは U20 の「ドラッグ可能パネル/モーダルの器」と「重なる UI の入力層」基盤の上に載せる。バックドロップ層は確定前にモーダル外（メインマップ・ツールバー・タイムライン）への入力を遮断し、編集確定の一時停止を入力層でも担保する。
- モーダル内部のインタラクティブ要素（リスト行選択・方針選択・ミニマップ操作・ボタン）は、装飾用の透明オーバーレイ・ハイライト層に入力を奪われない層順で配置する。前面 UI の期待操作が通り、確定前は背面操作が漏れ通らないことをテストで確認できる構造にする（受け入れ基準で固定）。

### 文言・エラー処理・初回ガイド

- すべての文言は日本語のみで定数モジュールへ集約する（FR-115、技術方針 5.5）。i18n 抽象レイヤは設けない（将来の FR-7.2 に備え集約に留める）。
- U13 から「拒否（収束失敗／時間制約違反／制約違反）」が返った場合は、その機械可読な種別に対応する日本語メッセージを提示し、内部不整合相当には「開発者へ報告してください」を付与する（FR-115 / FR-117）。本ユニットでエラー文言を握りつぶさない。
- 初回ガイドの表示/抑制状態はアプリ全体の UI 設定として一貫した保存先・反映先に置く（プロジェクト固有設定と混同しない。境界は教訓 5.36／後述「設定境界」）。

### 設定境界（教訓 5.36）

- 「競合解決ガイドを初回に表示する／二度目以降抑制する」状態は、プロジェクトに紐づく内容ではなくアプリ全体の利用者向け体験設定であるため、アプリ全体設定（FR-110 系のアプリ設定）側に置く。プロジェクト固有設定（FR-109）には持たせない。保存先と反映先を一貫させる。

### テスト容易性（NFR 5.8 / 教訓 5.41）

- UI から切り出せるロジック（解決方針ドラフトの集約と「全件指定済みか」の判定、競合リストの表示モデル生成、ミニマップ描画対象＝当該時刻の 2 地物形状＋重なり領域＋描き分け指示の組み立て、時間点/範囲の日本語表示文字列の整形）は、React/Canvas から分離した純粋関数・純粋フックとして実装し、Vitest で副作用なく単体検証できるようにする。
- ミニマップの実描画は U19 の描画コマンド列（中間表現）を対象に検証し、Canvas 実描画への委譲層を薄く保つ（教訓 5.41）。
- 重なる UI の入力層は、前面/背面の期待操作が通る（または適切にブロックされる）ことを確認するテストを置く（教訓 5.14 の検出）。
- 「選択→キャンセル→再表示」「選択→適用→再表示（再競合）」相当の連続操作で、一時 UI 状態が漏れなく破棄されることを確認する（教訓 5.2 の検出）。

## 受け入れ基準（テスト可能な形で列挙）

可能な限り、UI から切り出した純粋関数・純粋フックの Vitest 単体テスト、React コンポーネントテスト、または Playwright for Electron の E2E で検証する。ミニマップ実描画に依存する確認は U19 の描画コマンド列（中間表現）を対象に検証する。

1. **空間オーバーラップ検出時のモーダル表示と確定の一時停止（FR-62）**
   - U13 のプロセス結果が「競合あり・要方針指定」のとき、競合解決モーダルが表示され、編集確定が一時停止されている旨が UI 上に表示される。
   - U13 の結果が「競合なし（確定済み）」のときは本モーダルが表示されないこと（不要表示の回帰防止）。
   - モーダル起動契機が「U13 のプロセス結果」だけに依存し、UI 側がデータソースを直接走査して独自に競合を判定していないこと（入力＝U13 結果のみで表示が決まることをテストで固定、教訓 5.3 / 5.6）。

2. **全競合箇所のリスト表示（FR-62）**
   - U13 から受け取った競合箇所リストの全件がリスト行として表示される。複数競合の入力で全行が漏れなく現れること（片落としなし、教訓 5.1 / 5.18）。
   - 各行が「作中時間（時間点または時間範囲。負の年は紀元前として表示）」「双方の末端地物の表示名 2 件」「競合種類（末端重なり）」を表示する。時間表示文字列の整形（年のみ／年月／年月日、時間範囲、紀元前）を純粋関数で固定する。
   - 各行の解決状態（未指定／指定済み）が視覚的に区別され、未指定件数が UI から判別できる。

3. **ミニマッププレビューの表示（FR-62 / FR-63）**
   - 各競合に対し、当該競合の 2 地物と重なり領域を競合周辺に拡大したミニマップが表示される。プレビューは当該競合の作中時間における 2 地物形状と U13 提供の重なり領域を描く。
   - 選択中の解決方針（優先地物）に応じて、優先地物・差分調整で削られる側・調整後に残る領域が描き分けられ、優先地物を切り替えるとプレビューが追従する。
   - ミニマップの面描画が、穴は透過・飛び地は本土同様という規則（FR-21）を恒常表示と同一規則で守り、ミニマップ専用の塗り規則（穴塗りつぶし・飛び地別色・連結線）を作っていないこと（U19 の描画規則・コマンド列の再利用で固定、教訓 5.29 / 5.30）。

4. **解決方針の選択（FR-63）**
   - 各競合行で「優先する末端地物（2 件のいずれか）」を選択でき、選択により当該競合の解決方針（対象競合の識別子・優先地物 ID・調整対象地物 ID）が決定論的に定まる（優先＝選択側、調整対象＝もう一方）。
   - 競合ごとに独立して選択でき、選び直し（指定済み→別の優先地物）が可能で、選択変更がリスト状態・ミニマッププレビュー・適用ボタンの有効/無効に即時連動する。

5. **全競合解決まで未確定／適用後は単一アンドゥ単位（FR-63 / FR-73）**
   - 未指定の競合が 1 件でも残る間、適用（確定）ボタンが無効で、確定操作が発火しない（部分確定の禁止）。
   - 全競合に方針が揃うと適用ボタンが有効になり、押下で収集した全解決方針集合が U13 の「方針適用と再評価」へ一度に渡される。本ユニットが差分適用・確定を分割実行しないこと（U13 へ 1 回の依頼として渡すことを固定）。
   - 「全件指定済みか」の判定が、生の方針ドラフト集合を全件評価して行われること（派生ヘルパーの値だけに依存しない、教訓 5.10 / 5.18）。

6. **差分調整後の再競合とエラー提示（FR-63 の収束 / FR-115 / FR-117）**
   - U13 が適用結果として「さらに競合あり（更新後の競合リスト）」を返した場合、本ユニットは更新後の競合リストでモーダル表示を再構成し、ユーザーに再度方針指定を促す（最新の競合リストを反映する）。
   - U13 が「拒否（収束失敗等）」を返した場合、対応する日本語メッセージを提示する。内部不整合相当には「開発者へ報告してください」を付与する。

7. **キャンセルと一時状態の破棄（教訓 5.2）**
   - キャンセル時、編集案は確定されず（U13 へ適用依頼を出さず）、ドメイン状態が変更されない。
   - 「選択→キャンセル→再表示」「選択→適用→（再競合で）再表示」の連続で、前回の選択中方針ドラフト・プレビュー状態などの一時 UI 状態が次回へ引き継がれず破棄されること。

8. **初回ユーザー向けガイド（FR-118）**
   - 初回表示時にガイド（読み方・操作手順）が日本語で表示される。二度目以降は抑制でき、再表示する手段がある。
   - ガイドの表示/抑制状態がアプリ全体設定側に保存され、プロジェクト固有設定に書き込まれないこと（教訓 5.36 の境界）。

9. **重なる UI の入力層（教訓 5.14）**
   - モーダル表示中、バックドロップにより背面（メインマップ・ツールバー・タイムライン等）の編集/確定操作が確定前に遮断される。
   - モーダル内部のインタラクティブ要素（リスト行選択・方針選択・ミニマップ操作・適用/キャンセルボタン）への入力が、上に重なる装飾/透明層に奪われず確実に到達する。前面の期待操作が通り、背面操作が漏れ通らないことをテストで確認できる。
   - モーダル表示中はフォーカスがモーダル内に留まり、背面へ抜けない。

10. **層分離と日本語 UI（技術方針 2.3 / 2.13・FR-115）**
    - 本ユニットのコードは `ui` 層に属し、依存方向ルール（`ui → render` / `ui → domain` の内向き、`domain` から逆参照しない）に違反しない（lint で確認できる）。
    - ミニマップの高頻度描画状態を React state に持たせず、描画は U19 の描画層へ委譲し、再描画はプレビュー対象が変わったときに限ること。
    - すべての UI 文言（タイトル・列見出し・ボタン・ガイド・エラー）が日本語で定数モジュールに集約されていること。

## 関連要件（FR-id）

- **FR-62**（must）: 空間的オーバーラップ（地図全体の末端地物同士の重なり）が検出された場合、専用の競合解決モーダルダイアログを表示し、編集確定を一時停止する。検出された全競合箇所（作中時間/時間範囲・関連地物名・競合種類）をリスト表示する。本ユニットがこのモーダルとリスト・確定一時停止表示を担う（検出は U10／U13）。
- **FR-63**（must）: ユーザーは各競合箇所をミニマップでのプレビューを参考に解決方針（どちらの地物を優先し、もう一方をブーリアン演算で差分調整するか）を選択する。全競合に方針を指定するまで編集は確定されず、適用後は単一のアンドゥ・リドゥ操作の対象とする。本ユニットがミニマッププレビュー・方針選択・確定抑止・一括適用依頼を担う（差分演算は U06、確定は U13／U12）。
- **FR-118**（should）: 学習容易性（直感的な UI 配置とフロー、ツールチップとヘルプテキスト、チュートリアルと例示、特に競合解決ダイアログの初回ユーザー向けガイド）。本ユニットが競合解決モーダルの初回ガイドを担う。

補助的に関与する要件（本ユニットでは表示・連動のみを担い、実処理は依存ユニット）:

- **FR-26 / FR-27**（must）: 末端地物同士のみが空間排他の対象。本ユニットは末端重なりの競合のみを表示し、対象範囲を集約地物・線・点へ広げない（教訓 5.25）。
- **FR-21**（must）: 穴は常に透過・飛び地は本土同様に独立描画。本ユニットのミニマップ描画もこの規則を恒常表示と同一規則で守る。
- **FR-65 / FR-72**（must）: 作中時間の表示（年基本・月日任意・紀元前・正規化された時間）。本ユニットのリスト行の時間表示がこの方針に整合する。
- **FR-73**（must）: 複合操作（競合解決を含む）を単一アンドゥ単位として扱う。本ユニットは全方針を一括で U13 へ渡し、この前提を崩さない。
- **FR-115**（must）: UI 表示言語は日本語のみ。エラーメッセージも日本語で表示し、必要に応じて「開発者へ報告してください」を付与する。
- **FR-117**（should）: 例外の捕捉とユーザーフレンドリーな日本語エラーメッセージ表示。

関連する非機能要件: NFR 5.1（ミニマップ再描画を依存状態変化時に限り、React 再レンダリングと地図描画を分離）、NFR 5.7（日本語のみ UI）、NFR 5.8（UI から切り出したロジックの純粋テスト容易性）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

### 適用宣言（AI 作業開始ゲート, 開発ガイド 1.6）

着手前に以下の教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として宣言してから実装すること。引用と適用宣言を省略して着手してはならない。とくに教訓 5.14 は本ユニットの受け入れ基準に直結する。

- **教訓 5.14「重なる UI は入力を受ける層も同時に設計する」**（引用: 「重なり合う UI（オーバーレイ・バックドロップ・ハンドル・モーダル）は、描画順だけでなく入力を受ける層も同時に設計する。透明な背景層が操作ハンドルを覆うと、見た目は正しくても操作が奪われる。」）。**適用**: 本ユニットの競合解決モーダルは、バックドロップ・モーダル本体・競合リスト・ミニマップ・ガイド・ボタンが重なる。描画順だけでなく入力層を同時に設計し、バックドロップが確定前に背面の編集操作を遮断しつつ、モーダル内部のインタラクティブ要素が透明/装飾層に入力を奪われないようにする。受け入れ基準 9 で前面/背面の入力到達を検証する。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」**: 選択中の解決方針ドラフト・ミニマッププレビュー状態は、適用成功・キャンセル・再競合による再構成・モーダル再表示のすべての経路で明示的に破棄/再設定する。残ると次回の競合解決へ意図しない方針が引き継がれる。受け入れ基準 7 で確認する。
- **教訓 5.3「操作対象は表示状態に限定する」 / 5.6「状態変化の検出は結果状態で判定する」**: モーダルの起動と表示内容は「U13 のプロセス結果」という表示状態（供給データ）に限定し、UI 側でデータソース全体を走査して独自に競合を作らない。受け入れ基準 1 で固定する。
- **教訓 5.10「選択状態は生の集合まで評価して網羅する」 / 5.18「空配列・空オブジェクトは真値である」**: 「全競合に方針指定済みか」を、派生ヘルパー（残件数等）だけでなく生の方針ドラフト集合を全件評価して判定する。「未指定 0 件＝適用可」を論理和の短絡デフォルトで誤判定しない。受け入れ基準 5 で固定する。
- **教訓 5.1「集合演算は複数片を返す前提で扱う」**: 差分ブーリアン調整の結果（U06／U13 側）は複数片・複数リングになりうる。ミニマップで「調整後に残る領域」を描く際、全片を描き先頭片だけ採用する片落としをしない。リスト表示でも全競合を片落とししない。受け入れ基準 2・3 で固定する。
- **教訓 5.25「仕様が限定した対象範囲を実装で広げない」**: 空間排他は末端地物同士のみ（FR-26 / FR-27）。「分かりやすさのため集約地物の重なりも表示する」「線・点の交差も競合扱いにする」といった直感的拡張を加えない。本ユニットは U13 が末端重なりとして渡した競合のみを表示する。受け入れ基準 1・2 で対象範囲を固定する。
- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」 / 5.30「過少共有と過剰共有の両方を戒める」**: ミニマップの地物描画（穴透過・飛び地独立・派生集約形状・サイズ固定）は U19 の描画規則を再利用し、ミニマップ専用の塗り規則を独自に作らない（過少共有の戒め＝規則の単一の真実源）。一方、競合解決固有の描き分け（優先/調整対象/残領域）はミニマップ固有の関心事であり、無理に汎用描画へ畳み込まない（過剰共有の戒め）。受け入れ基準 3 で固定する。
- **教訓 5.22「確定まで共有データを破壊的に更新しない」**: 全競合解決と U13 の一括適用成功までは、UI 側で部分適用を先行させたり共有ドメイン状態を更新したりしない。本ユニットは全方針を 1 回で U13 へ渡し、確定の不可分性（FR-73 / FR-94）を崩さない。受け入れ基準 5 で固定する。
- **教訓 5.5「依存する状態は変化時に再検証する」**: 選択中競合・選択中方針・U13 から返った更新後競合リストのいずれが変わっても、それに依存する表示（リスト状態・ミニマップ・適用ボタン有効/無効）を再生成する。再競合でリストが入れ替わったのに古い選択が残る、といった取りこぼしを避ける。受け入れ基準 4・6 で固定する。
- **教訓 5.36「プロジェクト設定とアプリ全体設定の境界を先に定義する」**: 初回ガイドの表示/抑制状態は、プロジェクト固有設定（FR-109）ではなくアプリ全体設定（FR-110 系）に置く。保存先と反映先を一貫させる。受け入れ基準 8 で固定する。
- **教訓 5.19「分岐識別子は型定義・定数・ファクトリを経由する」**: 競合種類（末端重なり）・解決方針の優先/調整対象の区別・モーダルの状態（表示中／適用待ち／再競合／拒否）は、表示文字列や思い込みで分岐せず型定義・定数を経由する。
- **教訓 5.33 / 5.34（層をまたぐ契約・コンポーネント間契約を型で明示）**: U13（プロセス結果・競合箇所・解決方針）・U20（モーダル器・入力層・状態ストア）・U19（描画規則・描画コマンド列）との契約（型・構造・キー名）を共有型・型付きラッパー・両側テストで固定する。依存先 API が未確定なら本ユニット内に境界インタフェース（アダプタ）を切り、未確定部分を局所化して接続時に両側テストで固定する。
- **教訓 5.41「検証不能になった範囲は別手段で補う」**: ミニマップの Canvas 実描画・モーダルの重なり入力層など E2E 寄りで検証しづらい範囲は、純粋関数化（描画対象データ組み立て・表示モデル生成・全件指定済み判定）・描画コマンド列検証・入力到達テストで単体検証対象にして補い、未検証のまま放置しない。
- **性能（NFR 5.1）**: ミニマップはメインマップのような毎フレーム高頻度更新を要さない。再描画はプレビュー対象（選択中競合・選択中方針）が変わったときに限り、選択操作のたびに無駄な全再描画をしない。描画状態を React state に持たせない（技術方針 2.3）。
- **クリーンルーム原則（開発ガイド 3.1）**: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-62 / 63 / 118 ほか）・技術方針・開発ガイドの教訓として直接記述・参照する。
- **依存先未確定への備え**: U13 / U20 / U19 の API が確定していない場合でも、本ユニットは境界インタフェース（アダプタ）越しに依存することで着手可能。アダプタの契約は型で明示し、依存先確定後に接続して両側テストで固定する（教訓 5.33）。状態の真実は U20 の状態管理基盤・U13 の供給データに置き、本ユニットでドメインの真実を二重に持たない。

# U07 リング階層モデルと不変条件検証（領土→穴交互/包含/非交差）

## 目的

面情報（ポリゴン）の形状は、複数の閉じた頂点配列（リング）からなる階層構造で表現される。本ユニットは、この**リング階層モデル**と、それに課される**不変条件の検証**、および**リング削除時の交互構造を維持する再編**を、副作用のない純粋ロジックとして提供する。

具体的には次の三つを満たす関数群を実装する。

1. リング階層が常に「領土リング→穴リング→領土リング→…」と階層深度方向に交互となる不変条件（FR-24）を機械的に検証できる。
2. 穴リングの親内部への完全包含・境界非交差、同じ親を持つ兄弟リング同士の非交差、飛び地（独立した外周リング）の他外周との非重複（FR-25）を、リアルタイムに呼び出せる粒度で検証できる。
3. 穴リング/領土リングの削除時に、交互構造を保つよう子リングを付け替える再編を純粋関数として行う（FR-24 の削除と再編）。削除と再編は単一操作として前後状態をテストできる（FR-24）。

本ユニットは描画・UI・永続化・空間インデックス・編集コマンド（アンドゥ／リドゥの履歴積み）には踏み込まない。これらの上位機能が呼び出す**判定と再編の単一の真実源**を、純粋関数として切り出すことが目的である。

## スコープ

### やること

- **リング階層モデルの定義**: 面情報の形状を構成するリング集合と、その親子関係（どのリングがどのリングの内部に含まれるか）を表すデータモデルを定義する。各リングは「領土リング」「穴リング」の役割を判別共用体で持つ。階層深度（最外周の領土リングを 0 とし、内側に入るごとに +1）は階層構造から派生する値として算出し、リング自身には保持しない。
- **交互不変条件の検証**（FR-24）: 親から子へ辿る各経路で役割が「領土→穴→領土→…」と交互になっていること、最外周（親なし）のリングがすべて領土リングであることを検証する純粋関数を提供する。
- **包含・非交差の幾何検証**（FR-25）: 次をそれぞれ独立に検証できる純粋関数を提供する。
  - 穴リングが親リングの内部に**完全包含**され、かつ親リングの境界と**交差しない**こと。
  - 同じ親を持つ**兄弟リング同士が交差しない**こと（互いに分離、または一方が他方を内包する関係を許すかは「注意点」を参照）。
  - **飛び地**（同一面情報に属する別の最外周領土リング）が、他の外周リングと**重ならない**こと。
- **リング削除時の再編**（FR-24）:
  - **穴リングの削除**: 削除された穴の内側にあった子リング（穴の中の飛び地など）を、交互構造が保たれる位置（穴の親である領土リングの一段内側として整合する位置）へ付け替える。
  - **領土リングの削除**: 削除された領土リングの子（その内側の穴リング、さらにその内側の飛び地）を、交互構造が保たれるよう一段ずつ繰り上げて付け替える。
  - 削除と再編を**一つの純粋関数**として実装し、入力リング階層と削除対象を受け取り、再編後のリング階層を返す。返り値だけで前後状態を比較・検証できる形にする（FR-24 の単一操作テスト要件）。
- **検証結果の構造化**: 検証関数は真偽だけでなく、違反したリング・違反種別・関連リングを機械的に列挙できる結果値を返す。これにより上位の編集コマンド（リアルタイム検証や確定前検証）と競合通知の両方が同じ戻り値を利用できる（FR-25 のリアルタイム検証）。
- **プロパティベーステスト**: 任意のリング構成を生成し、再編後も交互不変条件が保たれることを fast-check で検証する（受け入れ基準）。

### やらないこと

- 面情報の頂点編集 UI・エッジ滑り・共有頂点システム（FR-28〜FR-33、FR-87〜FR-89）。本ユニットは検証・再編の純粋ロジックのみを提供し、これらの操作層は別ユニットが本ユニットを呼び出す。
- 末端地物同士の地図全体での空間的排他検証（FR-26〜FR-27）。本ユニットは**単一面情報内**のリング階層の整合のみを対象とし、面情報をまたぐ排他は扱わない。
- 面のブーリアン演算（和・差・交差）そのものの実装（穴あけ・合体・集約形状算出・競合差分調整。FR-37 / FR-45 / FR-50 / FR-51 / FR-63）。本ユニットは幾何述語（包含・交差・非重複）の検証を扱い、ブーリアン演算は別途委譲される。
- 面情報の親子関係（面情報同士のツリー階層。FR-34〜FR-53）。本ユニットの「リング階層」は**1 つの面情報の内部のリング構造**であり、面情報のツリー（末端地物・集約地物）とは別概念である。両者を混同しないこと。
- アンドゥ／リドゥ履歴への積み込み・イベント通知・描画・永続化。削除と再編が「単一操作としてアンドゥ／リドゥで完全復元できる」（FR-24）の履歴側実装は上位ユニットが担い、本ユニットは前後状態を一意に決める純粋関数を提供することで成立を支える。
- 面積・周長の計測（FR-20 の面積計算は測地ユニットが担う）。

## 依存（dependsOn）

- **U06**: 本ユニットは U06 が提供する**頂点・リングの基礎データモデルと幾何プリミティブ**に依存する。本ユニットは U06 から次を利用する前提で実装する（U06 のエクスポートに合わせて結線する）。
  - リング = 閉じた頂点配列を表す不変な値表現（頂点 ID 参照またはワールド座標列）。
  - 点とポリゴンの内外判定、線分交差判定、ポリゴン同士の交差・包含・分離を判定する純粋な幾何述語。
  - 数値誤差・退化ケースに備えた座標量子化／トレランスの基準値（技術方針 R2 の量子化方針）。

  U06 のエクスポート名・型が本ユニットの想定と異なる場合は、推測でフォールバックを書かず、U06 の実体を確認して結線する（開発ガイド §2.11 既存性の主張は実在確認してから書く）。U06 にリング包含判定など必要な述語が無い場合は、本ユニット内に幾何述語を持ち込まず、不足を未解決課題文書へ記録した上で U06 側へ追加するか結線方針を確認する（単一の真実源の維持。技術方針 2.9 / 開発ガイド §4「単一の真実源」）。

## 実装方針

技術方針（採用スタック）に沿い、本ユニットは `domain` 層の**フレームワーク非依存・純粋関数**として実装する。Electron／React／Canvas に一切依存せず、Vitest 単体で実行できること（技術方針 2.13 / 5.4）。

### データモデル

- リングの役割は**判別共用体**で表現し、「領土リング」「穴リング」を型レベルで区別する。不正状態（役割未定のリング、交互を破る構造）を可能な限り表現不能にする（技術方針 2.1）。
- リング階層は、各リングと「その親リングへの参照（最外周は親なし）」で表す。階層深度や交互性は、この親子関係から**派生算出**する（リング自身に深度・交互の真偽を保持しない。FR-38 と同じ「派生値は保持せず算出」の設計指針を、面情報のツリーではなくリング階層に適用する）。
- すべての値はイミュータブルとし、状態変更操作（再編）は新しいリング階層を返す（技術方針 2.6 / 開発ガイド §5.17）。`tsconfig` の `noUncheckedIndexedAccess` 前提で、頂点配列・リング配列の境界外アクセスを型で排除する（技術方針 2.1）。

### 検証ロジック

- 交互不変条件の検証は、最外周リング（親なし）から子へ辿り、各辺で役割が反転していること、かつ最外周がすべて領土リングであることを確認する純粋関数とする。
- 包含・非交差・非重複の幾何検証は U06 の幾何述語に委譲する。本ユニットは「どのリング対をどの述語で検証するか」という**検証の組み立て**を担う。
- 数値的退化（自己交差・ゼロ長エッジ・極小スリバー・誤差）に備え、幾何判定の前に座標量子化を通し、判定後に不変条件を再チェックする防御層を設ける（技術方針 R2）。
- 検証関数は**真偽だけでなく違反の詳細**（違反種別・違反リング・関連リング）を構造化した結果値で返す。リアルタイム検証（候補表示）と確定前検証（コマンド拒否）の両方が同じ関数・同じ戻り値を使う（開発ガイド §5.26「編集制約はコマンド確定前にも同じサービスで検証する」）。

### 再編ロジック

- 削除と再編は**単一の純粋関数**とし、`(リング階層, 削除対象リング) → 再編後リング階層` の形で実装する。途中の中間状態を外へ公開せず、返り値だけで前後状態を比較できるようにする（FR-24 単一操作テスト）。
- 穴削除・領土削除で付け替え規則が異なるため、**両方を明示的に実装**し、片方だけ実装して「もう一方も同様」と省略しない（開発ガイド §1.2 省略の禁止、§2.10 対概念へ判断を反映する）。
- 再編後は必ず交互不変条件を満たすことを、関数の事後条件として保証する。プロパティテストでこれを担保する。

### テスト

- 「入力リング階層 → 削除 → 期待リング階層」を Vitest で単体テストし、穴削除・領土削除・ネスト（穴の中の飛び地）・飛び地削除の各ケースを網羅する（技術方針 2.14）。
- fast-check で任意のリング構成（ネスト深さ・飛び地数・穴数を変化させたもの）を生成し、再編後も交互不変条件が保たれることをプロパティテストで検証する。ジェネレータはドメインの不変条件から導出し、他のリング系プロパティテストと再利用できる共通モジュールとして用意する（技術方針 R7）。
- テスト fixture は実体の生成関数（ファクトリ）でリング階層を構築し、リテラルで型を満たすだけの構造を作らない（開発ガイド §5.39）。

## 受け入れ基準

以下をすべてテスト可能な形で満たすこと。

1. **交互不変条件の検証**（FR-24）
   - 「領土→穴→領土→…」と交互になっているリング階層に対し検証が成功する。
   - 最外周に穴リングがある／親子で役割が反転しない（領土→領土、穴→穴）構成に対し検証が失敗し、違反リングを特定できる。
   - 最外周（親なし）のリングがすべて領土リングであることを検証できる。

2. **包含・非交差・非重複の検証**（FR-25）
   - 穴リングが親リング内部に完全包含され境界が交差しない構成で成功し、親境界をはみ出す／交差する構成で失敗を返す。
   - 同じ親を持つ兄弟リング同士が交差する構成で失敗を返し、分離している構成で成功する。
   - 飛び地（別の最外周領土リング）が他の外周と重なる構成で失敗を返し、重ならない構成で成功する。
   - 各検証は真偽に加えて違反種別・関連リングを構造化して返し、リアルタイム呼び出し（高頻度）に耐える単一関数として提供される。

3. **削除時の子リング付け替え**（FR-24）
   - 穴リング削除時、削除された穴の内側にあった子リングが交互構造を保つ位置へ正しく付け替えられる（穴削除ケース）。
   - 領土リング削除時、その内側の穴・飛び地が交互構造を保つよう繰り上げて付け替えられる（領土削除ケース）。
   - 穴削除・領土削除の両ケースが個別の単体テストで検証され、再編後の階層が交互不変条件を満たす。

4. **プロパティベース検証**（FR-24）
   - fast-check で任意のリング構成を生成し、任意の削除対象に対する再編後も交互不変条件が常に保たれることをプロパティテストで検証する。

5. **削除と再編の単一操作テスト**（FR-24）
   - 削除＋再編が一つの純粋関数で行われ、入力状態と返り値（再編後状態）を直接比較する前後状態テストが記述できる。中間状態に依存せず、同一入力に対し再編結果が決定的であることをテストする。

6. **テスト・ビルド**
   - 上記すべてが Vitest で全パスし、`domain` 層が Electron／React／Canvas 抜きで単体実行できること。

## 関連要件（FR-id）

- **FR-21**（面情報の飛び地の独立扱い）: 飛び地を本土同様の独立した外周領土リングとして階層に表現し、穴領域は常に透過扱いとなるリング役割を持たせる（本ユニットは役割と階層の表現を担い、描画の透過自体は描画層）。
- **FR-24**（リング階層の領土→穴交互不変条件、削除時の交互構造維持の再編、単一操作での復元可能性）: 本ユニットの中核。交互検証・穴削除/領土削除それぞれの子リング付け替え・前後状態テストを純粋関数で提供する。
- **FR-25**（穴の親内部完全包含・境界非交差・兄弟非交差・飛び地非重複のリアルタイム検証）: 本ユニットの中核。各制約を独立に検証できる純粋関数を提供する。

## 注意点・既知の落とし穴

開発ガイドの教訓を踏まえ、本ユニットの実装で特に注意する点を以下に挙げる。各教訓は着手前に該当節を引用し適用宣言すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **「リング階層」と「面情報のツリー」を混同しない**: 本ユニットの階層は 1 つの面情報内のリング（領土・穴）の入れ子構造である。面情報同士の親子（末端地物・集約地物。FR-34〜）とは別物。型名・関数名で取り違えないよう、対象が「リング」であることを明示する。
- **集合演算は複数片を返す前提で扱う**（開発ガイド §5.1）: 本ユニットが将来ブーリアン演算結果のリング群を受け取って検証する場合、複数リング・複数片を前提に全片を扱う。先頭片だけ検証して片落としにしない。検出: 結果が 2 片以上になる入力で全片が検証対象になることをテストする。
- **対概念へ判断を反映する**（開発ガイド §2.10 / §1.2）: 穴削除の付け替え規則を決めたら、領土削除の付け替え規則にも整合する判断を反映する。片方だけ実装して「もう一方も同様」と省略しない。
- **仕様が限定した対象範囲を実装で広げない**（開発ガイド §5.25）: 「兄弟リング非交差」「飛び地非重複」など制約の対象範囲は FR-25 の明記に従う。対称性・自然な拡張を理由に、面情報をまたぐ排他（FR-26 の末端地物排他）まで本ユニットへ取り込まない。範囲を広げたくなったら FR-25 / FR-27 を引用して止める。
- **編集制約はコマンド確定前にも同じサービスで検証する**（開発ガイド §5.26）: リアルタイム検証（候補表示用）と確定前検証（コマンド拒否用）は同じ関数・同じ戻り値を共有する。UI が候補を隠しても、ショートカット・メニュー・undo/redo・直接呼び出しで不正状態が入りうるため、検証は本ユニットの純粋関数に一元化する。拒否理由は通知用にもテスト用にも使える戻り値で返す。
- **派生値は保持せず算出する**: 階層深度・交互性の真偽はリングに保持せず親子関係から算出する。保持すると描画・検証・再編で値がドリフトする（開発ガイド §5.29「派生形状は単一の解決判定で全経路を動かす」と同じ趣旨を、リング階層の派生値に適用）。
- **退化ケースの防御**（技術方針 R2）: 自己交差・ゼロ長エッジ・極小スリバー・数値誤差で幾何述語が不正判定を返しうる。幾何判定の前に座標量子化を通し、判定後に不変条件を再チェックする。境界の接触（接するが重ならない）を「重なり」と誤判定しないトレランス設計を初期に確立する（FR-25 / FR-26 はいずれも境界接触を重なりに含めない）。
- **無限横スクロール／経度シフトとの整合**（技術方針 R3）: 世界端をまたぐリング（東端・西端を跨ぐ飛び地・穴）の包含・交差判定では、経度を連続スカラーで扱い、必要に応じて ±360 度オフセットでワールドラップ展開してから判定する。U06 がこのラップ正規化を提供する場合はそれに委譲し、本ユニットで独自に折り返し処理を再発明しない（単一の真実源）。
- **削除は参照掃除まで含めて整合する**（開発ガイド §5.21）: リング削除時、削除対象を子に持っていたリングからの参照を残さず、付け替え先へ正しく繋ぎ替える。dangling な親参照を残さないことを再編後の不変条件チェックで保証する。
- **イミュータブル設計の網羅**（開発ガイド §5.17）: 状態変更（再編・リング追加削除）は新インスタンスを返し、必要な変更系メソッドを全属性について洗い出す。役割（領土／穴）ごとに必要な操作が網羅されているか確認する。
- **空配列は真値である**（開発ガイド §5.18）: 「穴が 0 個」「飛び地が 0 個」「最外周のみ」の構成を、論理和の短絡で誤って空扱いにしない。リング数 0／1／多数の各境界を明示的に判定し、プロパティテストの生成範囲にも含める。
- **テスト fixture は実体を生成する**（開発ガイド §5.39）: リング階層の fixture は U06 のファクトリ／生成関数で構築し、リテラルで型だけ満たす構造にしない。未参照プロパティの欠落が別経路で沈黙して失敗するのを防ぐ。
- **失敗の教訓化**（開発ガイド §1.5 / §1.9）: 実装中に既存教訓で説明できない不具合の根本原因が見つかったら、完了前に開発ガイド §5 へ新教訓を追記し、回帰テストを同一作業内で追加する。

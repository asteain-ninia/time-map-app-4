# U06 幾何述語・座標量子化・ブーリアン演算ラッパ

## 目的

面情報（ポリゴン）の和・差・交差を行うブーリアン演算と、点in多角形・線分交差などの基本的な幾何述語を、ドメイン層の純粋関数として提供する。これらは穴あけ・合体・集約地物の形状算出・競合解決の差分調整・末端地物排他検証など、本アプリの中核機能（FR-20 / FR-25 / FR-32 ほか）が依存する最下層の幾何プリミティブである。

ブーリアン演算には成熟した外部ライブラリ `polygon-clipping` を用いるが、ライブラリを素のまま呼び出すのではなく、必ず本ユニットのラッパ経由で利用する。ラッパは次の二つの責務を担う。

1. **退化ケース防御（R2）**: 演算前に座標を固定スケールの整数格子へ量子化（スナップ）し、演算後に結果の不変条件を再検証する防御層を必須とする。自己交差・ゼロ長エッジ・極小スリバー・数値誤差に起因する不正形状を、ドメインへ流入させない。
2. **複数片の保全（教訓5.1）**: ブーリアン演算は単一ポリゴンではなく複数ポリゴン・複数リングを返しうる。結果のすべての片を扱い、片落とし（配列の先頭だけ採用するなど）を構造的に禁止する。

本ユニットは、上位ユニットがブーリアン演算と幾何述語を「安全な単一の窓口」を通してのみ使えるようにすることを目的とする。

## スコープ

### やること

- 面情報のブーリアン演算ラッパを提供する。
  - 和（union）・差（difference）・交差（intersection）の 3 演算。
  - 入力・出力ともに、複数ポリゴン・複数リング（外周＋穴）を含む形状を表現できる共通の多重ポリゴン型を用いる。
  - 各演算は **演算前の座標量子化 → ライブラリ呼び出し → 演算後の不変条件再検証** を内部で必ず実行する。
- 座標量子化（スナップ）ユーティリティを提供する。
  - 固定スケールの整数格子へ座標を丸める純粋関数。スケール（トレランス）はモジュール内の単一定数として定義し、全演算で共有する（単一の真実源）。
  - 量子化により発生したゼロ長エッジ・重複頂点の除去を含む。
- 演算後の不変条件チェック（防御層）を提供する。
  - 結果の各リングが有効か（最低 3 頂点・ゼロ長エッジを持たない・自己交差しない・リング階層が領土→穴交互の整合を保つ）を検証する。
  - 違反時は結果を返さず、テスト可能な戻り値（拒否理由を含む結果型）で操作を拒否する。例外で握りつぶさない。
- 幾何述語を純粋関数として提供する。
  - 点in多角形判定（穴を考慮した内外判定。境界上の扱いを明示）。
  - 線分交差判定（2 線分が交差するか、交点・端点接触の区別を含む）。
  - 自己交差判定（リング内のエッジ同士が交差するか）。
  - ゼロ長エッジ判定（連続する 2 頂点が量子化後に一致するか）。
- 世界端ラップ（U06 の依存である U05 が提供する経度ラップ正規化）を通した座標で正しく動作すること。すなわち、世界端をまたぐ面に対して U05 のラップ展開を適用した座標が入力されても、各演算・各述語が正しい結果を返す。

### やらないこと

- 経度ラップ展開そのもの（±360 度オフセット複製・周期境界正規化）は U05 の責務であり、本ユニットでは実装しない。本ユニットは「ラップ展開済みの座標が入力される」前提で動く。
- 空間インデックス（RBush）による候補絞り込みは本ユニットの責務ではない（上位ユニット）。本ユニットは与えられた形状ペアに対する厳密な幾何計算のみを行う。
- 末端地物排他の業務ルール判定（どの地物同士を検証するか、エッジ滑り応答）は上位ユニットの責務。本ユニットは「重なっているか」「内部にあるか」といった幾何述語の提供に留まる。
- 距離・面積・大円距離などの測地計算は別ユニット（測地計算モジュール）の責務であり、本ユニットでは扱わない。
- 描画・ヒットテスト・UI・永続化には一切関与しない。
- 集約地物の形状算出・穴あけ・合体・競合差分調整といった業務ロジックは上位ユニットが本ユニットのラッパを呼び出して実現する。本ユニットはそれらの業務フロー自体を実装しない。

## 依存（dependsOn）

- **U05（世界端ラップ／経度座標正規化）**: 本ユニットは U05 が提供する「世界端をまたぐ面のラップ展開（±360 度オフセットを考慮した連続座標への正規化）」を通した座標を入力として受け取る。本ユニットのラッパ・述語は、U05 で正規化済みの座標上で動作することを保証する。U05 の正規化関数を本ユニット内で再実装してはならない（単一の真実源）。

本ユニットは `domain` 層の純粋関数として実装し、Electron／React／Canvas に一切依存しない。Vitest 単体で実行可能であること。

## 実装方針（技術方針に沿う）

- **配置と純粋性**: `domain` 層に配置し、副作用のない純粋関数群とする。依存方向は内向き（`domain` へ）を維持し、UI・描画・シェルへの依存を持たない。これにより不変条件のプロパティテストと境界網羅テストを副作用なく実施できる（NFR 5.8）。
- **ブーリアン演算ライブラリの委譲**: 面の和・差・交差は `polygon-clipping` に委譲する。自前のブーリアン演算アルゴリズムは実装しない（数値的に最も危険な難所を実績ライブラリへ委譲するリスク最適配分）。ただしライブラリへの呼び出しは本ユニットのラッパ関数に一元化し、上位ユニットがライブラリを直接 import することを禁止する（境界を本ユニットに閉じ込める）。
- **座標量子化（R2 前段）**: ライブラリ呼び出し前に、すべての入力座標を固定スケールの整数格子へスナップする。スケール（量子化トレランス）はモジュール内の単一定数として定義し、和・差・交差・述語のすべてで同一値を共有する。トレランス設計（格子の細かさ）は本ユニットの初期に確立し、定数として一箇所に置く。
- **不変条件再検証（R2 後段）**: ライブラリ呼び出し後に、結果形状が本アプリのドメイン不変条件（領土→穴交互、各リング最低 3 頂点、ゼロ長エッジなし、自己交差なし）を満たすかを再検証する。違反時は成功結果を返さず、拒否理由を伴う結果型で返す。防御層はオプションではなく必須経路とする。
- **結果型の設計（判別共用体）**: 各ラッパ演算は「成功（複数片の形状）」と「拒否（理由）」を判別共用体で返し、不正状態を表現不能にする。例外による暗黙の制御フローを避け、呼び出し側が拒否を型で扱えるようにする（FR-32 / FR-25 の禁止条件をテスト可能な戻り値として扱う方針に直結）。
- **複数片の全片保全（教訓5.1）**: 演算結果の多重ポリゴン構造をそのまま保持し、全片を返す。内部実装でも結果配列の先頭のみを採用する処理を作らない。型上も「単一ポリゴン」へ早期に潰さず、多重ポリゴン型を維持する。
- **幾何述語の独立実装**: 点in多角形・線分交差・自己交差・ゼロ長エッジは、ライブラリに依らず小さな純粋関数として自前実装する。境界条件（境界上の点・端点接触・共線・量子化後の一致）の扱いを関数ごとに明示し、テストで固定する。
- **世界端ラップとの整合（R3）**: 本ユニットは U05 のラップ展開済み座標上で動作する。ラップをまたぐ面を入力したテスト（U05 の正規化を通した座標）で、各演算・述語が分断や片落としを起こさないことを検証する。
- **テスト同時実装**: 実装と同時にテストを書く。不変条件はプロパティベーステスト（fast-check）で生成入力により網羅し、退化ケース・複数片ケース・境界ケースは Vitest の単体テストで「入力→期待結果」を固定する。

## 受け入れ基準（テスト可能な形で列挙）

各基準は Vitest／fast-check で検証可能な形とする。

1. **和・差・交差が複数片を返す入力で全片を出力する（片落とし禁止・教訓5.1）**
   - 差演算の結果が 2 片以上に分かれる入力（例: ドーナツ状・分離する 2 領域に割れる形状）で、結果に全片が含まれることを単体テストで確認する。
   - 和演算で分離した 2 ポリゴンを和したとき（隣接しない場合）、結果が両片を含む多重ポリゴンとして返ることを確認する。
   - 交差演算が複数片を返す入力で、全片が出力に現れることを確認する。
   - 結果型が多重ポリゴン（複数ポリゴン・各ポリゴンが外周＋複数穴リング）を保持できることを型と実値の両方で確認する。

2. **演算前に座標量子化、演算後に不変条件チェックを行い、違反時は拒否する（R2）**
   - 量子化関数が、与えた座標を固定スケール整数格子へ丸め、量子化後に一致した連続頂点（ゼロ長エッジ）を除去することを確認する。
   - 各ラッパ演算が、量子化を経てからライブラリを呼び出すことを確認する（量子化を迂回する経路が存在しないこと）。
   - 演算結果が不変条件（領土→穴交互、各リング最低 3 頂点、ゼロ長エッジなし、自己交差なし）に違反する場合、成功結果ではなく拒否理由を伴う結果型を返すことを確認する。
   - 防御層を通さずライブラリ生結果を返す公開経路が存在しないことを確認する。

3. **点in多角形・線分交差・自己交差・ゼロ長エッジ述語が正しい**
   - 点in多角形: 内部点が真、外部点が偽、穴の内部点が偽、境界上の点が明示した規約どおりであることを、穴付き・飛び地付き形状で確認する。
   - 線分交差: 交差する／しない／端点で接触する／共線で重なる各ケースを区別して正しく判定することを確認する。
   - 自己交差: 自己交差するリングで真、単純多角形で偽を返すことを確認する。
   - ゼロ長エッジ: 量子化後に連続頂点が一致するリングで真、有効リングで偽を返すことを確認する。

4. **退化ケースで不正形状を生まない**
   - 極小スリバー（細長く面積がほぼゼロの重なり）を差・交差したとき、量子化と不変条件チェックにより、不正な極小リングや自己交差形状を出力しない（拒否するか、正規化された有効形状のみを返す）ことを確認する。
   - 自己交差を含む入力、ゼロ長エッジを含む入力に対して、結果が不正形状を含まないことを確認する。
   - fast-check で生成した多様なポリゴン入力に対し、成功結果は常に不変条件を満たす、というプロパティを検証する。

5. **世界端ラップ（U05）を通した座標で動作する**
   - U05 のラップ展開を適用した、世界端（経度 ±180 度境界）をまたぐ面の座標に対して、和・差・交差が分断・片落としを起こさず正しい結果を返すことを確認する。
   - ラップをまたぐ点in多角形・線分交差判定が、ラップ展開済み座標上で正しいことを確認する。

6. **境界の接触は重なりに含めないことと整合する（FR-26 系の前提を支える）**
   - 交差述語・交差演算において、エッジが接触するのみで内部が重ならないケースを、重なりではなく接触として扱える（または上位ユニットがそう判定できる）情報を返すことを確認する。

7. **`domain` 純粋性**: 本ユニットの全関数が副作用を持たず、Electron／React／Canvas に依存せず Vitest 単体で実行できることを確認する。

## 関連要件（FR-id）

- **FR-20**: 面情報を閉じたパス（リング構造）で形状定義し、任意数の穴・飛び地およびネスト構造に対応する。本ユニットは多重ポリゴン型と全片保全により、穴・飛び地・ネストを保持したブーリアン演算を支える。
- **FR-25**: 穴/飛び地の編集時、穴リングは親リング内部に完全包含され境界が交差しない、兄弟リング同士が交差しない、飛び地は他の外周リングと重ならない、という制約をリアルタイム検証する。本ユニットの点in多角形・線分交差・包含判定がこの検証の幾何基盤となる。
- **FR-32**: 共有化や共有頂点移動の結果、ゼロ長エッジ・自己交差・穴飛び地階層の破綻・末端地物同士の重なりが生じる場合は操作を禁止する。本ユニットのゼロ長エッジ述語・自己交差述語・不変条件チェックが、この禁止条件のテスト可能な判定材料を提供する。

関連する横断要件: NFR 5.8（不変条件の機械的検証・純粋ロジックの分離）、技術方針 R2（退化ケース防御の必須化）、R3（世界端ラップとブーリアン演算の整合）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の関連教訓を引用し適用宣言してから実装すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **教訓5.1 集合演算は複数片を返す前提で扱う**: 「ブーリアン（集合）演算は単一ポリゴンではなく、複数ポリゴン・複数リングを返す前提で扱う。差分・結合・競合解決では返却されたすべての片を変換し、片落とし（配列の先頭だけ採用）を避ける。検出: 差分・結合の結果が 2 片以上になる入力で、全片が出力に現れることをテストする。」
  - 適用: 本ユニットの和・差・交差ラッパは結果を多重ポリゴン型で返し、内部実装でも先頭片のみ採用する処理を作らない。受け入れ基準 1 の「2 片以上に割れる入力で全片が現れる」テストを必ず置く。

- **技術方針 R2（退化ケース防御）**: 「演算入力前に座標を固定スケールの整数格子へスナップ（量子化）し、演算後に不変条件チェックを再実行。違反時は操作を拒否する防御層を必須化。トレランス設計を初期に確立。」
  - 適用: 量子化を全演算の必須前処理、不変条件再検証を必須後処理とし、これらを迂回する公開経路を作らない。トレランス定数は本ユニット冒頭で一箇所に定義する。

- **教訓5.26 編集制約はコマンド確定前にも同じサービスで検証する**: 編集制約（自己交差・全体重複・階層破綻・禁止条件）は UI の候補表示だけでなく、確定前にも同じサービスで検証する。拒否理由はユーザー通知とテスト可能な戻り値の両方で扱う。
  - 適用: 本ユニットの不変条件チェックと幾何述語が「同じサービス（同じ純粋関数）」として上位の確定前検証から呼ばれる前提で、拒否理由をテスト可能な戻り値（判別共用体）で返す設計にする。

- **教訓5.18 空配列・空オブジェクトは真値である**: 論理和による短絡デフォルト補完に頼らず、型や状態を明示判定する。
  - 適用: ブーリアン演算結果が「空（片が一つもない）」の正当なケース（例: 完全に内包される差分の消失、交差なし）と、エラー（拒否）を明確に区別する。空結果は短絡で握りつぶさず、空の多重ポリゴンという有効値として返す。

- **教訓5.30 過少共有と過剰共有の両方を戒める**: 同じ判定・同じ baseline・同じ既定値処理は同じ実装を共有する。
  - 適用: 量子化トレランス・点in多角形の境界規約・自己交差判定は単一実装を全演算で共有する（過少共有の戒め）。一方で、和・差・交差で本質的に異なる検証が必要な箇所は安易に共通化しない。

- **教訓5.38 移動制約は線分交差で判定する（参考）**: 衝突検出と応答を分け、既存接触（t=0）を新規衝突として止め直さない。
  - 適用: 本ユニットの線分交差述語は「交差の有無・交点・端点接触・共線」を区別して返し、上位の衝突検出／応答（エッジ滑り等）がこの述語を素材として使えるようにする。境界の接触（FR-26 の「境界の接触は重なりに含めない」）を区別できる情報を返す。

- **開発ガイド §4 単一の真実源**: 同じ判定・同じ基準値は同じ実装を共有する。
  - 適用: U05 のラップ正規化を本ユニットで再実装しない。量子化トレランスを複数箇所に散在させない。

- **その他の落とし穴**:
  - `polygon-clipping` の出力リング向き（外周と穴の巻き方向の規約）を確認し、本アプリの領土リング／穴リングの向き規約へ正規化してから返す。向き規約の取り違えは点in多角形・塗り判定で対概念矛盾を生む。
  - 量子化スケールが粗すぎると正当な細い領域が消失し、細かすぎると数値誤差で退化ケースを防げない。トレランスは受け入れ基準 4（極小スリバー）と整合する値を初期に決め、定数として一箇所で管理する。
  - 上位ユニットが `polygon-clipping` を直接 import する抜け道を残さない。本ユニットのラッパが唯一の窓口であることを、依存方向の lint 強制および上位ユニット側のテストで担保する前提で公開 API を設計する。

# U32 プロパティパネル・錨一覧・詳細文書(Markdown)

## 目的

本アプリは、地物を選択してその属性と歴史を参照・編集するための主たる情報インタフェースとしてプロパティパネルを持つ。本ユニットは、画面右側サイドバーのプロパティパネルと、そこから開く詳細パネル（モーダル）、および詳細文書（Markdown）のレンダリングを React UI 層として実装する。

本ユニットの中核責務は次の六点である。

1. **選択状況に応じたプロパティパネル表示**: 選択システムが公開する選択状態（アクティブ地物・頂点選択コンテキスト）に応じて、(a) アクティブ地物のプロパティ、(b) 頂点選択コンテキストが一意ならその地物のプロパティ、(c) 複数地物が検出された場合は 1 件ずつ編集を促す案内、(d) 所有者が解決できない場合の案内、(e) 空選択時の案内、を網羅的に出し分ける。判定は派生済みヘルパー結果だけに頼らず生の ID セットまで評価して網羅する（FR-83、教訓 5.10）。
2. **歴史の錨一覧と編集対象錨の明示選択**: プロパティタブ内に対象地物の歴史の錨一覧を表示し、ユーザーが編集対象の錨を明示的に選択できる。錨を選択すると、タイムライン表示と現在時刻を当該錨の開始時刻へ即時同期し、以後の保存操作はその開始時刻を編集時刻として実行する（FR-84）。
3. **基本情報のサイドバー即時表示と編集統合**: 地物クリック時にサイドバーへ基本情報（名前・年代・色情報など）を即時表示し、編集モードでは同じパネル内で編集機能を統合する（FR-99 前段、FR-97）。
4. **ドラッグ可能・複数同時表示のモーダル詳細パネル**: 「詳細表示」ボタンで、ドラッグ可能・複数同時に開けるモーダル形式の詳細パネルを表示し、すべての属性と詳細文書を表示する（FR-99 後段）。
5. **Markdown 詳細文書の無害化レンダリング**: 各地物に添付された Markdown 詳細文書を、markdown-it でレンダリングし DOMPurify で無害化（XSS 対策）して表示する。画像埋め込みはプロジェクト ZIP 内アセットへの相対参照、文書内リンク（他オブジェクトへの参照）、基本書式（太字・斜体・リスト・表）に対応する（FR-98）。
6. **歴史の錨の表示切替（時間バー表示／リスト表示）**: 対象地物の歴史の錨の一覧表示を、「リスト表示」（錨を開始時刻昇順に並べる従来の一覧）と「時間バー表示」（時間軸上に各錨の存在期間を帯として描き、非存在期間を空白として示す）の二種類で切り替えられる。時間バー表示は表示領域の上端／下端時刻を動的に表示し、ホイールでズームでき、錨名称ラベルは画面占有率に基づき表示可否を判定する（FR-60）。

加えて、検証拒否・保存失敗など「ユーザーが次の判断に使うメッセージ」は、発生元と無関係なクリックやマウス操作で消去しない（教訓 5.12）。

本ユニットは「選択状態に応じて何をどう表示・編集するか」という UI 責務に集中する。選択状態そのものの管理・正規化・派生（アクティブ地物の 0/1 件保持、頂点選択コンテキストの解析）は依存ユニット（U22）の責務であり、本ユニットは U22 が公開する選択状態を**参照する側**に立つ。現在時刻・編集対象錨の同期先となるセッション状態と年月日入力コンポーネントは U16／U21 が提供し、本ユニットはそれらを利用する。

## スコープ

### やること

1. **選択状況別のプロパティパネル表示（FR-83）**
   - 依存ユニットが公開する選択状態（アクティブ地物 ID＝0/1 件、頂点選択コンテキスト＝単一／複数／不明／空）を参照し、次の各ケースを区別可能に表示する。
     - **アクティブ地物がある**: そのアクティブ地物のプロパティを表示・編集対象とする（FR-83 第一優先）。
     - **アクティブ地物がなく、頂点選択コンテキストが一意（単一所有）**: その地物のプロパティを表示・編集対象とする。
     - **アクティブ地物がなく、頂点選択が複数地物にまたがる（複数検出）**: 「複数の地物が選択されています。1 件ずつ選択して編集してください」相当の案内を表示し、特定地物のプロパティ編集には進ませない。
     - **アクティブ地物がなく、頂点選択の所有者が解決できない（所有者不明）**: 「選択頂点の所有地物を特定できません」相当の案内を表示する。
     - **空選択**: 「地物が選択されていません」相当の案内を表示する。
   - 上記の判定は、派生済みヘルパー結果（例: 「コンテキスト地物」だけ）に頼らず、**生の選択 ID セット**（アクティブ地物 ID と頂点選択セットの所有地物集合）まで評価して「単一／複数／不明／空」を網羅的に分岐する（教訓 5.10）。各ケースの表示メッセージ・表示条件を一対一で対応付ける。
   - 表示対象地物（プロパティの編集対象）は、アクティブ地物 → 頂点選択コンテキスト地物の順で第一候補を決める。コレクションの先頭やデータソース全体を既定で使わない（教訓 5.3 / 5.4）。

2. **基本情報のサイドバー即時表示と編集統合（FR-99 前段・FR-97）**
   - 地物が選択された（クリックされた）時点で、サイドバーのプロパティパネルへ基本情報を即時表示する。基本情報は基本属性（名前、年代＝開始年・終了年）と色情報（自動配色許可フラグ、塗り色、選択時色、境界色）を含む（FR-97）。
   - 編集モードでは、同じプロパティパネル内に編集機能を統合する（名前・年代・色情報などの編集 UI を表示し、表示モードでは編集 UI を無効化／非表示にする。教訓 5.13）。
   - 編集の確定（保存）は、現在の編集対象錨の開始時刻を編集時刻として、ドメインへのコマンド発行に委ねる（コマンド発行・履歴管理は依存ユニットへ委譲し、本ユニットは「どの地物の・どの錨を・どの値で更新するか」という編集意図を組み立てて渡す）。
   - 値が変わっていないのに発火する確定（blur/Enter 等）で幽霊 undo エントリを積まないよう、確定ハンドラに no-op ガードを入れる。ガードの baseline はフォーム同期と同一ソース（現在の錨の状態）から導く（教訓 5.24）。

3. **歴史の錨一覧と編集対象錨の明示選択（FR-84）**
   - 表示対象地物の歴史の錨一覧を、開始時刻昇順で表示する（各錨の開始時刻・必要なら終了時刻／非存在期間を表示）。錨列の整列・非重複・状態継続判定そのものは錨ユニットの責務であり、本ユニットは取得した錨列を**表示**するのみで再整列・再判定を実装しない（単一の真実源）。
   - ユーザーが一覧から編集対象の錨を**明示的に選択**できる。どの錨が現在の編集対象かを視覚的に明示する。
   - 錨を選択すると、タイムライン表示と現在時刻（セッション状態）を当該錨の**開始時刻**へ即時同期する。同期は U16／U21 が管理する現在時刻状態を更新することで行い、その結果メインマップ・タイムライン UI が当該時刻へ追従する（再描画・スライダー追従の実体は U16／U21 が担う）。
   - 編集対象錨を選択した状態での保存操作は、その錨の**開始時刻を編集時刻**として実行する。錨選択 → 保存の経路で編集時刻が一貫してその開始時刻になることを保証する（教訓 5.15 タイムスタンプはコンテキスト上の時刻を参照する。システム時刻を編集時刻に混入させない）。
   - 錨選択による現在時刻同期は、時刻を変える複数経路（スライダー・数値ジャンプ・再生・本ユニットの錨選択）のうちの一経路として、U16／U21 と同一の現在時刻更新アクションを通す。本ユニット独自の現在時刻書き換え経路を作らない（教訓 5.6、単一の真実源）。

4. **歴史の錨の表示切替＝時間バー表示／リスト表示（FR-60）**
   - 錨一覧を「リスト表示」と「時間バー表示」の二種類で切り替えられる切替コントロールを設ける。切替状態は当該パネルの UI 状態として保持する。
   - **リスト表示**: 上記 3 の錨一覧（開始時刻昇順の一覧）をそのまま用いる。
   - **時間バー表示**: 時間軸（横または縦）に沿って、各錨の存在期間（半開区間 [start, end)）を帯（バー）として描く。**非存在期間は空白**として表示し、地物が存在しない区間が視覚的に分かるようにする。
   - 時間バー表示は、**表示領域の上端／下端（または左端／右端）時刻を動的に表示**する（ズーム・スクロールに追従して端の時刻ラベルが更新される）。
   - 時間バー表示は**ホイールでズーム**でき、時間軸の表示スケール（単位時間あたりの画面長）を変更できる。ズームの中心・範囲制限は一貫した規約で定める。
   - 各錨の**名称ラベルは画面占有率に基づき表示可否を判定**する（バーの画面上の長さが十分なときのみラベルを描き、潰れて読めない場合は省略する）。占有率閾値は一貫した規約／設定で定め、表示・非表示の判定を単一の判定関数に集約する（教訓 5.29）。
   - 時間バー上の錨（バー）をクリック／選択すると、上記 3 と同一の「編集対象錨の選択 → 現在時刻を当該錨の開始時刻へ同期」経路を通す。リスト表示・時間バー表示のどちらから選んでも編集対象錨の選択・時刻同期は同じ単一経路を共有する（単一の真実源・教訓 5.6）。
   - 時間軸 ↔ 画面座標のマッピング（時刻 → 画面位置、ホイールズーム量 → スケール）の純粋計算は、可能なら U21 の「時間範囲 ↔ スライダー位置マッピング」「紀元前表示変換」と同じ U02 経由の時間計算・同じ表示変換規約を用い、暦法定数・正規化を本ユニットで再実装しない（単一の真実源）。
   - 時間バー表示・リスト表示の切替に伴う一時 UI 状態（ズーム量・スクロール位置・ホバー中ラベル）は、パネルのアンマウント・選択地物変更・モード切替の経路で適切に整理する（教訓 5.2）。

5. **ドラッグ可能・複数同時表示のモーダル詳細パネル（FR-99 後段）**
   - プロパティパネルに「詳細表示」ボタンを設け、押下でモーダル形式の詳細パネルを開く。詳細パネルにはすべての属性と詳細文書（Markdown レンダリング結果）を表示する。
   - 詳細パネルは**ドラッグで移動可能**とする（タイトルバー等のドラッグハンドルで位置を変更できる）。
   - 詳細パネルは**複数同時に表示可能**とする（異なる地物の詳細パネルを同時に並べて開ける）。各詳細パネルは独立した位置・状態を持ち、それぞれ個別に閉じられる。
   - 詳細パネルは編集モードでは編集機能を統合し、表示モードでは閲覧専用とする（教訓 5.13）。
   - 重なり合う詳細パネル・モーダル背景・ドラッグハンドルは、描画順だけでなく入力を受ける層も同時に設計する。透明な背景層がドラッグハンドルや前面パネルの操作を奪わないこと（教訓 5.14）。

6. **Markdown 詳細文書の無害化レンダリングと画像・リンク・書式（FR-98）**
   - 各地物に Markdown 形式の詳細文書を添付・編集でき、その内容を markdown-it でレンダリングし、**DOMPurify で無害化**してから DOM へ挿入する（XSS 対策。FR-116 / NFR 5.5）。生の HTML を無害化せずに挿入しない。
   - **画像埋め込み**: 画像はプロジェクト ZIP 内アセットへの**相対参照**として解決する。オフライン完結（FR-02）のため、外部 URL からの画像取得に依存しない設計とし、ZIP 内アセットの相対パスから表示用ソースを解決する経路を提供する（アセット入出力・ZIP 読み書きの実体は永続化ユニットが担い、本ユニットは相対参照 → 表示用ソースの解決契約を利用する）。
   - **文書内リンク（他オブジェクトへの参照）**: 文書内から他の地物（オブジェクト）への参照リンクを記述でき、クリックでその対象地物を選択／参照できる。リンク種別（オブジェクト参照か外部参照か）を区別し、オブジェクト参照は選択状態の更新へ、外部参照は無害化方針に従って扱う。
   - **基本書式**: 太字・斜体・リスト・表のレンダリングに対応する。
   - レンダリング・無害化のロジック（markdown-it 設定・DOMPurify 設定・オブジェクト参照リンクの解決）は、可能な限り副作用のない純粋関数として切り出し、Vitest で単独テストできるようにする。

7. **判断用メッセージの保持（教訓 5.12）**
   - プロパティ編集の検証拒否・保存失敗など、ユーザーが次の判断に使うメッセージは、発生元と無関係なクリックやマウス操作で即時消去しない。
   - メッセージを消す契機は「同種操作の再試行」「明示的な閉じる」「成功した置換操作（妥当値での再保存成功）」など、意味を持つイベントに限定する。

8. **テスト**
   - 選択状況別表示の分岐（アクティブ／コンテキスト一意／複数／不明／空）の単体テスト、錨選択 → 現在時刻同期 → 保存時の編集時刻一致のテスト、詳細パネルのドラッグ・複数同時表示のテスト、Markdown レンダリングの無害化（危険なスクリプト除去）・画像相対参照・リンク・書式のテスト、判断用メッセージが無関係操作で消えないテストを、実装と同時に書く（開発ガイド 1.9）。

### やらないこと

- **選択状態の管理・正規化・派生そのもの**: アクティブ地物（0/1 件）の保持・頂点選択セットの加除/範囲/置換・頂点選択コンテキスト（単一所有判定）の解析・選択の視覚的フィードバック分類は U22 の責務。本ユニットは U22 が公開する選択状態を参照するだけで、選択リデューサを再実装しない（単一の真実源）。
- **ドメインの真実とその更新ロジック・コマンド発行・アンドゥ/リドゥ**: 地物・錨・ツリーの型と不変条件、編集コマンドの適用、二重スタック履歴は別ユニット（コマンド基盤）の責務。本ユニットは編集意図（対象地物・対象錨・編集値）を組み立てて渡すに留め、状態遷移と履歴 push は委譲する。
- **錨列のデータモデル・整列・非重複・再編・状態継続判定**: 錨列の昇順整列・時間重複禁止・再編（分割/短縮/削除）・半開区間 [start, end) の継続規則は錨ユニットの責務。本ユニットは取得した錨列を表示し、編集対象錨を「選択」するのみで、錨列構造の編集ロジックを持たない。
- **現在時刻状態そのものの保持・タイムライン UI・スライダー/数値入力/再生の実装**: 現在時刻のセッション状態は U16 が保持し、スライダー・年月日入力・再生は U21 が実装する。本ユニットは錨選択時に U16／U21 と同一の現在時刻更新アクションを呼び、年月日入力が必要な箇所では U21 の共有コンポーネントを利用する。
- **メインマップの描画・再描画・地物のヒットテスト**: Canvas 描画と地物クリックのヒットテストは描画／編集ツール側ユニットの責務。本ユニットは選択結果として「どの地物が選択されたか」を受け取って表示する。
- **地物削除ボタンの実装（FR-85）**・**面情報スタイルセクションの自動配色制御（FR-100〜102）の本体**・**コンテキストメニュー（FR-96）**: 別ユニットの責務。本ユニットは FR-97 の基本属性・色情報を基本情報として表示・編集するが、自動配色アルゴリズム本体・四色定理割当・削除確認フロー・右クリックメニュー構成は範囲外（FR-102 のスタイルセクション UI と本ユニットの色情報表示の境界は実装着手時に確認し、現状.md に記録する）。
- **永続化・ZIP 読み書き・Zod スキーマ検証・IPC 境界**: 詳細文書本文・添付画像アセットの保存・読込・スキーマ検証は永続化ユニットの責務。本ユニットは詳細文書のレンダリングと、ZIP 内アセットの相対参照 → 表示用ソースの解決契約の利用に留める。
- **`domain` 層・`render` 層・`shell` 層の実装**: 本ユニットは `ui` 層（React）に閉じる。Markdown のレンダリング/無害化など純粋に切り出せるロジックは副作用のないモジュールとして `ui` 寄りに置き、`domain` の純粋性（React・Canvas 非依存で Vitest 実行可能）を壊さない。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが公開する選択状態・現在時刻状態・年月日入力コンポーネントを前提として実装する。

- **U22（選択システム: アクティブ地物・頂点選択セット・選択コンテキスト・視覚FB）**: アクティブ地物（0/1 件）、頂点選択セット、頂点選択コンテキスト（単一／複数／不明／空の区別可能な状態）を公開する。本ユニットはこの選択状態を参照して FR-83 の出し分けを行う。U22 が公開する「アクティブ地物 ID」「頂点選択コンテキストの分類（単一地物・複数・不明・空）」「コンテキスト地物 ID」の型・構造を前提インタフェースとして参照し、選択リデューサ自体は再実装しない。生の ID セットまで評価する分岐網羅（教訓 5.10）は U22 が提供する分類を基盤としつつ、本ユニットの表示メッセージ・表示条件を各分類へ一対一で対応付ける。
- **U21（タイムライン UI: スライダー・数値入力・年月日入力コンポーネント・再生）**: 年・月・日の独立入力欄を持つ再利用可能な年月日入力コンポーネント（年必須・月日任意・未指定トグル・暦設定に基づく即時検証・完全値受け渡し）を公開する。本ユニットの錨の存在期間表示や編集対象錨の時刻表示・編集にこの共有コンポーネントを利用する（FR-70 の粒度統一）。錨選択時の現在時刻同期は、U21 が時間を変える際に通すのと同一の現在時刻更新経路を用いる。FR-60 の時間バー表示の時間軸 ↔ 画面座標マッピング（時刻 → 画面位置・紀元前表示変換）は、U21 が用いる「時間範囲 ↔ スライダー位置マッピング」「紀元前表示変換」と同じ U02 経由の時間計算・同じ表示変換規約を共有し、暦法定数・正規化を本ユニットで再実装しない（単一の真実源）。
- **U16（UI/セッション状態ストア(Zustand)とドメインブリッジ）**: 現在時刻（年・月・日の完全値）をセッション状態として保持し、それを更新するアクションと、現在時刻変更時の依存状態再検証経路を提供する。本ユニットの「錨選択 → 現在時刻を当該錨の開始時刻へ同期」は、U16 の現在時刻更新アクションを呼ぶことで実現する（本ユニット独自の現在時刻書き換え経路を作らない）。また本ユニットが参照する選択状態（U22 が更新するもの）も Zustand 経由で購読する。プロパティ編集の確定（コマンド発行）は U16 がブリッジするコマンド基盤へ委ねる。

実装着手時に、U22 が公開する選択状態の型・分類、U21 の年月日入力コンポーネントの props/コールバック契約、U16 の現在時刻更新アクションと選択状態スライスのシグネチャを確認し、本ユニットの参照・呼び出しをそれらに整合させること。いずれかが未確定の場合は、本仕様に記す入出力契約（選択状態の分類＝単一/複数/不明/空、現在時刻＝年・月・日の完全値で更新、年月日入力＝完全値受け渡し）に沿った型インタフェースを先に定義し、その境界に対して UI とテストを実装する。層をまたぐ契約は共有型・両側テストで固定する（教訓 5.33 / 5.34）。

## 実装方針（技術方針に沿う）

技術方針（`docs/技術方針.md`）の 2.3（React は UI シェル・パネル・ダイアログに限定し地図描画を再レンダリングから切り離す）・2.5（Zustand ＋ 純粋ドメインコア、Zustand を単一の真実源とし Canvas 側は購読のみ）・2.11（Markdown は markdown-it ＋ DOMPurify で無害化、画像は ZIP 内アセットを相対参照）・2.13（ディレクトリ層分離と依存方向の内向き固定）、開発ガイド §4（単一の真実源・UI 文脈の優先・結果状態での判定・層をまたぐ契約の固定）に従う。

### 配置と層分離

- 本ユニットのコードは `ui` 層（React 関数コンポーネント）に属する。選択状態・現在時刻・ドメイン状態への参照は Zustand ストア（U16）経由で購読し、地図描画状態を React state に持たせない（技術方針 2.3）。依存方向は `ui → domain` の内向きに固定し、`domain` から `ui` を参照しない。
- Markdown のレンダリング/無害化、オブジェクト参照リンクの解決、選択状況の分類 → 表示メッセージのマッピングなど、純粋に切り出せるロジックは副作用のないモジュールとして実装し Vitest で単独テストする（NFR 5.8）。React コンポーネントはこれら純粋ロジックを呼び出す薄い層に保つ。

### 選択状況別表示（生 ID セットまで評価）

- 表示の分岐は、U22 が提供する分類（単一／複数／不明／空）を起点としつつ、**生の選択 ID セット**（アクティブ地物 ID と頂点選択セットの所有地物集合）まで評価して網羅する（教訓 5.10）。派生ヘルパーの戻り値だけで分岐を済ませない。
- 各ケースの表示メッセージと表示条件を一対一で対応付け、ケース判定を単一の純粋関数（選択状態 → 表示種別＋メッセージ）に集約する。描画・案内文・編集可否がこの単一判定を共有し、ドリフト（あるケースだけ別判定）を防ぐ（教訓 5.29）。
- 編集対象地物の第一候補はアクティブ地物、次点が頂点選択コンテキスト地物とし、UI 文脈に存在しない場合のみ「空選択」案内へ落ちる。コレクション先頭・固定デフォルトへ落とさない（教訓 5.3 / 5.4）。

### 基本情報の即時表示と編集統合

- 地物選択時の基本情報表示は、選択状態の変化（Zustand 購読）に反応して即時更新する。基本属性（名前・年代）と色情報（FR-97）をフォームに同期し、フォームの baseline は現在の編集対象錨の状態と同一ソースから導く。
- 表示モードと編集モードの切替は同一のモード判定で一括制御し、表示専用モードでは編集 UI・編集操作を一括無効化する（部品ごとの個別判定を散らさない。教訓 5.13）。
- 確定（保存）ハンドラには no-op ガードを入れ、現在状態（baseline）と一致する確定は履歴に積まない（教訓 5.24）。

### 錨一覧と編集対象錨の選択・時刻同期

- 錨一覧は錨ユニットから取得した錨列（開始時刻昇順）を表示する。整列・非重複・再編は本ユニットで再実装しない（単一の真実源）。
- 編集対象錨を選択したら、U16 の現在時刻更新アクションで現在時刻を当該錨の**開始時刻**（年・月・日の完全値）へ同期する。現在時刻は完全値で受け渡し、年だけ・小数年などの中間表現を使わない（教訓 5.16）。
- 保存時の編集時刻は、現在選択中の編集対象錨の開始時刻を参照する。編集時刻はコンテキスト上の時刻（錨の開始時刻＝現在時刻）から取得し、システム時刻（`Date.now()` 等）を編集時刻に混入させない（教訓 5.15）。
- 錨選択による現在時刻変更は、U16／U21 と同一の現在時刻更新経路を通す。これにより現在時刻変更時の依存状態再検証（選択地物がその時刻に存在するか等）が他経路と同様に起動する（教訓 5.5 / 5.6、再検証の実体は U16）。

### ドラッグ可能・複数同時の詳細パネル

- 詳細パネルは複数インスタンスを同時に保持できる状態構造（開いている詳細パネルのリスト：対象地物 ID・位置・個別状態）で管理する。各パネルは独立に開閉・移動できる。
- ドラッグ移動は押下 → 移動 → 解放のシーケンスを全パスで保証し、押下で立てたドラッグ中状態を解放で必ず解除する。クリック（移動なし）で状態が残らないこと（教訓 5.8）。ドラッグ中の一時状態（仮位置）は確定・キャンセル・アンマウントの全経路で破棄する（教訓 5.2）。
- 重なり合うパネル・モーダル背景・ドラッグハンドルは、描画順（z 順）と入力を受ける層を同時に設計する。透明背景がハンドルや前面パネルの操作を奪わないことをテストで確認する（教訓 5.14）。

### Markdown レンダリングと無害化

- markdown-it でレンダリングし、DOM へ挿入する前に必ず DOMPurify で無害化する。無害化を経ない生 HTML を挿入する経路を作らない（FR-116 / NFR 5.5）。無害化の許可タグ・属性方針を一箇所に定め、画像（相対参照）・リンク・基本書式（太字・斜体・リスト・表）を通しつつスクリプト・イベントハンドラ属性・危険な URI スキームを除去する。
- 画像は ZIP 内アセットの相対参照として解決する。外部 URL 取得に依存せず（FR-02 オフライン完結）、相対パス → 表示用ソースの解決を永続化ユニットが提供する契約経由で行う。解決できない参照は壊れた画像として安全に扱い、無害化方針を破らない。
- 文書内リンクは、オブジェクト参照（他地物への参照）と外部参照を区別する。オブジェクト参照リンクのクリックは対象地物の選択（U22 が公開する選択更新経路）へ繋ぎ、外部参照は無害化方針に従って扱う。リンク種別の判定は型・規約を経由し、表示文字列の思い込みで分岐しない（教訓 5.19）。
- レンダリング/無害化/リンク解決のコアは純粋関数として切り出し、危険な入力（`<script>`・`onerror` 属性・`javascript:` URI など）が確実に除去されることを Vitest で固定する（NFR 5.8、FR-116）。

### 判断用メッセージの保持

- 検証拒否・保存失敗メッセージは、その発生元（保存ボタン・該当入力欄）と無関係なクリック・マウス操作で消さない。消去契機を「同種操作の再試行」「明示的な閉じる」「妥当値での再保存成功」に限定する（教訓 5.12）。
- メッセージの保持・消去は専用の状態として管理し、無関係な再レンダリングや選択変更でリセットされない設計にする。

### 一時 UI 状態の破棄

- 編集中の下書き値、未確定の編集、詳細パネルのドラッグ仮位置、開いている詳細パネルの状態などの一時 UI 状態は、確定・キャンセル・パネルのアンマウント・モード切替・選択変更のすべての経路で適切に破棄／整理する（教訓 5.2）。ただし判断用メッセージ（教訓 5.12）は無関係操作では消さない点と区別して扱う。

### テスト

- React コンポーネントの操作テスト（選択状況別表示・錨一覧操作・詳細パネルのドラッグと複数同時表示・編集フォーム）と、純粋に切り出したロジック（選択状況 → 表示種別/メッセージのマッピング、Markdown 無害化、オブジェクト参照リンク解決、画像相対参照解決）の Vitest 単体テストを実装と同時に書く（開発ガイド 1.9）。
- E2E（Playwright for Electron）で、選択状況別表示の網羅、錨選択 → タイムライン/現在時刻同期 → 保存時の編集時刻一致、詳細パネルのドラッグ・複数同時表示、Markdown の画像/リンク/書式表示、判断用メッセージが無関係クリックで消えないこと、を検証する。検証不能になった範囲はロジックを純粋関数化して単体テストで補う（教訓 5.41）。

## 受け入れ基準（テスト可能な形で列挙）

以下はすべてテスト可能な形で満たすこと。テストは実装と同時に作成する（開発ガイド 1.9）。

1. **選択状況別表示の網羅（アクティブ／コンテキスト一意／複数／不明／空）（FR-83、教訓 5.10）**
   - アクティブ地物がある場合、そのアクティブ地物のプロパティが表示・編集対象になる。
   - アクティブ地物がなく頂点選択コンテキストが一意（単一所有）の場合、その地物のプロパティが表示・編集対象になる。
   - アクティブ地物がなく頂点選択が複数地物にまたがる場合、「1 件ずつ選択して編集してください」相当の案内が表示され、特定地物のプロパティ編集へ進ませない。
   - アクティブ地物がなく所有者が解決できない場合、所有者不明の案内が表示される。
   - 空選択の場合、地物未選択の案内が表示される。
   - これらが**生の選択 ID セット**まで評価して網羅的に分岐され、各ケースの表示メッセージ・表示条件が一対一に対応していることを、各ケースごとの専用テストで確認できる（派生ヘルパーの戻り値だけに頼っていない）。

2. **錨一覧と編集対象錨選択でタイムライン＋現在時刻が錨開始へ同期（FR-84）**
   - プロパティタブに対象地物の歴史の錨一覧が開始時刻昇順で表示される（錨列の整列・非重複は錨ユニットの単一実装を表示するのみで本ユニットが再整列していない）。
   - 一覧から編集対象の錨を明示的に選択でき、どの錨が編集対象かが視覚的に明示される。
   - 錨を選択すると、現在時刻（セッション状態）が当該錨の**開始時刻**（年・月・日の完全値）へ同期し、タイムライン表示・メインマップがその時刻へ追従する（本ユニットのテストでは「U16 の現在時刻更新アクションが当該錨の開始時刻で呼ばれる」ことを確認し、再描画/スライダー追従は U16/U21 の責務として境界で固定する）。
   - 編集対象錨を選択した状態での保存操作が、その錨の開始時刻を編集時刻として実行される（編集時刻＝コンテキスト上の時刻であり、システム時刻が混入していないことをテストで確認できる。教訓 5.15）。
   - 錨選択による現在時刻同期が、U16／U21 と同一の現在時刻更新経路を通る（本ユニット独自の現在時刻書き換え経路を作っていない）。

3. **基本情報サイドバー即時表示＋詳細表示ボタンでドラッグ可能・複数同時モーダル（FR-99 / FR-97）**
   - 地物選択時に、基本属性（名前・年代＝開始年/終了年）と色情報（自動配色許可フラグ・塗り色・選択時色・境界色）がサイドバーへ即時表示される（FR-97 の基本属性・色情報を含む）。
   - 編集モードでは同じパネルで編集機能が統合され、表示モードでは編集 UI が一括無効化される（教訓 5.13）。
   - 「詳細表示」ボタンでモーダル詳細パネルが開き、すべての属性と詳細文書が表示される。
   - 詳細パネルがドラッグで移動でき、複数同時に表示できる（異なる地物の詳細パネルを並べて開け、各々独立に移動・開閉できる）。ドラッグの押下→移動→解放で一時状態が残らない（教訓 5.8 / 5.2）。
   - 重なり合うパネル・背景・ドラッグハンドルで、前面/背面の期待操作が通る（透明背景が操作を奪わない。教訓 5.14）。

4. **Markdown 詳細文書が markdown-it＋DOMPurify で無害化レンダリングされ画像/リンク/書式対応（FR-98）**
   - 詳細文書が markdown-it でレンダリングされ、DOM 挿入前に DOMPurify で無害化される。`<script>`・`onerror` などのイベントハンドラ属性・`javascript:` 等の危険な URI スキームが確実に除去されることを単体テストで確認できる（無害化を経ない生 HTML 挿入経路が存在しない。FR-116 / NFR 5.5）。
   - 画像埋め込みが ZIP 内アセットへの相対参照として解決され、外部 URL 取得に依存しない（FR-02）。解決できない参照が安全に扱われる。
   - 文書内リンク（他オブジェクトへの参照）が機能し、オブジェクト参照リンクのクリックで対象地物の選択へ繋がる。リンク種別が型・規約で区別される（教訓 5.19）。
   - 基本書式（太字・斜体・リスト・表）が正しくレンダリングされる。

5. **判断用メッセージが無関係なクリックで消えない（教訓 5.12）**
   - プロパティ編集の検証拒否・保存失敗メッセージが、発生元と無関係なクリック・マウス操作（パネル他所のクリック・別地物の選択など）で即時消去されない。
   - メッセージが消える契機が「同種操作の再試行」「明示的な閉じる」「妥当値での再保存成功」に限定されていることを、無関係クリック後にメッセージが残ること・意味のあるイベントで消えることの両方でテスト確認できる。

6. **層分離と単一の真実源（技術方針 2.3 / 2.5 / 2.13）**
   - 本ユニットは `ui` 層に属し、選択状態（U22）・現在時刻（U16）・錨列（錨ユニット）を再実装せず、それぞれの単一実装を参照・利用している。
   - Markdown 無害化・選択状況分類・リンク解決など純粋に切り出したロジックが副作用のないモジュールとして Vitest 単独で実行できる。地図描画状態を React state に持たせていない。

7. **歴史の錨の時間バー表示／リスト表示の切替（FR-60）**
   - 錨一覧を「リスト表示」と「時間バー表示」で切り替えられ、切替が実際に表示形態を変えることを確認できる。
   - 時間バー表示で、各錨の存在期間がバーとして描かれ、**非存在期間が空白**として表示されることを確認できる。
   - 時間バー表示で、表示領域の上端／下端時刻が**動的に表示**され、ズーム・スクロールに追従して更新されることを確認できる。
   - 時間バー表示が**ホイールでズーム**でき、ズームに応じて時間スケールが変わることを確認できる。
   - 各錨の**名称ラベルが画面占有率に基づき表示可否判定**され（バーが十分長いときのみ表示）、占有率判定が単一の判定関数で行われることを単体テストで確認できる。
   - リスト表示・時間バー表示のどちらから錨を選んでも、編集対象錨の選択 → 現在時刻同期が**同一経路**を通る（受け入れ基準 2 と同じ単一経路）ことを確認できる。
   - 時間軸 ↔ 画面座標のマッピング（時刻 → 画面位置・ホイールズーム量 → スケール）が純粋関数として Vitest 単独で検証でき、暦法定数・正規化を本ユニットで再実装せず U02 経由の時間計算を用いることを確認できる。

## 関連要件（FR-id）

- **FR-83**（should）: プロパティパネルで選択状況に応じた表示を行う（アクティブ地物がある場合はそのプロパティ、頂点選択コンテキストが一意ならその地物、複数地物検出時は 1 件ずつ編集を促す案内、所有者不明時・空選択時はそれぞれの案内）。— 本ユニットの選択状況別表示（生 ID セットまで評価する網羅）が対応する。
- **FR-84**（should）: プロパティタブ内に歴史の錨一覧を表示し、ユーザーが編集対象の錨を明示的に選択できる。錨を選択するとタイムライン表示と現在時刻を当該錨の開始時刻へ即時同期し、保存操作はその開始時刻を編集時刻として実行する。— 本ユニットの錨一覧・編集対象錨選択・現在時刻同期・編集時刻一致が対応する。
- **FR-97**（must）: 各地物に基本属性（名前、年代＝開始年・終了年）と色情報（自動配色許可フラグ、塗り色、選択時色、境界色）を持たせる。— 本ユニットの基本情報サイドバー表示・編集が、これら基本属性・色情報の表示/編集 UI を提供する（自動配色アルゴリズム本体・スタイルセクションの配色制御 FR-100〜102 は別ユニット）。
- **FR-98**（should）: 各地物にマークダウン形式の詳細文書を添付でき、画像の埋め込み、文書内リンク（他オブジェクトへの参照）、基本的なフォーマット（太字・斜体・リスト・表など）をサポートする。— 本ユニットの markdown-it ＋ DOMPurify レンダリング・画像相対参照・文書内リンク・基本書式が対応する。
- **FR-99**（should）: オブジェクトクリック時にサイドバーで基本情報を即時表示し、編集モード時は編集機能を統合する。「詳細表示」ボタンでドラッグ可能・複数同時表示可能なモーダル形式の詳細パネルにすべての属性と詳細文書を表示する。— 本ユニットの基本情報即時表示・編集統合・ドラッグ可能/複数同時モーダル詳細パネルが対応する。
- **FR-60**（could）: 歴史の錨の表示を「時間バー表示」（非存在期間を空白として表示し、表示領域の上端/下端時刻を動的表示、ホイールでズーム可能で錨名称ラベルは画面占有率に基づき表示可否判定）と「リスト表示」の二種類で切り替えられる。— 本ユニットの錨一覧の時間バー表示／リスト表示切替がこの要件を**完全に所有**する（時間軸 ↔ 画面マッピングの純粋計算は U02 の時間計算・U21 と同じ表示変換規約を共有）。

関連する非機能要件: NFR 5.1（選択・編集操作の応答 100ms 以内、地図描画を React 再レンダリングから切り離す）、NFR 5.5（入力検証・無害化）、NFR 5.7（日本語 UI）、NFR 5.8（純粋に切り出したロジックの単体テスト・境界網羅）。関連概念: ドメインモデル §4.5（アクティブ地物・頂点選択コンテキスト・整合性と編集操作）、§4.4（歴史の錨と時間モデル）、§3.19（プロパティパネルと地物情報）、§3.24（属性情報と詳細文書）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の関連教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として 1 文以上で宣言してから実装すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **教訓 5.10「選択状態は生の集合まで評価して網羅する」**（引用: 「複数の選択状態（単一・複数・不明・空）を扱う UI では、派生済みヘルパー結果だけでなく、生の ID セットをすべて評価して分岐を網羅する。仕様メッセージと表示条件を一対一で対応付ける。」）
  - 適用: プロパティパネルの選択状況分岐を、U22 の派生分類だけに頼らず、アクティブ地物 ID と頂点選択セットの所有地物集合という生の ID セットまで評価して「アクティブ／コンテキスト一意／複数／不明／空」を網羅する。各ケースの案内メッセージ・編集可否・表示条件を一対一に対応付け、ケースごとの専用テストで固定する（受け入れ基準 1）。

- **教訓 5.12「判断用メッセージを無関係な操作で消さない」**（引用: 「検証拒否・保存失敗など、ユーザーが次の判断に使うメッセージは、発生元と無関係なクリックやマウス操作で即時消去しない。消す契機は『同種操作の再試行』『明示的な閉じる』『成功した置換操作』など、意味を持つイベントへ限定する。」）
  - 適用: プロパティ編集の検証拒否・保存失敗メッセージを専用状態で保持し、パネル他所のクリック・別地物選択などの無関係操作で消さない。消去契機を同種操作の再試行・明示的な閉じる・妥当値での再保存成功に限定する（受け入れ基準 5）。

- **教訓 5.15「タイムスタンプはコンテキスト上の時刻を参照する」**（引用: 「時間軸を持つデータのタイムスタンプは、必ずコンテキスト上の時刻（現在時刻）を参照し、システム時刻と混同しない。時刻源は一元管理するサービスから取得する。」）
  - 適用: 錨選択 → 保存の編集時刻は、選択中の編集対象錨の開始時刻（＝同期後の現在時刻）から取得し、`Date.now()` 等のシステム時刻を編集時刻に混入させない。時刻源は U16 が一元管理する現在時刻状態とする（受け入れ基準 2）。

- **教訓 5.5「依存する状態は変化時に再検証する」 / 5.6「状態変化の検出は結果状態で判定する」**（引用 5.6: 「『ある状態変化が起きたら追加処理を走らせる』検出は、特定の入力経路でゲートせず、変異後の結果状態で判定する。同じ状態変化を複数経路が引き起こす場合、特定経路に絞ったゲートは別経路で必ず漏れる。」）
  - 適用: 錨選択による現在時刻同期を、U16／U21 と同一の現在時刻更新アクションで行い、本ユニット独自の書き換え経路を作らない。これにより現在時刻変更時の依存状態再検証（選択地物の存在再検証等）が他経路と同様に結果状態ベースで起動する（受け入れ基準 2）。

- **教訓 5.13「表示専用モードでは編集経路を一括無効化する」**（引用: 「表示専用モードでは、編集 UI・編集メニュー項目・編集ショートカットを同じ権限判定で一括無効化する。部品ごとに個別判定を書くと、見た目だけ非表示でショートカットや右クリック操作が残る。」）
  - 適用: プロパティパネル・詳細パネルの編集 UI を、表示モード／編集モードの同一判定で一括制御する。部品ごとの個別判定を散らさず、表示モードで編集経路（フォーム・ボタン）が一括無効化されることをテストで確認する（受け入れ基準 3）。

- **教訓 5.14「重なる UI は入力を受ける層も同時に設計する」**（引用: 「重なり合う UI（オーバーレイ・バックドロップ・ハンドル・モーダル）は、描画順だけでなく入力を受ける層も同時に設計する。透明な背景層が操作ハンドルを覆うと、見た目は正しくても操作が奪われる。検出: 重なった状態で、背面/前面の期待操作が通ることをテストする。」）
  - 適用: ドラッグ可能・複数同時の詳細パネルは、z 順だけでなく入力を受ける層を設計し、透明背景がドラッグハンドルや前面パネルの操作を奪わないことを、重なり状態での操作テストで確認する（受け入れ基準 3）。

- **教訓 5.8「押下→移動→解放シーケンスを全パスで保証する」**（引用: 「押下 → 移動 → 解放のシーケンスは、全パス（クリック・ドラッグ）で状態が正しく開始・更新・終了することを保証する。押下で設定した状態は解放で必ず解除し、移動が発生しなかった場合（クリック）の考慮漏れに注意する。」）
  - 適用: 詳細パネルのドラッグ移動は、押下で立てたドラッグ中状態を解放で必ず解除し、クリック（移動なし）でも仮位置状態が残らないようにする（受け入れ基準 3）。

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」**（引用: 「一時的 UI 状態（描画プレビュー・選択中の値・ドラフト設定）は、開始・確定・キャンセル・ツール切替・モード切替のすべての経路で明示的に破棄する。」）
  - 適用: 編集中の下書き値・未確定編集・詳細パネルのドラッグ仮位置を、確定・キャンセル・アンマウント・モード切替・選択変更で破棄／整理する。ただし判断用メッセージ（教訓 5.12）は無関係操作では消さない点と明確に区別する。

- **教訓 5.24「確定ハンドラには no-op ガードを入れる」**（引用: 「値が変わっていなくても発火する確定ハンドラ（blur/Enter 等）を undo 履歴付きコマンドへ載せるときは、確定値が現在状態（baseline）と一致するなら実行しない no-op ガードを入れる。」）
  - 適用: プロパティ編集の確定（blur/Enter）に no-op ガードを入れ、現在の錨状態（baseline）と一致する確定では履歴を積まない。baseline はフォーム同期と同一ソース（現在の編集対象錨の状態）から導く。

- **教訓 5.3「操作対象は表示状態に限定する」 / 5.4「追加・編集・複製・結合は現在の UI 文脈を第一候補にする」**（引用 5.4: 「追加・編集・複製・結合の対象は、現在の UI 文脈（フォーカス中対象・選択中対象・現在時刻・表示中要素）を第一候補にする。コレクションの先頭要素や固定デフォルトを使うのは、UI 文脈が存在しない場合だけに限定する。」）
  - 適用: プロパティの表示・編集対象はアクティブ地物 → 頂点選択コンテキスト地物の順で UI 文脈から決め、データソース先頭や固定デフォルトへ落とさない。錨選択・保存も現在の編集対象錨という UI 文脈を基準にする。

- **教訓 5.19「分岐識別子は型定義・定数・ファクトリを経由する」**（引用: 「種別・モード名・設定キーのような分岐識別子は、表示文字列や思い込みで判定せず、型定義・定数・ファクトリを経由する。」）
  - 適用: 文書内リンクのリンク種別（オブジェクト参照／外部参照）や地物種別による表示分岐を、表示文字列の思い込みでなく型・定数・ファクトリで判定する（受け入れ基準 4）。

- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」**（引用: 「形状を『子の和として導出する』派生形状では、描画・ヒットテスト・派生サービス・選択など複数経路を、同じ形状解決判定で動かす。判定条件のドリフトは対概念矛盾を生む。」）
  - 適用: 選択状況 → 表示種別/メッセージのマッピングを単一の純粋判定に集約し、案内文表示・編集可否・編集対象決定がこの単一判定を共有する。あるケースだけ別判定にしてドリフトを生まない。

- **教訓 5.33 / 5.34「層をまたぐ API 契約は両側テストで固定する／コンポーネント間データ受け渡しは契約を型で明示する」**
  - 適用: U22 の選択状態分類・コンテキスト地物 ID、U21 の年月日入力コンポーネント契約、U16 の現在時刻更新アクションと選択スライスのキー・型を、共有型・両側テストで固定する。偶然の文字列一致に頼らない。

- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / §4「単一の真実源」**
  - 適用: 選択状態・錨列・現在時刻・年月日入力・ZIP アセット解決は依存ユニットの単一実装を共有し再実装しない（過少共有の戒め）。一方、プロパティパネルの基本情報編集と FR-102 のスタイルセクション配色制御は規則が異なるため安易に同一 UI へ畳み込まない（過剰共有の戒め）。境界は実装着手時に確認し現状.md に記録する。

- **Markdown 無害化の死守（技術方針 2.11、FR-116 / NFR 5.5）**: markdown-it のレンダリング結果は必ず DOMPurify を通してから DOM へ挿入し、無害化を経ない生 HTML 挿入経路を一切作らない。許可タグ・属性・URI スキームの方針を一箇所に集約し、危険入力の除去を単体テストで固定する。画像は ZIP 内アセットの相対参照とし外部取得に依存しない（FR-02 オフライン完結）。

- **描画は React 再レンダリングに乗せない（技術方針 2.3、NFR 5.1）**: 本ユニットは右サイドバー・モーダルという周辺 UI を担うが、選択状態・現在時刻・ドメイン状態は Zustand 購読で受け取り、地図描画状態を React state に持たせない。プロパティ編集の高頻度操作（連続入力）でメインマップ描画を巻き込まない。

- **クリーンルーム原則（開発ガイド 3.1）**: 本仕様・実装・コメント・テスト名で過去版・他プロダクト・外部の既存実装に一切言及しない。必要な制約はすべて v4 自身の要件（FR-83 / FR-84 / FR-97 / FR-98 / FR-99）・技術方針として直接記述・参照する。

- **やり残しの記録（開発ガイド §1.8）/ 教訓化（§1.5）**: FR-102 のスタイルセクション配色制御との境界、FR-85 削除ボタンとの境界、ZIP アセット解決契約の永続化ユニットとの接続など、後続へ波及する保留判断は現状.md に記録する。新たに根本原因を教訓化すべき事象があれば開発ガイド §5 へ追記してから完了とする。

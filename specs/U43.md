# U43 合成ルート・入力層実配線・E2Eハーネス（統合ユニット）

本書は実装ユニット U43 の実装指示書である。U43 は設計時に所有者が不在だった「アプリ全体を結線する合成ルート（Composition Root）」と「層をまたぐ実配線」「E2E ハーネス」を一括で担う統合ユニットである。U01〜U41 が各層の部品（ドメイン純粋ロジック・描画・UI 部品・各ツールの contract）を緑で揃えている前提に立ち、それらを**実際に動くアプリ**へ組み上げ、各ツールの「インタラクティブ受け入れ」を E2E で確認する。

> 背景（D20）: 個々のツールユニット（U23 追加 / U24 編集 / U25 穴飛び地 / U26 ナイフ / U27 穴あけ生成 / U28 所属変更 / U29 末端→集約 / U30 合体 / U31 削除 / U40 パン 等）は、自スコープのドメイン/契約テストは緑だが、受け入れの中核（押下→移動→解放の層またぎ実発火・モード別ルーティング・確定時整合性・一時状態の破棄/完了トリガー・選択再解決）が合成ルートと入力層の実配線、および E2E を必要とする。これらはユニット単位で前倒しできないため U43 に集約する。

---

## 目的

各部品を結線し、要件定義書の対話フロー（FR 群）が**実機で端から端まで動く**状態にする。具体的には合成ルート・store セッションスライス・入力層の実配線・E2E ハーネスを確立する。

---

## スコープ

### やること

- **合成ルート（AppShell）**: ツールバー / サイドバー / マップキャンバス / タイムライン / 各モーダル（競合解決等）を 1 つの React ツリーへ組み上げ、依存（store・MapRenderer・ユースケース）を注入する。Existence-resolver 等、各ユニットが「合成ルートの責務」として委譲した本番注入をここで行う。
- **store セッションスライス**: 各ツールの一時状態（追加セッション / 編集セッション / パン状態 / 測量セッション / ナイフセッション / 所属変更・合体の進行状態 等）を Zustand に実装し、開始・確定・キャンセル・ツール切替・モード切替の**全経路で明示破棄**する（教訓 §5.x の一時状態破棄規律）。
- **入力層の実配線（InputLayer / PointerDispatcher）**: ポインタ押下→移動→解放、ホイールズーム、コンテキストメニューを、現在のモード/ツールに応じて各ユースケースへ実ルーティングする。U40 の dispatch/pan 純粋ロジックと U17 カメラを実発火に接続する。
- **確定時整合性の結線**: 各編集確定が整合性維持プロセス（U13）と歴史の錨再編（U09）・競合解決 UI（U35）へ繋がること。
- **E2E ハーネス**: Playwright for Electron（または技術方針が許す代替の非対話 E2E）を導入し、`e2e/` と `playwright.config` を整備。起動・主要フロー（地物追加→編集→保存→読込、所属変更、合体、ナイフ分割、時間移動、競合解決）のスモーク E2E を最低 1 本ずつ用意する。**非対話**で実行できること（GUI を人手で触らずに走る）。
- 各ツールユニットが spec で「U43/最終合成へ委譲」と記した受け入れ基準を、ここで E2E として満たす。

### やらないこと

- 各ツールのドメインロジックの再実装（U23〜U41 で完了済み。U43 は結線と検証に徹する）。
- 新機能の追加。性能計測ハーネスと全方針充足の最終確認は U42 の責務（U43 は結線と対話 E2E まで）。

## 実装方針

技術方針.md（React18 UIシェル / Zustand / 自前Canvas2D MapRenderer / Electron / Playwright）に従う。合成ルートは「薄く、一読で結線が追える」ことを優先し、ロジックは各層へ委譲する。一時状態の破棄は全経路で漏れなく（教訓準拠）。E2E は非対話・タイムアウト前提で、CI/無人実行可能にする。

---

## 受け入れ基準

1. `npm run typecheck` / `npm run lint` / `npm run test`（全体）が緑のまま、アプリが合成ルートから起動構成できる。
2. E2E ハーネス（`e2e/` + 設定）が非対話で起動し、最低限のスモーク（起動→地物追加→保存→読込）が緑。
3. 各ツールユニットが U43 へ委譲した受け入れ（押下→移動→解放の実発火・モード別ルーティング・確定時整合性・一時状態破棄）が E2E で確認できる。
4. 一時状態が、確定・キャンセル・ツール切替・モード切替の全経路で破棄される（E2E/単体で確認）。

### 充足状況（U43 出荷時点・正確な自己申告）

レビュー指摘（high）を受けた**正確な部分充足**の記録。`acceptanceMet` は本ユニット単体では **基準1 のみ完全充足**であり、基準2・3・4 は**部分充足**として扱う（実装者の過大申告 `acceptanceMet=true` は訂正済み）。

- **基準1 — 充足**: `npm run typecheck`（node + web + **e2e**）／`npm run lint`（`e2e/` 含む）／`npm run test`（全体）が緑。合成ルート（`src/ui/App.tsx`）から起動構成できる。
    - 追加修正（build-health ギャップ閉塞）: 旧構成では `e2e/**/*.ts` と `playwright.config.ts` がどの typecheck 構成の include にも入っておらず、統合層（E2E）の型退行が `npm run typecheck` をすり抜けていた。`tsconfig.e2e.json` を新設し `typecheck` スクリプトに連結したため、E2E の型は一級の型検査対象になった。
- **基準2 — 部分充足（ハーネス緑は実機確認済み／round-trip は未割当ユニットへ）**: E2E ハーネス（`e2e/` + `playwright.config.ts`）は非対話・オフスクリーン（`E2E_TEST=1`）で起動し、`npm run test:e2e`（electron-vite build → playwright）で **6 passed・exit 0**（起動/AppShell マウント・IPC ブリッジ・`press→move→release` 実発火・console-clean・モードゲート）を緑で固定する（実装報告 commandsRun に明記。build-health 証跡として E2E 実行を含める）。ただし「地物追加→**保存→読込**」の永続化ラウンドトリップは出荷合成ルートでは到達不能。`createAddBootstrap`/`createKnifeBootstrap` の `startProcess` は**決定的リジェクトstub**（`整合性維持プロセスがまだ接続されていません。`）であり、SAVE が必ず拒否で終わるため。round-trip の実機 E2E は**ライブ U13 結線が成立した後**に追加する（下記「未割当ブロッカー」参照）。
- **基準3 — 部分充足（モード別ルーティング/確定時整合性/選択再解決は未割当ブロッカー後）**: 押下→移動→解放の実発火は View モードのパンで実機確認済み。しかし add/edit/knife の「モード別ルーティング」「確定時整合性」「選択再解決」は実機 E2E で未駆動。合成ルートは起動時 View モードでモードトグルが無効（教訓5.13）かつ表示専用を抜ける UI 導線が無く、`App.tsx` が timeline/sidebar slot を未配線のため到達不能。これらは `AddToolController.test.tsx` 等の単体 injection でのみ緑。ライブ orchestrator 結線・timeline/sidebar slot・表示専用 exit の配線後に E2E で固定する。
- **基準4 — 部分充足（単体で確認済み／実機 E2E は未割当ブロッカー後）**: 一時状態の全経路破棄（確定/キャンセル/ツール切替/モード切替）は U23/U26 等の**単体テスト**で緑。spec が要求する「E2E/単体で確認」のうち**単体は充足**、実機 E2E は基準3 と同根の到達不能により後続。

> **責務の所在の訂正（integration-lens / 開発ガイド §1.8）**: 旧版はライブ U13 結線・表示専用 exit・timeline/sidebar slot 配線・round-trip E2E を **U42 へ繰越**と記していたが、これは誤りであった。U42 は**検証専任ユニット**であり、その「やらないこと」が `新規ドメイン機能・新規 UI の実装` を明確に除外している（`specs/U42.md` §やらないこと）。`dependsOn` の `U42 は U43 に依存する` は依存方向の宣言にすぎず、U43 の結線責務を U42 へ移譲する根拠にはならない。よってこれらを U42 へ繰越すると両ユニットの隙間に責務が落ちる。
>
> **未割当ブロッカー（要計画・新規ユニット）**: ライブ U13 結線は `startProcess` の「1行差し替え」では**ない**。`ConsistencyPorts<DomainRoot, Snapshot>` アダプタ（U09 時間/U10 空間/U06 差分/U12 単一アンドゥを live domain root 上に束ねる）+ `applyProposal`（編集スナップショット→`DomainProject` の錨/履歴へ反映）が前提である。とくに `applyProposal`（AddSnapshot/SplitSnapshot → FeatureHistory の錨生成・挿入/置換）は、出荷済みのどのユニットも純粋ドメイン操作として公開していない**新規ドメイン責務**であり、検証作業ではないため U42 には属さない。この契約の**型骨格**を `src/ui/consistency-binding.ts`（`LiveConsistencyBinding` / `CreateLiveAddBinding` / `CreateLiveKnifeBinding`）に置き、残り結線量を可視化した。`App.tsx` のコメントも「1行差し替え」表現を撤回し実態（アダプタ+root受け渡し）へ訂正済み。**未解決課題として `docs/現状.md` に未割当で記録**（口頭・コミットメッセージのみに残さない、§1.8）。U43 では「結線と実発火の検証」「ハーネス整備（実機緑を commandsRun に明記）」「build-health ゲート閉塞」「ライブ結線契約の型骨格化」までを honest にスコープする。

## 関連要件（FR-id）

各ツールユニットが参照する対話系 FR（追加/編集/ナイフ/所属変更/合体/削除/パン/ズーム/競合解決/保存読込/タイムライン）の**実機到達**をまとめて満たす。詳細 FR は各ユニット spec を参照。

## 注意点・既知の落とし穴

- E2E は本質的に統合レベル。ユニット単位で前倒しできないため U43 に集約した（D20）。逆に U43 では「各ツールのドメインは緑」を前提に、結線と実発火の検証に集中する。
- 一時状態の破棄漏れは退行の温床（過去教訓）。全経路の破棄を E2E で固定する。
- 非対話厳守: E2E も含め GUI を人手で触る検証は禁止。Playwright for Electron が環境依存で不能なら、その事実を記録し、dev サーバ経由のブラウザ E2E 等の代替を検討（技術方針/開発ガイドの E2E 方針に従う）。
- クリーンルーム原則: 過去版・他プロダクトに言及しない。

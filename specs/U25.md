# U25 穴/飛び地の追加・編集・削除ツール

## 目的

面情報（ポリゴン）の形状に対し、**穴**（内部の除外領域）と**飛び地**（同一面情報に属する別の外周リング）を、ユーザー操作で**追加・編集・削除**できるツールを提供する。これは**単一の面情報の形状編集**であり、新しい独立した面情報（地物）を生成しない（FR-23）。くり抜いて新地物を作る操作（穴あけによる新地物生成）は別概念であり、本ユニットでは扱わない。

本ユニットの中核は次の四点である。

1. **穴/飛び地追加ツール**: ツール起動後の**最初のクリック位置**が対象面の内部か外部かで「穴作成モード」か「飛び地作成モード」かを**自動判定**し、以後のクリックで頂点を配置して**最低 3 点**でリングを確定する（FR-22）。
2. **形状編集**: 追加した（または既存の）穴/飛び地リングの頂点を移動・追加・削除でき、編集中は U07 の制約（穴の親内部完全包含・境界非交差、兄弟非交差、飛び地の他外周非重複）を**リアルタイムに検証**する（FR-25）。穴/飛び地の頂点も地図全体の他末端地物との衝突判定・スナップ・共有化の対象とする（FR-89）。
3. **削除**: 穴/飛び地リングを削除する。削除時はリング階層の交互構造（領土→穴→領土→…）を維持するため、子リングの付け替えを U07 の再編関数に委譲する。削除と再編は**単一の編集操作**としてアンドゥ／リドゥで完全復元できる（FR-24）。
4. **確定時の整合性維持プロセス**: 操作確定時に時間的・空間的整合性維持プロセス（編集案生成→時間整合性検証→空間競合検出→競合解決→一括確定）をトリガーする（FR-61〜FR-63 と同一の確定経路に乗せる）。

本ユニットは「面情報の形状を編集する**編集モードのツール**」であり、リング階層の判定・再編という純粋ロジックそのものは U07 が、頂点編集の操作基盤（頂点／エッジハンドル、ドラッグ、衝突判定＝エッジ滑り、近接スナップ、共有頂点化）は U24 が提供する。本ユニットはそれらを**呼び出して組み立てる**ことに集中し、判定・再編・スナップ・衝突応答を再実装しない（単一の真実源。技術方針 §4「単一の真実源」、開発ガイド §5.30 過少共有の戒め）。

## スコープ

### やること

- **穴/飛び地追加ツール**（FR-22）
  - 対象となる面情報（アクティブ地物。FR-79）が選択されている状態で起動するツールとして実装する。対象面が未選択の場合はツールを開始できず、その旨を日本語で案内する（操作対象は表示・選択中の要素を第一候補にする。開発ガイド §5.3 / §5.4）。
  - **最初のクリック位置の内外判定**: ツール起動後の最初のクリック点が、対象面情報の**いずれかの領土リングの内部**（かつ穴リングの内部ではない、すなわち塗り領域内）にあれば「穴作成モード」、それ以外（対象面の外部、または対象面の穴の中）であれば「飛び地作成モード」と自動判定する。内外判定は U07／U06 が提供するポリゴン内外述語に委譲する（独自の内外判定を再発明しない。単一の真実源）。判定モードを画面に明示し、ユーザーが現在どちらのリングを作っているか分かるようにする（FR-118 操作ガイド）。
  - **頂点配置と確定**: 2 点目以降のクリックで頂点を順次追加し、**最低 3 点**に達して初めて確定可能とする。3 点未満では確定を拒否し理由を通知する（FR-22）。追加中は確定済みと異なるスタイルで仮表示し、クロージング線を半透明表示し、最後の頂点を 1 つずつ取り消せ（Ctrl+Z 等）、追加全体をキャンセルでき（Escape 等）、グリッドスナップをオプションで利用できる（FR-78 の追加共通機能を本ツールにも適用する）。
  - **リング役割の付与**: 穴作成モードで確定したリングは**穴リング**として、その内外判定で内包していた領土リングの一段内側（交互構造で整合する位置）に追加する。飛び地作成モードで確定したリングは**領土リング**（独立した外周）として、対象面情報に別外周として追加する。リング役割・親子位置の決定と交互不変条件の充足は U07 のリング階層モデル／再編関数に委譲する（FR-24）。
- **穴/飛び地の形状編集**（FR-25 / FR-87 / FR-88 / FR-89）
  - 既存または追加直後の穴/飛び地リングの**頂点移動・頂点追加（エッジハンドル）・頂点削除**を提供する。3 頂点未満になる頂点削除は当該リングの削除として扱う（FR-88 の「3 点未満で面またはリング削除」をリング単位に適用）。頂点ハンドル／エッジハンドルの表示・ドラッグ・追加生成は U24 の頂点編集基盤を用いる（FR-87）。
  - **リアルタイム制約検証**: 編集中（ドラッグ追従・頂点追加候補表示）に、U07 の検証関数を呼び出して次を常時検証し、違反する操作を禁止または候補から除外し、違反箇所を視覚的に示す（FR-25）。
    - 穴リングが親領土リング内部に完全包含され、親境界と交差しないこと。
    - 同じ親を持つ兄弟リング同士が交差しないこと。
    - 飛び地（別の外周領土リング）が他の外周リングと重ならないこと。
  - **地図全体の衝突判定・スナップ・共有化**（FR-89）: 穴/飛び地の頂点も、地図全体の**他の末端地物との衝突判定（エッジ滑り）**、近接**スナップ**、**共有頂点化**の対象とする。エッジハンドルのドラッグで**生成中の頂点**も同様に衝突判定・スナップ・共有化の対象とする。これらの衝突応答・スナップ・共有化処理は U24 が提供する基盤に委譲し、本ユニットはその対象に穴/飛び地リングの頂点を確実に含める（対象から漏らさない）ことを担う。
- **穴/飛び地の削除と交互構造維持の再編**（FR-24）
  - 穴リング削除・飛び地（領土）リング削除のいずれも、**U07 の削除＋再編純粋関数** `(リング階層, 削除対象) → 再編後リング階層` を呼び出して行う。穴削除時・領土削除時で子リング付け替え規則が異なるが、その規則は U07 が実装する。本ユニットは両方の削除経路を提供し、片方だけ実装して「もう一方も同様」と省略しない（開発ガイド §1.2 省略の禁止、§2.10 対概念へ判断を反映する）。
  - 削除＋再編を**単一の編集コマンド**として履歴に積み、1 回のアンドゥで削除前の状態へ完全復元、1 回のリドゥで再適用できるようにする（FR-24 / FR-73 / FR-94）。
- **確定時の整合性維持プロセスのトリガー**（FR-61〜FR-63 / FR-88）
  - 追加・編集・削除のいずれの操作も、確定時に整合性維持プロセス（編集案生成→時間整合性検証→空間競合検出→競合解決ダイアログ→解決適用と一括確定）へ接続する。競合解決を含む一連全体を単一のアンドゥ単位として扱う（FR-73 / FR-94）。
  - 確定は**現在のタイムライン時刻を編集基準時刻**とし、当該地物の歴史の錨として記録する（FR-57：同時刻の錨があれば更新、なければ編集時刻を開始時刻とする新しい錨を追加）。形状編集であっても錨の完全状態を一体として扱う（FR-59）。
- **一時的 UI 状態の破棄**: 追加中の頂点列・判定中モード・編集中ドラフトなどの一時状態を、確定・キャンセル・ツール切替・モード切替・選択解除のすべての経路で破棄する（開発ガイド §5.2）。

### やらないこと

- **リング階層の判定・再編の純粋ロジックそのものの実装**（FR-24 / FR-25）。交互不変条件の検証、包含・非交差・非重複の幾何検証、削除時の子リング付け替えは **U07** が提供する。本ユニットは再実装せず呼び出す。
- **頂点編集の操作基盤の実装**（FR-28 / FR-30〜FR-33 / FR-87 / FR-89）。頂点／エッジハンドルの描画・ドラッグ、エッジ滑り（衝突検出・衝突応答）、近接スナップ、共有頂点化・共有解除といった基盤は **U24** が提供する。本ユニットはこれらを穴/飛び地リングに適用するだけで、衝突応答アルゴリズムやスナップ距離判定を独自実装しない。
- **穴あけによる新地物生成**（FR-45）。末端地物内部に新しい独立した末端地物を生成し元に穴を形成する操作は別ユニットの責務。本ユニットの「穴追加」は**単一面情報の形状編集**にとどまり、新地物を一切生成しない（FR-23）。両者を混同しないこと。
- **末端地物同士の地図全体での空間的排他検証アルゴリズムの実装**（FR-26 / FR-27）。衝突判定（エッジ滑り）の述語・空間インデックスは U24／依存ユニットが提供する。本ユニットは穴/飛び地頂点をその検証対象に含めることだけを担う。
- **面のブーリアン演算**（和・差・交差。FR-37 / FR-45 / FR-50 / FR-51 / FR-63）。競合解決での差分調整は整合性維持プロセス側が担う。
- **面情報同士のツリー階層（親子関係）操作**（FR-34〜FR-53）。本ユニットが扱う「穴/飛び地リング」は 1 つの面情報内のリング構造であり、面情報のツリー（末端地物・集約地物）とは別概念である（U07 の「やらないこと」と同じ注意）。
- **競合解決ダイアログ UI そのものの実装**（FR-62 / FR-63）。本ユニットは確定時に整合性維持プロセスへ接続するのみで、モーダル UI は別ユニットが提供する。
- **線情報・点情報の編集**。本ユニットは面情報のリング編集に限定する。

## 依存（dependsOn）

本ユニットは以下に依存する。依存ユニットが公開する型・純粋関数・操作基盤を前提として実装し、再実装しない（単一の真実源。技術方針 §4 / 開発ガイド §5.30）。依存ユニットのエクスポート名・型・関数シグネチャが本書の想定と異なる場合は、推測でフォールバックを書かず、依存ユニットの実体をソースで確認して結線する（開発ガイド §2.11 既存性の主張は実在確認してから書く）。

- **U24（面情報頂点編集ツールの操作基盤）**: 編集モードでの面情報頂点編集の操作基盤を提供する前提のユニット。本ユニットは U24 から次を利用する想定で実装する（実体に合わせて結線する）。
  - 頂点ハンドル・エッジハンドルの表示と、頂点移動・頂点追加・頂点削除の操作（FR-87 / FR-88）。
  - 頂点移動・生成中頂点に対する**地図全体の他末端地物との衝突判定（エッジ滑り）**、**近接スナップ**、**共有頂点化**の処理（FR-28 / FR-30〜FR-33 / FR-89）。
  - アクティブ地物・頂点選択セット・現在時刻などの編集セッション文脈、および編集コマンドを履歴へ積み整合性維持プロセスへ接続する確定経路。

  U24 がリング単位の追加（穴/飛び地の起点）や役割付与を直接提供しない場合、その不足を未解決課題文書（現状.md）へ記録し、U24 側の拡張か本ユニットでの組み立て方針を確認してから着手する。U24 の頂点編集対象に「穴/飛び地リングの頂点」が含まれていない場合は、それを含める結線が本ユニットの中核作業となる（FR-89 の受け入れ基準）。

- **U07（リング階層モデルと不変条件検証・削除時再編）**: 本ユニットは U07 から次を利用する。
  - リング階層モデル（領土リング／穴リングの判別共用体、リングの親子関係、派生算出する階層深度）。
  - 交互不変条件の検証、穴の親内部完全包含・境界非交差、兄弟非交差、飛び地非重複の各検証を行う純粋関数（FR-25）。リアルタイム検証（候補表示）と確定前検証（コマンド拒否）の両方で同じ関数・同じ戻り値を使う（開発ガイド §5.26）。
  - 穴削除・領土削除時の交互構造を保つ子リング付け替えを行う `(リング階層, 削除対象) → 再編後リング階層` の純粋関数（FR-24）。
  - 内外判定（点とリングの内外）に用いる幾何述語（U07 が U06 から再エクスポート／委譲する形を含む）。最初のクリック位置の穴/飛び地自動判定で利用する。

  U07 に必要な検証・再編関数が無い場合は、本ユニット内に幾何述語や再編ロジックを持ち込まず、不足を現状.md に記録した上で U07 側へ追加するか結線方針を確認する（単一の真実源）。

## 実装方針（技術方針に沿う）

技術方針が定める採用スタックと層分離に厳密に従う。

### 層分離と配置

- 本ユニットは**ツール層**である。判定・再編・幾何述語といった純粋ロジックは `domain`（U07）に置き、本ユニットは編集セッションの状態遷移・コマンド組み立て・ツール UI 結線を担う。
  - 穴/飛び地の追加・編集・削除を表現する**編集コマンド**（コマンド → 新ドメイン状態）は、純粋関数として `domain` 層に置き、Immer による不変更新・二重スタック履歴に乗せる（技術方針 2.6 / 2.13）。コマンド本体は Electron／React／Canvas に依存させず Vitest で単独実行できること。
  - ツールの状態遷移（モード自動判定中／頂点配置中／編集中／確定待ち）と UI セッション状態（現在のツール・対象面・追加中頂点列）は Zustand の薄いストアに置く。地図描画は React 再レンダリングサイクルから切り離し、Canvas 側が Zustand を購読して仮表示・ハイライトを描く（技術方針 2.3 / 2.5）。
- 依存方向は `domain` へ内向きに固定する。本ユニットの `domain` 部分（コマンド）から `ui` / `render` / `shell` を参照しない（技術方針 2.13 / 5.1）。

### 穴/飛び地自動判定

- 最初のクリック点の内外判定は U07／U06 の内外述語へ委譲する。「対象面の塗り領域内（領土リング内部かつ穴リング内部でない）」を穴作成、それ以外を飛び地作成と判定する。**飛び地と穴の判定は対概念**であり、判定条件を一方だけ決めて他方を取りこぼさない（開発ガイド §2.10 / §4「対概念の整合」）。
- 判定に用いるリング集合は「現在の編集基準時刻における対象面情報の有効な錨の形状」とする。時間が変われば対象形状も変わるため、時刻を固定して判定する（開発ガイド §5.15 タイムスタンプはコンテキスト上の時刻を参照する）。

### 編集中のリアルタイム検証と衝突・スナップ・共有化

- ドラッグ追従中・頂点追加候補表示中は、U07 の検証関数で包含／非交差／非重複をリアルタイム検証し、違反する移動先・追加位置を候補から除外する。同時に、U24 の衝突判定（エッジ滑り）・スナップ・共有頂点化を穴/飛び地頂点に適用する。
- ドラッグ中の連続更新はホットパスである。毎フレーム不変コピーを取らず、トランジェント（Immer ドラフト保持）またはミュータブル一時バッファで処理し、近傍候補（RBush）のみ軽量判定する。**操作確定時にのみ**正式なイミュータブルコマンドを発行して履歴に積む（技術方針 2.6 / R5、開発ガイド §5.8 押下→移動→解放を全パスで保証）。
- リアルタイム検証（候補表示用）と確定前検証（コマンド拒否用）は**同じ U07 関数・同じ戻り値**を共有する。UI が違反候補を隠しても、ショートカット・メニュー・直接呼び出し・アンドゥ／リドゥで不正状態が入りうるため、確定コマンドでも必ず同じ検証を通す（開発ガイド §5.26）。拒否理由は日本語ユーザー通知とテスト可能な戻り値の両方で扱う（FR-115）。

### 削除と交互構造維持の再編（単一操作）

- 穴削除・飛び地（領土）削除を**それぞれ明示的に**コマンド化し、内部で U07 の削除＋再編純粋関数を呼ぶ。削除と子リング付け替えを 1 つのコマンドにまとめ、1 回のアンドゥで削除前へ、1 回のリドゥで再適用できることを保証する（FR-24 / FR-94）。
- アンドゥに必要な情報（削除されたリング・その子リング・付け替え前後の親子関係）を依存データも含めて過不足なく保存し、復元時は新インスタンスを再帰生成する。ID を生成する処理は redo で採番し直さず初回 ID を復元する（開発ガイド §5.20）。
- execute / undo / redo は同じイベント規約で、touch した全リング・全形状へ対称に通知する。直後に手動リフレッシュを書きたくなったら通知漏れのサインである（開発ガイド §5.23）。

### 確定経路と整合性維持プロセス

- 追加・編集・削除の確定は、U24 が提供する（または整合性維持プロセスユニットが提供する）確定経路へ接続し、編集案生成→時間整合性検証→空間競合検出→競合解決→一括確定の固定順序を経る（FR-61）。競合解決を含む一連全体を単一アンドゥ単位とする（FR-73 / FR-94）。
- 確定値が現在状態（baseline）と一致する no-op（頂点が動いていない確定）では履歴コマンドを積まない（開発ガイド §5.24 幽霊 undo エントリの防止）。baseline はツール状態と同一ソースから導出する。

### テスト

- 「入力リング階層 → 追加／編集／削除コマンド → 期待リング階層」を Vitest で単体テストし、穴追加・飛び地追加・穴削除・飛び地削除・頂点移動・頂点追加・頂点削除（3 点未満でのリング削除）の各ケースを網羅する（技術方針 2.14、開発ガイド §1.9）。
- 自動判定（穴 vs 飛び地）は、最初のクリック点が塗り内／面外／穴内のそれぞれの位置にある入力で、判定結果が正しいことを単体テストする。
- リアルタイム検証で違反操作が拒否されること、確定コマンドでも同じ検証が働くことを両経路でテストする（開発ガイド §5.26）。
- 削除＋再編が単一コマンドで前後状態を比較でき、1 アンドゥで完全復元・1 リドゥで再適用できることをテストする（FR-24）。
- fast-check で任意のリング構成・任意の追加/編集/削除に対し、確定後も交互不変条件・包含/非交差/非重複が保たれることをプロパティテストで検証する（U07 のジェネレータ共通モジュールを再利用。技術方針 R7）。
- テスト fixture はリテラルで型を満たすのではなく、U07／U06 のファクトリで実体を構築する（開発ガイド §5.39）。

## 受け入れ基準（テスト可能な形で列挙）

以下をすべてテスト可能な形で満たすこと。

1. **最初のクリック位置による穴/飛び地の自動判定と最低 3 点での作成**（FR-22）
   - 最初のクリック点が対象面の塗り領域内（領土リング内部かつ穴内部でない）なら穴作成モード、面外または穴内なら飛び地作成モードと自動判定されることを、各位置の入力で単体テストできる。
   - 頂点が 3 点に達するまで確定できず、3 点未満での確定は拒否され理由が通知される。3 点以上で確定するとモードに応じて穴リング／領土（飛び地）リングが対象面情報に追加されることをテストできる。
   - 追加中の仮表示・クロージング線・最後の頂点取り消し・全体キャンセル・グリッドスナップが機能する（FR-78 の追加共通機能）。

2. **穴/飛び地追加が単一面の形状編集で新地物を生成しない**（FR-23）
   - 穴追加・飛び地追加の前後で、地図上の面情報（地物）の総数が変化しないことをテストできる。追加結果は対象面情報のリング集合の変化としてのみ現れ、新しい独立した面情報・新しい歴史の錨を持つ別地物は生成されない。

3. **編集時に包含/非交差/非重複制約をリアルタイム検証**（FR-25）
   - 穴/飛び地リングの頂点移動・頂点追加の編集中に、U07 の検証関数で「穴の親内部完全包含・境界非交差」「兄弟非交差」「飛び地の他外周非重複」が常時検証され、違反する移動先・追加位置が候補から除外される（または操作が禁止される）ことをテストできる。
   - リアルタイム検証と確定前検証が同じ関数・同じ戻り値を共有し、ショートカット・直接呼び出し経路でも不正形状が確定されないことをテストできる（開発ガイド §5.26）。

4. **削除時に交互構造を保つ子リング付け替えが単一操作でアンドゥ復元**（FR-24）
   - 穴リング削除時・飛び地（領土）リング削除時のいずれも、U07 の再編関数により子リングが交互構造を保つ位置へ付け替えられ、再編後の階層が交互不変条件を満たすことをテストできる。
   - 削除＋再編が単一の編集コマンドであり、1 回のアンドゥで削除前の状態へ完全復元、1 回のリドゥで再適用できることをテストできる。穴削除・領土削除の両ケースが個別の単体テストで検証される（片方のみで済ませない）。

5. **穴/飛び地頂点も衝突判定・スナップ・共有化の対象**（FR-89）
   - 穴/飛び地リングの頂点移動が、地図全体の他末端地物との衝突判定（エッジ滑り）・近接スナップ・共有頂点化の対象になることをテストできる。
   - エッジハンドルのドラッグで生成中の頂点も、同様に衝突判定・スナップ・共有化の対象になることをテストできる。
   - 穴/飛び地頂点がこれらの対象から漏れていないこと（外周頂点と同じ扱いを受けること）を回帰テストで確認できる。

6. **確定時の整合性維持プロセス接続と単一アンドゥ単位**（FR-61〜FR-63 / FR-73 / FR-94）
   - 追加・編集・削除の確定が整合性維持プロセス（時間整合性検証→空間競合検出→競合解決→一括確定）へ接続され、競合解決を含む一連全体が単一のアンドゥ単位として扱われることをテストできる。
   - 確定は現在のタイムライン時刻を編集基準時刻とし、当該地物の歴史の錨として記録される（同時刻の錨は更新、なければ新規追加。FR-57）。

7. **一時 UI 状態の全経路破棄**（開発ガイド §5.2）
   - 「追加開始 → キャンセル → 再開始」「追加開始 → 確定 → 再開始」「ツール切替」「モード切替」「選択解除」の各経路で、追加中頂点列・判定モード・編集ドラフトが破棄され、次回操作へ引き継がれないことをテストできる。

8. **純粋性・単独実行・ビルド**
   - 追加・編集・削除の編集コマンド（`domain` 部分）が Electron／React／Canvas に依存せず Vitest で単独実行でき、上記テストが全パスし、ビルドが通ること。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に以下の教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として 1 文以上で明示してから実装すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **教訓 §5.25「仕様が限定した対象範囲を実装で広げない」**: 本ユニットは**単一面情報の形状編集**に限定され、穴追加は新地物を生成しない（FR-23）。「くり抜くなら新地物も作るのが自然」と感じても、それは穴あけによる新地物生成（FR-45）の別ユニット責務である。範囲を広げたくなったら FR-22 / FR-23 / FR-45 を引用して止める。**適用**: 穴追加コマンドは対象面のリング集合だけを変更し、地物総数・新規錨を生成しない（受け入れ基準 2）。
- **教訓 §2.10「対概念へ判断を反映する」 / §1.2「省略の禁止」**: 穴と飛び地、追加と削除、穴削除の再編と領土削除の再編は対概念である。一方の自動判定・付け替え・テストを書いたら、他方にも同じ判断を反映し、「もう一方も同様」と省略しない。**適用**: 穴作成と飛び地作成、穴削除と飛び地削除をそれぞれ独立に実装・テストする（受け入れ基準 1・4）。
- **教訓 §5.26「編集制約はコマンド確定前にも同じサービスで検証する」**: リアルタイム検証（候補表示）と確定前検証（コマンド拒否）は U07 の同じ関数・同じ戻り値を共有する。UI が違反候補を隠しても、ショートカット・メニュー・undo/redo・直接呼び出しで不正形状が入りうる。拒否理由は日本語通知とテスト可能な戻り値の両方で扱う。**適用**: 確定コマンド内でも U07 検証を必ず通し、両経路をテストする（受け入れ基準 3）。
- **教訓 §5.2「一時的 UI 状態は全経路で破棄する」**: 追加中頂点列・判定モード・編集ドラフトを、開始・確定・キャンセル・ツール切替・モード切替・選択解除のすべての経路で破棄する。残ると次回操作へ暗黙に引き継がれ意図しない値で確定できてしまう。**適用**: 受け入れ基準 7 の各経路を E2E／単体で確認する。
- **教訓 §5.8「押下→移動→解放シーケンスを全パスで保証する」 / §5.7「完了トリガーを必ず実装する」**: 頂点配置・頂点ドラッグの押下→移動→解放を全パス（クリック・ドラッグ）で開始・更新・終了させる。移動が発生しなかったクリックの考慮漏れに注意し、追加の「完了（確定）」トリガーを UI から必ず呼ぶ。**適用**: クリックのみで頂点が増えるケースとドラッグで頂点が動くケースの両方をテストする。
- **教訓 §5.24「確定ハンドラには no-op ガードを入れる」**: 頂点が動いていない確定で履歴コマンドを積まない。baseline はツール状態と同一ソースから導出する。**適用**: no-op 確定で undo スタックが増えないことをテストする。
- **教訓 §5.20「元に戻す情報は依存データも含めて過不足なく保存する」 / §5.21「削除は参照掃除と連鎖剪定まで行う」**: 削除＋再編の undo に必要な情報（削除リング・子リング・付け替え前後の親子関係）を過不足なく保存し、復元時は新インスタンス再帰生成、初回 ID を復元する。削除時に dangling な親参照を残さない（U07 の再編後不変条件チェックで保証）。**適用**: 受け入れ基準 4 の単一操作アンドゥ復元をテストする。
- **教訓 §5.23「コマンドの execute/undo/redo は対称に通知する」**: execute / undo / redo を同じイベント規約で touch した全リング・全形状へ対称通知し、二重通知しない。**適用**: イベント発火を期待集合の厳密一致でテストする。
- **教訓 §5.15「タイムスタンプはコンテキスト上の時刻を参照する」 / FR-57 / FR-59**: 自動判定・確定はシステム時刻でなく現在のタイムライン時刻（編集基準時刻）を参照し、対象面の有効な錨の形状で判定・確定する。錨の完全状態を一体として扱い部分確定しない。**適用**: 異なる時刻で対象面形状が変わるケースの判定をテストする。
- **教訓 §5.30「過少共有と過剰共有の両方を戒める」 / §4「単一の真実源」**: 判定（内外）・検証（包含/非交差/非重複）・再編（付け替え）・衝突応答・スナップ・共有化は U07／U24 の実装を共有し再実装しない（過少共有の戒め）。一方で、穴と飛び地で制約・付け替え規則が異なる部分は安易に共有せず、差異を列挙してから共有可否を判断する（過剰共有の戒め）。
- **教訓 §5.1「集合演算は複数片を返す前提で扱う」**: 整合性維持プロセスの競合差分調整や、編集で形状が複数片に分かれる入力で、返却された全片を扱い先頭片だけ採用しない。**適用**: 結果が 2 片以上になる入力で全片が反映されることをテストする。
- **教訓 §5.18「空配列・空オブジェクトは真値である」**: 「穴 0 個」「飛び地 0 個」「最外周のみ」「追加中頂点 0 点」の境界を論理和の短絡で誤って空扱いにしない。リング数・頂点数 0／1／多数の境界を明示判定する。
- **退化ケースの防御**（技術方針 R2）: 自己交差・ゼロ長エッジ・極小スリバー・数値誤差に備え、幾何判定の前に座標量子化を通し（U07／U06 のトレランス基準を使用）、確定後に不変条件を再チェックする。境界の接触（接するが重ならない）を重なりと誤判定しないトレランス設計に従う（FR-25 / FR-26 はいずれも境界接触を重なりに含めない）。独自のトレランスを再発明しない。
- **無限横スクロール／経度シフトとの整合**（技術方針 R3）: 世界端をまたぐ穴/飛び地の内外判定・交差判定では、経度を連続スカラーで扱い、必要に応じて ±360 度オフセットでワールドラップ展開してから判定する。U07／U06 がラップ正規化を提供する場合はそれに委譲し、本ユニットで折り返し処理を再発明しない。
- **「リング階層」と「面情報のツリー」を混同しない**（U07 と同じ注意）: 本ユニットが扱うのは 1 つの面情報内のリング（領土・穴）の入れ子構造であり、面情報同士の親子（末端地物・集約地物。FR-34〜）とは別物。型名・関数名で取り違えない。
- **テスト fixture は実体を生成する**（教訓 §5.39）: リング階層・面情報の fixture は U07／U06 のファクトリで構築し、リテラルで型だけ満たす構造にしない。
- **クリーンルーム**（開発ガイド §3.1）: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-22〜FR-25 / FR-89 等）・技術方針として直接記述する。
- **失敗の教訓化**（開発ガイド §1.5 / §1.9）: 実装中に既存教訓で説明できない不具合の根本原因が見つかったら、完了前に開発ガイド §5 へ新教訓を追記し、回帰テストを同一作業内で追加する。やり残しは現状.md へ記録する（§1.8）。

## 目的

面情報のツリー位相（親子関係）を変えるあらゆる操作を、**単一の所属変更フロー**として提供する。割譲・連邦化・独立・帰属・直轄化・自治化・解体は、いずれも別個の操作種別として別 UI を持つのではなく、「対象地物の新しい上位領域を決める」という同一フローのパラメータ違いとして表現される（FR-46）。

本ユニットは、このフローの中核となる以下のドメインロジックと、それを駆動するための構造化された入出力契約を提供することを目的とする。

1. 対象地物に対する **新上位領域の決定**（「既存の面情報から選ぶ」「新規上位領域を作成する」「親なし＝最上位領域へ」の 3 択）と、その結果としての親子関係の張り替え。
2. **新規上位領域作成サブフロー**（名称・種別ラベル入力 → 末端で既存最上位を選ぶか新規最上位を作成 → 再帰的に上位領域を積み上げ、中間階層を後付け挿入）（FR-47）。
3. **親候補の絞り込み検証**（循環参照防止・存在期間で「親領域＝下位領域の和」を将来満たせる位置にあること）（FR-48、教訓 5.27）。
4. 飛び地化の許容（陸続きでない上位領域への所属、複数独立リング導出）（FR-49）。
5. 直接所属変更は末端地物のみ・集約地物は全下位領域を対象、という対象限定（FR-48）。
6. フロー全体を **不可分の 1 操作**として確定し、1 回のアンドゥで復元できること、確定時に階層整合性を維持すること（FR-48 / FR-94）。

本ユニットは純粋ドメインロジック（`domain` 層）として実装し、Electron・React・Canvas に依存しない。フローを駆動するダイアログ・候補リスト・プレビューの**描画**そのものは UI 層（U20 のシェル／ダイアログ枠の上に置くフロー UI）の責務であり、本ユニットは UI が必要とする構造化データ（選択肢・候補一覧・拒否理由・確定後の結果）を供給する純粋関数群を提供する。

## スコープ

### やること

1. **単一フローのモデル化（FR-46）**
   - 「対象地物（1 件）」を入力に取り、「新上位領域の決定」を 3 択（既存から選ぶ／新規作成／親なし＝最上位へ）で受ける単一のフロー状態機械を、純粋関数の遷移として実装する。
   - 割譲・連邦化・独立・帰属・直轄化・自治化・解体を、この単一フローの入力パラメータの組み合わせとして表現する（操作種別ごとの分岐 UI・分岐エンティティ・分岐コマンドを作らない）。各操作が本フローのどのパラメータ設定に対応するかを、本ユニット内のテストで対応表として固定する（後述「操作種別の対応表」）。

2. **親子関係の張り替えコマンド**
   - 対象地物の上位領域参照を、決定された新上位領域へ張り替える純粋コマンド（状態 → 新状態）を提供する。
   - 「親なし（最上位へ）」を選んだ場合は上位領域参照を外し、最上位フラグを真にする（独立／解体の構成要素）。最上位フラグが真であることと上位領域を持たないことの同値（FR-39）を確定後も保つ。
   - 張り替えにより集約地物が全下位領域を失う場合、その集約地物はその時刻以降自動消滅する（FR-35 / FR-41。消滅の検出は結果状態で判定する＝教訓 5.6。解体は「配下全下位領域を親なしへ移し、元集約地物を全下位領域消失で自動消滅させる」操作としてこの仕組みで表現する）。

3. **新規上位領域作成サブフロー（FR-47）**
   - 新規上位領域の名称・種別ラベルを入力として受け取り、新しい集約地物を生成する。集約地物は形状属性を保持せず、形状は下位領域の和として算出される（FR-35）。
   - サブフローの末端で「既存の最上位面情報を新規上位領域の上位に置く（帰属）」か「新規の最上位面情報を作成する」かを選べる。
   - 上位領域の作成を**再帰的に積み上げ**られる（新規上位領域のさらに上位に新規上位領域を作る）。これにより既存の親子関係の間へ**中間階層を後付け挿入**できる（自治化＝既存の下位領域とその上位領域の間に新規中間集約地物を挿入する操作は、このサブフローで表現する）。
   - 連邦化（複数の最上位面情報を新規最上位の下位領域として束ねる）は、複数対象に対し共通の新規最上位を新上位領域として割り当てる本サブフローの適用として表現する。

4. **親候補の絞り込み検証（FR-48、教訓 5.27）**
   - **循環参照防止**: 新上位領域候補は、対象地物自身および対象の下位領域すべてに含まれてはならない。ただし対象の**上位領域は直轄化のため候補に含む**（中間集約地物を抜かして、より上位の上位領域へ移す）。
   - **存在期間整合**: 候補上位領域が、対象の存在期間において「親領域＝下位領域の和」を将来満たせる位置にあること（存在期間が両立し、対象を下位に加えても集約地物形状＝下位領域の和の不変条件を満たせること）を検証する。
   - 候補一覧の算出（UI のピッカーが表示する許可候補集合）と、確定前検証（選ばれた候補が依然として合法か）の**両方**を同一の検証サービスで行う（教訓 5.26）。

5. **対象範囲の限定（FR-48）**
   - **直接の所属変更は末端地物に限る**。集約地物そのものの上位領域を変えたい場合は、その**全下位領域**を対象として所属変更を行う（集約地物を直接張り替えない）。
   - 集約地物が選択された場合は「全下位領域を対象とする」展開を行い、各下位領域に同一の新上位領域決定を適用する（複数対象の一括所属変更）。

6. **飛び地化の許容（FR-49）**
   - 下位領域が地理的に陸続きでない上位領域へ所属することを許容する。この場合、上位領域（集約地物）の形状は分離した全下位領域を包含する**複数の独立リング**として導出される。
   - 飛び地化は禁止条件ではない（陸続き判定を所属変更の合否条件にしない）。集約形状の和算出は U08（集約地物形状＝下位領域の和）の派生に委ね、本ユニットは「飛び地化しても拒否しない」ことを保証する。

7. **複合操作の不可分性と確定後整合性（FR-48 / FR-94）**
   - フロー確定時の全変更（親子張り替え＋新規上位領域生成＋中間階層挿入＋集約地物の自動消滅＋複数対象の一括適用）を、**不可分の 1 操作**として確定し、1 回のアンドゥで全復元できる単一コマンドとして組む。
   - 確定時に階層整合性（最上位フラグと親なしの同値、集約地物形状＝下位領域の和、循環なし）を U08 の検証サービスで再検証し、違反すれば確定せず状態を破棄して拒否する（教訓 5.22 / 5.26）。

### やらないこと

- **所属変更フローを駆動するダイアログ・候補リスト・ミニマッププレビューの描画**（U20 のシェル／ダイアログ枠の上に置くフロー UI／UI 層の責務）。本ユニットは UI が必要とする構造化データ（フロー状態・選択肢・許可候補一覧・拒否理由・確定後の結果）を供給するのみ。
- **集合演算（面の和・差）そのものの実装**。集約地物形状＝下位領域の和の算出・検証は U08（その内部で U06 のブーリアン演算）に委譲する。本ユニットでブーリアン演算を自前実装しない。
- **階層不変条件の検証アルゴリズム本体**（最上位フラグ同値・形状＝和・循環検出・階層深度派生）。U08 の責務。本ユニットは U08 の検証サービスを呼ぶのみ。
- **整合性維持プロセス（時間整合性検証・空間競合検出・競合解決）の骨格**。所属変更の確定が空間競合（末端地物同士の重なり）を生じうる場合の競合解決オーケストレーションは U13 の固定順序プロセスに委ねる。本ユニットは所属変更固有の事前条件（循環なし・存在期間整合）の検証と親子張り替えを担い、確定は U13 のプロセス／単一アンドゥ単位の機構へ接続する。
- **合体（結合）フロー**（FR-50〜FR-52）。結合は所属変更とは**別物**であり、本ユニットの対象外。事前条件も別概念として分離する（教訓 5.27）。
- **末端→集約遷移時のプロパティ引き継ぎ・直轄領の自動生成**（FR-36 / FR-37）。本ユニットは「末端地物が下位領域を獲得して集約地物へ遷移する」結果状態を生じさせる側だが、遷移時のプロパティ移送・形状破棄・差分からの直轄領自動生成のロジック本体は別ユニットの責務。本ユニットはその遷移を引き起こすトリガー（対象が新たな下位領域を得る）を結果状態として明示し、遷移処理へ接続する。
- **共有頂点の継続規則の本体**（U11）。所属変更で形状が作り直されることは原則ないが、新規上位領域（集約地物）は形状を持たないため共有頂点の張り替えは生じない。必要が生じる場合のみ U11 の継続規則を呼ぶ。
- **時間軸・歴史の錨そのものの編集**（錨列の昇順・非重複等は別ユニット）。本ユニットは「対象時刻で有効な状態スナップショット」を入力前提とし、所属変更を当該時刻の錨へ記録する形を取るが、錨列の再編アルゴリズム本体は扱わない。
- **種別ラベルに基づく検証**（FR-40）。種別ラベルは表示専用であり、親候補の絞り込み・整合性検証に一切関与させない（親が子の種別を強制しない、同一親に異種別の子を混在可）。

## 依存(dependsOn)

本ユニットは以下のユニットに依存する。依存ユニットの公開インタフェース（関数名・引数・戻り値型）は、偶然の一致に頼らず共有型・両側テストで固定する（教訓 5.33）。依存ユニットがまだ未実装の場合は、本仕様に記す入出力契約に沿った型インタフェースを先に定義し、その型に対してフロー骨格と単体テストを実装する。

- **U20 — アプリレイアウトシェルとモード/ツールバー骨格（所属変更フローを駆動する UI シェル／ダイアログ基盤の接続先）**: 本ユニットが供給する構造化データ（フロー状態・3 択の選択肢・許可候補一覧・新規上位領域作成サブフローの入力欄定義・拒否理由・確定結果）を受け取り、U20 のダイアログ枠・パネル枠・オーバーレイ層の上に所属変更フローのダイアログ・候補ピッカー・プレビューを描画する。本ユニットは UI 側が必要とするデータ契約（型）を定義・公開し、フロー UI はそれを import して駆動する。描画・入力収集は UI 層（U20 の枠組み上）、決定ロジック・検証・確定は本ユニット、という責務分界を型で固定する（教訓 5.33 / 5.34）。フロー自体の起動口（編集モードの右クリック「所属変更」項目）は U36 が提供し、U36 は対象面情報 ID を渡して本フローを開く。
- **U08 — ツリー階層モデルと不変条件検証**: 親候補の存在期間整合検証（親領域＝下位領域の和を将来満たせるか）、確定後の階層整合性再検証（最上位フラグ同値・形状＝和・隙間なし）、循環参照検出、下位領域の列挙・縦方向領域の算出、末端／集約の結果状態判定に使用する。本ユニットは U08 の検証・派生サービスを呼ぶのみで、検証アルゴリズム・ブーリアン演算を自前実装しない。U08 のトレランス／座標量子化方針（技術方針 R2）に整合させる。
- **U13 — 整合性維持プロセスの骨格（固定順序オーケストレーション）／単一アンドゥ単位の確定**: 所属変更の確定を、時間整合性検証 → 空間競合検出 → 競合解決 → 一括確定 の固定順序プロセスへ接続し、フロー全体を 1 アンドゥ単位の不可分コマンドとして確定する（FR-94）。本ユニットは「所属変更編集案（対象・新上位領域決定・生成する新規地物・複数対象展開・自動消滅対象を含む完全な変更案）」を U13 へ渡し、確定／競合あり／拒否の結果を受け取る。本ユニットは時間整合性検証・空間競合検出・アンドゥスタックを自前実装しない。
- **U11 — 共有頂点システムの継続規則（必要時のみ）**: 所属変更で形状の作り直しが生じる例外的ケース（あれば）で共有関係の継続を委譲する。集約地物は形状を持たないため通常は呼ばない。

> dependsOn に挙がっていない要件（合体フロー・直轄領自動生成・錨列再編・描画）には依存しない。入力は「対象時刻で確定済みの面情報集合とその親子関係・最上位フラグ・形状・存在期間」というプレーンなデータとして受け取る。

## 実装方針(技術方針に沿う)

技術方針（`docs\技術方針.md`）に従い、本ユニットは `domain` 層の純粋関数・イミュータブル更新として実装する。React・Electron・Canvas へ依存せず、Vitest 単独で実行できること（技術方針 2.13）。Immer によるイミュータブル更新（技術方針 2.6）、判別共用体による不正状態の排除（技術方針 2.1）を用い、RBush／polygon-clipping は依存ユニット側に局在させ本ユニット内部の純粋性を保つ。

### フロー状態の判別共用体表現（不正状態の排除）

所属変更フローの状態と「新上位領域の決定」を判別共用体で表現し、不正状態を表現不能にする（技術方針 2.1 / 4.43 相当）。

- **新上位領域の決定（判別共用体）**:
  - `既存を選ぶ`: 既存面情報 ID（許可候補一覧の中の 1 件）。
  - `新規作成`: 新規上位領域作成サブフローの結果（生成する集約地物の名称・種別ラベルと、そのさらに上位の決定＝再帰的に同じ判別共用体）。
  - `親なし`: 最上位領域へ（上位領域参照なし・最上位フラグ真）。
- **新規上位領域作成サブフローの末端（判別共用体）**: `既存最上位を上に置く（帰属）` または `新規最上位を作成`。これにより再帰の終端を型で固定する。
- 「種別ラベルが付いているか」「中間階層を何段挟むか」を任意段数で表現できるよう、`新規作成` の上位決定フィールドが自身と同じ判別共用体を再帰的に持つ構造とする（中間階層の後付け挿入＝再帰の段数）。

### 操作種別の対応表（FR-46 の単一フロー証明）

別 UI を設けないことを保証するため、各操作種別が本フローのどのパラメータ設定に写像されるかを、本ユニットのテストで対応表として固定する（教訓 5.30 過剰共有の戒め＝種別ごとに UI を分けない／過少共有の戒め＝同一フローを共有する、の両立を確認）。

| 操作種別 | 対象 | 新上位領域の決定 | 補足 |
| --- | --- | --- | --- |
| 割譲 | 末端地物（または集約の全下位領域） | `既存を選ぶ`（別の既存上位領域） | 既存親から別の既存親へ移す |
| 帰属 | 最上位の地物 | `既存を選ぶ`（既存上位領域の下へ） | 割譲と同型。最上位フラグ真→偽 |
| 連邦化 | 複数の最上位地物 | `新規作成`→末端`新規最上位を作成` | 共通の新規最上位の下位として束ねる |
| 独立 | 対象地物 | `親なし` | 最上位フラグ真へ |
| 直轄化 | 対象地物 | `既存を選ぶ`（対象の上位領域＝候補に含む） | 中間集約地物を抜かして上位へ |
| 自治化 | 既存の下位領域 | `新規作成`→末端`既存最上位を上に置く`相当（既存上位領域と対象の間へ中間集約を挿入） | 中間階層の後付け挿入 |
| 解体 | 集約地物の全下位領域 | 各下位領域に `親なし` | 元集約地物が全下位領域消失で自動消滅 |

> この対応表は「各種別が本当に同一フローのパラメータ違いか」を列挙確認するためのものである（教訓 5.30）。実装で種別ごとに分岐 UI・分岐コマンドを作りたくなったら、本表と FR-46 を引用して止める。

### 純粋関数・イミュータブル・確定前検証

- 入力ドメイン状態を破壊的に変更しない。確定前は共有データを破壊更新しない（教訓 5.22）。検証用の仮適用で合法性を確認してから U13 経由で確定し、失敗時は追加した新規地物・張り替えをすべてロールバックする。
- 親候補の許可候補一覧算出（UI ピッカー用）と、確定前の合法性再検証は、**同一の検証述語**を共有する（教訓 5.26 / 開発ガイド §4 単一の真実源）。UI が候補を隠していても、ショートカット・メニュー・直接呼び出し・undo/redo 経路から不正な新上位領域が入りうるため、確定前検証を必須にする。拒否理由はユーザー通知用日本語メッセージ（FR-115）とテスト可能な機械可読フィールドの両方で返す。

### 親候補絞り込みの検証述語（FR-48、教訓 5.27）

候補集合を絞り込む述語を、所属変更**固有**の事前条件として分離実装する（結合の事前条件と混同しない＝教訓 5.27）。

- **循環参照防止**: 候補が「対象地物自身」または「対象の下位領域すべて（U08 で列挙、循環に耐える走査＝教訓 5.28）」に含まれないこと。**対象の上位領域は候補に含む**（直轄化のため。FR-48 の例外を実装で削らない＝教訓 5.25）。
- **存在期間整合**: 候補上位領域の存在期間が対象の存在期間と両立し、対象を下位に加えても「親領域＝下位領域の和」を将来満たせる位置にあること（U08 の形状＝和検証の前提条件として評価）。
- 共通の事前条件（同一地物でない・対象時刻に存在する・有効である）も検証するが、これは結合フローと**別実装**として持ち、安易に共有しない（教訓 5.27 / 5.30 過剰共有の戒め）。

### 対象範囲の限定と複数対象展開（FR-48）

- 直接所属変更は末端地物のみ。集約地物が対象に渡された場合は「全下位領域を対象とする」へ展開する（教訓 5.25 仕様が限定した対象を実装で広げない／狭めない＝集約を直接張り替えない）。展開した複数対象に同一の新上位領域決定を一括適用し、全体を 1 アンドゥ単位とする。
- 末端／集約の判別は「下位領域を持つか」という結果状態で行い、生成経路・フラグでゲートしない（教訓 5.6）。

### 飛び地化の許容（FR-49）

- 陸続き判定を合否条件にしない。地理的に分離した上位領域への所属を拒否しない。集約地物の形状は分離した全下位領域を包含する複数の独立リングとして導出される（和算出は U08→U06 へ委譲。集合演算は複数片を返す前提で扱う＝教訓 5.1）。

### 結果状態での自動消滅判定（FR-35 / FR-41、教訓 5.6）

- 張り替えにより集約地物が全下位領域を失ったかは、特定の操作経路でゲートせず、**変異後の結果状態**（その集約地物の直接下位領域が 0 件か）で判定して自動消滅させる（教訓 5.6）。解体・独立・直轄化など複数経路が同じ「下位領域消失」を引き起こすため、経路ごとのゲートは漏れる。消滅させた集約地物への上位／下位参照の掃除と、それにより連鎖的に空になった上位集約の剪定まで同一操作内で行う（教訓 5.21）。

### 単一アンドゥ単位とイベント通知（FR-94、教訓 5.23）

- フロー確定の全変更を 1 つの不可分コマンドとして U13 経由で記録する。コマンド結果に「変更された地物 ID 集合・新規生成 ID・自動消滅で削除された ID・新上位領域 ID」を含め、execute / undo / redo が touch した全地物へ対称に通知できるようにする（教訓 5.23）。新規生成 ID は初回生成 ID をコマンド結果に記録し、redo で再採番しない（教訓 5.20）。確定後の選択状態は固定の全クリアではなく、コマンド結果（残る／新規／削除 ID）から再解決できる情報を返す（教訓 5.11）。

### 成果物・公開インタフェース（型レベルの契約）

実装者は以下の概念を型として定義すること（名称は実装で確定してよいが、契約の意味は固定）。

- **フロー入力（対象）**: 所属変更の対象地物 ID（1 件。集約なら全下位領域へ展開される）。
- **新上位領域の決定**: 上記「フロー状態の判別共用体表現」の判別共用体。
- **許可候補一覧**: `(現在状態, 対象, 対象時刻) → 合法な既存上位領域候補の ID と表示名のリスト`。循環防止・存在期間整合で絞り込んだもの。
- **所属変更編集案**: 対象（展開後の末端地物群）・新上位領域決定・生成する新規地物（集約地物・新規最上位）・自動消滅予定の集約地物・親子張り替え内容を持つ不変値。U13 へ渡す。
- **フロー結果（判別共用体）**: `確定済み`（次状態・変更 ID 集合・新規 ID・削除 ID）／`競合あり・要方針指定`（U13 の空間競合へ委譲）／`拒否`（拒否種別＝循環参照／存在期間不整合／対象種別不正／その他、日本語メッセージ、機械可読詳細）。

公開する主関数（概念）:
- 許可候補算出: `(現在状態, 対象, 対象時刻) → 許可候補一覧`。
- 所属変更編集案の組み立て: `(現在状態, 対象, 新上位領域決定, 対象時刻) → 編集案 または 拒否`。確定前検証（循環・存在期間・対象種別）をここで通す。
- 確定: 編集案を U13 のプロセス／単一アンドゥ単位へ渡し `フロー結果` を得る。

### 無限横スクロール・性能の段階戦略

- 座標の周期境界ラップ正規化は U08／U06／U13 側で処理される前提とし、本ユニットは経度を連続スカラーのまま受け渡し独自のラップ処理を行わない（技術方針 R3）。
- 検証・編集案組み立ては純粋関数のメインスレッド同期実装とし、計測で 100ms を超えると判明した場合に限り Web Worker へ移設できるよう外部 I/O・グローバル状態への依存を持たせない（技術方針 R5 / R9）。親子グラフ走査は U08 の循環安全な走査基盤を経由し O(n²) へ退化させない。

## 受け入れ基準(テスト可能な形で列挙)

各基準は Vitest 単体テストまたは fast-check プロパティテストで「入力状態 → フロー呼び出し → 期待結果状態」を検証できる形で満たすこと。

1. **単一フローで全操作種別を表現・別 UI を設けない（FR-46）**
   - 「操作種別の対応表」の 7 種別（割譲・帰属・連邦化・独立・直轄化・自治化・解体）がすべて、同一フロー（対象 ＋ 新上位領域決定）のパラメータ設定として実行でき、それぞれ期待どおりの親子関係結果になることを、種別ごとのテストケースで検証する。
   - フロー本体に「操作種別」を直接受け取る分岐入力が存在しない（種別は対応表上の解釈であり、コードのパラメータは対象と新上位領域決定のみ）ことを型・テストで固定する。

2. **新規上位領域作成サブフローで中間階層を再帰的に後付け挿入できる（FR-47）**
   - 新規上位領域（名称・種別ラベル付きの集約地物）を生成し、対象の新上位領域として割り当てられる。
   - サブフロー末端で「既存最上位を上に置く（帰属）」と「新規最上位を作成」の双方が選べ、それぞれ期待どおりのツリーになる。
   - 上位領域を 2 段以上**再帰的に積み上げ**た入力で、既存の親子関係の間へ中間集約地物が複数段後付け挿入される（自治化＝既存上位領域と既存下位領域の間に新規中間集約が入る）ことを検証する。
   - 連邦化: 複数の最上位地物に共通の新規最上位を割り当てると、全対象が新規最上位の下位領域になり、新規最上位が唯一のルートになることを検証する。

3. **循環参照防止と存在期間整合で違反を拒否（FR-48、教訓 5.27）**
   - 対象地物自身を新上位領域に指定すると拒否され、状態が変化しない。
   - 対象の下位領域（多段ネストの孫含む）を新上位領域に指定すると拒否される（循環防止）。
   - **対象の上位領域**を新上位領域に指定する直轄化は**許可される**（候補に含まれることを検証。FR-48 の例外を削っていないこと＝教訓 5.25）。
   - 存在期間が両立せず「親領域＝下位領域の和」を将来満たせない候補を指定すると拒否される。
   - 許可候補算出と確定前検証が同一述語を使い、UI を経由しない直接呼び出しでも違反が拒否されること（教訓 5.26）、拒否結果が機械可読な拒否種別と日本語メッセージの両方を持つことを検証する。
   - 循環参照を含む壊れた入力でも、下位領域列挙・候補算出が無限ループせず有限結果を返す（U08 の循環安全走査を経由、教訓 5.28）。

4. **飛び地化を許容（FR-49）**
   - 対象を、地理的に陸続きでない既存上位領域へ所属させる操作が**拒否されない**（陸続き判定が合否条件でないこと）。
   - 飛び地化した結果、上位領域（集約地物）の形状が分離した全下位領域を包含する複数の独立リングとして導出され、全片が反映される（片落としなし＝教訓 5.1）。和算出が U08→U06 に委譲されることを検証する。

5. **直接所属変更は末端のみ・集約は全下位対象、複合操作 1 アンドゥで確定後整合性（FR-48 / FR-94）**
   - 末端地物を直接所属変更でき、集約地物が対象に渡された場合は全下位領域へ展開されて一括適用される（集約地物そのものは直接張り替えられない）。末端／集約の判別が結果状態（下位領域の有無）で行われることを検証する（教訓 5.6）。
   - 張り替えで全下位領域を失った集約地物が、その時刻以降自動消滅し、その集約への上位／下位参照が同一操作内で掃除され、連鎖的に空になった上位集約も剪定される（教訓 5.21）。解体がこの仕組みで成立することを検証する。
   - フロー確定の全変更（張り替え＋新規生成＋中間挿入＋自動消滅＋複数対象一括）が U13 を通じて **1 つの不可分コマンド**として記録され、1 回のアンドゥで全復元される（コマンドが 2 個以上に割れない）。redo で新規 ID が再採番されない（教訓 5.20）。
   - 確定時に U08 の階層整合性検証（最上位フラグ同値・形状＝和・隙間なし・循環なし）を再実行し、違反すれば確定せず状態を破棄して拒否する（教訓 5.22 / 5.26）。確定後の状態が全不変条件を満たすことを検証する。

6. **結合との事前条件分離（教訓 5.27）**
   - 所属変更の事前条件（循環参照防止・存在期間整合）が、結合フローの事前条件（互いに上位・下位関係にない等）と別実装であり、所属変更フローが結合固有条件で誤って拒否／許可しないことを検証する（共通条件のみ共有、固有条件は分離）。

7. **回帰・非機能**
   - 全公開関数が副作用を持たず、同一入力に同一結果を返す（純粋性）。入力データを破壊的に変更しない。拒否時は状態が操作前と完全一致する（部分適用なし＝FR-94）。
   - 種別ラベルを変えても候補絞り込み・検証結果・許可候補一覧が変化しない（種別ラベル非関与＝FR-40）。
   - fast-check: ランダム生成した森に対し、合法な所属変更を適用した後も U08 の全不変条件（最上位フラグ同値・形状＝和・循環なし・階層深度整合）が保たれる。違法な所属変更（循環・存在期間不整合）は必ず拒否される（偽陰性なし）。

## 実装契約の確定事項（公開面・依存接続）

本ユニットの実装で確定した公開面と、受け入れ基準の充足方法を以下に明記する（spec と実装の乖離を残さないため）。

- **複数対象の一括所属変更（基準 2 連邦化）**: 単一対象の `buildAffiliationProposal(features, targetId, decision, options)` に加え、複数対象を受ける `buildAffiliationProposalForTargets(features, targetIds[], decision, options)` を公開する。後者は全対象へ同一決定を一括適用し、`create→新規最上位` 決定では新規最上位を **1 度だけ** 生成して全対象を再親付けする。これにより相互に無関係な複数最上位を共通の新規最上位へ束ね、新規最上位が唯一のルートになる連邦化を表現する（集約 ID が渡されたら各 ID を全下位領域へ展開して統合する）。

- **create→既存最上位 の存在期間整合（基準 3 / FR-48）**: `create` の上位 (`above`) が既存地物の場合、生成する中間集約（期間＝対象群の包絡）と既存上位の間にも循環・存在期間整合（`isLegalNewParent` と同一の `existencePeriodsCompatible`）を確定前に適用する。leaf-vs-newAgg だけでなく newAgg-vs-existing も検証し、期間が両立しない接続を確定前に拒否する。

- **形状＝和・隙間なし検査の有効化（基準 5 / FR-35）**: `BuildProposalOptions.vertexStore` を渡すと、確定後の `validateHierarchy(swept.features, { vertexStore })` が U08 の形状＝和・隙間なし検査（`checkAggregateShapes`）まで実行する。`vertexStore` 省略時は位相検査（最上位同値・循環・dangling・空集約）のみで形状検査はスキップする。所属変更の呼び出し側（U13 接続点）は対象時刻の頂点ストアを渡し、形状＝和の不変条件まで確定前に検証すること。

- **U13 接続（基準 5 / 依存 U13）**: `affiliation/adapter.ts` が U28 → U13 の型付きアダプタを提供する。`startAffiliationProcess(baseline, proposal, anchorTime, overrides)` は所属変更編集案を U13 の `EditProposal<Snapshot>`（`Snapshot = readonly Feature[]`）へ写像し、U13 の `startProcess` を経由して確定する。これにより確定前に必ず 時間整合性（U09）→ 編集制約 → 空間競合検出（U10）が固定順序で走り、空間競合は U13 へ委譲（`conflicts-pending`）、競合なしなら 1 アンドゥ単位の所属変更コマンドとともに `committed` を返す。U28 は時間整合性・空間競合・アンドゥスタックを自前実装せず、それらの port を注入される。両側テスト（`adapter.test.ts`）で U28→U13 契約を固定する（教訓 5.33 / 5.34）。

## 注意点・既知の落とし穴(開発ガイドの教訓を踏まえる)

着手前に開発ガイド §1.6 の作業開始ゲートに従い、下記の該当教訓を引用し適用宣言してから実装すること。

- **§5.27 結合と所属変更は事前条件を分けて検証する** — 適用: 所属変更固有の事前条件（循環参照防止＝新親が対象自身とその下位すべてに含まれない／存在期間で親＝下位の和を満たせる）を、結合の事前条件（互いに上位・下位関係にない等）と**別実装**で持つ。共通条件（同一対象でない・有効・対象時刻に存在）のみ共有し、固有条件は混ぜない。受け入れ基準 3・6 で固定する。
- **§5.25 仕様が限定した対象範囲を実装で広げない** — 適用: ①直接所属変更は末端地物のみ、集約は全下位対象（集約を直接張り替えない）。②循環防止の候補除外は「対象自身＋全下位領域」だが、**対象の上位領域は直轄化のため候補に含む**例外を実装で削らない。「対称性確保」で上位も除外したくなったら FR-48 を引用して止める。受け入れ基準 3・5 で固定する。
- **§5.6 状態変化の検出は結果状態で判定する** — 適用: 末端／集約の判別、集約地物の自動消滅判定（下位領域 0 件）を、特定経路でゲートせず変異後の結果状態で行う。解体・独立・直轄化など複数経路が同じ「下位領域消失」を起こすため、経路ゲートは別経路で漏れる。受け入れ基準 5。
- **§5.21 削除は参照掃除と連鎖剪定まで行う** — 適用: 自動消滅した集約地物への上位／下位参照を同一操作内で掃除し、参照が消えて空になった上位集約を連鎖剪定する。片方向・単一時点だけの掃除は dangling 参照を残す。
- **§5.22 確定まで共有データを破壊的に更新しない** — 適用: 親子張り替え・新規地物生成・中間挿入は、確定前検証（循環・存在期間・U08 整合性）を通るまで共有ドメイン状態を破壊更新しない。違反時は追加要素を全ロールバックして操作前状態を返す。
- **§5.26 編集制約はコマンド確定前にも同じサービスで検証する** — 適用: 許可候補算出（UI ピッカー）と確定前検証を**同一の検証述語**で行う。ショートカット・メニュー・直接呼び出し・undo/redo から不正な新上位領域が入らないよう確定前検証を必須にする。拒否理由は日本語通知とテスト可能な戻り値の両方で返す。受け入れ基準 3。
- **§5.28 階層を辿る再帰は循環で無限ループしない** — 適用: 下位領域列挙・縦方向領域算出・循環判定は U08 の循環安全走査（visited 再入遮断）を経由する。壊れたデータ（循環・親子不整合）でも有限結果を返す。循環テストケースを置く。受け入れ基準 3。
- **§5.23 execute/undo/redo は対称に通知する** — 適用: フロー確定コマンドの touch 対象（変更地物 ID・新規 ID・削除 ID・新上位領域 ID）を対称に通知できるよう、コマンド結果へ変更 ID 集合を含める。確定直後に手動リフレッシュを書きたくなったら通知漏れのサイン。
- **§5.20 元に戻す情報は依存データも含めて過不足なく保存する** — 適用: 新規上位領域・新規最上位の生成 ID は初回生成 ID をコマンド結果に記録し、redo で再採番しない。自動消滅で削除した集約地物の復元に必要な依存データ（親子参照・プロパティ）も保存する。
- **§5.11 構造変更操作後の選択は結果から再解決する** — 適用: 所属変更は対象 ID・ツリー構造を変える。確定後の選択を固定の全クリアで決めず、コマンド結果（残る／新規／削除 ID）から再解決できる情報を返す。
- **§5.10 選択状態は生の集合まで評価して網羅する** — 適用: 対象が末端単体・集約（全下位展開）・複数最上位（連邦化）・解体（全下位を親なし）など、対象集合の各状態（単一・複数・展開後）を生の ID セットまで評価して分岐を網羅する。仕様メッセージ（拒否理由）と表示条件を一対一対応させる。
- **§5.30 過少共有と過剰共有の両方を戒める** — 適用: 単一フロー（同じ決定ロジックを全種別で共有＝過少共有の戒め）を守りつつ、所属変更の候補絞り込みと結合の候補絞り込みは除外規則が異なるため安易に共有しない（過剰共有の戒め）。共有前に「2 操作の制約は本当に同一か」を列挙確認する。
- **§5.1 集合演算は複数片を返す前提で扱う** — 適用: 飛び地化で集約形状（下位領域の和）が複数片・複数リングになる。和算出（U08→U06）の全片を反映し、片落とし（先頭片だけ採用）をしない。受け入れ基準 4。
- **§5.33 / §5.34 層をまたぐ契約は型と両側テストで固定する** — 適用: U20（UI 駆動データの描画先シェル／ダイアログ枠）・U08（検証/派生）・U13（確定/競合）・U11（共有継続）の公開インタフェースを共有型で import し、関数名・引数・戻り値構造を両側テストで固定する。依存未実装時は本仕様の入出力契約に沿った型を先に定義する。
- **トレランスと数値誤差**（技術方針 R2）— 注意: 存在期間整合・形状＝和の判定は U08 と同一の座標量子化／トレランス基準を用い、基準値を本ユニットで重複定義しない（単一の真実源）。微小スリバーを違反と誤検出しない。
- **世界端ラップ**（技術方針 R3）— 注意: 飛び地化した上位領域が世界端をまたぐ場合の和算出・包含判定はラップ正規化前提に従う。本ユニットは経度を連続スカラーのまま受け渡し独自のラップ処理を行わない。
- **クリーンルーム原則**（開発ガイド §3.1）— 注意: 本書および実装に、過去版・他プロダクト・「従来」「前回」等の外部参照を持ち込まない。制約は本アプリ要件として直接記述する。

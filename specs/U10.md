# U10 空間インデックス(RBush)と末端地物ペア排他検証

## 目的

地図全体において末端地物（形状を持ち下位領域を持たない面情報）同士が決して空間的に重ならないという本アプリのドメイン基本ルール（FR-26）を、現実的な計算時間で検証できる仕組みを提供する。

具体的には次の 2 つを一体で実装する。

1. 末端地物のバウンディングボックスを載せる空間インデックス（R-tree）を構築・更新し、視野クリッピング候補・近接スナップ候補・排他検証候補の絞り込みに再利用できる単一の部品にする。
2. その空間インデックスを使い、近傍候補だけに絞った末端地物ペアの空間オーバーラップ検出関数を提供する。集約地物は検証対象から除外し（FR-27）、境界の接触は重なりに含めない。世界端（経度の周期境界）をまたぐ末端ペアの重なりも検出する。

このユニットは整合性維持プロセス（FR-61〜FR-63）・読み込み時整合性チェック（FR-106）・編集時のリアルタイム衝突判定（FR-28 / FR-89）といった上位機能から呼び出される土台であり、それら上位フローそのものはこのユニットのスコープ外である。

## スコープ

### やること

- 末端地物のバウンディングボックス（最小外接矩形）を要素とする空間インデックス（R-tree、技術方針が定める RBush）を構築・更新・問い合わせするラッパーを提供する。
  - 「ある矩形（視野矩形・近接矩形・ある末端地物の矩形）に交差する末端地物の候補集合」を返す問い合わせ API を持つ。
  - 末端地物の追加・削除・形状変更に追随してインデックスを更新できる（全件再構築と差分更新の双方を、呼び出し側が選べる形で提供する）。
- 地図全体の末端地物同士の空間オーバーラップを検出する純粋関数を提供する。
  - 入力は「ある時刻における全地物の評価済み状態」（どれが末端地物でどれが集約地物か、各末端地物の形状リング、経度連続スカラー座標）である。
  - 出力は重なっている末端地物ペアの一覧（各ペアの地物 ID 組と重なり領域、または重なり有無の判定に十分な情報）である。
- 検証対象を末端地物同士のペアに限定する。集約地物はインデックスにも検証対象にも載せない（FR-27 / 教訓 5.25）。
- 境界の接触（辺・頂点の共有、ゼロ面積の接触）は重なりに含めない。重なりは正の面積を持つ交差に限る（FR-26）。
- 候補絞りにより全ペア検証 O(n²) を避ける。各末端地物について、その矩形に交差する候補のみとペア判定を行う。
- 世界端（経度の周期境界）をまたぐ末端ペアの重なりを検出する。U05 の世界端ラップ正規化（±360 度オフセット展開）を用い、ラップ展開した複製に対してもインデックス問い合わせ・ペア判定を行う。
- 5,000 オブジェクト規模（NFR 5.2）で検証が現実的時間に収まることを示す計測（ベンチマーク）を用意する。

### やらないこと

- 競合解決ダイアログの UI、解決方針の適用（ブーリアン差分調整）そのもの（FR-62 / FR-63）。本ユニットは「検出」までを担い、解決は上位ユニットが担当する。
- エッジ滑り（FR-28）・頂点ドラッグ中のリアルタイム移動制約（FR-89）の操作ロジック本体。本ユニットは衝突判定の候補絞りと述語を提供するが、押下→移動→解放のドラッグ制御は上位ユニットのスコープ。
- 面のブーリアン演算（和・差・交差）の実装そのもの（U06 が提供する前提で利用する）。
- 集約地物の派生形状（下位領域の和）の算出（U08 側の責務）。本ユニットは「末端地物の形状」だけを扱う。
- 時間軸に沿った全錨の走査による整合性検証の制御（本ユニットは「ある時刻の評価済み状態」を入力に取り、時刻列の反復は呼び出し側）。
- 描画・視野クリッピングの実描画処理（本ユニットは候補集合を返すのみで、何を描くかは描画層の責務）。
- 線情報・点情報の排他判定（FR-29 のとおり線・点に排他性はなく、本ユニットの対象外）。

## 依存（dependsOn）

このユニットは以下に依存する。実装着手時点でこれらの公開インタフェースを利用する前提とし、未確定の場合は本ユニット内に最小の型境界（アダプタ）を切って後で接続する。

- **U06（幾何・面情報の形状とブーリアン／幾何述語）**: 末端地物の形状（領土リング・穴リングの集合）と、2 ポリゴンの交差判定・重なり面積算出・バウンディングボックス算出などの幾何述語を提供する。境界接触を重なりに含めない判定基準（正の面積の交差のみ重なりとみなす）は U06 の幾何述語と単一の真実源を共有する。
- **U05（世界端ラップ正規化）**: 経度を連続スカラーで保持し、周期境界（東端・西端）をまたぐ形状を ±360 度オフセットで複製・展開する正規化を提供する。本ユニットはこれを使って世界端をまたぐペアの重なりを検出する。
- **U08（面情報のツリー階層・末端/集約の区別）**: ある時刻において各面情報が末端地物か集約地物かの判定、各末端地物の評価済み形状の取得を提供する。本ユニットは末端地物のみをインデックス・検証対象とするため、この区別に依存する。

依存の利用は「内向きの純粋関数呼び出し」に限る。本ユニットは `domain` 層に属し、React・Electron・Canvas に依存しない。

## 実装方針（技術方針に沿う）

技術方針 2.7「空間インデックス: RBush」および R3（世界端ラップ）・R5（ドラッグ中の軽量判定）に従う。

### 配置と純粋性

- `domain` 層内のフレームワーク非依存モジュールとして実装する。Electron・React・Canvas を import しない。Vitest で単体実行できること。
- 空間検出関数は副作用のない純粋関数とする（同一入力に同一出力）。インデックスのラッパーは可変状態（R-tree インスタンス）を内部に持つが、構築・更新・問い合わせの境界を明示し、問い合わせ自体は副作用なしとする。

### 空間インデックス（R-tree / RBush）

- 末端地物のバウンディングボックスを `{minX, minY, maxX, maxY, ref}`（`ref` は地物 ID 等の参照）として R-tree に挿入する。座標は経度連続スカラー（U05 の連続座標）とワールド緯度で表現する。
- 視野クリッピング候補・近接スナップ候補・排他検証候補の 3 用途を同一インデックスで賄えるよう、問い合わせは「任意矩形に交差する候補参照の集合」を返す汎用 API に統一する（最適化手段を一つの部品に集約する、技術方針 2.7 / 5.2）。
- 更新方針: 形状変更が局所的なドラッグ中は差分更新（該当末端地物のみ remove→insert）、編集確定や読み込み直後など多数が変わる場合は一括再構築（bulk load）を選べるようにする。どちらを使うかは呼び出し側が指定する（教訓 5.5 のとおり、依存する状態が変化したらインデックスを再検証・更新する責務を明示する）。
- インデックスに載せるのは末端地物のみ。集約地物は形状属性を持たず派生形状であるため（FR-35）、インデックスにも検証にも載せない（FR-27 / 教訓 5.25）。

### 末端ペア排他検出アルゴリズム

1. 入力の評価済み状態から末端地物だけを抽出し、各々のバウンディングボックスを算出してインデックスを構築する（U06 の bbox 算出、U08 の末端判定を使用）。
2. 各末端地物 A について、A のバウンディングボックスに交差する候補集合をインデックスから取得する（自分自身と、ペアの重複検査（A,B と B,A の二重計上）を除外する）。
3. 候補 B ごとに U06 の幾何述語で「正の面積の交差があるか」を判定する。辺・頂点だけを共有する境界接触（ゼロ面積）は重なりに含めない（FR-26）。
4. 重なりを検出したら、ペア ID 組と重なり領域（または十分な情報）を結果に積む。集合演算が複数片を返しうることを前提に、片落としせず全片を扱う（教訓 5.1）。
5. これにより比較回数を近傍候補のみへ絞り、全ペア O(n²) を回避する（NFR 5.1 / 5.2、技術方針 5.2）。

### 世界端ラップ対応

- 経度は内部で連続スカラーとして保持する（技術方針 R3）。
- 周期境界（東端・西端）の近傍にある末端地物は、U05 のラップ正規化で ±360 度オフセットの複製を生成し、その複製もインデックスへの問い合わせ対象・ペア判定対象に含める。これにより、東端の地物と西端の地物が地図上では隣接して重なる場合も検出できる。
- ラップ展開は本ユニットがライブラリ任せにせず U05 の専用正規化関数を経由して行い、テストで世界端ケースを直接固定する（技術方針 R3）。

### 境界接触の扱い（単一の真実源）

- 「重なり」の定義は「正の面積を持つ交差」とし、境界の接触（共有辺・共有頂点・ゼロ面積接触）は重なりに含めない（FR-26）。この判定基準は U06 の幾何述語と共有し、本ユニットで別実装しない（教訓集の単一真実源・過少共有の戒め、5.30）。

### 計測

- 5,000 末端地物規模（NFR 5.2）の合成データで検出関数の実行時間を計測するベンチマークを用意する。R-tree 候補絞りありと、素朴な全ペア比較（参考実装）との比較で、候補絞りが O(n²) を回避していることを確認できる形にする。

## 受け入れ基準（テスト可能な形で列挙）

各基準は Vitest による単体テスト、または fast-check のプロパティテスト、計測ハーネスで検証する。

1. **末端地物のみがインデックス・検証対象になる（FR-27 / 教訓 5.25）**
   - 末端地物と集約地物が混在する入力で、集約地物はインデックスに挿入されず、検出結果のペアにも一切現れないことをテストする。
   - 集約地物の派生形状が末端地物と空間的に重なるように構成しても、その集約地物は重なりペアとして報告されないことをテストする（集約には排他制約を課さない）。

2. **末端ペアの重なりを検出し、境界接触は重なりに含めない（FR-26）**
   - 正の面積で交差する 2 つの末端地物を入力すると、そのペアが重なりとして報告される。
   - 辺だけを共有する隣接 2 末端地物（共有境界、ゼロ面積接触）は重なりとして報告されない。
   - 頂点 1 点だけを共有する 2 末端地物も重なりとして報告されない。
   - 共有頂点で境界を連動させた隣接末端地物（FR-30 系）でも、境界接触のみなら重なりとして報告されない。

3. **O(n²) を避け近傍候補で絞った検証になっている（NFR 5.1 / 5.2）**
   - 互いに遠く離れて重ならない N 個の末端地物を入力したとき、幾何述語（高コストな交差判定）の呼び出し回数が候補絞りにより O(n) 規模に収まり、N(N-1)/2 回には達しないことを、述語呼び出し回数のカウントで検証する。
   - 候補絞りありの検出結果が、素朴な全ペア比較の参照実装の結果と完全一致することをプロパティテスト（ランダム配置の末端地物群）で検証する（絞りが取りこぼさない）。

4. **世界端をまたぐ末端ペアの重なりも検出できる（U05 使用）**
   - 地図東端付近の末端地物と西端付近の末端地物が、経度の周期境界をまたいで実際には重なるように配置した入力で、そのペアが重なりとして報告される。
   - 周期境界をまたぐが実際には重ならない（ラップ後も離れている）ペアは報告されないことをテストする（誤検出しない）。

5. **5,000 オブジェクト規模で現実的時間に収まる計測がある（NFR 5.2）**
   - 5,000 末端地物の合成データに対し検出関数を実行する計測（ベンチマーク）が存在し、実行時間が記録される。
   - 同データで候補絞りありと素朴全ペアの実行時間・幾何述語呼び出し回数を比較し、候補絞りが優位であることを示す計測結果が得られる。

6. **インデックスの構築・差分更新・一括再構築が一致する**
   - 末端地物群を一括 bulk load したインデックスと、1 件ずつ insert したインデックスで、同一矩形問い合わせの候補集合（集合として）が一致する。
   - 末端地物 1 件を remove→insert で差分更新した後の問い合わせ結果が、全件再構築した結果と一致する（教訓 5.5: 依存状態変化時の再検証）。

7. **重なり結果は複数片・複数ペアを取りこぼさない（教訓 5.1）**
   - 1 つの末端地物が複数の他末端地物と同時に重なる入力で、すべての重なりペアが報告される。
   - 重なり領域が複数の分離した片になる入力でも、全片の情報が結果に含まれる（片落とししない）。

## 関連要件（FR-id）

- **FR-26**（must）: 末端地物同士は地図全体において決して重ならない（境界の接触は重なりに含めない）。本ユニットの検出関数が直接支える。
- **FR-27**（must）: 排他検証は末端地物同士のみを対象とし、集約地物には直接の排他制約を課さない。検証は末端ペアのみで集約を除外する。

関連して土台を提供する（本ユニットのスコープ外だが利用先）要件: FR-28（エッジ滑りの衝突候補絞り）・FR-89（リアルタイム衝突判定の候補絞り）・FR-61〜FR-63（整合性維持・競合解決の空間競合検出）・FR-106（読み込み時の錨間空間オーバーラップ検出）・FR-30〜FR-33（近接スナップ候補の同一インデックス再利用）・NFR 5.1 / 5.2（性能・規模）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

- **教訓 5.25「仕様が限定した対象範囲を実装で広げない」**: 排他検証の対象は末端地物同士のペアのみである（FR-27）。「対称性」「自然な拡張」を理由に集約地物を検証対象へ含めてはならない。集約地物の派生形状が末端地物と重なって見えても、それは排他違反ではない。集約をインデックスに載せない・検証ループに入れないことをテストで固定する。
  - 適用: インデックス構築段で U08 の末端判定により集約地物を除外し、受け入れ基準 1 で「集約は決して重なりペアに現れない」を回帰テスト化する。

- **教訓 5.1「集合演算は複数片を返す前提で扱う」**: 重なり領域や重なりペアは複数になりうる。配列の先頭だけ採用する片落としを避け、全片・全ペアを結果に積む。
  - 適用: 受け入れ基準 7 で複数同時重なり・複数片重なりを検証する。

- **教訓 5.5「依存する状態は変化時に再検証する」**: 末端地物の追加・削除・形状変更が起きたらインデックスを更新しないと、検出が古い形状で行われ取りこぼす。状態変化に追随する更新責務（差分更新／一括再構築）を明示する。
  - 適用: 受け入れ基準 6 で差分更新と一括再構築の一致を検証する。

- **教訓 5.30「過少共有と過剰共有の両方を戒める」/ 単一の真実源**: 「重なり（正の面積交差）」と「境界接触（ゼロ面積）」の判定基準は U06 の幾何述語と単一実装を共有し、本ユニットで別実装しない。基準がドリフトすると、ある場所では接触を重なり扱い、別の場所では非重なり扱いとなり矛盾する。
  - 適用: 境界接触の扱いは U06 の述語に委譲し、受け入れ基準 2 で辺共有・頂点共有・共有頂点境界の各ケースを固定する。

- **世界端ラップの落とし穴（技術方針 R3）**: 経度を 0〜360 や -180〜180 へ単純剰余するとラップ境界で形状が分断され、東端・西端の隣接重なりを取りこぼす、または誤検出する。経度は連続スカラーで保持し、U05 のラップ正規化（±360 度複製展開）を経由してから判定する。ライブラリ任せにせず、専用正規化関数をテストで固定する。
  - 適用: 受け入れ基準 4 で「またいで重なる」「またぐが重ならない」の両ケースを検証する。

- **数値誤差・退化ケース（技術方針 R2）**: 極小スリバー・ゼロ長エッジ・自己交差により、境界接触がわずかに正面積の交差として誤検出される、または逆に薄い重なりが取りこぼされる恐れがある。U06 が用いる座標量子化・トレランス設計に整合させ、境界接触（接触のみ）と微小重なりの区別をトレランス込みでテストする。
  - 適用: 受け入れ基準 2 のテストにトレランス境界付近のケースを含める。

- **O(n²) への退行**: 候補絞りを入れても、矩形が極端に大きい地物（世界規模の集約相当の末端や、ラップ展開した複製）が多数候補を返すと退行しうる。述語呼び出し回数を計測指標として持ち、退行を計測で検出する（教訓 1.7 / NFR 5.8）。
  - 適用: 受け入れ基準 3・5 で述語呼び出し回数を計測し、参照実装と結果一致・回数優位を確認する。

- **ペアの二重計上**: 候補絞りで A→B と B→A の両方を評価すると同一ペアを 2 回報告する。ペアを ID の正規化順（小さい ID を先）で一意化し、重複報告しないことをテストで固定する。

- **層境界（教訓 5.33 / 5.34）**: U05・U06・U08 から受け取る型（末端判定・形状リング・連続座標・幾何述語の戻り値）を型で明示し、偶然の構造一致に頼らない。依存が未確定の段階ではアダプタ境界を切り、接続時に両側テストで固定する。

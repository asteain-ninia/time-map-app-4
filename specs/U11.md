## 1. 目的

複数の面情報・線情報が**同一の頂点を共有して境界を連動させる「共有頂点システム」**を実装する（FR-30）。共有頂点をドラッグするとそれを共有する全形状が同時に変化し、ユーザーは複数地物の境界を一括で整合させながら編集できる。本ユニットは、その中核となる以下のドメインロジックを提供する。

1. 頂点を値オブジェクトとし ID 参照で共有を表現するデータモデル（技術方針 R6）。
2. 共有頂点グループの形成（共有化）・連動移動・共有解除。
3. 共有化への参加制限（同一リング内・同一線形内は同一グループ不可）（FR-32）。
4. 共有化・共有頂点移動の結果が不正形状（ゼロ長エッジ・自己交差・穴飛び地階層破綻・末端地物重なり）を生む場合の禁止（FR-32）。違反検証は U06/U07/U10 の検証サービスへ委譲する。
5. 結合・分割といった複合操作における共有関係の継続規則（新頂点への引き継ぎ、共有辺途中切断時の同座標頂点挿入）（FR-33/FR-95）。

本ユニットは純粋ドメインロジック（`domain` 層）として実装し、Electron・React・Canvas に依存しない。UI 描画・スナップ判定の画面側挙動（FR-31 のスクリーン座標近接判定など）は本ユニットのスコープ外であり、その判定本体は編集セッション（U24）が所有する。本ユニットは「どの頂点同士を共有化するか」という決定済み入力を受けてドメイン状態を更新する純粋関数を提供する。

## 2. スコープ

### 2.1 やること

- **頂点の値オブジェクト化と ID 参照モデル**（技術方針 R6）。頂点を不変な値オブジェクト（ID・ワールド座標を持つ）として定義し、面情報のリングおよび線情報のパスは頂点 ID 列で形状を参照する。同一頂点 ID を複数の形状（リング/線形）の頂点列が参照することで「共有」を表現する。
- **共有頂点グループの解決**。ある頂点 ID を参照している全ての形状参照（地物 ID・リングインデックス・頂点列位置）を列挙する純粋関数を提供する。共有頂点とは「2 つ以上の異なる形状参照から参照されている頂点」である。
- **共有化コマンド**。2 つの頂点（候補頂点と既存頂点）を 1 つの共有頂点へ統合し、両方を参照していた形状参照を統合後の共有頂点 ID へ付け替える。座標は既存頂点側に合わせる（統合先の正規座標を単一の真実源とする）。
- **連動移動コマンド**。共有頂点 ID の座標を更新すると、それを参照する全形状が同時に新座標を反映する（ID 参照なので参照側は自動的に追随する）。共有頂点を含む移動・地物移動・複数頂点同時移動で連動が成立する（FR-30、FR-88）。
- **共有解除コマンド**（FR-33）。共有頂点を、解除対象の形状参照について新規の独立頂点（同一座標・新 ID）へ複製して切り離す。残りの参照は元の共有頂点を保持する。解除後に参照が 1 つだけになった頂点は通常頂点となる。
- **参加制限の検証**（FR-32）。共有化候補ペアが「同一リング内の頂点同士」または「同一線形（同一線情報のパス）内の頂点同士」である場合は同一グループへ入れることを禁止する。既に共有グループを成している頂点に新たな参照を加える場合も、結果グループ内に同一リング/同一線形の重複参照が生じないことを検証する。
- **結果不正の禁止**（FR-32）。共有化または共有頂点移動の結果を適用した状態に対して、ゼロ長エッジ・自己交差・穴飛び地階層破綻・末端地物同士の重なりが生じないことを検証し、生じる場合は操作を拒否する。各検証は U06（自己交差・ゼロ長エッジ等のリング/線形妥当性）、U07（穴飛び地階層・リング包含）、U10（末端地物排他）の検証サービスへ委譲する（後述 4.4）。
- **継続規則（複合操作との接続）**（FR-33/FR-95）。
  - 分割（ナイフ）で形状が作り直される際、分割前に持っていた共有頂点関係を、新しく生成された対応頂点へ引き継ぐ。
  - 分断線が**共有辺の途中**を横切る場合、共有相手地物の対応辺にも同座標の頂点を挿入し、その新頂点を切断点と共有頂点関係に入れる。
  - 結合（合体）で結果地物が新規生成される際、結合対象が持っていた共有頂点関係を結果地物の対応頂点へ引き継ぐ。
- **共有解除直後の再共有抑制フラグの管理**（FR-33）。共有解除直後の頂点が即座に再共有化されないよう、当該頂点に「自動共有化抑制中」のセッション状態を立て、一度スナップ距離外へ離れると抑制を解除するための判定ロジックを提供する。抑制状態の保持先はドメイン真実ではなくセッション状態側だが、判定ロジック（抑制中か否か・解除条件）は本ユニットが純粋関数として提供する。
- **不変条件のプロパティテスト**（技術方針 R6/R7）。共有継続の前後比較プロパティテストを fast-check で記述し、共有化・連動・解除・分割・結合の前後で共有関係が規則どおり保たれることを検証する。

### 2.2 やらないこと

- **スクリーン座標での近接スナップ判定**（FR-31）と、スナップ距離（既定 50px、設定変更可、FR-110）の適用計算。これは編集セッション（U24）が所有する FR-31 のスナップ判定本体の責務であり、本ユニットは「共有化する頂点ペアが決定された」状態を入力として受ける。スナップ候補の絞り込みに用いる空間インデックス（RBush）の構築・問い合わせ自体は U10 が提供し、スクリーン座標距離の計算・ズーム依存判定・スナップ距離の適用は U24 が行う。本ユニットはその結果（決定済み候補ペア）を消費して共有化コマンド（参加制限・結果不正検証つき）を実行するのみ。
- **共有頂点の視覚的区別**（FR-30 の描画表現）。描画層（`render`）の責務。
- **コンテキストメニュー UI**（FR-33/FR-96 の「共有解除」メニュー項目の表示）。UI 層の責務。本ユニットは解除コマンドのドメイン関数のみ提供する。
- **末端地物排他の衝突判定・エッジ滑りの実装本体**（FR-26〜FR-29、FR-89）。U10 の責務。本ユニットは結果検証で U10 のサービスを呼ぶのみ。
- **自己交差・ゼロ長エッジ・リング妥当性検証の実装本体**（U06）、**穴飛び地階層検証の実装本体**（U07）。本ユニットはそれらのサービスを呼ぶのみ。
- **分割・結合・所属変更の操作本体**（U の別ユニット）。本ユニットは「共有関係の継続規則」を、それら複合操作から呼び出せる純粋関数として提供する側であり、分割・結合のフロー自体は実装しない。
- **アンドゥ/リドゥのスタック実装**（別ユニット）。本ユニットのコマンドは純粋関数（状態 → 新状態）として実装し、二重スタックへ積めるコマンド形式に従うが、スタック管理そのものは行わない。

## 3. 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが提供する型・サービスを前提として実装する。

- **U03**: ドメインモデルの基礎（地物・面情報のリング構造・線情報のパス・頂点・ID 体系）。頂点値オブジェクト、リング（領土/穴の判別共用体）、線形パス、地物 ID/頂点 ID の生成と参照の型を U03 から取得する。本ユニットの「値オブジェクト＋ID 参照」モデルは U03 の頂点・リング・パス定義の上に構築する。
- **U06**: リング/線形の幾何妥当性検証（ゼロ長エッジ・自己交差等）。共有化・移動の結果検証で呼ぶ。
- **U07**: 穴飛び地階層・リング包含の検証（穴リングが親に完全包含される、兄弟リング非交差、飛び地が他外周と非重複）。共有化・移動の結果検証で呼ぶ。

加えて、結果検証では **U10**（末端地物同士の排他・重なり検証）のサービスを呼ぶ。U10 は本ユニットの `dependsOn` には明記されていないが、受け入れ基準（FR-32 の「末端地物同士の重なり禁止」）の検証に必須である。U10 の検証サービスが未提供の場合に備え、本ユニットは結果検証を**注入可能な検証関数（バリデータ群）への委譲**として実装し、U10 のサービスをそのバリデータの 1 つとして差し込めるようにする（後述 4.4）。これにより U10 の実装有無に関わらず本ユニットの単体テストが成立する。

## 4. 実装方針

技術方針（`docs\技術方針.md`）に従い、本ユニットは `domain` 層の純粋関数・イミュータブル更新として実装する。React・Electron・Canvas へ依存しない。Immer によるイミュータブル更新（技術方針 2.6）、判別共用体による不正状態の排除（技術方針 2.1）、RBush/polygon-clipping は呼び出し側または検証側に局在させ本ユニット内部の純粋性を保つ。

### 4.1 データモデル（値オブジェクト＋ID 参照、R6）

技術方針 R6「頂点を値オブジェクト化し ID 参照で共有を表現する」に厳密に従う。

- **頂点値オブジェクト**: ID（不変・一意）とワールド座標（連続スカラー経度を含む。技術方針 R3 のラップ正規化前提に整合）を持つ不変オブジェクト。座標変更は新インスタンスを返す（開発ガイド §5.17）。等価性は属性値比較で定義する。
- **頂点ストア**: 頂点 ID → 頂点値オブジェクトの写像をドメイン状態の単一の真実源として保持する。座標はここに 1 か所だけ持ち、各形状参照は座標を複製せず ID で参照する。これにより共有頂点の連動移動は「頂点ストア上の 1 頂点の座標更新」だけで全参照へ反映される。
- **形状参照**: 面情報リングおよび線情報パスは、座標の配列ではなく**頂点 ID の配列**で形状を表す。ある頂点 ID が複数の（地物, リング/パス, 列位置）から参照されている状態が共有である。
- **共有グループの導出**: 共有頂点グループは独立した実体として保持せず、頂点ストアと形状参照から**実行時に導出**する（開発ガイド §4「単一の真実源」、§5.29「派生は単一の解決判定で全経路を動かす」）。具体的には「頂点 ID → その ID を参照する全形状参照の集合」を求める逆引きインデックスを純粋関数で構築し、参照数 ≥ 2 の頂点を共有頂点とする。逆引きインデックスの構築・問い合わせは共有判定・連動・解除・参加制限・継続規則のすべてで同一実装を共有する（ドリフト防止）。

> 注意: 「共有頂点グループを別エンティティとして二重に持つ」設計は単一の真実源に反し、形状参照と齟齬を起こす（開発ガイド §4、§5.34）。グループは常に参照から導出する。

### 4.2 共有化コマンド

入力: 現在のドメイン状態、共有化する 2 つの形状参照位置（地物 ID・リング/パス・列位置）の組（候補側と統合先側）。

1. **参加制限検証**（4.3）を実行し、違反なら拒否（理由つき）。
2. 候補頂点を参照していた全形状参照を、統合先頂点 ID へ付け替える（候補頂点が既に共有頂点なら、そのグループ全体を統合先へ統合する）。
3. 統合により孤立した（参照されなくなった）候補頂点 ID を頂点ストアから削除する（開発ガイド §5.21「削除は参照掃除まで行う」）。
4. 座標は統合先頂点の座標を採用する（候補頂点の座標は捨てる。統合先を正規座標の単一の真実源とする）。
5. **結果不正検証**（4.4）を実行し、違反なら状態を破棄して拒否（開発ガイド §5.22「確定まで共有データを破壊的に更新しない」）。
6. 検証通過時のみ新状態を返す。

### 4.3 参加制限（FR-32）

共有化候補ペア、および共有化後に成立する共有グループに対し、次を禁止する。

- **同一リング内禁止**: 同じ面情報の同じリング（同一の領土リングまたは同一の穴リング）に属する 2 頂点を同一共有グループへ入れない。
- **同一線形内禁止**: 同じ線情報の同じパスに属する 2 頂点を同一共有グループへ入れない。

判定は「共有グループに含まれる全形状参照の (地物 ID, リング/パス識別子) の集合に重複がないこと」で行う。候補頂点が既に共有グループを成している場合は、統合後グループの全参照について重複検査を行う（候補側グループの内部にも重複が無いことを前提とせず、統合後の最終状態で判定する。開発ガイド §5.6「結果状態で判定する」）。

> 開発ガイド §5.25「仕様が限定した対象範囲を実装で広げない」: 参加制限は「同一リング内」「同一線形内」に限定されている。これを「同一地物内すべて禁止」へ拡大解釈してはならない。同一面情報の**異なるリング**同士（例: 外周リングと飛び地リング、外周と穴）の頂点共有は禁止対象ではない。実装で対象範囲を広げる前に本節と要件定義書 FR-32 を引用すること。

### 4.4 結果不正の禁止（FR-32、U06/U07/U10 委譲）

共有化・連動移動・継続規則適用の結果状態に対し、次の 4 種を検証して 1 つでも違反すれば操作を拒否する。

1. **ゼロ長エッジ**: 隣接 2 頂点が同座標（または量子化後同一）になるエッジを生まない（U06）。共有化で 2 頂点が 1 頂点に統合された結果、同一リング/パス内で隣り合う頂点が同一 ID になる、または同座標になるケースを特に検出する。
2. **自己交差**: リング/線形が自己交差しない（U06）。
3. **穴飛び地階層の破綻**: 穴リングの親内包含・兄弟非交差・飛び地非重複（U07）。
4. **末端地物同士の重なり**: 連動・統合で動いた頂点を共有する末端地物が、他の末端地物と重ならない（U10。境界の接触は重なりに含めない。要件定義書 FR-26）。

実装は**注入されたバリデータ群への委譲**とする。本ユニットは「結果状態を受け取り違反理由のリストを返す」検証関数インタフェースを定義し、U06/U07/U10 の実サービスをそのインタフェースで束ねて受け取る。委譲先サービスが内部で polygon-clipping/RBush/量子化（技術方針 2.7/2.8、R2）を使うか否かは本ユニットの関知外であり、本ユニットは純粋に保つ。

> 開発ガイド §5.26「編集制約はコマンド確定前にも同じサービスで検証する」: UI の候補表示（共有化候補ハイライト等）で同じ検証を流用する場合も、コマンド確定前に**同じサービス**で再検証する。拒否理由はユーザー通知用メッセージとテスト可能な戻り値の両方で返す。

### 4.5 連動移動（FR-30/FR-88）

共有頂点の座標更新は頂点ストア上の単一頂点の座標差し替えで表現する。ID 参照ゆえ全参照形状が自動追随する。地物移動（全頂点を同一ベクトルで平行移動、FR-88）や複数頂点同時移動（FR-80）でも、移動対象に共有頂点が含まれれば同様に連動する。移動コマンドは確定時に 4.4 の結果不正検証を実行する。ドラッグ中の毎フレーム検証は近傍候補のみの軽量判定とし、確定時にフル検証を行う二段戦略（技術方針 R5/R9）に整合させるが、本ユニットが提供するのは確定コマンドの純粋関数であり、ドラッグ中の軽量判定は編集セッション側が呼ぶ。

### 4.6 共有解除（FR-33）

入力: 共有頂点 ID、解除対象の形状参照（どの参照を切り離すか）。

1. 解除対象の形状参照について、同座標・新 ID の頂点を頂点ストアへ追加し、その参照位置の頂点 ID を新 ID へ差し替える。
2. 元の共有頂点を参照する形状参照が 1 つだけになった場合、それは通常頂点になる（実体の変更は不要。導出上の共有判定が自動的に「非共有」になる）。
3. 解除直後の頂点（新 ID 側、および残存側のうち UI 上で対象だった頂点）に「自動共有化抑制中」フラグをセッション状態へ立てる。抑制は当該頂点がスナップ距離外へ一度離れたら解除する。本ユニットは「抑制中か」「抑制解除条件を満たすか（与えられた距離がスナップ距離を超えたか）」を判定する純粋関数を提供する（距離計算・スナップ距離値の供給は呼び出し側）。
4. 結果不正検証（4.4）は解除では原則不要（形状座標は不変）だが、呼び出し側が要求した場合に実行できるようにする。

### 4.7 継続規則（FR-95、複合操作との接続）

分割・結合は別ユニットが実装するが、それらが共有関係を正しく継続できるよう、本ユニットは次の純粋関数を提供する。

- **分割時の引き継ぎ**: 分割前の形状参照と分割後の新形状参照の**対応写像**（旧頂点 ID → 新頂点 ID、または旧頂点 → 複製先）を受け取り、旧頂点が持っていた共有関係を新頂点へ転写する。分割で頂点が作り直されても、対応する新頂点が同じ共有グループに入るようにする。
- **共有辺途中切断の同座標頂点挿入**: 分断線が共有辺（両端が共有頂点で、共有相手地物にも対応する辺がある辺）の途中を切る場合、切断点に新頂点を作り、共有相手地物の対応辺にも同座標の新頂点を挿入し、両者を共有頂点関係に入れる（FR-95）。挿入位置は対応辺上の比率位置で求める。挿入後に 4.3 参加制限と 4.4 結果不正検証を実行する。
- **結合時の引き継ぎ**: 結合対象が持っていた共有関係を、新規生成される結果地物の対応頂点へ転写する（FR-95）。結果地物は新規生成され結合主体は同一性を終了する（要件定義書 FR-50）ため、共有関係も結果地物側の頂点 ID 体系へ移し替える。

> 開発ガイド §5.20「元に戻す情報は依存データも含めて過不足なく保存する」「ID 等を生成するコマンドは redo で採番し直さず初回生成 ID を復元する」: 継続規則で生成する新頂点 ID は、複合操作のコマンド結果に記録し、redo 時に再採番しない。
>
> 開発ガイド §5.11「構造変更操作後の選択は結果から再解決する」: 分割・結合は対象 ID・形状が変わる。共有関係の継続もコマンド結果（残る頂点 ID・新規頂点 ID・削除された頂点 ID）から再解決する。

### 4.8 コマンドとイベント通知

各操作（共有化・連動移動・共有解除・継続規則適用）は「状態 → 新状態」の純粋コマンドとして実装し、複合操作の一部として 1 アンドゥ単位へ束ねられる形にする（技術方針 2.6、要件定義書 FR-94）。状態変更で touch した全頂点・全地物に対し、対称な通知（execute/undo/redo で同一規約、開発ガイド §5.23）ができるよう、コマンド結果に「変更された頂点 ID 集合・地物 ID 集合・新規/削除 ID」を含めて返す。

## 5. 受け入れ基準（テスト可能な形で列挙）

各項目は自動テスト（Vitest 単体／fast-check プロパティ）で検証可能であること。

1. **共有頂点ドラッグの連動**（FR-30）: 2 つ以上の面情報/線情報が共有する頂点の座標を更新する連動移動コマンドを適用すると、その頂点を参照する**すべての**形状の当該頂点座標が新座標に一致する。共有していない頂点は変化しない。（テスト: 共有頂点を含む 3 形状を用意し、移動後に全 3 形状の参照頂点座標が一致することを assert）
2. **同一リング内・同一線形内の参加制限**（FR-32）: 同一面情報の同一リング内 2 頂点、または同一線情報の同一パス内 2 頂点に対する共有化コマンドは**拒否**され、状態が変化しない。異なるリング同士・異なる地物同士は許可される。（テスト: 同一リング内ペアで拒否、外周リングと飛び地リング間ペアで許可）
3. **結果不正の禁止**（FR-32）: 共有化または共有頂点移動の結果、(a) ゼロ長エッジ、(b) 自己交差、(c) 穴飛び地階層破綻、(d) 末端地物同士の重なり、のいずれかが生じる入力に対して操作が拒否され、状態が変化せず、違反理由が戻り値で得られる。（テスト: 4 種それぞれについて、スタブ/実バリデータで違反を返させ拒否を確認。委譲先バリデータが呼ばれることも検証）
4. **共有解除と継続規則**（FR-33/FR-95）:
   - 共有解除コマンドで、解除対象の形状参照だけが同座標・新 ID の独立頂点へ切り離され、残り参照は元頂点を保持し、参照が 1 つになった頂点は共有頂点でなくなる。
   - 解除直後の頂点は自動共有化抑制中と判定され、スナップ距離を超えて離れると抑制が解除されると判定される。
   - 分割の対応写像を与えると、分割前の共有関係が分割後の新頂点へ引き継がれる。
   - 分断線が共有辺の途中を切る入力で、共有相手地物の対応辺に同座標頂点が挿入され、切断点と共有関係に入る。
   - 結合で結果地物の対応頂点へ共有関係が引き継がれる。
5. **共有継続の前後比較プロパティテスト**（技術方針 R6）: fast-check で、ランダムに生成した（共有頂点を含む）面情報/線情報の集合に対し、共有化 → 連動移動 → 共有解除、および分割・結合の継続規則適用の前後で、次の不変条件が保たれることを生成入力で検証する。
   - 共有グループは常に形状参照から一意に導出でき、グループ内に同一リング/同一線形の重複参照が存在しない（FR-32 不変条件）。
   - 連動移動の前後で、共有頂点を参照する全形状の当該頂点座標が常に一致する（参照の単一座標源、R6）。
   - 分割・結合の前後で、継続規則の定める共有関係が保たれる（引き継ぎ先頂点が同じグループに属する）。
   - 操作が拒否された場合、状態は操作前と完全一致する（部分適用が無い、FR-94）。

## 6. 関連要件（FR-id）

本ユニットが充足する要件（`coversRequirements`）と、検証で関与する近接要件を示す。

- **FR-30**（must）: 共有頂点システムの提供と連動。共有頂点ドラッグで共有全形状が連動。（本ユニットの中核。視覚的区別は描画層）
- **FR-32**（must）: 参加制限（同一リング内・同一線形内は同一グループ不可）と、結果不正（ゼロ長エッジ・自己交差・穴飛び地階層破綻・末端地物重なり）の禁止。
- **FR-33**（should）: 共有解除の提供と、解除直後の自動共有化抑制（一度スナップ距離外へ離れると解除）。
- **FR-95**（should）: 分割・結合での共有関係の継続規則（新頂点への引き継ぎ、共有辺途中切断時の同座標頂点挿入）。

関与する近接要件（本ユニットは検証委譲・連動の形で関与するが実装本体は別ユニット）:

- FR-26〜FR-29（末端地物排他・エッジ滑り、U10）、FR-31（スクリーン座標スナップの判定本体は編集セッション U24 が所有。本ユニットは決定済みペアを消費）、FR-88/FR-80（地物移動・複数頂点同時移動の連動、FR-30 と整合）、FR-94（複合操作の不可分性、コマンド形式）。技術方針 R6（値オブジェクト＋ID 参照、fast-check 前後比較）、R2（量子化・結果不変条件再検証）。

## 7. 注意点・既知の落とし穴（開発ガイドの教訓）

着手前に開発ガイド §1.6 の作業開始ゲートに従い、下記の該当教訓を引用し適用宣言してから実装すること。

- **§5.25 仕様が限定した対象範囲を実装で広げない**: 参加制限は「同一リング内」「同一線形内」に限定される。「同一地物内すべて禁止」へ拡大しない。同一面情報の異なるリング（外周と飛び地、外周と穴）間の共有は許可対象である。拡大したくなったら本書 4.3 と FR-32 を引用して止める。
- **§5.26 編集制約はコマンド確定前にも同じサービスで検証する**: 共有化候補の UI ハイライトで使った検証と、コマンド確定前の検証を同一サービスで行う。ショートカット・メニュー・直接呼び出し・undo/redo から不正状態が入らないよう、確定前検証を必須にする。拒否理由は通知用メッセージとテスト可能な戻り値の両方で返す。
- **§5.30 過少共有と過剰共有の両方を戒める**: 共有判定・参加制限・継続規則で使う「共有グループ導出」は単一実装を共有する（過少共有の戒め）。一方、結果不正検証のバリデータ群（U06/U07/U10）は対象も規則も異なるため安易に 1 つへ畳まない（過剰共有の戒め）。
- **§5.17 イミュータブルな値オブジェクトの設計**: 頂点は不変。座標変更は新インスタンスを返し等価性は属性比較。`withXxx` 系を作るなら全属性の網羅を確認する。
- **§5.21 削除は参照掃除と連鎖剪定まで行う**: 共有化で孤立した頂点 ID は頂点ストアから掃除する。共有解除・継続規則で参照が消えて孤立した頂点も剪定する。片方向・単一時点だけの掃除は dangling 参照を残す。
- **§5.22 確定まで共有データを破壊的に更新しない**: 共有化・連動・継続規則は、結果不正検証を通るまで頂点ストア/形状参照を破壊的に確定しない。違反時は追加要素を全ロールバックして操作前状態を返す。
- **§5.20 元に戻す情報は依存データも含めて過不足なく保存する**: 継続規則で生成する新頂点 ID はコマンド結果に記録し、redo で再採番しない。共有関係の復元に必要な依存データ（旧→新 ID 写像）を保存する。
- **§5.11 構造変更後の選択/関係は結果から再解決する**: 分割・結合後の共有関係は固定処理でなくコマンド結果（残存/新規/削除 ID）から再解決する。
- **§5.23 execute/undo/redo は対称に通知する**: 共有化・連動・解除・継続規則の touch 対象（頂点 ID・地物 ID）を対称に通知できるよう、コマンド結果へ変更 ID 集合を含める。直後の手動リフレッシュを書きたくなったら通知漏れのサイン。イベント発火テストは期待集合の厳密一致で検証する。
- **§5.28 階層を辿る再帰は循環で無限ループしない**: 共有グループ導出・継続規則で形状参照や階層を辿る際、壊れたデータ（自己参照・循環）でも visited セットで再入を遮断し有限結果を返す。循環テストケースを置く。
- **§5.31 永続化の読み書き・検証・往復を同期する**: 頂点の値オブジェクト＋ID 参照モデルは保存形式（FR-103）にも波及する。本ユニットでモデルを定義/変更したら、シリアライズ・デシリアライズ・整合性検証（存在しない頂点参照の検出、FR-106）・往復テストを同じ変更単位で同期する（保存・整合性ユニットと連携）。
- **§5.33 層をまたぐ API 契約は両側テストで固定する**: 結果不正検証のバリデータインタフェース（U06/U07/U10 への委譲契約）は、共有型・両側テストで固定し、文字列/構造の偶然一致に頼らない。
- **量子化と数値誤差**（技術方針 R2）: 共有化で 2 頂点を 1 つに統合する際、座標一致判定・ゼロ長エッジ検出は量子化（固定格子スナップ）後の同一性で行う。浮動小数の厳密一致に頼らない。共有辺途中切断の挿入点座標も量子化に整合させる。
- **世界端ラップ**（技術方針 R3）: 頂点座標は連続スカラー経度で保持し、世界端（±360 度境界）をまたぐ共有・連動でもラップ正規化を経て一貫した距離・包含判定になるよう、座標は U03/技術方針 R3 のラップ正規化前提に従う。
- **クリーンルーム原則**（開発ガイド §3.1）: 本書および実装に、過去版・他プロダクト・「従来」等の外部参照を持ち込まない。制約は本アプリ要件として直接記述する。

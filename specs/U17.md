# U17 MapRenderer インタフェースと Canvas カメラのワールド↔スクリーン VTransform

## 目的

本アプリは地図描画を `render` 層で命令的に制御する。地理特化のタイル地図ライブラリは正距円筒の架空地図・無限横ループ・本アプリ独自の面階層描画には制約と「魔法」になるため採用せず、ワールド座標（経度・緯度）からスクリーン座標（Canvas のピクセル）への変換を完全に自前制御する。これは正距円筒図法（FR-05）・無限横スクロール（FR-07）・世界全体〜都市内の連続ズーム（FR-08）・ズーム非依存の画面上一定サイズ表示（FR-17）・初期表示（FR-11）を成立させるための前提である。

本ユニットの目的は二つである。

1. **描画層を `MapRenderer` インタフェースとして抽象化する**。カメラ変換・地物バッチ・ヒットテストの契約を型で固定し、既定の Canvas 2D 実装を提供する。これにより、既定実装で性能未達が計測で判明した場合に、ドメイン・UI・状態を変更せず WebGL 実装へ局所的に差し替えられる退避路（技術方針 R1）を確保する。
2. **カメラのワールド↔スクリーン変換（VTransform）を実装する**。正距円筒図法に基づく双方向変換、無限横スクロール（経度を連続スカラーで保持し、端をまたぐ領域を破綻なく表示・端ラップ表示）、世界全体〜都市内の連続ズーム、カーソル位置を中心とするホイールズームを実現する。

本ユニットはカメラ変換とインタフェース契約・既定実装の骨格までを担い、地物（点・線・面）の具体的な塗り・パス描画の業務ロジック本体や、ヒットテストの幾何述語本体は後続ユニットの責務とする（本ユニットはそれらが乗る座標変換とバッチ／ヒットテストの契約・最小実装を提供する）。

この方針は技術方針 2.4「地図描画: Canvas 2D（差し替え可能インタフェース）」および 4. リスクと緩和策 R1 を直接の根拠とする。技術方針 2.4 は「描画層は `MapRenderer` インタフェース（カメラ変換・地物バッチ・ヒットテストの契約）として抽象化する。これにより既定の Canvas 2D 実装で性能未達が計測で判明した場合、ドメイン・UI・状態を変更せず WebGL 実装（PixiJS 等）へ局所的に差し替えられる退避路を確保する」と定めている。

## スコープ

### やること

1. **`MapRenderer` インタフェース（契約）の定義**
   - 描画層の差し替えを可能にする抽象インタフェースを `render` 層に定義する。最低限、以下の契約を含む。
     - **カメラ変換契約**: ワールド座標（経度・緯度）↔スクリーン座標（CSS ピクセル）の双方向変換、現在のカメラ状態（中心経度・中心緯度・ズーム）の設定／取得、ビューポートサイズ（幅・高さ・devicePixelRatio）の設定。
     - **地物バッチ契約**: 1 フレームで描画すべき地物（点・線・面・グリッド・ラベルなど）の集合を受け取り描画を実行する入口。バッチは「描画すべきものの記述（ワールド座標と視覚属性）」であり、レンダラはそれを現在のカメラで変換して描く。実装差し替え時に同じバッチ記述で同じ見た目を再現できる粒度で型を定義する。
     - **ヒットテスト契約**: スクリーン座標を受け取り、その位置にあるワールド座標、および（本ユニットの範囲では）当たり判定に必要な変換情報を返す入口。地物単位の当たり判定本体は後続ユニットが本契約のカメラ変換を用いて実装する前提で、契約上の最小シグネチャを定義する。
   - インタフェースは具象実装（Canvas 2D / WebGL）に依存しない純粋な型契約とし、ドメイン・UI・状態はこのインタフェースにのみ依存する（具象実装へ直接依存しない）。

2. **既定 Canvas 2D 実装**
   - `MapRenderer` を実装する Canvas 2D レンダラを提供する。本ユニットの範囲では、カメラ変換・ビューポート管理・無限横スクロールのタイル状繰り返し描画・グリッド／一定サイズ表示の基盤・最小の地物描画（点・線・面の骨格描画とラベルの一定サイズ配置）を備える。
   - HiDPI（devicePixelRatio）対応として、Canvas のバックバッファ解像度と CSS ピクセル座標系を分離し、変換は CSS ピクセル基準で行う。

3. **ワールド↔スクリーン変換（VTransform）**
   - 正距円筒図法に基づく `worldToScreen(経度, 緯度) → スクリーン座標` と `screenToWorld(スクリーン座標) → 経度, 緯度` の双方向変換を提供する。正距円筒では経度・緯度がそれぞれ x・y に線形対応する（緯度方向の歪み補正は行わない）。
   - カメラ状態は「中心経度（連続スカラー）・中心緯度・ズーム（連続値）」で表現する。変換はこのカメラ状態とビューポートサイズから一意に決まる。
   - `worldToScreen` と `screenToWorld` が互いの逆変換であること（往復一致）を保証する。

4. **無限横スクロール（連続スカラー経度・端ラップ表示）**
   - カメラの中心経度を連続スカラー（−180〜+180 に閉じ込めず任意実数を取りうる）として保持し、東西どちらへパンし続けても破綻しない。
   - 描画時、現在のビューポートが経度方向に世界 1 周（360 度幅）の端をまたぐ場合でも、地物・グリッド・ベースマップを ±360 度オフセットした複製として繰り返し描画し、世界端で表示が途切れない（端ラップ表示）。ビューポートが世界を複数周分覆うズームアウト時は、必要な周回数だけ繰り返して隙間なく敷き詰める。
   - 中心経度の表示用正規化（現在の中心経度を代表区間で表示する、FR-12 関連）は U05 の正規化関数を経由する。本ユニットで独自にまたぎ判定・±360 度補正を書かない。

5. **連続ズーム（世界全体〜都市内）とカーソル中心ホイールズーム**
   - ズームを連続値として扱い、世界地図全体から都市内地図レベルまでスムーズにズームできる。ズーム倍率はカメラ状態の一要素として保持する。
   - マウスホイール操作で、カーソル位置（スクリーン座標）が指すワールド座標がズーム前後で同一スクリーン位置に留まる「カーソル位置中心ズーム」を実現する。
   - ズーム範囲の上下限クランプの結線点を用意する（既定の制限値・ユーザー設定可能範囲は U16 のセッション設定が保持する想定で、本ユニットは渡されたクランプ範囲を適用する。範囲が未供給の場合の暫定既定は FR-10 の既定値=最小 1 倍〜最大 50 倍に従う）。

6. **点／線／ラベルのズーム非依存の一定サイズ描画基盤（FR-17）**
   - 点の大きさ・線の太さ・名前ラベルのフォントサイズが、ズームレベルに関わらず画面上の見た目のサイズで一定になる描画基盤を提供する。すなわち、位置はワールド→スクリーン変換で動くが、サイズ（半径・線幅・フォント px）はスクリーン空間で固定する。
   - 本ユニットでは「位置はワールド変換・サイズはスクリーン固定」という規約と、それを担保する描画ヘルパー（一定サイズで点・線・ラベルを置く最小実装）を提供する。地物種別ごとの詳細なラベル表示可否判定（FR-86）は後続ユニットの責務であり、本ユニットは一定サイズ描画の基盤のみを担う。

7. **初期表示（FR-11）**
   - 起動時のカメラ初期状態を「中心経度 0 度・中心緯度 0 度・地図全体が表示されるズームレベル」とする。地図全体が収まるズームは、ビューポートのアスペクト比から「世界の経度幅 360 度・緯度幅 180 度がともに収まる最大ズーム」として算出する。

### やらないこと

- 経度ラップ展開そのもの（±360 度オフセット複製・周期境界正規化の純粋関数）の実装。これは U05 の責務であり、本ユニットは U05 の正規化関数を経由して中心経度の表示正規化・端ラップ表示の周回数算出に用いるに留まる。U05 の正規化を本ユニットで再実装しない（単一の真実源）。
- 表示経度シフトの UI（FR-12 のスライダー／ボタン・本初子午線中心／太平洋中心の切替）。本ユニットはカメラの中心経度を連続スカラーで受け取って描画するに留まり、シフト操作の UI・状態遷移は別ユニットが担う（本ユニットはその受け皿となるカメラ状態設定 API を提供する）。
- パン操作の入力ハンドリング（左／中ボタンドラッグでのパン、FR-09）。本ユニットはカメラ状態をプログラム的に更新する API は提供するが、マウスドラッグのイベント処理・モード別のボタン割当は別ユニットが担う（本ユニットはホイールズームのカメラ計算のみを VTransform の責務として含む）。
- 点・線・面の業務的な描画（自動配色 FR-100/101、選択時の視覚フィードバック FR-82、エッジ滑りハイライト FR-28、穴の透過／飛び地の独立描画 FR-21、地物種別ごとのラベル表示可否 FR-86）。本ユニットは一定サイズ描画基盤とバッチ契約を提供し、これら業務描画は後続ユニットがバッチ記述を組み立てて実現する。
- 地物単位のヒットテスト本体（点in多角形・最近傍頂点判定・地物選択の優先順位）。本ユニットはヒットテスト契約のシグネチャと、それが用いるスクリーン↔ワールド変換を提供するに留まる。
- グリッド（緯線・経線）の間隔・色・不透明度・強調表示・ラベル文言の業務仕様（FR-13）。本ユニットは「グリッド線をワールド座標で受け取り一定サイズ表示する」描画基盤までを担い、間隔・強調などの設定駆動の仕様は別ユニットが担う。
- ベースマップ画像の読み込み・差し替え・自動補正・フォールバック（FR-03/04）。本ユニットは「与えられた画像をベースマップとして現在のカメラで端ラップ表示する」描画基盤を担うに留まり、画像の取得・検証は別ユニットが担う。
- 状態管理（Zustand）でのカメラ状態の保持・購読・即時再描画のブリッジ構築の全体。カメラ状態の真実源は U16 のセッション状態に置く想定であり、本ユニットは U16 が保持するカメラ状態を入力として受け取り変換・描画する（後述 依存）。

## 依存（dependsOn）

- **U16**: UI／セッション状態（選択・モード・ズーム・現在時刻・カメラ状態など）の薄いストア基盤に依存する。カメラの真実源（中心経度・中心緯度・ズーム・ズーム制限範囲）は U16 のセッション状態に置かれる想定とし、本ユニットはその状態を入力として受け取って描画し、ホイールズーム等で算出した新しいカメラ状態を U16 のストアへ書き戻す経路で結線する。U16 が確立するカメラ状態の型・更新 API に従い、本ユニットでカメラ状態を二重に定義しない（単一の真実源）。
  - U16 の具体的な型名・更新関数シグネチャが本ユニット着手時点で未確定の場合は、U16 が公開する「カメラ状態の読み出し」「カメラ状態の更新」の純粋／薄い API を介してアクセスする想定で実装し、U16 の公開境界に合わせて結線する。状態の真実源は U16 に置き、`render` 層はそれを購読・反映するのみとする（描画状態を React state には持たせない、技術方針 2.3/2.5）。

- **U05**: 経度の連続スカラー表現と ±360 度正規化、世界端ラップに関する純粋関数群に依存する。中心経度の表示用正規化（代表区間 `[-180, +180)` への写し）、および端ラップ表示で必要な ±360 度オフセットの周回数算出に U05 の正規化を用いる。本ユニットでまたぎ判定・±360 度補正・代表区間境界の基準値を独自に持たず、U05 を単一の真実源とする。

本ユニットは `render` 層に配置し、ドメイン（U05 が属する `domain` 層）と U16 のセッション状態に依存する。React コンポーネントツリーの再レンダリングサイクルからは独立し、Canvas を命令的に直接制御する（技術方針 2.3）。

## 実装方針（技術方針に沿う）

- **配置層と依存方向**: `MapRenderer` インタフェースと Canvas 2D 実装は `render` 層に置く。依存方向は内向き（`domain` へ）に固定し、`render` は `ui`／`shell` に依存しない。ドメイン・UI・状態は `MapRenderer` インタフェース（抽象）にのみ依存し、Canvas 2D 具象実装へ直接依存しない（技術方針 2.13、R1 の差し替え可能性を構造で担保）。
- **React からの分離**: 地図描画は React の再レンダリングサイクルから完全に切り離し、Canvas 側で直接管理する。描画状態を React state に持たせない。カメラ状態は U16（Zustand）に置き、`render` は購読のみで React の描画経路に乗らない（技術方針 2.3）。
- **インタフェース抽象の純度（R1）**: `MapRenderer` の契約は Canvas 2D 固有の概念（`CanvasRenderingContext2D` 等）を露出させず、WebGL 実装でも同一契約を満たせる抽象に保つ。カメラ変換・地物バッチ・ヒットテストの三契約を、実装差し替え時に呼び出し側を変更不要にする粒度で型固定する（技術方針 2.4、層をまたぐ契約の固定＝開発ガイド §4）。
- **VTransform の純粋関数化**: ワールド↔スクリーン変換・カーソル中心ズームのカメラ算出・初期全体表示ズーム算出といった座標計算は、`CanvasRenderingContext2D` に触れない純粋関数として切り出し、Canvas 描画コマンドと分離する。これにより変換ロジックを副作用なく単体テスト・プロパティテストでき（NFR 5.8）、WebGL 実装からも同じ純粋関数を再利用できる。Canvas 2D 実装はこの純粋な変換結果を使って描画コマンドを発行するだけにする。
- **連続スカラー経度と端ラップ**: 中心経度は連続スカラーとして保持する。表示用正規化と端ラップの周回数算出は U05 の正規化を経由する。端ラップ描画では、ビューポートが覆う経度範囲を求め、その範囲を覆うのに必要な ±360 度オフセットの集合を算出し、各オフセットで地物・グリッド・ベースマップを繰り返し描画する。オフセット集合の算出は U05 の基準値（360 度周期）と整合させ、本ユニットで独自の周期定数を持たない（技術方針 R3、単一の真実源）。
- **一定サイズ表示（FR-17）**: 「位置はワールド→スクリーン変換、サイズはスクリーン空間で固定」を描画基盤の規約として一箇所に実装する。点半径・線幅・フォント px はズームに依存せず、ワールド座標から導出しない。サイズ規約を共通ヘルパーに集約し、点・線・ラベルが各々独自にサイズを算出してドリフトしないようにする（技術方針 5.2「FR-17 のズーム非依存一定サイズ表示はワールド→スクリーン変換で制御」、単一の真実源）。
- **HiDPI**: バックバッファ解像度（物理ピクセル）と論理座標系（CSS ピクセル）を分離し、ワールド↔スクリーン変換は CSS ピクセル基準に統一する。devicePixelRatio はバックバッファのスケーリングにのみ用い、変換式へ混入させない（一定サイズ表示の基準を CSS ピクセルで一貫させる）。
- **カーソル中心ズーム**: ホイールズームは「ズーム前にカーソルのスクリーン座標が指すワールド座標を求め、ズーム後にそのワールド座標が同じスクリーン座標へ来るよう中心経度・中心緯度を補正する」純粋計算として実装する。中心経度は連続スカラーのまま補正し、世界端をまたいでも破綻しない。ズーム値はクランプ範囲（U16 由来、未供給時は FR-10 既定）でクランプする。
- **初期表示（FR-11）**: 初期カメラを中心経度 0・中心緯度 0・全体表示ズームとする純粋関数を提供する。全体表示ズームはビューポートのアスペクト比から、経度幅 360 度・緯度幅 180 度がともに収まる最大ズームとして算出する。アスペクト比により横が制約になるか縦が制約になるかを正しく場合分けする。
- **性能とバッチ（R1 の前提）**: 本ユニットは描画バッチの入口を契約として持ち、視野外クリッピング・LOD・ダーティ矩形・描画バッチ・オフスクリーンキャッシュといった最適化（技術方針 R1）を後続で組み込める構造にする。本ユニットの範囲では変換とバッチ契約・最小描画を提供し、最適化の本体は計測（自作計測ハーネス）で必要性が判明した時点で組み込む段階戦略を採る。
- **テスト同時実装**: VTransform の純粋関数を Vitest で「入力→期待座標」で固定し、fast-check で往復一致・カーソル中心不変・端ラップの不変式を生成入力で網羅する（技術方針 2.14、NFR 5.8）。Canvas 2D 実装の描画は、座標計算が純粋関数へ切り出されているため、変換の正しさはレンダラ非依存にテストできる。レンダラのバッチ／ヒットテスト契約は、差し替え可能性を担保するため契約レベルの両側テスト（呼び出し側・実装側）で固定する（開発ガイド §5.33）。

## 受け入れ基準（テスト可能な形で列挙）

各基準は、対応するテスト（VTransform 純粋関数の Vitest 単体／fast-check プロパティテスト、レンダラ契約の両側テスト、必要に応じて E2E）が緑になることをもって満たされたとみなす。

1. **ワールド↔スクリーン変換が正距円筒で正しく、無限横スクロールが破綻しない（FR-07）**
   - `worldToScreen` と `screenToWorld` が互いの逆変換であり、任意のワールド座標／スクリーン座標に対し往復が一致する（プロパティテスト）。
   - 正距円筒の線形性が満たされる（経度の等差はスクリーン x の等差に、緯度の等差はスクリーン y の等差に、同一スケールで対応する）。
   - 中心経度を連続スカラーとして東西へ任意量パンし続けても、変換が NaN／Infinity を生まず一貫した結果を返す。
   - ビューポートが世界端（経度 ±180 度境界）をまたぐとき、地物・グリッド・ベースマップが ±360 度オフセット複製として繰り返し描画され、世界端で表示が途切れない（端ラップ表示）。ズームアウトでビューポートが世界を複数周覆う場合、必要な周回数だけ隙間なく敷き詰められる。
   - 中心経度の表示用正規化が U05 の正規化を経由し、本ユニット内に独自のまたぎ判定・±360 度補正が存在しない。

2. **世界全体〜都市内の連続ズームとカーソル中心ホイールズームが動く（FR-08）**
   - ズームが連続値として扱え、世界全体レベルから都市内レベルまで段階的でなく連続に変化させられる。
   - ホイールズーム後、ズーム前にカーソルのスクリーン座標が指していたワールド座標が、ズーム後も同一のスクリーン座標に留まる（カーソル位置中心ズームの不変式。プロパティテストで任意のカーソル位置・任意のズーム変化に対し成立）。
   - ズーム値が供給されたクランプ範囲（未供給時は最小 1 倍〜最大 50 倍）でクランプされ、範囲外へ出ない。
   - カーソルが世界端付近にある状態でのホイールズームでも、中心経度が連続スカラーのまま補正され破綻しない。

3. **点／線／ラベルが画面上一定サイズで描画される（FR-17）**
   - 同一の点・線・ラベルを異なるズームで描画したとき、点の半径（px）・線の太さ（px）・ラベルのフォントサイズ（px）がズームに関わらず一定である。
   - 位置はワールド→スクリーン変換に従って動くが、サイズはスクリーン空間で固定であることを、ズームを変えてもサイズ px が不変・位置 px が変化することで検証する。
   - サイズ規約が共通ヘルパーに集約され、点・線・ラベルが各々独自にサイズを算出していない（単一の真実源）。

4. **初期表示が中心経度 0／緯度 0／全体表示（FR-11）**
   - 初期カメラ状態が中心経度 0 度・中心緯度 0 度である。
   - 初期ズームで地図全体（経度幅 360 度・緯度幅 180 度）がビューポートに収まる。横長／縦長いずれのアスペクト比でも、経度幅・緯度幅の両方が収まる最大ズームが選ばれる（はみ出さない・かつ無駄に小さすぎない）。
   - 初期全体表示ズーム算出が純粋関数として独立してテストでき、代表的なアスペクト比（横長・縦長・正方形）で期待ズームを返す。

5. **`MapRenderer` インタフェースで実装差し替え可能（WebGL 退避路・R1）**
   - ドメイン・UI・状態が Canvas 2D 具象実装に直接依存せず、`MapRenderer` インタフェース（抽象）にのみ依存している（具象 import が呼び出し側に存在しない）。
   - `MapRenderer` の契約（カメラ変換・地物バッチ・ヒットテスト）が、同一のバッチ記述・同一のカメラ状態に対し実装非依存に定義されており、別実装（モック実装またはスタブ WebGL 実装）を差し込んでも呼び出し側のコードを変更せず動作する契約両側テストが緑になる。
   - VTransform の座標計算が `CanvasRenderingContext2D` に依存しない純粋関数として切り出され、レンダラ実装を差し替えても再利用できる（純粋関数単体テストがレンダラ非依存に緑になる）。

6. **`render` 層の分離規律**
   - カメラ状態の真実源が U16 のセッション状態にあり、本ユニットはそれを入力として受け取り描画し、算出した新カメラ状態を U16 へ書き戻す経路で結線されている（カメラ状態を本ユニットで二重定義していない）。
   - 描画状態が React state に保持されておらず、Canvas が命令的に制御されている（React 再レンダリング経路に地図描画が乗っていない）。

## 関連要件（FR-id）

- **FR-07**（must）: 横方向の無限スクロールを実現し、地図の東端・西端をまたぐ領域を表示・編集できる。本ユニットは連続スカラー経度のカメラと端ラップ表示で、世界端をまたぐ表示を破綻なく実現する。
- **FR-08**（must）: ズームイン・ズームアウト・パン操作をサポートし、世界地図全体から都市内地図レベルまでの広範囲かつスムーズなズームを実現する。本ユニットは連続ズームとカーソル位置中心ホイールズームを VTransform として実装する（パン入力ハンドリングは別ユニット）。
- **FR-11**（should）: 起動時の初期表示は中心経度 0 度・中心緯度 0 度・地図全体が表示されるズームレベルとする。本ユニットは初期カメラ状態と全体表示ズーム算出を提供する。
- **FR-17**（should）: 点・線・面の点の大きさ・線の太さ・名前ラベルは、ズームレベルに関わらず画面上の見た目のサイズが一定になるよう調整する。本ユニットは「位置はワールド変換・サイズはスクリーン固定」の一定サイズ描画基盤を提供する。

関連する横断要件・背景根拠: 技術方針 2.4（Canvas 2D 差し替え可能インタフェース）、R1（性能未達時の WebGL 局所差し替え退避路）、R3（無限横スクロール・経度シフトと世界端ラップの整合）、FR-09（パン・ホイールズームの操作仕様。本ユニットはホイールズームのカメラ計算のみ担い、ドラッグパンは別ユニット）、FR-10（ズーム制限範囲。本ユニットはクランプ適用を担い、制限値の保持・設定は U16／設定ユニット）、FR-12（表示経度シフト。本ユニットは中心経度の連続スカラー受け皿を提供、UI は別ユニット）、FR-13（グリッド）・FR-86（地物種別ごとのラベル表示可否）・FR-21（穴透過／飛び地独立描画）・FR-82（選択視覚フィードバック）は本ユニットの一定サイズ・バッチ基盤の上に後続ユニットが実装する。NFR 5.1（60FPS／100ms）・NFR 5.8（純粋ロジックの分離・機械的検証）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の関連教訓を節番号・見出し・本文ごと直接引用し、今回の実装判断へどう適用するかを「適用:」として明示してから着手すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **開発ガイド §4「単一の真実源」／§5.30 過少共有と過剰共有の両方を戒める**
  - 適用: 経度の周期境界（360 度周期・代表区間境界・またぎ判定）は U05 の正規化を唯一の窓口として用い、本ユニットで独自に再実装しない（過少共有の戒め）。FR-17 の一定サイズ規約（点半径・線幅・フォント px のスクリーン固定）は共通ヘルパーに集約し、点・線・ラベルが各々独自にサイズを算出してドリフトさせない。カメラ状態の真実源は U16 に一元化し、本ユニットで二重定義しない。一方で、緯度（周期性なし）に経度の周期処理を流用しない（過剰共有の戒め）。

- **開発ガイド §5.29 派生形状は単一の解決判定で全経路を動かす**
  - 適用: ワールド↔スクリーン変換は描画・ヒットテスト・将来の選択経路すべてで同一の変換関数を用いる。描画とヒットテストが別々の変換式を持つと「描画されているのにその位置をクリックしても当たらない」「ラベル位置が描画と違う」という対概念矛盾を生む。`worldToScreen`／`screenToWorld` を単一の真実源として全経路から呼ぶ。検出: 同一カメラ状態で `worldToScreen`→`screenToWorld` の往復一致を全経路の前提としてテストで固定する。

- **開発ガイド §5.33 層をまたぐ API 契約は両側テストで固定する**
  - 適用: `MapRenderer` の契約（カメラ変換・地物バッチ・ヒットテスト）は、呼び出し側（UI／状態）と実装側（Canvas 2D／将来の WebGL）が共有する層またぎ契約である。契約名・型・入出力規約を共有型で明示し、実装を差し替えても呼び出し側を変更不要にするため、契約レベルの両側テスト（呼び出し側がモック実装でも、Canvas 2D 実装でも同一に動く）で固定する。旧契約名が残らないよう API 名変更時は全層を同一変更単位で更新する。

- **開発ガイド §5.32 多層に波及する変更は最大 2 層に分割する**
  - 適用: `MapRenderer` 契約の変更は `render`・`ui`・状態・テストへ多層波及しうる。契約の追加・変更は影響経路を最大 2 層で宣言して分割し、宣言外の経路に及びそうなら別タスクへ切り出す。本ユニットでは契約定義・Canvas 2D 既定実装・VTransform 純粋関数までに責務を閉じ、業務描画（自動配色・選択表示・グリッド業務仕様・ベースマップ取得）へ越境しない。

- **開発ガイド §5.25 仕様が限定した対象範囲を実装で広げない**
  - 適用: FR-17 は「点の大きさ・線の太さ・名前ラベル」を一定サイズの対象として明示している。面の塗り自体のスケールや、グリッド線の太さ・ラベルの業務仕様まで本ユニットで勝手に拡張しない。本ユニットは一定サイズ描画の基盤を提供し、種別ごとの表示可否（FR-86）・グリッド設定（FR-13）など仕様で別ユニットに属する範囲へ広げない。緯度に周期正規化を被せるなどの「対称性確保」を理由にした拡張もしない。

- **開発ガイド §5.18 空配列・空オブジェクトは真値である**
  - 適用: バッチに地物が 0 件のフレーム、端ラップのオフセット集合が要素 1 個（またぎなし）のケースを、論理和による短絡デフォルト補完で握りつぶさない。空バッチ・単一オフセットは型・件数で明示判定し、未定義動作（描画スキップの取りこぼし・NaN）を避ける。

- **開発ガイド §5.17 イミュータブルなエンティティ/値オブジェクトの設計**
  - 適用: VTransform・カメラ状態・カーソル中心ズームの算出は入力カメラ状態を破壊変更せず新しい値を返す純粋関数とする。同じ入力に同じ出力を返し、往復一致・カーソル中心不変はこの等価性で判定する。

- **量子化・浮動小数の落とし穴（技術方針 R2／R3 と整合）**
  - 端ラップのための ±360 度オフセットは、世界端をまたぐ繰り返し描画で誤差が累積しないよう、中心経度の連続スカラーに整数オフセットを一度だけ適用する形で算出する（360 度の加減を反復しない）。世界を複数周覆うズームアウトでも、オフセット集合算出が有限回で完了し無限ループ・NaN／Infinity を生まないことをテストで保証する。

- **病的入力・極端カメラでの安全性**
  - 極端なズーム（クランプ範囲端）、極端な中心経度（例: 連続スカラー 10^6 度）、退化ビューポート（幅・高さ 0、devicePixelRatio 異常値）でも、変換が NaN／Infinity を生まず、初期全体表示ズーム算出が破綻しないことを fast-check の極端値生成で検証する。

- **HiDPI と一定サイズの基準の取り違え**
  - 検出観点: devicePixelRatio をワールド↔スクリーン変換式に混入させると、FR-17 の一定サイズが端末ごとにずれる。変換と一定サイズは CSS ピクセル基準に統一し、devicePixelRatio はバックバッファのスケーリングにのみ用いる。異なる devicePixelRatio で同一の CSS ピクセルサイズが得られることをテストで固定する。

# U16 UI/セッション状態ストア(Zustand)とドメインブリッジ

## 目的

本アプリは、ジオメトリ・時間・階層という本質的に難しいドメインを抱える歴史可視化ツールであり、ドメインの真実（地物・頂点・リング・錨・ツリー・フラグ）は React にも Electron にも Canvas にも依存しない純粋関数の独立コアに置く。本ユニットはその外側に位置する「UI / セッション状態の薄いストア」を構築し、純粋ドメインコアと React・Canvas をつなぐ単一の接続点（ブリッジ）を確立する。

UI / セッション状態とは、ドメインの真実そのものではないが、現在の対話セッションにおける「いまどこを・いつを・どのモードで見て、何を選んでいるか」という揮発的な状態である。具体的には、選択（アクティブ地物・頂点選択セット）、モード（表示／追加／編集の排他モードとアクティブツール）、現在時刻（タイムラインが指す作中時刻）、ズーム／カメラ（倍率・中心・パン）、現在の中心経度（経度シフト）を指す。これらを Zustand で薄く一元管理し、フレームワーク非依存のドメインストアを Zustand の `subscribe` でブリッジすることで、Zustand を「アプリ全体の単一の真実源」に据える。

本ユニットの中核責務は次の四点である。

1. UI / セッション状態を Zustand で薄く管理し、ドメインを React 非依存に保つ層境界を引く（技術方針 2.5）。
2. React 外の純粋ドメインストアを `subscribe` でブリッジし、ドメイン状態の変化と UI/セッション状態の変化が一つの真実源に集約される構造をつくる。
3. 現在時刻が変化したとき、それに依存する選択状態（選択中の地物がその時刻に存在するか）を再検証し、非存在なら選択を解除する（教訓 5.5）。
4. プロジェクト固有設定とアプリ全体設定の境界を定義し、保存先と反映先を一貫させたうえで、設定変更が関連表示へ即時反映される経路を提供する（教訓 5.36、FR-109 / FR-110）。

そのうえで、高頻度更新の地図描画は React の再レンダリングサイクルから完全に切り離し、Canvas 側は本ストアを購読するのみで React の描画経路に乗らないという規律を、本ユニットの設計初期から構造として固定する（技術方針 2.3 / 2.5、NFR 5.1）。

## スコープ

### やること

1. **UI / セッション状態の薄い Zustand ストア定義**
   - 次の揮発的状態を保持するストアを定義する。いずれもドメインの真実ではなく、セッション固有の閲覧・操作文脈である。
     - 選択: アクティブ地物（常に 0 件または 1 件）と、頂点選択セット（選択頂点 ID の集合）。
     - モード: 表示／追加／編集の排他モードと、現在アクティブなツール識別子。
     - 現在時刻: タイムラインが指す作中時刻（時間点。U02 の完全値型で保持する）。
     - ズーム／カメラ: 倍率・中心座標・パン位置（ワールド座標系）。
     - 現在の中心経度: 経度シフトの中心経度（連続スカラーで保持し、無限横スクロールに対応）。
   - ストアは「薄く」保つ。ドメインの真実（地物・錨・ツリー等）を Zustand に複製して持たない。ドメイン状態は純粋ドメインコアが保持し、本ストアはそれへの参照（後述ブリッジ）と UI/セッション状態のみを持つ。

2. **純粋ドメインストアの Zustand `subscribe` ブリッジ**
   - React 非依存の純粋ドメインコアが保持する「現在のドメイン状態（不変値）」を、Zustand ストアからブリッジして参照できるようにする。ドメイン状態が新しい不変値へ差し替わったとき、Zustand 側の購読者（React・Canvas）がそれを観測できる単一経路を提供する。
   - Zustand を単一の真実源とし、UI/セッション状態とドメイン状態（の現在値参照）の双方をここから購読できるようにする。Canvas 側はこの購読のみで描画を駆動し、React の再レンダリングを介さない。
   - ドメイン状態の更新そのもの（コマンド適用・履歴 push）は U12 のコマンド基盤に委ね、本ユニットはその結果として生じる「新しいドメイン状態」をストアへ反映し購読者へ伝える橋渡しに徹する。

3. **時間変化時の依存状態の再検証（選択の再検証・解除）**
   - 現在時刻が変化したら、それに依存する UI/セッション状態を再検証する。特に、アクティブ地物が新しい時刻において有効な錨を持つ（その時刻に存在する）かを判定し、非存在なら選択を解除する（教訓 5.5、FR-71）。
   - 同様に、頂点選択セットが指す地物・頂点が新時刻に存在しないなら、選択頂点 ID を整理（非存在分を除去し、結果が空なら頂点選択コンテキストも解消）する。
   - 再検証は「現在時刻が変わった」という結果状態で起動し、特定の入力経路（スライダー操作経由／数値ジャンプ経由／錨選択による同期経由）に限定したゲートでは行わない（教訓 5.6）。時刻を変える全経路が同じ再検証を通る。

4. **プロジェクト設定とアプリ全体設定の境界定義と即時反映経路**
   - プロジェクト固有設定（FR-109: プロジェクト名・説明、赤道長、扁平率、タイムライン最小/最大年、グリッド間隔/色/不透明度、ベースマップ指定、面情報ラベル画面占有率閾値、新規面の自動配色既定値、既定パレットテーマ、カスタムパレット）と、アプリ全体設定（FR-110: 共有頂点スナップ距離=既定 50px、描画更新頻度=1〜60FPS・既定 60、全頂点マーカー表示上限）の境界を型で明示的に分離する。
   - 各設定がどちらに属し、どこに保存され（プロジェクト設定はプロジェクトデータ＝保存対象、アプリ全体設定はアプリレベルの永続化対象）、どこへ反映されるかを一貫させる（教訓 5.36）。本ユニットは「保存先の決定（型による分類）」と「変更の即時反映経路（購読者への通知）」を担い、実際の永続化 I/O は別ユニットへ委ねる。
   - 設定変更が確定したら、関連する表示（赤道長・グリッド設定はマップ表示、スナップ距離・描画更新頻度・マーカー表示上限は編集/描画挙動）へ即時反映されるよう、Zustand ストア経由で購読者へ通知する経路を提供する（FR-109 / FR-110）。

5. **選択・モード・時刻・カメラを更新するアクション（薄いセッターと派生）**
   - 上記状態を更新する型付きアクション（選択の置換/加除/全解除、モード切替、ツール切替、時刻設定、カメラ更新、経度シフト、設定更新）を提供する。
   - 単一クリックで頂点選択セットを置換、Shift+クリックで加除、ドラッグ矩形で範囲選択といった頂点選択の更新規則（FR-80）の状態保持と、選択セットから所有地物を導く頂点選択コンテキスト（FR-81）の派生を提供する（派生は表示状態として保持し、データソース全体の再走査をしない。教訓 5.3）。
   - モード切替・ツール切替の際は、一時的 UI 状態（追加中ドラフト・ドラッグ中の仮値・選択中の値など）が残らないよう破棄する責務の入口を設ける（教訓 5.2）。ただし一時状態の実体（描画プレビュー等）は描画/編集ツール側ユニットが保持するため、本ユニットは「破棄を全経路で起こす契約」を提供する。

6. **上記すべてに対する単体テスト**
   - Vitest で、状態更新アクション・時間再検証・設定分類・ブリッジ反映の入力→期待状態を直接比較するテストを書く。再検証は経路ごとに回帰テストを置く（教訓 5.6）。

### やらないこと

- **ドメインの真実そのものの定義・更新ロジック**: 地物・頂点・リング・錨・ツリーの型と不変条件、コマンドによる状態遷移、アンドゥ/リドゥ二重スタックは U12（コマンド基盤）と基盤ドメインユニットが提供する。本ユニットはそれらを複製せず、ブリッジして参照・通知するに留める。
- **ある時刻における地物の有効状態の算出（時間解決そのもの）**: 「ある時刻に地物が存在するか／その時刻で有効な錨はどれか」を判定する時間解決ロジックは、時間モデル（U02）と錨列ユニットが提供する。本ユニットはその判定関数を呼び出して選択再検証に用いるだけで、半開区間判定や錨列走査を再実装しない（単一の真実源。教訓 §4）。
- **タイムライン UI・スライダー・数値入力欄・再生制御の実装**: これらは React UI 層の別ユニット。本ユニットは現在時刻という状態と、それを更新するアクション、変化時の再検証経路のみを提供する。
- **Canvas 描画そのもの（ワールド↔スクリーン変換・地物バッチ・ヒットテスト）**: 描画は `MapRenderer` 実装（別ユニット）が担う。本ユニットは描画が購読する状態（カメラ・現在時刻・選択・中心経度・描画関連設定）を提供し、購読配線の契約を定めるが、描画ロジックは持たない。
- **設定の永続化 I/O・Zod スキーマ検証・ファイル保存**: 設定の保存形式・スキーマ検証・`.tmap` への書き込みは永続化ユニットが担う。本ユニットは設定の「分類（プロジェクト/アプリ全体）」と「即時反映経路」のみを担い、保存先の物理 I/O は委ねる。
- **競合解決ダイアログ・整合性維持プロセスのロジック**: 本ユニットはそれらが参照する選択・時刻・モードを保持するだけで、検証・解決ロジックは持たない。
- **Electron メイン/preload・IPC**: 本ユニットは renderer 側の状態層であり、IPC 境界には踏み込まない。

## 依存（dependsOn）

- **U12（純粋コマンド基盤とアンドゥ/リドゥ二重スタック）**: ドメイン状態の更新は U12 のコマンド適用・履歴管理を通じて行われ、その結果として「新しいドメイン状態（不変値）」と「コマンド結果（残存/新規/削除 ID・touch 集合）」が得られる。本ユニットのブリッジは、U12 がドメインストアへ反映した新状態を Zustand 側へ伝え、コマンド結果（残存/新規/削除 ID）を用いて選択を再解決する（教訓 5.11）。本ユニットは U12 が公開する「ドメイン状態のルート型・要素 ID 型・コマンド結果型」を前提インタフェースとして参照する。

- **U02（時間モデル(正規化)と暦設定の純粋ロジック）**: 現在時刻は U02 の時間点型（年必須・月日任意の完全値型）で保持する。時刻の前後比較・状態継続判定（半開区間 [start, end)）は U02 の純粋関数を経由し、選択再検証における「選択地物がこの時刻に存在するか」の時間側判定の基盤として用いる（小数年を使わず完全値で受け渡す。FR-70 / FR-72、教訓 5.16）。

実装着手時に、U12 が公開するドメイン状態ルート型・コマンド結果型と、U02 の時間点型・比較/状態継続関数の正確なシグネチャを確認し、本ユニットの型・アクションをそれに整合させること。両ユニットの実装が未完了の場合は、それぞれが公開する境界型（U12: ドメイン状態ルート型・要素 ID 型・コマンド結果型／U02: 時間点型・比較・状態継続判定）を前提インタフェースとして仮定し、その境界に対してブリッジとアクションを組み立てる。地物の「ある時刻における存在判定」は、錨列ユニットが提供する判定関数（U02 の状態継続判定を内部で用いるもの）に委譲する想定とし、本ユニットでは存在判定関数を注入可能な依存（関数インタフェース）として受け取り、再実装しない。

## 実装方針（技術方針に沿う）

技術方針の 1.（採用スタック）・2.3（React は UI シェルに限定し地図描画を再レンダリングから切り離す）・2.5（Zustand ＋ 純粋ドメインコア、`subscribe` ブリッジ、単一の真実源）・2.13（ディレクトリ層分離と依存方向の内向き固定）、開発ガイド §4（単一の真実源・結果状態での判定）に従う。

### 配置と依存方向

- 本ユニットの状態ストア（Zustand）は `ui` 寄りの状態層に配置する。Zustand 自体は `domain` には置かない。`domain`（純粋ドメインコア）は React・Zustand・Canvas を一切 import しない状態を保ち、Vitest 単体で実行できる土台を壊さない（技術方針 2.13、NFR 5.8）。
- 依存方向は `domain` へ内向きに固定する。ブリッジは「外側（状態層）が `domain` を購読する」一方向で構成し、`domain` から状態層・UI・描画への依存を作らない。ドメインストアの通知は、`domain` 内では副作用を起こさず「新しい不変値」と「コマンド結果（touch 集合等の値）」として表現し（U12 の通知規約に整合）、それを外側のブリッジが読み取って Zustand へ反映する。
- Canvas（描画層）は Zustand ストアを購読するのみで、React コンポーネントツリーを介さない。React は周辺 UI（ツールバー・パネル・ダイアログ・タイムライン UI）のみを管理し、地図描画状態を React state に持たせない（技術方針 2.3）。

### ストアの薄さと単一の真実源

- Zustand ストアは UI/セッション状態（選択・モード・現在時刻・カメラ・中心経度・設定）と、ドメイン状態への現在値参照のみを持つ。ドメインの真実を複製しない。これにより「Zustand のコピーとドメインの真実がドリフトする」二重真実源を構造的に排除する（開発ガイド §4 単一の真実源）。
- 同じ派生・同じ判定（例: 頂点選択コンテキストの所有地物導出、ある時刻の存在判定）は一箇所で実装し、描画・選択・プロパティ表示など複数経路が同じ判定を共有する（教訓 5.29 / 5.30、§4）。存在判定は依存ユニットの関数を共有し、本ユニットで別実装しない。

### ブリッジの構成

- ドメインストア（純粋ドメインコアが保持する現在状態）から Zustand への反映は、U12 のコマンド適用結果を入口とする。コマンドが新しいドメイン状態を返したら、ブリッジがそれを Zustand のドメイン参照スロットへ差し替え、購読者へ変化を伝える。
- 反映時には U12 のコマンド結果（残存/新規/削除 ID）を用いて選択状態を再解決する。構造変更操作（結合・分割・移動・削除）の後で固定の全クリアをせず、残る要素 ID・新規要素 ID・削除された ID から選択を再解決する（教訓 5.11）。
- Canvas はブリッジ済み Zustand ストアの該当スライス（カメラ・現在時刻・選択・中心経度・描画関連設定・ドメイン状態参照）を購読し、変化時に命令的に再描画する。React の再レンダリングを介さないことを購読配線の契約として固定する。

### 時間変化時の依存状態の再検証

- 現在時刻を変更するアクションは、時刻を書き換えた「結果状態」で依存状態の再検証を必ず起動する。再検証は次を含む。
  - アクティブ地物が新時刻に存在するか（有効な錨を持つか）を判定し、非存在なら選択解除する（教訓 5.5、FR-71）。存在判定は依存ユニットの関数へ委譲する（半開区間 [start, end) の継続規則は U02／錨列ユニットの単一実装を用いる。FR-55）。
  - 頂点選択セットの各頂点が新時刻の地物形状に存在するかを判定し、非存在分を除去する。結果が空なら頂点選択コンテキストも解消する。
- 再検証の起動条件は「現在時刻が変化した結果状態」とし、時刻を変える全経路（スライダー・数値ジャンプ・錨選択による現在時刻同期 FR-84・再生による自動進行など）が同一の再検証を通ることを保証する（教訓 5.6）。特定経路のフラグでゲートしない。

### 設定の境界と即時反映

- プロジェクト固有設定とアプリ全体設定を別々の型（判別可能な構造）として定義し、各設定キーがどちらに属するかを型・定数で一意に決める（教訓 5.19 分岐識別子はファクトリ/定数経由、5.36 設定境界の先行定義）。
- 設定更新アクションは、対象設定の分類に応じて保存文脈（プロジェクト設定＝プロジェクトデータの一部で dirty 化・保存対象、アプリ全体設定＝アプリレベルの永続化対象）を一貫させる。本ユニットは分類と通知を担い、物理保存は永続化ユニットへ委ねる。
- 設定変更確定時、関連表示へ即時反映するため Zustand 経由で購読者へ通知する（赤道長・グリッド設定→マップ描画、スナップ距離・描画更新頻度・マーカー表示上限→編集/描画挙動）。共有リソース（設定）の更新は依存する全購読者へ通知し、一部購読者の取りこぼしを作らない（教訓 5.35）。

### モード/ツール切替時の一時状態破棄

- モード切替・ツール切替・選択解除の全経路で、一時的 UI 状態（ドラフト・ドラッグ中仮値・選択中の値）が破棄される契約を提供する（教訓 5.2）。本ユニットはその破棄を起動する入口（状態リセットのアクション）を全経路に通し、一時状態の実体保持は描画/編集ツール側に委ねる。
- 表示専用モード（表示モード）では、編集系アクション（選択編集・ツール操作）を同一のモード判定で一括無効化できるよう、モードを状態として一元管理する（教訓 5.13）。個別部品ごとの権限判定を散らさない。

### テスト方針（技術方針 2.14 / NFR 5.8）

- Vitest で、各アクションの「入力状態 → アクション → 期待状態」を直接比較する。
- 時間再検証は、時刻を変える複数経路それぞれについて、選択地物が非存在になるケースで選択解除されること・存在し続けるケースで選択維持されることを経路ごとに回帰テストする（教訓 5.6 / 5.5）。
- 設定分類は、各設定キーが期待どおりプロジェクト/アプリ全体に分類され、保存文脈と即時反映通知が一貫することをテストする。
- ブリッジは、ドメイン状態差し替え時に Zustand 購読者が新状態を観測できること、コマンド結果から選択が再解決されること（固定全クリアでないこと）をテストする。
- 存在判定・時間比較などドメイン側の判定は依存ユニットの関数を注入し、本ユニットで別実装していないことをテストの依存注入で確認する（単一の真実源）。

## 受け入れ基準

以下はすべてテスト可能な形で満たすこと。テストは実装と同時に作成する（開発ガイド 1.9）。

1. **UI/セッション状態が Zustand で薄く管理され、ドメインが React 非依存（技術方針 2.5）**
   - 選択（アクティブ地物・頂点選択セット）・モード・アクティブツール・現在時刻・ズーム/カメラ・中心経度が Zustand ストアで保持される。
   - ドメインの真実（地物・錨・ツリー等）は Zustand に複製されず、純粋ドメインコアが保持する。`domain` 層のモジュールが React・Zustand・Canvas を import しないことを確認できる（`domain` 単独で Vitest 実行が成立する）。

2. **ドメインストアを `subscribe` でブリッジし単一真実源になる**
   - 純粋ドメインコアの状態が新しい不変値へ差し替わると、Zustand を購読する側（React・Canvas を模したテスト購読者）がその変化を観測できる。
   - UI/セッション状態とドメイン状態（の現在値参照）の双方が同一の Zustand 真実源から購読でき、二重真実源（Zustand 側コピーとドメインの真実の乖離）が存在しないことをテストで確認できる。
   - 構造変更操作後（U12 のコマンド結果に削除/新規 ID を含むケース）、選択がコマンド結果から再解決され、固定の全クリアに依存しない（教訓 5.11）。

3. **現在時刻変更時に選択地物の存在を再検証し非存在なら選択解除（教訓 5.5、FR-71）**
   - アクティブ地物が新時刻に存在しない（有効な錨を持たない）場合、現在時刻変更後にアクティブ地物の選択が解除される。
   - アクティブ地物が新時刻にも存在する場合、選択が維持される。
   - 頂点選択セット中で新時刻に存在しない頂点が除去され、結果が空なら頂点選択コンテキストが解消される。
   - 時刻を変える複数経路（スライダー相当・数値ジャンプ相当・錨選択による同期相当・再生自動進行相当）のいずれを通っても同一の再検証が起動することを、経路ごとの回帰テストで確認できる（教訓 5.6）。存在判定は依存ユニットの関数へ委譲し本ユニットで再実装していない。

4. **プロジェクト設定とアプリ全体設定の境界が定義され保存/反映先が一貫（教訓 5.36、FR-109 / FR-110）**
   - 各設定キーが型・定数によりプロジェクト固有（FR-109 列挙項目）かアプリ全体（FR-110 列挙項目）に一意に分類される。
   - プロジェクト設定の更新は保存対象（プロジェクトデータの一部・dirty 化）として扱われ、アプリ全体設定の更新はアプリレベルの永続化対象として扱われる、という保存文脈の一貫性をテストで確認できる。
   - 設定変更確定時、関連表示へ即時反映する通知が購読者へ届く（赤道長・グリッド設定変更でマップ描画購読者へ、スナップ距離・描画更新頻度・マーカー表示上限変更で編集/描画購読者へ）。設定スナップ距離の既定 50px・描画更新頻度の既定 60FPS・タイムライン既定範囲などの既定値が反映される。

5. **Canvas 側は購読のみで React 描画経路に乗らない**
   - Canvas を模したテスト購読者は、Zustand ストアの該当スライス（カメラ・現在時刻・選択・中心経度・描画関連設定・ドメイン状態参照）を購読するだけで変化を受け取れる。
   - 描画駆動状態が React state ではなく Zustand/命令的経路に置かれることを、購読配線の契約（React の再レンダリングを介さずに描画購読者が更新を観測できること）としてテストで確認できる。

## 関連要件（FR-id）

- **FR-64**（must）: 時間軸スライダーで表示対象時間を直感的に変更でき、移動に応じてメインマップ表示が即時に該当時間の状態へ更新される。設定された時間範囲と現在時間を数値表示する。— 本ユニットは「現在時刻」という状態と、それを更新するアクション、変更時に購読者（描画）へ即時反映する経路、時間範囲設定の保持を提供する（スライダー UI 実体は別ユニット）。

- **FR-71**（must）: 時間変更操作に応じて、メインマップ上の全地物の状態を、選択時間における有効な錨に基づいて即時更新する。— 本ユニットは現在時刻変更を購読者へ即時伝播する単一経路を提供し、あわせて時刻に依存する選択状態を再検証する（依存状態の再検証。教訓 5.5）。

- **FR-109**（should）: プロジェクト固有の設定をモーダルで編集でき、赤道長やグリッド設定の変更は関連表示に即時反映する。— 本ユニットはプロジェクト固有設定の状態保持・分類・即時反映通知経路を提供する（編集モーダル UI と永続化は別ユニット）。

- **FR-110**（should）: アプリ全体に適用される設定（共有頂点スナップ距離=既定 50px、描画更新頻度=1〜60FPS・既定 60、全頂点マーカー表示上限）を編集でき、保存後は即時反映する。— 本ユニットはアプリ全体設定の状態保持・分類・即時反映通知経路を提供する。

（関連: FR-79 / FR-80 / FR-81 の選択・頂点選択セット・頂点選択コンテキストの状態保持、FR-75 の追加/編集排他モード、FR-84 の錨選択による現在時刻同期、FR-12 の中心経度シフト、FR-66 のタイムライン時間範囲設定を、本ユニットの UI/セッション状態として保持する。ドメインの真実更新は U12、時間計算は U02 に委ねる。）

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

作業開始前に、以下の関連教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として 1 文以上で宣言してから着手すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **教訓 5.5「依存する状態は変化時に再検証する」**: 「ある状態が変化したら、それに依存する他の状態も検証・更新する。例: 時間が変わったら、選択中要素がその時間に存在するか検証し、なければ選択を解除する。暗黙的ルールはコードで明示的にチェックする。」
  - 適用例: 現在時刻を更新するアクションは、書き換え後の結果状態でアクティブ地物・頂点選択の存在を必ず再検証し、非存在なら解除/整理する。「時刻を変えたら選択を見直す」という暗黙ルールを、専用の再検証関数として明示実装し回帰テストで固定する。

- **教訓 5.6「状態変化の検出は結果状態で判定する」**: 「『ある状態変化が起きたら追加処理を走らせる』検出は、特定の入力経路（呼び出しフラグ・引数の有無）でゲートせず、変異後の結果状態で判定する。同じ状態変化を複数経路が引き起こす場合、特定経路に絞ったゲートは別経路で必ず漏れる。検出: 同じ結果状態を生む他経路を列挙して網羅を確認し、回帰テストを経路ごとに置く。」
  - 適用例: 選択再検証を「スライダー操作のときだけ」など特定経路に紐づけない。スライダー・数値ジャンプ・錨選択による現在時刻同期（FR-84）・再生自動進行のすべてが同一の時刻設定アクションを通り、同一の再検証を起動する。経路を列挙し、各経路の回帰テストを置く。

- **教訓 5.36「プロジェクト設定とアプリ全体設定の境界を先に定義する」**: 「プロジェクト固有設定とアプリ全体設定の境界を先に定義し、保存先と反映先を一貫させる。新規プロジェクト開始時は、表示中データだけでなく、保存先パス・メタデータ・バックアップ対象・dirty 状態・終了確認ガードも、同じ保存文脈として同時に初期化する。」
  - 適用例: FR-109 と FR-110 の各設定キーを型・定数でプロジェクト/アプリ全体に一意分類し、保存文脈（保存対象・dirty 化）と反映先を一貫させる。本ユニットは分類と即時反映通知を担い、保存先パス・dirty 状態・終了確認ガードといった保存文脈の同時初期化は永続化/プロジェクトライフサイクル側ユニットと整合させる（本ユニットの設定分類がその基盤を提供する）。

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」**: 「一時的 UI 状態（描画プレビュー・選択中の値・ドラフト設定）は、開始・確定・キャンセル・ツール切替・モード切替のすべての経路で明示的に破棄する。残ると次回操作へ暗黙に引き継がれ、意図しない値で確定できてしまう。」
  - 適用例: モード切替・ツール切替・選択解除アクションの全経路で一時状態破棄を起動する契約を提供する。「選択→キャンセル→再作成」「選択→確定→再作成」の連続操作で残留が起きないことを検証する。

- **教訓 5.3「操作対象は表示状態に限定する」 / 5.4「追加・編集・複製・結合は現在の UI 文脈を第一候補にする」**: ユーザー操作の対象は表示状態（リアクティブ派生状態）を基準にし、データソース全体を直接検索しない。操作対象は現在の UI 文脈（フォーカス中・選択中・現在時刻・表示中要素）を第一候補にする。
  - 適用例: 頂点選択コンテキストの所有地物導出や、操作対象の決定は、Zustand が保持する選択・現在時刻という表示状態から行い、ドメイン全体の先頭要素や固定デフォルトへ落ちないようにする。先頭要素へ落ちる回帰をテストで防ぐ。

- **教訓 5.11「構造変更操作後の選択は結果から再解決する」**: 「結合・分割・移動・削除のように対象 ID や形状が変わる操作では、完了後の選択状態を固定の全クリアで決めない。コマンド結果が『残る要素 ID』『新規要素 ID』『削除された ID』を返し、UI はその結果から選択を再解決する。」
  - 適用例: U12 のコマンド結果（残存/新規/削除 ID）をブリッジで受け取り、それに基づいて選択を再解決する。次に調整すべき対象が残る操作では選択維持を回帰テストに含める。

- **教訓 5.35「共有リソース更新は全依存先へ通知する」**: 「共有リソースを更新したら、依存する全コンポーネントに変更を通知する。リアクティブ状態やコンテキストは、内部データが常に最新とは限らない前提で設計する。」
  - 適用例: 設定（共有リソース）の更新時、依存する全購読者（描画・編集挙動）へ Zustand 経由で通知し、一部購読者だけが古い設定値を持つドリフトを作らない。

- **横断指針（開発ガイド §4「単一の真実源」「結果状態での判定」）**: 同じ判定・同じ既定値処理は同じ実装を共有する。状態変化の追加処理は結果状態で判定する。
  - 適用例: 「ある時刻の存在判定」「半開区間の継続規則」「境界接触の扱い」は依存ユニット（U02／錨列／幾何ユニット）の単一実装を共有し、本ユニットで別実装しない。Zustand を単一の真実源とし、ドメインの真実を複製しない。

- **横断指針（開発ガイド §4「層をまたぐ契約の固定」、教訓 5.33 / 5.34）**: ブリッジで共有する状態スライスの名前・型・構造は層をまたぐ契約であり、偶然の一致に頼らず共有型・型付きラッパー・両側テストで固定する。Canvas 購読者・React 購読者・状態層が同じスライス契約を参照する。

- **純粋性と層境界の死守（技術方針 2.5 / 2.13）**: ドメインの真実とその更新は `domain` に閉じ、Zustand・React・Canvas を `domain` から import しない。ブリッジは外側から `domain` を購読する一方向で構成する。これを破ると `domain` 単独の Vitest 実行（NFR 5.8）が壊れる。

- **描画は React 再レンダリングに乗せない（技術方針 2.3、NFR 5.1）**: 地図描画状態を React state に持たせると再レンダリングで 60FPS が破綻する。描画駆動状態は Zustand と命令的 Canvas に置き、Canvas は購読のみで描画する規律を設計初期から固定する。本ユニットの状態スライスはこの分離を構造として担保する。

- **時間は完全値で受け渡す（教訓 5.16、FR-70 / FR-72）**: 現在時刻は U02 の完全値型（年・月・日）で保持・受け渡しし、年だけ・小数年などの部分値・中間表現を使わない。時間比較・状態継続判定は U02 の正規化ロジックを経由する。

- **やり残しの記録（開発ガイド §1.8）/ 教訓化（§1.5）**: 本ユニットで保留した判断（存在判定関数の注入インタフェース確定・設定保存文脈の永続化ユニットとの接続など、後続へ波及するもの）は現状.md に記録する。新たに根本原因を教訓化すべき事象があれば開発ガイド §5 へ追記してから完了とする。

## 目的

末端地物をナイフツールで **2 つに分割** する操作の全体（事前の対象面選択 → 分断線入力 → 分割可能検証 → 分割実行 → 継承先選択 → 整合性維持プロセスへの受け渡し）を実装する（FR-44、FR-90〜FR-93）。

ユーザーは編集モードで分割対象の末端地物を選び（地図全体を薄いオーバーレイで覆い対象面を強調表示）、線情報追加と同じ操作感で分断線を入力する。分断線は開いた線（対象面の境界をまたいで貫く）でも閉じた線（最初の分割点を中心とする画面固定円の内側をクリックして閉じる）でもよい。確定時に「各分割結果が最低 3 頂点の有効なポリゴンを形成できるか」を検証し、成立しなければ日本語エラーを表示して分割を行わない。分割成立時は、片方が元地物の同一性を保ち（プロパティ継承先）、もう片方が新規末端地物として生成される。継承先はモーダルダイアログで選択し、非継承側のプロパティは面情報追加時の入力フローを再利用して入力する。一連の操作は **不可分の 1 操作・1 アンドゥ単位** として記録し（FR-94）、分割前の共有頂点関係を継続し（FR-95）、確定後は整合性維持プロセス（U13）の競合解決へ遷移する。

本ユニットは、分割の幾何ロジック（対象面の分断・リング再編・共有頂点継続の写像生成）を `domain` 層の純粋関数として実装し、対象面選択・オーバーレイ強調・分断線プレビュー・固定円・継承先選択モーダルの描画と入力受け取りを `render`／`ui` 層に実装する。分割の確定は `domain` の純粋コマンドとして発行し、整合性維持プロセス（U13）へ編集案として引き渡す。

## スコープ

### やること

- **ナイフツールのモード／インタラクションフロー**（FR-90、開発ガイド §5.7/§5.8）
  - 編集モードでナイフツールを起動できる。起動後の段階を「対象面選択 → 分断線入力 → 確定（分割可能検証）→ 継承先選択 → 非継承側プロパティ入力 → 整合性維持へ受け渡し」の明示的なステートマシンとして実装する。各段階に対し開始・進行・確定・キャンセル・ツール切替・モード切替の全経路で一時状態を破棄する（開発ガイド §5.2/§5.7/§5.8）。
- **対象面選択とオーバーレイ強調**（FR-90）
  - ナイフツール起動中、地図全体を薄い半透明オーバーレイで覆う。クリックで対象とする末端地物を 1 件選び、選択された対象面はオーバーレイの上に強調表示（明確なアウトライン・対象であることが分かる塗り）する。対象は末端地物に限る（後述「分割対象の制約」）。対象未選択の間は分断線入力を開始できない。
- **分断線入力（線情報追加と同じ操作感）**（FR-90、FR-92）
  - クリックで分断線の頂点を順に置く。追加中の分断線は確定済み地物と異なるスタイルで仮表示する。最後に置いた頂点を 1 つずつ取り消せ（Ctrl+Z 等）、分断線入力全体をキャンセルできる（Escape 等）。グリッドスナップをオプションで利用できる。これらは面・線追加ツールと同じ操作感・同じ補助機能を共有する（FR-76〜FR-78 の追加時共通機能と整合。実体は依存ユニット U23/U24 の入力フローを再利用する。後述「依存」）。
  - 分断線の点配置に幾何制約は課さない（FR-90「分断線の点配置に制約はなく」）。成立可否は確定時の検証で判定する。
- **閉線分割（固定円）**（FR-92）
  - 分断線入力中、最初の分割点を中心に **画面固定サイズ**（ズーム非依存。FR-17 と同じスクリーン座標一定サイズの考え方）の円を表示する。
  - 3 点以上入力した状態で円内をクリックすると分断線を閉じ、閉線分割として扱う。閉じる形状は最初の点へ戻る任意の閉じた多角形でよく、円形には限定しない（FR-92「任意の閉じた形状、円形に限定しない」）。固定円は「閉じてよい」ことを示すヒット領域・視覚ガイドであって、閉じる形状そのものではない。
  - 操作ガイド文（例: 対象面を選択／分断線を引いて貫いてください／3 点以上で中心の円をクリックすると閉じます 等、いずれも日本語）を画面上に表示する（FR-92、FR-115）。
- **分割可能検証（確定時）**（FR-90、FR-44）
  - 分断線確定時に、対象面を分断線で 2 分割した結果が「各末端地物が最低 3 頂点で有効なポリゴンを形成する」ことを検証する（FR-44）。成立しない（一方が 3 頂点未満／面が貫かれず 2 片に割れない／自己交差等で不正形状になる）場合は分割を行わず、日本語エラーメッセージを表示する（FR-90「成立しなければエラー表示」、FR-115）。
  - 検証は UI の入力時可否表示だけでなく、コマンド確定前にも同じドメインサービスで再検証する（開発ガイド §5.26）。拒否理由はユーザー通知用メッセージとテスト可能な戻り値の両方で返す。
- **分割の幾何実行（2 分割）**（FR-44、FR-90）
  - 対象末端地物の形状（外周リング・穴リング・飛び地リングを含むリング集合）を、開いた分断線または閉じた分断線で 2 つのポリゴンへ分割する純粋関数を実装する。面のブーリアン演算は polygon-clipping へ委譲し（技術方針 2.8）、演算前後で座標量子化と不変条件再検証を行う（技術方針 R2、開発ガイド §5.22）。集合演算は複数片・複数リングを返す前提で全片を扱う（開発ガイド §5.1）。
- **穴・飛び地・リング再編**（FR-91）
  - 分断線が **穴リングを横切る** 場合、その穴リングは 2 分割され、各分割で生じた新ポリゴンの **外周リングへ合流** する（穴の片割れがそれぞれの新ポリゴンの外形を欠く形になる）。
  - 横切られた穴の **内部にあった飛び地**（穴の中にネストしていた領土リング）は、親リングを **一段上げた飛び地** となる（穴が消えて外周直下の飛び地へ昇格する）。
  - 分断線に **横切られなかったリング** の親子（ネスト）関係は維持し、横切られなかったリングはそれを内包する側のポリゴンへそのまま帰属する（FR-91「横切られなかったリングの親子関係は維持」）。
  - リング階層は再編後も「領土リング→穴リング→領土リング→…」の交互不変条件を満たすこと（FR-24）を再編内で保証・検証する（U07 の検証へ委譲）。
- **共有頂点の継続**（FR-95、U11 連携）
  - 分割で形状が作り直される際、分割前に対象面が持っていた共有頂点関係を、新しく生成された対応頂点へ引き継ぐ。分断線が **共有辺の途中** を横切る場合は、共有相手地物の対応辺にも同座標の頂点を挿入し、切断点と共有頂点関係に入れる。これらの継続規則は U11 が提供する純粋関数（対応写像による引き継ぎ・共有辺途中切断時の同座標頂点挿入）へ委譲し、本ユニットは「旧頂点 ID → 新頂点 ID（または複製先）」の対応写像と分断線の切断点情報を生成して渡す（FR-95、開発ガイド §5.11/§5.20）。
- **継承先選択モーダル**（FR-93）
  - 分割確定後、分割結果のプロパティ継承先を選ぶモーダルダイアログを画面中央に表示する。**分割結果の小さい方**（面積が小さい側）をプレビューで囲んで示し、各結果を継承先として選ぶボタンを提供する。ボタン選択時に該当側をハイライトする。確定ボタンで継承先を確定する。
  - 継承先に選ばれた側は **元地物の同一性を保ったまま** 形状変化として続き、もう片方（非継承側）は新規末端地物として生成される（FR-44）。
- **非継承側のプロパティ入力（追加フロー再利用）**（FR-93）
  - 非継承側のプロパティ入力は、面情報追加時の入力フォーム／フロー（名称・種別ラベル・色・存在期間等。FR-76／FR-97）を **再利用** する。本ユニットはこのフローを新規に作らず、依存ユニット（U23）が提供する追加入力フローを呼び出す（開発ガイド §5.30 過少共有の戒め）。
- **不可分・1 アンドゥ単位での確定と整合性維持への受け渡し**（FR-94、FR-44、FR-93）
  - 「継承先側の形状更新＋非継承側の新規地物生成＋共有頂点継続＋（FR-91 のリング再編）」を 1 つの編集案（または 1 コマンド）として束ね、整合性維持プロセス（U13）へ引き渡す。確定後は U13 の固定順序（時間整合性検証 → 空間競合検出 → 競合解決 → 一括確定）に従い、競合があれば競合解決モーダルへ遷移する（FR-61〜FR-63）。一連は単一のアンドゥ・リドゥ操作の対象とする（FR-94／FR-73）。
- **新規地物の上位領域初期継承**（FR-44 と整合）
  - 非継承側の新規末端地物の上位領域（親）は、元末端地物の上位領域を初期継承する（穴あけによる新地物生成 FR-45 の親継承と同型の扱い。分割は同一親の下で兄弟になるのが自然）。継承先側は元の親子関係を保持する。
- **テスト**（技術方針 5.5、開発ガイド §1.9）
  - 分割幾何・リング再編・共有頂点継続の対応写像生成は `domain` の純粋関数として Vitest 単体テストで「入力状態 → 期待結果状態」を検証する。リング階層交互性・末端 3 頂点・分割の不可分性は fast-check のプロパティテストで生成入力により検証する（技術方針 5.5）。インタラクションのステートマシン（対象選択 → 分断線 → 継承先 → 確定／各経路のキャンセル）は E2E で検証する。

### やらないこと

- **競合検出・競合解決アルゴリズム本体**（FR-61〜FR-63）: U13（整合性維持オーケストレーション）および U10（空間競合検出）・U06（差分ブーリアン調整）の責務。本ユニットは分割確定の編集案を U13 へ渡し、競合解決モーダルの駆動は U13 が返す構造化データに委ねる。本ユニットは「分割が確定したら U13 の競合解決へ遷移する」接続のみを担う。
- **アンドゥ／リドゥの二重スタック実装・コマンド適用機構**（FR-73／FR-74）: 別ユニットの責務。本ユニットのコマンドは純粋関数（状態 → 新状態）として実装し、1 アンドゥ単位へ束ねられる形に従うが、スタック管理そのものは行わない。
- **面情報追加の入力フォーム本体**（FR-76／FR-97）: U23 の責務。本ユニットは非継承側プロパティ入力でそれを再利用する（新規作成しない）。
- **線情報追加ツールの入力本体**（FR-19／FR-76）: U24 の責務。本ユニットは分断線入力で同じ操作感・同じ補助機能（頂点取り消し・キャンセル・グリッドスナップ・仮表示）を再利用する。
- **共有頂点システムの中核ロジック**（FR-30〜FR-33）: U11 の責務。本ユニットは継続規則の純粋関数を U11 から呼ぶのみ（対応写像・切断点情報を渡す側）。
- **集約地物の分割**: 集約地物は直接分割できない（FR-44「集約地物は直接分割できない」）。本ユニットは集約地物を分割対象から除外する（後述「分割対象の制約」、開発ガイド §5.25）。集約地物の形状は下位領域の和として導出されるため、分割は末端地物に対してのみ意味を持つ。
- **穴あけによる新地物生成**（FR-45）・**所属変更フロー**（FR-46〜FR-49）・**合体（結合）**（FR-50〜FR-52）: いずれも別概念・別ユニット。分割と事前条件・フローを混同しない（開発ガイド §5.27）。
- **リング/線形の幾何妥当性検証本体**（自己交差・ゼロ長エッジ、U06）・**穴飛び地階層検証本体**（U07）・**末端地物排他検証本体**（U10）: 本ユニットはこれらの検証サービスを呼ぶのみ。
- **描画層の地物バッチ描画・ヒットテスト基盤本体**（FR-17 一定サイズ表示・MapRenderer 契約）: `render` 層の基盤は別ユニット。本ユニットはオーバーレイ・分断線プレビュー・固定円・ハイライトの描画をその基盤の上に追加する。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが提供する型・サービス・フローを前提として実装する。依存ユニットの公開インタフェース（関数名・引数・戻り値型）は偶然の一致に頼らず共有型・両側テストで固定する（開発ガイド §5.33／§5.34）。依存ユニットが未実装の場合は、本仕様に記す入出力契約に沿った型インタフェースを先に定義し、その型へ向けて実装と単体テストを進める。

- **U24 — 線情報追加ツール／線入力インタラクション**: 分断線入力の「クリックで頂点を順に置く」「最後の頂点を取り消す」「全体キャンセル」「グリッドスナップ」「追加中の仮表示」といった操作感・補助機能を提供する。本ユニットの分断線入力はこの入力コンポーネント／フローを再利用し、面・線追加と同じ操作感（FR-76〜FR-78）を共有する。本ユニットは線入力の確定結果（分断線の頂点列）を受け取って分割幾何へ渡す。
- **U11 — 共有頂点システム**: 分割時の共有関係の継続規則（分割前の共有関係を新頂点へ引き継ぐ対応写像転写、共有辺途中切断時の共有相手地物への同座標頂点挿入）を純粋関数として提供する（FR-95）。本ユニットは対応写像と切断点情報を生成し U11 の継続関数へ渡す。頂点の値オブジェクト＋ID 参照モデル（U03 由来）も U11 を通じて扱う。
- **U13 — 整合性維持プロセスの骨格（固定順序オーケストレーション）**: 分割確定の編集案を受け取り、時間整合性検証 → 空間競合検出 → 競合解決 → 一括確定の固定順序で処理する（FR-61〜FR-63）。本ユニットは分割の編集案を組み立てて U13 へ渡し、U13 が返すプロセス結果（確定済み／競合あり・要方針指定／拒否）に従って UI を駆動する。分割の不可分性（FR-94）は U13 経由の単一コマンド確定で満たす。
- **U23 — 面情報追加の入力フロー／プロパティ入力フォーム**: 非継承側の新規末端地物のプロパティ入力（名称・種別ラベル・色・存在期間等。FR-76／FR-97）に再利用する追加入力フローを提供する。本ユニットはこのフローを呼び出し、入力結果を新規地物の初期プロパティに反映する。

> dependsOn に明記されないが、本ユニットの分割幾何・検証は **U06**（幾何述語・座標量子化・ブーリアン演算ラッパ）、**U07**（リング階層モデルと不変条件検証）、**U10**（末端地物排他検証）、**U03**（ドメイン型・ID・頂点値オブジェクト）の各サービス／型に依存する。これらは分割可能検証・リング再編の交互性検証・分割結果の排他検証で呼ぶ。委譲先が未提供でも本ユニットの単体テストが成立するよう、結果検証は **注入可能な検証関数（バリデータ群）への委譲** として実装する（U11 と同型の方針）。

## 実装方針（技術方針に沿う）

技術方針（`docs\技術方針.md`）に従い、層を厳密に分離する。分割の幾何・検証・編集案生成は `domain` 層の純粋関数・イミュータブル更新（Immer、技術方針 2.6）として実装し、Electron／React／Canvas に依存させない。対象面選択・オーバーレイ・分断線プレビュー・固定円・継承先選択モーダルの描画と入力は `render`／`ui` 層に置き、`domain` の純粋関数を呼ぶ。判別共用体で不正状態を表現不能にする（技術方針 2.1）。

### 1. インタラクションのステートマシン（`ui`／セッション状態）

ナイフツールの進行を明示的なステートマシンとして実装する。状態（判別共用体）は最低限以下を持つ。

1. `対象面選択中`: オーバーレイ表示。クリックで末端地物を 1 件選ぶ。対象未選択では次へ進めない。
2. `分断線入力中`: 対象面が選択済み。U24 の線入力を再利用して分断線頂点列を蓄積。最初の点を中心とする固定円を表示。3 点以上で円内クリックにより閉線へ。ガイド文表示。
3. `継承先選択中`: 分割成立（検証通過）後。継承先選択モーダル表示（小さい方プレビュー）。
4. `非継承側プロパティ入力中`: U23 の追加入力フローを再利用。
5. `整合性維持へ受け渡し済み`: 編集案を U13 へ渡し、結果に従い競合解決モーダルまたは確定へ。

各状態から開始・進行・確定・キャンセル・ツール切替・モード切替の全経路で一時状態（オーバーレイ・分断線ドラフト・固定円・選択中継承先・プレビュー）を破棄する（開発ガイド §5.2「一時的 UI 状態は全経路で破棄する」、§5.7「完了トリガーを必ず実装する」、§5.8「押下→移動→解放を全パスで保証する」）。`domain` のドメイン真実は確定（U13 経由のコマンド確定）まで破壊更新しない（開発ガイド §5.22）。一時状態は Zustand のセッションストア側に置き、Canvas は購読のみで React 再レンダリングサイクルに乗せない（技術方針 2.3／2.5）。

### 2. 分割対象の制約（末端地物限定）

分割対象は **末端地物に限る**（FR-44「集約地物は直接分割できない」）。対象面選択で集約地物をクリックしても対象にしない（または選べないことを案内する）。これを「対称性確保」「自然な拡張」を理由に集約地物へ広げない（開発ガイド §5.25）。対象範囲を広げたくなったら本節と FR-44 を引用して止める。

### 3. オーバーレイ・分断線・固定円の描画（`render`）

- オーバーレイは地図全体を薄い半透明で覆う。対象面はオーバーレイの上に強調アウトライン＋塗りで描く。穴領域は透過、飛び地は独立領域として描く（FR-21）。
- 分断線は確定済み地物と異なるスタイルで仮表示する（FR-78 の追加時仮表示と同様）。閉線確定後は閉じた形状として表示する。
- 固定円は **ズーム非依存の画面固定サイズ**（FR-17 と同じスクリーン座標一定サイズの考え方。ワールド→スクリーン変換で半径をスクリーン px 一定に保つ）。
- ガイド文は画面上に常時表示し、現在のステートに応じて文面を切り替える（日本語、FR-92／FR-115）。
- **入力を受ける層の設計**（開発ガイド §5.14）: オーバーレイ・固定円・モーダルのバックドロップなど重なる UI は、描画順だけでなく入力を受ける層も同時に設計する。透明オーバーレイが対象面選択クリックや分断線クリックを奪わないよう、ヒットテストの優先順位（オーバーレイは対象選択クリックを通す／固定円は閉線ヒット領域として機能する 等）を明示し、重なった状態で期待操作が通ることをテストする。

### 4. 分断線による 2 分割（`domain`、polygon-clipping 委譲）

対象末端地物のリング集合（外周・穴・飛び地）と分断線（開いた頂点列または閉じた頂点列）を入力に、2 つのポリゴンへ分割する純粋関数を実装する。

- **開いた分断線**: 対象面の外周（および横切られる穴・飛び地）を貫く分断線で領域を 2 片へ割る。分断線は対象面の境界の外から外へ抜けて初めて領域を 2 分割しうる。割れない（貫いていない）入力は分割可能検証で拒否する。
- **閉じた分断線**: 閉じた多角形の内側を一方、外側を他方として 2 片に割る。閉領域が対象面の内部に完全に収まる場合は「内側＝新ポリゴン、外側＝残り（穴を持つ側）」となり、閉領域が境界をまたぐ場合は対象面と閉領域の交差・差分で 2 片を求める。
- 面のブーリアン演算は polygon-clipping へ委譲する（技術方針 2.8）。演算入力前に座標を固定スケールの整数格子へ量子化し、演算後に不変条件（自己交差なし・ゼロ長エッジなし・リング階層交互性・末端 3 頂点）を再検証する（技術方針 R2、開発ガイド §5.22）。
- **複数片対応**（開発ガイド §5.1）: ブーリアン演算は複数ポリゴン・複数リングを返しうる。分割は結果が「ちょうど 2 つの領域グループ」に分かれることを要件とするが、各グループ自体が複数領土リング（飛び地）や穴を含みうる。返却された全片を漏れなく 2 グループのどちらかへ正しく帰属させ、片落とし（先頭片のみ採用）をしない。
- **世界端ラップ**（技術方針 R3）: 対象面・分断線が世界端（±360 度境界）をまたぐ場合、ワールドラップ展開（±360 度オフセット複製）してから演算する座標正規化を経る。経度は連続スカラーで保持し、ラップ正規化を `domain` の専用関数で処理する（ライブラリ任せにしない）。

### 5. リング再編（FR-91）

分割で生じた 2 ポリゴンへ、対象面の各リングを次の規則で帰属・再編する。

- **横切られた穴リング**: 穴リングが分断線で 2 分割される場合、各片はそれぞれの新ポリゴンの **外周リングへ合流** する（穴の片割れが新ポリゴンの外形の凹みとして取り込まれる）。
- **横切られた穴の中の飛び地**: その穴の内部にネストしていた領土リング（飛び地）は、親穴が消えるため **親リングを一段上げた飛び地** になる（外周直下の飛び地へ昇格）。
- **横切られなかったリング**: 横切られなかった穴・飛び地・ネストは親子関係を維持し、それを内包する側のポリゴン（包含判定で決定）へそのまま帰属する（FR-91）。
- 再編後、リング階層が「領土→穴→領土→…」の交互不変条件（FR-24）を満たすことを U07 の検証で確認する。違反する再編結果は分割を拒否する（開発ガイド §5.26）。包含判定・親子の付け替えは U07 のリング階層モデルを用い、本ユニットで独自実装しない（過少共有の戒め、開発ガイド §5.30）。
- 階層を辿る付け替えは、壊れたデータ（循環・親子不整合）でも無限ループしないよう visited セットで再入を遮断する（開発ガイド §5.28）。

### 6. 共有頂点の継続（FR-95、U11 委譲）

- 分割で頂点が作り直されるため、「旧頂点 ID → 新頂点 ID（または複製先）」の対応写像を生成し、U11 の継続関数へ渡して共有関係を新頂点へ転写する。
- 分断線が **共有辺の途中** を切る場合は、切断点座標（量子化整合）と共有辺の識別情報を U11 へ渡し、共有相手地物の対応辺に同座標頂点を挿入させ、切断点と共有関係に入れる（FR-95）。挿入後に U11 側で参加制限・結果不正検証が走る前提とし、本ユニットはその結果（拒否を含む）を受けてフローを止める。
- 生成する新頂点 ID はコマンド結果へ記録し、redo で再採番しない（開発ガイド §5.20）。

### 7. 継承先選択と非継承側プロパティ入力（FR-93）

- 分割成立後、2 ポリゴンの面積（FR-20 の面積計算ロジックを使用。技術方針 2.9 の自前測地モジュール）を比較し、**小さい方** をプレビューで囲って継承先選択モーダル（画面中央）を表示する。各結果を継承先に選ぶボタン＋選択時ハイライト＋確定ボタンを備える。
- 継承先に選ばれた側は元地物の同一性（地物 ID・既存の錨列・親子関係）を保ち、形状だけが分割後の形状へ変化する。非継承側は **新規末端地物**（新規地物 ID）として生成し、上位領域は元末端地物の上位領域を初期継承する（FR-44 と整合）。
- 非継承側のプロパティ入力は U23 の面情報追加入力フローを再利用する。新規にフォームを作らない（開発ガイド §5.30）。入力結果を新規地物の初期プロパティ（名称・種別ラベル・色・存在期間）へ反映する。
- **UI 文脈の優先**（開発ガイド §5.3／§5.4）: 継承先・非継承側の決定は「いま画面で選択・操作している対象面と分割結果」を第一候補にし、コレクションの先頭や固定デフォルトに落とさない。
- **判断用メッセージの保持**（開発ガイド §5.12）: 分割可能検証の拒否メッセージは、発生元と無関係なクリックで即時消去しない。消す契機は「分断線の再入力」「明示的な閉じる」「分割成功」など意味を持つイベントに限定する。

### 8. 編集案の組み立てと整合性維持への受け渡し（FR-94／FR-44）

- 「継承先側の形状更新＋非継承側の新規地物生成＋リング再編＋共有頂点継続」を 1 つの編集案として組み立て、U13 へ渡す。編集案は当該時刻の完全状態スナップショット（形状・属性・親子関係・存在状態）を一体として扱い、部分確定を許可しない（FR-59 と整合）。
- U13 が固定順序（時間整合性検証 → 空間競合検出 → 競合解決 → 一括確定）で処理し、競合があれば競合解決モーダルへ遷移する（FR-61〜FR-63）。確定は単一の不可分コマンド（1 アンドゥで全復元、FR-94）として記録される。
- コマンド結果として「残る地物 ID（＝継承先）」「新規地物 ID（＝非継承側）」「変更頂点 ID 集合」を返し、確定後の選択状態は結果から再解決する（開発ガイド §5.11）。
- コマンドの execute／undo／redo は touch した全地物・全頂点へ対称に通知する（開発ガイド §5.23）。確定直後に手動リフレッシュを書きたくなったら通知漏れのサイン。

### 9. 移動制約・衝突は確定整合性側に寄せる（技術方針 R5／R9）

分断線入力中のリアルタイム判定は近傍候補のみの軽量判定とし、フルの分割可能検証・排他検証は確定時に実行する二段戦略に整合させる（技術方針 R5／R9）。分割の幾何・検証は副作用のない純粋関数として書き、計測で 100ms 級が問題化した場合に限り Web Worker へ移設できるよう外部 I/O・グローバル状態への依存を持たせない（技術方針 R9）。

### 成果物・公開インタフェース（型レベルの契約）

実装者は以下の概念を型として定義すること（名称は実装で確定してよいが、契約の意味は固定）。

- **分断線（KnifeLine 相当）**: 頂点列と「開いた／閉じた」種別を持つ不変値。閉じた場合は最初の点へ戻る閉多角形として解釈する。
- **分割可能検証結果（判別共用体）**: `分割可能`（2 ポリゴンの幾何と各リング再編の見積もりを含む）／`分割不可`（拒否種別＝貫通せず／3 頂点未満／不正形状 等、日本語メッセージ、機械可読詳細）。
- **分割結果（SplitResult 相当）**: 2 つのポリゴン形状（リング集合）と、各々の面積、旧→新頂点 ID 対応写像、共有辺途中切断点情報、リング再編の記録（昇格した飛び地・合流した穴片）を持つ不変値。
- **継承先選択（InheritanceChoice 相当）**: どちらのポリゴンを継承先（元地物の同一性継続）とするかの選択。
- **分割編集案（SplitEditProposal 相当）**: 継承先側の形状更新と非継承側の新規地物生成（初期プロパティ・初期親）を一体に持ち、U13 へ渡す不変値。

公開する主関数（概念、すべて `domain` 純粋関数）:

- 分割可能検証: `(対象末端地物の状態, 分断線) → 分割可能検証結果`。
- 分割実行: `(対象末端地物の状態, 分断線) → 分割結果`（検証通過を前提。リング再編・対応写像・切断点を含む）。
- 編集案生成: `(分割結果, 継承先選択, 非継承側プロパティ) → 分割編集案`。

## 受け入れ基準（テスト可能な形で列挙）

各項目は自動テスト（`domain` は Vitest 単体／fast-check プロパティ、インタラクションは E2E）で検証可能であること。

1. **対象面選択＋オーバーレイ強調＋分断線で 2 分割（FR-90）**: ナイフツール起動で地図全体が薄いオーバーレイで覆われ、クリックした末端地物が対象として強調表示される。対象未選択では分断線入力を開始できない。線情報追加と同じ操作感（クリックで頂点追加・最後の頂点取り消し・全体キャンセル・グリッドスナップ・仮表示）で分断線を入力し、対象面を貫く分断線を確定すると対象末端地物が 2 つに分割される。（E2E + `domain` 単体: 単純な凸ポリゴン＋貫通分断線で 2 ポリゴンになることを assert）
2. **穴を横切る場合のリング再編（FR-91）**: 分断線が穴リングを横切る入力で、(a) 穴リングが 2 分割され各新ポリゴンの外周へ合流する、(b) その穴の内部にあった飛び地が親を一段上げた飛び地になる、(c) 横切られなかったリング（別の穴・飛び地・ネスト）は親子関係を維持し正しい側のポリゴンへ帰属する、ことを `domain` 単体で検証する。再編後にリング階層の交互性（FR-24）が保たれることを U07 検証で確認する。
3. **閉線分割（固定円・3 点以上で円内クリック）とガイド文（FR-92）**: 分断線入力中、最初の点を中心とする画面固定サイズ（ズーム非依存）の円が表示される。3 点以上入力した状態で円内をクリックすると分断線が閉じ、閉線分割として扱われる（2 点以下では閉じない／円外クリックは頂点追加として扱われる）。閉じる形状は円形に限定されず任意の閉多角形でよい。各ステートに対応する日本語ガイド文が画面上に表示される。（E2E: 3 点 + 円内クリックで閉線確定、2 点 + 円内クリックでは閉じないことを確認。ズーム変更で円の画面サイズが一定であることを確認）
4. **分割可能検証（各末端最低 3 頂点）と不可時エラー（FR-90／FR-44）**: 分割結果の一方が 3 頂点未満になる分断線、または対象面を貫かず 2 片に割れない分断線、自己交差等で不正形状になる分断線に対して、分割が実行されず日本語エラーが表示される。検証はコマンド確定前にも同じドメインサービスで行われ、拒否理由が機械可読な戻り値と日本語メッセージの両方で返る。（`domain` 単体: 各拒否種別で `分割不可` を返すこと。E2E: エラー表示）
5. **継承先選択モーダル＋小さい方プレビュー、非継承側は追加入力フロー再利用（FR-93）**: 分割確定後、画面中央に継承先選択モーダルが表示され、分割結果の小さい方（面積比較）がプレビューで囲まれる。継承先を選ぶボタンと選択時ハイライト、確定ボタンが機能する。継承先側は元地物の同一性（地物 ID・錨列・親子）を保ち形状のみ変化し、非継承側は新規末端地物として生成され、そのプロパティ入力に面情報追加の入力フロー（U23）が再利用される。非継承側の上位領域は元末端地物の上位領域を初期継承する。（E2E + `domain` 単体）
6. **不可分 1 操作・1 アンドゥ・共有頂点継続・確定後に競合解決へ（FR-44／FR-94／FR-95／FR-61〜63）**:
   - 分割確定（継承先側更新＋非継承側生成＋リング再編＋共有頂点継続）が U13 経由の単一コマンドとして記録され、1 回のアンドゥで分割前状態へ完全復元される（コマンドが 2 個以上に割れない）。
   - 分割前に対象面が他地物と共有していた頂点関係が、分割後の新頂点へ引き継がれる。分断線が共有辺の途中を切る入力では、共有相手地物の対応辺に同座標頂点が挿入され共有関係に入る（U11 の継続関数が呼ばれることを検証）。
   - 分割確定後、整合性維持プロセス（U13）の固定順序へ編集案が渡され、空間競合があれば競合解決モーダルへ遷移する。
7. **集約地物は分割できない（FR-44、開発ガイド §5.25）**: 集約地物を対象面選択でクリックしても分割対象にならない（対象にできないことが案内される）。分割幾何・編集案生成が集約地物を受け取らないことを `domain` 単体で固定する。
8. **一時状態の全経路破棄（開発ガイド §5.2／§5.7）**: 「対象選択 → キャンセル → 再起動」「対象選択 → 分断線途中 → ツール切替 → 再起動」「分割確定 → 継承先選択でキャンセル → 再起動」など各経路でオーバーレイ・分断線ドラフト・固定円・選択中継承先・プレビューが残らず、次回操作へ暗黙に引き継がれないことを E2E で検証する。
9. **不変条件のプロパティテスト（技術方針 5.5）**: fast-check で、ランダム生成した末端地物（穴・飛び地・ネストを含む）と分断線に対し、分割が成立する入力では (a) 結果 2 ポリゴンの各末端が最低 3 頂点・有効ポリゴン、(b) リング階層が領土→穴交互（FR-24）、(c) 分割前後で対象面のリング集合に含まれていた領域の総和が（量子化誤差の範囲で）保存される（領域の取りこぼし・重複なし）、(d) 操作が拒否された場合は状態が操作前と完全一致（部分適用なし、FR-94）、を生成入力で検証する。

## 関連要件（FR-id）

本ユニットが充足する要件（`coversRequirements`）と、検証・連携で関与する近接要件を示す。

- **FR-44**（must）: 末端地物をナイフツールで 2 分割。継承先指定で一方は同一性継続、もう一方は新規生成。集約地物は直接分割不可。各末端は最低 3 頂点。
- **FR-90**（must）: 対象面選択＋地図全体の薄オーバーレイで対象強調、線情報追加と同じ操作感で分断線入力、点配置に制約なし、確定時に分割可能検証、不成立はエラー表示。
- **FR-91**（should）: 分断線が穴リングを横切る場合の穴 2 分割と外周合流、穴内飛び地の親一段上げ、横切られないリングの親子維持。
- **FR-92**（should）: 分断線入力中、最初の点中心の画面固定円、3 点以上で円内クリックにより閉線分割（任意の閉形状）。操作ガイド文表示。
- **FR-93**（should）: 継承先選択モーダル（中央、小さい方プレビュー、継承先ボタン＋ハイライト、確定）。非継承側は面情報追加の入力フロー再利用。その後整合性維持の競合解決へ。
- **FR-94**（must）: 分割は不可分の 1 操作として履歴記録・通知・整合性検証を一括完了し、1 アンドゥで復元。
- **FR-95**（should）: 分割前の共有頂点を新頂点へ引き継ぎ、共有辺途中切断時は共有相手へ同座標頂点を挿入して共有関係を継続。

関与する近接要件（本ユニットは委譲・連携の形で関与し、実装本体は別ユニット）:

- FR-20〜FR-24（リング・穴・飛び地・交互不変条件、面積計算）、FR-26（末端地物排他、U10）、FR-45（穴あけ新地物の親初期継承と同型の扱い）、FR-59（完全状態の一体編集）、FR-61〜FR-63（整合性維持・競合解決、U13）、FR-73（複合操作の単一アンドゥ単位）、FR-76〜FR-78（追加時共通機能・仮表示・頂点取り消し・キャンセル・グリッドスナップ、U24／U23）、FR-97（基本属性・色情報、U23）、FR-115/FR-117（日本語エラー）。技術方針 2.8（polygon-clipping）、R2（量子化・不変条件再検証）、R3（世界端ラップ）、R5/R9（二段戦略）。

## 注意点・既知の落とし穴（開発ガイドの教訓）

着手前に開発ガイド §1.6 の作業開始ゲートに従い、下記の該当教訓を引用し適用宣言してから実装すること。

- **§5.25 仕様が限定した対象範囲を実装で広げない**: 分割対象は末端地物に限る（FR-44）。「集約地物も和形状を分ければ自然」等の理由で集約地物へ広げない。広げたくなったら本書「分割対象の制約」と FR-44 を引用して止める。
- **§5.1 集合演算は複数片を返す前提で扱う**: 分割のブーリアン演算は複数ポリゴン・複数リングを返しうる。返却された全片を 2 グループへ漏れなく帰属させ、先頭片のみ採用といった片落としをしない。検出: 結果が複数片になる入力（穴・飛び地を含む対象面）で全片が出力に現れることをテストする。
- **§5.2 一時的 UI 状態は全経路で破棄する**: オーバーレイ・分断線ドラフト・固定円・選択中継承先・プレビューは、開始・確定・キャンセル・ツール切替・モード切替の全経路で破棄する。残ると次回操作へ暗黙に引き継がれる。検出: 受け入れ基準 8 の各連続操作を E2E で確認する。
- **§5.7 完了トリガーを必ず実装する**: 分断線確定・閉線確定・継承先確定・非継承側入力確定の各「完了」トリガーを UI から必ず呼ぶ。ロジック側に関数があっても UI からの呼び出しがなければ機能しない。
- **§5.8 押下→移動→解放シーケンスを全パスで保証する**: 対象面選択・分断線頂点クリック・閉線円内クリックは、クリック（移動なし）とドラッグの両パスで状態が正しく開始・更新・終了することを保証する。押下で立てた状態は解放で必ず解除する。
- **§5.14 重なる UI は入力を受ける層も同時に設計する**: 薄オーバーレイ・固定円・モーダルのバックドロップは描画順だけでなく入力層も設計する。透明オーバーレイが対象選択・分断線クリックを奪わないようヒット優先順位を明示する。検出: 重なった状態で期待操作が通ることをテストする。
- **§5.11 構造変更操作後の選択は結果から再解決する**: 分割は対象 ID・形状が変わる。確定後の選択は全クリアで決めず、コマンド結果（残る地物 ID＝継承先・新規 ID＝非継承側・削除 ID）から再解決する。
- **§5.20 元に戻す情報は依存データも含めて過不足なく保存する**: 分割で生成する新頂点 ID・新規地物 ID・旧→新対応写像・リング再編記録をコマンド結果に保存し、redo で再採番しない。共有関係復元に必要な依存データを過不足なく持つ。
- **§5.22 確定まで共有データを破壊的に更新しない**: 分割可能検証を通り、U13 で全競合解決と確定が済むまで、対象面のドメイン真実を破壊更新しない。検証用の仮形状で成立を確認してから反映し、失敗時は追加した要素を全ロールバックして操作前状態へ戻す。
- **§5.23 execute/undo/redo は対称に通知する**: 分割コマンドは touch した全地物（継承先・新規・共有相手）・全頂点へ対称に通知する。確定直後の手動リフレッシュを書きたくなったら通知漏れのサイン。イベント発火テストは期待集合の厳密一致で検証する。
- **§5.26 編集制約はコマンド確定前にも同じサービスで検証する**: 分割可能検証（各末端 3 頂点・不正形状なし）と排他検証は、UI の入力時可否表示だけでなくコマンド確定前にも同じドメインサービスで再検証する。ショートカット・メニュー・直接呼び出し・undo/redo から不正状態が入らないようにする。拒否理由は通知用メッセージとテスト可能な戻り値の両方で返す。
- **§5.27 結合と所属変更は事前条件を分けて検証する**: 分割は結合・所属変更とは別概念。事前条件（対象が末端地物・分断線が貫く・各末端 3 頂点）を、結合（2 つ以上選択・上位下位関係でない 等）や所属変更（循環参照防止 等）の条件と混同しない。
- **§5.30 過少共有と過剰共有の両方を戒める**: 分断線入力の操作感は U24、非継承側プロパティ入力は U23、共有継続は U11、リング階層判定は U07 と、既存の単一実装を共有する（過少共有の戒め）。一方で、分割固有の検証（各末端 3 頂点・穴横切り再編）は他操作と規則が異なるため安易に畳まない（過剰共有の戒め）。
- **§5.32 多層に波及する変更は最大 2 層に分割する**: 分割は domain（幾何・編集案）・render（オーバーレイ・固定円）・ui（ステートマシン・モーダル）・U11/U13/U23/U24 連携と多層に及ぶ。1 単位に詰めず影響経路を分割して進め、宣言外の層へ及びそうなら別タスクへ切り出す。
- **§5.33／§5.34 層をまたぐ契約は型と両側テストで固定する**: U11／U13／U23／U24 および U06／U07／U10 への委譲契約（関数名・引数・戻り値構造）は共有型で import し両側テストで固定する。依存未実装時は本仕様の入出力契約に沿った型を先に定義する。
- **§5.38 移動制約は線分交差で判定し、衝突検出と応答を分ける**: 分断線が対象面・リング・共有辺を「横切る／貫く」判定は、点の内外だけでなく分断線分が境界を横切るかを線分交差で判定する。穴横切り・共有辺途中切断の判定も同様に線分交差で行う。
- **量子化と数値誤差**（技術方針 R2）: 分割のブーリアン演算前後で座標を固定格子へ量子化し、ゼロ長エッジ・自己交差・極小スリバーを演算後の不変条件再検証で弾く。浮動小数の厳密一致に頼らない。共有辺途中切断の挿入点座標も量子化に整合させる。
- **世界端ラップ**（技術方針 R3）: 対象面・分断線が世界端をまたぐ場合、ワールドラップ展開してから演算する座標正規化を専用関数で処理する。経度は連続スカラーで保持し、ライブラリ任せにしない。
- **クリーンルーム原則**（開発ガイド §3.1）: 本書および実装に、過去版・他プロダクト・「従来」等の外部参照を持ち込まない。制約は本アプリ要件として直接記述する。

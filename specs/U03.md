# U03 ドメイン型(判別共用体)・ID・頂点値オブジェクト

本書は実装ユニット U03 の実装指示書である。実装者（別エージェント）はこの指示書だけを読んで着手できる。クリーンルーム文書であり、過去版・他プロダクト・外部の既存実装には一切言及しない。必要な制約はすべて本アプリ（time-map-app-4）自身の要件・方針として直接記述する。根拠とする要件 ID は FR-NN 形式で示す（要件定義書を典拠とする）。

---

## 目的

`domain` 層の中核となるデータ型を、TypeScript の判別共用体（discriminated union）と値オブジェクトで定義する。この型定義が後続の全ユニット（ジオメトリ演算・時間モデル・階層モデル・コマンド／履歴・永続化・描画・UI）の共通語彙となる。

本ユニットの最重要目的は、**不正状態を「型レベルで表現不能」にする**ことである。具体的には次の不変条件を、実行時チェック以前にコンパイル時に保証する。

- 集約地物は形状属性を保持しない（集約地物に形状を代入するコードがコンパイルエラーになる）。
- 地物は「点情報 / 線情報 / 末端地物 / 集約地物」のいずれか 1 つに必ず分類され、網羅性チェック（exhaustiveness）が効く。
- リングは「領土リング / 穴リング」のいずれか 1 つに分類され、網羅性チェックが効く。
- 頂点は値オブジェクトであり、ID 参照によって複数オブジェクト間の共有を表現する（座標の重複保持で共有を表さない）。
- 最上位フラグが真であることと上位領域を持たないことが同値であることを、なるべく型で表現する。

加えて、衝突しない ID 生成サービスと、地物の基本属性（名前・年代）・色情報の型を提供する。

## スコープ

### やること

1. **ID 型（ブランド型）の定義**
   - 頂点 ID・地物 ID・リング ID・歴史の錨 ID・共有頂点グループ ID など、ドメインで参照に用いる ID をすべて「公称的（nominal）」なブランド型として定義する。素の `string` と相互代入できないようにし、ID の取り違えをコンパイル時に防ぐ。

2. **ID 生成サービス**
   - タイムスタンプ単独に依存せず、同一ミリ秒内でも衝突しない ID を生成するサービスを提供する。
   - 既存 ID 集合に対する重複検査（生成した ID が既存と衝突していないことの確認）を行うインタフェースを備える。

3. **頂点（値オブジェクト）**
   - 頂点 ID と座標（ワールド座標）を持つイミュータブルな値オブジェクトとして定義する。
   - 共有は ID 参照で表現する（複数のリング／線形が同一頂点 ID を参照することで共有頂点を表す）。
   - 等価性は属性値比較で定義する（ID と座標の一致）。
   - 変更系メソッド（`withXxx` 系）を全属性について網羅的に提供する。

4. **リングの判別共用体**
   - 「領土リング」「穴リング」を判別共用体として定義する。
   - リングは頂点 ID の順序付き配列（頂点配列ではなく ID 参照配列）で形状を表す。
   - リング階層（親リング参照）を表す構造を定義し、「領土→穴→領土→…」の交互制約をなるべく型で表現する（完全な型表現が困難な部分は実行時不変条件として明示する）。

5. **地物の判別共用体**
   - 「点情報」「線情報」「末端地物」「集約地物」を判別共用体として定義する。
   - 点情報: 単一頂点 ID への参照を持つ。
   - 線情報: 順序付き頂点 ID 配列（パス）を持つ。
   - 末端地物: 形状（領土リング・穴リングからなるリング集合）を持つ。
   - 集約地物: **形状属性を型として持たない**（下位領域参照のみを持ち、形状は実行時に下位領域の和として算出される）。

6. **基本属性・色情報の型**
   - 基本属性: 名前、年代（開始年・終了年）の型。
   - 色情報: 自動配色許可フラグ、塗り色、選択時色、境界色の型。

7. **網羅性チェック用ユーティリティ**
   - 判別共用体の網羅漏れをコンパイル時に検出する `assertNever` 相当のヘルパーを提供する。

8. **値オブジェクト／エンティティのイミュータブル設計規約の確立**
   - 状態変更は新インスタンスを返す。
   - `withXxx` 系メソッドを全属性について網羅する（後述の落とし穴を参照）。

### やらないこと

- ジオメトリ演算（距離・面積・大円距離・ブーリアン演算・自己交差判定・包含判定）の実装は行わない（別ユニット）。本ユニットは型定義のみ。
- 集約地物の形状算出（下位領域の和の計算）そのものは実装しない。本ユニットでは「集約地物が形状属性を型として持たない」ことを保証するに留める。算出ロジックは階層／ジオメトリのユニットが担う。
- 歴史の錨の時間軸ロジック（錨列の昇順管理・時間重複解消・正規化）は実装しない（別ユニット）。本ユニットでは錨 ID と「錨が地物の完全状態スナップショットである」という構造の型枠を定義するに留める。なお、本ユニットが定義する地物型・属性型・色情報型・形状（リング集合）型・親子関係参照は、錨が保持する「完全状態スナップショット」の構成要素である。
- ツリー位相操作（分裂・穴あけ・所属変更・合体）、整合性維持プロセス、競合解決、アンドゥ／リドゥの実装は行わない（別ユニット）。型がそれらの土台となるよう設計する。
- 永続化（シリアライズ／デシリアライズ／スキーマ検証）の実装は行わない（別ユニット）。ただし本ユニットの型はプレーンデータへ写像可能な構造（後述）にしておく。
- 描画・UI に関する型は定義しない（`domain` 層に閉じる）。

## 依存（dependsOn）

- **U01** に依存する。U01 は `domain` 層を含むディレクトリ構成・`tsconfig`（strict 全有効）・lint・テスト基盤（Vitest／fast-check）など、本ユニットの型を配置・コンパイル・テストするための土台を提供する。U01 が確立した `domain` ディレクトリ（フレームワーク非依存・純粋）の中に本ユニットの成果物を置くこと。
- U01 が確立した依存方向（`domain` へ内向き固定）に従い、本ユニットの型は React・Electron・Canvas・描画ライブラリ等を一切 import しない。`domain` 単独で Vitest 実行できる状態を保つ。

## 実装方針（技術方針に沿う）

技術方針の採用スタックに従う。

- **言語**: TypeScript（strict 全有効）。`strict` / `noUncheckedIndexedAccess` / `exactOptionalPropertyTypes` / `noImplicitOverride` を前提に書く。
  - `noUncheckedIndexedAccess` を前提に、頂点 ID 配列・リング配列へのインデックスアクセスは `undefined` の可能性を型で受け止める（後述の落とし穴）。
  - `exactOptionalPropertyTypes` を前提に、任意属性は「キーが無い」と「値が undefined」を取り違えない。

- **判別共用体による不正状態の排除**: 地物（点／線／末端／集約）とリング（領土／穴）を判別共用体で表す。各バリアントは判別タグ（`kind` 等の単一のリテラル判別子）を持つ。網羅性は `assertNever` ヘルパーで担保する。集約地物のバリアントには形状属性のフィールドを定義しないことで、「集約地物に形状を代入する」コードを型エラーにする（FR-35 の型表現）。

- **イミュータブル設計**: ドメインの値オブジェクト／エンティティはイミュータブル。状態変更は新インスタンスを返す `withXxx` 系で行い、全属性について網羅する。等価性は属性値比較で定義する（教訓 5.17）。

- **頂点の値オブジェクト化・ID 参照共有**: 頂点を値オブジェクトとし、共有は ID 参照で表す（技術方針 R6）。リングや線形は頂点インスタンスを直接埋め込まず、頂点 ID の配列を保持する。頂点の実体は地物から独立した頂点ストア（ID → 頂点 の写像）で管理する前提の型を用意する（ストアの操作実装は本ユニットでは最小限のイミュータブルな読み書きヘルパーに留め、空間インデックス連携や近接スナップは別ユニット）。

- **ID 生成（教訓 5.37）**: ID 生成サービスを経由する。ミリ秒精度タイムスタンプ単独に依存させず、単調増加カウンタや乱数等を併用し、かつ「既存 ID 集合との重複検査」を行う API を提供する。タイムスタンプはシステム時刻ではなく、生成サービスが一元管理する時刻源／カウンタから取得する（教訓 5.15 の趣旨）。

- **純粋・副作用なし**: ID 生成サービスを除き、型・値オブジェクトの操作は純粋関数とする。ID 生成も「現在の ID 集合（または採番状態）を引数で受け取り、新 ID と更新後の採番状態を返す」純粋な形を基本とし、グローバル可変状態に暗黙依存しない（テスト容易性。NFR 5.8）。redo 時に ID を採番し直さず初回生成 ID を復元できる設計余地を残す（教訓 5.20）。

- **プレーンデータへの写像可能性**: 値オブジェクトをクラスで実装する場合でも、ネストした値を再帰的にプレーン形式へ／から変換できる構造にしておく（永続化・履歴ユニットが利用。教訓 5.20 / 5.31）。クラスのメソッドにロジックを閉じ込めすぎず、判別タグと素のフィールドで状態が表現されるようにする。

### 想定する型構成（実装者向けの指針。名称・配置は U01 の規約に合わせ調整可）

以下は実装の指針であり、最終的なファイル名・型名は U01 が確立した命名・配置規約に従って調整してよい。ただし「集約地物が形状を持たない」「頂点は ID 参照で共有」「判別共用体で網羅性が効く」という性質は必ず満たすこと。

- ID 型: 各 ID をブランド型で定義（頂点 ID・地物 ID・リング ID・錨 ID・共有頂点グループ ID）。
- 座標: ワールド座標（正距円筒前提の連続スカラー経度を含む内部表現。経度は周期境界をまたぐ連続値として保持しうる。技術方針 R3 を踏まえ、座標型自体は連続スカラーを許容する）。
- 頂点（値オブジェクト）: `{ id: 頂点ID; 座標 }`。`withXxx` 系を網羅。
- リング（判別共用体）: 領土リング `{ kind: 'territory'; id; vertexIds: 頂点ID[]; parentRingId?: リングID }` ／ 穴リング `{ kind: 'hole'; id; vertexIds: 頂点ID[]; parentRingId: リングID }`。穴リングは必ず親（領土リング）を持つ点を型に反映する（穴は最外周にはなれない）。
- 形状（末端地物の持つもの）: 領土リング・穴リングの集合。階層は parentRingId 参照で表す。
- 基本属性: `{ name: string; startYear; endYear }`（年代の型は U01／時間ユニットと整合）。
- 色情報: `{ autoColorEnabled: boolean; fillColor; selectedColor; borderColor }`（FR-97）。
- 地物（判別共用体）: 共通フィールド（地物 ID・基本属性・色情報・種別ラベル等）＋ バリアント固有フィールド。
  - 点情報: `{ kind: 'point'; ...; vertexId: 頂点ID }`
  - 線情報: `{ kind: 'line'; ...; vertexIds: 頂点ID[] }`
  - 末端地物: `{ kind: 'leaf'; ...; shape: 形状 }`（形状＝リング集合を持つ）
  - 集約地物: `{ kind: 'aggregate'; ...; childIds: 地物ID[] }`（**`shape` を持たない**。下位領域参照のみ）
- 最上位フラグと上位領域の同値: 親子関係の表現を「上位領域 ID（任意）」を持つ形とし、最上位フラグを独立に冗長保持せず、`parentId` の有無から最上位を一意に導出する（または両者を別個に持つことを型レベルで禁止する。後述）。
- 種別ラベル: 任意文字列（表示専用、整合性検証に関与しない。FR-40）。
- 網羅性ヘルパー: `assertNever(x: never): never`。

## 受け入れ基準（テスト可能な形で列挙）

各基準は Vitest／fast-check／TypeScript の型検査（`tsc --noEmit` および型レベルテスト）で機械的に検証できる形で満たすこと。型エラーになるべきコードは、専用の型テスト（コンパイルが失敗することを確認する仕組み、または `@ts-expect-error` を用いた負例）で固定する。

1. **判別共用体と網羅性**
   - 点情報・線情報・末端地物・集約地物が判別共用体で定義され、判別タグによる分岐で網羅性チェックが効く（全バリアントを処理しない `switch` が `assertNever` でコンパイルエラーになる）。
   - 領土リング・穴リングが判別共用体で定義され、同様に網羅性チェックが効く。
   - 検証: 全バリアントを処理する `switch` がコンパイルでき、1 バリアントを欠いた `switch` が型エラーになる負例テストを置く。

2. **集約地物に形状を代入できない（FR-35 の型表現）**
   - 集約地物の値に形状属性（`shape` 等）を代入・設定するコードが型エラーになる。
   - 検証: 集約地物へ形状を渡す負例に `@ts-expect-error` を付し、それが正しくエラーになることを型テストで確認する。集約地物バリアントには形状フィールドが存在しないことを型レベルで固定する。

3. **頂点が値オブジェクトで ID により共有を表現できる**
   - 頂点はイミュータブルな値オブジェクトであり、等価性が属性値比較（ID・座標の一致）で定義される。
   - 複数のリング／線形が同一頂点 ID を参照することで共有を表現でき、頂点インスタンスの重複埋め込みでは共有を表さない。
   - 検証: 同一値の 2 頂点が等価判定で真になるテスト、異なる座標で偽になるテスト、同一頂点 ID を 2 つのリングが参照する構造を構築でき頂点ストアからの解決が一意になるテスト。

4. **ID 生成が同一ミリ秒でも衝突せず既存重複検査を行う（教訓 5.37 適用）**
   - ID 生成サービスが、同一ミリ秒内で連続生成しても重複しない ID を返す。
   - 生成サービスが既存 ID 集合との重複検査を行い、衝突しない ID を返す（既存集合に偶然含まれる候補を避ける／検出する）。
   - 検証: 時刻源を固定（同一ミリ秒に固定）して大量生成し、生成 ID 集合に重複が無いことを確認するテスト。既存 ID 集合を与えて生成し、結果が既存と衝突しないことを確認するテスト。fast-check で「任意個数を任意順で生成しても全 ID が一意」をプロパティ検証する。

5. **イミュータブル設計で `withXxx` 系の網羅が型で担保される（教訓 5.17 適用）**
   - 値オブジェクト／エンティティの状態変更は新インスタンスを返し、元インスタンスを破壊しない。
   - 全属性について `withXxx` 系メソッド（または同等の更新 API）が網羅されている。
   - 検証: `withXxx` が新インスタンスを返し元が不変であることのテスト。各属性に対応する更新 API が存在することを型／テストで固定する（属性集合と更新 API の対応を機械的に突き合わせるテストを置く）。

6. **最上位フラグと親なしの同値**
   - 「最上位である」ことと「上位領域を持たない」ことが同値になるよう型で表現する（最上位フラグと親 ID を矛盾して同時保持できる状態を作れない、または最上位を親 ID の有無から一意に導出する API のみを公開する）。
   - 検証: 親 ID 無し → 最上位、親 ID 有り → 非最上位、が常に成り立つテスト。両者が矛盾する値を構築しようとすると型エラーまたは構築不能になることを負例テストで確認する。

7. **リング階層の交互制約をなるべく型で表現**
   - 穴リングは必ず親（領土リング）参照を持ち、最外周になれないことを型に反映する（穴リングの `parentRingId` を必須にする）。完全に型で表現しきれない交互性（領土→穴→領土→…）は、実行時不変条件として検証できる述語を定義し、その述語をテストで固定する。
   - 検証: 穴リングを親無しで構築するコードが型エラーになる負例テスト。交互性述語が、正しい階層で真・交互が崩れた階層で偽を返すテスト。

8. **基本属性・色情報の型**
   - 名前・年代（開始年・終了年）を持つ基本属性型、自動配色許可フラグ・塗り色・選択時色・境界色を持つ色情報型が定義され、地物の共通フィールドとして参照できる（FR-97）。
   - 検証: 各地物バリアントが基本属性・色情報を保持することを型・構築テストで確認する。

9. **`domain` 単独でコンパイル・テストできる**
   - 本ユニットの型・サービスが React／Electron／Canvas／描画ライブラリを import せず、`domain` 単独で `tsc --noEmit` と Vitest が緑になる。
   - 検証: 依存方向の lint（U01 で確立）に違反しないこと、`domain` 配下のテストが単独実行で緑になることを確認する。

## 関連要件（FR-id）

本ユニットがカバーする要件:

- **FR-18**: 点情報（単一頂点に紐づく位置・プロパティ・視覚的表現）の型を定義する。
- **FR-19**: 線情報（複数頂点のパス・プロパティ・視覚的表現）の型を定義する。長さ計算自体は別ユニット。
- **FR-20**: 面情報（閉じたパス＝リング構造、穴・飛び地・ネスト対応）の型を定義する。面積計算自体は別ユニット。
- **FR-34**: 面情報の親子関係（森構造）の参照を型で表現する。最上位（親なし）の概念を含む。
- **FR-35**: 集約地物が形状属性を保持しないことを型レベルで保証する（本ユニットの最重要事項）。集約地物が直接追加されない／全下位領域喪失で消滅する等の振る舞いは別ユニットだが、その土台となる「形状なし・下位領域参照のみ」の型を提供する。
- **FR-38**: 階層深度を地物自身に保持せず親子関係から算出できるよう、地物型に階層深度フィールドを持たせない（派生値であることを型構造で表す）。算出ロジック自体は別ユニット。
- **FR-40**: 種別ラベル（任意・表示専用・整合性検証に関与しない）の型を定義する。
- **FR-97**: 基本属性（名前・年代＝開始年/終了年）と色情報（自動配色許可フラグ・塗り色・選択時色・境界色）の型を定義する。

参考にする関連概念（直接の実装責務は別ユニットだが整合させる）: 共有頂点（FR-30〜FR-33。本ユニットは ID 参照共有の土台のみ）、歴史の錨（FR-54。錨 ID と完全状態スナップショットの構成要素を提供）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の教訓を引用し「適用:」として今回の判断を宣言してから実装すること（開発ガイド 1.6 AI 作業開始ゲート）。

- **教訓 5.17（イミュータブルなエンティティ/値オブジェクトの設計）**
  「状態変更は新インスタンスを返し、等価性は属性値比較で定義する。変更系メソッド（withXxx 等）を導入する際は、全属性について必要なメソッドが網羅されているか洗い出し、サブクラスが追加状態を持つ場合は基底メソッドのオーバーライド要否を検討する。」
  - 適用: 頂点・地物・リング・基本属性・色情報のすべてで `withXxx` を全属性網羅し、属性追加時に更新 API の追加漏れが起きないよう、属性集合と更新 API の対応をテストで固定する。地物の判別共用体では各バリアント固有属性についても更新 API を網羅する。

- **教訓 5.37（ID 生成はタイムスタンプ単独に依存しない）**
  「ID 生成はミリ秒精度タイムスタンプだけに依存すると、同一ミリ秒内で衝突する。ID 生成サービスを経由し、既存データとの重複検査を行う。」
  - 適用: ID 生成サービスにカウンタ／乱数等を併用し、既存 ID 集合との重複検査 API を備える。同一ミリ秒固定での重複なし生成をテストで固定する。

- **教訓 5.25（仕様が限定した対象範囲を実装で広げない）**
  「ドメインの基本ルールが仕様で対象を明示的に限定しているとき、実装で『対称性確保』『自然な拡張』を理由に対象範囲を広げない。」
  - 適用: 排他性は末端地物同士のみ（FR-26 / FR-27）、集約地物は形状を持たない（FR-35）といった限定を型に正しく反映し、「集約地物にも形状を持たせれば自然」といった拡張をしない。型の段階で集約地物に形状フィールドを足さない。

- **教訓 5.18（空配列・空オブジェクトは真値である）**
  - 適用: 「子を持たない（空配列）」「リングを持たない」状態を論理和の短絡で誤判定しない。集約地物が下位領域 0 件かどうか、リング集合が空かどうかは、配列長や明示的な状態で判定する型・述語にする。

- **教訓 5.19（分岐識別子は型定義・定数・ファクトリを経由する）**
  - 適用: 判別タグ（点／線／末端／集約、領土／穴）は文字列リテラルの直書きで判定せず、型定義と定数／ファクトリ経由で扱う。大文字小文字差で分岐が変わらないよう、判別子はリテラル型で固定する。

- **教訓 5.20（元に戻す情報は依存データも含めて過不足なく保存する）**
  - 適用: 値オブジェクトはプレーン形式へ／から再帰変換できる構造にし、ID は redo 時に採番し直さず初回生成 ID を復元できる形（生成と保持の分離）にする。本ユニットでは復元ロジックは実装しないが、型がそれを妨げないようにする。

- **その他の落とし穴**
  - `noUncheckedIndexedAccess` により、`vertexIds[i]` や `rings[i]` は `T | undefined` 型になる。インデックスアクセス結果を非 null と決めつけず、`undefined` を型で受け止める（境界外参照の握り潰しをしない）。
  - `exactOptionalPropertyTypes` により、`parentId?: 地物ID` のような任意フィールドは「キー無し」と「値 undefined」を区別する。任意属性の取り違えに注意する。
  - 頂点を ID 参照で共有する設計のため、頂点インスタンスをリング／線形へ直接埋め込む実装をしない（共有が壊れる）。頂点の実体は頂点ストア（ID → 頂点）に一元管理し、リング／線形は ID のみを持つ。これにより共有頂点ドラッグ時の連動（別ユニット）の土台が成立する。
  - 集約地物の形状は「下位領域の和」として実行時に算出される派生値である（FR-35）。本ユニットでは集約地物に形状フィールドを置かず、形状解決は別ユニットの単一の解決判定に委ねる（教訓 5.29 の趣旨：派生形状は単一の解決判定で全経路を動かす）。本ユニットの型がこの将来の単一解決を妨げないようにする。
  - 階層深度（FR-38）は派生値であり地物自身に保持しない。地物型に `depth` 等のフィールドを置かない（保持すると親子関係とのドリフトが生じる）。
  - 最上位フラグと親 ID を独立した 2 つの可変フィールドで持つと不一致（FR-39 違反）が型で許容されてしまう。最上位は親 ID の有無から導出する、または両者の矛盾する組み合わせを構築できない型設計にする。

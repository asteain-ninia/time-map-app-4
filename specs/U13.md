# U13 整合性維持プロセスの骨格(固定順序オーケストレーション)

## 目的

ユーザーが歴史の錨を追加・編集して確定しようとした際に走る「時間的・空間的整合性維持プロセス」の骨格を、純粋なオーケストレーションとして実装する。本ユニットは、編集案生成から一括確定までを **固定順序のパイプライン** として束ね、各ステップ（時間整合性検証・空間競合検出・差分ブーリアン調整・単一アンドゥ単位での適用）を下位ユニットへ委譲する調停役に徹する。

このユニットは「決められた順序で正しい部品を正しい入力で呼び、競合があれば確定を止めて構造化された競合情報を返し、全競合に解決方針が指定されたら一括で確定する」という制御フローを、副作用のない純粋関数として `domain` 層に閉じ込めることを目的とする。幾何演算・時間正規化・空間判定の具体アルゴリズムは下位ユニットが担い、本ユニットはそれらを保持・実装しない。

## スコープ

### やること

- 錨追加/編集確定時の **固定順序オーケストレーション** を実装する。順序は以下のとおりで、入れ替え・並べ替えを許さない（FR-61）。
  1. 編集案生成（編集対象の地物・錨について、確定したい完全状態スナップショットを 1 つの編集案として組み立てる）
  2. 錨の時間整合性検証（U09 へ委譲）
  3. 空間競合検出（U10 へ委譲）
  4. 競合解決（解決方針の収集 → 差分ブーリアン調整は U06 へ委譲）
  5. 解決適用と一括確定（単一アンドゥ単位として U12 で確定）
- 編集制約（自己交差・全体重複・階層破綻・禁止条件）を、**コマンド確定前にも同じ検証サービスで再検証** し、違反時は確定せず拒否理由を構造化して戻り値で返す（教訓 5.26）。
- 空間オーバーラップ（地図全体の末端地物同士の重なり）が検出された場合、**検出された全競合箇所** を構造化リストとして返す。各競合は少なくとも次を含む（FR-62）。
  - 競合が成立する作中時間（時間点）または時間範囲
  - 関連する地物の識別情報と表示名（双方の末端地物）
  - 競合種類（本ユニットのスコープでは「末端地物同士の空間オーバーラップ（末端重なり）」を扱う）
- 解決方針（優先地物 + もう一方を差分ブーリアン調整）を受け取り、適用できること（FR-63）。
- **全競合に解決方針が指定されるまで確定しない** こと（部分確定の禁止）と、適用後の結果全体を **単一のアンドゥ・リドゥ操作の対象** とすること（FR-63 / FR-73）。
- プロセスの状態を機械可読な戻り値（後述「成果物・公開インタフェース」）として返し、UI 層（競合解決モーダル）がそれを参照してダイアログを駆動できるようにする。

### やらないこと

- 競合解決モーダルダイアログそのものの描画・ミニマッププレビューの描画（UI 層の責務。本ユニットは UI が必要とする構造化データのみを供給する）。
- 時間整合性検証アルゴリズムの実装（U09 の責務。本ユニットは結果を受けて分岐するだけ）。
- 空間競合検出アルゴリズム・空間インデックスの実装（U10 の責務。本ユニットは末端地物同士のペア重なりを「検出してもらう」立場）。
- ブーリアン差分演算そのものの実装（U06 の責務。本ユニットは「優先地物・調整対象・調整種別」を渡して結果を受け取るだけ）。
- アンドゥ・リドゥの二重スタック実装・コマンド適用機構の実装（U12 の責務。本ユニットは「ひとまとまりの変更を 1 アンドゥ単位として確定してほしい」と依頼するだけ）。
- ドラッグ中のリアルタイム衝突判定・エッジ滑り（FR-28 / FR-89）。本ユニットは「操作確定時のフル整合性」側であり、ドラッグ中の軽量判定は別ユニットの責務。
- 末端地物以外（集約地物・線情報・点情報）への空間排他制約の付与。排他検証は末端地物同士のみを対象とする（FR-26 / FR-27、教訓 5.25）。

## 依存(dependsOn)

本ユニットは以下を呼び出す。いずれも `domain` 層の純粋関数・純粋サービスとして提供される前提で、本ユニットはそれらのインタフェース契約に依存する（実体の差し替えはインタフェースで吸収する）。

- **U09 — 錨の時間整合性検証**: 編集案に含まれる錨について、錨列の昇順・時間的非重複・有効期間が正であること等（FR-54〜FR-59）を検証する。戻り値は「合格」または「拒否理由（時間制約違反の構造化情報）」を返すものとして扱う。
- **U10 — 空間競合検出**: 編集案を適用した結果状態に対し、地図全体の末端地物同士のペア重なり（FR-26）を検出する。戻り値は「競合なし」または「競合箇所リスト（時間・地物ペア・重なり領域など）」を返すものとして扱う。
- **U06 — ブーリアン差分調整**: 優先地物と調整対象（もう一方の末端地物）を渡し、調整対象から優先地物との重なり領域を差し引いた新形状を返す。集合演算が複数片を返しうる前提で扱う（教訓 5.1）。
- **U12 — 単一アンドゥ単位（コマンド/履歴）**: 編集案の確定＋全競合解決の結果を、1 回のアンドゥで復元できる単一のコマンド（不可分の 1 操作）として確定する（FR-73 / FR-94）。

> 依存ユニットの公開インタフェース（関数名・引数・戻り値型）は、偶然の一致に頼らず共有型・両側テストで固定する（教訓 5.33）。本ユニットの実装者は、各依存ユニットの公開型を import し、契約をコンパイル時に固定すること。依存ユニットがまだ未実装の場合は、本仕様に記す入出力契約に沿った型インタフェースを先に定義し、その型に対してオーケストレーション骨格と単体テストを実装する。

## 実装方針(技術方針に沿う)

- **配置層**: `domain` 層（フレームワーク非依存・純粋）に置く。Electron / React / Canvas に一切依存させず、Vitest 単独で実行できること。整合性維持・競合解決は純粋関数として実装し、計測で 100ms を超えると判明した場合に限り後から Web Worker へオフロードできるよう、副作用のない関数として書く（技術方針 4. R9、リスク表）。
- **純粋関数・イミュータブル**: 入力ドメイン状態を破壊的に変更しない。確定前は共有データを破壊更新しない（教訓 5.22）。プロセスは「現在のドメイン状態 + 編集案 + （あれば）解決方針集合」を入力に取り、「次状態（確定時）」または「保留中プロセス状態（競合あり・要方針指定）」または「拒否（理由つき）」を返す判別共用体で表現する。不正状態を表現不能にする（技術方針 2.1）。
- **固定順序の明示的表現**: パイプラインの各ステップを順に呼ぶ単一のオーケストレータ関数として実装し、順序が一読で追えるようにする。途中ステップが拒否/競合を返したら、後続ステップへ進まず即座にその結果を返す（早期リターン）。順序のハードコードはテストで固定する（後述）。
- **編集案生成の一体性**: 属性のみの編集であっても、内部では当該錨の完全状態（形状・属性・所属・親子関係）を一体の編集案として扱い、部分確定を許可しない（FR-59）。編集案は「どの地物のどの錨を、どの完全状態に置こうとしているか」を表す不変の値オブジェクトとする。
- **確定前の制約再検証（教訓 5.26）**: UI が候補を隠していても、ショートカット・メニュー・直接呼び出し・undo/redo 経路から不正状態が入りうる。よって時間整合性検証（U09）と空間競合検出（U10）はこのオーケストレーション内（＝コマンド確定前）で必ず通す。拒否理由は、ユーザー通知用メッセージ（日本語、FR-115）と、テスト可能な機械可読フィールドの両方を戻り値に含める。
- **全競合解決の強制**: 競合箇所ごとに「解決方針が指定済みか」を判定し、未指定の競合が 1 つでも残る間は確定段階へ進ませない。全競合に方針が揃って初めて、各方針で U06 の差分調整を適用 → 調整後状態で U10 の空間競合検出を再実行 → 残競合ゼロを確認 → U12 で一括確定、と進む。差分調整が新たな競合を生む可能性に備え、再検出で残競合があれば再びプロセス状態として返す（収束ループはオーケストレータが管理し、上限到達時は拒否を返す）。
- **集合演算の複数片対応（教訓 5.1）**: U06 の差分調整結果は複数ポリゴン・複数リングを返しうる。返却された全片を調整対象の新形状へ反映し、先頭片のみ採用といった片落としをしない。
- **末端地物限定（教訓 5.25）**: 空間競合の対象は末端地物同士のみ。集約地物・線・点を排他対象に含めない。検出を U10 へ委譲する際も、この対象範囲が広がっていないことを契約・テストで固定する。
- **単一アンドゥ単位（FR-73 / FR-94）**: 編集案確定 + 全差分調整 + 自動生成（あれば）を、U12 を通じて不可分の 1 コマンドとして記録する。途中で別アンドゥ単位に割れないことを保証する。U12 のコマンドは execute / undo / redo が対称に通知される前提とする（教訓 5.23）。
- **無限横スクロール対応**: 空間競合検出・差分調整は世界端をまたぐ面を含みうる。座標の周期境界ラップ正規化は U10 / U06 側で処理される前提とし、本ユニットは時間・地物ペアの取り回しに専念する（技術方針 4. R3）。本ユニットは経度を連続スカラーのまま受け渡し、独自にラップ処理を行わない。
- **エラー処理**: すべての拒否理由・例外は捕捉し、日本語のユーザー向けメッセージへ写像する。重大な内部不整合（依存ユニットからの想定外戻り値など）は「開発者へ報告してください」案内付きのメッセージとして扱う（FR-115 / FR-117）。

### 成果物・公開インタフェース（型レベルの契約）

実装者は以下の概念を型として定義すること（名称は実装で確定してよいが、契約の意味は固定）。

- 編集案（EditProposal 相当）: 対象地物 ID・対象錨の時刻・確定したい完全状態スナップショット（形状・属性・親子関係・存在状態）を持つ不変値。
- 競合箇所（Conflict 相当）: 競合成立時間（時間点または時間範囲）・関連地物 2 件の ID と表示名・競合種類（末端重なり）を持つ構造化値。プレビュー用に重なり領域の幾何情報も保持できる。
- 解決方針（Resolution 相当）: 対象競合の識別子・優先地物 ID・調整対象地物 ID（＝差分で削られる側）を持つ値。
- プロセス結果（判別共用体）:
  - `確定済み`: 次ドメイン状態と、U12 へ渡した（または渡される）単一コマンドの識別情報を持つ。
  - `競合あり・要方針指定`: 未解決を含む全競合箇所リスト。UI はこれでモーダルを駆動する。
  - `拒否`: 拒否種別（時間制約違反 / 制約違反 / 収束失敗 等）と、ユーザー向け日本語メッセージ、機械可読な詳細。

公開する主関数（概念）:
- プロセス開始: `(現在状態, 編集案) → プロセス結果`。時間検証 → 空間検出までを実行し、競合がなければそのまま確定、あれば「競合あり」を返す。
- 方針適用と再評価: `(現在状態, 編集案, 解決方針集合) → プロセス結果`。全方針が揃っていれば差分調整 → 再検出 → 確定。未充足や残競合なら「競合あり」を返す。

## 受け入れ基準(テスト可能な形で列挙)

以下はすべて `domain` 層の純粋関数として Vitest で「入力状態 → プロセス呼び出し → 期待結果状態」を検証できる形で満たすこと。

1. **固定順序の実行（FR-61）**: 錨追加・編集確定の双方で、編集案生成 → 時間整合性検証(U09) → 空間競合検出(U10) → （競合解決） → 一括確定 の順に処理が走る。依存をスパイ/スタブ化したテストで、呼び出し順序がこのとおりであり、時間検証で拒否された場合は空間検出が呼ばれない（早期リターン）ことを検証する。
2. **空間競合の構造化リスト（FR-62）**: 末端地物同士の空間オーバーラップが検出された場合、確定を一時停止し、`競合あり` 結果を返す。各競合箇所が「作中時間（時間点または範囲）・関連地物 2 件の表示名・競合種類（末端重なり）」を含むことを検証する。複数競合が同時に存在する入力で、全競合が漏れなくリストに現れること（片落としなし、教訓 5.1 の精神を検出側にも適用）を検証する。
3. **解決方針の適用（FR-63）**: 「優先地物 + もう一方を差分ブーリアン調整」の解決方針を渡すと、U06 の差分調整が優先地物・調整対象の組で呼ばれ、調整対象の新形状（複数片を含みうる）が結果状態へ反映される。差分調整結果が 2 片以上になる入力で、全片が反映されることを検証する。
4. **全競合解決まで未確定／適用後は単一アンドゥ単位（FR-63 / FR-73）**: 競合が複数あるとき、一部の競合にのみ方針を指定した状態では `確定済み` を返さず `競合あり`（未解決を含む）を返すことを検証する。全競合に方針を指定して初めて確定し、確定が U12 を通じて 1 つの不可分コマンド（1 回のアンドゥで全復元）として記録されることを検証する（コマンドが 2 個以上に割れないこと）。
5. **確定前の制約再検証と拒否理由の戻り値（教訓 5.26）**: UI を経由しない直接呼び出しでも、時間制約違反・全体重複・階層破綻・禁止条件が検出されたら確定せず `拒否` を返す。拒否結果が「機械可読な拒否種別」と「日本語のユーザー向けメッセージ」の両方を持つことを検証する。
6. **末端地物限定（FR-26 / FR-27、教訓 5.25）**: 空間競合検出の対象が末端地物同士のみであり、集約地物・線情報・点情報が排他対象に含まれないこと（含めようとしても検出対象に渡らないこと）を検証する。
7. **差分調整後の再検出と収束（FR-61 の順序維持）**: 差分調整適用後に再度空間競合検出を実行し、残競合があれば再び `競合あり` を返す。収束しない（規定回数を超えても残競合が消えない）場合は無限ループせず `拒否（収束失敗）` を返すことを検証する。
8. **属性のみ編集の一体確定（FR-59）**: 属性だけを変更する編集案でも、内部では当該錨の完全状態を一体として扱い、部分確定が発生しないこと（時間・空間検証を経て 1 コマンドで確定）を検証する。

## 関連要件(FR-id)

- FR-61: 確定時に固定順序で 時間検証 → 空間検出 → 競合解決 → 一括確定 を実行する。
- FR-62: 空間オーバーラップ検出時に全競合箇所を構造化リストで返し、確定を一時停止する。
- FR-63: 解決方針（優先地物 + 差分ブーリアン調整）を適用でき、全競合に方針指定するまで未確定、適用後は単一アンドゥ単位。
- 併せて FR-73（複合操作を単一アンドゥ単位として扱う）・FR-26 / FR-27（末端地物同士のみの排他）・FR-59（完全状態の一体編集・部分確定禁止）・FR-94（複合操作の不可分性）・FR-115 / FR-117（日本語エラーメッセージ）を骨格として満たす土台を提供する。

## 注意点・既知の落とし穴(開発ガイドの教訓を踏まえる)

- **教訓 5.26（編集制約はコマンド確定前にも同じサービスで検証する）**: 適用 — 時間検証(U09)・空間検出(U10) を本オーケストレーション内（コマンド確定前）で必ず通し、UI 候補表示に依存しない。拒否理由は日本語通知とテスト可能な戻り値の両方で返す。これが本ユニットの中核要件であり、受け入れ基準 5 で固定する。
- **教訓 5.1（集合演算は複数片を返す前提で扱う）**: 適用 — U06 の差分調整結果は複数片・複数リングを返しうる。全片を反映し、先頭片のみ採用といった片落としをしない。受け入れ基準 3 で固定する。
- **教訓 5.25（仕様が限定した対象範囲を実装で広げない）**: 適用 — 空間排他は末端地物同士のみ。「対称性」「自然な拡張」を理由に集約地物・線・点へ広げない。受け入れ基準 6 で固定する。
- **教訓 5.23（コマンドの execute/undo/redo は対称に通知する）**: 適用 — U12 へ渡す単一コマンドは execute / undo / redo が touch した全地物へ対称通知される前提で組む。確定直後に手動リフレッシュを書きたくなったら通知漏れのサイン。
- **教訓 5.27（結合と所属変更は事前条件を分けて検証する）**: 適用 — 本ユニットが扱うのは錨の追加/編集確定に伴う整合性維持であり、結合・所属変更とは別フロー。事前条件を混同せず、本フロー固有（時間整合・空間排他）の検証に絞る。
- **教訓 5.33 / 5.34（層をまたぐ契約は型と両側テストで固定する）**: 適用 — U06 / U09 / U10 / U12 の公開インタフェースを共有型で import し、関数名・引数・戻り値構造を両側テストで固定する。依存未実装時は本仕様の入出力契約に沿った型を先に定義する。
- **教訓 5.22（確定まで共有データを破壊的に更新しない）**: 適用 — 競合解決の途中（差分調整の試行・再検出）で共有ドメイン状態を破壊更新しない。全競合解決と再検出ゼロを確認してから U12 で確定し、失敗時は何も反映しない。
- **教訓 5.18（空配列・空オブジェクトは真値である）**: 適用 — 「競合なし」を空配列、「方針未指定」を空集合で表すとき、論理和の短絡デフォルト補完に頼らず、長さ・有無を明示判定する。「競合 0 件＝確定可」「未解決 0 件＝確定可」を取り違えない。
- **収束の上限**: 差分調整が新たな重なりを誘発しうるため、再検出ループには明示的な上限回数を設け、無限ループを防ぐ。上限到達は `拒否（収束失敗）` として日本語メッセージで返す（受け入れ基準 7）。
- **クリーンルーム原則（開発ガイド 3.1）**: 本仕様・実装ともに過去版や外部の既存実装に言及せず、必要な制約は v4 要件として直接記述・参照すること。
- **性能の段階戦略（技術方針 R9）**: まず純粋関数のメインスレッド同期実装で書く。NFR 5.1 は本プロセスに数秒〜数十秒を許容するが、計測で 100ms 級のホットパスが問題化した場合に限り、純粋関数のまま Web Worker へ移設できるよう、外部 I/O・グローバル状態への依存を持たせない。

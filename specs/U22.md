# U22 選択システム(アクティブ地物・頂点選択セット・選択コンテキスト・視覚FB)

## 目的

編集モードにおける「選択」の単一の真実源を確立する。本ユニットは以下の三つの選択状態を一貫した規約で管理し、それらに基づく視覚的フィードバックと複数頂点の同時移動を提供する。

1. **アクティブ地物**: ユーザーが地物本体を直接クリックして明示的に選択した地物。常に 0 件または 1 件のみ保持する。選択時はその全頂点を半透明マーカーで表示する。
2. **頂点選択セット**: 選択中の頂点 ID の集合。単一クリックで置換、Shift+クリックで加除、ドラッグ矩形で範囲選択する。複数頂点を選択した状態で選択頂点をドラッグすると、選択セット全体を同一ベクトルで同時移動し、これを単一の編集操作として扱う。
3. **頂点選択コンテキスト**: 頂点選択セットから所有地物を解析し、単一地物がセット内の全頂点を所有する場合のみその地物を保持する派生状態。プロパティパネルはアクティブ地物がない場合にこのコンテキストを参照する。

本ユニットは「選択がいまどうなっているか」という状態と、その状態の正規化・派生・視覚化・同時移動コマンド生成に集中する。地物本体・頂点・リングの形状定義そのもの、頂点ハンドル／エッジハンドルの描画と当たり判定の下回り、編集モードのモード切替やツールバー、整合性維持プロセス・競合解決、共有頂点のスナップ／共有化ロジックは依存ユニットの責務であり、本ユニットはそれらを利用する側に立つ。

## スコープ

### やること

- **アクティブ地物の保持（0/1 件）**
  - 編集モードで地物本体を直接クリックすると、その地物を唯一のアクティブ地物として保持する（常に 0 件または 1 件。複数アクティブ地物は表現不能とする）。
  - 別の地物をクリックすると置換する。
  - 何もない場所（地物・頂点・ハンドルのいずれにもヒットしない場所）のクリック、または Escape キーで選択を解除し、アクティブ地物を 0 件にする。
  - アクティブ地物が選択されている間、その地物の全頂点を半透明マーカーで表示する（マーカー描画自体は描画層に委譲し、本ユニットは「全頂点を半透明マーカー対象とする」という選択由来の指示を出す）。
- **頂点選択セット（選択頂点 ID の集合）の管理**
  - 単一クリック（頂点ヒット）: 選択セットを当該頂点 1 件で**置換**する。
  - Shift+クリック（頂点ヒット）: 当該頂点が未選択なら**加える**、選択済みなら**除く**（トグル加除）。
  - ドラッグ矩形（空き領域からのドラッグ）: 矩形に含まれる頂点群を**範囲選択**する（既存セットの置換、または Shift 併用時は加算。挙動は受け入れ基準で固定）。
  - 何もない場所のクリック・Escape で頂点選択セットも空にする。
- **複数頂点の同時移動（単一編集操作）**
  - 頂点選択セットが複数件のとき、選択頂点のいずれかをドラッグすると、選択セット内の全頂点を**同一ベクトル**で同時移動する。
  - この同時移動は**ひとつの編集操作**として履歴に積む（途中のドラッグ中フレームは履歴化せず、解放（確定）時に 1 件のコマンドとして発行する）。
  - 移動ベクトルの算出・確定コマンド発行の本ユニットの責務範囲は「どの頂点群をどれだけ動かすか（選択セット × 同一ベクトル）」の決定であり、頂点座標の実更新・衝突判定（エッジ滑り）・共有頂点連動は依存ユニットの編集ロジックへ委譲する（本ユニットは「選択セット全体に同一ベクトルを適用する単一コマンド」を組み立てる）。
- **頂点選択コンテキストの解析**
  - 頂点選択セットの各頂点 ID から所有地物を逆引きし、**単一地物がセット内の全頂点を所有する場合のみ**その地物をコンテキストとして保持する。
  - 複数地物にまたがる場合・所有者が解決できない場合・セットが空の場合は、それぞれ「複数」「不明」「空」という区別可能な状態を返す（後述の生 ID 集合まで評価する分岐網羅）。
  - プロパティパネルなどの消費側が参照できるよう、コンテキスト状態を構造化して公開する。
- **選択状態の視覚的フィードバック（区別可能な 4 系統）**
  - アクティブ地物: 太いシアンのアウトライン + シアン塗り。
  - 頂点選択コンテキスト地物（アクティブ地物がない場合の補助ハイライト）: 点線アウトライン。
  - 選択済み頂点: 通常頂点・半透明マーカーと区別される専用スタイル。
  - ドラッグ中頂点: 選択済み頂点ともさらに区別される専用スタイル。
  - これら 4 系統が同時に成立しうる状況でも互いに区別できることを保証する（視覚スタイルの最終描画は描画層が担い、本ユニットは「どの要素がどの選択カテゴリか」を一意に分類する派生状態を提供する）。
- **生の ID 集合まで評価する分岐網羅（教訓 5.10）**
  - アクティブ地物 ID（0/1 件）と頂点選択セット（生の ID 集合）を、派生済みヘルパー結果だけに頼らず、生の値まで評価して「単一／複数／不明／空」を網羅的に分類する。
  - 仕様メッセージ・表示条件・プロパティパネル参照先を、各分類に一対一で対応付ける。
- **構造変更後の選択再解決（教訓 5.11）**
  - 結合・分割・移動・削除のように対象 ID や形状が変わる操作が完了した後、選択状態（アクティブ地物・頂点選択セット）を固定の全クリアで決めず、**コマンド結果が返す「残る要素 ID／新規要素 ID／削除された ID」から再解決する**。
  - 構造変更後に存在しなくなった地物・頂点は選択から除き、残った／新規生成された対象のうち「次に操作すべき対象」が選択として残るよう再構築する。
- 上記すべてを、副作用のない選択状態遷移関数（純粋な選択リデューサ）と、その結果を購読する薄い UI/セッション状態として実装する。

### やらないこと

- 頂点ハンドル・エッジハンドルそのものの描画と当たり判定の下回り、地物本体のヒットテスト幾何（依存ユニットが提供する。本ユニットはヒット結果を受け取って選択状態へ写像する側）。
- 頂点座標の実更新・移動制約（末端地物排他・エッジ滑り・自己交差防止）・共有頂点の連動／スナップ／共有化（依存ユニットの編集・空間整合性ロジックへ委譲。本ユニットは「選択セット × 同一ベクトル」という意図のみを渡す）。
- 編集モード／追加モードのモード切替、ツールバーのツール選択 UI（別ユニット）。本ユニットは「編集モードであること」を前提に動く。
- プロパティパネルの描画・地物プロパティ編集・錨一覧・削除ボタンの UI（別ユニット）。本ユニットは頂点選択コンテキスト等の選択状態を**公開**するだけで、パネル側の表示文言・レイアウトは持たない。
- コンテキストメニュー（右クリックメニュー）の項目構成（別ユニット）。本ユニットは「アクティブ地物／頂点選択セットがある」という選択状態を提供する。
- 整合性維持プロセス・競合解決ダイアログ（別ユニット）。同時移動コマンドの確定後にこれらがトリガーされるが、その実行は本ユニットの責務外。
- アンドゥ／リドゥの二重スタック機構そのもの（別ユニット）。本ユニットは「同時移動を単一コマンドとして 1 件発行する」ところまでを担い、スタック管理は履歴ユニットへ委譲する。
- 追加モードでの仮表示・頂点配置（FR-76〜78 は別ユニット）。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが提供する型・ヒットテスト・編集コマンド・描画契約を前提として実装する。

- **U24**: 編集ツールの基盤（頂点ハンドル・エッジハンドルの表示と当たり判定、地物本体／頂点のヒットテスト、頂点移動・追加・削除の編集コマンド、地物移動ツール）。本ユニットは U24 が返すヒット結果（「どの地物／どの頂点／空き領域をクリックしたか」）を選択状態へ写像し、複数頂点同時移動では U24 の頂点移動コマンドを「選択セット × 同一ベクトル」で組み立てて発行する。頂点座標の実更新・衝突判定・共有頂点連動は U24（およびその先の空間整合性ロジック）へ委譲する。
- **U20**: 編集モード／追加モードの排他モード管理とツールバー。本ユニットは「編集モードが有効である」ことを前提に選択を駆動し、モードが切り替わった／編集モードを抜けた際に選択を破棄する契機を U20 のモード状態から受け取る。
- **U19**: 地物描画層が提供する選択視覚化の描画契約（アウトライン太さ・塗り・点線・頂点マーカースタイルのレンダリング）。本ユニットは「どの要素がどの選択カテゴリか」を分類した派生状態を渡し、実際のシアン塗り・点線・マーカー描画は U19 が担う。

依存ユニットが公開するヒットテスト・編集コマンド・描画契約を再実装せず、本ユニットからは呼び出して利用する（単一の真実源。開発ガイド §4「単一の真実源」、教訓 5.30 過少共有の戒め）。

> 補足: dependsOn に挙がる U24／U20／U19 の spec がまだ存在しない場合でも、本ユニットは上記「依存に期待する契約（ヒット結果型・編集コマンド・モード状態・描画契約）」をインタフェースとして仮定して実装を進めてよい。契約は層をまたぐ API として共有型・両側テストで固定すること（教訓 5.33）。

## 実装方針（技術方針に沿う）

技術方針が定める採用スタックと層分離に厳密に従う。

### 配置と層分離

- 選択状態の遷移ロジック（クリック／Shift＋クリック／矩形選択／同時移動ベクトル算出／コンテキスト解析／選択再解決）は、可能な限り**フレームワーク非依存の純粋関数**として実装し、Vitest で単独実行できるようにする。理想的には選択リデューサを `domain` 寄りの純粋モジュールに置く（Electron・React・Canvas に非依存）。
- 「いま何が選択されているか」という UI/セッション状態（アクティブ地物 ID・頂点選択セット・ドラッグ中フラグ等）は Zustand の薄いストアで保持し、純粋リデューサの出力をストアへ反映する。Canvas（U19 描画層）はストアを `subscribe` で購読し、React の再描画経路に乗らない（技術方針 2.3 / 2.5）。
- 高頻度更新（ドラッグ中の頂点位置プレビュー）は React state に載せない。ドラッグ中はトランジェント／ミュータブル一時バッファで扱い、解放（確定）時にのみ正式なイミュータブルコマンドを 1 件発行する（技術方針 2.6、R5）。

### アクティブ地物（0/1 件）の表現

- アクティブ地物は「0 件 = なし」「1 件 = ある地物 ID」のいずれかとして表現し、複数件を表現できない型（`FeatureId | null` 相当、または 0/1 を保証する判別共用体）で持つ。これにより「複数アクティブ地物」という不正状態を構造的に排除する。
- アクティブ地物選択時、その全頂点を半透明マーカー対象として U19 へ渡す。マーカー表示上限（FR-110 の「全頂点マーカー表示上限」）に抵触する場合の扱いは描画層／設定の責務に委ね、本ユニットは選択対象の頂点集合を正しく供給する。

### 頂点選択セットと加除・範囲・置換

- 頂点選択セットは頂点 ID の集合（Set 相当）として保持する。単一クリック＝置換、Shift＋クリック＝トグル加除、矩形＝範囲、を一つの選択リデューサの中で**排他ではなく入力種別の組み合わせ**として分岐する（教訓 5.34「条件分岐は排他ではなく組み合わせで考える」）。
- 押下 → 移動 → 解放のシーケンスを全パスで保証する。空き領域からの押下＋移動＝矩形選択、頂点上での押下＋移動＝同時移動、移動が発生しなかった（クリック）場合は置換／加除として確定する。押下で設定した一時状態（矩形ドラフト・ドラッグ中フラグ）は解放で必ず解除する（教訓 5.8）。

### 複数頂点の同時移動

- 同時移動は「選択セット内の全頂点 ID」×「同一移動ベクトル」を引数に、U24 の頂点移動コマンドを 1 件として組み立てる。途中フレームはトランジェントで処理し、確定時にのみコマンドを発行することで、単一アンドゥ単位（FR-94 / FR-73）を保証する。
- 値が変わっていない（ベクトルがゼロ）確定は no-op ガードで弾き、幽霊 undo エントリを積まない（教訓 5.24）。

### 頂点選択コンテキストの解析

- 頂点選択セットの各 ID から所有地物を逆引きし、所有者集合を求める。所有者集合が「単一地物」かつ「その地物の全頂点を選択が覆う／少なくとも所有者が一意」のときのみコンテキスト地物を確定する。仕様は「単一地物が全頂点を所有する場合のみ保持」と定めるため、その条件を厳密に判定する（FR-81）。
- 解析は派生済みヘルパー結果だけでなく**生の ID 集合**まで評価し、「単一／複数／不明／空」を漏れなく分類する（教訓 5.10）。各分類は区別可能な値として公開する。

### 視覚フィードバックの分類

- 描画は U19 に委ねるが、「どの地物がアクティブ（太シアン＋シアン塗り）」「どの地物がコンテキスト（点線）」「どの頂点が選択済み（専用スタイル）」「どの頂点がドラッグ中（別スタイル）」という**分類**は本ユニットが単一の派生判定で供給する。描画・ヒットテスト・選択が同じ分類を参照することでドリフト（描画と選択の不一致）を防ぐ（教訓 5.29 派生形状の単一解決判定）。
- 穴領域は選択・ハイライト等の一時的視覚効果でも常に透過、飛び地は本土同様に独立領域として扱う（FR-21）。本ユニットの選択ハイライト指示も穴を塗らず、飛び地を別扱いしない。

### 一時的選択状態の破棄

- 矩形ドラフト・ドラッグ中フラグ・プレビュー位置などの一時的 UI 状態は、開始・確定・キャンセル（Escape）・ツール切替・モード切替（U20）のすべての経路で明示的に破棄する（教訓 5.2）。残留して次回操作へ引き継がれないこと。

### 構造変更後の選択再解決

- 結合・分割・移動・削除コマンドの結果が返す「残る要素 ID／新規要素 ID／削除された ID」を受け取り、選択を再解決する。固定の全クリアにしない（教訓 5.11）。
- 時間移動（現在時刻変更）など、選択中地物がその時刻に存在しなくなる状況では、選択がその時刻に有効かを再検証し、無効なら選択を解除する（教訓 5.5）。

### テスト

- 選択リデューサの単体テストを Vitest で書く。入力（現在の選択状態 + 入力イベント種別）→ 期待される新選択状態を「入力状態 → 期待状態」で網羅する（NFR 5.8）。
- 生の ID 集合に対する「単一／複数／不明／空」4 分類の分岐を、各分類ごとの専用テストで網羅する（教訓 5.10、受け入れ基準 5）。
- fast-check で「任意の頂点集合・任意の所有関係」に対しコンテキスト解析が矛盾しない（単一所有判定が偽陽性／偽陰性を出さない）ことをプロパティテストする。
- 「選択 → キャンセル → 再操作」「選択 → 確定 → 再操作」の連続で一時状態が残らないことを検証する（教訓 5.2 の検出手段）。
- 構造変更（結合・分割・削除）後に「次に操作すべき対象が選択として残る」回帰テストを置く（教訓 5.11 の検出手段）。
- テスト fixture は依存ユニットのファクトリ等で実体を生成して構築し、リテラルで型を満たそうとしない（教訓 5.39）。

## 受け入れ基準（テスト可能な形で列挙）

1. **アクティブ地物 0/1 件と半透明マーカー・Escape 解除（FR-79）**: 編集モードで地物本体をクリックすると当該地物がアクティブ地物（1 件）になり、その全頂点が半透明マーカー対象として供給されることをテストで確認できる。別地物クリックで置換され常に 0/1 件を超えない。何もない場所のクリックまたは Escape でアクティブ地物が 0 件に解除されることを確認できる。複数アクティブ地物を表現しようとしても型／状態が許さない。
2. **頂点選択セットの置換／加除／範囲（FR-80）**: 単一クリックで選択セットが当該頂点 1 件に置換される。Shift+クリックで未選択頂点が加わり選択済み頂点が除かれる（トグル）。空き領域からのドラッグ矩形で矩形内の頂点群が選択されることを、それぞれ専用テストで確認できる。
3. **複数頂点の同時移動が単一操作（FR-80 / FR-94）**: 複数頂点選択中に選択頂点をドラッグすると選択セット全体が同一ベクトルで移動し、ドラッグ確定時に**1 件の編集コマンド**として発行されること（途中フレームが履歴化されないこと）をテストで確認できる。ゼロベクトル確定は no-op ガードで履歴に積まれない。
4. **頂点選択コンテキストは単一所有時のみ保持・プロパティパネル参照（FR-81）**: 頂点選択セットの全頂点を単一地物が所有する場合のみコンテキスト地物が確定し、複数地物にまたがる場合・所有者不明の場合・空の場合はそれぞれ区別可能な状態（単一／複数／不明／空）になることをテストで確認できる。アクティブ地物がない場合にプロパティパネルがこのコンテキストを参照できる形で公開されている。
5. **生 ID 集合まで評価し単一/複数/不明/空を網羅（教訓 5.10）**: アクティブ地物 ID（0/1）と頂点選択セット（生の ID 集合）を生の値まで評価し、「単一／複数／不明／空」の 4 分類を漏れなく分岐していることを、各分類ごとの専用テストで確認できる。各分類が表示条件／参照先と一対一に対応している。
6. **選択状態の視覚 FB の区別（FR-82）**: アクティブ地物（太シアンアウトライン+シアン塗り）、頂点選択コンテキスト地物（点線アウトライン）、選択済み頂点、ドラッグ中頂点が、それぞれ区別可能なカテゴリとして分類・供給されることをテストで確認できる。4 系統が同時成立する状況でも互いに区別できる。穴領域は選択ハイライト時も透過のまま、飛び地は独立領域として扱われる。
7. **構造変更後の選択再解決（教訓 5.11）**: 結合・分割・移動・削除の完了後、選択が固定の全クリアにならず、コマンド結果（残る ID／新規 ID／削除 ID）から再解決され、存在しなくなった対象は除外、次に操作すべき対象が選択として残ることをテストで確認できる。
8. **一時状態の全経路破棄（教訓 5.2）**: 矩形ドラフト・ドラッグ中フラグ等の一時状態が、確定・キャンセル（Escape）・ツール切替・モード切替のすべての経路で破棄され、次回操作へ引き継がれないことを「選択→キャンセル→再操作」「選択→確定→再操作」の連続テストで確認できる。
9. **時間変化時の選択再検証（教訓 5.5）**: 現在時刻が変わり選択中地物がその時刻に存在しなくなった場合、選択が解除されることをテストで確認できる。
10. **純粋性・単独実行（NFR 5.8）**: 選択遷移ロジックは副作用のない純粋関数として `domain` 寄りに実装され、Vitest で単独実行できる。UI/セッション状態は薄い Zustand ストアに限定され、地図描画は購読のみで React 再描画経路に乗らない。

## 関連要件（FR-id）

- **FR-79** (must): 編集モードで地物を直接選択して 0 件または 1 件のアクティブ地物を保持し、選択時に全頂点を半透明マーカーで表示する。何もない場所のクリックや Escape で選択を解除する。
- **FR-80** (must): 頂点選択セット（選択頂点 ID の集合）を管理し、単一クリックでセット置換、Shift+クリックで加除、ドラッグ矩形で範囲選択ができる。複数頂点選択中に選択頂点をドラッグすると選択セット全体を同一ベクトルで同時移動し、これを単一の編集操作として扱う。
- **FR-81** (should): 頂点選択セットから所有地物を解析する頂点選択コンテキストを管理し、単一地物が全頂点を所有する場合のみその地物を保持する。プロパティパネルはアクティブ地物がない場合にこのコンテキストを参照する。
- **FR-82** (should): 選択状態に応じた視覚的フィードバック（アクティブ地物は太いシアンのアウトラインとシアン塗り、頂点選択コンテキスト地物は点線アウトライン、選択済み頂点とドラッグ中頂点を別スタイルで区別）を提供する。

関連する非機能要件: NFR 5.1（選択・編集操作の応答 100ms 以内、ドラッグ中 60FPS）、NFR 5.8（選択遷移の純粋関数化と入力→期待状態の再現テスト）。関連概念: ドメインモデル §4.5（アクティブ地物・頂点選択セット／頂点選択コンテキスト）、§4.2（頂点・共有頂点）、§3.18（選択機能）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

### 適用宣言（AI 作業開始ゲート, 開発ガイド 1.6）

着手前に以下の教訓を引用し、本ユニットへの適用を宣言してから実装すること。

- **教訓 5.10「選択状態は生の集合まで評価して網羅する」**（引用: 「複数の選択状態（単一・複数・不明・空）を扱う UI では、派生済みヘルパー結果だけでなく、生の ID セットをすべて評価して分岐を網羅する。仕様メッセージと表示条件を一対一で対応付ける。」）。**適用**: 本ユニットではアクティブ地物 ID（0/1）と頂点選択セット（生の ID 集合）を生の値まで評価し、「単一／複数／不明／空」を漏れなく分類して、プロパティパネル参照先・視覚 FB カテゴリを各分類に一対一で対応付ける。
- **教訓 5.11「構造変更操作後の選択は結果から再解決する」**（引用: 「結合・分割・移動・削除のように対象 ID や形状が変わる操作では、完了後の選択状態を固定の全クリアで決めない。コマンド結果が『残る要素 ID』『新規要素 ID』『削除された ID』を返し、UI はその結果から選択を再解決する。」「検出: 次に調整すべき対象が残る操作では、選択維持を回帰テストに含める。」）。**適用**: 本ユニットは構造変更コマンドの結果から選択を再解決し、固定全クリアにしない。次に操作すべき対象が選択として残る回帰テストを置く。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」**: 矩形ドラフト・ドラッグ中フラグ・プレビュー位置は、開始・確定・キャンセル（Escape）・ツール切替・モード切替のすべてで明示破棄する（受け入れ基準 8）。
- **教訓 5.3「操作対象は表示状態に限定する」 / 5.4「現在の UI 文脈を第一候補にする」**: 選択・同時移動・コンテキスト解析の対象は「いま編集モードで表示・選択されている要素」に限定し、データソース全体を直接検索しない。第一候補は現在の UI 文脈（フォーカス／選択中対象・現在時刻）。
- **教訓 5.5「依存する状態は変化時に再検証する」**: 時間が変わったら選択中地物がその時刻に存在するか検証し、なければ選択解除（受け入れ基準 9）。
- **教訓 5.8「押下→移動→解放シーケンスを全パスで保証する」**: クリック（移動なし）とドラッグ（矩形／同時移動）の両パスで状態が正しく開始・更新・終了すること。押下で設定した状態は解放で必ず解除。移動が発生しなかった場合の置換／加除確定を漏らさない。
- **教訓 5.9「排他分岐が重要処理をスキップしていないか確認する」**: アクティブ地物選択／頂点選択／矩形選択の優先順位と、同時選択／排他選択を明確に定義する。地物本体ヒットと頂点ヒットが重なる位置でどちらを採るかを一意に決める。
- **教訓 5.18「空配列・空オブジェクトは真値である」**: 「頂点選択セットが空＝空状態」「アクティブ地物 0 件」を論理和の短絡で誤らない。型・状態を明示判定する。
- **教訓 5.24「確定ハンドラには no-op ガードを入れる」**: 同時移動の確定でベクトルがゼロなら履歴に積まない（受け入れ基準 3）。baseline はドラッグ開始時の頂点位置と同一ソースから導く。
- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」**: 描画・ヒットテスト・選択・視覚 FB 分類を同じ選択分類判定で動かし、「描画されているのに選択できない」「ハイライト位置が描画と違う」というドリフトを防ぐ。判定を共通関数へ集約し単体テストで固定する。
- **教訓 5.33「層をまたぐ API 契約は両側テストで固定する」 / 5.34「コンポーネント間データ受け渡しは契約を型で明示する」**: U24（ヒット結果型・頂点移動コマンド）・U20（モード状態）・U19（描画契約・選択カテゴリ）との契約は共有型・両側テストで固定する。条件分岐は排他ではなく組み合わせで考える。
- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / §4「単一の真実源」**: ヒットテスト・編集コマンド・描画は依存ユニットの実装を共有し再実装しない（過少共有の戒め）。
- **FR-21（穴の透過・飛び地の独立）/ FR-94（複合操作の不可分性）**: 選択ハイライトでも穴は塗らず飛び地は独立扱い。同時移動は単一アンドゥ単位。

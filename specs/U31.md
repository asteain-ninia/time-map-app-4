# U31 面情報の削除と参照掃除・連鎖剪定

## 目的

面情報の「削除」を、ドメインの参照整合性を一切壊さずに完了させる単一の操作として実装する。本ユニットは、削除可否の事前判定・削除の実行（参照掃除と連鎖剪定）・削除を起動するプロパティタブの削除 UI の三つを担い、次を保証することを目的とする。

- 面情報の削除は、全時刻を通じてその地物への上位/下位領域参照を持つ他地物が存在しないか、再編が許容される場合にのみ可能とする（FR-41）。
- 削除を実行するとき、残存する全要素の全時間軸状態（全錨）から削除対象への参照を**同一操作内で**掃除し、参照が消えて空（全下位領域喪失）になった集約地物を**剪定・連鎖消滅**させる（教訓 5.21 / FR-35 / FR-41）。
- プロパティタブの「地物を削除」ボタンは、アクティブ地物または頂点選択コンテキストの地物がある場合のみ有効化し、押下時に確認ダイアログを提示、**確定時のみ**履歴記録を伴う削除コマンドを発行する（FR-85）。

本ユニットは「削除という 1 つのユーザーアクション」を、不可分の単一アンドゥ単位として組み立てて発行する側に立つ。削除コマンドの履歴への積み方・二重スタック管理そのものは依存ユニット（U12）が、選択状態の供給と削除後の選択再解決は依存ユニット（U22）が、親子関係の走査と集約地物の判定基盤は依存ユニット（U08）が担う。本ユニットはそれらを呼び出して利用し、再実装しない（単一の真実源。開発ガイド §4 / 教訓 5.30）。

## スコープ

### やること

1. **削除可否の事前判定（FR-41）**
   - 削除対象の面情報について、**全時刻（全錨）を通じて**その地物を上位領域または下位領域として参照する他地物が存在するかを、依存ユニット U08 の親子走査を用いて判定する。
   - 「参照を持つ他地物が存在しない」場合は無条件に削除可能とする。
   - 「参照を持つ他地物が存在する」場合でも、**再編が許容される**（参照掃除と連鎖剪定によってドメイン不変条件を保ったまま削除を完了できる）場合は削除可能とする。再編が成立しない場合は削除を拒否し、拒否理由をユーザー通知用メッセージ（日本語、FR-115）とテスト可能な機械可読フィールドの両方で返す（教訓 5.26）。
   - 判定は単一時点ではなく全時間軸を横断して行う。ある時刻にだけ参照が残ると dangling 参照になるため、片方向・単一時点だけの判定を禁止する（教訓 5.21）。

2. **参照掃除（残存全要素・全時間軸）（教訓 5.21 / FR-41）**
   - 削除を実行するとき、残存する全要素の**全錨**を走査し、削除対象の地物 ID を上位領域参照・下位領域参照として持つすべての箇所から参照を取り除く。
   - 掃除は双方向に行う。削除対象を「親」として持つ子地物の上位領域参照、削除対象を「子」として持つ親（集約地物）の下位領域参照、その両方を同一操作内で除去する（片方向掃除の禁止。教訓 5.21）。
   - 共有頂点を介した参照は本ユニットの掃除対象に含めるかを明示する（後述「実装方針／共有頂点の扱い」）。

3. **空集約の剪定・連鎖消滅（FR-35 / FR-41 / 教訓 5.21）**
   - 参照掃除の結果、ある時刻において直接下位領域を 1 つも持たなくなった集約地物は、その時刻以降の状態として自動的に消滅させる（FR-35：集約地物が全下位領域を失うとその時刻以降自動消滅）。
   - 集約地物の消滅は、それ自身が別の集約地物の下位領域であった場合、上位の集約地物の下位領域参照を空にしうる。よって**連鎖的に**剪定を繰り返し、もう空になる集約地物が無くなるまで（不動点に達するまで）伝播させる。
   - この連鎖剪定は削除と同一の操作内で完結させ、途中状態（dangling 参照や空集約が残る状態）を確定結果に残さない。

4. **集約地物が全下位を失った場合の自動消滅（FR-41 / FR-35）**
   - 自動消滅の起動条件は「下位領域を 0 個になった」という**変異後の結果状態**で判定し、特定の呼び出し経路（削除コマンド経由かどうか）でゲートしない（教訓 5.6）。本ユニット内の連鎖剪定だけでなく、後続ユニットの所属変更・結合などが下位領域を空にした場合でも同じ判定基盤で消滅できるよう、判定を共通化して提供する。
   - 集約地物は時刻ごとに下位領域が変わりうるため、消滅は「その時刻以降」の状態に対して適用する。全時刻で下位領域が 0 個なら地物自体が全期間で消滅する。

5. **プロパティタブの削除ボタンと確認ダイアログ（FR-85）**
   - プロパティタブに「地物を削除」ボタンを常設する。ボタンは**アクティブ地物（U22）があるか、または頂点選択コンテキストの地物（U22）がある**場合のみ有効化し、いずれも無い場合は無効化する。
   - 押下時に確認ダイアログを提示する。確認ダイアログで**確定したときのみ**削除コマンドを発行して履歴に記録する。キャンセル時は何も起こさず履歴に積まない。
   - 削除対象は「いま UI 上で選択・表示されている地物」（アクティブ地物を第一候補、無ければ頂点選択コンテキスト地物）とし、データソース全体の先頭要素や固定既定を使わない（教訓 5.3 / 5.4）。

6. **削除結果（残存/削除 ID）の供給と選択再解決の起動**
   - 削除コマンドは、U12 のコマンド結果契約に従い「残存した要素 ID／新規生成された要素 ID（通常なし）／削除された要素 ID（削除対象＋連鎖消滅した集約地物）」を返す。連鎖剪定で消滅した集約地物も削除 ID 集合に含める。
   - U22 の選択管理が、この結果から選択状態を再解決できるようにする（固定全クリアにしない。教訓 5.11）。削除対象および連鎖消滅した地物は選択から除く。

### やらないこと

- 点情報・線情報の削除そのものの実装。本ユニットは**面情報の削除**（上位/下位参照と集約地物の連鎖を伴うもの）に集中する。ただし削除ボタン UI は FR-85 の「地物を削除」ボタンとして点・線・面に共通であってよく、面情報固有の参照掃除・連鎖剪定ロジックが本ユニットの中核である（点・線に上位/下位参照と集約連鎖は無いため、それらの削除は対象自身の除去で完了する）。
- アンドゥ／リドゥの二重スタック機構・コマンド適用機構そのもの（U12 の責務）。本ユニットは「削除を不可分の 1 コマンドとして 1 件発行する」ところまでを担い、スタック管理・上限・リドゥ破棄は U12 へ委譲する。
- 親子関係の走査基盤・階層深度の派生算出・集約地物/末端地物の判別・形状=下位領域の和の検証（U08 の責務）。本ユニットは U08 の走査・判定を呼び出して利用する。
- 選択状態（アクティブ地物・頂点選択セット・頂点選択コンテキスト）の保持・解析・視覚フィードバック・削除後の選択再解決の実装本体（U22 の責務）。本ユニットは U22 が公開する選択状態を**参照して**ボタン有効化と削除対象決定に使い、削除結果（残存/削除 ID）を U22 へ**供給する**だけ。
- 所属変更フロー（割譲・連邦化・独立・帰属・直轄化・自治化・解体）・結合・分割といったツリー位相変更操作（別ユニット）。これらも下位領域を空にして集約地物を消滅させうるが、本ユニットは「削除起点の参照掃除・連鎖剪定」と「結果状態で自動消滅を判定する共通基盤」を提供し、各位相変更操作はその基盤を再利用する。
- 末端地物同士の空間的排他検証・整合性維持プロセス・競合解決（FR-26〜29 / FR-61〜63、別ユニット）。削除は参照整合性の操作であり、削除単体で末端地物の重なりを新たに生むことはない（無主地の発生は許容。FR-39）。よって本ユニットは削除後に空間競合検出を必須トリガーとしない（必要な場合の連携は依存契約として記すに留める）。
- プロパティパネル全体のレイアウト・属性編集フォーム・歴史の錨一覧（FR-83 / FR-84、別ユニット）。本ユニットはそのパネル内に置かれる「削除ボタン＋確認ダイアログ」のみを担う。
- 永続化（保存ファイルへの反映）。削除はセッション内のドメイン状態とアンドゥ履歴に対する操作であり、ファイル保存は別ユニットの責務。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。いずれの公開インタフェース（型・関数名・引数・戻り値）も、偶然の一致に頼らず共有型・両側テストで固定する（教訓 5.33 / 5.34）。依存ユニットが未実装の場合でも、本仕様に記す入出力契約をインタフェースとして仮定し、その型に対して本ユニットの実装と単体テストを進めてよい。

- **U22 — 選択システム（アクティブ地物・頂点選択コンテキスト・視覚FB）**: 削除ボタンの有効化条件（アクティブ地物 1 件、または頂点選択コンテキストの地物が一意）と、削除対象の決定（アクティブ地物を第一候補、無ければ頂点選択コンテキスト地物）に用いる。本ユニットは U22 が公開する選択状態を参照し、削除コマンド結果（残存/削除 ID）を U22 へ渡して削除後の選択再解決（教訓 5.11）を起動させる。選択状態の保持・解析・再解決の実装は U22 が担い、本ユニットは再実装しない。
- **U12 — 純粋コマンド基盤とアンドゥ/リドゥ二重スタック**: 削除を「ドメイン状態 → { 新ドメイン状態, コマンド結果 }」の純粋コマンドとして発行し、不可分の単一アンドゥ単位として履歴に積む（FR-73 / FR-94）。コマンド結果は U12 の契約（残存/新規/削除/touch の各 ID 集合）に従う。連鎖消滅した集約地物も削除 ID と touch 集合へ集約する。確認ダイアログで確定したときのみ push する。
- **U08 — ツリー階層モデルと不変条件検証（森構造・派生深度・形状=和）**: 削除可否判定と参照掃除のための親子走査（上位領域参照・下位領域参照の双方向導出、循環に耐える有限走査）と、集約地物/末端地物の判別、集約地物が下位領域 0 個になった状態の検証結果定義を提供する基盤として用いる。本ユニットは U08 の走査・判定を呼び出し、親子走査・深度算出・末端/集約判別を自前実装しない。U08 が「0 個下位領域の検証結果」を一意に定義していることを前提に、本ユニットがその 0 個状態を**自動消滅という状態変化へ落とす**（U08 spec の「自動消滅は別ユニットが担う」に対応する側が本ユニット）。

> 補足: U08 spec は「全下位領域を失った集約地物の自動消滅は別ユニットが担うが、本ユニット（U08）は 0 個状態の検証結果を一意に定義する」と記している。本ユニット U31 はその「別ユニット」であり、U08 の 0 個状態判定を起点に剪定・連鎖消滅を実行する。両者の対概念（検証 ↔ 消滅実行）が整合するよう、判定条件は U08 の定義に一致させる（開発ガイド §2.10 / §4 対概念の整合）。

## 実装方針（技術方針に沿う）

技術方針の 1.（採用スタック）・2.5（Zustand ＋ 純粋ドメインコア）・2.6（純粋コマンド ＋ Immer ＋ 二重スタック）・2.13（ディレクトリ層分離と依存方向の内向き固定）に従う。

### 配置と層分離

- 削除可否判定・参照掃除・連鎖剪定・自動消滅判定のロジックは、**フレームワーク非依存の純粋関数**として `domain` 層に置き、Electron／React／Canvas を一切 import せず Vitest 単体で実行できる状態を保つ（技術方針 2.13）。入力に「現在のドメイン状態 ＋ 削除対象 ID」を取り、「次のドメイン状態 ＋ コマンド結果」または「拒否（理由つき）」を返す純粋関数とする。入力状態を破壊的に変更しない（Immer の `produce` で不変更新、構造共有）。
- 削除ボタン・確認ダイアログの UI は React（`ui` 層）で実装し、押下→確認→確定の確定経路でのみ `domain` の削除コマンドを呼ぶ。UI は選択状態（U22）を Zustand 経由で購読してボタンの有効/無効を切り替える。地図描画（Canvas）は削除結果を購読して再描画するが、React 再描画経路には乗らない（技術方針 2.3 / 2.5）。
- 依存方向は `domain` へ内向きに固定する。`domain` の削除ロジックは UI・描画・シェルへ依存しない。

### 削除可否判定（全時刻横断）

- 削除可否は「全錨を通じた参照の有無」で判定する。U08 の親子走査で、削除対象を上位領域参照／下位領域参照として持つ他地物を、**各地物の各錨ごと**に列挙する。単一時点だけ・片方向だけの判定にしない（教訓 5.21）。
- 「再編許容」の定義を本ユニットで明示する。参照掃除＋連鎖剪定を適用した結果が、ドメイン不変条件（最上位フラグ⇔親なしの同値、集約地物=下位領域の和、リング階層の交互性、錨列の昇順・非重複）を全時刻で満たすなら再編許容＝削除可能とする。満たせない場合（例：削除によって不変条件を回復できないデータ）は拒否する。判定には U08 の検証関数を再利用する（教訓 5.26：確定前にも同じサービスで検証）。
- 判定結果は構造化して返す（削除可能／拒否＋拒否理由種別＋関与地物 ID の列挙）。拒否理由は日本語通知文言とテスト可能な機械可読フィールドの双方で扱える（教訓 5.26 / FR-115）。

### 参照掃除（双方向・全時間軸）

- 参照掃除は次を漏れなく行う（教訓 5.21 / 5.1 の「全件列挙」の精神）。
  - 削除対象を**親**として持つ全子地物の全錨から、上位領域参照を除去（除去後その子は最上位になりうる：最上位フラグと親なしの同値を保つよう同期。FR-39）。
  - 削除対象を**子**として持つ全集約地物の全錨から、下位領域参照を除去。
  - 共有頂点を介する参照（後述）について、削除対象が単独所有していた頂点の扱いと、共有していた頂点の参照剥離を規約どおり処理する。
- 「～も同様に」で省略せず、参照を持ちうる全箇所（全地物・全錨・上位/下位の両方向）を明示的に処理する（開発ガイド §1.2 省略の禁止）。

### 連鎖剪定・自動消滅（不動点まで）

- 参照掃除後、各時刻で下位領域が 0 個になった集約地物を列挙し、その時刻以降の状態として消滅させる。消滅した集約地物が別の集約地物の下位領域だった場合は、その上位を再評価し、空になればさらに消滅させる。**変化が起きなくなる（不動点）まで反復**する。
- 連鎖剪定の走査は U08 の循環耐性のある走査基盤を用い、壊れたデータ（循環参照）でも無限ループしない（教訓 5.28）。剪定の反復自体も、処理済み集合または明示的な上限で停止を保証する。
- 自動消滅の起動は「下位領域 0 個」という結果状態で判定し、削除経路に限定したフラグでゲートしない（教訓 5.6）。この判定関数は本ユニットの公開 API として切り出し、所属変更・結合など他経路の消滅判定からも同一実装を共有できるようにする（単一の真実源。教訓 5.30）。

### 共有頂点の扱い

- 面情報の削除が、削除対象と他地物が共有していた頂点に与える影響を明示する。削除対象が単独所有する頂点は削除と同時に除去する。他地物と共有する頂点は、削除対象側の参加だけを剥がし、共有先地物の形状を壊さない（残る地物にとって有効なリング・線形を維持する）。共有頂点システム本体（参加管理・連動）は U11 が担い、本ユニットは「削除対象の参加を共有グループから外す」依頼を出す側に立つ（再実装しない）。
- 削除を元に戻す（undo）のに必要な情報には、剥がした共有頂点参加・除去した親子参照・連鎖消滅した集約地物の状態を**過不足なく**含める。redo で ID を採番し直さない（教訓 5.20）。

### 単一アンドゥ単位・対称通知

- 削除可否判定→参照掃除→連鎖剪定→自動消滅までを、U12 を通じて**不可分の 1 コマンド**として記録する。途中で別アンドゥ単位に割れないことを保証する（FR-73 / FR-94）。
- コマンドの execute / undo / redo は、touch した全要素（削除対象・参照を掃除した子/親・連鎖消滅した集約地物・共有頂点を剥がした残存地物）へ同じイベント規約で対称に通知する。直後に手動リフレッシュを書きたくなったら通知漏れのサイン（教訓 5.23）。

### 確定までの非破壊・no-op

- 確認ダイアログで確定するまで、共有キャッシュ／共有ドメインデータを破壊的に更新しない（教訓 5.22）。削除コマンドは純粋関数として新状態を計算し、確定時にのみ U12 へ push する。
- 削除対象が存在しない・選択が空など、実質的に何も削除しない確定は no-op ガードで弾き、幽霊 undo エントリを積まない（教訓 5.24）。

### テスト（技術方針 2.14 / NFR 5.8）

- Vitest で「入力状態 → 削除コマンド → 期待状態」を直接比較する。参照掃除後に全地物の全錨へ dangling 参照が残らないことをアサートする。
- 連鎖剪定の多段ケース（子削除→親集約が空→さらにその親集約が空、の連鎖）が不動点まで伝播し、すべての空集約が消滅することを確認する。
- **片方向／単一時点だけの掃除で dangling 参照が残らないことを反証するテスト**を必ず置く（受け入れ基準 5）。意図的に片方向だけ掃除した結果を不変条件検証（U08）にかけ、違反が検出されること（＝本ユニットの正しい実装が双方向・全時刻で掃除すること）を回帰で固定する。
- fast-check で「任意の森＋任意の錨列に対し、削除可能と判定された地物を削除すると、削除後の全状態が U08 の不変条件をすべて満たし、削除対象 ID への参照が全要素・全錨から消えている」ことをプロパティテストする。
- 確認ダイアログの確定/キャンセル経路をテストし、キャンセル時に履歴へ積まれないこと、確定時のみ 1 件積まれることを確認する（FR-85）。テスト fixture は依存ユニットのファクトリで実体を生成して構築し、リテラルで型を満たそうとしない（教訓 5.39）。

## 受け入れ基準（テスト可能な形で列挙）

各基準は Vitest 単体テストまたは fast-check プロパティテストで検証できる形で満たすこと。

1. **全時刻で参照を持つ他地物がない／再編許容時のみ削除可能（FR-41）**
   - 削除対象への上位/下位領域参照を持つ他地物が全時刻を通じて存在しない面情報は、無条件に削除可能と判定される。
   - 参照を持つ他地物が存在しても、参照掃除＋連鎖剪定で全時刻のドメイン不変条件を保てる場合は削除可能と判定される（再編許容）。
   - 再編で不変条件を回復できない場合は削除が拒否され、拒否理由種別と関与地物 ID を含む構造化結果（日本語通知文言＋機械可読フィールド）が返ることをテストで確認できる。
   - 可否判定が単一時点ではなく全錨を横断して行われることを、「ある時刻にだけ参照が残る」入力で確認できる。

2. **残存全要素の全時間軸状態から参照を掃除し空集約を連鎖剪定（教訓 5.21）**
   - 削除実行後、残存する全要素の全錨を走査して、削除対象 ID への上位領域参照・下位領域参照が**双方向ともに**残っていないことをテストで確認できる。
   - 参照掃除で下位領域が 0 個になった集約地物が消滅し、その消滅でさらに空になった上位集約地物も消滅する連鎖剪定が、不動点に達するまで伝播することを多段ケースで確認できる。
   - 参照掃除と連鎖剪定が削除と同一操作内で完結し、途中状態（dangling 参照・空集約）が確定結果に残らない。

3. **集約地物が全下位を失うと自動消滅（FR-41 / FR-35）**
   - ある時刻に集約地物の直接下位領域が 0 個になったとき、その時刻以降の状態としてその集約地物が消滅する。
   - 自動消滅が「下位領域 0 個」という結果状態で判定され、削除経路に限定したフラグでゲートされていない（同じ結果状態を生む別経路でも消滅できる共通判定であること）をテストで確認できる（教訓 5.6）。
   - 全時刻で下位領域 0 個なら地物自体が全期間で消滅する。

4. **削除ボタンが対象ある時のみ有効・確認ダイアログ・確定時のみ履歴記録（FR-85）**
   - 「地物を削除」ボタンが、アクティブ地物がある場合、または頂点選択コンテキストの地物がある場合のみ有効化され、いずれも無い場合は無効化されることを確認できる。
   - 押下時に確認ダイアログが提示され、**確定したときのみ**削除コマンドが発行されて履歴に 1 件記録される。キャンセル時は履歴に積まれない。
   - 削除対象がアクティブ地物を第一候補、無ければ頂点選択コンテキスト地物となり、データソース先頭や固定既定に落ちない（教訓 5.4）。

5. **片方向／単一時点だけの掃除で dangling 参照が残らないテストがある（教訓 5.21）**
   - 意図的に片方向だけ（または単一時点だけ）参照を掃除した結果を U08 の不変条件検証にかけると、dangling 参照が違反として検出される反証テストが存在する。
   - 本ユニットの正規の削除（双方向・全時刻掃除）では、同じ検証で dangling 参照が一切残らないことを対で確認できる。

6. **単一アンドゥ単位・対称通知・ID 不変（FR-73 / FR-94・教訓 5.20 / 5.23）**
   - 削除（参照掃除＋連鎖剪定＋自動消滅を含む）が不可分の 1 コマンドとして記録され、1 回のアンドゥで削除前状態へ完全復元、1 回のリドゥで削除後状態へ完全復元される。
   - コマンド結果に削除 ID 集合（削除対象＋連鎖消滅した集約地物）が含まれ、U22 の選択再解決がこの結果から駆動できる（固定全クリアに依存しない。教訓 5.11）。
   - execute / undo / redo が touch した全要素へ対称に通知し（厳密一致で検証）、undo→redo で ID が採番し直されない。

7. **純粋性・単独実行（NFR 5.8）**
   - 削除可否判定・参照掃除・連鎖剪定・自動消滅判定が副作用のない純粋関数として `domain` 層に実装され、入力状態を破壊せず、Vitest で単独実行できる。
   - 連鎖剪定・親子走査が循環参照データでも無限ループせず有限結果を返す（U08 の循環耐性走査を用いる。教訓 5.28）。

## 関連要件（FR-id）

- **FR-41**（must）: 面情報の削除は、全時刻を通じてその地物への上位/下位領域参照を持つ他地物が存在しないか、再編が許容される場合にのみ可能とする。集約地物が下位領域を全て失った場合は自動消滅する。
- **FR-85**（should）: プロパティタブに「地物を削除」ボタンを常設し、アクティブ地物または頂点選択コンテキストの地物がある場合のみ有効化する。押下時は確認ダイアログを提示し、確定時のみ履歴記録を伴う削除処理を行う。

あわせて参照する要件・概念: FR-35（集約地物は形状を持たず、全下位領域を失うとその時刻以降自動消滅）、FR-39（最上位フラグと親なしの同値・無主地の許容）、FR-73 / FR-94（単一アンドゥ単位・複合操作の不可分性）、FR-83 / FR-84（プロパティパネル文脈・削除ボタンの設置先）、FR-115（日本語エラー文言）。ドメインモデル §4.3（末端地物・集約地物・上位/下位領域）、§4.5（アクティブ地物・頂点選択コンテキスト）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として 1 文以上で宣言してから実装すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **教訓 5.21「削除は参照掃除と連鎖剪定まで行う」**（引用: 「削除操作は、対象自身を消すだけでは完了しない。残存する全要素の全（時間軸）状態から、削除対象への参照を同じ操作内で掃除し、参照が消えて空になった派生要素は剪定・連鎖消滅させる。片方向・単一時点だけの掃除は dangling 参照を残す。」）。**適用**: 本ユニットの削除は、残存全要素の全錨から削除対象 ID への上位/下位参照を双方向・全時刻で掃除し、空になった集約地物を不動点まで連鎖剪定する。片方向／単一時点だけの掃除で dangling 参照が残らないことを反証テストで固定する（受け入れ基準 5）。

- **教訓 5.6「状態変化の検出は結果状態で判定する」**（引用: 「『ある状態変化が起きたら追加処理を走らせる』検出は、特定の入力経路（呼び出しフラグ・引数の有無）でゲートせず、変異後の結果状態で判定する。同じ状態変化を複数経路が引き起こす場合、特定経路に絞ったゲートは別経路で必ず漏れる。」）。**適用**: 集約地物の自動消滅は「下位領域 0 個」という結果状態で判定する共通関数として提供し、削除・所属変更・結合など下位領域を空にする全経路で同じ判定が走るようにする。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.11「構造変更操作後の選択は結果から再解決する」**: 削除コマンドは残存/削除 ID を返し、U22 が固定全クリアではなくその結果から選択を再解決する。削除対象および連鎖消滅した集約地物は選択から除く。
- **教訓 5.20「元に戻す情報は依存データも含めて過不足なく保存する」**: undo 復元には、除去した親子参照・剥がした共有頂点参加・連鎖消滅した集約地物の状態を過不足なく含める。redo で ID を採番し直さず初回 ID を復元する。
- **教訓 5.22「確定まで共有データを破壊的に更新しない」**: 確認ダイアログ確定まで共有ドメインデータを破壊更新しない。純粋関数で新状態を算出し、確定時にのみ U12 へ push する。
- **教訓 5.23「コマンドの execute/undo/redo は対称に通知する」**: touch した全要素（削除対象・掃除した子/親・連鎖消滅した集約・共有頂点を剥がした残存地物）へ対称通知し、通知テストは厳密一致で検証する。
- **教訓 5.24「確定ハンドラには no-op ガードを入れる」**: 削除対象が無い／選択が空など実質無操作の確定は履歴に積まない。
- **教訓 5.26「編集制約はコマンド確定前にも同じサービスで検証する」**: 削除可否判定（再編許容判定）を、UI のボタン無効化だけでなくコマンド確定前にも U08 の検証サービスで再検証する。ショートカット・メニュー・直接呼び出し・undo/redo 経路から不正削除が入らないようにし、拒否理由はユーザー通知とテスト可能な戻り値の両方で扱う。
- **教訓 5.28「階層を辿る再帰サービスは循環で無限ループしない」**: 参照掃除・連鎖剪定の親子走査は U08 の `visited` セットで再入遮断する走査を用い、循環参照データでも有限結果を返す。剪定の反復にも停止保証を置く。循環参照テストケースを必ず置く。
- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / 開発ガイド §4「単一の真実源」**: 親子走査・末端/集約判別・自動消滅判定は単一実装を共有する（過少共有の戒め）。一方で、削除の事前条件と所属変更・結合の事前条件は別概念であり、候補絞り込みや事前検証を安易に共有しない（過剰共有の戒め。教訓 5.27 も参照）。
- **開発ガイド §2.10「対概念へ判断を反映する」**: 「上位領域参照の掃除」と「下位領域参照の掃除」、「U08 の 0 個状態検証」と「本ユニットの自動消滅実行」、「最上位フラグ」と「親なし」の同値（FR-39）など、対概念に同じ判断を反映する。子の親参照を外して最上位化したら最上位フラグも真に同期する。
- **教訓 5.3 / 5.4「操作対象は表示状態・現在の UI 文脈に限定する」**: 削除対象はアクティブ地物（第一候補）→頂点選択コンテキスト地物の順で、現在の UI 文脈から決める。データソース先頭・固定既定に落ちる回帰をテストで防ぐ。
- **教訓 5.18「空配列・空オブジェクトは真値である」**: 「下位領域 0 個」「選択が空」を論理和の短絡で誤判定しない。型・状態を明示判定する。
- **教訓 5.1「集合演算は複数片を返す前提で扱う」**: 飛び地など下位領域が複数片の集約地物でも、参照掃除・剪定で全片・全下位領域を漏れなく扱い、片落としをしない。
- **FR-39（無主地の許容）**: 削除で末端地物が消えても、その領域が無主地になるのは許容される。削除単体で末端地物の重なりは生じないため、本ユニットは削除後に空間競合検出を必須トリガーとしない（過剰検証の防止。教訓 5.25 仕様が限定した対象範囲を実装で広げない）。
- **層をまたぐ契約の固定（教訓 5.33 / 5.34）**: U22（選択状態・削除結果）・U12（コマンド結果型）・U08（走査/検証 API）との契約は共有型・両側テストで固定する。
- **クリーンルーム（開発ガイド §3.1）**: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-41 / FR-85 ほか）・技術方針として直接記述する。
- **やり残しの記録（開発ガイド §1.8）**: 本ユニットで保留した判断（共有頂点剥離の細目・再編許容の境界ケースなど後続ユニットへ波及するもの）は現状.md に記録する。新たに根本原因を教訓化すべき事象があれば開発ガイド §5 へ追記してから完了とする（§1.5）。

# U24 編集ツール(頂点/エッジハンドル・移動・点/線/面編集・エッジ滑り・確定で整合性)

## 目的

編集モードで選択中の地物（アクティブ地物または頂点選択コンテキストの地物）に対して、頂点ハンドル・エッジハンドルの表示と、地物移動・点/線/面の頂点編集・属性編集・削除といった一連の編集操作を提供する。さらに、面情報の頂点編集時には地図全体の他の末端地物との空間的排他（FR-26）をリアルタイムに保つ「エッジ滑り」を実装する。

本ユニットは「押下→移動→解放」のドラッグ操作フローを担う**操作層（編集ツール）**であり、次の二段戦略を中核とする。

- **ドラッグ中（軽量判定）**: 近傍候補のみを対象に軽量な衝突判定・スナップ・共有化候補判定を行い、毎フレーム不変コピーを取らずトランジェント／一時バッファで応答性（NFR 5.1 の 100ms）を守る（技術方針 R5）。
- **操作確定時（フル整合性）**: 押下した移動を解放で確定する瞬間に、整合性維持プロセス（U13）へ編集案を渡し、時間的・空間的整合性を一括検証してから単一アンドゥ単位として確定する。

幾何述語・空間インデックス・ブーリアン演算・リング階層検証・整合性維持オーケストレーション・履歴積みといった下位ロジックは依存ユニットへ委譲し、本ユニットはそれらを**正しい順序・正しい入力で駆動する操作フローの調停**に徹する。

## スコープ

### やること

- **頂点ハンドル／エッジハンドルの提示用モデル**（FR-87）
  - 選択地物の各頂点を**頂点ハンドル**として、各辺の中点を**エッジハンドル**として算出し、描画層・ヒットテストが参照できる構造化データ（ワールド座標 + 種別 + 由来リング/頂点 ID）として提供する。
  - 頂点ハンドルは「移動」「削除」、エッジハンドルは「新頂点追加」の操作対象である。本ユニットは操作の起点となるハンドル集合の算出とヒット判定の入力提供を担い、実際の見た目（マーカー描画・ハイライト）は描画層が行う。
  - ハンドルの画面上一定サイズ表示（FR-17）はワールド→スクリーン変換の責務であり、本ユニットはワールド座標と種別を供給するのみ。
- **地物移動ツール**（FR-88）
  - アクティブ地物の全頂点を**同一ベクトルで平行移動**する。共有頂点はそれを共有する全形状が連動する（FR-30、U11 経由）。
  - 移動は単一の編集操作として扱い、確定時に整合性維持プロセス（U13）を経る。
- **点情報編集**（FR-88）: 属性編集・点（単一頂点）の移動・点情報の削除。点情報は排他性を持たない（FR-29）ため、移動にエッジ滑り・末端排他を課さない。
- **線情報編集**（FR-88）: 属性編集・頂点移動・頂点追加（エッジハンドル）・頂点削除。頂点削除の結果**2 点未満**になる場合は線情報自体を削除する。線情報は排他性を持たない（FR-29）ため末端排他・エッジ滑りを課さない。
- **面情報編集**（FR-88 / FR-89）: 属性編集・頂点移動・頂点追加（エッジハンドル）・頂点削除。
  - 頂点削除の結果、対象リングが**3 点未満**になる場合は、そのリングを削除する。リング削除によって面情報が領土リングを 1 つも持たなくなる場合は面情報自体を削除する。リング削除に伴う交互構造の再編は U07 へ委譲する。
  - 面頂点の移動・追加では、地図全体の他の末端地物との**エッジ滑り**（後述）をリアルタイムに適用する。
- **エッジ滑り（面頂点編集時のリアルタイム衝突判定）**（FR-28 / FR-89）
  - ドラッグ中の面頂点が他の末端地物の内部へ食い込もうとすると**エッジで阻まれ、エッジに沿って滑る**。
  - **衝突検出と衝突応答を分離**する。移動先点の合法性だけでなく、開始点から移動先までの**線分が境界を横切るか**を判定する（教訓 5.38）。
  - 既存接触（接触状態 t=0 から始まる移動）は新規衝突として止め直さず、**食い込み成分だけを捨てて接線方向の移動を許可**する（教訓 5.38）。
  - 滑っている境界（滑り対象のエッジ）を描画層がハイライトできるよう、**滑り境界の識別情報**を出力する。
  - エッジ間衝突判定により、**尖った部分（頂点）を飛び越える**動きでも重なりを発生させない（FR-28）。
  - 穴リングの頂点・飛び地の頂点も、外周（親リング）と交差しないという制約を満たすように移動を拘束する（FR-89、リング内制約は U07 の述語へ委譲）。
- **共有頂点化のスクリーン座標近接スナップ判定本体**（FR-31）: ドラッグ中・エッジハンドル生成中の頂点が、他頂点に**スクリーン座標距離**で近づいたときに共有頂点化候補になるかを判定する本体を、本ユニット（編集セッション）が所有する。具体的には次を本ユニットで結線する。
  - スナップ距離（既定 50px、設定変更可）は U16 が保持するアプリ全体設定（FR-110）から読み取り、本ユニットでハードコードしない（単一の真実源）。
  - 近接候補の絞り込みは U10 の空間インデックス問い合わせ（任意矩形に交差する近傍候補集合 API）で得た候補集合を起点とする。本ユニットはワールド座標の近傍候補を、現在のカメラ（ワールド↔スクリーン変換）でスクリーン座標へ写像し、ドラッグ中頂点のスクリーン位置との距離がスナップ距離以下の頂点を**スナップ候補**として決定する。
  - 近接判定は**ズームレベルに応じて変化**する（同一のスクリーン距離 50px は、ズームによって異なるワールド距離に対応する）。判定はスクリーン座標距離で行い、ワールド座標の固定距離で代用しない（FR-31）。
  - スナップ候補が決まったら、それを「共有頂点化する頂点ペアの決定」として U11 へ渡す。U11 は決定済みペアを受けて共有化コマンド（参加制限・結果不正検証つき）を実行する。**スナップされただけで離した場合は共有頂点化せず通常移動とする**（FR-31）：確定（解放）時点でスナップ候補が成立していた場合のみ共有化を編集案へ含め、ドラッグ途中で離脱した候補は破棄する。
  - スナップ候補（ドラッグ中の一時状態）は、確定・キャンセル・ツール切替・モード切替の全経路で破棄する（教訓 5.2）。
- **エッジハンドルで生成中の新頂点も対象**（FR-89）: エッジハンドルのドラッグで生成中の頂点も、エッジ滑り（衝突判定）・上記の近接スナップ判定・共有頂点化候補の対象とする。
- **押下→移動→解放シーケンスの全パス保証**（教訓 5.8）: クリック（移動なし）とドラッグ（移動あり）の双方で、押下で開始した一時状態が解放で必ず終了・破棄され、状態が正しく開始・更新・終了することを保証する。
- **確定トリガーの実装**（教訓 5.7）: 各編集フロー（移動・頂点編集・追加・削除）に「完了」のトリガーを定義・実装し、解放（または明示確定）で整合性維持プロセス（U13）を起動する。
- **一時 UI 状態の全経路破棄**（教訓 5.2）: ドラッグ中のプレビュー・スナップ候補・滑り状態などの一時状態を、確定・キャンセル（Escape 等）・ツール切替・モード切替のすべての経路で破棄する。

### やらないこと

- **整合性維持プロセス本体**（時間整合性検証・空間競合検出・競合解決ダイアログ駆動・差分ブーリアン調整・単一アンドゥ確定の固定順序オーケストレーション）。これは U13 の責務。本ユニットは確定時に編集案を U13 へ渡すだけ。
- **空間インデックスの構築・末端地物ペア排他検出アルゴリズム本体**。U10 の責務。本ユニットは近傍候補問い合わせと衝突述語を U10（が依存する幾何プリミティブ）経由で利用する。
- **リング階層の不変条件検証・リング削除時の交互構造再編**。U07 の責務。本ユニットは「3 点未満でリング削除」を判断したら再編を U07 へ委譲する。
- **共有頂点システム本体**（共有頂点化のスナップ判定・共有グループ管理・共有解除）。U11 の責務。本ユニットは共有頂点をドラッグした際の連動と、移動結果の共有化候補判定を U11 へ委譲する。
- **選択機構本体**（アクティブ地物の選択・頂点選択セット/コンテキストの管理・矩形範囲選択）。U22 の責務。本ユニットは U22 が確定した「現在の編集対象」を入力として受け取る。
- **頂点ハンドル／エッジハンドル／滑り境界ハイライトの実描画**（描画層 = `MapRenderer` の責務。本ユニットは描画層が参照する構造化データを供給するのみ）。
- **属性入力フォーム・プロパティパネル UI そのものの描画**（FR-83〜102 の UI 層責務。本ユニットは属性編集を「編集案の属性部分の更新」として扱う）。
- **ナイフツール（分割）・所属変更・結合などツリー位相を変える複合操作**（FR-44/46/50 等、別ユニット）。
- **複数頂点の同時移動（頂点選択セット全体の同一ベクトル移動）の選択管理**は U22 が担い、本ユニットは選択セットを受けて同一ベクトル移動を「単一の編集操作」として扱う（FR-80）。
- **アンドゥ・リドゥの二重スタック実装**（U12 の責務。U13 経由で単一アンドゥ単位として確定される）。

## 依存(dependsOn)

本ユニットは以下の公開インタフェース契約に依存する。依存ユニットの公開型（関数名・引数・戻り値型）は偶然の一致に頼らず、共有型を import して両側テストで固定する（教訓 5.33 / 5.34）。依存ユニットが未実装の場合は、本仕様に記す入出力契約に沿った型インタフェースを先に定義し、その型に対して操作フローと単体テストを実装する。

- **U22 — 選択機能（アクティブ地物・頂点選択セット/コンテキスト）**: 現在の編集対象（アクティブ地物 0/1 件、頂点選択セット、頂点選択コンテキストの所有地物）を提供する。本ユニットは「いま UI 上で選択されている対象」を第一候補に操作する（教訓 5.3 / 5.4）。複数頂点選択中の同一ベクトル移動の対象集合も U22 から受け取る（FR-80）。
- **U13 — 整合性維持プロセスの骨格**: 操作確定時に「現在のドメイン状態 + 編集案」を渡し、時間整合性検証 → 空間競合検出 → 競合解決 → 単一アンドゥ確定の固定順序プロセスを起動する（FR-61〜63）。本ユニットは編集案を組み立てて渡し、戻り値（確定済み／競合あり・要方針指定／拒否）を UI へ橋渡しする。確定時のフル整合性はすべて U13 を経由し、本ユニット内で確定処理を再実装しない。
- **U11 — 共有頂点システム**: 共有頂点のドラッグ時にそれを共有する全形状を連動させる（FR-30）。本ユニットがスクリーン座標近接で**決定した共有頂点化ペア**（FR-31 のスナップ判定本体は本ユニットが所有。下記 FR-31 のスコープ参照）を U11 へ渡すと、U11 は共有化禁止条件（同一リング内・同一線形内、ゼロ長エッジ・自己交差・階層破綻・末端重なりを生む場合、FR-32）を検証して共有化コマンドを実行する。U11 はスクリーン座標のスナップ距離計算・候補絞り込みは行わない（それは本ユニットの責務）。本ユニットはドラッグ結果と決定済みペアを渡し、共有連動結果・共有化の可否を受け取る。
- **U10 — 空間インデックス(RBush)と末端地物ペア排他検証**: エッジ滑りのドラッグ中、移動する面頂点の近傍にある他末端地物の候補を絞り込む問い合わせと、末端地物同士の重なり述語（境界接触は重なりに含めない、世界端ラップ対応）を提供する。あわせて FR-31 の近接スナップ判定で用いる**近傍頂点候補集合**（任意矩形に交差する候補参照集合 API、近接スナップ候補用途として U10 が単一インデックスで賄う）を提供する。ドラッグ中は「近傍候補のみ軽量判定」にこのインデックスを用いる（技術方針 R5 / R9）。
- **U16 — UI/セッション状態ストア(Zustand)とドメインブリッジ**: アプリ全体設定の共有頂点スナップ距離（既定 50px、FR-110）を保持・提供する。本ユニットの FR-31 近接スナップ判定はこの設定値を読み取って用い、距離をハードコードしない（設定値と編集挙動が同一値を使う単一の真実源）。
- **U07 — リング階層モデルと不変条件検証**: 面頂点削除で「3 点未満」になったリングの削除と交互構造再編（FR-24）、および穴リングが親内部に完全包含され外周と交差しない・飛び地が他外周と重ならないという制約（FR-25）の幾何検証を委譲する。面頂点ドラッグ中のリング内制約（穴/飛び地頂点の外周非交差）も U07 の述語で判定する。

> 依存の利用にあたっては、U10/U11 が依存する幾何プリミティブ（点とポリゴンの内外判定・線分交差判定・交差/包含/分離述語・座標量子化トレランス）を再発明せず、単一の真実源として共有すること（技術方針 2.9 / 開発ガイド §4 単一の真実源）。必要な述語が見当たらない場合は、本ユニット内に幾何述語を持ち込まず、不足を未解決課題文書に記録し結線方針を確認する（開発ガイド §2.11）。

## 実装方針(技術方針に沿う)

- **配置層**: 操作フロー（押下→移動→解放の状態機械、編集案の組み立て、ハンドル算出、エッジ滑りの拘束計算）は副作用のない判定可能な単位として `domain` 層に切り出し、Vitest 単独で実行できるようにする。Canvas のヒットテスト結線・ポインタイベント受理・描画層への滑り境界ハイライト連携は描画/UI 層に置き、ドメインの純粋ロジックへ依存させる（依存方向を `domain` へ内向き固定。技術方針 2.13 / 5.4）。
- **二段戦略の明示実装**（技術方針 R5 / R9、教訓 5.8）:
  - **ドラッグ中（軽量・ホットパス）**: 毎フレーム Immer の不変コピーを取らず、トランジェント（ドラフト保持）またはミュータブルな一時バッファで頂点座標を更新する。衝突判定は U10 の空間インデックスで近傍候補のみに絞り、移動する頂点に隣接する 2 辺と候補末端地物の境界エッジだけを線分交差判定する軽量経路に限定する。100ms 応答（NFR 5.1）を守る。
  - **操作確定時（フル整合性）**: 解放（または明示確定）で初めて、確定後形状を含む**正式な編集案**を組み立て U13 へ渡す。U13 が時間整合性・地図全体の末端排他をフル検証し、単一アンドゥ単位として確定する。確定までは共有ドメイン状態を破壊更新しない（教訓 5.22）。
- **押下→移動→解放の状態機械**（教訓 5.8 / 5.7）: ツールごとに「アイドル → 押下(対象ハンドル確定・開始状態設定) → 移動(プレビュー更新) → 解放(確定 or no-op 判定)」の状態遷移を明示的に表現する。
  - 押下で設定した一時状態（ドラッグ対象・開始座標・滑り状態・スナップ候補）は、解放で必ず解除する。
  - **移動が発生しなかったクリック**（押下と解放が同位置）でも整合的に終了させ、ドラッグ前提の処理を取りこぼさない（教訓 5.8 の「クリック考慮漏れ」）。
  - キャンセル（Escape）・ツール切替・モード切替でも同じ破棄経路を通す（教訓 5.2）。
- **エッジ滑りの衝突検出／応答分離**（教訓 5.38、FR-28 / FR-89）:
  - **衝突検出**: 開始点 → 移動先点の線分が、近傍候補末端地物の境界エッジを横切るか（線分交差）を判定し、最初の接触点（パラメータ t）を求める。移動先点が他末端地物内部にあるか（内外判定）だけで判定しない。
  - **衝突応答**: 接触後の残り移動を、接触したエッジの**接線方向成分のみ**として与え、法線方向（食い込み）成分を捨てる。これにより頂点はエッジに沿って滑る。
  - **既存接触の扱い**: 開始時点で既にエッジに接している（t=0）場合は新規衝突として止め直さず、食い込み成分だけ捨てて接線移動を許可する。
  - **尖り飛び越し**: 移動経路が他末端地物の尖った頂点（凸頂点）を飛び越えうる場合も、エッジ間衝突判定により最終位置で重なりが生じないように拘束する。複数エッジへの連続接触（角を回り込む滑り）も応答を反復適用して扱う。
  - **穴/飛び地の頂点**: 面の穴リング頂点・飛び地頂点も、自面の外周（親リング）と交差しない制約を U07 の述語で課したうえで滑らせる（FR-89）。
- **共有頂点との連動**（FR-30〜32、U11 経由）: 共有頂点をドラッグしたら U11 を通じて共有する全形状の該当頂点を連動更新する。地物移動ツールでも共有頂点は連動する（FR-88）。共有化の結果ゼロ長エッジ・自己交差・階層破綻・末端重なりが生じる移動は U11/U13 の検証で禁止される（FR-32）。
- **編集案の一体性**（FR-59）: 属性のみの編集であっても、内部では当該錨の完全状態（形状・属性・所属・親子関係・存在状態）を一体の編集案として U13 へ渡し、部分確定を許可しない。属性編集と頂点編集を別々のアンドゥ単位に割らない。
- **no-op ガード**（教訓 5.24）: 値が変わっていない確定（移動量ゼロのドラッグ、属性が baseline と同値の確定）では、整合性プロセス起動とアンドゥ履歴積みを行わない。baseline はフォーム同期と同一ソースから導出する。
- **構造変更後の選択再解決**（教訓 5.11）: 頂点削除でリング/地物が消える、頂点追加で新頂点が増えるなど対象が変わる操作では、確定後の選択状態を固定の全クリアで決めず、結果（残る頂点 ID・新規頂点 ID・削除された ID）から U22 と協調して再解決する。
- **無限横スクロール対応**（技術方針 R3）: 面頂点の座標は経度連続スカラーのまま扱い、世界端をまたぐ衝突判定は U10 のワールドラップ正規化（±360 度オフセット展開）に委譲する。本ユニットで折り返し処理を再発明しない。
- **エラー処理**（FR-115 / FR-117）: U13 が拒否（時間制約違反・制約違反・収束失敗等）を返した場合、日本語のユーザー向けメッセージへ写像して UI へ返す。想定外の内部不整合は「開発者へ報告してください」案内付きで扱う。

### 成果物・公開インタフェース（型レベルの契約）

実装者は以下の概念を型として定義すること（名称は実装で確定してよいが、契約の意味は固定）。

- ハンドル集合（EditHandles 相当）: 選択地物から算出した頂点ハンドル列・エッジハンドル列。各ハンドルはワールド座標・種別（頂点/エッジ）・由来（リング ID/頂点 ID/辺の両端 ID）を持つ不変値。
- ドラッグセッション（DragSession 相当）: 操作種別（地物移動/頂点移動/エッジハンドル追加）・対象（地物 ID・頂点 ID/辺・連動する共有頂点群）・開始座標・現在プレビュー座標・滑り状態（接触エッジ・滑り境界の識別情報）を持つ一時状態。確定/キャンセルで破棄される。
- 滑り結果（SlideResult 相当）: 拘束後の頂点位置（エッジに沿って滑った位置）・滑り境界の識別情報（描画層がハイライトに使う）を持つ。衝突なしのときは入力位置そのもの。
- 編集案（U13 の EditProposal 契約に適合）: 対象地物 ID・対象錨の時刻・確定したい完全状態スナップショット（形状・属性・親子関係・存在状態）を持つ不変値。確定時に U13 へ渡す。

公開する主操作（概念）:
- ハンドル算出: `(選択地物, 錨評価済み形状) → ハンドル集合`。
- 押下: `(ツール種別, ヒットしたハンドル/地物, 押下座標) → ドラッグセッション`。
- 移動（ドラッグ中・軽量）: `(ドラッグセッション, 現在座標, 近傍候補) → 新ドラッグセッション + 滑り結果`。共有連動・エッジ滑りの軽量判定を含む。
- 解放（確定）: `(ドラッグセッション, 現在ドメイン状態) → 編集案 → U13 起動 → プロセス結果`。no-op ガードで無変化なら何もしない。
- キャンセル/破棄: `(ドラッグセッション) → アイドル`（一時状態を全破棄）。

## 受け入れ基準(テスト可能な形で列挙)

以下はすべてテスト可能な形で満たすこと。純粋ロジック（ハンドル算出・滑り拘束・状態機械・編集案組み立て）は Vitest の「入力状態 → 操作 → 期待結果」で検証し、押下→移動→解放の通し挙動とハイライトは E2E でも確認する。

1. **ハンドル表示**（FR-87）: 選択地物に対して、各頂点に頂点ハンドル、各辺の中点にエッジハンドルが算出される。頂点ハンドルが移動/削除、エッジハンドルが新頂点追加の操作対象として区別され、由来リング/頂点が特定できることを検証する。面情報の穴リング・飛び地リングの各辺にもエッジハンドルが出ることを含む。
2. **地物移動ツール**（FR-88 / FR-30）: アクティブ地物の全頂点が同一ベクトルで平行移動し、共有頂点はそれを共有する全形状で連動して移動する。移動が単一の編集操作として U13 を経て確定されることを検証する。
3. **点編集**（FR-88 / FR-29）: 点情報の属性編集・移動・削除が動く。点情報の移動に末端排他・エッジ滑りが課されない（面情報と重なってよい）ことを検証する。
4. **線編集と 2 点未満削除**（FR-88）: 線情報の属性編集・頂点移動・エッジハンドルによる頂点追加・頂点削除が動く。頂点削除で残り頂点が 2 点未満になる場合に線情報自体が削除されることを検証する。線情報に末端排他・エッジ滑りが課されないことを含む。
5. **面編集と 3 点未満削除・リング/面削除**（FR-88）: 面情報の属性編集・頂点移動・頂点追加・頂点削除が動く。リングが 3 点未満になる場合にそのリングが削除され、交互構造の再編が U07 を通じて行われること、領土リングが 0 になる場合に面情報自体が削除されることを検証する。
6. **エッジ滑り（リアルタイム衝突判定・滑り境界ハイライト・尖り飛び越し）**（FR-28 / FR-89）:
   - ドラッグ中の面頂点を他末端地物の内部へ動かそうとすると、エッジで阻まれエッジに沿って滑り、最終位置で末端地物同士が重ならないことを検証する。
   - 滑り境界の識別情報が出力され、描画層がハイライトできることを検証する。
   - 移動経路が他末端地物の尖った頂点を飛び越えうる入力でも、重なりが発生しない（エッジ間衝突判定が効く）ことを検証する。
   - 穴リング頂点・飛び地頂点を外周と交差させようとする移動が外周非交差制約で拘束されることを検証する（U07 の述語経由）。
   - エッジハンドルのドラッグで生成中の新頂点も衝突判定・スナップ・共有化候補の対象になることを検証する。
7. **衝突検出と応答の分離**（教訓 5.38）:
   - 開始点 → 移動先の**線分**が境界エッジを横切る入力で衝突が検出される（移動先点が内部かどうかだけで判定していない）ことを検証する。
   - 既存接触（t=0）から接線方向へ動かす移動が、新規衝突として止め直されず、食い込み成分のみ捨てて接線移動が許可されることを検証する。
8. **二段戦略（ドラッグ中軽量→確定時フル整合性）**（R5 / R9 / 教訓 5.8）:
   - ドラッグ中は近傍候補のみの軽量判定で動き、毎フレーム不変コピーを取らない（確定前に共有ドメイン状態を破壊更新しない、教訓 5.22）ことを検証する。
   - 解放（確定）時にのみ整合性維持プロセス（U13）がフル整合性で起動され、単一アンドゥ単位として確定されることを検証する。
9. **押下→移動→解放の全パス保証**（教訓 5.8 / 5.7 / 5.2）:
   - ドラッグ（移動あり）とクリック（移動なし）の双方で、押下で設定した一時状態が解放で必ず解除されることを検証する。
   - キャンセル（Escape）・ツール切替・モード切替でも一時状態（プレビュー・スナップ候補・滑り状態）が破棄され、次操作へ引き継がれないことを「開始→キャンセル→再操作」「開始→確定→再操作」の連続で検証する。
   - 各編集フローに完了トリガーが実装され、UI からの呼び出しで確定が実際に走ることを検証する。
10. **編集案の一体性と no-op ガード**（FR-59 / 教訓 5.24）: 属性のみの編集でも完全状態が一体の編集案として確定され、部分確定が起きないこと。移動量ゼロや属性無変化の確定では整合性プロセス起動・履歴積みが行われない（幽霊 undo を作らない）ことを検証する。
11. **構造変更後の選択再解決**（教訓 5.11）: 頂点削除・追加・リング/地物削除後、選択状態が結果（残る/新規/削除 ID）から再解決され、固定の全クリアで決められないことを検証する。
12. **共有頂点化のスクリーン座標近接スナップ判定本体**（FR-31）:
   - ドラッグ中（およびエッジハンドル生成中）の頂点が、他頂点へスクリーン座標距離でスナップ距離（既定 50px、U16 設定）以下に近づくと共有頂点化候補（スナップ候補）として決定されることを検証する。近接判定がスクリーン座標距離で行われ、同一スクリーン距離が**ズームによって異なるワールド距離**に対応する（ズーム依存）ことを、異なるズームでの境界ケースで検証する。
   - スナップ候補の絞り込みに U10 の近傍候補集合 API を用い、スナップ距離を U16 の設定から読み取る（ハードコードしない）ことを検証する。
   - **スナップされただけで離すと共有頂点化されず通常移動になる**ことを検証する（解放時にスナップ候補が成立していた場合のみ共有化が編集案へ含まれ、途中で離脱した候補は破棄される）。
   - 決定したスナップ候補ペアが U11 へ渡され、共有化の参加制限・結果不正検証（FR-32）は U11 が行うこと（本ユニットはスナップ判定本体のみ所有し、共有化コマンドの検証は再実装しない）を境界テストで固定する。

## 関連要件(FR-id)

- **FR-28**: 末端地物の頂点編集時、他末端地物の内部へドラッグするとエッジで阻まれ沿って滑る。滑り境界をハイライトし、エッジ間衝突判定で尖り飛び越しでも重ならない。
- **FR-29**: 末端地物追加時に他末端内部へ頂点を置けない／線・点には排他性がない（本ユニットでは点・線編集に末端排他・エッジ滑りを課さないことで反映）。
- **FR-87**: 各頂点を頂点ハンドル（移動/削除）、各辺中点をエッジハンドル（新頂点追加）として提示する。
- **FR-88**: 地物移動ツール（全頂点同一ベクトル平行移動・共有頂点連動）、点/線/面編集（属性/頂点移動/追加/削除、線は 2 点未満・面は 3 点未満で削除）を提供し、完了時に整合性維持プロセスをトリガーする。
- **FR-89**: 面頂点編集で地図全体の他末端地物との衝突判定（エッジ滑り）をリアルタイム実施し、穴/飛び地頂点も外周非交差制約。エッジハンドルで生成中の頂点も衝突判定・スナップ・共有化対象。
- **FR-31**: 頂点を画面上（スクリーン座標）の距離で他の頂点に近づけると共有頂点化候補になり、近接判定はズームレベルに応じて変化する（既定スナップ距離 50px・設定変更可）。スナップされただけで離すと共有頂点化されず通常移動になる。— 本ユニット（編集セッション）がこのスクリーン座標近接スナップ判定の**本体**を所有し、U10 の近傍候補集合・U16 のスナップ距離設定を用いて候補を決定し、決定済みペアを U11 へ渡す（共有化の参加制限・結果不正検証は U11、FR-32）。
- 併せて FR-17（ハンドルのズーム非依存一定サイズ表示のためのワールド座標供給）・FR-30 / FR-32（共有頂点連動と禁止条件）・FR-59（完全状態の一体編集）・FR-61〜63（確定時の整合性維持と競合解決）・FR-73 / FR-94（単一アンドゥ単位）・FR-79〜82（選択状態の利用）・FR-115 / FR-117（日本語エラーメッセージ）を満たす土台と協調する。

## 注意点・既知の落とし穴(開発ガイドの教訓を踏まえる)

各教訓は着手前に該当節を引用し、今回の実装判断への適用を「適用:」として宣言してから着手すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **教訓 5.8（押下→移動→解放シーケンスを全パスで保証する）**: 適用 — クリック（移動なし）とドラッグ（移動あり）の双方で開始状態を解放で必ず解除し、移動が発生しなかったクリックの考慮漏れを作らない。受け入れ基準 9 で固定する。本ユニットの中核。
- **教訓 5.38（移動制約は線分交差で判定し、衝突検出と応答を分ける）**: 適用 — エッジ滑りは移動先点の内外判定だけでなく開始点→移動先の線分交差で衝突検出し、検出（最初の接触点）と応答（接線移動）を別処理にする。既存接触（t=0）は止め直さず食い込み成分だけ捨てる。受け入れ基準 6・7 で固定する。
- **教訓 5.7（完了トリガーを必ず実装する）**: 適用 — 各編集フローに「完了」トリガー（解放/明示確定）を実装し、ロジックがあっても UI から呼ばれず機能しない状態を作らない。受け入れ基準 9 で固定する。
- **教訓 5.2（一時的 UI 状態は全経路で破棄する）**: 適用 — ドラッグプレビュー・スナップ候補・滑り状態を確定・キャンセル・ツール切替・モード切替の全経路で破棄する。「開始→キャンセル→再操作」「開始→確定→再操作」の連続で検出する。
- **教訓 5.22（確定まで共有データを破壊的に更新しない）**: 適用 — ドラッグ中は一時バッファ/トランジェントで更新し、共有ドメイン状態は U13 の確定までは破壊更新しない。失敗時は何も反映しない。
- **教訓 5.24（確定ハンドラに no-op ガードを入れる）**: 適用 — 移動量ゼロ・属性無変化の確定で整合性プロセス起動と履歴積みを行わず、幽霊 undo エントリを作らない。baseline はフォーム同期と同一ソースから導出する。
- **教訓 5.11（構造変更操作後の選択は結果から再解決する）**: 適用 — 頂点削除/追加・リング/地物削除後は固定の全クリアにせず、結果 ID から U22 と協調して選択を再解決する。
- **教訓 5.25（仕様が限定した対象範囲を実装で広げない）**: 適用 — 末端排他・エッジ滑りは末端地物（面情報）同士のみ。「対称性」を理由に線・点へ排他やエッジ滑りを広げない（FR-29 を引用して止める）。集約地物を排他対象に含めない（FR-27）。
- **教訓 5.26（編集制約はコマンド確定前にも同じサービスで検証する）**: 適用 — ドラッグ中のリアルタイム拘束（候補表示・滑り）に加え、確定時にも U13/U10/U07 の同じ検証を必ず通す。UI が候補を隠してもショートカット・メニュー・直接呼び出し・undo/redo で不正状態が入りうる。拒否理由は日本語通知とテスト可能な戻り値の両方で返す。
- **教訓 5.3 / 5.4（操作対象は表示状態・現在の UI 文脈を第一候補にする）**: 適用 — 編集対象は U22 が確定した「いま選択されている地物・頂点」を使い、データソース全体やコレクション先頭を既定で操作しない。
- **教訓 5.1（集合演算は複数片を返す前提で扱う）**: 適用 — 確定後に U13 が走らせる差分調整は複数片を返しうる。本ユニットが確定後形状を編集案へ渡す際、片落とし前提の整形をしない（複数片・複数リングを許す形で渡す）。
- **教訓 5.18（空配列・空オブジェクトは真値である）**: 適用 — 「衝突候補 0 件」「滑り境界なし」「選択頂点 0 件」を論理和の短絡デフォルト補完で誤判定しない。長さ・有無を明示判定する。
- **教訓 5.14（重なる UI は入力を受ける層も同時に設計する）**: 適用 — 頂点/エッジハンドルやハイライトのオーバーレイが、背面の地物ヒットテストやパン操作を奪わないよう、描画順と入力受理層を同時に設計する。重なった状態で期待操作が通ることをテストする。
- **教訓 5.33 / 5.34（層をまたぐ契約は型と両側テストで固定する）**: 適用 — U07 / U10 / U11 / U13 / U22 の公開インタフェースを共有型で import し、関数名・引数・戻り値構造を両側テストで固定する。依存未実装時は本仕様の入出力契約に沿った型を先に定義する。
- **退化ケースの防御**（技術方針 R2）: 適用 — 自己交差・ゼロ長エッジ・極小スリバー・数値誤差で滑り/衝突判定が誤るのを防ぐため、幾何判定の前に座標量子化を通し、判定後に不変条件を再チェックする。境界の接触（接するが重ならない）を重なりと誤判定しないトレランス設計を初期に確立する（FR-26 / FR-28 は境界接触を重なりに含めない）。
- **無限横スクロール／経度シフトとの整合**（技術方針 R3）: 適用 — 世界端をまたぐ面頂点の衝突判定は U10 のワールドラップ正規化に委譲し、本ユニットで折り返し処理を再発明しない。経度は連続スカラーのまま受け渡す。
- **性能の段階戦略**（技術方針 R5 / R9）: 適用 — ドラッグ中は近傍候補のみの軽量判定で 100ms 応答を守り、確定時にフル整合性。計測で確定時のフル整合性が問題化した場合に限り、純粋関数のまま U13 経由で Web Worker へオフロードできるよう副作用を持たせない。
- **クリーンルーム原則**（開発ガイド §3.1）: 本仕様・実装ともに過去版や外部の既存実装に言及せず、必要な制約は v4 要件として直接記述・参照する。
- **失敗の教訓化**（開発ガイド §1.5 / §1.9）: 実装中に既存教訓で説明できない不具合の根本原因が見つかったら、完了前に開発ガイド §5 へ新教訓を追記し、回帰テストを同一作業内で追加する。

# U41 地物の表示制御・検索・エラー処理/ログ・日本語文言集約

本書は実装ユニット U41 の実装指示書である。実装者（別エージェント）はこの指示書だけを読んで着手できる。前提知識は本書の中に閉じて記述する。要件・技術方針・開発作法の根拠は本書末尾の「関連要件」「注意点・既知の落とし穴」に引用する。

本ユニットは time-map-app-4 のクリーンルーム文書群の一部である。過去版・他プロダクト・「以前のやり方」等の外部参照に依存せず、必要な制約はすべて v4 自身の要件・技術方針として直接記述する（開発ガイド §3.1）。

## 目的

time-map-app-4 における「閲覧・発見・横断的な健全性」を担う四つの機能群を、一つのユニットとして整合的に構築する。具体的には次を満たす。

1. **地物の表示制御**: 地図上に表示される地物群を、種別・階層深度・個別地物の各軸での表示/非表示の切替・不透明度調整・特定の種別/階層/地物集合の強調表示によって制御する（FR-113）。
2. **検索**: 地物を名前・説明・属性値で検索し、結果をハイライト・結果へジャンプする。検索対象・結果は「現在 UI 上に表示されている要素（表示状態）」を基準にする（FR-113、開発ガイド 教訓 5.3）。
3. **横断的なエラー処理・ログ・診断情報**: アプリ全体で発生しうる例外を捕捉し、ユーザーフレンドリーな日本語エラーメッセージ（必要に応じて「開発者へ報告してください」の案内付き）で提示し、エラーログの記録と診断情報の提供を行う（FR-115 / FR-117）。
4. **入力バリデーション/サニタイズの横断適用と日本語 UI 文言の集約**: すべてのユーザー入力・外部入力に対する検証と無害化を横断的に適用する基盤を提供し（FR-116）、UI 文言を日本語の定数モジュールへ集約する（i18n 抽象は設けず、将来のローカライズに備えて文言を一箇所へ集める。FR-115）。あわせてツールチップ/ヘルプ/例示による学習容易性を確保する（FR-118）。

本ユニットは「アプリ横断の発見・健全性・文言基盤」を担う。地図描画そのもの、地物データの定義・更新、各ダイアログ本体の業務ロジックは実装しない。それらは依存ユニット・後続ユニットが提供し、本ユニットはその上に「フィルター」「検索」「エラー/ログ」「バリデーション基盤」「文言集約」を載せる。

> 本ユニットには性質の異なる四つの責務が同居するが、いずれも「UI 横断で一貫した規約を提供する」点で共通する。文言集約・バリデーション・エラー処理は他の二機能（フィルター・検索）の実装にも使われる土台であり、同一ユニットに置くことで規約のドリフトを避ける。

## スコープ

### やること

#### 1. 地物の表示制御（FR-113）

- 右サイドバーの「階層/ツリー管理パネル（地物一覧）」区画（入れ物は依存ユニットが用意する）に嵌まる、地物の表示制御 UI とその状態を実装する。
- **表示/非表示切替**: 地物群を表示制御の軸（種別・階層深度・個別地物）単位で表示・非表示に切り替える。本アプリの面情報の階層・重ね順は地物自身の親子関係（および派生値である階層深度）から導出し、地物とは独立した順序属性や全体共通の重ね順序を持たない（FR-34）ため、表示制御が束ねる軸を本ユニットで明確に定義する（後述「実装方針/表示制御の軸の定義」）。少なくとも次の軸でのフィルターを提供する。
  - 地物種別（点情報・線情報・面情報）による表示切替。
  - 面情報の階層深度（FR-38 の派生値。最上位=0、子=親+1）に基づく表示切替（例: 「階層深度 N 以下のみ表示」）。これは FR-42 のグローバル階層深度スライダーによる集約表示とは別軸の「表示/非表示フィルター」であり、両者が干渉しないことを設計で担保する（後述）。
- **不透明度調整**: フィルター対象（種別／階層深度／個別地物・選択集合）の描画不透明度をスライダー等で調整する。不透明度は描画レイヤが購読する表示状態として持ち、ドメインの真実（地物データ）を書き換えない。
- **特定の種別/階層/地物集合の強調表示**: 指定した種別・階層・地物集合を強調し、それ以外を減衰（ディム）表示する。強調は一時的な表示状態であり、保存対象のスタイル（FR-100 の面スタイル）を破壊的に変更しない。
- これらフィルター状態（表示/非表示・透明度・強調）はセッション固有の表示状態として保持し、描画レイヤがそれを購読して反映する。フィルター状態の変更は描画購読者へ即時反映する。

#### 2. 検索（FR-113、教訓 5.3）

- サイドバー等から起動できる検索 UI を実装し、地物を**名前・説明・属性値**で検索する。
  - 名前: 各地物の基本属性の名前（FR-97）。
  - 説明: マークダウン形式の詳細文書（FR-98）を含むテキスト。検索対象はレンダリング前の原文テキストとし、マークダウン記法はサニタイズ済みの素テキストとして扱う（後述バリデーション/サニタイズと整合）。
  - 属性値: 各地物が持つ属性（種別ラベル FR-40、年代 FR-97 ほか）の値。
- **結果のハイライトと結果へのジャンプ**:
  - 検索結果一覧を表示し、各結果を地図上でハイライトする。
  - 結果を選択するとその地物へジャンプ（カメラを当該地物が見える位置・ズームへ移動し、現在時刻に存在するなら選択へ反映）する。
- **検索対象・結果は表示状態を基準にする（教訓 5.3、FR-113）**:
  - 検索の対象集合は「現在 UI 上に表示されている要素（現在時刻に存在し、本ユニットの表示制御で表示状態にある地物）」とする。データソース全体を無条件に走査して、非表示・非存在の地物を結果に混ぜない。
  - すなわち、現在時刻（FR-71）と表示制御（本ユニットの表示/非表示）の両方を反映した表示状態を検索の母集合とする。表示状態が変われば検索結果も同じ基準で再評価する。
  - ジャンプ先がジャンプ後の表示状態で存在しない（現在時刻に錨を持たない等）場合の扱い（選択しない・案内表示）を明確化する（教訓 5.5 と整合）。

#### 3. 全例外の捕捉・日本語エラーメッセージ・ログ/診断情報（FR-115 / FR-117）

- アプリ横断の**エラー境界とエラーハンドリング基盤**を提供する。
  - React UI ツリーに対するエラー境界（描画中の例外を捕捉して、アプリ全体のクラッシュを防ぎ、日本語のフォールバック UI を表示する）。
  - 非同期処理・イベントハンドラ・IPC 呼び出し境界・ファイル/外部入力処理など、React エラー境界が捕捉しない経路で発生する例外を捕捉する共通ハンドラ（グローバルエラーハンドラ）。
  - ドメイン処理（整合性維持・幾何演算・保存/読込等、別ユニットが実装）が返す「拒否理由・失敗」を、ユーザー通知へ変換する共通経路を提供する。本ユニットは通知の規約と表示を担い、各ドメイン処理のロジックは持たない。
- **日本語エラーメッセージ（FR-115）**: すべてのエラーメッセージは日本語で表示する。ユーザーの操作で回復可能なエラー（入力不正・検証拒否等）は具体的な対処を案内し、回復不能・想定外の内部エラーには「開発者へ報告してください」の案内を付与する。文言は文言定数モジュール（後述 5）に集約する。
- **エラーログの記録と診断情報（FR-117）**:
  - エラー発生時に、診断に必要な情報（発生時刻、エラー種別、メッセージ、スタック/原因、操作文脈の要約）をログとして記録する経路を提供する。
  - ログ記録はオフライン完結（FR-02）を守り、外部送信を行わない。記録先（メモリ内リングバッファ／ローカルファイル等）は技術方針に従い、ファイル I/O が必要な場合は依存する起動・シェル基盤の経路を通す（本ユニットはログ記録の規約とインタフェースを担い、物理 I/O は委譲する）。
  - 診断情報のスナップショット（直近のログ・アプリ/データ概況）をユーザーが取得・参照できる手段（ヘルプメニュー等からの診断情報表示）を提供する。診断情報には個人情報・プロジェクト内容の機微を不必要に含めない方針を明記する。
  - 「コンテキスト上の時刻（現在時刻）」と「実時間（記録時刻）」を混同しない。ログの記録時刻はシステム実時刻だが、操作文脈として記録する作中時刻は現在時刻（タイムラインが指す時刻）を参照する（教訓 5.15）。

#### 4. 入力バリデーション/サニタイズの横断適用（FR-116）

- すべてのユーザー入力・外部入力に対し、検証と無害化を横断的に適用するための**共通バリデーション基盤**を提供する。
  - 検証ロジックと型を二重定義しないよう、スキーマを単一宣言として書き、そこから型を導出する方式に従う（技術方針 2.10）。
  - 検証結果は「ユーザー通知用の日本語メッセージ」と「テスト可能な戻り値（成功/失敗＋理由）」の両方で扱う（教訓 5.26）。
  - マークダウン詳細文書（FR-98）等の外部由来テキストは無害化（サニタイズ）してから表示・検索に用いる。本ユニットは「検証・サニタイズを必ず通す共通入口（境界ヘルパー）」と「未検証入力が下流へ漏れない規約」を担い、各画面の入力フォーム本体や保存スキーマ本体は依存/後続ユニットが定義する（本ユニットはその検証を横断適用するための共通ヘルパーと運用規約を提供する）。
- 本ユニット自身が受け取る入力（検索クエリ・フィルター設定値・透明度の数値範囲等）にも、この共通基盤を適用する（自己適用）。

#### 5. 日本語 UI 文言の定数集約と学習容易性（FR-115 / FR-118）

- **UI 文言の定数モジュールへの集約（FR-115、技術方針 5.5）**:
  - 本ユニットが追加する UI 文言（フィルター/検索の UI ラベル・ヘルプ・例示、エラーメッセージ、ツールチップ）を日本語で文言定数モジュールへ集約する。
  - i18n の抽象レイヤ（翻訳キー解決・ロケール切替機構）は設けない。文言を一箇所へ集めるに留め、将来の FR-7.2（ユーザーローカライズ）に備える。
  - 文言集約モジュールの構造（カテゴリ分け・命名規約・文言の参照方法）を定義し、後続ユニットが同じ規約で文言を追加できる土台を提供する。先行ユニット（U20 等）が既に文言定数モジュールを設けている場合は、それを単一の真実源として再利用し、二重に文言モジュールを作らない（教訓 5.30 過少共有の戒め／単一の真実源）。
- **学習容易性（FR-118）**:
  - フィルター・検索・診断情報など本ユニットの UI 要素にツールチップ・ヘルプテキスト・入力例示を付与する。
  - 検索クエリの書式や属性検索の使い方などを例示で示す。エラーメッセージは「何が起きたか」と「どう対処するか」を含む形で記述する。

#### 6. テスト

- 上記すべてに対し、実装と同時に単体テストを書く（開発ガイド 1.9）。フィルター/検索のロジック・バリデーション・文言参照・エラー変換は UI から切り出して純粋関数として分離し、副作用なくテストできるようにする（教訓 5.41、NFR 5.8）。

### やらないこと

- **地図描画そのもの**（Canvas 2D / `MapRenderer` 実装、ワールド↔スクリーン変換、地物・グリッド・ラベルの描画）。本ユニットはフィルター/強調/透明度の「表示状態」を提供し、描画レイヤがそれを購読して反映する。描画ロジックは描画ユニットの責務。
- **地物データの定義・更新・ドメインの真実**（地物・頂点・リング・錨・ツリーの型と更新コマンド、アンドゥ/リドゥ）。本ユニットはそれらを読み取り・購読するのみで、変更しない。フィルター・検索・強調はドメインの真実を書き換えない（表示状態のみを扱う）。
- **FR-42 のグローバル階層深度スライダーによる集約表示（省略階層を集約形状で描画する機能）そのもの**。本ユニットの地物の表示制御（表示/非表示・不透明度・強調）は別軸であり、FR-42 の実装は描画/集約形状ユニットの責務。本ユニットは両者が干渉しない設計境界を引くのみ。
- **個別フォーカス（FR-43 の縦方向領域の深掘り表示）** の実装。本ユニットのスコープ外。
- **各画面の入力フォーム本体・保存データスキーマ本体・マークダウンレンダリング機構本体**（FR-98 / FR-103 等）。本ユニットは「検証・サニタイズを横断適用する共通基盤と運用規約」を担い、各フォーム/スキーマ/レンダラの実体は依存/後続ユニットが定義する。
- **整合性維持プロセス・競合解決・幾何演算・保存/読込などのドメイン処理ロジック**。本ユニットはそれらが返す失敗・拒否理由をユーザー通知へ変換する共通経路を提供するのみで、処理本体は持たない。
- **アプリのレイアウト骨格・モード/ツールバー・サイドバー区画の入れ物・標準メニュー構造・ショートカット基盤・ドラッグ可能パネル機構**（FR-111 / FR-112 / FR-75）。これらは依存ユニット（U20）が提供する。本ユニットはその枠組みの中に自機能を差し込み、メニュー項目（検索・診断情報表示等）を既存のメニュー/ショートカット基盤へ登録する。
- **Electron メイン/preload の IPC 実体・ウィンドウ管理・ファイル I/O の物理実装**。本ユニットはログ記録・診断情報がファイル永続化を要する場合に、依存する起動・シェル基盤の経路を通すのみ。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。依存先が提供する仕組みを再実装せず、購読・利用する（単一の真実源。開発ガイド §4「単一の真実源」、教訓 5.30 過少共有の戒め）。

- **U20（アプリレイアウトシェルとモード/ツールバー骨格）**: 本ユニットの UI（階層/ツリー管理パネル（地物一覧）区画の表示制御 UI・検索 UI・診断情報表示）を差し込む先となるレイアウト骨格を提供する。右サイドバーの「階層/ツリー管理パネル（地物一覧）」区画・「イベント一覧」区画の入れ物、標準メニュー（ファイル・編集・表示・ツール・ヘルプ）の構造と項目枠、ショートカット → コマンド ID の登録・解決・ディスパッチ基盤、ツールチップ共通機構、ドラッグ可能パネルの器、日本語 UI 文言の定数モジュール（既に集約方式が確立されているならそれ）、表示専用一括無効化ヘルパーを前提とする。本ユニットは検索・診断情報表示等を「コマンド ID」として U20 のメニュー/ショートカット基盤へ登録し、文言は U20 の文言定数集約規約に沿って追加する。

- **U32**: 右サイドバーの階層/ツリー管理パネル（地物一覧）／プロパティ系の区画、ないし地物データ・表示状態（現在時刻に有効な地物集合・属性・スタイル）へアクセスするための基盤を提供する依存ユニット。本ユニットの地物の表示制御・検索は、ここが公開する「現在の表示状態（現在時刻に存在する地物とその描画属性）」と「地物の属性・名前・説明への読み取り経路」の上に構築する。本ユニットはそれらを購読・読み取りするのみで、地物データを変更しない。

- **U16（UI/セッション状態ストアとドメインブリッジ）**: 現在時刻・選択（アクティブ地物・頂点選択セット）・カメラ（ズーム/中心/パン）・中心経度などの UI/セッション状態の薄いストアと、純粋ドメインコアを購読するブリッジを提供する。本ユニットのフィルター状態（表示/非表示・透明度・強調）はこのセッション状態層に置く（ドメインの真実とは分離した表示状態として扱う）。検索の「表示状態の母集合」は、U16 が保持する現在時刻と、U16/U32 が公開する表示状態から導出する。検索結果ジャンプは U16 のカメラ・選択アクションを通じて反映する。時刻が変わったとき選択・検索結果の有効性が再評価される経路（教訓 5.5）も U16 の再検証規約に整合させる。

> 注: 依存先 U20 / U32 / U16 が公開する正確な API 名・型・状態キーは、それらのユニットの成果物に従う。本ユニットは「レイアウト/メニュー/ショートカット/文言基盤（U20）」「階層/ツリー管理パネル（地物一覧）区画・地物表示状態/属性読み取り（U32）」「UI/セッション状態（現在時刻・選択・カメラ）と購読/更新（U16）」という能力に依存する。依存先 API が未確定の段階では、本ユニット内に明示的な境界インタフェース（adapter）を定義してそこへ依存先を接続し、未確定部分を局所化する。層をまたぐ契約（状態キー・コマンド ID・関数名・チャネル名・公開する表示状態の型）は偶然の一致に頼らず共有型・型付きラッパー・両側テストで固定する（教訓 5.33 / 5.34）。
>
> 実装着手時に、(a) U32 が公開する「現在の表示状態（現在時刻に有効な地物集合とその描画属性・名前・説明・属性値への読み取り）」、(b) U16 が公開する「現在時刻型・選択アクション・カメラ更新アクション・購読経路」、(c) U20 が公開する「メニュー/ショートカット登録 API・ツールチップ機構・文言定数モジュール・サイドバー区画マウント点・表示専用判定」の正確なシグネチャを確認し、本ユニットの adapter をそれに整合させること。

依存ユニットが前提とする土台（リポジトリ基盤・層分離・React 18・TypeScript strict・Electron セキュリティ設定・Zustand 状態層・純粋ドメインコア）は確立済みである前提とする。

## 実装方針（技術方針に沿う）

技術方針の採用スタックと層分離に厳密に従う。

### 配置と層分離

- 本ユニットのコードは原則 `ui` 層（React）に属する。`ui` 層は `domain`（純粋ドメインコア）を参照してよいが、`render` / `shell` への依存方向は技術方針の依存方向ルール（内向き固定）に従う。`domain` から `ui` を参照しない（技術方針 2.13）。
- フィルター・検索・バリデーション・エラー変換・文言参照のうち、UI から切り出せる純粋ロジック（検索のマッチング判定・表示状態母集合の導出・フィルター適用判定・透明度/強調の表示状態算出・バリデーション・エラー → メッセージ変換）は、React・Canvas・Zustand に依存しない純粋関数として分離し、Vitest 単体でテスト可能にする（技術方針 2.13、NFR 5.8、教訓 5.41）。
- 描画への反映は「表示状態（フィルター結果・透明度・強調・検索ハイライト集合）」を Zustand のセッション状態スライスとして公開し、描画レイヤ（U32/描画ユニット）が**購読のみ**で反映する。React の再レンダリングサイクルに地図描画状態を載せない（技術方針 2.3、NFR 5.1）。本ユニットは描画ロジックを持たず、描画が購読する表示状態の契約を提供する。

### 表示制御の軸の定義（FR-113 / FR-34 / FR-38 と整合）

- 本アプリの面情報の階層・重ね順は地物自身の親子関係（および派生値である階層深度）から導出し、地物とは独立した順序属性や全体共通の重ね順序を持たない（FR-34）。したがって本ユニットの表示制御は**フィルター対象を束ねる表示上のグルーピング軸**として定義し、ドメインに新たな序列を導入しない。少なくとも次を提供する。
  - **地物種別軸**: 点情報／線情報／面情報の表示切替。
  - **階層深度軸**: 面情報の派生値である階層深度（FR-38、最上位=0）を基準にした表示切替（例: 深度しきい値以下のみ表示）。階層深度は地物自身に保持せず親子関係から算出する派生値であり、本ユニットはその算出を依存ユニットの単一実装に委ね、再実装しない（単一の真実源）。
  - **個別地物軸**: 個々の地物を ID 単位で表示/非表示・強調する。
- 表示制御の軸の定義・各軸の識別子は型定義・定数を経由して扱い、表示文字列や思い込みで分岐しない（教訓 5.19）。

### 地物の表示制御と FR-42 の非干渉（FR-113 vs FR-42）

- 本ユニットの地物の表示制御（表示/非表示・不透明度・強調）は「どの地物を／どの見え方で描くか」を制御する表示状態である。一方 FR-42 のグローバル階層深度スライダーは「省略階層を集約形状として描画する集約表示」であり別軸である（FR-42 はやらないこと）。
- 両者が同時に作用したときの結合規則（例: フィルターで非表示にした地物は集約形状の算出母集合に含めるのか／表示時の透明度・強調をどう合成するか）を明示し、表示状態の最終算出を**単一の解決判定**へ集約する（教訓 5.29 派生形状は単一の解決判定で全経路を動かす）。描画・ヒットテスト・検索ハイライトが同じ表示状態解決を共有し、「描画されているのに検索に出ない／選択できない」等の対概念矛盾を作らない。

### 検索（FR-113、教訓 5.3 / 5.5）

- 検索の母集合は「表示状態（現在時刻に存在し、本ユニットの表示制御で表示状態にある地物）」とする。データソース全体を直接走査せず、表示状態（リアクティブ派生状態）を基準にする（教訓 5.3）。
- 名前・説明・属性値のマッチング判定は純粋関数として実装する。説明（マークダウン詳細文書）はサニタイズ済みの素テキストを検索対象とする（後述バリデーション/サニタイズ）。
- 結果ハイライト集合・現在のジャンプ対象は表示状態として保持し、描画レイヤが購読して反映する。
- ジャンプは U16 のカメラ更新アクションでカメラを移動し、対象が現在時刻に存在すれば U16 の選択アクションで選択へ反映する。存在しない場合は選択せず、日本語の案内を表示する。
- 現在時刻・表示制御が変化したら、検索結果の有効性を同じ表示状態基準で再評価する（教訓 5.5 / 5.6 結果状態での判定）。特定の入力経路に限定したゲートで再評価しない。

### エラー処理・ログ・診断情報（FR-115 / FR-117）

- React UI ツリーのエラー境界と、React 外（非同期・イベント・IPC・I/O 境界）のグローバルエラーハンドラを併設し、捕捉漏れの経路を作らない。「この経路でだけ捕捉する」とせず、想定される全経路を列挙して網羅する（教訓 5.6）。
- エラー → ユーザー通知の変換は単一の共通経路に集約し、表示文言は文言定数モジュールから引く。回復可能エラーは対処案内を、回復不能/想定外エラーは「開発者へ報告してください」を付与する（FR-115）。
- ログ記録はオフライン完結（FR-02）で外部送信しない。記録のインタフェース（log(level, message, context)）を提供し、ファイル永続化が必要な場合は依存する起動・シェル基盤の経路を通す（本ユニットは規約と入口を担い、物理 I/O は委譲）。
- ログの記録時刻（システム実時刻）と、操作文脈として記録する作中時刻（現在時刻＝コンテキスト時刻）を区別する（教訓 5.15）。
- 拒否理由・保存失敗など「ユーザーが次の判断に使うメッセージ」は、発生元と無関係なクリックやマウス操作で即時消去しない。消す契機は「同種操作の再試行」「明示的な閉じる」「成功した置換操作」へ限定する（教訓 5.12）。

### 入力バリデーション/サニタイズ（FR-116、技術方針 2.10 / 2.11）

- 検証はスキーマを単一宣言として書き型を導出する方式に従い、検証ロジックと型の二重定義を排除する（技術方針 2.10）。
- 検証・サニタイズを必ず通す共通入口（境界ヘルパー）を提供し、未検証の外部入力が下流（ドメイン・描画・検索）へ流入しない規約を定める（技術方針 2.10 / R8、教訓 5.26）。本ユニット自身の入力（検索クエリ・フィルター値・透明度数値範囲）にも自己適用する。
- マークダウン等の外部由来テキストの無害化（サニタイズ）を表示・検索の前に通す（技術方針 2.11、FR-116 / NFR 5.5）。サニタイズ機構本体（レンダラ）は依存/後続ユニットが持ち、本ユニットはそれを「必ず通す」横断規約と検索前処理の入口を担う。
- 検証拒否は「ユーザー通知用の日本語メッセージ」と「テスト可能な戻り値（成功/失敗＋理由）」の両方で返す（教訓 5.26）。

### 文言集約と学習容易性（FR-115 / FR-118、技術方針 5.5）

- UI 文言は日本語のみ・定数モジュールへ集約する。i18n 抽象は設けない（FR-115、技術方針 5.5）。U20 等が既に文言定数モジュールを確立しているなら、それを単一の真実源として再利用し、二重に作らない（教訓 5.30）。新規に追加する場合は、後続ユニットが同規約で文言を追加できるよう、カテゴリ分け・命名規約・参照方法を定義する。
- ツールチップ／ヘルプ／例示は U20 のツールチップ共通機構に乗せ、文言は文言定数から引く。検索書式・属性検索の使い方を例示で示す（FR-118）。

### テスト方針（技術方針 2.14 / NFR 5.8）

- Vitest で、検索マッチング・表示状態母集合導出・フィルター適用・透明度/強調の表示状態算出・バリデーション・エラー → メッセージ変換の「入力 → 期待出力」を直接比較する。
- 検索が「表示状態（現在時刻＋フィルター）」を母集合とし、非表示・非存在地物を結果に混ぜないことを回帰テストで固定する（教訓 5.3）。
- 現在時刻・フィルター変更時に検索結果が同じ基準で再評価されることを経路ごとに回帰テストする（教訓 5.5 / 5.6）。
- エラー捕捉は、React 描画中例外・非同期/イベント例外・拒否理由変換の各経路で日本語メッセージが表示されログが記録されることを検証する。
- バリデーションは、成功/失敗＋理由の戻り値と、対応する日本語メッセージが一対一であることを検証する（教訓 5.26 / 5.10）。
- E2E 寄りで検証しづらい範囲（ファイルへのログ永続化・IPC 連携）は、純粋関数化・アダプタ分離・モックで単体テスト対象にして補う（教訓 5.41）。

## 受け入れ基準（テスト可能な形で列挙）

以下はすべてテスト可能な形で満たすこと。テストは実装と同時に作成する（開発ガイド 1.9）。

1. **地物の表示制御が動く（FR-113）**
   - 地物種別（点／線／面）・面情報の階層深度（FR-38 派生値）・個別地物を軸に、地物の表示/非表示を切り替えられ、描画購読者へ即時反映されることを確認できる。
   - フィルター対象の不透明度を調整でき、描画購読者がそれを反映することを確認できる。
   - 特定の種別/階層/地物集合の強調表示で当該対象が強調され、それ以外が減衰表示されることを確認できる。
   - 表示制御（表示/非表示・不透明度・強調）はドメインの真実（地物データ・保存対象スタイル）を書き換えない表示状態であることを確認できる。
   - 本ユニットの地物の表示制御と FR-42 のグローバル階層深度集約表示が干渉せず、表示状態の最終算出が単一の解決判定に集約されている（描画・検索ハイライトが同じ表示状態を共有する）ことを確認できる（教訓 5.29）。

2. **検索が名前/説明/属性で結果ハイライト/ジャンプし、表示状態基準である（FR-113、教訓 5.3）**
   - 名前・説明（サニタイズ済み素テキスト）・属性値のいずれでも地物を検索でき、結果一覧が表示されることを確認できる。
   - 検索結果が地図上でハイライトされ、結果を選ぶと当該地物へジャンプ（カメラ移動）し、現在時刻に存在すれば選択へ反映されることを確認できる。存在しなければ選択せず日本語の案内が出ることを確認できる。
   - 検索の母集合が「現在時刻に存在し、表示制御で表示状態にある地物」に限定され、非表示・非存在の地物が結果に混入しないことを回帰テストで確認できる（教訓 5.3）。
   - 現在時刻または表示制御が変化すると、検索結果が同じ表示状態基準で再評価されることを、変化を起こす複数経路それぞれで確認できる（教訓 5.5 / 5.6）。

3. **全例外を捕捉し日本語エラーメッセージ表示・ログ記録/診断情報（FR-115 / FR-117）**
   - React 描画中の例外がエラー境界で捕捉され、アプリ全体がクラッシュせず日本語のフォールバック UI が表示されることを確認できる。
   - 非同期/イベント/IPC/外部入力境界で発生する例外がグローバルハンドラで捕捉され、日本語メッセージで通知されることを確認できる（捕捉経路を列挙し漏れがないことをテストで確認）。
   - 回復可能エラーには対処案内が、回復不能/想定外エラーには「開発者へ報告してください」が付与されることを確認できる。
   - エラー発生時に診断情報（発生時刻＝実時刻、エラー種別、メッセージ、原因、操作文脈の要約）がログに記録され、ユーザーが診断情報を参照できる手段があることを確認できる。ログがオフライン完結（外部送信しない）であることを確認できる。
   - 操作文脈に記録する作中時刻は現在時刻（コンテキスト時刻）であり、記録時刻（実時刻）と混同しないことを確認できる（教訓 5.15）。
   - 判断用メッセージ（拒否理由・失敗）が、発生元と無関係な操作で即時消去されないことを確認できる（教訓 5.12）。

4. **UI 文言が定数モジュールへ集約されている（FR-115）**
   - 本ユニットが追加する UI 文言（フィルター/検索の UI ラベル・ヘルプ・例示、エラーメッセージ、ツールチップ）が日本語で、文言定数モジュールに集約されていることを確認できる。
   - i18n 抽象レイヤ（ロケール切替・翻訳キー解決機構）を設けていないことを確認できる。
   - 先行ユニットの文言定数モジュールが存在する場合は、それを再利用し二重に文言モジュールを作っていないことを確認できる（単一の真実源）。

5. **ツールチップ/ヘルプ/例示で学習容易性を確保（FR-118）**
   - フィルター・検索・診断情報など本ユニットの UI 要素にツールチップ・ヘルプテキスト・入力例示が付与されていることを確認できる。
   - 検索クエリ書式・属性検索の使い方が例示で示され、エラーメッセージが「何が起きたか」と「どう対処するか」を含むことを確認できる。

6. **入力バリデーション/サニタイズの横断適用（FR-116）**
   - 本ユニットが受け取る入力（検索クエリ・フィルター値・透明度数値範囲）が共通バリデーション基盤で検証され、不正値が日本語メッセージで拒否され、テスト可能な戻り値（成功/失敗＋理由）で扱われることを確認できる（教訓 5.26）。
   - 外部由来テキスト（説明＝マークダウン）がサニタイズを通ってから表示・検索に用いられることを確認できる。
   - 検証スキーマが単一宣言で型を導出し、検証ロジックと型が二重定義されていないことを確認できる（技術方針 2.10）。

7. **層分離と React 切り離し（技術方針 2.3 / 2.13）**
   - 本ユニットのコードは依存方向ルールに違反しない（lint で確認できる）。フィルター・検索・バリデーション・エラー変換の純粋ロジックが Vitest 単体で実行できる形に分離されていることを確認できる。
   - フィルター/強調/検索ハイライトの描画反映は Zustand セッション状態の購読で行われ、地図描画状態を React state に載せていないことを確認できる。

### 適用宣言（AI 作業開始ゲート, 開発ガイド §1.6）

着手前に以下の教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として 1 文以上で宣言してから実装すること。引用と適用宣言を省略して着手してはならない。

- **教訓 5.3「操作対象は表示状態に限定する」**（引用: 「ユーザー操作の対象は『現在 UI 上に表示されている要素』に限定する。データソース全体を直接検索せず、表示状態（リアクティブ派生状態）を基準にする。」）。**適用**: 検索の母集合を「現在時刻に存在し、表示制御で表示状態にある地物」に限定し、データソース全体を無条件に走査して非表示・非存在地物を結果へ混ぜない。受け入れ基準 2 で母集合限定を回帰テストする。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.5「依存する状態は変化時に再検証する」**: 現在時刻・表示制御が変化したら、検索結果・ハイライト・ジャンプ対象の有効性を再評価し、非存在・非表示になった要素を結果から外す。ジャンプ先が現在時刻に存在しないときの扱いも明示する。
- **教訓 5.6「状態変化の検出は結果状態で判定する」**: 検索結果の再評価とエラー捕捉を「特定の入力経路だけ」でゲートしない。時刻・フィルターを変える全経路、例外が起きうる全経路（React 描画中／非同期／イベント／IPC／I/O）を列挙し、結果状態で判定して経路ごとに回帰テストする。
- **教訓 5.12「判断用メッセージを無関係な操作で消さない」**: 検証拒否・保存失敗など次の判断に使うメッセージを、発生元と無関係なクリック/マウス操作で即時消去しない。消す契機は「同種操作の再試行」「明示的な閉じる」「成功した置換操作」へ限定する。
- **教訓 5.15「タイムスタンプはコンテキスト上の時刻を参照する」**: ログ/診断情報で、操作文脈として記録する作中時刻はコンテキスト時刻（現在時刻）を参照し、記録時刻（システム実時刻）と混同しない。時刻源は一元管理する経路（U16）から取得する。
- **教訓 5.26「編集制約はコマンド確定前にも同じサービスで検証する」 / 5.10「選択状態は生の集合まで評価して網羅する」**: 入力検証は UI の候補表示だけでなく確定前にも同じ検証を通し、拒否理由をユーザー通知とテスト可能な戻り値の両方で扱う。検証メッセージと表示条件・戻り値を一対一に対応付ける。
- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」**: 表示状態（フィルター・透明度・強調・検索ハイライト・FR-42 集約表示との合成）の最終算出を単一の解決判定へ集約し、描画・ヒットテスト・検索ハイライトが同じ判定を共有する。判定のドリフトで「描画されているのに検索に出ない／選択できない」対概念矛盾を作らない。
- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / §4「単一の真実源」**: 文言定数モジュール・階層深度算出・表示状態解決・サニタイズ入口など「同じ判定/同じ基盤」は依存ユニットの単一実装を再利用し二重に作らない（過少共有の戒め）。一方、見た目が似たフィルター軸でも対象・除外規則が異なるなら安易に共有しない（過剰共有の戒め）。
- **教訓 5.19「分岐識別子は型定義・定数・ファクトリを経由する」**: 表示制御の軸・地物種別・エラー種別・コマンド ID・文言キーは表示文字列や思い込みで分岐せず、型定義・定数を経由する。新識別子の追加・改名時は作成・表示・検索・無効化の全経路で同じ値を使うテストを置く。
- **教訓 5.33 / 5.34（層をまたぐ契約・コンポーネント間契約を型で明示）**: 依存ユニット（U20 メニュー/ショートカット/文言/サイドバー区画、U32 表示状態/属性読み取り、U16 現在時刻/選択/カメラ）との契約（状態キー・コマンド ID・公開する表示状態型・関数名）は文字列の偶然一致に頼らず共有型・型付きラッパー・両側テストで固定する。依存先 API が未確定なら本ユニット内に境界インタフェース（adapter）を切って未確定部分を局所化する。
- **教訓 5.41「検証不能になった範囲は別手段で補う」**: ファイルへのログ永続化・IPC 連携・診断情報出力など E2E 寄りで検証しづらい範囲は、純粋関数化・アダプタ分離・モックで単体テスト対象にして補い、未検証のまま放置しない。
- **技術方針 2.3（React 再レンダリングと地図描画の分離, NFR 5.1）**: フィルター/強調/検索ハイライトの描画反映を React state に持たせると 60FPS が破綻する。表示状態を Zustand セッションスライスとして公開し、描画レイヤは購読のみで反映する規律を設計初期から徹底する。
- **技術方針 2.10 / R8（境界での検証強制）**: 未検証の外部入力（外部地図・ファイル・IPC・検索/フィルター入力）がドメイン・描画・検索へ流入しないよう、検証/サニタイズの共通入口を必ず通す規約を定め、漏れを構造的に塞ぐ。
- **オフライン完結（FR-02）**: エラーログ・診断情報・検索・フィルターのいずれも外部サービスへ接続・送信しない。診断情報に機微情報を不必要に含めない方針を文書化する。
- **クリーンルーム（開発ガイド §3.1）**: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-113 / 115 / 116 / 117 / 118 ほか）・技術方針として直接記述する。
- **やり残しの記録（開発ガイド §1.8）/ 教訓化（§1.5）**: 本ユニットで保留した判断（依存先 API 確定後の adapter 接続、ログ永続化の物理 I/O 経路の確定、FR-42 集約表示との合成規則の詳細など、後続へ波及するもの）は現状.md に記録する。新たに根本原因を教訓化すべき事象があれば開発ガイド §5 へ追記してから完了とする。

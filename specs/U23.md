# U23 追加ツール(点/線/面・仮表示・取消/キャンセル・親選択・確定で整合性)

## 目的

地図上のクリック操作で点情報・線情報・面情報の新規地物を作成し、形状確定後にプロパティ入力フォームを経て「現在のタイムライン時刻を開始時刻とする歴史の錨」として記録する追加ツール一式を実装する。保存時には整合性維持プロセス（U13）をトリガーし、空間・時間整合性を満たした形でのみ確定する。

本ユニットの中核は、追加モードにおける一連のインタラクションフロー（開始 → クリックで頂点配置 → 形状確定 → プロパティ入力 → 保存／キャンセル）を、一時 UI 状態の生成・更新・破棄まで含めて取りこぼしなく組み立てることである。追加中は確定済み地物と異なる仮スタイルで形状をプレビュー表示し、面はクロージング線を半透明で示し、最後の頂点を 1 つずつ取り消せ、追加全体をキャンセルでき、グリッドスナップを任意で利用できる。面追加時には親なし／親となる面情報を随時選択でき、選択した場合は新規面の親子関係を同一操作として記録する。追加中の頂点も衝突判定・スナップ・共有化の対象として扱う。

このフローでは、一時 UI 状態を**開始・確定・キャンセル・ツール切替・モード切替の全経路で破棄する**こと（教訓 5.2）と、**「保存（完了）」のトリガーを UI から確実に発火させる**こと（教訓 5.7）を不変条件として実装する。形状確定後の保存処理は、編集案を組み立てて整合性維持プロセス（U13）へ引き渡す調停に徹し、幾何ブーリアン演算・時間正規化・空間競合検出・コマンド確定の具体アルゴリズムは下位ユニットへ委譲する。

## スコープ

### やること

- **点／線／面の追加ツール（FR-76）**: 追加モードのツールバーから「点追加」「線追加」「面追加」の各ツールを選択でき、地図上のクリックで形状を作成する。
  - 点情報: 1 点のクリックで形状を確定する。
  - 線情報: 2 点以上のクリックでパスを構成し、明示的な完了操作で形状を確定する（最低 2 頂点を満たさない確定は拒否する）。
  - 面情報: 3 点以上のクリックでリングを構成し、明示的な完了操作（クロージング＝始点に閉じる）で形状を確定する（最低 3 頂点を満たさない確定は拒否する）。
- **形状確定後のプロパティ入力フォーム（FR-76）**: 形状が確定したら、地物の基本属性（名前・色情報など、FR-97）を入力するフォームを提示する。フォームの保存操作で当該地物の最初の錨を確定する。
- **現在時刻を開始時刻とする錨記録（FR-76）**: 保存時、**現在のタイムライン時刻（UI 文脈上の現在時刻）を開始時刻とする歴史の錨**として地物を記録する。開始時刻はシステム時計ではなく、必ずタイムライン上の現在時刻を参照する（教訓 5.15）。
- **保存で整合性維持プロセスをトリガー（FR-76）**: 保存時、編集案（対象地物・開始時刻・確定したい完全状態スナップショット）を組み立てて整合性維持プロセス（U13）へ引き渡す。U13 が空間競合（末端地物同士の重なり）を返した場合は確定を一時停止し、競合解決フローへ制御を委ねる。整合性を満たした場合のみ、単一アンドゥ単位として確定する（FR-73 / FR-94）。
- **仮表示・追加中スタイル（FR-78）**: 追加中のオブジェクトを、確定済み地物とは視覚的に区別できる仮スタイルで描画する。
- **面のクロージング線半透明表示（FR-78）**: 面追加中、最後に置いた頂点から始点へ戻る閉合線（クロージング線）を半透明で表示し、確定後の輪郭との違いを示す。
- **頂点 1 つずつの取消（FR-78）**: 直前に配置した頂点を 1 つずつ取り消せる（Ctrl+Z 等）。取消は配置済み頂点が 1 つ以上ある間のみ有効とし、頂点が 0 になった状態でさらに取り消そうとした場合の振る舞いを定義する（後述「注意点」）。
- **追加全体のキャンセル（FR-78）**: 追加中の操作全体をキャンセルできる（Escape 等）。キャンセル時は配置済み頂点・仮表示・親選択などの一時状態をすべて破棄し、何も記録せずに追加開始前の状態へ戻す。
- **グリッドスナップ（任意・FR-78）**: グリッドスナップのオン/オフを切り替えられ、オン時はクリック位置を緯線・経線グリッド（FR-13 のグリッド設定に整合）へスナップする。
- **面追加時の親選択（FR-77）**: 面情報追加時、指定時刻（現在のタイムライン時刻）に新規面の存在期間を覆える既存面情報があれば、追加中に「親なし（最上位領域へ）」または「親となる面情報」を随時選択できる。親を選択した場合、新規面の親子関係を**同じ操作（同一アンドゥ単位）**として記録する。
- **追加中頂点の衝突判定・スナップ・共有化対象化（FR-78 / FR-29 / FR-31）**: 追加中に配置する頂点も、他の末端地物との衝突判定（末端地物の内部には頂点を設置できない、FR-29）・近接スナップ（FR-31）・共有頂点化（FR-30〜FR-33）の対象として扱う。これらのリアルタイム判定は下位ユニット（末端排他・近傍候補は U10、スクリーン座標近接スナップ判定本体は U24 編集セッション、共有化コマンドは U11）へ委譲し、本ユニットは追加フローからそれらを呼び出して結果を仮形状へ反映する。FR-31 のスナップ判定本体・スナップ距離の適用は本ユニットで再実装しない。
- **一時 UI 状態の全経路破棄（教訓 5.2）**: 開始・確定（保存成功）・キャンセル・ツール切替・モード切替のいずれの経路でも、追加中の一時 UI 状態（配置済み頂点列・仮表示・カーソル追従プレビュー・親選択・グリッドスナップのドラフト等）を明示的に破棄する。
- **完了トリガーの実装（教訓 5.7）**: 線・面の形状確定（クロージング/完了操作）と、プロパティフォームの保存（錨確定）の両方について、UI からロジックを呼び出す「完了」トリガーを実際に配線する。

### やらないこと

- 整合性維持プロセス本体（固定順序オーケストレーション・時間整合性検証・空間競合検出・差分ブーリアン調整・一括確定）の実装。これは U13 とその配下の責務であり、本ユニットは編集案を渡して結果を受け取るだけ（U13 への委譲）。
- 競合解決モーダルダイアログそのものの描画・ミニマッププレビューの描画（競合解決 UI 側の責務）。本ユニットは保存時に U13 を起動し、U13 が「競合あり」を返したら競合解決フローへ制御を渡す接続のみを担う。
- 既存地物の頂点編集・移動・削除（編集ツールの責務、FR-87〜FR-89）。本ユニットは新規追加のみを扱う。
- ナイフツール（分割）・所属変更フロー・合体（結合）（FR-90 系 / FR-46 系 / FR-50 系）。面追加時の親選択は新規面に対する親子関係の初期付与であり、既存地物のツリー位相変更（所属変更フロー）とは別物（教訓 5.27 / 5.30）。
- 衝突判定・エッジ滑り・近接スナップ・共有頂点化の**アルゴリズム実装**。本ユニットは追加中頂点をこれらの判定対象として渡し、結果を仮形状へ反映するクライアントに徹する。
- 穴・飛び地の追加（FR-22）。本ユニットは新規地物の最初の外周リング（面の場合）を作るところまでを扱い、穴/飛び地追加ツールは別ユニットの責務。
- タイムライン UI・現在時刻管理そのものの実装（U21 の責務）。本ユニットは現在時刻を読み取って錨開始時刻に使うのみ。

## 依存(dependsOn)

本ユニットは以下に依存する。依存ユニットの公開インタフェース（関数名・引数・戻り値型）は偶然の一致に頼らず共有型・両側テストで固定する（教訓 5.33）。依存ユニットが未実装の場合は、本仕様に記す入出力契約に沿った型インタフェースを先に定義し、その型に対して追加フローと単体テストを実装する。

- **U20 — アプリレイアウトシェルとモード/ツールバー骨格（FR-75 前提）**: 追加モードと編集モードを排他的に切り替えるモード機構と、追加モードで表示されるツール群（点/線/面追加）の選択状態を提供する。本ユニットは「追加モードで点/線/面追加ツールが選択されている」状態を起点にフローを開始し、ツール切替・モード切替のイベントを受けて一時状態を破棄する。
- **U13 — 整合性維持プロセスの骨格（FR-61〜FR-63）**: 保存時に編集案を渡して起動する整合性維持プロセス。本ユニットは U13 のプロセス開始関数 `(現在状態, 編集案) → プロセス結果` を呼び、戻り値の判別共用体（`確定済み` / `競合あり・要方針指定` / `拒否`）で分岐する。`確定済み` なら追加完了、`競合あり` なら競合解決フローへ制御を渡す、`拒否` なら日本語メッセージを提示して保存を中断する。
- **U21 — タイムラインUI／現在時刻（FR-64〜FR-72 の時刻参照）**: UI 文脈上の現在時刻（年・月・日を含む完全な時間値）を提供する。本ユニットは保存時の錨開始時刻として現在時刻を読み取る。時間値は分解した一部だけでなく完全値で受け渡す（教訓 5.16）。
- **U22 — 選択システム（FR-79〜FR-82）**: 追加完了後に新規地物を選択状態へ載せる先（アクティブ地物・頂点選択コンテキスト）を提供する。本ユニットは追加完了後、結果コマンドが返す新規地物 ID から選択を再解決する（教訓 5.11）。

> 本ユニットは `domain` 層の純粋ロジック（編集案組み立て・形状検証・錨生成）と、`ui` 層の追加インタラクション（ツール選択・クリック収集・仮表示駆動・フォーム）と、`render` 層の仮表示描画にまたがる。層境界を越える契約は共有型と両側テストで固定する（教訓 5.33 / 5.34）。

## 実装方針(技術方針に沿う)

- **層分離**: 形状の妥当性検証（線は 2 点以上・面は 3 点以上・自己交差なし等）、編集案（最初の錨）の組み立て、現在時刻からの錨開始時刻決定は、副作用のない `domain` 層の純粋関数として実装し、Vitest 単独で実行できること。追加インタラクション（ツール選択・クリック収集・取消/キャンセルのキーハンドリング・親選択 UI・プロパティフォーム）は `ui` 層（React）に置き、仮表示の描画は `render` 層（Canvas 2D・`MapRenderer`）に置く。追加中の一時状態は、地図描画状態として Zustand と命令的 Canvas 側に保持し、React の再レンダリングサイクルに毎クリックの頂点列を載せて 60FPS を破綻させない（技術方針 2.3 / 2.5）。
- **一時 UI 状態の単一の真実源**: 追加中の状態（配置済み頂点列・クロージング線の有無・カーソル追従プレビュー点・グリッドスナップ ON/OFF・選択中の親候補・現在の追加ツール種別）を 1 つの「追加セッション」状態としてまとめて保持し、開始でのみ生成、破棄経路でのみ消去する単一の真実源にする。判定ロジックの分散を避ける（開発ガイド 4. 単一の真実源）。
- **一時状態の全経路破棄（教訓 5.2）**: 追加セッション状態の破棄を、(a) 追加開始（前回の残存があれば開始時に必ずクリア）、(b) 保存成功による確定後、(c) Escape 等の全体キャンセル、(d) 追加ツール間の切替（点→線→面など）、(e) 追加モードから編集モード/表示モードへのモード切替、のすべての経路に配線する。破棄は 1 つの共通ヘルパー（追加セッションのリセット関数）に集約し、各経路がそれを呼ぶ。残存状態が次回操作へ暗黙に引き継がれないことを保証する。
- **完了トリガーの明示配線（教訓 5.7）**: ロジック側に「形状確定」「錨保存」のメソッドがあっても、UI からの呼び出しがなければ機能しない。よって、線/面の完了操作（クロージング・ダブルクリックや完了ボタン等）と、プロパティフォームの保存ボタン（兼 Enter 確定）の両方を、対応するロジック呼び出しへ確実に配線する。完了トリガーが存在し発火することを E2E で確認する。
- **現在時刻参照（教訓 5.15 / 5.16）**: 錨の開始時刻は U21 が管理する UI 文脈上の現在時刻から取得し、システム時計を使わない。現在時刻は年・月・日を含む完全な時間値で受け取り、分解した一部だけを錨へ渡さない。
- **編集案の一体性（FR-59）**: 保存時の編集案は、当該地物の最初の錨の完全状態スナップショット（形状・属性・親子関係＝親選択結果・存在状態）を一体として組み立てる。属性と形状と親子関係を別々のコマンドに分割せず、1 つの不可分な編集案として U13 へ渡す。
- **親選択の同一操作記録（FR-77 / FR-94）**: 面追加で親を選択した場合、新規面の親子関係を最初の錨に含め、U13 を通じて**追加と親子関係付与を単一アンドゥ単位**として確定する。親選択を別操作・別アンドゥ単位に割らない。親なし選択時は最上位フラグ真（親領域なし）で記録し、「最上位フラグ真」と「親領域なし」の同値（FR-39）を満たす。
- **親候補の妥当性（FR-77 / FR-48）**: 面追加時の親候補は「指定時刻（現在時刻）に新規面の存在期間を覆える既存面情報」に限定する。候補列挙は表示状態に基づき（教訓 5.3）、新規面自身は循環参照の対象にならない（新規生成のため）。親候補は所属変更フローの候補とは制約が異なるため、候補一覧ロジックを安易に共有しない（教訓 5.30）。
- **追加中頂点の制約反映（FR-29 / FR-31 / FR-78）**: クリックで頂点を置く際、(a) 末端地物の内部には頂点を設置できない（FR-29、線/点には排他なし）、(b) 近接スナップ候補があればスクリーン座標距離（既定 50px、FR-31 / FR-110）でスナップ、(c) スナップ先が共有頂点化候補なら共有化対象とする、をリアルタイム判定する。判定アルゴリズムは下位ユニットへ委譲し、本ユニットは結果（許可/不許可・スナップ後座標・共有候補 ID）を受けて仮形状へ反映する。ドラッグ/連続移動中は近傍候補（RBush）だけの軽量判定とし、確定時に U13 でフル整合性を実行する二段戦略（技術方針 R5 / R9）。
- **グリッドスナップ（FR-78 / FR-13）**: グリッドスナップ ON 時は、クリック位置をグリッド設定（間隔・FR-13）に整合する格子点へスナップする。共有頂点スナップとグリッドスナップの優先順位を明確に定義する（後述「注意点」）。
- **仮スタイル描画（FR-78 / FR-17）**: 追加中の頂点・辺・カーソル追従プレビュー・面のクロージング線は、確定済み地物と異なる仮スタイルで描画する。点・線の見た目サイズはズーム非依存で一定（FR-17）。クロージング線は半透明。これらは `render` 層が追加セッション状態を購読して描画し、React 再レンダリングを介さない。
- **無限横スクロール対応（技術方針 R3）**: 頂点座標は経度を連続スカラーのまま保持し、本ユニットでは独自のラップ正規化を行わない。世界端をまたぐ衝突判定・空間整合性のラップ処理は下位ユニット（衝突判定・U13/U10）側で行う前提とする。
- **確定までの非破壊（教訓 5.22）**: 形状確定〜プロパティ入力〜保存の途中段階では、共有ドメイン状態（確定済み地物集合）を破壊的に更新しない。U13 が `確定済み` を返して初めてドメインへ反映し、`拒否`・キャンセル時は何も記録しない。
- **完了後の選択再解決（教訓 5.11）**: 追加完了後、U13/コマンド結果が返す新規地物 ID から選択状態（アクティブ地物または頂点選択コンテキスト、U22）を再解決する。固定の全クリアで決めない。
- **エラー処理（FR-115 / FR-117）**: 形状不成立（線 2 点未満・面 3 点未満・自己交差）・親候補不適合・U13 の `拒否` などは、日本語のユーザー向けメッセージで提示する。判断用メッセージは無関係なクリックで即時消さない（教訓 5.12）。重大な内部不整合は「開発者へ報告してください」案内を付す。

### 成果物・公開インタフェース（型レベルの契約）

実装者は以下の概念を型として定義すること（名称は実装で確定してよいが、契約の意味は固定）。

- 追加ツール種別: 点 / 線 / 面 の判別共用体。表示文字列で判定せず型・定数・ファクトリを経由する（教訓 5.19）。
- 追加セッション状態（AddSession 相当）: 現在の追加ツール種別・配置済み頂点列・カーソル追従プレビュー点・グリッドスナップ ON/OFF・（面のみ）選択中の親候補（親なし／親 ID）・（面のみ）クロージング可能か、を持つ可変の一時 UI 状態。生成は開始時のみ、破棄は全経路の共通リセットで行う。
- 形状確定結果（ShapeDraft 相当）: 確定した頂点列（点 1 / 線 2+ / 面 3+ のリング）と種別を持つ不変値。形状妥当性検証を通過したもののみ生成される。
- 追加編集案: 形状確定結果＋プロパティ入力＋現在時刻（錨開始時刻）＋（面のみ）親子関係から組み立てた、地物の最初の錨の完全状態スナップショット（U13 の編集案契約に適合）。
- 公開する主操作（概念）:
  - セッション開始: 追加ツール選択時に呼ばれ、既存セッションがあれば破棄してから新規生成。
  - 頂点追加 / 頂点取消 / セッションキャンセル: クリック・Ctrl+Z・Escape 等から呼ぶ。
  - 形状確定: 線/面の完了操作から呼ぶ。妥当性検証を通せばプロパティ入力段階へ遷移。
  - 保存（錨確定）: プロパティフォーム保存から呼ぶ。編集案を組み立て U13 を起動し、結果で分岐。

## 受け入れ基準(テスト可能な形で列挙)

`domain` 層の検証は Vitest で「入力 → 関数呼び出し → 期待結果」を、UI/描画にまたがるフローは Playwright for Electron の E2E で検証できる形で満たすこと。

1. **点/線/面の作成と錨記録（FR-76）**: 追加モードで点追加ツールを選び 1 点クリックすると点情報が作成され、線追加ツールで 2 点以上クリックして完了すると線情報が、面追加ツールで 3 点以上クリックして完了すると面情報が作成される。各々で形状確定後にプロパティ入力フォームが表示され、保存すると**現在のタイムライン時刻を開始時刻とする錨**として地物が記録されることを検証する。線 2 点未満・面 3 点未満での確定が拒否されることも検証する。
2. **保存時の整合性維持プロセス起動（FR-76）**: 保存操作で U13 のプロセス開始関数が編集案を伴って呼ばれることを検証する。U13 が `確定済み` を返したら追加が完了し新規地物が選択される、`競合あり` を返したら競合解決フローへ制御が渡り確定が一時停止する、`拒否` を返したら日本語メッセージが提示され何も記録されない、の各分岐を検証する。
3. **錨開始時刻が現在時刻（FR-76 / 教訓 5.15）**: 異なるタイムライン時刻で同種の追加を行うと、それぞれ当該時刻を開始時刻とする錨が記録される。システム時計（実時刻）には依存しないことを検証する。
4. **仮表示・クロージング線・取消・キャンセル・グリッドスナップ（FR-78）**:
   - 追加中の頂点・辺が確定済み地物と異なる仮スタイルで描画される。
   - 面追加中、最後の頂点から始点へのクロージング線が半透明で表示される。
   - Ctrl+Z 等で最後に置いた頂点が 1 つずつ取り消され、頂点数が正しく減る。
   - Escape 等で追加全体がキャンセルされ、配置済み頂点・仮表示・親選択がすべて消え、何も記録されない。
   - グリッドスナップ ON 時、クリック位置がグリッド格子点へスナップされ、OFF 時はスナップされない。
5. **面追加時の親選択と同一操作記録（FR-77）**: 面追加時、指定時刻に新規面の存在期間を覆える既存面があれば「親なし」または親面を選択でき、親を選んで保存すると新規面の最初の錨に親子関係が含まれ、**追加と親子関係付与が単一アンドゥ単位**として記録される（1 回のアンドゥで親子関係ごと取り消される）ことを検証する。親なし選択時は最上位フラグ真で記録される。
6. **一時 UI 状態の全経路破棄（教訓 5.2 / FR-78）**: 次の連続操作で、いずれも追加中状態が次回へ引き継がれないことを E2E で検証する。
   - 「追加開始 → 数点配置 → キャンセル → 再度追加開始」: 再開始時に頂点列が空であること。
   - 「追加開始 → 数点配置 → 保存（確定） → 再度追加開始」: 再開始時に頂点列が空であること。
   - 「追加開始（面） → 数点配置 → 別の追加ツールへ切替（線）」: 切替後に頂点列・親選択が空であること。
   - 「追加開始 → 数点配置 → 編集モード/表示モードへ切替」: 切替後に追加セッションが破棄されていること。
7. **完了トリガーの存在と発火（教訓 5.7）**: 線/面の完了操作（クロージング/完了ボタン等）とプロパティフォームの保存操作の双方が、UI からロジック呼び出しへ配線され実際に発火することを E2E で検証する（ロジックにメソッドがあるだけで UI から呼ばれない状態を回帰として弾く）。
8. **追加中頂点の衝突判定・スナップ・共有化対象化（FR-29 / FR-31 / FR-78）**: 面追加中、他の末端地物の内部へ頂点を置こうとすると設置が阻まれること（線/点は面と重なれること）、近接する既存頂点へスクリーン座標距離でスナップされ共有化候補として扱われることを検証する。
9. **完了後の選択再解決（教訓 5.11）**: 追加完了後、新規生成された地物がアクティブ地物（または頂点選択コンテキスト）として選択されることを、コマンド結果の新規 ID から再解決して検証する。

## 関連要件(FR-id)

- **FR-76（must）**: 点（1 点）/線（2 点以上）/面（3 点以上）の追加ツールを提供し、クリックで形状作成 → 確定後にプロパティ入力フォーム → 保存で現在時刻を開始時刻とする錨として記録し、整合性維持プロセスをトリガーする。
- **FR-77（should）**: 面追加時、指定時刻に新規面の存在期間を覆える既存面があれば親なし／親面を随時選択でき、選択時は親子関係を同一操作として記録する。
- **FR-78（should）**: 追加中オブジェクトの仮スタイル表示・面のクロージング線半透明表示・頂点 1 つずつの取消・追加全体のキャンセル・グリッドスナップ（任意）。
- 併せて FR-29（追加中頂点の末端地物内部設置禁止・線点に排他なし）・FR-31（近接スナップ）・FR-30〜FR-33（共有頂点化）・FR-59（完全状態の一体編集）・FR-73 / FR-94（単一アンドゥ単位・複合操作の不可分性）・FR-97（基本属性・色情報）・FR-39（最上位フラグと親なしの同値）・FR-115 / FR-117（日本語エラーメッセージ）を満たす土台を提供する。

## 注意点・既知の落とし穴(開発ガイドの教訓を踏まえる)

- **教訓 5.2（一時的 UI 状態は全経路で破棄する）**: 適用 — 追加セッション状態（配置済み頂点・仮表示・親選択・グリッドスナップのドラフト）を、開始・確定・キャンセル・ツール切替・モード切替の全経路で共通リセット関数により破棄する。残ると次回操作へ暗黙引き継ぎされ意図しない値で確定できてしまう。受け入れ基準 6 で「選択 → キャンセル → 再作成」「選択 → 確定 → 再作成」を含む全経路を固定する。
- **教訓 5.7（完了トリガーを必ず実装する）**: 適用 — 線/面の形状確定とプロパティ保存の「完了」トリガーを UI から実際に配線する。ロジックにメソッドがあっても UI から呼ばれなければ機能しない。受け入れ基準 7 で発火を固定する。
- **教訓 5.15（タイムスタンプはコンテキスト上の時刻を参照する）**: 適用 — 錨開始時刻は U21 の UI 文脈上の現在時刻を参照し、システム時計と混同しない。受け入れ基準 3 で固定する。
- **教訓 5.16（時間値は完全値で受け渡し倍率の二重適用を防ぐ）**: 適用 — 現在時刻は年・月・日を含む完全な時間値で受け取り、分解した一部だけを錨へ渡さない。
- **教訓 5.5（依存する状態は変化時に再検証する）**: 適用 — 追加中にタイムライン時刻が変化した場合、面の親候補（その時刻に新規面を覆える既存面）も変化しうる。時刻変化時に親候補の妥当性を再検証し、選択中の親が不適合になったら選択を解除/再提示する。
- **教訓 5.3（操作対象は表示状態に限定する）/ 5.4（追加は現在の UI 文脈を第一候補にする）**: 適用 — 親候補列挙・グリッドスナップ・衝突判定の対象は、現在 UI 上に表示されている地物・現在時刻を基準にし、データソース全体やコレクション先頭を既定で使わない。
- **教訓 5.30（過少共有と過剰共有の両方を戒める）**: 適用 — 面追加時の親候補一覧は、見た目が似ていても所属変更フロー（FR-46〜FR-48）の親候補とは除外規則が異なる（新規面は循環参照対象にならない・存在期間条件が違う）。候補一覧ロジックを安易に共有せず、制約の同一性を列挙確認してから共有可否を判断する。
- **教訓 5.27（結合と所属変更は事前条件を分けて検証する）**: 適用 — 本ユニットの親選択は新規面への親子関係の初期付与であり、既存地物のツリー位相を変える所属変更フローや合体とは別概念。事前条件を混同しない。
- **教訓 5.11（構造変更操作後の選択は結果から再解決する）**: 適用 — 追加完了後の選択は固定の全クリアで決めず、コマンド結果が返す新規地物 ID から再解決する。受け入れ基準 9 で固定する。
- **教訓 5.22（確定まで共有データを破壊的に更新しない）**: 適用 — 形状確定〜保存途中で確定済み地物集合を破壊更新しない。U13 が `確定済み` を返して初めて反映し、拒否/キャンセル時は何も記録しない。
- **教訓 5.18（空配列・空オブジェクトは真値である）**: 適用 — 「親候補なし」「配置済み頂点 0 件」を空配列で表すとき、論理和の短絡デフォルト補完に頼らず長さ・有無を明示判定する。「親候補が空＝親なし選択肢のみ提示」と「未選択」を取り違えない。
- **教訓 5.19（分岐識別子は型定義・定数・ファクトリを経由する）**: 適用 — 追加ツール種別（点/線/面）を表示文字列で判定せず型・定数・ファクトリを経由し、作成・表示・編集・保存の全経路で同じ値を使う。
- **教訓 5.25（仕様が限定した対象範囲を実装で広げない）**: 適用 — 追加中頂点の排他は末端地物に対してのみ働く。線・点は面と重なってよく（FR-29）、「対称性確保」を理由に線・点へ排他を広げない。
- **教訓 5.8（押下→移動→解放シーケンスを全パスで保証する）/ 5.14（重なる UI は入力を受ける層も同時に設計する）**: 適用 — クリック（押下→解放）とドラッグの両パスで頂点配置・カーソル追従プレビューが正しく開始/更新/終了すること、仮表示オーバーレイがマップのクリック入力を奪わないことを保証する。
- **取消が頂点 0 のときの振る舞い**: 配置済み頂点が 0 の状態で取消（Ctrl+Z）した場合、追加フローを取り消すのか何もしないのか（あるいは追加開始自体のキャンセルにするのか）を明確に定義し実装する。曖昧にしない。
- **スナップ優先順位の明確化**: 共有頂点スナップ（FR-31、既定 50px）とグリッドスナップ（FR-78）が同時に候補になりうる場合の優先順位を一意に定義する（例: 既存頂点への共有スナップを優先し、なければグリッドへ）。単一の真実源として 1 箇所に決める。
- **クリーンルーム原則（開発ガイド 3.1）**: 本仕様・実装ともに過去版・他プロダクト・外部の既存実装に一切言及しない。必要な制約は v4 の要件・方針として直接記述・参照する。
- **性能の段階戦略（技術方針 R5 / R9）**: 追加中のリアルタイム衝突判定・スナップは近傍候補（RBush）だけの軽量判定にとどめ、確定時に U13 でフル整合性を実行する。追加中状態は Canvas 側に保持し React 再レンダリングに載せず 60FPS を防衛する。

# U18 ベースマップ描画と差し替え・グリッド・経度シフト

## 目的

メインマップの背景となるベースマップ（出界図）を描画し、ユーザー指定地図への差し替えを安全に扱い、緯線・経線グリッドと経度シフト UI を提供する。本ユニットは「地図の背景レイヤと、その周辺の地図表示制御（グリッド・経度シフト）」を担う。具体的には次の 4 つの責務を持つ。

1. **プリセット出界図の同梱と表示（FR-03）**: 正距円筒図法を前提とするプリセット出界図をアプリ内に同梱し、初回起動時・新規プロジェクト作成時・指定地図が読み込めない場合にこれを表示する。
2. **ユーザー指定地図への差し替え（FR-04）**: ユーザーが任意の地図ファイルをベースマップとして指定でき、出界図形式（正距円筒図法・縦横比など）に適合しない場合は自動補正を試み、不可能ならエラー通知してプリセット地図にフォールバックし、指定した地図はプロジェクト内にコピー保存する。
3. **ベースマップの無干渉描画（FR-06）**: ベースマップはマウスイベントもテキスト選択も受け付けず、地物操作やパン操作を一切阻害しない背景として描画する。
4. **緯線・経線グリッドと経度シフト UI（FR-13 / FR-12）**: 既定 10 度間隔の緯線・経線グリッドを赤道・本初子午線・180 度経線を強調して描画し、ON/OFF・間隔・色・不透明度の設定と、ズーム非依存の一定フォントサイズのラベルを提供する。経度シフト（本初子午線中心／太平洋中心の切替など）をボタン／スライダーで行い、現在の中心経度を表示し、シフト量はズームレベルに依存させる。

本ユニットは「ベースマップ画像と表示制御の層」であり、地物（点・線・面）そのものの描画・選択・編集には関与しない。地物描画は本ユニットのレイヤより上に重ねて描画される前提とし、本ユニットはその下地と背景制御に集中する。

## スコープ

### やること

#### プリセット出界図の同梱と表示（FR-03）

- 正距円筒図法を前提とするプリセット出界図画像をアプリ内に同梱する。同梱アセットはオフラインで完結して読み込めること（外部接続を前提としない）。
- 次の 3 つの契機でプリセット出界図を表示する。
  1. 初回起動時（プロジェクト未指定の初期状態）。
  2. 新規プロジェクト作成時。
  3. プロジェクトが指定するベースマップが読み込めない場合（ファイル欠落・破損・形式不適合で補正も失敗）。
- プリセット出界図は赤道長などの正距円筒メタ（縦横比 = 経度 360 度：緯度 180 度 = 2:1 を満たす）を持ち、ワールド座標系へ正しく貼り付けられること。
- ベースマップは無限横スクロール（FR-07）に対応し、世界の東端・西端をまたぐ表示で背景が途切れない（経度方向に周期的にタイル状反復描画する）。これは依存ユニット U17 のカメラ変換・ワールドラップ正規化（U05）に従って行い、本ユニットは「背景画像をどの経度オフセットで何枚描くか」の決定に集中する。

#### ユーザー指定地図への差し替え（FR-04）

- ユーザーが任意の画像ファイルをベースマップとして指定できる入口（設定ダイアログ FR-109 のベースマップ指定／ファイル選択経由）を提供する。
- 指定地図が出界図形式（正距円筒図法前提、縦横比 2:1）に適合するかを判定する。
- 適合しない場合は**自動補正を試みる**（例: 縦横比のリサンプル／余白付加・切り抜きによる 2:1 正規化など、正距円筒として解釈可能な形へ補正する試行）。
- 自動補正が不可能（または補正後も妥当な正距円筒画像にならない）な場合は、**日本語のエラーを通知してプリセット出界図にフォールバック**する。
- 差し替えに成功した（補正成功を含む）指定地図は、**プロジェクト内にコピー保存**する（プロジェクト永続化コンテナへ取り込む参照を生成する。実際の ZIP 書き込みは永続化ユニットの責務で、本ユニットは「プロジェクト内アセットとして保存対象に登録する」までを担う）。
- 差し替えの結果（成功／補正して成功／失敗でフォールバック）と理由を、ユーザー通知（日本語）とテスト可能な戻り値の両方で扱える形で返す。
- 外部から読み込む地図ファイルは検証・サニタイズの対象とする（FR-116 / NFR 5.5）。画像として妥当か・想定外の巨大寸法でないか等を境界で検証し、ドメイン／描画層へ流入させる前に弾く。

#### ベースマップの無干渉描画（FR-06）

- ベースマップはマウスイベント（クリック・ドラッグ・ホイール等）を一切奪わず、テキスト選択の対象にもならない。地物操作・パン操作・ズーム操作はベースマップの上で透過的に行えること。
- ベースマップ描画は地物描画レイヤより下（背景）に配置し、ヒットテスト（地物選択・頂点選択）の対象から完全に除外する。

#### 緯線・経線グリッド（FR-13）

- 緯線・経線グリッドを描画する。既定間隔は 10 度。
- 赤道（緯度 0 度）・本初子午線（経度 0 度）・180 度経線を**強調表示**する（他のグリッド線と視覚的に区別する強調スタイル）。
- グリッドの設定項目を提供する。
  - **ON/OFF 切替**。
  - **間隔**: 5 / 10 / 15 / 30 度から選択（既定 10 度）。
  - **色**。
  - **不透明度**。
- 緯度経度ラベルを描画し、**ズームレベルに関わらず一定のフォントサイズ**で表示する（地物のラベルと同様、画面上の見た目サイズが一定。FR-17 の方針と整合）。
- グリッドも無限横スクロールに追従し、世界端をまたいでも経線が途切れず、ラベルの経度値が周期境界をまたいで正しく表示される（U05 のラップ正規化に従う）。
- グリッド設定（間隔・色・不透明度・ON/OFF）はプロジェクト固有設定（FR-109）として扱い、変更は関連表示に即時反映する。

#### 経度シフト UI（FR-12）

- ボタン／スライダーで地図の表示経度を左右にシフトできる UI を提供する（本初子午線中心／太平洋中心の切替など、典型的な中心経度プリセットへの切替を含む）。
- 現在の中心経度を数値表示する。シフト操作で中心経度表示が即時更新される。
- **シフト量はズームレベルに依存**する（同じスライダー操作量でも、ズームインしているほど中心経度の移動量が小さくなる等、画面上の移動感が一定になるようズーム依存でスケールする）。
- 経度シフトは内部の連続経度スカラー（U05）とカメラ変換（U17）に作用し、ベースマップ・グリッド・地物すべてが同じ中心経度で一貫して表示される（本ユニットは中心経度をカメラ／表示状態へ反映し、背景とグリッドの再描画を行う）。

### やらないこと

- 地物（点情報・線情報・面情報）そのものの描画・ラベル・選択・編集（別ユニットの責務。本ユニットは背景とグリッド・経度シフト制御に限定する）。
- カメラのワールド↔スクリーン変換そのもの・ズーム／パン入力ハンドリング・無限横スクロールのカメラ実装（依存ユニット U17 の責務。本ユニットは U17 が提供するカメラ・変換・ヒットテスト契約を利用する）。
- 連続経度スカラーの保持・世界端ラップ正規化アルゴリズムそのもの（U05 の責務。本ユニットは呼び出して利用する）。
- ベースマップ画像・コピー保存ファイルの ZIP コンテナ書き込み・ファイル I/O・アトミック保存・世代バックアップ（永続化基盤ユニットの責務。本ユニットは「プロジェクト内アセットとして保存対象に登録する／参照を生成する」までで、バイト列の書き込みは委譲する）。
- 保存データ全体のスキーマ検証・整合性チェック（U14 の責務。本ユニットはベースマップ参照（パス・メタ・縦横比・赤道長）の妥当性検証のみを境界で行う）。
- 赤道長（km）入力そのものの UI と測地計算（FR-05 / 測地ユニットの責務）。ただしベースマップのワールド座標貼り付けは正距円筒（縦横比 2:1）前提に従う。
- 測量モード・グリッドスナップ（FR-14〜16 / FR-78）。本ユニットのグリッドは表示用であり、スナップ機能は別ユニットの責務。
- WebGL 実装への差し替え（性能未達時の退避路。`MapRenderer` インタフェース経由で別途行う。本ユニットは既定の Canvas 2D 実装に対して背景・グリッド描画を実装する）。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが提供する契約・純粋関数・描画基盤を前提として実装する。

- **U17**: 地図描画基盤（`MapRenderer` インタフェース、Canvas 2D によるワールド↔スクリーン変換＝カメラ、ズーム・パン、無限横スクロール、ヒットテスト契約、ズーム非依存の一定サイズ描画の仕組み）。本ユニットの背景描画・グリッド描画・経度シフトは、U17 のカメラ変換とフレーム描画ループに乗せて実装する。ベースマップは U17 の描画レイヤ最下層に配置し、ヒットテスト対象から除外する。経度シフトは U17 のカメラ中心経度へ反映する。

U17 を経由して間接的に前提となるもの（U17 が利用しており、本ユニットも同じ単一の真実源を共有する）:

- **U05**: 経度の連続スカラー表現と世界端ラップ正規化。無限横スクロール背景の反復描画・グリッド経線のラップ・経度シフトの中心経度計算は、U05 のラップ正規化関数に従う（本ユニットで再実装しない）。

依存ユニットが公開するカメラ変換・ラップ正規化・描画契約を再実装せず、本ユニットからは呼び出して利用する（単一の真実源。開発ガイド §4「単一の真実源」、教訓 5.30 過少共有の戒め）。

## 実装方針（技術方針に沿う）

技術方針が定める採用スタックと層分離に厳密に従う。

### 配置と層分離

- ベースマップ・グリッドの**描画コード**は `render` 層（Canvas 2D による命令的描画、U17 の `MapRenderer` 実装の一部）に属する。React の再レンダリングサイクルから切り離し、Canvas 側で直接描画する（描画状態を React state に持たせない。技術方針 2.3）。
- **経度シフト UI・グリッド設定パネル**などのウィジェットは `ui` 層（React 関数コンポーネント）に属する。
- 中心経度・グリッド設定・現在のベースマップ参照などの**表示／セッション状態**は Zustand ストア（UI/セッション状態）で薄く扱い、Canvas 側は購読のみで React の描画経路に乗らない（技術方針 2.5）。
- ベースマップ差し替えの**自動補正判定・形式適合判定・フォールバック決定**ロジックは、Canvas や React に依存しない純粋関数として `domain`（またはそれに準じる純粋ロジック）へ切り出し、Vitest で単独実行できるようにする（FR-04 の補正可否判定・フォールバック判定をテスト可能にする。NFR 5.8）。
- 依存方向は内向きに固定する。`render` / `ui` は `domain` を参照してよいが、`domain` は `render` / `ui` / `shell` を参照しない。

### プリセット出界図とアセット同梱

- プリセット出界図はアプリ内同梱アセットとして読み込む。Electron の sandbox 下でネット接続なしに読み込めること（FR-02 / FR-03）。
- ベースマップ画像は正距円筒（縦横比 2:1）としてワールド座標に貼り付け、U17 のカメラ変換に従ってスクリーンへ投影する。無限横スクロールでは経度方向に ±360 度オフセットで反復描画し、視野に入るタイルだけを描く（視野外クリッピング。NFR 5.1）。

### ベースマップ差し替え・自動補正・フォールバック

- 差し替えフローは「形式適合判定 → （不適合なら）自動補正試行 → （補正可なら）採用＋プロジェクト内コピー登録 →（補正不可なら）エラー通知＋プリセットフォールバック」の固定順序で実装する。
- 各分岐の結果（採用／補正採用／フォールバック）と理由を構造化した戻り値で返し、ユーザー通知（日本語メッセージ）とテスト可能な戻り値の両方で扱える形にする（教訓 5.26）。
- 外部入力（地図ファイル）は境界で検証・サニタイズする（FR-116 / NFR 5.5）。画像として妥当か・寸法が想定範囲内かを検証し、未検証の外部入力を描画／ドメインへ流入させない（R8）。検証は境界モジュールとして分離・命名し、lint が「外部入力は検証を通す」を検知できる構造にする。
- 差し替えが確定するまで現在のベースマップ（共有表示状態）を破壊的に更新しない。補正成功・採用確定で初めて表示を切り替え、失敗時はプリセットへ確実に戻す（教訓 5.22 / 5.2）。
- プロジェクト内コピー保存は「保存対象アセットとして登録する／参照（パス・メタ）を生成する」までを本ユニットの責務とし、実バイト列の ZIP 書き込みは永続化ユニットへ委譲する（教訓 5.36: 保存先・メタ・バックアップ対象を同じ保存文脈で扱う接続点を明示する）。

### グリッド描画と一定フォントラベル

- グリッドは U17 のフレーム描画ループ内で、カメラ変換に従って緯線・経線を描く。間隔（5/10/15/30 度）・色・不透明度・ON/OFF はグリッド設定状態から読み、設定変更で即時再描画する（FR-109）。
- 赤道・本初子午線・180 度経線の強調は、通常グリッド線と別スタイル（線幅・色・不透明度など）で描き分ける。強調判定は緯度=0／経度=0／経度=±180 を**単一の判定関数**で行い、描画・ラベル両方で同じ判定を共有する（判定のドリフトを防ぐ。教訓 5.29 / §4）。
- ラベルのフォントサイズはズーム非依存（画面上一定）にする。これは地物の一定サイズ表示（FR-17）と同じ「ワールド→スクリーン変換後にスクリーン空間で一定サイズを適用する」仕組みを共有し、独自実装でドリフトさせない（§4 単一の真実源）。
- 経線・経度ラベルは無限横スクロールに追従し、U05 のラップ正規化で経度値を正規化して表示する（世界端で経度が不連続にならない）。

### 経度シフト

- 経度シフト量はズーム依存でスケールする。「スライダー操作量 → 中心経度移動量」の換算は一箇所に定義し、ズームレベルを掛ける箇所を一元化して二重適用を防ぐ（教訓 5.16: 倍率の二重適用防止）。
- 中心経度は連続スカラー（U05）として保持し、表示時にラップ正規化して数値表示する。経度シフトはカメラ（U17）の中心経度へ反映し、ベースマップ・グリッド・地物が同じ中心で一貫描画される。
- 中心経度プリセット（本初子午線中心＝0 度／太平洋中心＝180 度 等）はボタンで切替でき、切替後に中心経度表示が即時更新される。

### テスト

- 補正可否判定・フォールバック判定・経度シフト量のズール依存換算・グリッド強調線判定・経度ラベルのラップ正規化など、純粋ロジックは Vitest で単体テストする。境界ケース（縦横比が 2:1 ちょうど／僅かにずれる／補正不能、世界端をまたぐ経線・ラベル、中心経度 ±180 付近）を網羅する（NFR 5.8）。
- 「初回／新規／読込失敗 → プリセット表示」「指定地図 → 補正成功 → 採用」「指定地図 → 補正不能 → フォールバック」の各経路を、入力状態 → 期待結果（表示中ベースマップ種別・通知・コピー登録の有無）で再現テストする。
- ベースマップがヒットテスト対象から除外されていること（背面のベースマップを覆っても地物操作・パンが通ること）を、重なり層の入力テスト（教訓 5.14）で確認する。E2E（Playwright for Electron）でクリック／ドラッグがベースマップに奪われないことを確認する。
- 一時的検証不能になる範囲（ファイル選択・画像読込・ZIP 登録）は純粋関数化・アダプタ分離・モックで単体テスト対象にして補う（教訓 5.41）。

## 受け入れ基準（テスト可能な形で列挙）

1. **プリセット出界図の表示（FR-03）**: 初回起動時・新規プロジェクト作成時・指定ベースマップが読み込めない場合（欠落・破損・補正失敗）の 3 経路すべてで、プリセット出界図が表示されることを、各経路の入力状態 → 表示中ベースマップ種別を検証するテストで確認できる。プリセット出界図は同梱アセットからオフラインで読み込める。
2. **正距円筒の正しい貼り付けと無限横スクロール背景（FR-03 / FR-07）**: ベースマップが正距円筒（縦横比 2:1）としてワールド座標へ貼り付けられ、世界の東端・西端をまたぐ表示で背景が途切れず周期反復描画されることを確認できる。視野外のタイルは描画されない（視野外クリッピング）。
3. **ユーザー地図差し替えと自動補正（FR-04）**: ユーザーが指定した出界図形式適合の地図が、差し替えで採用され表示されることをテストで確認できる。縦横比などが不適合の地図は自動補正が試みられ、補正可能なら補正後の地図が採用される。
4. **補正不能時のエラー通知とプリセットフォールバック（FR-04）**: 自動補正が不可能な地図を指定した場合、日本語のエラーが通知され、表示がプリセット出界図にフォールバックすることを、戻り値（結果種別・理由）と表示中ベースマップ種別の両方で確認できる。失敗時に現在表示が壊れた状態（中途半端な補正結果）にならない。
5. **プロジェクト内コピー保存（FR-04）**: 差し替えに成功（補正成功含む）した指定地図が、プロジェクト内アセットとして保存対象に登録され、参照（パス・メタ）が生成されることを確認できる（実バイト列の ZIP 書き込みは永続化ユニットへ委譲するが、登録／参照生成までが本ユニットで行われる）。
6. **ベースマップの無干渉（FR-06）**: ベースマップがマウスイベント・テキスト選択を受け付けず、ヒットテスト対象から除外されていることを確認できる。ベースマップを覆う領域でも、地物選択・頂点選択・パン・ズームが阻害されず通ることを重なり層テスト／E2E で確認できる。
7. **グリッドの描画と既定間隔（FR-13）**: 緯線・経線グリッドが描画され、既定間隔が 10 度であることを確認できる。
8. **赤道・本初子午線・180 度経線の強調（FR-13）**: 緯度 0 度・経度 0 度・経度 ±180 度の線が、通常グリッド線と区別される強調スタイルで描画されることを確認できる。強調判定が単一の判定関数で行われ、描画とラベルで同じ判定を共有していることを確認できる。
9. **グリッド設定（ON/OFF・間隔・色・不透明度）（FR-13 / FR-109）**: グリッドの ON/OFF 切替、間隔の 5/10/15/30 度からの選択、色、不透明度がそれぞれ設定でき、変更が即時に描画へ反映されることをテストで確認できる。
10. **ズーム非依存の一定フォントラベル（FR-13 / FR-17）**: 緯度経度ラベルが、ズームレベルを変えても画面上のフォントサイズが一定で表示されることを確認できる。ラベルの一定サイズは地物の一定サイズ表示と同じ仕組みを共有している。
11. **経度シフトと中心経度表示（FR-12）**: ボタン／スライダーで表示経度を左右にシフトでき、本初子午線中心／太平洋中心などの切替ができ、操作に応じて現在の中心経度の数値表示が即時更新されることを確認できる。
12. **シフト量のズーム依存（FR-12）**: 同一のシフト操作量に対し、ズームレベルが高いほど中心経度の移動量が小さくなる（画面上の移動感が一定になる）ことを、ズーム依存換算の純粋関数テストで確認できる。倍率の二重適用が起きていない。
13. **世界端をまたぐグリッド・ラベルの一貫性（FR-07 / FR-13）**: 無限横スクロールで経線が世界端をまたいでも途切れず、経度ラベルがラップ正規化されて連続的に正しい経度値を示すことを、中心経度 ±180 付近を含む境界テストで確認できる。
14. **設定即時反映（FR-109）**: グリッド設定・経度シフト・ベースマップ差し替えの結果が、再起動を要さず関連表示に即時反映されることを確認できる。
15. **純粋ロジックの単独実行（NFR 5.8）**: 補正可否判定・フォールバック判定・シフト量換算・グリッド強調判定・経度ラベル正規化は副作用のない純粋関数として `domain` で Vitest 単独実行でき、境界ケースを網羅したテストが通る。

## 関連要件（FR-id）

- **FR-03** (must): 地図（ベースマップ）を表示し、プリセット地図（出界図）を同梱する。初回起動時・新規作成時・指定地図が読み込めない場合はプリセット地図を表示する。
- **FR-04** (should): ユーザーが任意の地図ファイルをベースマップとして指定でき、出界図形式に適合しない場合は自動補正を試み、不可能ならエラー通知してプリセット地図にフォールバックする。指定した地図はプロジェクト内にコピー保存する。
- **FR-06** (must): ベースマップはマウスイベントもテキスト選択も受け付けず、地物操作やパン操作を阻害しない。
- **FR-12** (should): ユーザーがボタンやスライダーで地図の表示経度を左右にシフトでき（本初子午線中心／太平洋中心の切替など）、シフト量はズームレベルに依存し、現在の中心経度を表示する。
- **FR-13** (should): 10 度間隔を既定とする緯線・経線グリッドを表示し、赤道・本初子午線・180 度経線を強調表示する。グリッドの ON/OFF 切替、間隔（5/10/15/30 度）、色、不透明度を設定できる。緯度経度ラベルはズームに関わらず一定フォントサイズで表示する。

関連する周辺要件・非機能要件:

- **FR-02**（オフライン完結・スタンドアロン）: プリセット出界図・差し替え地図はネット接続なしで読み込む。
- **FR-05 / FR-07**（正距円筒前提・無限横スクロール）: ベースマップ・グリッドは正距円筒（縦横比 2:1）前提で貼り付け、世界端をまたいで反復描画する。
- **FR-17**（ズーム非依存の一定サイズ表示）: グリッドラベルの一定フォントサイズはこの方針と同じ仕組みを共有する。
- **FR-109**（プロジェクト固有設定の即時反映）: グリッド間隔・色・不透明度・ベースマップ指定はプロジェクト固有設定として即時反映する。
- **FR-116 / NFR 5.5**（入力検証・無害化）: 外部から読み込む地図ファイルを境界で検証・サニタイズする。
- **NFR 5.1**（60FPS・視野外クリッピング）: ベースマップ・グリッドの反復描画は視野内タイルに限定する。
- **NFR 5.8**（テスト容易性）: 補正可否・フォールバック・シフト換算・強調判定・ラベル正規化を純粋関数として境界網羅テストする。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

### 適用宣言（AI 作業開始ゲート, 開発ガイド 1.6）

着手前に以下の教訓を引用し、本ユニットへの適用を宣言してから実装すること。引用と適用宣言を省略して着手してはならない。

- **教訓 5.14「重なる UI は入力を受ける層も同時に設計する」**（引用: 「重なり合う UI（オーバーレイ・バックドロップ・ハンドル・モーダル）は、描画順だけでなく入力を受ける層も同時に設計する。透明な背景層が操作ハンドルを覆うと、見た目は正しくても操作が奪われる。検出: 重なった状態で、背面/前面の期待操作が通ることをテストする。」）。**適用**: 本ユニットのベースマップは最背面に描画し、ヒットテスト・マウスイベント・テキスト選択の対象から完全に除外する（FR-06）。ベースマップを覆う領域でも地物選択・パン・ズームが通ることを重なり層テスト／E2E で確認する（受け入れ基準 6）。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.16「時間値は完全値で受け渡し、倍率の二重適用を防ぐ」**: 経度シフトのズーム依存換算で、ズーム倍率を掛ける箇所を一元化する。「スライダー操作量 → 中心経度移動量」の換算定義は一箇所に置き、UI 側と描画側の両方でズームを掛ける二重適用を作らない（受け入れ基準 12）。
- **教訓 5.22「確定まで共有データを破壊的に更新しない」 / 5.2「一時的 UI 状態は全経路で破棄する」**: ベースマップ差し替えは、補正成功・採用確定まで現在表示中のベースマップ（共有表示状態）を破壊的に更新しない。補正試行中の一時画像・ドラフト設定は、確定・キャンセル・失敗フォールバックの全経路で破棄する。失敗時はプリセットへ確実に戻し、中途半端な補正結果を表示に残さない（受け入れ基準 4）。
- **教訓 5.26「編集制約はコマンド確定前にも同じサービスで検証する」 / 拒否理由は通知と戻り値の両方**: 差し替え失敗・補正不能・形式不適合の拒否理由は、日本語ユーザー通知（FR-115: 日本語のみ、必要に応じ「開発者へ報告してください」を付与）とテスト可能な戻り値の両方で扱える形にする。
- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」 / §4「単一の真実源」**: 赤道・本初子午線・180 度経線の強調判定は単一の判定関数に集約し、線描画とラベル描画の両経路で同じ判定を共有する。判定のドリフトで「強調線は描かれるがラベルは強調されない」等の矛盾を生まない（受け入れ基準 8）。
- **§4「単一の真実源」 / 教訓 5.30「過少共有の戒め」**: カメラのワールド↔スクリーン変換（U17）・連続経度スカラーと世界端ラップ正規化（U05）・ズーム非依存の一定サイズ表示の仕組み（FR-17）は、依存ユニットの実装を共有し再実装しない。背景反復描画・グリッド経線ラップ・ラベル一定サイズを独自実装でドリフトさせない。
- **教訓 5.35「共有リソース更新は全依存先へ通知する」 / FR-109 即時反映**: グリッド設定・中心経度・ベースマップ参照を更新したら、依存する描画（Canvas）・UI（設定パネル・中心経度表示）の全依存先へ通知し即時反映する。Zustand 購読で Canvas 側が最新値を読む構造にする（受け入れ基準 9 / 11 / 14）。
- **教訓 5.36「プロジェクト設定とアプリ全体設定の境界を先に定義する」**: グリッド間隔・色・不透明度・ベースマップ指定はプロジェクト固有設定（FR-109）に属する。新規プロジェクト開始時はベースマップ（プリセットへ）・グリッド設定・中心経度・保存対象アセット参照を同じ保存文脈で同時に初期化する。アプリ全体設定（FR-110）と取り違えない。
- **教訓 5.41「検証不能になった範囲は別手段で補う」**: ファイル選択・画像読込・ZIP コピー登録など E2E で検証しにくい範囲は、補正可否判定・フォールバック判定・参照生成を純粋関数化／アダプタ分離してモックで単体テストする（受け入れ基準 15）。
- **R3（無限横スクロール・経度シフトが世界端をまたぐ処理と衝突）**: ベースマップ反復描画・グリッド経線・経度ラベル・中心経度は世界端（経度 ±180）をまたぐ。経度はすべて U05 のラップ正規化関数を経由し、本ユニットで独自に剰余計算しない。中心経度 ±180 付近の境界テストを置く（受け入れ基準 13）。
- **NFR 5.1（60FPS・視野外クリッピング）**: ベースマップ・グリッドの反復描画は視野内タイルに限定する。グリッドは間隔が細かい（5 度）かつ広域ズームアウト時に線数が増大するため、視野内に入る線のみ描き、必要に応じて広域では描画密度を間引く（LOD）方針を検討する。地図描画状態を React state に持たせず Canvas 側で描く（技術方針 2.3）。
- **クリーンルーム（開発ガイド 3.1）**: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-03 / 04 / 06 / 12 / 13）・技術方針として直接記述する。

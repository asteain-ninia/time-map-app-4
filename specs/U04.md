## 1. 目的

本アプリの地図は正距円筒図法を前提とする。ユーザーが地図の「赤道長(km)」と「扁平率(flattening)」を入力すると（いずれもプロジェクト設定 FR-109）、その値を基準に地図上の地理計算（距離・線長・面積）が物理単位(km / km²)へ換算される（FR-05 / FR-109）。扁平率は緯度方向の地表スケールを経度方向と非対称にする係数として距離・面積へ反映する。

本ユニットは、その換算を担う **小さな純粋関数モジュール** を提供する。具体的には次を算出する。

- 2 点間の **正距円筒距離**（地図平面上の見た目どおりの距離）と **大円距離**（球面上の最短経路距離）の双方（FR-14）。
- 線情報の **長さ(km)**（複数頂点パスの区間和）（FR-19）。
- 面情報の **面積(km²)**（リング構造に基づく符号付き面積の合成）（FR-20）。

座標系・暦に閉じた小さな純粋モジュールとして実装し、副作用も外部依存ライブラリも持たないことで、境界ケース（世界端ラップ等）を機械的に網羅検証できる状態にする（NFR 5.8）。

## 2. スコープ

### 2.1 やること

- 赤道長(km)と扁平率(flattening)を引数に受け取り、地図座標（経度 lon・緯度 lat、いずれも度単位）から物理距離・面積を導く純粋関数群を提供する。赤道長と扁平率はいずれもプロジェクト設定（FR-109）の値であり、モジュール内に隠れた定数を持たず外部から注入する（技術方針 §2.9 の「赤道長・扁平率の引数化」）。
- 赤道長と扁平率は単一のパラメータオブジェクト `geoParams = { equatorKm, flattening }` にまとめて受け渡す（引数の取り違えを型で防ぐ。暦設定の引数化と同じ思想）。
- 次の公開関数を実装する（名称は目安。実装者は本アプリの `domain` 命名規約に合わせてよいが、責務と引数・戻り値の意味は固定とする）。
  1. `equirectangularDistanceKm(a, b, geoParams)` — 2 点間の正距円筒距離(km)。
  2. `greatCircleDistanceKm(a, b, geoParams)` — 2 点間の大円距離(km)。
  3. `lineLengthKm(points, geoParams)` — 頂点列で表される線の長さ(km)。距離尺度（正距円筒／大円）を選べるようにする（既定は正距円筒。FR-14 の測量線が大円最短経路を扱うため大円も選べること）。
  4. `polygonAreaKm2(rings, geoParams)` — リング構造で表される面の面積(km²)。
- **世界端ラップ（±360 度）をまたぐ計算を折り返しで正しく扱う**。経度が周期境界（地図の東端・西端）をまたぐ 2 点・線分・ポリゴンを、分断せず最短の折り返し経路／連続展開で計算する（FR-07 の無限横スクロール、FR-14 の「世界端をまたぐ測定線は折り返して表示し分断しない」と整合）。
- 赤道長から導く基準スカラー（赤道 1 度あたりの km、緯度 1 度あたりの km）を単一の内部ヘルパーに集約し、全関数がそれを共有する。
- すべての公開関数・内部ヘルパーに対し Vitest 単体テストと fast-check プロパティテストを同時に用意する。

### 2.2 やらないこと

- 描画・スクリーン座標変換・カメラ操作（U04 はワールド座標上の純粋計算のみ。描画層には触れない）。
- 完全な楕円体測地解（Vincenty 法等の測地線方程式・等角緯度・子午線弧長の級数展開による厳密解）。本ユニットは正距円筒図法前提に閉じ、扁平率は §4.3 で定義する**緯度方向スケールの簡易補正係数**として距離・面積へ反映するに留める（汎用測地ライブラリは採用しない、技術方針 §2.9）。扁平率を距離・面積計算へ取り込むこと自体は本ユニットの責務に含む（FR-109）。
- ブーリアン演算（面の和・差・交差）。面積計算は与えられたリング頂点列の幾何面積を求めるだけで、リング同士の重なり解消や集約形状の導出は行わない（別ユニットの責務）。
- ポリゴンの妥当性検証（自己交差・ゼロ長エッジ・リング階層交互性の検査）。本ユニットは「与えられた頂点列に対する数値計算」を提供し、不変条件検証は呼び出し側／別ユニットが担う。
- 暦・時間計算（本ユニットは時間に依存しない。赤道長という空間パラメータのみに依存する）。
- 永続化・スキーマ検証・IPC・UI。

## 4. 実装方針（技術方針に沿う）

### 4.1 配置と層

- 本モジュールは `domain` 層（フレームワーク非依存・純粋）に置く。Electron / React / Canvas / 状態管理いずれにも依存しない。Vitest 単体で実行可能であること。
- 依存方向は `domain` へ内向き。外部ライブラリ依存を持たない（測地計算は自前純粋関数とする技術方針 §2.9 に従う。汎用測地ライブラリは採用しない）。

### 4.2 言語・型

- TypeScript（strict 全有効：`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`）。
- `noUncheckedIndexedAccess` 前提のため、頂点配列・リング配列へのインデックスアクセスは `undefined` 可能性を型で扱い、境界外参照をコンパイル時に排除する（線・面の頂点ループで多発する。安易な `!` 断定で潰さず、空・1 点・2 点などの少数要素ケースを早期 return で扱う）。
- 関数はすべて **純粋関数**（同じ入力に同じ出力、副作用なし、引数を破壊的に変更しない、グローバル状態を読まない）。`Math.random` や現在時刻に依存しない。

### 4.3 計算の定義（正距円筒図法前提の球面近似）

赤道長 `equatorKm` は、地図の赤道（緯度 0 度）に沿った全周の長さ(km)である。扁平率 `flattening`（= f）は、子午線方向（極方向）の周長が赤道周長に対しどれだけ短いかを表す無次元量（f = 0 で真球）。これらを基準に次のスカラーを導く（**単一ヘルパーに集約**。`geoParams = { equatorKm, flattening }` から導出）。

- 経度 1 度あたりの赤道上 km: `kmPerLonDegAtEquator = equatorKm / 360`。
- 緯度 1 度あたりの km: 球面（f=0）では子午線円周＝赤道円周なので `equatorKm / 360`。扁平率を取り込む場合、子午線円周は赤道円周に対し概ね係数 `(1 - f)` 倍に縮むと近似し、`kmPerLatDeg = (equatorKm / 360) * (1 - flattening)` とする。これにより扁平率は**緯度方向スケールを経度方向と非対称にする係数**として距離・面積へ正面から作用する（技術方針 §2.9）。`flattening = 0` のとき従来の球面近似に厳密一致する（退化ケース）。
- 球面メトリックを要する大円距離の半径は赤道基準 `R = equatorKm / (2π)` を用いる（大円距離は赤道周長を基準とした球面近似に閉じ、扁平率は緯度方向スケールを通じて正距円筒距離・面積へ作用させる役割分担とする。両者の定義をドリフトさせないこと）。

各計算の定義は以下とする。実装者はこの定義を厳守し、別解釈で広げない。

1. **正距円筒距離**（地図平面上の距離）
   - 2 点 `a=(lonA, latA)`, `b=(lonB, latB)` について、まず後述 §4.4 の折り返しで経度差 `Δlon`（最短になる符号付き差、絶対値 ≤ 180 度）を求める。
   - 経度方向の地上距離は **緯度補正** を掛ける。正距円筒図法では平面上の横距離は緯度に依らず一定だが、地表上の実距離としては高緯度ほど経度 1 度が短くなる。本アプリの「正距円筒距離」は **地図平面（プレートキャレ）上の見た目どおりの距離** と定義する。すなわち緯度補正を掛けず、`dx = Δlon * kmPerLonDegAtEquator`, `dy = (latB - latA) * kmPerLatDeg`, 距離 `= sqrt(dx² + dy²)` とする。`kmPerLatDeg` は扁平率を織り込んだ上記スカラー（`(equatorKm / 360) * (1 - flattening)`）であり、扁平率は dy（緯度方向成分）を通じて距離へ反映される。
   - （補足: 高緯度の経度短縮を反映する球面実距離は大円距離側で表現する。両者の役割分担を §4.3-2 と一致させ、定義をドリフトさせないこと。）
2. **大円距離**（球面上の最短経路距離）
   - 半径 `R = equatorKm / (2π)`。緯度経度をラジアンへ変換し、数値的に安定な **haversine 公式** で中心角を求めて `距離 = R * 中心角` とする。
   - 経度差は §4.4 の折り返し後の値を用いる（折り返さなくても haversine は周期性を持つが、入力前に正規化して一貫させる）。
   - haversine は対蹠点付近でも安定する。`atan2` を用いる実装とし、`acos` 直接版（桁落ちしやすい）は使わない。
3. **線の長さ**
   - 頂点列 `points`（順序付き）の隣接ペアごとに距離（既定は正距円筒、引数で大円も選択可）を求め総和する。点数 < 2 のときは長さ 0(km) を返す。
   - 各区間の経度差は §4.4 の折り返しで求める（パスが世界端をまたいでも区間ごとに最短折り返しで連続させ、分断・二重計上しない）。
4. **面積**
   - リング構造 `rings`：外周リング（領土）と穴リングを含む。本ユニットは「符号付き面積」を合成して総面積を返す。
   - 各リングの頂点を、リング内で連続するよう §4.4 の折り返しで経度をアンラップ（連続化）してから、緯度を sin 補正した等積近似のシューレース（多角形面積）公式で km² を求める。等積近似は次のいずれかに統一する: (a) 経度方向に `kmPerLonDegAtEquator`、緯度方向に `kmPerLatDeg` を掛けた平面シューレース（プレートキャレ平面面積。FR-20 の「面積(km²)」を地図平面面積として定義）。本アプリは **平面シューレース(a)** を採用する。定義を 1 つに固定し、テストで固定する。
   - 穴リングは外周リングと逆符号で寄与し、総面積 = |外周面積の和| − |穴面積の和|。リング階層が「領土→穴→領土→…」交互である前提（FR-20 / FR-24）に基づき、各リングの寄与符号は **巻き順（時計回り／反時計回り）ではなくリング種別（領土／穴）で決める**。すなわち領土リングは +、穴リングは − として絶対値を合算する。巻き順に依存した符号決定は呼び出し側のデータ巻き順次第で破綻するため採らない。
   - 面積は常に非負を返す（穴が外周を上回る等の不正入力でも下限 0 でクランプはせず、計算結果をそのまま返したうえで、そうした不正は別ユニットの妥当性検証が弾く前提とする。ただし負値を返さない設計が望ましいので、総和方式は「領土合計 − 穴合計」とし両者とも絶対値で積む）。

### 4.4 世界端ラップ（±360 度）の取り扱い — 最重要

技術方針 R3「無限横スクロール・経度シフトが世界端をまたぐ計算と衝突する」への対策をこのモジュールで担う。専用のラップ正規化を **ライブラリ任せにせず明示実装し、切り出してテストする**。

- **2 点間 / 線区間**: 経度差は「素朴な差 `lonB - lonA`」ではなく、`±360` 度の整数倍を加減して **絶対値が最小になる符号付き差**（区間 (−180, 180]）に正規化する。これにより東端・西端をまたぐ 2 点でも最短側の折り返しで距離が出る（分断しない）。
- **リング（面）**: リングは閉路なので「最短差」を区間ごとに足すと一周して整合する。各頂点の経度を、直前頂点との最短差を累積する形で **アンラップ（連続化）** してからシューレースに渡す。これで西端・東端をまたぐ国土も 1 つの連続多角形として面積が出る。
- 入力経度の絶対値が大きい（例: 連続スカラーとして +540 度等で保持された）場合でも、まず `[-180, 180)`（または一貫した基本範囲）へ周期正規化してから差分を取る。基本範囲の境界（ちょうど ±180 度、0 度、±360 度）での扱いを 1 つに統一する。
- ラップ正規化関数は単独で公開（または内部公開）し、独立にテストする。U03 に同等関数があればそれを共有し、本ユニットで二重実装しない（§3 参照）。

### 4.5 数値の堅牢性

- 度⇄ラジアン変換、`sqrt` / `atan2` / `sin` の使用は標準 `Math` に限る。
- 浮動小数の比較はテストで許容誤差（相対 or 絶対の epsilon）を用いる。等値比較で落とさない。
- 退化入力（同一 2 点、ゼロ長区間、頂点数不足のリング）に対して **NaN や例外を出さず、0 や妥当な値を返す**（同一点間距離は 0、頂点数 < 3 のリング面積は 0）。

### 4.6 テスト（実装と同時に書く。開発ガイド §1.9）

- **Vitest 単体テスト**: 既知の解析解と突き合わせる代表ケースを置く。例:
  - 赤道長 = 40000km（地球規模の目安値）で、赤道上 90 度離れた 2 点の大円距離 ≈ 10000km。
  - 同一点間の正距円筒距離・大円距離・線長 = 0。
  - 正距円筒距離が `sqrt(dx²+dy²)` の定義どおりであること（軸平行・斜めの両方）。
  - 単純な矩形リング（緯度経度で定義）の面積が平面シューレース定義どおりであること。
  - 外周＋内側の穴を持つリングで、総面積 = 外周 − 穴。
- **fast-check プロパティテスト**（NFR 5.8。技術方針 §2.9・§2.14、R3・R7）:
  - 入力ジェネレータは **紀元前（負の年）を一切必要としない**。本ユニットは時間に依存しないので、年・時刻の生成子を用いない。生成するのは経度・緯度・赤道長・扁平率・頂点列のみ（緯度は [−90, 90]、経度は世界端ラップを試すため [−540, 540] など基本範囲を超える値も含める。扁平率は 0 を含む [0, ~0.1] 程度の範囲、退化ケース 0 を必ず含める）。
  - 性質例:
    - 距離の対称性: `dist(a,b) == dist(b,a)`（誤差内）。正距円筒・大円の双方。
    - 非負性: すべての距離・線長・面積が ≥ 0。
    - ラップ不変性: 任意の点・リングの全経度に一律 `+360k`（整数 k）を加えても、正距円筒距離・大円距離・線長・面積が（誤差内で）変わらない。**これが世界端ラップを折り返しで正しく扱えていることの中核プロパティ**。
    - 世界端境界ケース網羅: 一方の点を東端近傍（例 +179.x 度）、他方を西端近傍（例 −179.x 度）に置いたとき、距離が「素朴差 359 度相当」ではなく「折り返し 1 度相当」になること（分断しない）。
    - 線長の加法性: 区間を途中点で分割しても総長が（誤差内で）保たれる。
    - 赤道長スケール線形性: 赤道長を c 倍すると距離・線長は c 倍、面積は c² 倍になる。
    - 扁平率退化一致: `flattening = 0` のとき、正距円筒距離・線長・面積が従来の球面近似（`kmPerLatDeg = equatorKm/360`）と誤差内で厳密一致する。
    - 扁平率の緯度方向単調性: 同一入力に対し `flattening` を増やすと、純粋に緯度方向成分を持つ距離（南北方向の 2 点間距離）および面積が単調に減少する（経度のみ異なる東西方向距離は扁平率に依存しない）。
- ジェネレータは本ユニット内で再利用可能な形に切り出す（R7「ジェネレータをドメインの不変条件から導出する共通モジュールとして一度だけ構築」。本ユニット範囲では経度・緯度・頂点列・赤道長・扁平率の生成子を共通化する）。

## 5. 受け入れ基準（テスト可能な形で列挙）

実装者は、以下すべてが Vitest / fast-check で緑になるまで本ユニットを「完了」にしない（PROTOCOL「受け入れ基準が緑になるまでユニットを完了にしない」）。

1. **AC-1（大円・正距円筒の双方）**: 赤道長(km)・扁平率を `geoParams` で引数に渡すと、任意の 2 点間について正距円筒距離(km)と大円距離(km)の **双方** が計算できる。代表ケースで解析解（例: 赤道上 90 度差 → 赤道長の 1/4）と誤差内一致する単体テストがある。
2. **AC-2（線長・面積の km 単位）**: 頂点列の線の長さ(km) と、リング構造の面積(km²) が算出できる。矩形・穴あきリングの面積、複数区間の線長について解析解と一致する単体テストがある。点数 < 2 の線長 = 0、頂点数 < 3 のリング面積 = 0 を満たす。
3. **AC-3（世界端ラップ）**: 世界端（経度の東端・西端）をまたぐ 2 点間距離・線長・面積が **折り返して正しく出る（分断しない）**。東端近傍と西端近傍の 2 点で距離が折り返し最短側になること、全経度へ `+360k` を加えても結果不変であることをテストで確認する。
4. **AC-4（fast-check 境界網羅・紀元前不要）**: fast-check により、距離の対称性・非負性・赤道長スケール線形性・ラップ不変性・世界端境界ケース・扁平率退化一致・扁平率の緯度方向単調性を網羅するプロパティテストが存在し緑である。生成入力は **紀元前（負の年）・時刻を必要としない**（本ユニットは時間非依存）。
5. **AC-5（扁平率の引数化と反映, FR-109）**: 赤道長・扁平率は `geoParams` として全公開関数の引数で受け取り、モジュール内に隠れた定数を持たない。扁平率は緯度方向スケール `(1 - flattening)` を通じて正距円筒距離・線長・面積へ作用し、`flattening = 0` で球面近似に厳密一致する単体テストがある。
6. **AC-6（純粋・無依存・単体テスト可能）**: 本モジュールは副作用なし・外部依存ライブラリなしの純粋関数群であり、`domain` 層のみで Vitest 単体実行できる。Electron / React / Canvas / 状態管理に依存しない。strict 全有効でビルドが通る。

## 6. 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の教訓を引用・適用宣言してから書くこと（開発ガイド §1.6「AI 作業開始ゲート」）。

- **§5.30 過少共有と過剰共有の両方を戒める / 設計指針「単一の真実源」**:
  - 適用: 赤道長から導く km/度スカラーと、経度ラップ正規化は **1 か所のヘルパーに集約** し、距離・線長・面積の全関数が共有する。係数や正規化を関数ごとに書き直すと、片方だけ直して計算がドリフトする。一方で U03 と本ユニットの正規化が「同一制約か」を確認したうえで共有し、別制約を無理に同一実装へ押し込めない。
- **R3 / FR-14 / FR-07 世界端ラップ**:
  - 適用: 経度差は素朴な減算ではなく ±360 度折り返しの最短差で取る。リングはアンラップして連続化してから面積を出す。これを怠ると、東端↔西端をまたぐ測定線・国土が「地図を一周する巨大値」になり分断・誤計算する。回帰防止として「全経度 +360k で結果不変」のプロパティテストを必須にする。
- **§5.1 集合演算は複数片を返す前提で扱う（面積の符号合成へ転用）**:
  - 適用: 面積はリングが複数（外周＋複数穴＋飛び地外周）になる前提で、**全リングを漏れなく合算** する。配列の先頭リングだけ採用する片落としをしない。穴は減算、領土は加算で全件を処理する。
- **§5.18 空配列・空オブジェクトは真値である**:
  - 適用: 空の頂点列・空のリング配列を「偽」として暗黙に既定補完しない。長さ・要素数を明示的に判定し、空入力は 0(km / km²) を返す。`points || fallback` のような短絡に頼らない。
- **§5.25 仕様が限定した対象範囲を実装で広げない**:
  - 適用: 本ユニットは「正距円筒前提の球面近似」に閉じる。対称性・自然な拡張を理由に厳密楕円体測地・扁平率反映・ブーリアン演算・妥当性検証へ手を広げない（§2.2 やらないこと）。広げたくなったら本書の該当節を引用して止まる。
- **§5.39 テスト fixture は実体クラス／実体生成を使う**:
  - 適用: テストの頂点・リング fixture は、U03 由来の点型／本ユニットのリング型のコンストラクタ・ファクトリで構築する。リテラルで型を満たすと未参照プロパティ欠落が沈黙通過しうる。
- **§5.33 / §5.34 層をまたぐ契約は型で明示し両側テストで固定する**:
  - 適用: 公開関数のシグネチャ（点型・リング型・赤道長・戻り値 km / km²）を型で固定し、呼び出し側（測量モード／線・面のプロパティ表示）が依存する契約を型と単体テストで固定する。引数順・単位（km か度か）の取り違えを型と命名で防ぐ。
- **数値定義のドリフト防止**:
  - 適用: 「正距円筒距離＝地図平面距離（緯度補正なし）」「大円距離＝球面 haversine」「面積＝平面シューレース（領土＋／穴−）」という 3 つの定義を本書どおり 1 つずつに固定し、テストで固定する。定義を実装中に別解釈へ揺らさない（揺らすと AC-1〜AC-3 の解析解テストが破れる）。

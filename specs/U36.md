## 1. 目的

編集モードにおいて、**アクティブ地物または頂点選択セットを右クリックするとコンテキストメニューを表示し、対象オブジェクトの種類・現在のツール種類に応じて項目内容が動的に変化する**操作統合を実装する（FR-96）。これにより、ユーザーはプロパティパネルやツールバーへ移動せずに、選択中の対象へその場で意味のある操作（削除・プロパティ編集・共有解除・分割・所属変更・結合）を適用できる。

本ユニットは新しい編集アルゴリズムを実装するユニットではなく、**既存の各操作フローへの代替起動口（右クリック経路）を 1 か所に集約する操作統合（コーディネーション）ユニット**である。各メニュー項目は、対応する既存フロー（分割 U26 / 所属変更 U28 / 結合 U30 / 削除 U31 / 共有解除 U11）を起動するだけであり、操作の本体・整合性検証・履歴積みはそれらの依存ユニットが担う。本ユニットの責務は次の三点に絞る。

1. **メニューの動的構成**: いま選択されている対象（アクティブ地物 0/1 件・頂点選択セット）と、その対象の種類（点情報／線情報／面情報＝末端地物／集約地物、共有頂点を含むか）、現在のツール種類から、表示すべきメニュー項目集合を**派生状態として算出する**。
2. **既存フローへのディスパッチ**: 各項目の選択を、対応する既存フローの起動関数へ正しい対象・正しい起点状態で接続する。
3. **権限境界の一括適用**: 表示専用モード（編集が許可されないモード）では、右クリックメニュー・メニュー項目・対応ショートカット経路を**同じ権限判定で一括無効化する**（教訓 5.13）。

操作完了時の整合性維持プロセス（FR-61〜FR-63）は、各既存フロー（および最終的に U13）が責務として走らせる。本ユニットは「右クリック起動でも、UI 上のボタン起動と同一のフローと同一の整合性プロセスを通る」ことを保証する結線役に徹する。

## 2. スコープ

### 2.1 やること

- **右クリックの受理とメニュー起動条件**（FR-96）
  - 編集モード（FR-75）かつ表示専用でないとき、メインマップ上の右クリック（コンテキストメニュー要求イベント）を受理する。
  - メニューを開く条件は「**アクティブ地物が 1 件ある**」または「**頂点選択セットが空でない**」のいずれかが成立していること。どちらも成立しない（空選択）右クリックではメニューを開かない（または操作対象なしの状態として何も出さない。受け入れ基準で固定）。
  - 右クリック位置（スクリーン座標）と、右クリックがヒットした要素（地物本体／特定の頂点／空き領域）を入力として受け取る。メニューの対象は「いま選択されている対象」を第一候補とする（教訓 5.3/5.4）。右クリックが選択外の地物・頂点にヒットした場合の選択置換挙動は U22 の選択規約に委ね、本ユニットは確定後の選択状態を基準にメニューを構成する（後述 4.2）。
- **メニュー項目の動的構成（派生状態）**（FR-96）
  - 選択対象と種類・ツール種類から、表示項目集合を算出する純粋関数を提供する。項目の出し分けは以下を満たす。
    - **共通項目（対象が点／線／面のいずれでも出す）**: 「削除」「プロパティ編集」。
    - **共有頂点項目**: 頂点選択セットに**共有頂点が 1 つ以上含まれる**場合に「共有解除」を出す。
    - **面情報項目（対象が面情報＝末端地物のとき）**: 「分割」「所属変更」「結合」を出す。
  - 各種別ルール（点／線／末端地物／集約地物／共有頂点の有無）は型定義・定数・ファクトリ経由で判定し、表示文字列や思い込みで分岐しない（教訓 5.19）。
  - 対象種別ごとに項目が「出る／出ない」だけでなく「出るが無効（グレーアウト）」となる状態も区別して算出する（例: 面情報だが分割が現時点で不可能な場合の扱いは受け入れ基準で固定。少なくとも集約地物では分割を提供しない＝出さない、後述 4.4）。
- **既存フローへのディスパッチ**（FR-96、各依存ユニットへ接続）
  - 「削除」→ 削除フロー（U31）を起動する。確認ダイアログ・参照掃除・連鎖剪定・履歴記録は U31 が担う（FR-85 とも整合）。
  - 「プロパティ編集」→ プロパティ編集 UI（プロパティパネル／詳細パネル）を当該対象に対して開く（属性編集自体は別ユニットの責務。本ユニットは「この対象のプロパティ編集を開く」意図を発火する）。
  - 「共有解除」→ 共有解除フロー（U11）を、右クリック対象の共有頂点（または頂点選択セット内の共有頂点）に対して起動する（FR-33）。
  - 「分割」→ ナイフツール／分割フロー（U26）を、対象面情報を分割対象として起動する（FR-44）。
  - 「所属変更」→ 所属変更フロー（U28）を、対象面情報を対象として起動する（FR-46）。
  - 「結合」→ 結合（合体）フロー（U30）を起動する。結合は 2 つ以上の対象を要するため、対象選択の起点（少なくとも当該面情報を結合の最初の対象に据える）として接続する（FR-50）。結合対象が 1 つしか確定していない場合の扱いは後述 4.4・受け入れ基準で固定する。
- **権限境界の一括無効化（表示専用モード）**（教訓 5.13）
  - 表示専用モード（編集が許可されないモード）では、右クリックでメニューを**開かせない**。メニュー項目を見た目だけ非表示にして経路を残すのではなく、右クリック受理・メニュー構成・各項目ディスパッチを同じ権限判定（共通ヘルパーまたは状態機械）で一括的に遮断する。
  - 同じ権限判定を、メニュー項目に対応するキーボードショートカット経路（もし本アプリでメニュー項目相当のショートカットを提供する場合）にも適用し、ショートカットだけ生き残る取りこぼしを作らない。
- **一時 UI 状態の全経路破棄**（教訓 5.2）
  - 開いているコンテキストメニューは、項目選択（確定）・メニュー外クリック・Escape・選択解除・モード切替・ツール切替・時間移動による選択無効化（後述）のすべての経路で閉じ、開いていたメニューの一時状態（対象スナップショット・表示位置・ハイライト）を破棄する。
- **選択状態変化への追従**（教訓 5.5）
  - メニューが開いている間に、依存する選択状態（アクティブ地物・頂点選択セット）や時刻が変化して対象が無効化された場合、開いているメニューを閉じる（古い対象に対する操作を発火させない）。
- **メニュー入力層の設計**（教訓 5.14）
  - コンテキストメニューはメインマップ上に重なるオーバーレイである。描画順だけでなく入力受理層も同時に設計し、メニューが開いている間は背面のマップ操作（パン・選択・別の右クリック）を奪わない／奪う境界を明示する。メニュー外クリックでメニューを閉じる入力経路と、項目クリックで確定する入力経路を区別する。
- **エラー・拒否の日本語表示への写像**（FR-115/FR-117）
  - ディスパッチ先フロー（U11/U26/U28/U30/U31/U13）が拒否（制約違反・時間制約違反・収束失敗・結合事前条件違反等）を返した場合、その理由を日本語のユーザー向けメッセージとして UI へ橋渡しする。想定外の内部不整合は「開発者へ報告してください」案内付きで扱う。本ユニットは拒否理由を握りつぶさず、判断用メッセージを無関係なクリックで即時消さない（教訓 5.12）。

### 2.2 やらないこと

- **各操作の本体実装**: 分割アルゴリズム（U26）・所属変更フロー本体と循環参照検証（U28）・結合の論理和／平坦化／混在処理と事前条件検証（U30）・削除の参照掃除と連鎖剪定（U31）・共有解除の頂点複製と再共有抑制（U11）は、いずれも各依存ユニットの責務。本ユニットは起動口を提供するだけで、これらのドメインロジックを再実装しない。
- **整合性維持プロセス本体**（FR-61〜FR-63、U13）。本ユニットは「右クリック起動でも各フローが確定時に整合性維持プロセスを通る」ことを結線で保証するのみで、固定順序オーケストレーション・競合検出・競合解決ダイアログ駆動は U13 と各フローが担う。
- **選択機構本体**（アクティブ地物の保持・頂点選択セット／コンテキストの管理・矩形範囲選択・選択の視覚 FB）。U22 の責務。本ユニットは U22 が確定した選択状態を入力として受け、メニュー構成・ディスパッチに使う。右クリックによる選択置換の規約自体も U22 に委ねる（本ユニットは確定後の選択を基準にする）。
- **プロパティ編集 UI・属性入力フォーム・錨一覧・削除ボタンそのものの描画**（プロパティパネル系ユニットの責務）。本ユニットは「この対象のプロパティ編集を開く」意図の発火のみ行う。
- **モード切替・ツールバーのツール選択 UI**（別ユニット）。本ユニットは「編集モードであること」「現在のツール種類」を入力として受け取る側であり、モード／ツールの切替操作自体は持たない。
- **アンドゥ・リドゥの二重スタック実装**（U12 の責務）。各フローが U13/U12 経由で単一アンドゥ単位として確定する（FR-94）。本ユニットは履歴を直接積まない。
- **コンテキストメニューの最終的な見た目（CSS・アイコン・配置の細部）**: React UI シェルの実装範囲だが、本仕様は「どの項目をどの状態で出すか」という構成ロジック（派生状態）の契約を定める。視覚スタイルの最終描画は UI 層が担う。
- **測量モード・追加モードでの右クリック**（本ユニットは編集モードのコンテキストメニューに限定。FR-96 が編集モードを対象とする）。
- **共有頂点のスクリーン近接スナップ判定・空間インデックス**（FR-31。スナップ判定本体は編集セッション U24 が所有し、近傍候補は U10、共有化コマンドは U11）。本ユニットは「頂点選択セットに共有頂点が含まれるか」を、U11/U22 が公開する共有判定の派生結果から取得するだけで、共有判定を再発明しない。

## 3. 依存（dependsOn）

本ユニットは以下のユニットへディスパッチ（接続）する。依存ユニットの公開インタフェース（フロー起動関数名・引数・戻り値型）は偶然の一致に頼らず、共有型を import して両側テストで固定する（教訓 5.33/5.34）。**依存ユニットが未実装の場合は、本仕様に記す入出力契約に沿った型インタフェース（フロー起動口）を先に定義し、その型に対してメニュー構成・ディスパッチ・単体テストを実装する**（U13/U24 と同じ運用）。

- **U26 — 分割（ナイフツール）フロー**: 「分割」項目から、対象**末端地物**を分割対象としてナイフツール／分割フローを起動する（FR-44）。集約地物は分割対象に含めない（FR-44、教訓 5.25）。本ユニットは対象地物 ID と起動意図を渡し、分割の入力（分断線）・確定・継承先ダイアログ・整合性遷移は U26 が担う。
- **U28 — 所属変更フロー**: 「所属変更」項目から、対象面情報を対象として所属変更フローを起動する（FR-46）。割譲・連邦化・独立・帰属・直轄化・自治化等の操作種別の出し分けと循環参照検証は U28 の責務（教訓 5.27）。本ユニットは対象を渡してフローを開く。
- **U30 — 結合（合体）フロー**: 「結合」項目から、結合フローを起動する（FR-50）。結合は 2 つ以上の対象を要し、対象が互いに上位・下位関係にないこと等の事前条件検証は U30 の責務（教訓 5.27）。本ユニットは当該面情報を結合対象の起点として渡し、対象集合の確定・上位/プロパティ決定ダイアログ・整合性遷移は U30 が担う。
- **U31 — 削除フロー**: 「削除」項目から、対象（点／線／面いずれでも）を削除フローへ渡す（FR-41/FR-85）。確認ダイアログ・全時刻からの参照掃除・空になった派生（集約地物）の連鎖剪定・履歴記録は U31 の責務（教訓 5.21）。
- **U11 — 共有頂点システム（共有解除）**: 「共有解除」項目から、対象共有頂点に対し共有解除コマンドを起動する（FR-33）。解除対象の特定（右クリック頂点／選択セット内の共有頂点）・同座標新頂点への切り離し・再共有抑制は U11 の責務。本ユニットは「どの共有頂点を解除するか」を渡す。

加えて、本ユニットは次のユニットの公開状態・契約を**入力として参照する**（dependsOn には未記載だが結線に必須。U24 と同じく、未実装時はインタフェース契約を先に定義する）。

- **U22 — 選択システム**: 現在の選択状態（アクティブ地物 0/1 件、頂点選択セット、頂点選択コンテキストの所有地物、共有頂点を含むか）を提供する。本ユニットのメニュー対象・出し分けはこの選択状態を第一候補にする（教訓 5.3/5.4）。U22 はコンテキストメニューの項目構成を「別ユニット（本ユニット）に委ねる」と明示しており、本ユニットはその受け皿である。
- **U13 — 整合性維持プロセスの骨格**: 各フローの確定が U13 を通ることを前提とする。本ユニットは U13 を直接起動しないが、各フロー起動 → 確定 → U13 という経路が右クリック起動でも成立することを結線・テストで保証する（FR-61〜FR-63）。
- **モード／ツール状態の提供元**: 編集モードか否か・表示専用か否か・現在のツール種類を提供するモード状態（FR-75 のモード切替を持つユニット）。本ユニットは権限判定（表示専用無効化）と項目出し分け（ツール種類）にこれを用いる。

## 4. 実装方針（技術方針に沿う）

技術方針に従い、本ユニットは責務を二層に分けて実装する。**「どの項目をどの状態で出すか」「どのフローへ何を渡すか」という構成・ディスパッチ判定は副作用のない純粋関数として `domain`（またはフレームワーク非依存の選択/メニュー派生ロジック）に切り出し、Vitest 単独で実行できるようにする**。コンテキストメニューの描画・ポインタ（右クリック）イベント受理・メニュー外クリックの捕捉・項目クリックの結線は React UI シェル（技術方針 2.3）に置き、依存方向を `domain` へ内向き固定する（技術方針 2.13、開発ガイド §4）。地図描画は React の再レンダリングサイクルから切り離す規律（技術方針 2.3）を守り、メニュー開閉のような UI/セッション状態は Zustand の薄いストアで扱う（技術方針 2.5）。

### 4.1 メニュー構成ロジック（純粋な派生状態）

メニュー項目集合は、選択状態・対象種類・ツール種類から決定的に導出する**純粋関数**として実装する。

- 入力: 現在の選択状態（アクティブ地物 ID と種類、頂点選択セットの生 ID 集合、頂点選択コンテキストの所有地物、共有頂点を含むか）、現在のツール種類、編集権限（編集可否）。
- 出力: 表示すべき項目の順序付きリスト。各項目は「種別識別子（型/定数経由、教訓 5.19）」「表示ラベル（日本語、FR-115）」「有効/無効（グレーアウト）状態と無効理由」「ディスパッチ先フローの識別」を持つ不変値とする。
- 出し分け規約（FR-96）:
  - 共通: 削除・プロパティ編集（対象が点／線／面のいずれでも）。
  - 共有頂点を含む: 共有解除。
  - 面情報（末端地物）: 分割・所属変更・結合。
- **生の ID 集合まで評価して分岐を網羅する**（教訓 5.10）。アクティブ地物の有無（0/1）と頂点選択セット（空／単一／複数／所有者不明）を、派生ヘルパー結果だけでなく生の値まで評価し、各状態に項目集合を一対一で対応付ける。空選択ではメニューを構成しない。
- **構成ロジックは単一の真実源とし全経路で共有する**（開発ガイド §4、教訓 5.29）。右クリックメニューの構成と、もし将来同等のショートカット案内・補助 UI で「いま可能な操作」を提示する場合は、同じ構成判定を共有してドリフトを防ぐ。

### 4.2 対象の決定（UI 文脈優先）

メニューの操作対象は「いま UI 上で選択されている対象」を第一候補にする（教訓 5.3/5.4）。

- アクティブ地物が 1 件ある場合: その地物を対象とする。種類（点／線／末端地物／集約地物）はアクティブ地物の現在錨評価から判定する。
- アクティブ地物がなく頂点選択セットが非空の場合: 頂点選択コンテキスト（U22 が解析する所有地物。単一地物が全頂点を所有する場合のみ確定）を対象に使う。所有者が複数／不明のときは、地物全体に対する操作（分割・所属変更・結合）の対象を一意に決められないため、それらの項目は出さない（または無効化）。共有解除は頂点単位で成立しうるため、頂点選択セット内の共有頂点を対象に出してよい（後述 4.3）。
- 右クリックが現在の選択外の要素にヒットした場合の選択置換は U22 の規約に従い、**選択が確定した後の状態**でメニューを構成する。本ユニットがデータソース全体や先頭要素を勝手に対象にしない（教訓 5.4）。

### 4.3 共有解除項目の対象判定（FR-33、U11/U22 経由）

- 「共有頂点を含む」判定は、U11/U22 が公開する共有判定の派生結果（頂点 ID → 共有か否か）から取得する。本ユニットは共有判定を再実装しない（開発ガイド §4 単一の真実源）。
- 頂点選択セットに共有頂点が 1 つ以上含まれるとき「共有解除」を出す。右クリックが特定の共有頂点にヒットしている場合はその頂点を解除対象の第一候補とし、複数共有頂点が選択されている場合の解除対象範囲（ヒット頂点のみ／選択中の全共有頂点）は受け入れ基準で固定する。
- ディスパッチ先 U11 の共有解除コマンドへ「どの共有頂点を、どの形状参照について解除するか」を渡す。解除後の再共有抑制は U11 が担う。

### 4.4 面情報項目の可否（末端地物限定・出し分け）

- **分割（U26）**: 対象が**末端地物**のときのみ提供する。集約地物は形状属性を持たず直接分割できない（FR-44/FR-35）ため、集約地物では分割項目を出さない。仕様が末端地物に限定した対象範囲を「対称性」で集約地物へ広げない（教訓 5.25）。
- **所属変更（U28）**: 面情報（末端地物）に対し提供する。集約地物の所属変更は全下位領域を対象に行う（FR-48）ため、集約地物に対する所属変更の起動可否・対象の渡し方は U28 の契約に従う（本ユニットは対象を渡し、操作種別の出し分けは U28）。
- **結合（U30）**: 面情報に対し提供する。結合は 2 つ以上の対象を要する（FR-52）。右クリック起点では当該面情報を結合対象の起点として渡し、追加対象の確定は U30 のフローに委ねる。対象が 1 つしか確定できない状況では結合を無効化（理由つきグレーアウト）するか、U30 のフローへ「起点 1 件」を渡して対象追加を促すかを、U30 の契約に合わせて受け入れ基準で固定する。
- **結合と所属変更を混同しない**（教訓 5.27）。両者は別概念であり別フロー（U30/U28）へディスパッチする。メニュー上でも別項目として明確に分け、片方の事前条件をもう片方に流用しない。

### 4.5 表示専用モードでの一括無効化（教訓 5.13、必須）

- 編集権限（編集可否）の判定を**単一の共通ヘルパー／状態機械**で行い、表示専用のとき次をすべて遮断する。
  - 右クリック（コンテキストメニュー要求）の受理 → メニューを開かない。
  - メニュー構成ロジック → 編集項目を生成しない。
  - 各項目のディスパッチ → 起動経路を無効化する。
  - 各項目に対応するショートカット経路（提供する場合）→ 同じ権限判定で無効化する。
- **部品ごとに個別判定を書かない**。見た目だけ非表示にして右クリックやショートカット経路を残すアンチパターンを避ける。モード境界は共通判定で表現し、追加・編集モードの切替（FR-75）と整合させる。

### 4.6 ディスパッチと整合性プロセスの結線（FR-96 後段）

- 各項目選択は、対応フロー（U11/U26/U28/U30/U31）の公開起動関数を、4.2/4.3/4.4 で決めた対象・起点状態で呼ぶだけにする。フロー本体・確定・整合性維持プロセス（U13）・履歴積み（U12）はディスパッチ先が担う。
- **右クリック起動でも、UI ボタン起動と同じフロー・同じ整合性プロセスを通る**ことを保証する（FR-96「これらの操作も完了時に整合性維持プロセスを経る」）。本ユニットは別経路の簡略フローを作らない（教訓 5.6: 同じ結果状態を生む複数経路に対し、特定経路だけのゲート／簡略化を作らない）。
- 削除・分割・結合・所属変更・共有解除はいずれも対象 ID・形状が変わりうる構造変更操作である。完了後の選択状態は固定の全クリアで決めず、フローのコマンド結果（残る ID／新規 ID／削除 ID）から U22 と協調して再解決する（教訓 5.11）。本ユニットは選択再解決を直接行わないが、ディスパッチがコマンド結果を U22 へ橋渡しできる結線にする。

### 4.7 一時状態・選択追従・入力層（教訓 5.2/5.5/5.14）

- 開いているメニューの一時状態（対象スナップショット・表示位置・ハイライト）は、確定・メニュー外クリック・Escape・選択解除・モード切替・ツール切替・時間移動による対象無効化のすべての経路で破棄する（教訓 5.2）。
- メニュー表示中に選択状態・時刻が変化して対象が無効化されたら、メニューを閉じる（教訓 5.5）。古い対象へのディスパッチを発火させない。
- メニューオーバーレイは、描画順と入力受理層を同時に設計する（教訓 5.14）。メニュー表示中は背面マップへの誤クリック（パン・別選択）を起こさず、メニュー外クリックで閉じる経路と項目クリックで確定する経路を分ける。

### 4.8 成果物・公開インタフェース（型レベルの契約）

実装者は以下の概念を型として定義すること（名称は実装で確定してよいが契約の意味は固定）。

- メニュー項目（ContextMenuItem 相当）: 種別識別子（型/定数経由、教訓 5.19）・日本語ラベル・有効/無効状態・無効理由・ディスパッチ先フロー識別を持つ不変値。
- メニュー構成（ContextMenuModel 相当）: 対象（地物 ID と種類／共有頂点集合）・項目の順序付きリスト・表示位置（スクリーン座標）を持つ不変値。空選択時は「メニューなし」を表現する状態を持つ。
- メニュー構成関数（純粋）: `(選択状態, ツール種類, 編集権限) → メニュー構成 | メニューなし`。生 ID 集合まで評価して分岐を網羅する（教訓 5.10）。
- ディスパッチ（純粋な意図発火 + UI 結線）: `(選択された項目, メニュー構成) → 対応フローの起動意図`。本ユニットはフローの起動意図を返し、結線層が依存ユニットの起動関数を呼ぶ。

## 5. 受け入れ基準（テスト可能な形で列挙）

純粋ロジック（メニュー構成・対象決定・出し分け・権限判定・ディスパッチ意図）は Vitest の「入力状態 → 操作 → 期待結果」で検証し、右クリック→メニュー表示→項目選択→フロー起動の通し挙動と入力層は E2E（Playwright for Electron）でも確認する。

1. **右クリックでメニュー表示**（FR-96）: 編集モードかつ非表示専用で、アクティブ地物が 1 件あるとき、または頂点選択セットが空でないとき、メインマップ上の右クリックでコンテキストメニューが表示される。空選択（アクティブ地物なし・頂点選択セット空）ではメニューが表示されない。
2. **オブジェクト種類による動的変化**（FR-96）:
   - 対象が点情報のとき、共通項目（削除・プロパティ編集）が出て、面情報項目（分割・所属変更・結合）が出ない。
   - 対象が線情報のとき、共通項目が出て、面情報項目が出ない。
   - 対象が面情報（末端地物）のとき、共通項目に加え分割・所属変更・結合が出る。
   - 対象が集約地物のとき、分割が出ない（末端地物限定、FR-44/FR-35、教訓 5.25）ことを検証する。所属変更・結合の出し分けは U28/U30 契約に沿う。
3. **共有頂点による動的変化**（FR-96/FR-33）: 頂点選択セットに共有頂点が含まれるとき「共有解除」が出て、含まれないとき出ない。共有判定は U11/U22 の派生結果から取得し、本ユニットで再判定していないことを検証する。
4. **ツール種類による動的変化**（FR-96）: 現在のツール種類に応じてメニュー内容が変化する規約（少なくともツール種類が出し分けの入力に含まれること）を、入力ツール種類を変えたときに項目集合が規約どおり変わるテストで固定する。
5. **共通・共有頂点・面の項目セットが規約どおり出る**（FR-96）: 削除・プロパティ編集（共通）、共有解除（共有頂点）、分割・所属変更・結合（面情報）が、それぞれの成立条件で出ることを一括で検証する。各項目の種別識別子が型/定数経由で一意であること（教訓 5.19）を含む。
6. **既存フローへのディスパッチと整合性プロセス接続**（FR-96 後段）:
   - 「削除」選択で削除フロー（U31）が、対象（点/線/面）を引数に起動される。
   - 「共有解除」選択で共有解除（U11）が、対象共有頂点を引数に起動される。
   - 「分割」選択で分割フロー（U26）が、対象末端地物を引数に起動される。
   - 「所属変更」選択で所属変更フロー（U28）が、対象を引数に起動される。
   - 「結合」選択で結合フロー（U30）が、当該面情報を結合起点として起動される。
   - 「プロパティ編集」選択でプロパティ編集 UI が当該対象に対して開く。
   - 各起動が、UI ボタン起動と同一のフロー・同一の整合性維持プロセス（最終的に U13）を通ること（右クリック専用の簡略経路がないこと）を検証する（教訓 5.6）。
7. **表示専用モードでの一括無効化**（教訓 5.13、FR-96 受け入れ基準）: 表示専用モードでは、(a) 右クリックでメニューが開かない、(b) メニュー構成ロジックが編集項目を生成しない、(c) ディスパッチ経路が無効、(d) 対応ショートカット経路（提供時）も無効、のすべてが**同じ権限判定**で成立することを検証する。見た目だけ非表示で右クリック／ショートカットが生き残る取りこぼしがないことを含む。
8. **対象の UI 文脈優先と分岐網羅**（教訓 5.3/5.4/5.10）: アクティブ地物がある場合はそれを対象にし、ない場合は頂点選択コンテキスト（単一所有のみ）を対象にする。所有者が複数／不明のとき地物全体操作（分割/所属変更/結合）が出ない（または無効）こと、空選択でメニューが出ないことを、生の ID 集合まで評価した分岐で網羅検証する。
9. **拒否理由の日本語写像とメッセージ保持**（FR-115/FR-117、教訓 5.12）: ディスパッチ先フローが拒否（事前条件違反・制約違反等）を返したとき、日本語のユーザー向けメッセージへ写像される。判断用メッセージが発生元と無関係なクリックで即時消去されないことを検証する。
10. **一時状態の全経路破棄と選択追従**（教訓 5.2/5.5）: メニューが、項目選択・メニュー外クリック・Escape・選択解除・モード切替・ツール切替・時間移動による対象無効化のすべてで閉じ、一時状態が破棄される。「開く→キャンセル→再操作」「開く→確定→再操作」の連続で残留状態がないこと、開いている間に選択/時刻が変わり対象が無効化されたら閉じることを検証する。
11. **入力層の保証**（教訓 5.14）: メニュー表示中に背面マップへの誤操作（パン・別選択）が起きず、メニュー外クリックで閉じ、項目クリックで確定する経路が区別されることを E2E で検証する。
12. **構造変更後の選択再解決の結線**（教訓 5.11）: 削除・分割・結合・所属変更・共有解除の完了後、選択が固定全クリアでなくフローのコマンド結果から U22 と協調して再解決される結線（本ユニットがコマンド結果を橋渡しすること）を検証する。

## 7. 注意点・既知の落とし穴（開発ガイドの教訓）

着手前に開発ガイド §1.6 の作業開始ゲートに従い、下記の該当教訓を節番号・見出しごと引用し、今回の実装判断への適用を「適用:」として 1 文以上で宣言してから実装すること。

- **§5.13 表示専用モードでは編集経路を一括無効化する**: 適用 — 表示専用モードでは右クリック受理・メニュー構成・各項目ディスパッチ・対応ショートカットを単一の権限判定で一括無効化し、部品ごとの個別判定で「見た目だけ非表示・右クリック／ショートカット残存」を作らない。受け入れ基準 7 で固定する。本ユニットの受け入れ基準に明記された必須事項。
- **§5.25 仕様が限定した対象範囲を実装で広げない**: 適用 — 分割は末端地物に限定（FR-44/FR-35）。集約地物へ「対称性」で広げず、面情報という理由だけで集約地物に分割を出さない。広げたくなったら本書 4.4 と FR-44 を引用して止める。
- **§5.27 結合と所属変更は事前条件を分けて検証する**: 適用 — 結合（U30）と所属変更（U28）は別概念。メニューでも別項目とし、別フローへディスパッチし、片方の事前条件を流用しない。
- **§5.10 選択状態は生の集合まで評価して網羅する**: 適用 — アクティブ地物 ID（0/1）と頂点選択セット（生 ID 集合: 空／単一／複数／所有者不明）を派生ヘルパーだけで判定せず生の値まで評価し、項目集合・表示条件を各分類へ一対一対応させる。受け入れ基準 8 で固定する。
- **§5.3 操作対象は表示状態に限定する／§5.4 追加・編集・複製・結合は現在の UI 文脈を第一候補にする**: 適用 — メニュー対象はいま選択されている対象（アクティブ地物→頂点選択コンテキスト）を第一候補にし、データソース全体・コレクション先頭を既定で対象にしない。
- **§5.6 状態変化の検出は結果状態で判定する**: 適用 — 右クリック起動でも UI ボタン起動と同じ結果状態（同じフロー・同じ整合性プロセス）を通す。右クリック専用の簡略・別ゲートを作らない（別経路で整合性が漏れる）。
- **§5.5 依存する状態は変化時に再検証する**: 適用 — メニュー表示中に選択・時刻が変化して対象が無効化されたら、メニューを閉じて古い対象へのディスパッチを防ぐ。受け入れ基準 10。
- **§5.2 一時的 UI 状態は全経路で破棄する**: 適用 — 開いているメニューの一時状態を、確定・外クリック・Escape・選択解除・モード切替・ツール切替・対象無効化の全経路で破棄する。「開く→キャンセル→再操作」「開く→確定→再操作」で検出する。
- **§5.14 重なる UI は入力を受ける層も同時に設計する**: 適用 — メニューオーバーレイは描画順と入力受理層を同時に設計し、背面マップ操作を奪う／奪わない境界を明示する。外クリックで閉じる経路と項目クリックで確定する経路を分ける。受け入れ基準 11。
- **§5.9 排他分岐が重要処理をスキップしていないか確認する**: 適用 — 「アクティブ地物優先／頂点選択コンテキスト」の選択優先順位と、項目の出し分け分岐が、共有解除・面情報項目などの成立条件をスキップしないことを確認する。
- **§5.11 構造変更操作後の選択は結果から再解決する**: 適用 — 削除・分割・結合・所属変更・共有解除の完了後、選択を固定全クリアにせず、フローのコマンド結果（残存/新規/削除 ID）から U22 と協調して再解決する結線にする。
- **§5.12 判断用メッセージを無関係な操作で消さない**: 適用 — ディスパッチ先の拒否理由メッセージを、発生元と無関係なクリックで即時消さない。消す契機を「再試行」「明示的な閉じる」「成功した置換」に限定する。
- **§5.19 分岐識別子は型定義・定数・ファクトリを経由する**: 適用 — メニュー項目種別・ツール種類・対象種類の分岐は表示文字列でなく型/定数/ファクトリ経由で判定し、作成・表示・ディスパッチ・テストの全経路で同じ値を使う。
- **§5.26 編集制約はコマンド確定前にも同じサービスで検証する**: 適用 — メニューで項目を有効表示しても、各フローの確定前検証（U13/各依存ユニット）を必ず通す。右クリック経路から不正状態が入らないよう、確定前検証をスキップしない。
- **§5.33 / §5.34 層をまたぐ契約は型と両側テストで固定する**: 適用 — U11/U22/U26/U28/U30/U31/U13 の起動関数・引数・戻り値型を共有型で import し両側テストで固定する。依存未実装時は本仕様の入出力契約に沿った型を先に定義する（U24 と同じ運用）。
- **§5.18 空配列・空オブジェクトは真値である**: 適用 — 「頂点選択セットが空」「メニュー項目 0 件」「共有頂点なし」を論理和の短絡デフォルト補完で誤判定せず、長さ・有無を明示判定する。
- **クリーンルーム原則（§3.1）**: 本仕様・実装ともに過去版・他プロダクト・「従来」等の外部参照を持ち込まない。制約は v4 要件として直接記述・参照する。
- **失敗の教訓化（§1.5 / §1.9）**: 実装中に既存教訓で説明できない不具合の根本原因が見つかったら、完了前に開発ガイド §5 へ新教訓を追記し、回帰テストを同一作業内で追加する。

# U14 永続化スキーマ(Zod)とバージョン検証・整合性チェック・自動修復

## 目的

プロジェクトデータ・アプリケーション設定・外部から読み込むデータに対する単一の宣言的スキーマ（Zod）を定義し、そこから TypeScript 型を導出する。これにより「検証ロジックと型が二重定義される」偶発的複雑性を排除する。保存形式の論理的完全性（全頂点・点情報・線情報・面情報・歴史の錨・最上位フラグ・親子関係・種別ラベル・設定・ベースマップ参照）をスキーマで保証し、読み込み時にはマニフェスト先頭のバージョン文字列で形式の妥当性を検証する。さらに、スキーマ検証だけでは捕捉できないドメイン水準の不整合（存在しない頂点参照・ツリー位相不整合・形状保持規則違反・末端排他違反・親=下位和不一致・時間矛盾・錨間オーバーラップ）を検出し、ユーザーが選択可能な自動修復オプションを提供する。

本ユニットは保存内容の「構造的妥当性」と「ドメイン整合性」を担う境界防御層である。実際の ZIP コンテナ入出力・ファイル I/O・自動バックアップは別ユニットの責務であり、本ユニットはそのバイト列を JS 値へ変換した後（または変換する前）のスキーマ検証・整合性チェック・修復という純粋ロジック層に集中する。

## スコープ

### やること

- 保存データ全体（マニフェスト JSON）の Zod スキーマ定義と、そこからの TS 型導出。対象は要件 FR-103 が列挙する保存内容すべて。
  - 頂点（共有頂点を含む）、点情報、線情報、面情報（末端地物・集約地物）。
  - 各地物の歴史の錨（時間依存の状態スナップショット: 形状・属性・親子関係・存在状態）。
  - 各錨の最上位フラグ・親子関係（上位領域参照）・種別ラベル。
  - 面情報のリング構造（領土リング／穴リング、飛び地、ネスト）。
  - アプリケーション設定（プロジェクト固有設定・アプリ全体設定）。
  - ベースマップ参照（ZIP コンテナ内アセットへの相対参照と赤道長等のメタ）。
- マニフェスト先頭にバージョン文字列フィールドを保持するスキーマ設計。読み込み時にバージョンの妥当性を検証し、システムが対応する形式と一致しない場合は互換性の警告／拒否を返す。
  - バージョンを判別子とする discriminated union でスキーマを分岐する設計とする（現時点では対応バージョンは 1 種類でよいが、判別子による分岐構造を最初から用意する）。
  - 互換マイグレーション（旧形式の読み込み変換）は本ユニットのスコープ外。非互換バージョンは警告／拒否のみとする。
- 読み込み時のドメイン整合性チェック（FR-106 が列挙する 7 種の不整合）の検出。各検出項目について、ユーザーが選択可能な自動修復オプションを返す。
  1. 存在しない頂点参照（地物・リングが参照する頂点 ID がデータ中に存在しない）。
  2. ツリー位相の不整合（親参照の循環、親が存在しない、最上位フラグと親の有無の不一致など）。
  3. 末端地物／集約地物の形状保持規則違反（集約地物が形状属性を持つ、末端地物が形状を持たない等）。
  4. 末端地物の排他違反（同一時刻で末端地物同士が重なる）。
  5. 親領域と下位領域の和の不一致（集約地物の形状＝全直接下位領域の和に厳密一致しない）。
  6. 時間プロパティの矛盾（錨列が開始時刻昇順でない、時間的重複、有効期間が非正、終了時刻が次錨より後など）。
  7. 錨間の空間的オーバーラップ（異なる地物の同時刻状態が空間的に競合する）。
- 検出結果を構造化したレポート（不整合種別・関連地物名／ID・該当作中時刻または時間範囲・競合種類）として返す型と、修復オプションの提示・適用ロジック。
- 外部入力（IPC・ファイル読込・外部地図入力）の境界では必ず Zod を通すための公開 API（パースエントリポイント）の整備と、未検証入力がドメインへ流入しないことを lint で強制する仕組みへの接続点（lint ルールが検知できるよう、境界モジュールを明示的に分離・命名する）。
- serialize（ドメイン状態 → マニフェスト JSON 値）と deserialize（マニフェスト JSON 値 → ドメイン状態）の往復関数、およびそれらが恒等（往復で同値）になることを保証する往復テスト。
- read（deserialize）・write（serialize）・validation（Zod スキーマ・整合性チェック）・往復テストを同一変更単位で同期する（教訓 5.31）。

### やらないこと

- ZIP コンテナ（`.tmap`）の入出力・ファイル I/O・一時ファイル → fsync → アトミックリネーム・世代バックアップ（別ユニットの永続化基盤の責務。本ユニットは JS 値レベルで完結する）。
- 旧バージョン形式の読み込み互換・版間データマイグレーション（要件 §5.3／将来実装 §7.3 によりスコープ外。バージョン不一致は警告／拒否のみ）。
- ベースマップ画像・添付画像のバイナリ検証・自動補正・フォールバック処理（本ユニットは参照（パス・メタ）の妥当性のみ検証）。
- 整合性チェックで用いる幾何述語（重なり判定・和集合算出）そのものの実装。これらは依存ユニットが提供する純粋関数を呼び出して利用する（本ユニットは「検出と修復オプション提示の枠組み」を担い、幾何演算は委譲する）。
- ドメインの編集操作・コマンド・アンドゥ／リドゥ・整合性維持プロセス（競合解決ダイアログ等）。本ユニットは「読み込み時の一度きりの検査・修復」であり、編集中のリアルタイム検証とは別物。
- Markdown 詳細文書の無害化（DOMPurify 等の責務。ただし詳細文書フィールドがスキーマ上「文字列として存在する」ことの検証は行う）。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが提供するドメイン型・純粋関数・不変条件を前提として実装する。

- **U07**: 地物・頂点・リング・共有頂点のドメインモデル（判別共用体: 点／線／末端／集約、領土リング／穴リング）。スキーマはこれらのドメイン型と一対一対応し、型を導出した結果が U07 の型と構造的に整合すること。
- **U08**: 面情報の階層構造（ツリーモデル: 親子関係、最上位フラグ、階層深度の派生、集約地物＝下位領域の和）。ツリー位相整合性・形状保持規則・親=下位和一致の検証はこの不変条件に基づく。
- **U09**: 歴史の錨と時間モデル（錨列の昇順・非重複、時間正規化、有効期間、非存在期間）。時間矛盾検出はこの時間モデルの不変条件に基づく。
- **U10**: 空間整合性・末端地物排他・幾何述語（重なり判定・和集合算出・空間インデックス）。末端排他違反・錨間オーバーラップ・親=下位和一致の幾何判定はこれらの純粋関数へ委譲する。

依存ユニットが公開する不変条件検証関数・幾何述語・時間正規化関数を再実装せず、本ユニットからは呼び出して利用する（単一の真実源。教訓 §4「単一の真実源」、教訓 5.30 過少共有の戒め）。

## 実装方針（技術方針に沿う）

技術方針が定める採用スタックと層分離に厳密に従う。

### 配置と層分離

- 本ユニットのコードは `domain` 層（フレームワーク非依存・純粋）に属する。Electron・React・Canvas に一切依存せず、Vitest で単独実行可能であること。依存方向は `domain` へ内向きに固定し、`domain` から `ui` / `render` / `shell` を参照しない。
- 外部入力の境界（IPC・ファイル読込・外部地図入力）でのパースは、境界モジュールとして明示的に分離・命名する。これにより「外部入力は Zod を通す」を lint ルールが検知・強制できる構造を作る（R8）。

### スキーマ定義（Zod）

- スキーマは単一の宣言として書き、TS 型は `z.infer` で導出する。検証ロジックと型を二重定義しない（技術方針 2.10）。
- 地物の種別（点／線／末端地物／集約地物）、リングの種別（領土リング／穴リング）は discriminated union で表現し、不正状態を表現不能にする（FR の不変条件を型で表現: 集約地物は形状を持たない／末端地物は形状を持つ等）。
- マニフェスト最上位は `version`（バージョン文字列）を判別子とする discriminated union とする。バージョンが既知の対応値でなければ、パース段階で「非互換」として扱う。
- スキーマは `strict`（未知キーを拒否、または明示的に `strip`／`passthrough` を選び理由をコメントで記す）を基本とし、外部入力のサニタイズ（無害化）を兼ねる（FR-116 / NFR 5.5）。
- 任意属性は `exactOptionalPropertyTypes` と矛盾しないよう、`.optional()` の意味（キー欠落許容か `undefined` 許容か）を明示する。

### バージョン検証

- 読み込み時、まずバージョン文字列の妥当性を検証する。対応形式と一致しない場合は、ドメインへ流入させず、互換性の警告（または拒否）を構造化された結果として返す。
- 警告／拒否の判定と理由は、ユーザー通知（日本語メッセージ）とテスト可能な戻り値の両方で扱える形にする（教訓 5.26 の「拒否理由は通知と戻り値の両方」）。

### 整合性チェックと自動修復

- 整合性チェックは「Zod スキーマ検証を通過した構造的に妥当なデータ」に対して行う 2 段目の検査と位置づける。スキーマ検証（構造）と整合性チェック（ドメイン意味）を明確に分離する。
- 7 種の不整合それぞれについて検出関数を純粋関数として実装し、検出結果（不整合種別・関連地物・時刻／時間範囲・詳細）を構造化レポートとして集約する。
- 各検出に対し、ユーザーが選択可能な自動修復オプション（複数案）を返す。修復はユーザー選択を受けて初めて適用し、適用も純粋関数（入力データ → 修復後データ）として実装する。修復オプションの例:
  - 存在しない頂点参照 → 参照を削除する／ダミー頂点を生成する／当該リング・地物を除外する。
  - ツリー位相不整合（循環・親消失） → 親参照を切って最上位化する／当該地物を除外する。
  - 形状保持規則違反 → 集約地物の形状属性を破棄する／末端地物として再分類する。
  - 末端排他違反・錨間オーバーラップ → 一方を優先し他方を差分調整する／当該錨を除外する（幾何演算は U10 へ委譲）。
  - 親=下位和不一致 → 差分を直轄領として補う／集約形状を下位和で再算出する。
  - 時間矛盾 → 錨列を昇順に整列・重複解消（分割・短縮・削除）する（時間再編ロジックは U09 の規則に従う）。錨列が 0 件になる結果は許可しない。
- 修復は確定まで共有データを破壊的に更新しない（教訓 5.22）。検証用に新インスタンスを生成し、適用結果が再びすべての不変条件を満たすことを再検証してから返す（R2 の「演算後に不変条件チェックを再実行」と同型）。
- 階層を辿る検出（ツリー位相・親=下位和）は、壊れたデータ（循環参照）でも無限ループしないよう visited セットで再入を遮断する（教訓 5.28）。

### serialize / deserialize と往復

- serialize（ドメイン状態 → プレーンな JSON 値）と deserialize（JSON 値 → ドメイン状態）を対称に実装する。履歴・永続化にはプレーン形式で保存し、復元時は新インスタンスを生成、ネストした値も再帰的に変換する（教訓 5.20）。
- ID を生成するような処理は、復元時に採番し直さず保存された ID を復元する（教訓 5.20）。
- read・write・validation・往復テストを同一変更単位で同期する（教訓 5.31）。フィールドを追加・optional 化・撤去する際は再保存往復テストを必ず追加する。

### テスト

- Vitest でスキーマ・検証・往復の単体／契約テストを書く。fast-check で不変条件のプロパティテスト（生成入力に対する serialize→deserialize の恒等性、検出関数が不正データを必ず捕捉すること）を行う。
- ジェネレータはドメインの不変条件から導出した共通モジュールを再利用する（R7）。
- テスト fixture は実体（依存ユニットのファクトリ等）をインスタンス化して構築し、リテラルで型を満たそうとしない（教訓 5.39）。

## 受け入れ基準（テスト可能な形で列挙）

1. **保存内容の論理的完全性（FR-103）**: Zod スキーマが、全頂点（共有頂点含む）・点情報・線情報・面情報（末端／集約）・各地物の歴史の錨・各錨の最上位フラグ・親子関係・種別ラベル・アプリケーション設定・ベースマップ参照をすべて表現できることを、各要素を含む完全なサンプルデータがスキーマ検証を通過するテストで確認できる。いずれかの必須要素を欠いたデータは検証エラーになることをテストで確認できる。
2. **スキーマからの型導出**: スキーマから `z.infer` で導出した TS 型が依存ユニット（U07〜U10）のドメイン型と構造的に整合し、型レベルテスト（または代入互換性の確認）が通る。検証ロジックと型が二重定義されていない。
3. **バージョン保持と非互換の警告／拒否（FR-104）**: マニフェストはバージョン文字列を保持する。対応バージョンのデータは正常に読み込め、未知／非対応バージョンのデータは互換性の警告（または拒否）を構造化結果として返し、ドメインへ流入させないことをテストで確認できる。バージョンを判別子とする discriminated union で分岐している。
4. **7 種の不整合検出（FR-106）**: 以下 7 種それぞれについて、不整合を含むデータを入力すると検出され、構造化レポート（種別・関連地物・時刻／時間範囲・詳細）に現れることを、不整合種別ごとの専用テストで確認できる。(a) 存在しない頂点参照、(b) ツリー位相不整合、(c) 末端/集約の形状保持規則違反、(d) 末端地物排他違反、(e) 親領域=下位領域の和の不一致、(f) 時間プロパティの矛盾、(g) 錨間の空間的オーバーラップ。
5. **自動修復オプションの提供と適用（FR-106）**: 各不整合に対しユーザーが選択可能な修復オプション（1 つ以上）が返され、オプションを適用すると当該不整合が解消し、かつ適用後データが再びすべての不変条件・スキーマを満たすことをテストで確認できる。時間矛盾の修復で錨列が 0 件になる結果は発生しない。
6. **整合データは無修復で通過**: 不整合のない正当なデータは、検出レポートが空（修復不要）となり、そのまま読み込めることをテストで確認できる（過剰検出・誤検出がない）。
7. **serialize→deserialize 往復テスト（教訓 5.31）**: 任意の正当なドメイン状態に対し、serialize した結果を deserialize すると元の状態と同値になる往復テストが通る。fast-check による生成入力でも恒等性が保たれる。
8. **外部入力の Zod 強制（R8）**: 外部入力（IPC・ファイル読込・外部地図入力）の境界が分離・命名され、そこを Zod パースエントリポイント経由でしか通れない構造になっている。未検証の外部入力がドメインへ流入する経路を lint ルールが検知・拒否できることを確認できる（lint 実行で違反が報告される）。
9. **純粋性・単独実行**: 本ユニットのコードは `domain` 層に属し、Electron・React・Canvas に依存せず Vitest で単独実行できる。検出・修復・往復はすべて副作用のない純粋関数である。
10. **循環データでの安全性（教訓 5.28）**: 親子参照が循環する壊れたデータを入力しても、ツリー位相検出が無限ループせず有限時間で「ツリー位相不整合」を報告することをテストで確認できる。

## 関連要件（FR-id）

- **FR-103** (must): プロジェクトデータの保存・読み込み。保存内容の論理的完全性（全頂点・点／線／面情報・歴史の錨・最上位フラグ・親子関係・種別ラベル・設定・ベースマップ）をスキーマで定義する。
- **FR-104** (should): 保存形式にバージョン情報を保持し、読み込み時にバージョンの妥当性を検証し、対応形式と一致しない場合は互換性の警告を表示する。
- **FR-106** (must): 読み込み時のデータ整合性チェックで 7 種の不整合（存在しない頂点参照・ツリー位相不整合・形状保持規則違反・末端地物排他違反・親領域と下位領域の和の不一致・時間プロパティの矛盾・錨間の空間的オーバーラップ）を検出し、ユーザーが選択可能な自動修復オプションを提供する。
- **FR-116** (should): すべてのユーザー入力のバリデーションと無害化、外部から読み込むデータ形式の検証とサニタイズ。

関連する非機能要件: NFR 5.3（保存内容の論理的完全性とバージョン情報の保持）、NFR 5.5（入力検証・無害化）、NFR 5.8（不変条件の機械的検証・往復テストの再現性）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

### 適用宣言（AI 作業開始ゲート, 開発ガイド 1.6）

着手前に以下の教訓を引用し、本ユニットへの適用を宣言してから実装すること。

- **教訓 5.31「永続化の読み書き・検証・移行・往復テストを同期する」**（引用: 「永続化の読（deserialize）・書（serialize）・検証（validation）・移行（migration）・往復テストは、同じ変更単位で同期する。片側だけ変えると『保存はできるが次に開けない』壊れたファイル経路ができ…データ損失リスクになる。」「検出: フィールドを optional 化・撤去・固定値化する変更では、再保存往復テストを必ず追加する。」）。**適用**: 本ユニットでは serialize・deserialize・Zod スキーマ・整合性チェックを 1 つの変更単位として実装し、いずれかのフィールドを変更するたびに再保存往復テストを同時更新する。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.32 / 5.33 / 5.34（多層波及・層をまたぐ契約・コンポーネント間の契約を型で明示）**: 保存スキーマは `domain` 型・永続化・整合性チェック・（将来の）UI 修復ダイアログに波及する多層変更になりやすい。一度に詰め込まず影響経路を最大 2 層で宣言して分割し（5.32）、層をまたぐ契約は共有型・両側テストで固定する（5.33）。仕様から削除した属性は UI → 状態管理 → 永続化 → 描画の順にすべて除去する（5.34）。
- **教訓 5.25「仕様が限定した対象範囲を実装で広げない」**: 末端排他違反の検出は末端地物同士のみを対象とし（FR-26 / FR-27）、集約地物に直接の排他制約を課さない。「対称性確保」を理由に集約地物まで排他検証へ含めないこと。検出対象を広げる前に FR-27 を引用して確認する。
- **教訓 5.22「確定まで共有データを破壊的に更新しない」 / R2**: 自動修復は検証用の新インスタンスで成功を確認し、適用後に全不変条件・スキーマを再検証してから返す。失敗時は元データを汚染しない。
- **教訓 5.28「階層を辿る再帰サービスは循環で無限ループしない」**: 整合性チェックの入力は「壊れている前提」のデータである。ツリー位相・親=下位和の検出は visited セットで再入を遮断し、循環参照でも有限時間で終了すること（受け入れ基準 10）。
- **教訓 5.1「集合演算は複数片を返す前提で扱う」**: 末端排他違反・錨間オーバーラップ・親=下位和の幾何判定で集合演算（U10 へ委譲）を使う際、結果が複数ポリゴン・複数リングになる前提で全片を扱い、先頭片だけを採用しない。
- **教訓 5.18「空配列・空オブジェクトは真値である」**: 「不整合 0 件＝空レポート」「下位領域が空＝集約地物消滅条件」など、空集合の扱いを論理和の短絡で誤らない。型・状態を明示的に判定する。
- **教訓 5.26「編集制約はコマンド確定前にも同じサービスで検証する」 / 拒否理由は通知と戻り値の両方**: バージョン非互換・整合性違反の拒否理由は、日本語ユーザー通知とテスト可能な戻り値の両方で扱える形にする（FR-115: 日本語のみ、必要に応じ「開発者へ報告してください」を付与）。
- **R8（境界での Zod 検証が運用規律に依存し、漏れると型安全の前提が崩れる）**: 境界モジュールでの Zod 通過を lint ルールで強制し、未検証の外部入力がドメインへ流入する経路を構造的に塞ぐ（受け入れ基準 8）。「ここだけ手動で型アサーション」を作らない。
- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / §4「単一の真実源」**: 不変条件の判定（排他・時間・階層）は依存ユニット（U07〜U10）の実装を共有し再実装しない（過少共有の戒め）。一方で、修復オプションの除外規則が不整合種別ごとに異なる場合は安易に共有しない（過剰共有の戒め）。
- **教訓 5.20「元に戻す情報は依存データも含めて過不足なく保存する」**: serialize はプレーン形式で保存し、deserialize で新インスタンスを再帰生成、保存済み ID を採番し直さず復元する。
- **クリーンルーム（開発ガイド 3.1）**: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-103 / 104 / 106 / 116）・技術方針として直接記述する。
- **マイグレーションのスコープ外（要件 §5.3 / §7.3）**: バージョン非互換は警告／拒否のみとし、旧形式読み込み変換のコードを書き込まない。ただし `version` を判別子とする discriminated union の分岐構造は将来のマイグレーション導入に備えて最初から用意しておく。

# U05 経度連続スカラー・世界端ラップ正規化

## 目的

本アプリは地図の横方向の無限スクロールを実現し、地図の東端・西端をまたぐ領域を表示・編集できる（FR-07）。また表示経度を左右にシフトできる（FR-12）。この「世界が経度方向に周期的（±360 度でループする）」という性質は、面のブーリアン演算・末端地物のペア排他検証・空間インデックスによる近傍探索が「世界端（±360 度の周期境界）をまたぐ面」を正しく扱えなければ破綻する。たとえば経度 +179 度から −179 度へまたぐ細長い面は、素朴に座標を扱うと地球を半周する巨大な面として誤解釈され、ブーリアン演算・面積計算・重なり判定がすべて誤る。

本ユニットの目的は、この周期境界問題を **`domain` 層の専用の純粋関数群** として単一の真実源に切り出し、後続の幾何述語・ブーリアン演算・排他検証・空間インデックスが「周期境界を意識せずに連続座標として演算できる」基盤を提供することである。周期境界の扱いをライブラリ（ブーリアン演算ライブラリ等）の暗黙挙動に委ねず、本アプリ自身が明示的に制御する。

この目的は技術方針のリスク緩和策 R3 を直接の根拠とする。R3 は「内部は経度を連続スカラーで保持し、ブーリアン演算・排他検証は周期境界をまたぐ面をワールドラップ展開（±360 度オフセット複製）してから処理する座標正規化を `domain` に明示実装する。ライブラリ任せにせず、専用のラップ正規化関数として切り出しテストする」と定めている。

## スコープ

### やること

1. **経度の連続スカラー表現と ±360 度正規化**
   - 経度を「連続スカラー」（実数値。−180〜+180 のような区間に閉じ込めず、任意実数を取りうる）として保持・受け渡すための型・規約を定義する。
   - 任意の経度スカラーを、指定した代表区間（既定は半開区間 `[-180, +180)`）へ ±360 度の整数倍だけ加減して写す正規化関数を提供する。
   - 緯度は周期性を持たない（極で折り返さない座標値として、入力をそのまま通す）。緯度に対する周期正規化は行わない（行わないことを明示する）。

2. **リング（閉じた頂点列）の世界端ラップ展開（連続化）**
   - 1 本のリング（領土リング／穴リングのいずれも対象）について、隣接頂点間の経度差が ±180 度を超える「またぎ」を検出し、後続頂点に ±360 度のオフセットを累積的に加えることで、リング全体を「経度方向に連続したスカラー座標」へ展開する関数を提供する。
   - 展開後のリングは、隣接頂点の経度差が常に絶対値 180 度未満になる（=最短方向で接続される）ことを保証する。
   - 複数周回（同一方向に世界を 2 周以上するような病的なリングを含む入力）でも、累積オフセットが単調に積み上がる形で一貫して展開できる。

3. **ラップ展開の逆正規化（往復一致）**
   - 展開済みの連続スカラー座標を、各頂点ごとに ±360 度正規化して代表区間へ戻す逆変換を提供する。
   - 「ラップ展開 → 何らかの幾何演算（恒等変換を含む）→ 逆正規化」の往復が、演算が恒等であれば元の正規化済み座標と一致することを保証する（往復不変式）。

4. **演算用の ±360 度オフセット複製（ワールドラップ複製）**
   - 周期境界をまたぐ可能性のある 2 つ以上の面・リング集合に対し、ブーリアン演算・排他検証・空間探索の前処理として、片方（または両方）を −360 / 0 / +360 度オフセットした複製を生成し、両者が同一の連続座標系で重なるよう揃えるための関数を提供する。
   - 複製はあくまで「演算のための一時的な座標系合わせ」であり、複製で増えた座標は演算後に逆正規化して元の代表系へ戻す前提とする。

5. **公開境界（契約）の明確化**
   - 後続ユニット（幾何述語・ブーリアン演算・排他検証・空間インデックス）が「経度の周期性をこのモジュール経由でのみ扱う」ための公開関数群と、その入出力の型・前提条件・事後条件を、テストで固定できる形で定義する。

### やらないこと

- 面のブーリアン演算（和・差・交差）そのものの実装。本ユニットは前処理（座標の連続化と複製）と後処理（逆正規化）のみを担い、演算本体は後続ユニットが担う。
- 末端地物の排他検証アルゴリズム本体・空間インデックス（R-tree）の構築・近傍探索本体。本ユニットはそれらが「周期境界をまたぐ面」を扱えるための座標正規化を提供するに留まる。
- ワールド座標 ↔ スクリーン座標のカメラ変換、表示経度シフトの UI（FR-12 のスライダー／ボタン）、無限横スクロールの描画ループ。本ユニットは描画層・UI 層に依存せず、描画には関与しない（描画層が消費する純粋関数のみを提供する）。
- 距離・面積・大円距離などの測地計算（別ユニットの自前測地モジュールが担う）。ただし本ユニットの逆正規化／連続化は、測地計算が世界端をまたぐ入力を正しく扱うための前処理として再利用されうる。
- 緯度方向の極（±90 度）に関する特殊処理。本アプリの図法は正距円筒図法を前提とし（FR-05）、緯度は周期性を持たないため対象外とする。

## 依存（dependsOn）

- **U03**: 本ユニットが扱う頂点・リング・座標の基本型（頂点の座標値、リング＝閉じた頂点列、領土リング／穴リングの区別など）に依存する。U03 が確立する座標・リングのドメイン型・判別共用体を入力として受け取り、その型のまま連続化・正規化した結果を返す。U03 の型に新しい識別子・別表現を増やさず、U03 の単一の真実源に従う。
  - U03 の具体的な型名・関数シグネチャが本ユニット着手時点で未確定の場合は、U03 が公開する「頂点座標を読み出す純粋関数」と「リングの頂点列を取得する純粋関数」を介してアクセスする想定で実装し、U03 の公開境界に合わせて結線する。型の二重定義を避け、座標表現の真実源は U03 に置く。

## 実装方針（技術方針に沿う）

- **配置層**: すべて `domain` 層の純粋関数として実装する。React・Electron・Canvas・空間インデックスライブラリ・ブーリアン演算ライブラリのいずれにも依存しない。`domain` は Electron／React／Canvas 抜きで単体テスト実行できる、という層分離規律を守る（技術方針 2.13）。依存方向は `domain` へ内向きに固定し、本モジュールは他層を import しない。
- **純粋性・イミュータブル**: 入力を破壊変更せず、新しい値を返す。同じ入力に対し常に同じ出力を返す副作用のない関数として実装する。これは NFR 5.8 のテスト容易性（時間計算と同様に、座標正規化を副作用なく境界網羅できる）を直接支える。
- **連続スカラー表現**: 経度は内部的に「正規化済みの代表区間値」と「連続化された展開済み値」の両方を取りうるが、関数の入出力でどちらの規約かを型または関数名で明示し、混同を構造的に防ぐ。`noUncheckedIndexedAccess` 前提で頂点配列アクセスの境界外参照をコンパイル時に排除する（技術方針 2.1）。
- **またぎ検出の基準**: 隣接頂点の経度差の絶対値が 180 度を超えたら「世界端をまたいだ」と判定し、最短方向（差の符号と逆向きに ±360 度）へオフセットを累積する。基準値（180 度・360 度・代表区間の境界）は定数として一箇所に定義し、正規化・逆正規化・複製・またぎ検出のすべてがその同一定数を共有する（単一の真実源、開発ガイド §4）。
- **量子化との整合**: 技術方針 R2 はブーリアン演算入力前に座標を固定スケールの整数格子へスナップ（量子化）する方針を採る。本ユニットの連続化・複製・逆正規化は、この量子化と整合するよう「±360 度オフセットは量子化スケール上でも誤差なく整数倍として表現できる値」を用い、往復で代表区間境界の頂点が量子化誤差で隣のセルへずれないことをテストで担保する。
- **単一の真実源としての公開**: 後続の幾何述語・ブーリアン演算・排他検証・空間インデックスが経度の周期性を扱うとき、必ず本モジュールの関数を経由する。各所で独自にまたぎ判定や ±360 度補正を書かない（判定ロジックの分散はドリフトを生む、開発ガイド §4「単一の真実源」、§5.30「過少共有の戒め」）。
- **テスト**: Vitest で代表的な入力（端をまたがない通常リング／+180 度をまたぐリング／−180 度をまたぐリング／複数周回／代表区間境界ちょうどの頂点）の単体テストを書く。さらに fast-check のプロパティテストで「任意のリング・任意の経度オフセットに対して連続化 → 逆正規化が元へ戻る」「正規化は常に代表区間に収まる」「またぎ検出後の隣接経度差は 180 度未満」などの不変式を生成入力で網羅する（技術方針 2.14、NFR 5.8）。ジェネレータは端跨ぎ・複数周回・境界ちょうどを意図的に多く生成するよう設計する（後続のプロパティテストで再利用できる共通ジェネレータとして整える、技術方針 R7）。

## 受け入れ基準（テスト可能な形で列挙）

各基準は、対応するテスト（Vitest 単体テストまたは fast-check プロパティテスト）が緑になることをもって満たされたとみなす。

1. **経度の連続スカラー保持と ±360 度正規化**
   - 任意の実数経度（例: 540 度, −450 度, 180 度, −180 度, 0 度）を正規化すると、既定の代表区間 `[-180, +180)` に収まる。
   - 正規化結果は、入力に ±360 度の整数倍を加減した値と元の値が周期同値であることを満たす（正規化前後で「経度の周期同値類」が保存される）。
   - 代表区間の境界（+180 度は −180 度へ写る、−180 度はそのまま）の扱いが一貫しており、テストで境界値を明示的に検証している。
   - 緯度は正規化対象外であり、入力値がそのまま保持される。

2. **世界端をまたぐリングの連続化（ラップ展開）**
   - +180 度をまたぐリング、−180 度をまたぐリングのそれぞれについて、連続化後のリングの隣接頂点間の経度差が常に絶対値 180 度未満になる。
   - 端をまたがない通常リングは、連続化しても各頂点の経度が（量子化誤差の範囲で）変化しない（不要なオフセットを加えない）。
   - 連続化後のリングが「経度方向に分断されない単一の連続したパス」を成すことを、隣接差の不変式で検証している。

3. **往復一致（連続化 → 演算 → 逆正規化）**
   - 「連続化 → 恒等演算 → 逆正規化」の往復が、元の正規化済みリングと各頂点で一致する（プロパティテストで任意リングに対し成立）。
   - 任意の ±360 度オフセットを加えた複製に対しても、逆正規化すると元の代表区間表現へ戻る（複製と逆正規化の往復一致）。
   - 往復一致は代表区間境界ちょうどの頂点・複数周回リングでも成立する。

4. **fast-check による端跨ぎ・複数周回の境界テスト**
   - fast-check のジェネレータが、端をまたぐリング・複数周回するリング・代表区間境界ちょうどの頂点を含む入力を生成し、上記 1〜3 の不変式をプロパティとして検証している。
   - 複数周回（同一方向に 2 周以上）の入力でも、連続化が累積オフセットの単調性を保ち、逆正規化で破綻しない（無限ループ・NaN・Infinity を生まない）。

5. **後続ユニットの単一の真実源として使える**
   - 公開関数群が、後続の幾何述語・ブーリアン演算・排他検証・空間インデックスから「周期境界をまたぐ 2 面を同一連続座標系へ揃える前処理」「演算後に代表区間へ戻す後処理」として呼び出せるシグネチャ・型で定義されている。
   - ±360 度オフセット複製を用いて、周期境界をまたぐ 2 つのリング集合が「同一連続座標系で重なるべきものは重なる／重ならないべきものは重ならない」と判定できる最小の結線テスト（前処理 → 重なりの有無を素朴判定 → 後処理）が緑になる。
   - 周期性の扱いが本モジュールに集約され、テスト内でモジュール外の独自またぎ判定を必要としない（単一の真実源であることを、利用側テストがこのモジュールのみを呼ぶことで示す）。

## 関連要件（FR-id）

- **FR-07**（must）: 横方向の無限スクロールを実現し、地図の東端・西端をまたぐ領域を表示・編集できる。本ユニットは、東端・西端をまたぐ面を演算・検証できるようにする座標基盤を提供する。
- **FR-12**（should）: 表示経度を左右にシフトでき、シフト量はズームに依存し現在の中心経度を表示する。本ユニットの経度連続スカラー表現・±360 度正規化は、表示経度シフトで生じる任意オフセットの座標を一貫して扱う基盤となる。

（背景根拠: 技術方針 4. リスクと緩和策 R3。R3 は本ユニットの直接の出発点であり、FR-07／FR-12 に加え FR-14 測量線・FR-90 分割が世界端をまたぐ場合の正しさにも本ユニットの正規化が波及する。これらは後続ユニットの責務であり本ユニットでは実装しないが、本ユニットの公開境界はそれらから再利用される前提で設計する。）

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に以下の教訓を引用・適用宣言してから実装すること（開発ガイド §1.6 AI 作業開始ゲート）。

- **§4「単一の真実源」／§5.30 過少共有と過剰共有の両方を戒める**
  - 適用: またぎ判定・±360 度補正・代表区間境界・量子化スケールの基準値は、本モジュール内の一箇所の定数・一組の関数に集約する。後続の幾何述語・ブーリアン演算・排他検証・空間インデックスが各々に独自のまたぎ判定を書くと、わずかな基準差（180 度を含む／含まない、+180 度の写し先）でドリフトが生じ、「ある経路では重なると判定し別経路では重ならない」矛盾を生む。利用側テストは本モジュールのみを呼ぶこと（過少共有の戒め）。一方、緯度には経度の周期処理を流用しない（周期性を持たない概念へ周期正規化を被せない、過剰共有の戒め）。

- **§5.1 集合演算は複数片を返す前提で扱う**
  - 適用: ±360 度オフセット複製を生成すると、入力 1 リングから複数の複製リングが生じる。前処理・後処理で「先頭の片だけ採用」する片落としをしない。複製したすべての片を逆正規化対象に含め、複数片を返す前提で配列を扱う。検出: 複製が 2 片以上になる入力で全片が出力に現れることをテストする。

- **§5.18 空配列・空オブジェクトは真値である**
  - 適用: 頂点 0 個・1 個・2 個のリング（リングとして成立しない退化入力）や、オフセットが 0 の複製を、論理和による短絡デフォルト補完で握りつぶさない。空・退化入力は型・件数で明示判定し、未定義動作（NaN・空配列の暗黙スキップ）を避ける。

- **§5.17 イミュータブルなエンティティ/値オブジェクトの設計**
  - 適用: 連続化・正規化・複製・逆正規化はいずれも新インスタンスを返し、入力リング・入力頂点を破壊変更しない。等価性は座標値比較で定義し、往復一致テストはこの等価性で判定する。

- **§5.32 多層に波及する変更は最大 2 層に分割する／§5.33 層をまたぐ API 契約は両側テストで固定する**
  - 適用: 本ユニットの公開境界は後続の複数ユニット（幾何述語・ブーリアン演算・排他検証・空間インデックス）から消費される層またぎ契約である。関数名・型・入出力規約（「正規化済み代表区間値」か「展開済み連続値」か）を型で明示し、利用側が増えるたびに契約がドリフトしないよう、本ユニットの公開関数の入出力を本ユニット側テストで固定する。本ユニットでは座標正規化のみに責務を閉じ、演算本体・検証本体へ越境しない。

- **量子化誤差の落とし穴（技術方針 R2 と整合）**
  - 代表区間境界ちょうどの頂点（±180 度）は、正規化 → 量子化 → 逆正規化の往復で隣のセルへずれやすい。±360 度オフセットは量子化スケール上でも誤差なく整数倍で表せる値を用い、境界頂点の往復が量子化セルをまたがないことを明示的にテストする。`Number` の浮動小数演算で 360 度の加減を繰り返すと誤差が累積するため、複数周回入力では「正規化された値に対して整数オフセットを一度だけ適用する」形に正規化し、加減の反復を避ける。

- **病的入力での安全性（NaN・Infinity・無限ループの禁止）**
  - 複数周回・極端なオフセット（例: 経度 10^6 度）でも、正規化が有限回の整数除算で完了し、無限ループや NaN／Infinity を生まないことをプロパティテストで保証する（fast-check で極端値を生成する）。

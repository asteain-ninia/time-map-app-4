# U08 ツリー階層モデルと不変条件検証(森構造・派生深度・形状=和)

## 目的

面情報の親子関係を「複数ルートを持つ森構造」として表現し、その上に成り立つドメインの階層不変条件を機械的に検証できる純粋ロジックを提供する。本ユニットは描画・UI・操作フローを持たず、`domain` 層に閉じた副作用のない関数群として、以下を保証することを目的とする。

- 階層深度を親子関係から派生算出し、地物自身には保持しない（単一の真実源を親子関係に置く）。
- 「最上位フラグが真」と「上位領域を持たない」の同値を検証し、不一致データを拒否する。
- 集約地物の形状が全直接下位領域の和に厳密一致し、内部に隙間を作らないことを検証する（U06 のブーリアン演算を使用）。
- 壊れたデータ（循環参照・親子不整合）でも無限ループせず有限結果を返す。

これらの検証は、編集コマンドの確定前検証・保存データ読込時の整合性チェック（FR-106）・プロパティテスト（NFR 5.8）の共通基盤として後続ユニットから再利用される。

## スコープ

### やること

1. **森構造モデルの確立**
   - 面情報の集合を、各面情報が高々 1 つの上位領域を持つ親子関係グラフ（森: 複数ルートを許す根付き木の集まり）として解釈する読み取りユーティリティを提供する。
   - 親から子（直接下位領域）への参照、子から親（上位領域）への参照の双方を、与えられた面情報集合から一貫して導出する。
   - 各面情報が「末端地物（形状を保持し下位領域を持たない）」か「集約地物（下位領域を持ち形状属性を保持しない）」かを、下位領域の有無という結果状態から判定する（呼び出し経路でゲートしない。教訓 5.6）。

2. **階層深度の派生算出（FR-38）**
   - 任意の面情報について、最上位（ルート）を 0、子を親 +1 とする階層深度を親子関係から算出する純粋関数を提供する。
   - 階層深度は地物自身のフィールドとして保持・受理せず、常に親子関係から再計算する。
   - 階層深度の最大値はツリーごとに異なってよい（森全体で単一の最大深度を仮定しない）。

3. **最上位フラグと親なしの同値検証（FR-39 / FR-34）**
   - 各面情報について「最上位フラグが真」⇔「上位領域を持たない」が成り立つことを検証する。
   - 「最上位フラグが真かつ上位領域を持つ」「最上位フラグが偽かつ上位領域を持たない」のいずれの不一致も違反として検出し、テスト可能な戻り値で報告する。

4. **集約地物の形状=直接下位領域の和の検証(FR-35 / FR-39)**
   - 集約地物の形状（実行時に下位領域の和集合として算出される）が、その全直接下位領域の形状の和に厳密一致し、内部に隙間（被覆されない領域）を作らないことを検証する。
   - 和集合の算出には U06 が提供するブーリアン演算（面の和・差）を使用する。本ユニットでブーリアン演算を自前実装しない。
   - 「集約地物形状 − 下位領域の和」と「下位領域の和 − 集約地物形状」の双方を評価し、許容トレランス内で差分が空であることを検証する（隙間なし・はみ出しなしの双方向確認）。

5. **循環参照に耐える再帰サービス（教訓 5.28）**
   - 親子グラフを辿るすべての再帰処理（深度算出・ルート探索・下位領域列挙・縦方向領域算出など）を、`visited` セットで再入を遮断し、循環参照・親子不整合データでも無限ループせず有限結果を返すよう実装する。
   - 循環を検出した場合は、無限ループせずに「循環参照あり」を検証違反として報告する（深度算出等は循環に巻き込まれたノードを安全な既定で扱い結果を返す）。

6. **検証結果の構造化**
   - 各検証は、ユーザー通知に使える違反内容と、テストで厳密比較できる戻り値の両方を満たす形（違反の有無・違反種別・関与した面情報の識別子の列挙）で結果を返す（教訓 5.26）。

### やらないこと

- 面情報の作成・編集・削除・所属変更・分割・結合などのツリー位相変更操作（U08 は検証と派生算出のみを担い、位相を変えない）。
- 集約地物の遷移（末端→集約）や直轄領の自動生成（FR-36 / FR-37）。本ユニットはそれらの結果状態を検証する側であり、生成は行わない。
- 末端地物同士の空間的排他検証（FR-26〜29）。本ユニットの形状検証は「集約地物=直接下位領域の和」に限定し、末端地物のペア排他は別ユニットの責務とする。
- 時間軸・歴史の錨に関する処理（錨列の昇順・非重複検証など）。本ユニットは「ある一時点で有効な状態スナップショット」を入力前提とし、時間モデルそのものは扱わない。
- 描画・ヒットテスト・ラベル配置・表示フォーカス（FR-42 / FR-43）などの表示制御。
- 種別ラベルに基づく検証（FR-40）。種別ラベルは表示専用であり、本ユニットの整合性検証・階層整合性検証に一切関与させない。
- ブーリアン演算そのものの実装（U06 に委譲）。

## 依存(dependsOn)

- **U06（幾何ブーリアン演算）**: 集約地物形状＝直接下位領域の和の検証で、面の和集合算出および差分算出に使用する。U06 が提供する「複数リング・穴・飛び地を扱える面のブーリアン演算（和・差・交差）」と、その結果が複数片を返しうる前提（教訓 5.1）に依拠する。U06 のトレランス／座標量子化方針（技術方針 R2）に整合させ、和集合差分の空判定はそのトレランス基準で行う。
- **U03**: 面情報・リング・頂点を含むドメインの基礎型（判別共用体による点／線／末端／集約、領土リング／穴リングの区別）と、面情報の親子参照・最上位フラグ・形状の表現。本ユニットはこれらの型を入力として受け取り、新たなドメイン型を増設しない（必要な場合も U03 の型定義を拡張する形で行い、本ユニット独自の重複型を作らない）。

> dependsOn に挙がっていない要件（時間モデル・排他検証・描画）には依存しない。入力は「検証対象時点で確定済みの面情報集合とその親子関係・最上位フラグ・形状」というプレーンなデータとして受け取る。

## 実装方針(技術方針に沿う)

- **配置層**: すべて `domain` 層の副作用のない純粋関数として実装する。Electron／React／Canvas に一切依存せず、Vitest 単体で実行できる状態を保つ（技術方針 2.13）。入力を受け取り検証結果・派生値を返すのみで、外部状態を変異させない。
- **不正状態の型排除**: 「集約地物は形状属性を保持しない」「最上位フラグと親なしの同値」を、可能な限り U03 の判別共用体で型表現し、不正状態を表現不能にする（技術方針 2.1 / 4.43）。型で表現しきれない実行時不変条件（循環なし・形状=和）は本ユニットの検証関数が担う。
- **単一の真実源**: 階層深度・末端/集約の区別・ルート判定は、親子関係という単一の真実源から派生算出する。同じ判定（例: 末端か集約か）を複数箇所で別実装しない（教訓 5.6 / 開発ガイド §4 単一の真実源）。派生形状の解決判定は共通関数へ集約し、規約自体を単体テストで固定する（教訓 5.29）。
- **結果状態での判定**: 末端／集約の判別は「下位領域を持つか」という変異後の結果状態で行い、特定の生成経路や呼び出しフラグでゲートしない（教訓 5.6）。
- **循環遮断**: 親子グラフを辿る再帰は共通の走査ヘルパーに集約し、`visited` セットで再入を遮断する（教訓 5.28）。深度算出・下位領域列挙・縦方向領域算出・ルート探索のすべてが同一の安全な走査基盤を経由する。
- **ブーリアン委譲とトレランス**: 和集合・差分は U06 へ委譲し、演算前後で不変条件を再検証する防御層を持つ（技術方針 R2）。差分が空かの判定はトレランス（座標量子化に整合した閾値）で行い、浮動小数の微小スリバーを違反と誤検出しない。
- **検証 API の二面性**: 各検証関数は「違反の有無を表す真偽」だけでなく、違反種別・関与識別子を含む構造化結果を返し、ユーザー通知（日本語メッセージ生成は呼び出し側）とテストの双方で使える戻り値とする（教訓 5.26）。本ユニット自体は UI 文言を生成しない（文言集約は別途、技術方針 5.5 / FR-115）。
- **プロパティテスト基盤への接続**: 検証ロジックは fast-check のプロパティテストから「任意の森に対し不変条件が保たれる」ことを反証する対象として設計する。森・ツリー・親子関係のジェネレータは不変条件から導出する共通モジュールとして構築し再利用する（技術方針 R7）。

## 受け入れ基準(テスト可能な形で列挙)

各基準は Vitest 単体テストまたは fast-check プロパティテストで検証できる形で満たすこと。

1. **階層深度の派生算出（FR-38）**
   - 最上位（上位領域を持たない面情報）の階層深度が 0 を返す。
   - 子の階層深度が常に「親の階層深度 + 1」に等しい（多段ネストで成り立つ）。
   - 入力の面情報が階層深度フィールドを保持していても、それを参照せず親子関係から再計算した値を返す（地物に保持された値と親子から算出した値が食い違うデータを与えても、算出値が返ることをテストする）。
   - 深度の異なる複数ツリーを含む森で、ツリーごとに最大深度が異なってよいことを確認する。

2. **最上位フラグと親なしの同値検証（FR-39 / FR-34）**
   - 「最上位フラグ真 ∧ 親なし」「最上位フラグ偽 ∧ 親あり」の整合データは違反なしを返す。
   - 「最上位フラグ真 ∧ 親あり」を違反として検出し、関与面情報を結果に含める。
   - 「最上位フラグ偽 ∧ 親なし」を違反として検出し、関与面情報を結果に含める。
   - 複数ルートを持つ森（複数の最上位面情報が併存）で、各ルートが正しく最上位として受理される。

3. **集約地物形状＝直接下位領域の和に厳密一致（FR-35 / FR-39・隙間なし）**
   - 集約地物の形状が全直接下位領域の和に一致するデータは違反なしを返す。
   - 集約地物の形状に下位領域の和で覆われない隙間がある場合を違反として検出する。
   - 集約地物の形状が下位領域の和をはみ出す場合を違反として検出する。
   - 下位領域が地理的に分離（飛び地的）していても、和が複数片になる場合に全片を考慮して一致判定する（片落としがないこと。教訓 5.1）。
   - 全下位領域を失った集約地物（下位領域 0 個）が、本ユニットの形状検証で「集約地物として不正」または「末端扱い」のいずれか定義した規約どおりに扱われることをテストで固定する（FR-35 の自動消滅は別ユニットが担うが、本ユニットは 0 個状態の検証結果を一意に定義する）。

4. **循環参照でも無限ループせず有限結果（教訓 5.28）**
   - 自己参照（自分が自分の親）を含むデータで、深度算出・下位領域列挙が無限ループせず有限時間で結果を返す。
   - 2 ノード以上の循環（A→B→A など）を含むデータで、循環を検証違反として報告し、かつ無限ループしない。
   - 循環を含む森でも、循環に巻き込まれていない健全なツリー部分の検証・深度算出は正しく動作する（部分的健全性）。
   - 上記の循環ケースを明示的なテストケースとして置く（教訓 5.28 の「検出」要件）。

5. **fast-check による森の不変条件保持**
   - 不変条件から導出した森ジェネレータが生成する任意の整合森に対し、最上位フラグ⇔親なしの同値・階層深度の親子整合・集約地物形状＝下位領域の和が常に違反なしと判定される。
   - 不変条件を意図的に破った森（同値違反・隙間・循環）を生成すると、対応する検証が必ず違反を検出する（検証の偽陰性がないことを反証で確認する）。

6. **回帰・非機能**
   - 全検証関数が副作用を持たず、同一入力に対し同一結果を返す（純粋性）。入力データを破壊的に変更しない。
   - 種別ラベルを変えても検証結果が変化しない（種別ラベル非関与・FR-40）ことをテストで固定する。
   - 5,000 オブジェクト規模の森でも検証が現実的時間で完了する（O(n²) の全ペア比較に退化しない走査であることを、形状検証以外の親子走査について確認する）。

## 関連要件(FR-id)

- **FR-34**: 面情報を複数ルートの森構造で階層管理し、階層・重ね順は地物自身の親子関係（および派生値である階層深度）から導出する。地物とは独立した順序属性や全体共通の重ね順序は持たない。各ルートは最上位フラグ真かつ上位領域なし。
- **FR-35**: 集約地物は形状属性を保持せず、形状は下位領域の和集合として実行時算出。全下位領域を失うと自動消滅（本ユニットは 0 個状態の検証結果定義を担当、消滅処理自体は別ユニット）。
- **FR-38**: 各面情報の階層深度は派生値（最上位 0・子は親 +1）であり、地物自身に保持せず常に親子関係から算出。最大深度はツリーごとに異なってよい。
- **FR-39**: 最上位フラグ真と上位領域なしは同値で不一致を許可しない。集約地物形状はその全直接下位領域の和に厳密一致し内部に隙間を作らない。地図全体の無主地は許容。
- **FR-40**: 種別ラベルは表示専用で整合性検証・階層整合性に関与しない（検証非関与の確認対象）。

## 注意点・既知の落とし穴(開発ガイドの教訓を踏まえる)

- **教訓 5.28（循環で無限ループしない）** — 適用: 親子グラフを辿る全再帰関数を共通走査基盤に集約し `visited` セットで再入遮断する。循環参照テストケースを必ず置き、有限結果を返すことを確認する。シリアライズ層の検証とは別に、テスト経路で直接構築した循環データに対しても runtime 安全性を二重防御する。
- **教訓 5.6（結果状態で判定）** — 適用: 末端地物／集約地物の判別を「下位領域を持つか」という結果状態で行い、生成経路・呼び出しフラグでゲートしない。同じ状態を複数経路が生むため、特定経路ゲートは別経路で漏れる。
- **教訓 5.29（派生形状は単一の解決判定で全経路を動かす）** — 適用: 集約地物の派生形状（下位領域の和）の解決判定を単一の共通関数へ集約し、後続の描画・ヒットテスト・選択・ラベル配置がすべて同じ判定を使えるようにする。判定条件のドリフトは「描画されるのに選択できない」等の矛盾を生む。規約自体を単体テストで固定する。
- **教訓 5.1（集合演算は複数片を返す前提）** — 適用: 下位領域の和・差分が複数ポリゴン・複数リングを返す前提で扱い、片落とし（先頭片だけ採用）を避ける。和が複数片になる飛び地ケースで全片が一致判定に反映されることをテストする。
- **教訓 5.25（仕様が限定した対象範囲を実装で広げない）** — 適用: 排他制約は末端地物同士のみ（FR-26 / FR-27）、形状=和の検証は集約地物のみ（FR-35）と仕様が対象を限定している。「対称性確保」を理由に集約地物へ排他制約を課したり、末端地物へ形状=和検証を課したりしない。種別ラベルを検証に巻き込まない（FR-40）。
- **教訓 5.26（確定前に同じサービスで検証）** — 適用: 本ユニットの検証関数を、UI 候補表示だけでなくコマンド／ユースケースの確定前検証・保存読込時検証（FR-106）からも同一サービスとして呼べる形にする。拒否理由はユーザー通知とテスト可能な戻り値の両方で扱える構造化結果とする。
- **教訓 5.30（過少共有と過剰共有の両方を戒める）** — 適用: 深度算出・ルート判定・末端集約判別は単一実装を共有する（過少共有の戒め）。一方で、本ユニットの整合性検証を、制約規則の異なる他操作（排他検証・所属変更候補絞り込み）と安易に共有しない（過剰共有の戒め）。共有前に制約が本当に同一かを列挙確認する。
- **トレランスと数値誤差（技術方針 R2）** — 注意: 形状=和の差分空判定を厳密等価ではなくトレランス内で行い、polygon-clipping 由来の微小スリバー・ゼロ長エッジを違反と誤検出しない。U06 と同一の座標量子化／トレランス基準を用い、基準値を本ユニットで重複定義しない（単一の真実源）。
- **無主地の許容（FR-39）** — 注意: 「集約地物内部に隙間を作らない」は集約地物配下の被覆についての制約であり、地図全体としてどの末端地物にも覆われない無主地は許容される。森全体の被覆完全性を検証対象にしない（過剰検証の防止）。
- **0 個下位領域の扱い** — 注意: 集約地物が全下位領域を失った状態（FR-35 の自動消滅対象）について、本ユニットの形状検証がどう判定するかを一意に定義しテストで固定する。消滅処理は別ユニットの責務だが、検証結果の曖昧さは残さない（教訓 5.10 選択・状態の生集合まで評価して網羅する考え方を、0 個・1 個・複数個の各下位領域件数へ適用する）。
- **派生値を入力に持ち込まない** — 注意: 階層深度は派生値であり、入力データが誤った深度フィールドを持っていても無視して再計算する。誤った保持値を信頼すると FR-38 の「地物に保持しない」原則が崩れる。

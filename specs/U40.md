# U40 パン操作・モード別マウス操作の統合

本書は実装ユニット U40 の実装指示書である。実装者（別エージェント）はこの指示書だけを読んで着手できるよう、前提知識を本書の中に閉じて記述する。要件・技術方針・開発作法の根拠は本文および末尾「関連要件」「注意点・既知の落とし穴」に引用する。

本書はクリーンルーム文書である。過去版・他プロダクト・特定の既存実装には一切言及せず、必要な制約はすべて time-map-app-4（以下「本アプリ」）自身の要件・技術方針として直接記述する（開発ガイド 3.1）。

## 目的

本アプリのメインマップ上で発生するマウス操作（左／中ボタンのドラッグによるパン、マウスホイールによるズーム）を、追加／編集／表示の各モードの文脈に応じて正しく振り分け、パンと選択・編集ドラッグが互いに衝突しない単一の入力ディスパッチ層を確立する。具体的には次を満たす。

1. **表示モードでは左ボタンまたは中ボタンのドラッグでパンする。追加モード・編集モードでは中ボタンドラッグでパンする**（FR-09）。
2. **全モードでマウスホイールによりカーソル位置中心のズームを行う**。ズームは U17 が提供するカーソル位置中心ホイールズームのカメラ算出に統合し、本ユニットでズーム計算を再実装しない（FR-09 / FR-08）。
3. **モード別マウス操作の優先順位と排他選択を明確化する**。あるボタン押下がパン・選択・編集ドラッグ・追加・コンテキストメニュー等のどの処理に向かうかを一意に決定し、排他分岐が重要な処理（選択・編集の開始や、押下状態の解除）をスキップしないようにする（開発ガイド 教訓 5.9）。
4. **押下→移動→解放のシーケンスを全パス（クリック／ドラッグ）で保証する**。押下で設定した一時状態（パン中フラグ・基準座標等）は解放で必ず解除し、移動が発生しなかったクリックの考慮漏れを防ぐ（開発ガイド 教訓 5.8）。

本ユニットは「マウスイベントをモード文脈で正しい振り分け先へ届けるディスパッチ規律」と「パン操作そのものの開始・更新・終了」に集中する。カメラのワールド↔スクリーン変換・ホイールズームのカメラ算出は U17、入力レイヤの配置と重なる UI の入力層設計・モード状態の保持は U20、選択・頂点ドラッグ・矩形選択・地物本体ヒットは U22 がそれぞれ担い、本ユニットはそれらを利用する側に立つ。

## スコープ

### やること

- **メインマップ上のポインタ入力ディスパッチ規律の確立**
  - メインマップ領域（U20 が用意する中央マップ入力レイヤ）で発生する押下（pointerdown）・移動（pointermove）・解放（pointerup / pointercancel）・ホイール（wheel）・コンテキストメニュー要求（contextmenu）を受け取り、現在のモード（追加／編集／表示）と押下ボタン種別（左／中／右）に応じて、行き先（パン開始／選択・編集の開始／追加の点配置／コンテキストメニュー／無視）を**一意に決定する**ディスパッチ規律を実装する。
  - 行き先の決定は「現在モード × ボタン種別 × ヒット対象（後述）」の組み合わせから単一の決定関数で導出し、表示文字列・思い込みで分岐しない（教訓 5.19）。
- **モード別パンのボタン割当（FR-09）**
  - **表示モード**: 左ボタンドラッグまたは中ボタンドラッグでパンする。
  - **追加モード**: 中ボタンドラッグでパンする（左ボタンは点配置などモード固有操作に充て、本ユニットはパンに横取りしない）。
  - **編集モード**: 中ボタンドラッグでパンする（左ボタンは選択・頂点ドラッグ・矩形選択などに充て、本ユニットはパンに横取りしない）。
  - 上記割当を「モード→パンを起動するボタン集合」の単一テーブルとして定義し、各経路がこのテーブルを参照する（単一の真実源）。
- **パン操作の開始→更新→終了（押下→移動→解放）**
  - **開始（押下）**: パン起動条件を満たすボタンが押下されたら、パン中状態に入り、基準となる押下時スクリーン座標と押下時カメラ中心（中心経度・中心緯度）を記録する。
  - **更新（移動）**: パン中に移動が起きたら、押下基準からのスクリーン移動量をワールド移動量へ換算し、カメラの中心経度・中心緯度を更新する（中心経度は連続スカラーのまま更新し、世界端をまたいでも破綻しない）。スクリーン→ワールドの換算には U17 の変換（VTransform）を用い、本ユニットで座標変換式を再実装しない。
  - **終了（解放）**: 解放・キャンセルでパン中状態を必ず解除し、記録した基準座標・基準カメラ等の一時状態を破棄する。**移動が一度も発生しなかった場合（純粋なクリック）でも**、押下で設定したパン中状態・基準座標が確実に解除されることを保証する（教訓 5.8）。
- **ドラッグ閾値（クリックとドラッグの判別）**
  - 押下から解放までのスクリーン移動量が一定のドラッグ閾値（px）未満なら「クリック（移動なし）」、以上なら「ドラッグ」とみなす判別を一箇所に実装する。これにより、左ボタンクリック（移動なし）が表示モードでパンに化けて選択解除等の本来処理を取りこぼさない／編集モードで頂点クリックが微小移動で誤って同時移動扱いにならない、という両端の取りこぼしを防ぐ（教訓 5.8 / 5.9）。閾値はパン・選択・矩形選択で共通の判別基準を共有する（単一の真実源）。
- **全モードでのカーソル位置中心ホイールズーム（FR-09）**
  - 追加・編集・表示のいずれのモードでも、メインマップ上のホイール操作を受け取り、カーソルのスクリーン座標を中心に保つズームを行う。ズーム後のカメラ状態（中心経度・中心緯度・ズーム値）の算出は **U17 のカーソル位置中心ホイールズームのカメラ算出**へ委譲し、本ユニットはホイールイベント（カーソル位置・ズーム増減方向と量）を U17 の算出へ渡し、結果のカメラ状態を U16 のセッション状態へ書き戻す経路で結線する。ズーム範囲のクランプも U17／U16 側の責務に従う（本ユニットでズーム計算・クランプを再実装しない）。
- **パンと選択／編集ドラッグの非衝突**
  - 編集モードの左ボタンドラッグは選択・頂点ドラッグ・矩形選択（U22）へ向かい、パンへは向かわない。編集モード・追加モードのパンは中ボタンに限定することで、左ボタンの選択・編集・追加操作とパンが**同一押下で二重起動しない**ことを構造的に保証する。
  - 表示モードでは編集系操作が無効化される（U20 の表示専用一括無効化と整合）ため、左ボタンドラッグをパンに充てても選択・編集ドラッグと衝突しない。
  - ヒット対象（地物本体・頂点ハンドル・エッジハンドル・空き領域のいずれをクリックしたか）の判定は U22／U17 のヒットテストを利用し、本ユニットはその結果を受けて「このボタン・このモード・このヒット対象ならパンか、選択・編集委譲か」を一意に決める。本ユニットはヒットテスト幾何を再実装しない。
- **一時的パン状態の全経路破棄（教訓 5.2）**
  - パン中フラグ・押下基準座標・押下時カメラ等の一時状態を、解放・キャンセル（pointercancel）・モード切替・ウィンドウ／領域からのポインタ離脱（必要に応じて pointerleave 等）・ツール切替のすべての経路で明示的に破棄する。残留して次操作へ引き継がれないこと。
- **入力ディスパッチ／パン算出の純粋ロジック分離**
  - 「モード × ボタン × ヒット対象 → 行き先」の決定、ドラッグ閾値判定、押下基準からのカメラ中心更新量の算出を、フレームワーク非依存の純粋関数として切り出し、Vitest で単独実行できるようにする（NFR 5.8）。

### やらないこと

- ワールド↔スクリーン変換（VTransform）の実装、カーソル位置中心ホイールズームのカメラ算出、ズーム範囲のクランプ。これらは **U17** の責務であり、本ユニットは U17 の変換・ズーム算出を呼び出して利用するに留まる（座標変換式・ズーム計算を本ユニットで再実装しない＝単一の真実源）。
- カメラ状態（中心経度・中心緯度・ズーム）の保持そのもの。カメラ状態の真実源は **U16 のセッション状態**に置かれる想定であり、本ユニットはパン／ズームで算出した新カメラ状態を U16 のストアへ書き戻す経路を結線するに留まる（本ユニットでカメラ状態を二重定義しない、技術方針 2.3 / 2.5）。
- 中央マップ入力レイヤの DOM 配置・重なる UI（モーダル・ドラッグ可能パネル・オーバーレイ・コンテキストメニュー）の入力層構造の設計。これは **U20** の責務であり、本ユニットは U20 が用意した入力レイヤ上のイベントを受け取って振り分けるに留まる（重なる UI が前面にあるときに地図入力が奪われる／奪われない層構造は U20 が担う、教訓 5.14）。
- モード（追加／編集／表示）の保持・排他トグル・表示専用一括無効化。これは **U20** の責務であり、本ユニットは現在モードを U20 のモード状態から読み取って振り分けに用いる。
- アクティブ地物選択・頂点選択セット・矩形選択・複数頂点同時移動・選択コンテキスト解析・選択視覚フィードバック。これは **U22** の責務であり、本ユニットは左ボタンドラッグ（編集モード）等を U22 へ委譲するに留まる（選択・頂点ドラッグのロジックを本ユニットで持たない）。
- 地物本体・頂点ハンドル・エッジハンドルのヒットテスト幾何（点in多角形・最近傍頂点判定等）。本ユニットはヒット結果を受け取って振り分けに使うのみ（ヒットテスト本体は U17／U22 系の描画・選択層が提供）。
- 点／線／面の追加時の頂点配置・仮表示・確定（FR-76〜78）。本ユニットは追加モードで左ボタンクリックを追加系の操作へ委譲する経路のみを担い、追加の操作ロジックは別ユニットが担う。
- コンテキストメニュー（右クリックメニュー）の項目構成・動的内容生成（FR-96）。本ユニットは右ボタンによるコンテキストメニュー要求を U20 のコンテキストメニュー機構へ委譲する経路のみを担う。
- 表示経度シフトの UI（FR-12 のスライダー／ボタン・本初子午線中心／太平洋中心の切替）。本ユニットはマウスドラッグによるパンのみを担い、シフト操作 UI は別ユニットが担う。
- 整合性維持プロセス・競合解決・アンドゥ／リドゥ機構。パンはカメラ操作でありドメイン編集ではないため、パン自体は履歴・整合性プロセスの対象外とする（本ユニットはパンを履歴へ積まない）。

## 依存（dependsOn）

本ユニットは以下のユニットに依存する。これらが提供する変換・モード状態・選択ロジック・入力レイヤを前提として実装し、依存先が公開する仕組みを再実装せず購読・利用する（単一の真実源。開発ガイド §4「単一の真実源」、教訓 5.30 過少共有の戒め）。

- **U17（MapRenderer インタフェースと Canvas カメラのワールド↔スクリーン VTransform）**: 本ユニットはパンの座標換算に U17 の `screenToWorld`／`worldToScreen`（VTransform）を用い、ホイールズームに U17 の「カーソル位置中心ホイールズームのカメラ算出」を用いる。U17 はカメラ状態をプログラム的に更新する API を提供する（U17 のスコープ「やらないこと」に「パン操作の入力ハンドリングは別ユニットが担い、本ユニットはカメラ状態をプログラム的に更新する API を提供する」と明記されている）。本ユニットはその受け皿に対しパン・ズームで算出したカメラ状態を流し込む。座標変換・ズーム算出を本ユニットで再実装しない。
- **U20（アプリレイアウトシェルとモード/ツールバー骨格）**: 本ユニットは U20 が用意する中央マップ入力レイヤ上でポインタ／ホイールイベントを受け取り、U20 のモード状態（追加／編集／表示の排他モード、および表示専用＝編集不可の権限判定）を読み取って振り分けに用いる。重なる UI が前面にあるときの入力層構造（教訓 5.14）は U20 が設計済みである前提に立ち、本ユニットは「地図入力レイヤがイベントを受け取れる状態のときのみ」振り分ける。右クリックによるコンテキストメニュー要求は U20 のコンテキストメニュー機構へ委譲する。
- **U22（選択システム: アクティブ地物・頂点選択セット・選択コンテキスト・視覚FB）**: 編集モードの左ボタン操作（地物本体クリック・頂点クリック・Shift+クリック・空き領域からの矩形選択・頂点ドラッグによる同時移動）は U22 が駆動する。本ユニットは編集モードの左ボタン押下→移動→解放を U22 の選択／編集経路へ委譲し、押下→移動→解放のシーケンス整合（教訓 5.8）を本ユニットのパン経路と U22 の選択経路で二重に矛盾なく成立させる。ヒット対象（地物本体／頂点／ハンドル／空き領域）の判定結果は U22 を通じて利用する。

> 注: 依存先 U17 / U20 / U22 が公開する正確な API 名・型（カメラ更新関数・モード状態キー・ヒット結果型・選択イベント入口）は各ユニットの成果物に従う。本ユニットは「カメラ状態の更新 API とカーソル中心ズーム算出（U17）」「中央マップ入力レイヤとモード状態・表示専用権限判定（U20）」「ヒット結果と選択／編集委譲入口（U22）」という能力に依存する。依存先 API が未確定の段階では、本ユニット内に明示的な境界インタフェース（adapter）を定義し、そこへ依存先を接続する形で未確定部分を局所化する。層をまたぐ契約（チャネル名・関数名・状態キー・イベント種別）は偶然の一致に頼らず共有型・両側テストで固定する（教訓 5.33 / 5.34）。

## 実装方針（技術方針に沿う）

技術方針が定める採用スタックと層分離に厳密に従う。

### 配置と層分離

- 本ユニットの入力ディスパッチは、メインマップ上の高頻度ポインタ／ホイールイベントを扱う。**この経路を React の再レンダリングサイクルに乗せない**（技術方針 2.3）。パン中の連続更新（pointermove ごとのカメラ中心更新）は React state へ持たせず、U16 のセッション状態（カメラ）を更新し U17（`render`）が購読して命令的に再描画する経路に流す。
- 「モード × ボタン × ヒット対象 → 行き先」の決定、ドラッグ閾値判定、押下基準からのカメラ中心更新量算出は、Electron・React・Canvas に非依存の**純粋関数**として切り出し、`domain` 寄り（または `render`／`ui` から切り離せる純粋モジュール）に置いて Vitest で単独実行できるようにする（NFR 5.8、技術方針 2.14）。イベントの受け取り（DOM ハンドラ）と純粋な決定ロジックを分離し、ハンドラは「イベントを正規化して純粋関数へ渡し、結果を依存先 API へ流す」薄い接着層に留める。
- 入力レイヤの DOM 配置・層構造は U20 が、カメラ状態の保持は U16 が、座標変換・ズーム算出は U17 が、選択・編集は U22 が持つ。本ユニットはこれらの境界 API のみに依存し、いずれの真実源も二重に持たない。

### 高頻度イベントの扱い（NFR 5.1）

- pointermove・wheel は高頻度になりうるため、必要に応じてスロットリングまたはフレーム同期（requestAnimationFrame でのまとめ適用）を行い、60FPS（NFR 5.1）を防衛する。ただしパンの追従が体感で遅延しない粒度に留める。スロットリングしても押下→解放の状態整合（最終解放で必ず解除、最終位置を取りこぼさない）が崩れないようにする。
- ドラッグ中の連続更新で重いイミュータブルコピーを毎フレーム取らない。カメラ状態の更新は軽量なスカラー（中心経度・中心緯度・ズーム）の更新であり、ドメインの不変モデル全体のコピーを伴わない（技術方針 R5 の趣旨に整合）。

### モード別パンと優先順位（FR-09、教訓 5.9）

- 「現在モード」と「押下ボタン種別」と「ヒット対象」を入力に、行き先を返す単一の決定関数を実装する。決定規約は次を満たす（モード×ボタンのパン割当は単一テーブルから導出する）。
  - 中ボタンドラッグ: **全モードでパン**（追加・編集・表示すべて）。
  - 左ボタンドラッグ: **表示モードのみパン**。追加モードでは追加系操作（点配置等）へ、編集モードでは選択・頂点ドラッグ・矩形選択（U22）へ委譲し、パンへ向けない。
  - 右ボタン: 全モードでコンテキストメニュー要求（U20 へ委譲）。パンへ向けない。
- 排他分岐が重要処理をスキップしないこと（教訓 5.9）。例えば「中ボタンでパンを起動した」分岐が、左ボタン経路の選択・編集の開始や、解放時の一時状態解除をスキップさせない。各ボタン経路は独立に押下→移動→解放を完結させ、決定関数は「このボタンの行き先」を一意に返すが、他ボタン経路の責務を奪わない。複数ボタンの同時押下（パン中に別ボタン押下等）でも、各押下に対応する一時状態が取りこぼされない設計とする（pointerId 単位での追跡を基本とする）。

### 押下→移動→解放の全パス保証（教訓 5.8）

- パン経路は「押下で基準座標・基準カメラ・パン中フラグを設定」「移動でカメラ中心を更新」「解放／キャンセルでパン中フラグと基準を必ず解除」を一つのシーケンスとして実装する。
- **移動が一度も起きなかったクリック**（左ボタン表示モードでの単純クリック含む）でも、押下で設定した状態が解放で解除されることを保証する。ドラッグ閾値未満ならパンを「クリック扱い」として確定し（カメラは動かさない）、表示モードのクリックが選択解除等の本来処理（該当する場合）を取りこぼさないようにする。
- pointercancel・ポインタの領域外離脱・モード切替の最中にパン中だった場合も、一時状態を破棄して安全な状態へ戻す（教訓 5.2 と連動）。

### パンと選択／編集の非衝突（FR-09）

- 編集モード・追加モードでパンを中ボタンに限定することで、左ボタンの選択・編集・追加操作と同一押下でパンが二重起動しない。表示モードでは編集系が無効化されているため左ボタンパンが選択・編集と衝突しない（U20 の表示専用一括無効化と整合）。
- 同一の pointerdown が「パン」と「選択・編集委譲」の両方へ同時に流れないよう、決定関数は単一の行き先を返し、行き先が確定したらそのシーケンス（パン or 委譲）に専念する。

### カーソル位置中心ホイールズーム（FR-09 / FR-08）

- wheel イベントから「カーソルのスクリーン座標」「ズーム増減方向と量」を取り出し、U17 のカーソル位置中心ホイールズームのカメラ算出へ渡す。算出された新カメラ状態（カーソル位置のワールド座標が前後で同一スクリーン座標に留まる、ズームはクランプ済み）を U16 へ書き戻す。
- 本ユニットでズーム前後のワールド座標保存・中心補正・クランプを再実装しない（U17 を単一の真実源とする）。全モードで同一のホイールズーム経路を共有する（過少共有の戒め）。

### 文言とエラー処理

- 本ユニットはマウス操作のディスパッチであり恒久 UI 文言は少ないが、もし表示文言（操作ガイド等）を持つ場合は日本語のみとし、定数モジュールへ集約する（FR-115、技術方針 5.5）。例外はユーザーフレンドリーな日本語メッセージで扱う（FR-117）。

### テスト

- 入力ディスパッチ決定関数（モード × ボタン × ヒット対象 → 行き先）を、全モード × 全ボタン × 代表的ヒット対象の組み合わせで網羅する単体テストを Vitest で書く（教訓 5.9 / 5.34、条件分岐は排他ではなく組み合わせで網羅）。
- 押下→移動→解放のシーケンスを、ドラッグ（移動あり）とクリック（移動なし）の両パスで、パン中状態が正しく開始・更新・終了する／解放で必ず解除されることを検証する（教訓 5.8）。pointercancel・モード切替中のパン放棄も検証する（教訓 5.2）。
- パン算出（押下基準からのスクリーン移動量 → カメラ中心更新量）の純粋関数を「入力 → 期待カメラ中心」で固定し、世界端をまたぐパン（中心経度の連続スカラー更新）で破綻しないことをテストする。
- カーソル位置中心ホイールズームは U17 の算出を呼ぶ結線テストとし、本ユニットがカーソル位置・ズーム量を正しく渡し結果を U16 へ書き戻すことを両側テストで固定する（教訓 5.33）。U17 のズーム不変式（カーソル位置のワールド座標が前後で同一スクリーン座標に留まる）自体は U17 のテストで担保される前提に立つ。
- パンと選択／編集ドラッグの非衝突（同一 pointerdown が両方へ流れない、編集モード左ドラッグがパンを起動しない、表示モード左ドラッグが選択を起動しない）を回帰テストで固定する。
- 純粋ロジックから切り離せない DOM 連携部分は、アダプタ分離・モックで単体テスト対象にして補い、未検証のまま放置しない（教訓 5.41）。

## 受け入れ基準（テスト可能な形で列挙）

各基準は、対応するテスト（純粋関数の Vitest 単体／組み合わせ網羅、押下→移動→解放のシーケンステスト、依存先との結線両側テスト、必要に応じて E2E）が緑になることをもって満たされたとみなす。

1. **表示モードで左／中ドラッグパン、追加／編集モードで中ドラッグパン（FR-09）**: 表示モードでは左ボタンドラッグでも中ボタンドラッグでもパンし、カメラの中心経度・中心緯度が押下基準からの移動量に応じて更新されることを確認できる。追加モード・編集モードでは中ボタンドラッグでパンし、左ボタンドラッグはパンを起動しない（追加系操作／選択・編集へ委譲される）ことを確認できる。モード×ボタンのパン割当が単一テーブルから導出されている。
2. **全モードでホイールがカーソル位置中心ズーム（FR-09）**: 追加・編集・表示のいずれのモードでも、メインマップ上のホイール操作でカーソル位置中心のズームが行われることを確認できる。ズーム前後で、カーソルのスクリーン座標が指すワールド座標が同一スクリーン座標に留まる（不変式は U17 の算出に委譲し、本ユニットはカーソル位置・ズーム量を正しく渡し結果を U16 へ書き戻す結線が緑になる）。本ユニット内にズーム計算・クランプの再実装が存在しない。
3. **モード別マウス操作の優先順位／排他が明確で重要処理をスキップしない（教訓 5.9）**: 「現在モード × 押下ボタン × ヒット対象」から行き先（パン／選択・編集委譲／追加委譲／コンテキストメニュー委譲／無視）が一意に決まり、全モード × 全ボタン × 代表的ヒット対象の組み合わせを網羅したテストで、各組み合わせが期待どおりの単一行き先へ向かうことを確認できる。中ボタンのパン分岐が左ボタンの選択・編集・追加の開始や、解放時の一時状態解除をスキップさせないことを確認できる。
4. **押下→移動→解放が全パス（クリック／ドラッグ）で正しく開始／更新／終了（教訓 5.8）**: パン経路で、押下でパン中状態・基準座標が設定され、移動でカメラ中心が更新され、解放で必ず解除されること、および**移動が一度も発生しなかったクリック**でも押下で設定した状態が解放で確実に解除されることを確認できる。ドラッグ閾値未満の操作はクリック扱い（カメラ非更新）として確定し、閾値以上はドラッグ（パン）として確定する。pointercancel・モード切替中のパン放棄でも一時状態が破棄される。
5. **パンと選択／編集ドラッグが衝突しない**: 編集モードの左ボタンドラッグが選択・頂点ドラッグ・矩形選択（U22）へ向かいパンを起動しない、追加モードの左ボタンが追加系へ向かいパンを起動しない、表示モードの左ボタンドラッグがパンへ向かい選択・編集を起動しない（表示専用で編集系が無効）ことを確認できる。同一 pointerdown が「パン」と「選択・編集委譲」の両方へ同時に流れないことをテストで確認できる。
6. **一時的パン状態の全経路破棄（教訓 5.2）**: パン中フラグ・押下基準座標・押下時カメラ等の一時状態が、解放・pointercancel・モード切替・領域離脱・ツール切替のすべての経路で破棄され、次操作へ引き継がれないことを「パン開始→キャンセル→再操作」「パン開始→解放→再操作」の連続テストで確認できる。
7. **純粋性・層分離（技術方針 2.3 / 2.5、NFR 5.8）**: 入力ディスパッチ決定・ドラッグ閾値判定・パン算出が副作用のない純粋関数として切り出され Vitest で単独実行できる。カメラ状態の真実源が U16 にあり本ユニットで二重定義していない。座標変換・ズーム算出が U17 に委譲され本ユニットで再実装していない。パン中の連続更新が React 再レンダリング経路に乗らず、U16 更新→U17 購読の経路で命令的に再描画される。
8. **依存契約の固定（教訓 5.33 / 5.34）**: U17（カメラ更新・カーソル中心ズーム算出）・U20（中央マップ入力レイヤ・モード状態・表示専用権限判定・コンテキストメニュー機構）・U22（ヒット結果・選択／編集委譲入口）との契約が共有型・両側テストで固定され、依存先 API が未確定の場合でも境界インタフェース（adapter）越しに着手でき、依存先確定後に接続できる。

## 関連要件（FR-id）

- **FR-09**（should）: 表示モードでは左ボタンまたは中ボタンのドラッグでパン、追加・編集モードでは中ボタンドラッグでパンを行う。全モードでマウスホイールによりカーソル位置中心のズームを行う。— 本ユニットの中核要件。モード別パン割当・全モードホイールズーム統合・操作の非衝突を実装する。

補助的に関与する要件（本ユニットは「ディスパッチ・委譲・結線」を担い、実処理は依存・後続ユニット）:

- **FR-08**（must）: ズームイン・ズームアウト・パン操作をサポートし、世界地図全体から都市内地図レベルまでの広範囲かつスムーズなズームを実現する。— パン操作の入力ハンドリングを本ユニットが、連続ズームとホイールズームのカメラ算出を U17 が担う。
- **FR-06**（must）: ベースマップはマウスイベントもテキスト選択も受け付けず、地物操作やパン操作を阻害しない。— 本ユニットのパン入力がベースマップに阻害されないこと（入力レイヤ層構造は U20）と整合させる。
- **FR-12**（should）: ユーザーが表示経度を左右にシフトできシフト量はズームレベルに依存する。— 本ユニットはマウスドラッグによるパンのみを担い、シフト UI は別ユニット。中心経度の連続スカラー更新は U17 の受け皿と整合させる。
- **FR-75**（must）: 追加モードと編集モードを排他モードとして提供する。— 本ユニットはモード状態（U20）を読み取って振り分けるが、モードの保持・トグルは U20。
- **FR-42**（should）: 表示モードの切替は編集・追加モードと干渉しない。— モード別パン割当が表示／編集／追加の各文脈で干渉なく成立することと整合。
- **FR-96**（should）: コンテキストメニュー。— 本ユニットは右ボタン要求を U20 のコンテキストメニュー機構へ委譲する。

関連する非機能要件: NFR 5.1（ズーム／パンの 60FPS、選択・編集応答 100ms、pointermove・wheel の高頻度イベントスロットリング、地図入力経路と React 再描画の分離）、NFR 5.8（入力ディスパッチ・閾値判定・パン算出の純粋関数化と入力→期待状態の再現テスト）。関連する横断根拠: 技術方針 2.3（React 再レンダリングと地図描画の分離）、2.4（Canvas 2D 描画層・VTransform）、R3（無限横スクロール・連続スカラー経度・世界端ラップ）、R5（ドラッグ中の連続更新で重いコピーを取らない）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

### 適用宣言（AI 作業開始ゲート, 開発ガイド 1.6）

着手前に、以下の教訓を節番号・見出し・本文ごと直接引用し、今回の実装判断へどう適用するかを「適用:」として 1 文以上で明示してから着手すること。引用と適用宣言を省略して着手してはならない（開発ガイド 1.6）。

- **教訓 5.9「排他分岐が重要処理をスキップしていないか確認する」**（引用: 「排他的な条件分岐が、他の重要な処理をスキップさせていないか確認する。選択優先順位と、同時選択/排他選択を明確に定義する。」）。**適用**: 本ユニットでは「モード × ボタン × ヒット対象 → 行き先」を単一の決定関数で一意に定め、中ボタンパンの分岐が左ボタンの選択・編集・追加の開始や解放時の一時状態解除をスキップさせないことを、全組み合わせ網羅テスト（受け入れ基準 3）で保証する。
- **教訓 5.8「押下→移動→解放シーケンスを全パスで保証する」**（引用: 「押下 → 移動 → 解放のシーケンスは、全パス（クリック・ドラッグ）で状態が正しく開始・更新・終了することを保証する。押下で設定した状態は解放で必ず解除し、移動が発生しなかった場合（クリック）の考慮漏れに注意する。」）。**適用**: パン経路で押下時に設定した基準座標・パン中フラグを、解放・pointercancel・モード切替の全経路で必ず解除し、移動が一度も起きなかったクリックでも取りこぼさないことを受け入れ基準 4 で検証する。

その他、本ユニットで特に該当する教訓と落とし穴:

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」**: パン中フラグ・押下基準座標・押下時カメラ等の一時状態を、解放・キャンセル・モード切替・領域離脱・ツール切替のすべての経路で明示破棄する。残ると次操作へ暗黙に引き継がれる（受け入れ基準 6）。
- **教訓 5.5「依存する状態は変化時に再検証する」**: モードが切り替わったらパン中状態の妥当性を再検証し、編集／追加モードへ移った瞬間にパン中だった場合の扱い（中ボタンパンは全モード共通のため継続可だが、状態整合は保つ）を明示する。モード依存の行き先判定はモード変化時に再評価する。
- **教訓 5.19「分岐識別子は型定義・定数・ファクトリを経由する」**: モード名・ボタン種別（左／中／右）・行き先種別（パン／選択委譲／追加委譲／コンテキストメニュー／無視）は表示文字列や思い込みで判定せず、型定義・定数を経由する。新識別子の追加・改名時は決定・委譲・テストの全経路で同じ値を使う。
- **教訓 5.14「重なる UI は入力を受ける層も同時に設計する」**: 重なる UI（モーダル・ドラッグ可能パネル・コンテキストメニュー）の入力層設計は U20 の責務だが、本ユニットは「地図入力レイヤがイベントを受け取れる状態のときのみ」パン／ズームを振り分け、前面 UI 表示中に地図パンが誤起動しないこと（および前面 UI の操作を奪わないこと）を U20 の層構造と整合させてテストで確認する。
- **教訓 5.30「過少共有と過剰共有の両方を戒める」 / §4「単一の真実源」**: 座標変換・ズーム算出（U17）、カメラ状態（U16）、モード状態・入力レイヤ（U20）、選択・ヒット（U22）は依存先の実装を共有し再実装しない（過少共有の戒め）。一方、表示モードの左ボタンと編集モードの左ボタンは行き先が異なるため、左ボタン処理を安易に共通化しない（過剰共有の戒め）。ドラッグ閾値判定はパン・選択・矩形選択で同一基準を共有する（過少共有の戒め）。
- **教訓 5.33「層をまたぐ API 契約は両側テストで固定する」 / 5.34「コンポーネント間データ受け渡しは契約を型で明示する」**: U17（カメラ更新・ズーム算出）・U20（入力レイヤ・モード状態・表示専用判定・コンテキストメニュー）・U22（ヒット結果・選択委譲入口）との契約は文字列の偶然一致に頼らず共有型・型付きラッパー・両側テストで固定する。依存先 API 未確定なら境界インタフェース（adapter）を切って局所化する。条件分岐は排他ではなく「モード × ボタン × ヒット対象」の組み合わせで網羅する。
- **教訓 5.41「検証不能になった範囲は別手段で補う」**: DOM ポインタ／ホイールイベント連携など E2E 寄りで検証しづらい範囲は、決定関数・閾値判定・パン算出を純粋関数化し、イベント正規化部分をアダプタ分離・モックで単体テスト対象にして補い、未検証のまま放置しない。
- **技術方針 2.3（React 再レンダリングと地図描画の分離）／R5（ドラッグ中の重いコピー回避）**: パン中の連続更新を React state に載せると 60FPS が破綻する（NFR 5.1）。本ユニットはカメラ状態（U16）を更新し U17（`render`）が購読して命令的に再描画する経路に流し、ドラッグ中にドメイン不変モデル全体のコピーを取らない。
- **技術方針 R3（無限横スクロール・連続スカラー経度）**: パンによる中心経度更新は連続スカラーのまま行い、世界端（±180 度境界）をまたいでも −180〜+180 に閉じ込めず破綻しない。またぎ判定・±360 度補正・代表区間正規化は U17（およびその先の正規化）に委譲し、本ユニットで独自に周期処理を書かない（単一の真実源）。
- **クリーンルーム（開発ガイド 3.1）**: 本ユニットの実装・コメント・テスト名で過去版や外部の既存実装に言及しない。制約はすべて v4 自身の要件（FR-09 ほか）・技術方針として直接記述する。
- **依存先未確定への備え**: U17 / U20 / U22 の API が確定していない場合でも、本ユニットは境界インタフェース（adapter）越しに依存することで着手可能。adapter の契約は型で明示し、依存先確定後に接続する（教訓 5.33）。各真実源（カメラ＝U16、変換／ズーム＝U17、モード／入力レイヤ＝U20、選択／ヒット＝U22）は依存ユニットに置き、本ユニットで二重に持たない。

# U21 タイムラインUI(スライダー・数値入力・年月日入力コンポーネント・再生)

## 目的

本アプリは歴史を時間軸に沿って網羅的に視覚化・追跡するツールであり、タイムラインは「表示対象時間を変更する主要インターフェース」である。時間を変えると、その時点で有効な歴史の錨に基づきメインマップ上の全地物の状態（形状・属性・存在の有無）が即時に再構成される（FR-64 / FR-71）。

本ユニットは、画面下部のタイムライン UI を React コンポーネント群として実装する。具体的には、(1) 時間軸スライダーによる直感的な時間移動と即時マップ更新、(2) 設定された時間範囲と現在時間の数値表示、(3) 年/月/日を独立した入力欄として提示し月日に「未指定」トグルを備える年月日入力コンポーネント（直接ジャンプ・暦設定に基づく即時妥当性検証・負の年=紀元前表示）、(4) 時間範囲の最小/最大設定（既定 0〜10000 年）・目盛り/ラベル・イベントマーカー、(5) 前進/後退ステップ操作（単位選択・長押し連続）、(6) 再生制御（速度 0.1〜10 倍、1 倍=1 年/秒、端で自動停止、倍率を日数増分へ換算し二重適用を防止）を提供する。

加えて本ユニットは、年月日入力コンポーネントを「タイムラインの直接ジャンプ欄」と「プロパティ編集パネルの存在期間入力」の双方で共有できる再利用可能なコンポーネントとして設計する。時間変更通知は常に年・月・日を個別値（完全値）で配信し、小数年などの中間表現を用いない（FR-70・教訓 5.16）。すべての時間計算（正規化・比較・妥当性検証・年間日数換算）は U02 が提供する共通の純粋ロジックを経由し、本ユニットは UI 表示と入力受付・状態反映に責務を限定する。

## スコープ

### やること

1. **時間軸スライダーと即時マップ更新（FR-64）**
   - 時間軸スライダーを描画し、ドラッグ／クリックで表示対象時間を変更できる。
   - スライダーで時間が変わると、現在時刻を保持するセッション状態（Zustand ストア）を更新し、その変更がメインマップの即時再描画を駆動する（再描画自体は U16 が担うため、本ユニットは現在時刻の更新と通知のみを行う）。
   - スライダーの位置と現在時刻は双方向に同期する（数値入力やステップ・再生で時刻が変わったらスライダーつまみも追従する）。

2. **時間範囲と現在時間の数値表示（FR-64）**
   - 設定された時間範囲（最小／最大）の両端と、現在時間を、年（および指定があれば月・日）の数値で常時表示する。
   - 負の年は紀元前として表示する（後述の紀元前表示規約に従う）。

3. **年/月/日 独立入力コンポーネント（FR-65 / FR-67 / FR-70）**
   - 年・月・日を独立した数値入力欄として提示する。年は必須、月・日は任意。
   - 月・日それぞれに「未指定」トグルを設け、未指定なら当該粒度の情報を保持しない（未指定は「値が無い」状態として扱い、`0` などの数値で代用しない）。
   - 入力値の妥当性を、U02 の暦設定（初期実装はグレゴリオ暦）に基づく検証関数で即時検証し、無効値（範囲外の月、その月に存在しない日、平年の 2月29日 など）はその場でエラー表示する。エラー中は確定（ジャンプ／反映）を拒否する。
   - 負の年を入力でき、紀元前として解釈・表示する。
   - 「直接ジャンプ」操作（確定）で、入力された完全な時間値を U02 の正規化を経て現在時刻へ反映し、マップを即時更新する。
   - このコンポーネントを再利用可能な単一の React コンポーネントとして実装し、タイムラインの直接ジャンプ欄と、プロパティ編集パネルの存在期間入力（開始時刻・終了時刻）の双方から同一実装を共有できるようにする（FR-70）。共有時の差異（タイトル文言・必須/任意・終了時刻の「未設定」許容など）は props で吸収し、入力・検証・完全値受け渡しのコア挙動は共通化する。

4. **時間範囲設定・目盛り・ラベル・イベントマーカー（FR-66）**
   - タイムラインがカバーする時間範囲の最小値・最大値を読み取り、既定は 0 年〜10000 年とする（範囲値そのものの保存・編集ダイアログは設定ユニットの責務。本ユニットは範囲値を受け取って表示・走査に用い、欠落時に既定 0〜10000 を用いる）。
   - スライダー下部に目盛りとラベルを表示する。目盛り間隔はズーム（後述の任意拡大）や範囲幅に応じて読みやすい粒度を選ぶ。
   - 重要イベントを「イベントマーカー」として時間軸上の該当位置に表示し、設定（追加・編集・削除）できる UI を提供する。マーカーは時間点に対応づけられ、クリックでその時刻へジャンプできる。

5. **前進/後退ステップ操作（FR-68）**
   - 前進・後退のステップボタンを提供し、ステップ単位として年・月・日のいずれかを選択できる（初期選択は年）。
   - ステップ値は常に 1 単位とする（1 年・1 月・1 日）。
   - ボタン長押しで連続ステップを行う（押下中は一定間隔で繰り返し、解放で停止）。
   - 月・日が未指定の現在時刻に対してステップする場合は、U02 の暦設定に基づく既定値（1月1日）を補完してから単位を加減する。
   - ステップ加減算は U02 の時間計算を経由し、月末・年境界・うるう年・紀元前境界を暦設定どおりに扱う（UI 側で日数を独自計算しない）。

6. **再生制御（FR-69）**
   - 再生／一時停止ボタンと再生速度セレクタ（0.1 / 0.5 / 1 / 2 / 5 / 10 倍。1 倍 = 1 年/秒）を提供する。
   - 一定間隔のタイマーで現在時刻を前進させる。U02 の暦設定が持つ年間日数に基づき、速度倍率を「1 tick あたりの日数増分」へ換算する。
   - 時間範囲の端（最大値、後退再生があれば最小値）に到達したら自動停止する。
   - 速度の二重適用を防ぐ（後述「注意点」教訓 5.16）。倍率を「タイマー間隔」と「1 tick あたりの進行量」の両方へ掛けない。どちらが速度を表すかを一箇所に決めて適用する。

7. **状態反映と通知**
   - 現在時刻（年・月・日の完全値）をセッション状態（Zustand）に保持し、スライダー・数値入力・ステップ・再生・イベントマーカー・プロパティパネルからの錨選択など、すべての時間変更経路がこの単一の状態を更新する（単一の真実源）。
   - 時間変更通知は常に年・月・日の個別値（完全値）で配信し、小数年などの中間表現を経由しない（FR-70・教訓 5.16）。

8. **テスト**
   - 上記挙動の単体テスト（React コンポーネントのレンダリング／操作テスト）と、純粋に切り出せるロジック（速度→日数増分換算、ステップ加減、紀元前表示変換、範囲↔スライダー位置のマッピング）の Vitest 単体テスト。E2E で「スライダー操作→マップ即時更新」「未指定トグルの保持」「再生の端で自動停止」「共有コンポーネントの二重適用なし」を検証する。

### やらないこと

- **時間計算の純粋ロジック実装**（正規化・逆変換・比較・期間長・状態継続判定・暦設定・妥当性検証・年間日数換算の本体）。これらは U02 が提供する。本ユニットは U02 の関数を呼び出して利用するに留め、暦法定数（各月の日数・うるう年規則・年間日数）を UI 側にハードコードしない。
- **メインマップの描画・再描画そのもの**。現在時刻に基づく地物状態の再構成・Canvas 描画は U16（地図描画／時間駆動の即時マップ更新）の責務。本ユニットは現在時刻を更新して通知するのみ。
- **歴史の錨そのもののデータモデル・錨列管理（昇順整列・非重複・再編・状態継続判定）**。本ユニットは時間軸 UI であり、錨データの編集ロジックは扱わない（存在期間入力の値受け渡しと検証 UI のみを担い、確定後の錨再編は錨ユニット／コマンド層が行う）。
- **歴史の錨の時間バー表示／リスト表示の切替（FR-60）**。FR-60 は錨一覧の表示形態（時間バー表示／リスト表示）を切り替える機能であり、錨一覧を所有する U32（プロパティパネル・錨一覧・詳細文書）が完全に所有する。本ユニットはタイムライン上の**イベントマーカー（時間軸上の重要イベント表示）**のみを扱い、FR-60 の二表示切替・非存在期間の空白表示・ホイールズーム・錨名称ラベルの占有率判定は実装しない。FR-60 は本ユニットのカバー要件には含めない（U32 が coversRequirements に含める）。なお FR-60 の時間バー表示は本ユニットの「時間範囲 ↔ スライダー位置マッピング」「紀元前表示変換」と同じ U02 経由の時間計算・表示変換規約を共有するため、その純粋計算を U32 が再利用できるよう公開する。
- **プロジェクト設定ダイアログ（時間範囲最小/最大の編集・保存）** の本体（設定ユニットの責務）。本ユニットは範囲値を消費し、欠落時に既定 0〜10000 を用いる。
- **永続化・Zod スキーマ・IPC 境界検証**。イベントマーカー等の保存は永続化ユニットの責務。
- **`domain` 層・`render` 層・`shell` 層の実装**。本ユニットは `ui` 層（React）に閉じ、`domain`（U02）の純粋関数とセッション状態ストア（Zustand）を経由してのみ時間計算・状態反映を行う。

## 依存（dependsOn）

- **U16 — 地図描画／時間駆動の即時マップ更新**: 本ユニットがセッション状態の現在時刻を更新すると、U16 がその変更を購読してメインマップを当該時刻の状態へ即時再描画する。本ユニットは「現在時刻を更新し通知する側」であり、再描画の実体は U16 が担う。U16 が購読する現在時刻状態の型・キー・更新規約（年・月・日の完全値で保持・配信する）を、共有型と両側テストで固定する（教訓 5.33 / 5.34）。U16 が公開する「現在時刻の取得」「即時更新の購読」境界に合わせて結線し、本ユニットから描画ロジックへ直接踏み込まない。
- **U02 — 時間モデル（正規化）と暦設定の純粋ロジック**: 時間点型（年必須・月日任意・未指定を区別）・正規化値型・暦設定（グレゴリオ暦）・正規化／逆変換・前後比較・期間長計算・妥当性検証・完全値構築ヘルパー、および年間日数（再生の日数増分換算の基礎）を提供する。本ユニットの数値入力検証・ステップ加減・再生換算・紀元前解釈は、すべて U02 の関数を経由する。U02 の型に新しい時間表現を増やさず、単一の真実源に従う。

実装着手時に U16 のセッション状態（現在時刻）契約と U02 の公開型・関数シグネチャを確認し、本ユニットの状態反映・関数呼び出しをそれらに整合させること。いずれかが未確定の場合は、本仕様に記す入出力契約（現在時刻＝年・月・日の完全値で保持・通知、時間計算は U02 経由）に沿った型インタフェースを先に定義し、その境界に対して UI とテストを実装する。

## 実装方針（技術方針に沿う）

技術方針（`docs/技術方針.md`）の 2.3（React は UI シェル・パネル・ダイアログ・タイムライン UI に限定）・2.5（Zustand ＋ 純粋ドメインコア、Zustand を単一の真実源とし Canvas 側は購読のみ）・2.13（ディレクトリ層分離と依存方向の内向き固定）に厳密に従う。

### 配置と層分離

- 本ユニットのコードは `ui` 層（React 関数コンポーネント）に属する。時間計算は `domain`（U02）へ、即時再描画は `render`（U16 が購読）へ委譲し、依存方向は `ui → domain` の内向きに固定する。`domain`（U02）から `ui` を参照しない。
- 現在時刻・再生状態・ステップ単位選択などのセッション/UI 状態は Zustand の薄いストアに置く。地図描画状態を React state に持たせない（高頻度更新で 60FPS が破綻するため。技術方針 2.3）。タイムラインの再生 tick で現在時刻が変わったら、Zustand ストアの現在時刻を更新し、Canvas 側（U16）は購読で追従する。React の再レンダリングサイクルを毎フレームの地図描画に巻き込まない。

### 時間値の取り扱い（完全値・単一経路）

- 現在時刻は「年・月・日の完全値」（U02 の時間点型）としてストアに保持する。スライダー位置・数値入力欄・ステップ・再生・イベントマーカー・錨選択のいずれの経路も、この単一の現在時刻状態を更新する（単一の真実源、開発ガイド §4・教訓 5.16）。
- 時間変更通知は年・月・日の個別値（完全値）で行い、小数年・経過秒数などの中間スカラーを通知に用いない（FR-70）。スライダー内部で連続スカラー位置を扱う場合でも、ストアへ反映する時点で U02 の正規化／逆変換を経て年・月・日の完全値へ落とす。
- 月・日が未指定の現在時刻にステップ・再生を適用するときは、U02 の既定補完（1月1日）を経由する。論理和短絡（`month || 1` 等）で補完しない（教訓 5.18）。

### 検証・エラー表示

- 年月日入力欄の妥当性検証は U02 の検証関数を呼び、無効値を即時にインライン表示する。エラー文言は日本語のみ（FR-115）。確定（ジャンプ／反映）は検証合格時のみ許可する。
- 検証拒否メッセージは、発生元と無関係なクリック・マウス操作で即時消去しない（教訓 5.12）。消す契機は「同種の再入力」「明示的な閉じる」「妥当な値での再確定」に限定する。

### 再生制御の二重適用防止

- 速度倍率の適用箇所を一箇所に固定する。設計として「タイマー間隔は固定（例: 一定 tick）」とし、速度倍率は「1 tick あたりの進行量（日数増分）」にのみ掛ける方式を採る（または逆に進行量固定で間隔へのみ掛ける方式のいずれか一方）。両方へ倍率を掛けない（教訓 5.16）。
- 1 倍 = 1 年/秒の定義を基準に、U02 の年間日数を用いて倍率→日数増分を換算する。換算ロジックは純粋関数として切り出し、Vitest で「各倍率に対する 1 秒あたり進行量が定義どおり」「二重適用していない（換算結果が単一の倍率適用と一致）」ことをテストする。
- 端到達時の自動停止は、U02 の前後比較で「次の進行先が範囲端を超える／到達する」を判定して止める。停止時は再生状態を確実に解除する（教訓 5.8 押下→移動→解放の状態解除に準じ、再生開始で立てた状態は停止で必ず落とす）。

### 共有コンポーネント（年月日入力）の契約

- 年月日入力コンポーネントの props・コールバックの型を明示し、タイムライン側・プロパティパネル側の両方が同じ契約で利用することを型と両側テストで固定する（教訓 5.33 / 5.34）。
- コールバックは常に「年・月・日の完全値（＋未指定フラグ）」を渡し、年だけ・月だけといった部分値を単独で渡す API を作らない（教訓 5.16）。受け取り側（タイムラインの現在時刻反映、存在期間の開始/終了反映）が完全値を一度だけ適用するようにし、コンポーネント内と受け取り側の双方で補完・換算を二重に行わない。

### 一時 UI 状態の破棄

- 入力途中の下書き値・未確定のジャンプ値・再生状態・長押しの連続タイマー・ドラッグ中のスライダー仮位置などの一時 UI 状態は、確定・キャンセル・コンポーネントのアンマウント・モード切替のすべての経路で明示的に破棄する（教訓 5.2）。残ると次回操作へ暗黙に引き継がれ、意図しない値で確定しうる。

### テスト

- React コンポーネントの操作テスト（レンダリング・入力・トグル・ボタン・長押し・再生）と、純粋に切り出したロジック（速度→日数増分換算・ステップ加減・紀元前表示変換・範囲↔スライダー位置マッピング）の Vitest 単体テストを実装と同時に書く（開発ガイド 1.9）。
- E2E（Playwright for Electron）で UI 経路全体（スライダー→即時マップ更新、未指定トグルの保持、再生の端で自動停止、共有コンポーネントでの二重適用なし）を検証する。検証不能になった範囲はロジックを純粋関数化して単体テストで補う（教訓 5.41）。

## 受け入れ基準（テスト可能な形で列挙）

以下はすべてテスト可能な形で満たすこと。テストは実装と同時に作成する（開発ガイド 1.9）。

1. **スライダー/数値入力で時間変更しマップが即時更新、範囲と現在を数値表示（FR-64 / FR-65）**
   - 時間軸スライダーをドラッグ／クリックすると現在時刻（セッション状態）が変わり、その変更が U16 の即時マップ更新を駆動する（本ユニットのテストでは「現在時刻状態が更新され、購読通知が発火する」ことを確認し、再描画自体は U16 側の責務として境界で固定する）。
   - 数値入力（直接ジャンプ）で現在時刻が変わり、同様にマップ更新が駆動される。
   - 時間範囲（最小／最大）の両端と現在時間が数値で表示され、時刻変更に追従して更新される。範囲値が与えられない場合は既定 0〜10000 年が用いられる。
   - スライダー位置と現在時刻が双方向に同期する（数値入力・ステップ・再生で時刻が変わるとつまみが追従する）。

2. **年/月/日独立欄+未指定トグル、暦設定で即時検証、紀元前表示（FR-67 / FR-65 / FR-70）**
   - 年・月・日が独立した入力欄として提示され、年は必須、月・日は任意である。
   - 月・日それぞれに「未指定」トグルがあり、未指定にすると当該粒度の情報を保持しない（`0` 等の数値で代用されない）ことを確認できる。未指定→指定→未指定の往復で情報が握りつぶされない。
   - 無効値（範囲外の月、その月に存在しない日、平年の 2月29日 等）は U02 の検証で即時エラー表示され、確定（ジャンプ／反映）が拒否される。妥当値では確定できる。
   - 負の年が紀元前として表示・解釈される（紀元前 N 年が一貫した規約で表示される）。
   - 検証エラーメッセージが、無関係なクリック・マウス操作で即時消去されない（教訓 5.12）。

3. **イベントマーカー・目盛り・時間範囲設定（既定0〜10000年）（FR-66）**
   - スライダー下部に目盛りとラベルが表示され、範囲幅・拡大に応じて読みやすい粒度になる。
   - 重要イベントをイベントマーカーとして時間軸上の該当位置に表示・追加・編集・削除でき、マーカークリックでその時刻へジャンプできる。
   - 時間範囲の最小／最大を消費して表示・走査に反映し、欠落時は既定 0〜10000 年を用いる。
   - （歴史の錨の時間バー表示／リスト表示切替＝FR-60 は本ユニットの範囲外であり、錨一覧を所有する U32 が完全に所有する。本ユニットは時間軸上のイベントマーカー表示・設定までを担う。）

4. **ステップ操作（単位選択・長押し連続）と再生（速度・端で自動停止）（FR-68 / FR-69）**
   - 前進／後退ステップで現在時刻が 1 単位だけ動き、単位（年・月・日）を選択できる（初期は年）。ステップ値は常に 1 単位である。
   - ボタン長押しで連続ステップし、解放で停止する。長押しの連続タイマーが解放・アンマウントで確実に解除される（残留しない）。
   - 月・日未指定の現在時刻に対するステップは、U02 の既定値（1月1日）補完を経てから単位加減され、月末・年境界・うるう年・紀元前境界が暦設定どおりに扱われる。
   - 再生で一定間隔のタイマーにより時間が前進し、速度セレクタ（0.1/0.5/1/2/5/10 倍、1 倍=1 年/秒）に従う。倍率は U02 の年間日数に基づき日数増分へ換算される。
   - 時間範囲端に到達すると自動停止し、再生状態が確実に解除される。

5. **プロパティ存在期間入力と同一コンポーネント共有・完全値受け渡しで二重適用なし（FR-70 / 教訓 5.16）**
   - 年月日入力コンポーネントが、タイムラインの直接ジャンプ欄とプロパティ編集パネルの存在期間入力（開始/終了時刻）の双方で同一実装として共有される。
   - コンポーネントのコールバックは常に年・月・日の完全値（＋未指定フラグ）を渡し、部分値の単独受け渡しを行わない。受け取り側は完全値を一度だけ適用する。
   - 再生の速度倍率が二重適用されないこと（換算ロジックの結果が単一倍率適用と一致すること）を単体テストで確認する。タイマー間隔と 1 tick 進行量の双方へ倍率を掛けていない。

6. **層分離と単一の真実源**
   - 本ユニットは `ui` 層に属し、暦法定数（各月の日数・うるう年規則・年間日数）を UI 側にハードコードせず、時間計算をすべて U02 経由で行う。
   - 現在時刻はセッション状態（Zustand）に年・月・日の完全値で保持され、全時間変更経路がこの単一状態を更新する。地図描画状態を React state に持たせていない。

## 関連要件（FR-id）

- **FR-64**（must）: 時間軸スライダーで表示対象時間を直感的に変更でき、移動に応じてメインマップ表示が即時に該当時間の状態へ更新される。設定された時間範囲と現在時間を数値表示する。— 本ユニットのスライダー・数値表示・現在時刻更新（U16 が即時再描画を駆動）が対応する。
- **FR-65**（must）: 特定の時間（年、オプションで月・日）を数値で直接入力してジャンプでき、年を基本単位とし月・日精度を扱い、負の年数を紀元前として解釈・表示する。— 直接ジャンプ欄と紀元前表示が対応する。
- **FR-66**（should）: タイムラインの時間範囲の最小/最大を設定でき（既定 0〜10000 年）、スライダー下部に目盛りとラベルを表示し、重要イベントをイベントマーカーとして時間軸上に表示・設定できる。— 範囲消費・目盛り/ラベル・イベントマーカーが対応する（範囲の編集・保存ダイアログは設定ユニット）。
- **FR-67**（should）: 年・月・日を独立した数値入力欄として提示し、月・日に「未指定」トグルを設け、未指定なら当該粒度の情報を保持しない。妥当性は暦設定に基づき検証し無効値は即時エラー表示する。初期実装はグレゴリオ暦。— 年月日入力コンポーネントの中核要件。
- **FR-68**（could）: 前進・後退のステップ操作で年・月・日いずれかの単位を選択でき（初期は年）、ステップ値は常に 1 単位で長押しで連続操作できる。月・日未指定時は既定値（1月1日）を補完する。— ステップ操作が対応する。
- **FR-69**（could）: 再生制御を提供し一定間隔のタイマーで時間を進める。速度セレクタ（0.1/0.5/1/2/5/10 倍、1 倍=1 年/秒）を備え、年間日数に基づき倍率を日数増分へ換算する。範囲端で自動停止する。— 再生制御が対応する（二重適用防止は教訓 5.16）。
- **FR-70**（should）: プロパティ編集パネルの存在期間入力はタイムラインと同じ入力コンポーネントを共有し、年必須・月日任意の粒度を統一する。時間変更通知は常に年・月・日を個別値で配信し小数年などの中間表現を使わない。すべての時間操作は暦設定と整合する共通の時間計算ロジックを経由する。— 共有コンポーネントと完全値受け渡し、U02 経由の時間計算が対応する。
- **FR-60**（could）: 歴史の錨の表示を時間バー表示とリスト表示で切り替えられる。— 本ユニットはこの要件をカバーしない（U32 が coversRequirements に含めて完全に所有する）。本ユニットは時間軸上のイベントマーカー表示・設定（FR-66）のみを担い、時間バー表示が共有する時間計算・表示変換規約（U02 経由）を公開して U32 が再利用できるようにする。

関連する非機能要件: NFR 5.1（高頻度更新の地図描画を React 再レンダリングから切り離す＝60FPS 防衛）、NFR 5.7（日本語 UI）、NFR 5.8（純粋に切り出したロジックの単体テスト・境界網羅）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

着手前に、以下の関連教訓を節番号・見出し・本文ごと直接引用し、本ユニットへの適用を「適用:」として宣言してから実装すること（開発ガイド 1.6 AI 作業開始ゲート）。

- **教訓 5.16「時間値は完全値で受け渡し、倍率の二重適用を防ぐ」**（本ユニット最重要・引用: 「時間軸 UI では、年・月・日を分解した一部の値だけを下位層へ渡さず、完全な時間値を受け渡す。再生処理では、速度を表すのが『間隔』か『1 tick あたりの進行量』かを一箇所に決め、両方へ倍率を掛けない（二重適用防止）。」）
  - 適用: 年月日入力の共有コンポーネントは常に完全値（年・月・日＋未指定フラグ）をコールバックで渡し、部分値の単独 API を作らない。再生は速度倍率の適用箇所を一箇所（1 tick あたりの日数増分、または間隔のいずれか一方）に固定し、両方へ掛けない。換算結果が単一倍率適用と一致することを単体テストで固定する（受け入れ基準 5）。

- **教訓 5.18「空配列・空オブジェクトは真値である」**（引用: 「空配列・空オブジェクトは真値である。論理和による短絡評価のデフォルト補完に頼らず、型や状態を明示的に判定する。」）
  - 適用: 月・日の「未指定」を `month || 1` のような短絡で補完しない。年 0・月 0 相当・日 0 相当を偽値として既定へ落とさない。未指定は型・状態で明示判定し、補完は U02 の正規化経路でのみ行う（受け入れ基準 2・4）。

- **教訓 5.15「タイムスタンプはコンテキスト上の時刻を参照する」**（引用: 「時間軸を持つデータのタイムスタンプは、必ずコンテキスト上の時刻（現在時刻）を参照し、システム時刻と混同しない。時刻源は一元管理するサービスから取得する。」）
  - 適用: タイムラインが扱う時刻はすべて「作中時間（現在時刻状態）」であり、システム時刻（`Date.now()`）を作中時間の判定・表示・進行に混入させない。再生の進行も作中時間に対して行い、実時間タイマーは tick の駆動にのみ用いる。

- **教訓 5.5「依存する状態は変化時に再検証する」**（引用: 「ある状態が変化したら、それに依存する他の状態も検証・更新する。例: 時間が変わったら、選択中要素がその時間に存在するか検証し、なければ選択を解除する。」）
  - 適用: 本ユニットが現在時刻を変えたとき、その時刻に依存する選択状態（選択中地物がその時刻に存在するか等）の再検証が必要となる。本ユニットは「時刻が変わった」ことを完全値で確実に通知し、依存状態の再検証を購読側が行えるようにする。時刻変更通知が漏れると依存状態がドリフトする。

- **教訓 5.2「一時的 UI 状態は全経路で破棄する」**（引用: 「一時的 UI 状態（描画プレビュー・選択中の値・ドラフト設定）は、開始・確定・キャンセル・ツール切替・モード切替のすべての経路で明示的に破棄する。」）
  - 適用: 入力途中の下書き値・未確定ジャンプ値・再生状態・長押し連続タイマー・スライダー仮位置を、確定・キャンセル・アンマウント・モード切替で破棄する。とくに長押しタイマーと再生タイマーのクリーンアップ漏れ（リーク・残留進行）に注意する（受け入れ基準 4）。

- **教訓 5.8「押下→移動→解放シーケンスを全パスで保証する」**（引用: 「押下 → 移動 → 解放のシーケンスは、全パス（クリック・ドラッグ）で状態が正しく開始・更新・終了することを保証する。押下で設定した状態は解放で必ず解除し…」）
  - 適用: スライダーのドラッグ（押下→移動→解放）と長押しステップ（押下→連続→解放）は、押下で立てた状態（ドラッグ中・連続中フラグ、タイマー）を解放で必ず解除する。クリック（移動なし）でも状態が残らないこと。再生の開始→停止も同型で、停止で再生状態を確実に落とす。

- **教訓 5.12「判断用メッセージを無関係な操作で消さない」**（引用: 「検証拒否・保存失敗など、ユーザーが次の判断に使うメッセージは、発生元と無関係なクリックやマウス操作で即時消去しない。」）
  - 適用: 年月日入力の検証エラー文言は、無関係なクリック・スライダー操作で消さない。消す契機は同種の再入力・明示的な閉じる・妥当値での再確定に限定する（受け入れ基準 2）。

- **教訓 5.33 / 5.34「層をまたぐ API 契約は両側テストで固定する／コンポーネント間データ受け渡しは契約を型で明示する」**
  - 適用: 共有する年月日入力コンポーネントの props・コールバック型、および U16 が購読する現在時刻状態のキー・型を、共有型と両側テストで固定する。タイムライン側とプロパティパネル側、U21 側と U16 側が偶然の一致でなく型で契約を共有する。

- **教訓 5.30「過少共有と過剰共有の両方を戒める」**
  - 適用: 年月日入力のコア（入力・検証・完全値受け渡し）はタイムラインと存在期間入力で確実に共有する（過少共有の戒め）。一方、両用途で異なる規則（タイムラインは現在時刻=単一時点、存在期間は開始/終了の対・終了の「未設定」許容）は props で分け、コンポーネントを安易に同一挙動へ畳み込まない（過剰共有の戒め）。共有前に「2 用途の制約は本当に同一か」を列挙して確認する。

- **暦法定数を UI にハードコードしない**: 各月の日数・うるう年規則・年間日数・既定補完（1月1日）・紀元前の年 0 規約は U02 の単一の真実源に置き、本ユニットはそれを呼び出す。UI 側で独自に日数計算・補完・符号解釈を書かない（将来の独自歴拡張＝要件 7.1 に向けた共通ロジック化を壊さないため）。

- **紀元前表示の規約**: U02 は内部正規化で年 0 を許容する天文学的連番を採る前提である。本ユニットは負の年を「紀元前」としてユーザー表示へ変換する責務を持つ。負年→紀元前ラベルの変換規約（年 0 の表示扱いを含む）を一箇所に集約し、表示・入力解釈の双方が同じ規約に従うことをテストで固定する。規約を変える場合は表示・入力・テストを同一変更単位で同期する。

- **クリーンルーム原則（開発ガイド 3.1）**: 本仕様・実装・コメント・テスト名で過去版・他プロダクト・外部の既存実装に一切言及しない。必要な制約はすべて v4 自身の要件（FR-64〜FR-70）・技術方針として直接記述・参照する。

- **やり残しの記録（開発ガイド 1.8）**: FR-60 の時間バー/リスト二表示切替本体は U32 が所有するため本ユニットの未カバーではない（範囲分界として明示）。その他の未着手項目は現状.md に記録する。再発防止知見は教訓集（開発ガイド §5）に追記する。

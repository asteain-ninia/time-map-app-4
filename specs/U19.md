# U19 地物描画(点/線/面・穴透過・飛び地独立・派生集約形状・ラベル・LOD)

## 目的

選択中の時刻における全地物の状態を、メインマップ（Canvas 2D 描画層）上に描画する描画ユニットを提供する。本アプリの中核体験は「任意の時点における世界の状態を地図上で再現する」ことであり（FR-01）、時間を移動すると地図全体が即時にその時刻の姿へ更新される（FR-71）必要がある。本ユニットはその「再現された地図の見た目」を実際に画面へ描く責務を一手に引き受ける。

具体的には次を一体で実現する。

- 選択時刻で有効な錨に基づいて評価された全地物（点情報・線情報・面情報）を、種別ごとに正しく描画し、時間変更に応じて即時再描画する（FR-71）。
- 面情報の描画で、穴リングは常に透過（塗りなし）、飛び地は本土と同様に独立した領土リングとして描画する。選択・ハイライト等の一時的な視覚効果でも、穴は常に透過・飛び地は本土同様で、恒常表示と異なる輪郭・塗り分けをしない（FR-21）。
- 集約地物（下位領域を持ち形状属性を保持しない面情報）の派生形状（下位領域の和）を、単一の形状解決判定（U08 が確立した共通解決判定）で描画する（FR-42 の集約表示・教訓 5.29）。
- 種別ごとの条件でラベルを描画する。点情報は最小ズーム倍率に基づく表示可否、線情報は可視長に基づく表示可否、面情報は外周・飛び地のリングごとに画面占有率に基づく表示可否を判定し、面情報はリングごとにラベルを描く（FR-86）。
- 点の大きさ・線の太さ・名前ラベルのフォントサイズを、ズームレベルに関わらず画面上の見た目サイズが一定になるよう描く（FR-17）。
- 視野外クリッピング（RBush）・LOD・描画バッチ・高頻度イベントのスロットリングにより、5,000 オブジェクト規模で 60FPS を維持する（NFR 5.1 / 5.2）。その達成を裏づける計測（FPS ベンチマーク）を備える。

本ユニットは「与えられた評価済み状態とカメラ変換を、画面へ描く」ことに責務を限定する。地物の評価（どの錨が有効か）・ツリー集約形状の算出・空間インデックスの構築・座標のワールドラップ正規化・選択状態やモードの保持は、いずれも依存ユニットの責務であり、本ユニットはそれらの出力を消費する。

## スコープ

### やること

1. **選択時刻に基づく全地物の描画と即時再描画（FR-71）**
   - 入力として「選択時刻で評価済みの全地物状態」（各地物が当該時刻に存在するか・存在するなら点／線／末端面／集約面の別と形状・スタイル属性）と「カメラ変換（ワールド→スクリーン）」を受け取り、メインマップへ全地物を描画する。
   - 選択時刻が変わった（U16 由来の時刻状態が更新された）ときに、評価済み状態の差し替えを受けて即時に再描画する。時間変更で形状・属性・存在の有無が変わったら、その変化が画面へ反映される（FR-71）。
   - 当該時刻に存在しない地物（非存在期間＝時間的飛び地に入っている地物）は描画しない。

2. **点情報の描画（FR-17 / FR-18）**
   - 単一頂点の位置にアイコン・色・サイズで点情報を描く。点のサイズはズームレベルに関わらず画面上で一定サイズになるよう、スクリーン座標基準でマーカー半径を決める（FR-17）。

3. **線情報の描画（FR-17 / FR-19）**
   - 複数頂点のパスを線として描く。線の太さはズームに関わらず画面上一定（スクリーン座標基準の線幅）にする（FR-17）。世界端をまたぐ線は、U05 のワールドラップ展開済み座標を用い、折り返して分断せず連続描画する（技術方針 R3 / FR-14 の方針と整合）。

4. **面情報（末端地物）の描画とリング構造（FR-20 / FR-21）**
   - 領土リング（最外周・飛び地）を塗り＋境界線で描き、穴リングは塗らずにくり抜く（透過）。
   - 飛び地（地理的に分離した独立外周リング）を、本土の領土リングと同じスタイルで独立領域として描く。人工的な連結線で繋がない（FR-21）。
   - リング階層は「領土→穴→領土→…」と交互である前提（FR-24）に従い、塗り・くり抜きをリングの種別（領土／穴）に基づいて適用する。ネスト（穴の中の飛び地）も同じ規則で再帰的に描く。
   - 同一面情報の全領土リング（本土＋飛び地）は同一スタイル（同一塗り色・境界色）で一貫描画し、飛び地だけ別塗りにしない（FR-21 / FR-101 の「飛び地は同一面として一貫した色」）。

5. **集約地物の派生形状描画（FR-42 / 教訓 5.29）**
   - 集約地物は形状属性を持たないため、その描画形状は U08 が提供する単一の形状解決判定（下位領域の和＝派生形状）から取得して描く。本ユニットで集約形状を別途算出・別判定で求めない。
   - 階層深度フォーカス（FR-42 のグローバル深度スライダーで「階層深度≤N」に集約表示する状態）が与えられたとき、省略される階層の地物を自身の派生形状（下位領域の和）として描く。どの地物を集約形状として描き、どの地物を実形状で描くかは、依存ユニットが解決した同一の形状解決判定の結果に従う（描画・ヒットテスト・ラベル位置が同じ解決判定で動く＝教訓 5.29）。

6. **ラベルの種別別条件描画（FR-86 / FR-17）**
   - 点情報: 設定された最小ズーム倍率以上のときにラベルを表示する。
   - 線情報: 線の可視長（画面上の投影長）が閾値以上のときにラベルを表示する。
   - 面情報: 各リング（外周・各飛び地）ごとに画面占有率（リングのスクリーン投影面積／ビューポート面積など、設定で定める占有率閾値）を判定し、閾値以上のリングにラベルを描く。面情報は外周・飛び地のリングごとにラベルを描画する（リング単位）。
   - ラベルのフォントサイズはズームに関わらず一定（スクリーン座標基準）にする（FR-17）。占有率閾値はプロジェクト設定（FR-109「面情報ラベル画面占有率閾値」）から受け取る。

7. **視野外クリッピング・LOD・描画バッチ・スロットリング（NFR 5.1 / 5.2）**
   - 視野外クリッピング: 現在のビューポート矩形に交差する地物のみを描画対象に絞る。候補絞りは U10 の空間インデックス（RBush）への矩形問い合わせを再利用する。世界端ラップ展開した複製も問い合わせ対象に含め、東端・西端をまたいで見える地物も描く。
   - LOD（詳細度制御）: ズームレベルに応じて描画の詳細度を下げる（例: 遠景では微小頂点列の簡略化・極小地物のラベル抑制・極小面の塗り省略）。表示結果の正しさ（穴透過・飛び地独立）を壊さない範囲で簡略化する。
   - 描画バッチ: 同種・同スタイルの描画をまとめ、状態変更（塗り色・線幅設定）の切替回数を抑える。
   - スロットリング: パン・ズーム・ドラッグ中の高頻度イベントによる再描画を、設定された描画更新頻度（FR-110「描画更新頻度=1〜60FPS・デフォルト 60」）に合わせて間引く（requestAnimationFrame ベースの再描画ループに集約し、1 フレームに 1 回だけ描く）。

8. **性能計測（NFR 5.1 / 5.2 / 5.8）**
   - 5,000 オブジェクト規模（各オブジェクト平均 10 錨）の合成データで、パン・ズーム時の FPS を計測する計測ハーネスを用意し、60FPS の到達可否を記録できる形にする。視野クリッピング・LOD の有無で描画コストが変わることを計測で示せるようにする。

9. **`MapRenderer` インタフェースへの準拠**
   - 描画層は技術方針 2.4 が定める `MapRenderer` インタフェース（カメラ変換・地物バッチ・ヒットテストの契約）に準拠して実装し、既定実装を Canvas 2D とする。インタフェースに閉じることで、性能未達時に WebGL 実装へ局所差し替えできる退避路を保つ。

### やらないこと

- 地物の時刻評価（どの錨が有効か・存在判定）そのもの（U16 / 時間モデルの責務）。本ユニットは「評価済み状態」を入力に取り、錨列の走査・正規化はしない。
- 集約地物の派生形状（下位領域の和）の算出そのもの（U08 の責務）。本ユニットは U08 の形状解決判定の結果を消費するだけで、ブーリアン和を自前で計算しない。
- 空間インデックス（RBush）の構築・更新（U10 の責務）。本ユニットは視野クリッピング候補絞りのために U10 の問い合わせ API を利用するだけで、インデックスの保守はしない。
- カメラ（ズーム・パン・経度シフト・無限横スクロール）の状態管理と入力ハンドリング（U17 の責務）。本ユニットはカメラが提供するワールド↔スクリーン変換を消費し、入力からカメラを更新しない。
- 経度の連続スカラー保持と世界端ラップ正規化のロジックそのもの（U05 の責務、U10 経由で利用）。本ユニットはラップ展開済み座標を描く。
- 選択状態・アクティブ地物・頂点選択・編集モードの保持と遷移（選択・編集系ユニットの責務）。本ユニットは「選択ハイライトを描くべきか」のフラグ／スタイル指示を入力として受け取り描くだけで、選択ロジックを持たない。
- ヒットテスト（クリック地物特定）の上位フロー。`MapRenderer` 契約としてヒットテストの座標基盤は本ユニットが提供するが、選択への接続は選択系ユニットが担う。
- 自動配色の色決定（FR-100 / FR-101）。本ユニットは与えられたスタイル属性（塗り色・選択色・境界色・透過）で描くだけで、配色アルゴリズムを実行しない。
- グリッド・緯線経線（FR-13）、ベースマップ画像（FR-03〜FR-06）、測量線（FR-14〜FR-16）、頂点ハンドル／エッジハンドル（FR-87）の描画。これらは別ユニットの責務であり、本ユニットは「地物本体とそのラベル」の描画に限定する（重なり順の取り決めは依存ユニットと契約で固定する）。
- 競合解決・整合性維持プロセス（FR-61〜FR-63）。本ユニットは描画のみで編集を起こさない。

## 依存（dependsOn）

実装着手時点でこれらの公開インタフェースを利用する前提とし、未確定の場合は本ユニット内に最小の型境界（アダプタ）を切って後で接続し、接続時に両側テストで契約を固定する（教訓 5.33 / 5.34）。

- **U17（カメラ・ビューポート / ワールド↔スクリーン変換）**: ズーム・パン・経度シフト・無限横スクロール（FR-07 / FR-08 / FR-12）を反映したワールド座標→スクリーン座標変換と、現在のビューポート矩形を提供する。本ユニットは全描画でこの変換を経由し、FR-17 のズーム非依存一定サイズ表示（点・線・ラベル）をスクリーン座標基準で実現する。
- **U10（空間インデックス RBush・末端地物の候補問い合わせ）**: ビューポート矩形に交差する地物候補の問い合わせ API を提供する。本ユニットはこれを視野外クリッピング（描画対象絞り込み）に再利用する。世界端ラップ展開した複製の問い合わせも U10 経由で行う。
- **U08（ツリー階層・末端/集約の区別・派生形状の単一解決判定）**: ある時刻における各面情報が末端地物か集約地物かの区別と、集約地物の派生形状（下位領域の和）を解決する単一の共通判定を提供する。本ユニットは集約地物をこの解決判定の結果で描き、別判定・別算出を行わない（教訓 5.29）。階層深度フォーカス（FR-42）で「どの地物を集約形状として描くか」も同じ解決判定の結果に従う。
- **U09**: 面情報の穴・飛び地・リング階層（領土リング→穴リング交互、ネスト）の表現と、リングの種別（領土／穴）判定・リング階層の読み取りを提供する。本ユニットは穴透過・飛び地独立描画（FR-21）とリング単位ラベル（FR-86）をこのリング表現に基づいて行う。
- **U16**: 選択時刻（現在時刻）の状態と、その時刻で評価済みの全地物状態（存在の有無・形状・属性スナップショット）を提供する。本ユニットは時刻変更通知を受けて即時再描画する（FR-71）。

> dependsOn に挙がっていない関心事（時刻評価ロジック・集約形状算出・インデックス保守・カメラ入力・配色）には依存しない。本ユニットは `render` 層に属し、`domain` を内向きに参照するのみで、`domain` から逆参照されない（技術方針 2.13 の依存方向）。

## 実装方針（技術方針に沿う）

技術方針 2.3（高頻度描画を React から切り離す）・2.4（Canvas 2D / `MapRenderer` 抽象）・2.5（Zustand 購読で Canvas を駆動）・5.2（性能）・R1（描画最適化）・R3（世界端ラップ）・R5（ドラッグ中の軽量処理）に従う。

### 配置層と React からの分離

- 描画層は `render` 層に置き、技術方針 2.4 の `MapRenderer` インタフェースに準拠した Canvas 2D 実装とする。
- 高頻度更新の地図描画は React の再レンダリングサイクルから完全に切り離す（技術方針 2.3）。描画状態を React state に持たせると再レンダリングで 60FPS が破綻するため、本ユニットは Zustand ストア（選択時刻・カメラ・評価済み状態）を `subscribe` で購読し、命令的に Canvas へ描く（技術方針 2.5）。React 側は描画呼び出しのトリガにだけ関与する。
- 描画の純粋な部分（種別ごとの描画コマンド列の生成、ラベル表示可否の判定、LOD レベルの決定、視野矩形交差判定）は、可能な限り Canvas API から分離した純粋関数として切り出し、Vitest で単体検証できるようにする（NFR 5.8 / 教訓 5.41）。Canvas への実描画は薄い委譲層に閉じる。

### ズーム非依存の一定サイズ表示（FR-17）

- 点のマーカー半径・線幅・ラベルフォントサイズは、ワールドサイズではなくスクリーンサイズで固定する。形状の頂点はワールド→スクリーン変換（U17）で投影し、サイズ系の量だけはスクリーン基準の定数（設定値）を使う。これによりズームに関わらず見た目サイズが一定になる（FR-17）。
- 同じサイズ基準（点サイズ・線幅・フォントサイズの算出）は単一の実装に集約し、点・線・面ラベルで別実装にしない（単一の真実源・教訓 5.30）。

### 穴透過・飛び地独立（FR-21）

- 面の塗りは「領土リングを塗り、穴リングでくり抜く」規則で行う（Canvas 2D では even-odd / nonzero の塗りルールまたはリング向き制御により、穴を透過させる）。穴リングには塗りを乗せない（FR-20 / FR-21）。
- 飛び地は独立した領土リングとして本土と同じ描画パスで描く。飛び地専用の輪郭・塗り分けや連結線を加えない（FR-21）。恒常表示・選択ハイライトのどちらでも、穴は透過・飛び地は本土同様という規則を共有する（一時的視覚効果でも変えない）。
- 選択ハイライト（アクティブ地物のシアン塗り・アウトライン等、FR-82）を描く場合も、上記の穴透過・飛び地独立規則を恒常表示と同一の形状解決・同一のリング規則で適用する。ハイライト用に別の形状を作らない（教訓 5.29 / FR-21）。

### 派生集約形状の単一解決判定（教訓 5.29）

- 集約地物の描画形状は U08 の単一形状解決判定から取得する。描画・ヒットテスト・ラベル位置は同じ解決判定の結果を使い、判定条件のドリフトによる「描画されるのに選択できない」「ラベル位置が描画とずれる」等の対概念矛盾を避ける（教訓 5.29）。
- 階層深度フォーカス（FR-42）で集約表示する地物の選別も、依存ユニットが解決した同一判定の結果に従い、本ユニットで「集約として描くか実形状で描くか」を独自判定しない。

### 視野外クリッピング・LOD・バッチ・スロットリング（NFR 5.1・R1）

- 視野外クリッピング: 描画前に U17 のビューポート矩形を U10 の空間インデックスへ問い合わせ、交差候補のみを描画対象に絞る。世界端ラップ展開複製も問い合わせ対象に含める（技術方針 R3）。集約地物の派生形状は U08 解決後のバウンディングボックスでクリッピング判定する。
- LOD: ズームレベルから詳細度を決め、遠景での頂点列簡略化・極小地物の省略・ラベル抑制を行う。簡略化は穴透過・飛び地独立・派生形状の正しさを壊さない範囲に限定する。
- 描画バッチ: 同一スタイルの描画をまとめ、Canvas の状態切替（fillStyle・lineWidth 等）回数を最小化する。
- スロットリング: 全再描画を単一の `requestAnimationFrame` ループに集約し、1 フレーム 1 描画とする。パン・ズーム・ドラッグ中の連続イベントは「再描画要求フラグを立てる」だけにして、フレーム境界でまとめて描く。描画更新頻度の上限は設定（FR-110、既定 60FPS）に従う。ドラッグ中は重い再計算を避け軽量描画に徹する（技術方針 R5）。
- ダーティ領域 / オフスクリーンキャッシュは、計測で必要性が判明した場合に R1 の範囲で局所追加する（既定構成は単純さを優先し、過剰最適化を前倒ししない）。

### 計測（NFR 5.1 / 5.2 / 5.8）

- 5,000 オブジェクト規模（平均 10 錨）の合成データで、パン・ズーム時の FPS を記録する計測ハーネスを整備する。視野クリッピング ON/OFF・LOD ON/OFF の比較で最適化の効果が確認できる形にする（技術方針 2.14 / R1）。

### 層をまたぐ契約の固定

- U17（カメラ変換・ビューポート）・U10（候補問い合わせ）・U08（末端/集約区別・派生形状解決）・U09（リング種別・階層）・U16（評価済み状態・時刻）から受け取る型・構造を型で明示し、偶然の構造一致に頼らない（教訓 5.33 / 5.34）。依存未確定の段階はアダプタ境界を切り、接続時に両側テストで固定する。
- 重なり順（ベースマップ→グリッド→面→線→点→ラベル→ハンドル等、本ユニットは面・線・点・ラベルを担当）は、グリッド／ベースマップ／ハンドル描画ユニットと描画順の契約を明示して固定する（教訓 5.14 の「重なる UI は入力層も同時に設計」を描画順・ヒットテスト順に適用）。

## 受け入れ基準（テスト可能な形で列挙）

各基準は、可能な限り純粋関数の Vitest 単体テスト（描画コマンド列・ラベル可否判定・LOD 判定・視野交差判定）または計測ハーネス／Playwright for Electron の E2E で検証する。Canvas 実描画に依存する確認は、描画コマンド列（何をどのスタイルで描くかの中間表現）を対象に検証することで副作用なくテストする（教訓 5.41）。

1. **選択時刻に基づく全地物の描画と時間変更での即時更新（FR-71）**
   - ある選択時刻の評価済み状態を与えると、その時刻に存在する全地物（点・線・面）が描画コマンド列に現れ、存在しない地物（非存在期間の地物）は現れない。
   - 選択時刻を別の時刻へ変更し評価済み状態を差し替えると、新しい時刻の形状・属性・存在の有無を反映した描画コマンド列へ更新される（形状変化・存在の出現／消滅・属性変化の各ケースを個別に固定する）。
   - 時刻変更通知を受けてから再描画が走ることを、再描画トリガの呼び出しで検証する。

2. **穴は常に透過・飛び地は本土同様に独立描画（FR-21）**
   - 穴リングを持つ末端面の描画コマンド列で、穴リングに塗りが乗らず（透過）、領土部分のみが塗られる。
   - 飛び地を持つ末端面で、飛び地が本土の領土リングと同一スタイル（同一塗り色・境界色）で独立した領域として描かれ、連結線が描かれない。
   - 選択ハイライト（アクティブ地物）状態でも、穴は透過のまま・飛び地は本土同様のまま描かれ、恒常表示と穴／飛び地の輪郭・塗り分けが変わらない（一時的視覚効果でも規則が変わらないことを固定する）。
   - 穴の中の飛び地（ネスト）でも、領土→穴→領土の交互規則どおりに塗り・くり抜きが適用される。

3. **集約地物の派生形状を単一解決判定で描画（FR-42 / 教訓 5.29）**
   - 集約地物を、U08 の派生形状解決判定が返した形状（下位領域の和）で描画する。下位領域が飛び地的に分離して和が複数片になる場合も、全片が描画コマンド列に現れる（片落とししない・教訓 5.1）。
   - 描画に使う形状・ヒットテストに使う形状・ラベル位置算出に使う形状が、同一の解決判定結果に由来することをテストで固定する（描画形状とヒットテスト形状の不一致を回帰として防ぐ・教訓 5.29）。
   - 階層深度フォーカス（FR-42）で「階層深度≤N」に集約表示する状態を与えると、省略階層の地物が派生形状（下位領域の和）として描かれ、N より浅い地物は実形状で描かれる選別が、依存ユニットの解決結果どおりになる。

4. **種別ごとの条件でラベルを描画・面はリングごと（FR-86 / FR-17）**
   - 点情報のラベルが、設定の最小ズーム倍率未満では描かれず、以上で描かれる（境界値を含めて固定）。
   - 線情報のラベルが、可視長（スクリーン投影長）が閾値未満では描かれず、以上で描かれる。
   - 面情報のラベルが、リング（外周・各飛び地）ごとに画面占有率閾値（設定値）で表示可否判定され、閾値以上のリングにのみ描かれる。1 つの面情報の外周と飛び地で占有率が異なる場合、占有率が閾値以上のリングだけにラベルが付く（リング単位描画）。
   - ラベルのフォントサイズ・点サイズ・線幅が、ズームレベルを変えても画面上一定サイズになる（異なるズームで同一のスクリーンサイズが算出される・FR-17）。

5. **視野外クリッピング＋LOD＋バッチで 5,000 オブジェクト規模 60FPS の計測がある（NFR 5.1 / 5.2）**
   - 5,000 オブジェクト（平均 10 錨）規模の合成データで、パン・ズーム時の FPS を記録する計測ハーネスが存在する。
   - 視野外クリッピングにより、ビューポート外の地物が描画対象から除外されることを、描画対象集合（クリッピング後の候補）の検証で固定する。世界端ラップ展開でビューポートにまたいで入る地物は描画対象に含まれる。
   - LOD ON/OFF・クリッピング ON/OFF で描画コスト（描画コマンド数・実行時間）が変化することを計測で示す。
   - スロットリングにより、フレーム内の連続イベント（パン中の多数の mousemove 相当）に対して 1 フレーム 1 描画に集約されることを、再描画呼び出し回数のカウントで固定する。

6. **回帰・非機能**
   - 描画コマンド列生成・ラベル可否判定・LOD 判定・視野交差判定の純粋関数部分が副作用を持たず、同一入力に同一出力を返す（純粋性）。入力の評価済み状態を破壊的に変更しない。
   - 描画状態を React state に持たず、Zustand 購読＋命令的 Canvas で駆動していることを設計上の不変として保つ（再レンダリング起因の描画破綻がないこと・技術方針 2.3）。
   - サイズ系（点サイズ・線幅・フォントサイズ）の算出が単一実装に集約され、点・線・面ラベルで一致した基準値を使う（教訓 5.30 / 単一の真実源）。

## 関連要件（FR-id）

- **FR-17**（should）: 点の大きさ・線の太さ・名前ラベルは、ズームレベルに関わらず画面上の見た目サイズが一定になるよう調整する。本ユニットがスクリーン座標基準のサイズ固定で実現する。
- **FR-21**（must）: 飛び地は人工線で繋がず分離描画し、全レベルの面情報で飛び地をサポート。選択・ハイライト等の一時的視覚効果でも穴は常に透過、飛び地は本土同様の独立領域として表示し、恒常表示と異なる輪郭・塗り分けをしない。本ユニットの面描画規則が直接支える。
- **FR-71**（must）: 時間変更操作に応じて、メインマップ上の全地物の状態（形状・属性・存在の有無）を、選択時間における有効な錨に基づいて即時更新する。本ユニットが「評価済み状態の差し替え→即時再描画」で実現する。
- **FR-86**（should）: 地物ラベルを種別ごとの条件で描画する（点=最小ズーム倍率、線=可視長、面=リングごと画面占有率）。本ユニットのラベル描画判定が直接支える。

関連して本ユニットが土台／前提として関わる（直接の達成責務は依存ユニット側にある）要件: FR-18 / FR-19 / FR-20（点・線・面の表示）、FR-42（階層深度フォーカスの集約表示の描画反映）、FR-82（選択状態の視覚的フィードバックの描画）、FR-100 / FR-101（与えられたスタイル・配色結果での描画、穴透過の一貫）、FR-109（面情報ラベル画面占有率閾値の設定値消費）、FR-110（描画更新頻度の設定値消費）、NFR 5.1 / 5.2（性能・規模）。

## 注意点・既知の落とし穴（開発ガイドの教訓を踏まえる）

- **教訓 5.29「派生形状は単一の解決判定で全経路を動かす」** — 適用: 集約地物の描画形状を本ユニットで独自算出せず、U08 の単一の形状解決判定から取得する。描画・ヒットテスト・ラベル位置算出をすべて同じ解決結果で動かし、判定条件のドリフトによる「描画されるのに選択できない」「ラベル位置が描画とずれる」矛盾を防ぐ。受け入れ基準 3 で描画形状とヒットテスト形状が同一由来であることを固定する。

- **教訓 5.25「仕様が限定した対象範囲を実装で広げない」** — 適用: FR-21 は「穴は常に透過・飛び地は本土同様で、恒常表示と異なる輪郭・塗り分けをしない」と明示している。選択ハイライト時に「分かりやすさのため飛び地だけ別色にする」「穴の縁を強調する」等の直感的拡張を加えない。一時的視覚効果でも穴透過・飛び地独立の規則を恒常表示と共有することを受け入れ基準 2 で固定する。

- **教訓 5.1「集合演算は複数片を返す前提で扱う」** — 適用: 集約地物の派生形状（下位領域の和）は飛び地的に複数片・複数リングになりうる。U08 から受け取った全片を描画し、配列の先頭片だけ描く片落としをしない。受け入れ基準 3 で複数片の全描画を固定する。

- **教訓 5.30「過少共有と過剰共有の両方を戒める」/ 単一の真実源** — 適用: 点サイズ・線幅・ラベルフォントサイズのズーム非依存サイズ算出（FR-17）は単一実装を共有する（過少共有の戒め）。一方、ラベル表示可否の判定条件は種別ごとに本質的に異なる（点=ズーム倍率、線=可視長、面=リング占有率・FR-86）ため、安易に単一述語へ統合しない（過剰共有の戒め）。サイズ算出は共有、可否判定は種別別に分けることを受け入れ基準 4・6 で固定する。

- **世界端ラップの落とし穴（技術方針 R3）** — 注意: 経度を単純剰余すると世界端をまたぐ線・面が分断され、東端・西端で見えるべき地物が描かれない／二重に描かれる。経度は連続スカラーで保持し、U05（U10 経由）のラップ展開済み座標で描き、視野クリッピングの問い合わせにもラップ複製を含める。受け入れ基準 1（線の連続描画）・5（またいで入る地物の描画対象化）で固定する。

- **教訓 5.5「依存する状態は変化時に再検証する」** — 適用: 選択時刻・カメラ・評価済み状態・スタイル・階層深度フォーカスのいずれが変わっても、それに依存する描画を再生成する。時刻だけ変えて形状再評価を忘れる、カメラだけ変えてラベル可否（占有率・可視長はカメラ依存）を再判定し忘れる、といった取りこぼしを避ける。受け入れ基準 1・4 で時刻変更・ズーム変更それぞれの再描画を固定する。

- **教訓 5.3「操作対象は表示状態に限定する」** — 適用: 描画対象は「選択時刻に存在しビューポートに入る地物」という表示状態に限定し、データソース全件を毎フレーム走査しない。視野クリッピング（U10 問い合わせ）を経由する。受け入れ基準 5 で描画対象がクリッピング後集合に限られることを固定する。

- **React 再レンダリングによる 60FPS 破綻（技術方針 2.3）** — 注意: 描画状態を React state に持たせると、パン・ズームのたびに再レンダリングが走り 60FPS が破綻する。描画は Zustand 購読＋命令的 Canvas に閉じ、`requestAnimationFrame` の単一ループへ集約する。受け入れ基準 6 で「React state に描画状態を持たない」設計不変を保つ。

- **スロットリングの二重適用・取りこぼし（教訓 5.16 の精神）** — 注意: 高頻度イベントごとに即描画すると 60FPS を超えて無駄描画になり、逆に間引きが強すぎると時刻変更の即時更新（FR-71）が遅延する。再描画は「要求フラグ→次フレームで 1 回描画」に一元化し、間引きの単位を一箇所に決める（二重適用しない）。時刻変更は確実に次フレームで反映されることを受け入れ基準 1・5 で固定する。

- **LOD 簡略化が正しさを壊す** — 注意: 遠景での頂点間引き・面省略が、穴の透過・飛び地の独立・派生形状の被覆を壊してはならない（FR-21 / FR-42）。簡略化は見た目の正しさを保てる範囲に限定し、簡略化 ON でも穴透過・飛び地独立が維持されることを受け入れ基準 2 のバリエーションで確認する。

- **層をまたぐ契約（教訓 5.33 / 5.34）** — 適用: U17・U10・U08・U09・U16 から受け取る型（カメラ変換・ビューポート矩形・候補集合・末端/集約区別・派生形状・リング種別・評価済み状態・選択時刻）を型で明示し、偶然の構造一致に頼らない。依存未確定段階はアダプタ境界を切り、接続時に両側テストで固定する。描画順・ヒットテスト順の契約も、グリッド／ベースマップ／ハンドル描画ユニットと明示的に固定する（教訓 5.14）。

- **テスト容易性のための純粋分離（教訓 5.41 / NFR 5.8）** — 注意: Canvas 実描画は E2E でしか観測しづらい。描画コマンド列（中間表現）・ラベル可否・LOD レベル・視野交差判定を純粋関数として切り出し、Vitest 単体で検証できるようにして、実描画への委譲層を薄く保つ。検証不能な実描画部分は計測ハーネス／E2E で補う。

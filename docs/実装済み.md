## 2026-09-04 UI 再設計 増分 2 の手直し（4 本の検証への対応）

増分 2 に対する 4 本の検証（設計適合・コード反証・外部審査 GPT・実データの探索的バグ狩り）が
すべて「要修正」となったので、指摘を A〜H の 8 群に分けて手直しした。中核（見ている年に保存が
効く・行き先を押す前に見せる・まとめ役の子でも歴史が読める）は 4 本とも実機で動作確認済みで、
作り直しではない。詳細は `docs/ui-redesign/進捗/増分2.md` §11。

- **保存の意味論**（A 群）。**保存した属性を、次にその属性が本当に変わる錨まで前へ引き継ぐ**
  ようにした。錨は「その時点の全体の写し」なので、まとめ役の下では兄弟を直した年の錨が旧名の
  写しを持ち、1000 年で改名しても 2000 年で元に戻っていた。書き換えた錨が何本あっても
  1 回の押下＝1 つの取り消し単位で、効く範囲は押す前に文字で見せる。あわせて、存続期間で
  開始を動かした錨と同じ年に新設すると錨 ID が衝突して片方が黙って消えていたのを直し、
  月日から始まる錨を選んでいるときは粒度を問わず上書きできるようにし、打ちかけの確認を
  素性欄の枝の外へ出して選択が外れる経路でも描くようにし、Ctrl+K が鍵盤から黙って終わる
  経路に理由を出し、値が変わっていない保存を押せなくし、飾りの開始年／終了年を保存の対象から
  外して読み取り専用にした。
- **記録の差分**（B 群）。錨表の差分を **保存の対象と同じ広さ**（名前・種別ラベル・見た目・
  詳細文書）＋親＋形で見比べるようにした。見た目だけ・詳細文書だけを直して作った錨が子の
  錨表から消え、行の文が「変化はありません」と嘘をついていた。「前の錨」の決め方を 1 か所に
  まとめ、「続く」行を親の系列そのものから出して穴を隠さないようにした。
- **錨表の操作性**（C 群）。選ばれている錨の行まで自動で送り、矢印キー・Home・End で
  仮想スクロールの窓の外にも到達できるようにした。
- **見た目**（D 群）。素性欄に常時出ていた横スクロールを消し（犯人は fieldset の既定
  `min-inline-size`）、節（見た目・歴史の錨・詳細文書）を畳めるようにした。
- **時間バー**（E 群）。素性欄の時間バー表示の切替を外した（裁定 §N-8 の推奨 (A)）。部品は
  増分 6 で流用するので残し、バーの右端を「次の錨の始まり」で切る誤りは直した。
- **読み込みの整合チェック**（F 群）。形が同じ時刻断面では幾何の検査を使い回すようにした。
  異なる時刻 51 で **64.5 秒 → 1.75 秒**。
- **実測と裁定材料**（G 群）。`scripts/measure-anchor-growth.ts` を「年が揃う／年がばらける」の
  2 筋書き・ウォームアップと複数回の中央値・manifest と `.gimoza` の分離・start と end の
  両境界での年の数え直し・cold/warm の分離へ作り直し、実測し直した。設計書 §N-13 の裁定材料を
  実測で書き直し、画面の費用表示を **実ファイル基準**（デーレ共和国の錨 1 本で約 60 KB）に直した。
- **文書**（H 群）。要件定義書 FR-84 を新しい契約（編集時刻＝現在選択時刻）へ書き換え、
  技術方針 §6.4 から「存続期間だけは即時」の規則化を外し、`docs/ui-redesign/README.md` に
  裁定一覧（所有者の裁定と、推奨で先行しているもの）を作った。

## 2026-09-04 UI 再設計 増分 1 の手直し（4 本の検証への対応）

増分 1 に対する 4 本の検証（設計適合・コード反証・外部審査・実データの探索的バグ狩り）が
すべて「要修正」となったので、指摘を A〜G の 7 群に分けて手直しした。作り直しではない。
詳細は `docs/ui-redesign/進捗/増分1.md` §10。

- **保存の安全**（最優先）。上書き確認を排他にし、確認中は 開く・新規・ドラッグ＆ドロップ・
  もう一度の保存・自動保存を止める（確認したファイルと実際に書かれるファイルが入れ替わり
  得た）。確認から戻ったら保存先の同一性を検査する。未保存警告の「保存して続行」も
  上書き確認を通し、本文に保存先を出す。**自動保存は上書き先を確認するまで本体ファイルに
  書かない**（変更が無いときも書かない／成功しても「直前の結果」を書き替えない）。保存の
  戻りを真偽値から結末の種別へ広げ、「やめた」を失敗として出すのをやめ、書き込み失敗の
  二重通知（状態行と OS の警告ボックス）をやめた。
- **削除の確認を 3 経路で 1 つにした**。Delete キーと右クリックの「削除」は確認なしで
  即座に消していた。所有者の裁定「消す前に何が起きるかを必ず見せる」に合わせる。
- **「読むだけ」の抜け道を塞いだ**。設定ダイアログのプロジェクト設定・パレット・背景地図の
  差し替え・タイムライン範囲・上部バーのグリッドトグルが、読むだけでも書き換えられた。
- **寸法の 2 つの症状を根で断った**。未保存の印が付いた瞬間に地図が 34px 飛ぶ（素性表示の
  幅が中身で変わっていた）／「プロパティ」タブで画面全体が 0.8px 左へずれる（主行の列が
  `1fr` で、セルの `min-width` が窓幅を超えさせていた）。
- **状態行に全編集経路の結果を流した**。`Command.label` の語彙の混在は、画面へ出す直前の
  写像表 1 か所で解く。診断ログを購読できるようにし、作中時刻の `[object Object]` を直した。
- **E2E の運用**。露出の検査をヘッドレスで走らせる第 3 の旗を足し、保存の成功経路を
  実データ抜きで固定できるようにした。

## 2026-09-03 UI 再設計の下準備（E2E ヘルパー一本化・testid 化・実データ投入口）

UI の全面再設計（`docs/ui-redesign/`）に先立ち、再設計の結果に依存しない準備を 3 つ入れた。アプリの見た目・挙動は変えていない。

- **「面を 1 つ描いて保存する」手順を `e2e/helpers.ts` へ一本化した**。これまで `commitOneFace` を使う spec は 14 本で、残り 28 本が同じ手順（表示専用を抜ける → 追加モード → 面ツール → 頂点クリック → 完了 → 保存 → 選択の再解決を待つ）を直書きしていた。helpers に冪等なモード切替（`leaveViewMode` / `enterAddMode` / `enterEditMode` / `returnToViewMode`）と、面を描く部品（`armAddAreaTool` / `placeVertices` / `drawFace` / `commitFace` / `commitSquareFace` / `commitOneFace`。座標・頂点数・上位領域・名前は引数）を置き、28 本すべてを置き換えた。検証内容と座標は変えていない。探索用の spec が持つ「異常を記録して続行する」版は意味を保つため関数を残し、構える・頂点を打つ部分だけ helpers を使う（残りは現状.md B6）。追加ツールの導線を作り直したとき、直す場所は helpers の 1 箇所になる。
- **E2E がスタイル用のクラス名で要素を探していた 12 箇所を `data-testid` に切り替えた**。src 側は属性を足しただけ（`toolbar-modes` / `tooltip` / `tooltip-bubble` / `timeline-ticks-unit` / `timeline-tick-label` / `anchor-interval-summary-*` / `conflict-row-features` / `policy-choice-option` / `context-menu-item`）。既存の testid は改名していない。メニューのショートカット表示は既存の `menu-accel-*` を使った。撤去済みの時刻ブックマーク UI に対するクラス名での「無いこと」確認は、同趣旨の testid 側の確認が既にあるので落とした。
- **E2E 専用の実データ投入口を足した**。`E2E_TEST=1` で起動したときだけ、レンダラに `window.__E2E_HARNESS__.loadProject(絶対パス)` が生える。経路は D&D と同じ `dropLoadCommand`（未保存ガード → 読込 → 修復判定 → reflect → 保存先の昇格）なので、メニューの「開く」と同じ流れを通る。仕組みは 3 層: main が E2E のときだけ preload の引数に旗を積み（`webPreferences.additionalArguments`）、preload は旗があるときだけ印 `window.timeMapE2E` を公開し、`FileOpsController` はその印があるときだけ登録簿（`src/ui/e2e/harness.ts`）へ登録する。旗と公開名は `src/shell/ipc/e2e-harness.ts` の 1 箇所で決め、両側の単体テストで固定した。本番相当の起動（`E2E_TEST` 未設定）で何も露出しないことは実機で確かめた。IPC の契約（チャネル）は変えていない。
    - 起動引数 `--open-file` ではなく関数にしたのは、テストの途中で何度でも読み込めること、読み込みの完了（reflect まで）を戻り値で待てること、IPC 契約に手を入れずに済むことによる。`window.__E2E__` に同居させなかった理由は現状.md B5。
    - helpers に `loadProject(page, path)` / `launchAppWithProject(path)` を足し、実データを読み込む最初の spec（`e2e/real-data.spec.ts`）を置いた。正準ファイルは一時ディレクトリへコピーしてから開き（開発ガイド §5.48）、地物一覧の件数と、一覧から選んでプロパティが出ることを確かめる。実データが無い環境では skip（置き場は既存のベンチと同じ `DERLE_TMAP_DIR`。未設定ならリポジトリ直下の `derle-import/`）。
- 併せて、直前の「利用者に見える名前を gimoza に統一」がビルドに反映されることを実機で確かめた: スモーク起動が通る、E2E で `page.title()` が `gimoza`、一時 userData を渡さない起動で `app.getPath('userData')` が従来の `%APPDATA%\time-map-app-4` のままで `%APPDATA%\gimoza` が作られない。

## 2026-09-03 利用者に見える名前を gimoza に統一（残件）

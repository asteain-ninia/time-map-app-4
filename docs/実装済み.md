## 2026-09-06 UI 再設計 増分 5 の手直し（5 本の検証への対応）

設計適合・コード反証・実データのバグ狩り・外部審査 2 本の計 5 本が「要修正」を出したので、
指摘を 7 つの群（A〜G）に分けて片付けた。作り直しではない ―― 中核（固定行・再マウント無し・
K-2・鍵の関門・読むだけの地図クリック・道具を持ち替えても選択が残る・全件ゲート）は実機で
成立していた。詳細と対応表は `docs/ui-redesign/進捗/増分5.md` §12。

**所有者の裁定と司令塔の決定**（所有者は覆せる）:

- 裁定: モード排他は崩す（鍵＋道具 1 段）／読むだけでも地図クリックで**選べる・読める・
  直せない**／道具を持ち替えても選択を捨てない／表示条件を変えても選択は外さない。
- 決定 (1) **鍵はアプリバーの右端 96px の固定枠へ戻す**（左レールから外す。レールの縦あふれと
  鍵の文字欠けの根だった）。(2) 地図内のズーム・縮尺・頂点の候補一覧は**増分 6 で置く**。
  (3) 手順のある 5 道具の **Esc の階段は今回揃える**。(4) 測る（測量）は別の軸のまま残すが
  **オプションバーを使う**。(5) ナイフ・穴あけの新地物の素性入力は、追加の道具と同じ
  **右パネルの「新規の姿」**へ。

**A 入力の持ち主と下書きの保護**

- **作図中の右クリックが下書きを壊し視点を飛ばす**のを直した（実データで再現。重症度 4）。
  右クリックは**メニューを開くが選択は変えない** ―― 昇格が背後の地物を選び、それを見張って
  いた追加の道具が下書きごと捨てていた。判定は「畳んだ持ち主」ではなく **生の「下書きを
  持っているか」**を見る（素性入力中は持ち主が `text` になって下書きが隠れるため）。
- **素性を入力している局面で Escape が誰にも受けられていなかった**のを直した。道具側は
  「文字の欄なら素通り」で降り、大域側は焦点の関門で落ちていた。いまは Escape だけ道具が
  受け、打ちかけのある欄では 1 度確認する。**利用者自身の Escape で出ている確認は、
  もう一度の Escape で「捨てる」**にした（旧版は「このままにする」だったので、押すたびに
  板が開いては閉じるだけで永久に素の状態へ戻れなかった）。
- **道具の持ち替えと鍵の開け閉めでも、確定できる打ちかけは黙って捨てない**。年・一覧の
  選択と同じ形で確認を出し、「このままにする」で道具（鍵）が元へ戻る。
- **鍵盤の持ち主の穴を塞いだ**: 吸着 ▾ を共通の器へ載せ替えて開閉を報せる／標準メニューの
  開閉を報せ、Escape を捕捉段で受ける／結合の選択板・継承先の板・新地物の素性入力・
  捨てる前の確認を**「下書き」ではなく「モーダル」**として数える／つまみ
  （`input[type=range]`）に焦点があるあいだ大域の打鍵を止め、Escape で抜けられるようにする／
  「まだ誰も持っていない」を地図が載る前に出す／板が開いていて打鍵が止まったときは
  **その板を閉じる**という次の一手つきで理由を出す。
- **測量を入り切りすると内部の状態が壊れる**のを直した（画面は「選ぶ」なのに内部は「追加」）。
  `activeTool` を書くところは `mode` の導出と必ず一組にした。
- **読むだけでは頂点・辺中点を掴ませない**（描く条件と掴める条件を同じ入力で決める）。
  見えていない頂点が選ばれず、Escape の階段も 1 段増えない。
- **頂点の選択を捨てる条件**を「直前が頂点の道具だったか」から「**掴める道具から出るか**」へ。
  「選ぶ」「動かす」で掴んだ頂点が、ナイフや追加の道具へ持ち越されなくなった。
- **クリックかドラッグかを、離した位置でも測り直す**（移動の見本が 1 つも届かない押下が
  クリック扱いになっていた）。

**C オプションバーの所有権と対象欄**

- **手順の道具を後ろ→前に持ち替えると次の一手が消える**のを直した。「降りたら空へ」を
  **後片付け関数**へ移すと、React が「全部の後片付け → 全部の押し込み」の順に走らせるので、
  木の位置に依らず正しい順になる。
- **読むだけでも選んでいる地物の名前を対象欄に出す**（裁定の「読める」の前半）。
  ナイフ・輪郭・穴あけは**自前の対象を持つ道具**に分類し、掴んでいない地物の名前を出さない。
- **測るがオプションバーを使う**（道具名「📏 測る」・対象・次の一手・確定欄［測量を終える］）。
  レールの表記も「測量モード」から「📏 測る」へ（画面から「モード」の語を落とす）。
- 常設の設定部品が毎レンダー登録し直されるのをやめた（報せ口を id ごとに使い回す）。

**B 手順のある 5 道具の Esc の階段と確定**（司令塔の決定 (3)(5)）

- **Escape を 1 段ずつにした**（設計書 §D.4.1）。5 道具とも Escape 1 回で「手順の対象」
  「元からの選択」「道具」の三段をまとめて捨てており、結ぶ・所属変更では **道具が掴んだ
  のではない元からの選択**まで消えていた。いまは「下書きの点列をまとめて捨てる →
  対象を離す（道具は持ったまま）→ 頂点 → 地物 → 道具を降りる」の 1 段ずつで、
  対象も下書きも無いときは大域の階段へ譲る。
- **確定後のふるまいを揃えた**。ナイフだけが確定後に道具を降りていた（続けて分けたい人は
  毎回選び直すことになる）。5 道具とも道具を持ったまま次の対象待ちへ戻る。
- **案内・断り・確定を全部オプションバーへ**。ナイフの拒否板が地図クリックを奪っていたのと、
  所属変更の案内が地図上端の黒帯と二重に出ていたのを直した。「手順 n/m」を対象欄へ。
- **［最上位へ（所属を外す）］に確認を入れた**（押した瞬間に確定していた）。
- **ナイフ・穴あけの新地物の素性入力を右パネルの「新規の姿」へ移した**（司令塔の決定 (5)）。
  地図の中央の板を消し、追加の道具と同じ口で受ける。同じ作業に置き場を 2 通り持たない。

**D シェルの寸法と畳み**

- **鍵をアプリバー右端の 96px 枠へ戻し、レールは道具 12 個だけ**にした。ボタンを枠込み
  32px・字送り 12px に詰め、1280×800 と 1366×768 で**縦スクロールバーが出ず、文字も
  切れない**ことを機械検査で固定した。**800×600 では収まらない**ので、その窓だけ縦に
  送れる形にしてある（`docs/現状.md` B17 に残作業として書いた）。
- **設定欄の畳み「≫」**を実装した（入り切らない部品をポップオーバーへ送る）。判定は実測で、
  測れないとき（レイアウトを持たない環境）は全部そのまま出す。検査は「設定欄の各部品の
  矩形が設定欄の矩形に収まる」を 800〜1920 の 5 段で見る（親の `scrollWidth` では捕まらない）。

**E 文言・案内・状態行**

- 読むだけの案内文が**もう無いボタン**（「編集モードに切り替えてください」）を指していたのを、
  鍵のラベルに揃えた。メニュー・右クリック・吹き出しに割れていた 3 つの名前を
  **「読むだけ ⇄ 直せる」**の 1 つにした。使われなくなったモードの語の表は消した。
- 輪郭（穴・飛び地）の確定が「素性の変更を行いました」と出ていたのを、**追加か削除かを
  形から判定して**「穴・飛び地の追加／削除」と出すようにした。
- **読むだけの Ctrl+K が「0 年にはすでに錨があります」と答えていた**のを、「読むだけだから」
  を先に答えるようにした（鍵 1 つで解ける理由を先に見せる）。
- **作業のまとまり（束）の名札**を出した（「3 / 220」しか出ておらず、何のまとまりを順に
  片付けているのか分からなかった）。
- **何も選んでいない右クリックが項目 1 個の板になる**のをやめ、地物に依らない「見る」側の
  項目（全体表示・拡大・縮小・鍵）を常に並べるようにした。

**F テスト**

- **K-2 の走査を設計書 §B.5 の台帳を回す表に一般化した**（入力ブリッジ 9 通り・
  ポップオーバー 4 枚・一時の板）。旧版は道具 4 つとポップオーバー 2 枚の手書きで、
  **台帳へ足した部品が検査に入らないまま増える**形だった（K-2 の 3 回目の事故がその形）。
- **再マウントの検査を要素の同一性（印）で見る**ようにした。カメラの値は外の店に居るので、
  地図セルが作り直されても同じ値を復元でき、**検査は緑のまま**だった。
- 読むだけの表に 3 行を足し、道具一覧のベタ書き 3 か所を実装から引く 1 本へ寄せ、
  「持ち替えで選択が残る」を 12 道具全部で回すようにした。視覚回帰は最終コードで
  撮り直した（教訓 §5.63）。

**手直しの途中で見つけて直したもの**: 設定欄の畳みが (a) 一度畳むと戻らない
（見張る先に下限があって幅が動かない）(b) 畳むほど器が縮んでもっと畳む（自分の幅を
測っていた）(c) 幅 0 の部品が 1 つあると 1 度も働かない、の 3 つ。**Escape で出した確認を
Escape で閉じると輪になる**（連打で素の状態へ戻れない）。**道具を持ち替えたときの確認が、
アプリ自身の再武装まで止めて重なり競合の板を地図に居座らせる**。教訓は開発ガイド
§5.69 / §5.70。

## 2026-09-06 UI 再設計 増分 5「器の入れ替え」（固定行のシェル・鍵と道具 1 段・選択を捨てない）

`docs/ui-redesign/03-実装計画.md` §5 の 4 コミット（5a〜5d）。**8 増分のうち、いちばん広く
壊す増分**である。詳細と受け入れ条件の充足は `docs/ui-redesign/進捗/増分5.md`。

- **5a 固定行のシェル**: アプリバー 32 / オプションバー 40 / 主行 残り / 時刻レール 据え置き /
  状態行 28 の**固定高**にし、`flex-wrap: nowrap` に統一した。入り切らないものは**窓幅だけで
  決まる畳み**で落ちる（設計書 §B.4）。アプリバーを 32px に収めるため、深さ（＋個別フォーカスの
  4 部品）・格子・測量の読み取りをオプションバーの設定欄へ降ろした。**測量を ON にしても地図が
  縮まない**（それまでは 87〜95px 縮んでいた）。ポップオーバーの器を 1 つ（`shell/OptionPopover`）
  に寄せ、「表示 ▾」もそこを通した。
- **5b 鍵と道具 1 段**（裁定 1）: モードの 3 ボタンを廃し、**鍵 1 個＋道具の 1 段**にした。
  内部の `mode` は道具から導出する（`mode = 鍵が閉 ? view : 面／線／点 ? add : edit`）ので、
  `canEdit` も `app-mode` も `aria-pressed` もそのまま生きている。**面を描くまでが 2 手から
  1 手**になった。あわせて **裁定 N-4(A)** を実装 ―― 読むだけでも地図クリックで選べ、
  Escape で外せる（HB5-4 を覆した）。左のレールは 120 → 88px。
- **5c 選択を捨てない・鍵盤の持ち主・Esc の階段**: `setActiveTool` の既定を反転し、道具を
  持ち替えても選択が消えないようにした（現状 B28）。`shortcutsSuspended` の 11 項目の OR を
  `focusOwner` の 6 値へ畳み、**手順のある道具は「下書きを持っている」ときだけ鍵盤を取る**
  形にした（**所属変更の確定直後の Ctrl+Z が効く**）。右クリックはダイアログのときだけ止まる。
  Escape は「頂点 → 地物 → 道具」の 1 段ずつになった。
- **5d 確定の列をオプションバーへ**: ナイフ・結合・所属変更・輪郭・穴あけの確定／やめる／
  1 つ戻すを、地図の下端中央からオプションバーの確定欄 176px へ移した（U-10 は守り、位置だけ
  移す＝E-2 / N-27）。**地図に重なる押せる部品は道具の入力ブリッジ 1 枚だけ**になり、K-2 の
  事故が構造的に起こり得なくなった。5×5 の格子走査で機械検査している。

## 2026-09-06 E2E / スモークのウィンドウを表示しないようにした（PC のフォーカスを奪わない）

E2E を回すと Electron のウィンドウが次々と前面へ出て、**テストのあいだ PC で他の作業が
できなかった**（所有者の困りごと）。描画はもともとオフスクリーンなのに、`ready-to-show` で
**無条件に** `show()` を呼んでいたのが原因。詳細は `docs/技術方針.md` §2.14、教訓は
開発ガイド §5.66。

- **旗（`E2E_TEST` / `SMOKE_TEST` / `E2E_OFFSCREEN`）が立っているときは `show()` を呼ばない**
  ようにした。`show: false` のままなので画面に出ず、フォーカスも奪わない。判定は Electron を
  import しない純粋関数（`src/shell/main/headless-window.ts`）に置き、**オフスクリーンで描くか
  どうかの判定と同じ 1 か所**から読む（条件が 2 つに割れて片方だけ直る事故を防ぐ）。単体テストで
  「旗ありなら出さない・旗なしなら出す」を固定した。
- **本番の挙動は変えていない。** 旗が無ければ従来どおり `ready-to-show` で `show()` する。
- **「奪っていない」を数で確かめた。** 旗が立っているあいだはウィンドウを前面に出さない、を
  目で見て言うのではなく、**前面のウィンドウが何のプロセスかを一定間隔で記録して数える**形で
  確かめた（検出手段は開発ガイド §5.66）。直す前は E2E を 1 周回すあいだに前面が何度も
  Electron へ移っていたが、直した後はスモークも探索も含めて**一度も移らない**。ウィンドウを
  出す仕事が消えたぶん、E2E の所要時間も短くなった。実測した回数と割合は開発ガイド §5.66 に
  検出手段の例として置いてある。

## 2026-09-06 UI 再設計 増分 4 の 2 回目の手直し

実データでもう一度使い倒し、Grok の文書審査（判定 revise）と突き合わせて出た 8 群を
片付けた。詳細は `docs/ui-redesign/進捗/増分4.md` §12。

- **錨の無い年で名前欄がマウスで押せなかったのを直した。** 素性欄の「見出し／保存列」を
  `position: sticky` で中身の上に**重ねる**作りをやめ、**重ねずに縦へ並べる 3 段**にした。
  1500 年では保存列が説明文＋ボタン 2 つで 103px に育ち、1280×800 でそのあいだの帯が
  20px しか残らず、26px の名前欄がどのスクロール位置でも押せなかった（0 年では帯が 58px
  あって押せていたので検査は全部すり抜けた）。3 段にしても本文の取り分が 0px になる窓が
  あったので、**本文に 1 行ぶんの下限**を入れ、入り切らないぶんは外の器のスクロールで
  届くようにした。教訓 5.61 に「重ねる作りそのものをやめる」を結論として書いた。
- **表示条件を変えても選択を外さなくなった**（利用者に見える変化）。これまでは種別を切る・
  👁 で隠すなどをした瞬間に、選んでいた地物の選択が外れて**素性欄が空になって**いた。
  設計書 §D.6 の「選んでいる地物は表示条件に関わらず必ず描く」と正面からぶつかっていた
  ので、必ず描く側を採った。**隠しても選んだままで、素性欄は読める**。隠れていることは
  一覧の 🚫 印と、地図に描かれ続けることと、状態行の知らせが伝える。掴めるハンドルは
  出ない（隠れているものは見るために描いているだけで、触るためではない）。
  **司令塔の決定で、所有者はいつでも覆せる**（戻し方は `docs/ui-redesign/README.md` B-2）。
- **隠れた行を選んだときに、視点が合って理由が出るようになった。** これまでは視点も動かず
  状態行も黙ったまま、地図には当人だけが描かれていた ―― 描いてあるのにどこに描いたかを
  教えない形だった。
- **名前欄に焦点が入ったままでも Ctrl+Z と束の送りが効くようになった。** 素性欄の Enter は
  「保存して次へ」なので、送ったあとは焦点が次の地物の名前欄にある。そこで押しても
  何も起きなかった。**打ちかけが無い欄でだけ**通す（打ちかけがあれば従来どおり止める）。
  Escape で焦点を一覧へ返せるようにもした。
- **一覧の中の入力欄で Home/End/矢印を押しても、打ちかけが消えなくなった。** 一覧の器が
  中の入力欄の鍵盤まで横取りしていた。束の送り（Alt+↑↓）が二重に効いて 1 回で 2 つ進む
  のも直した。
- **時間軸の範囲外の年を、黙って端へ丸めるのをやめた。** Ctrl+P では「（時間軸の範囲外。
  いまの時間軸は 0年〜10000年）」と出して押せなくし、直接ジャンプ欄では理由を出して断る。
- **点や線に「上位領域」が黙って付くのをやめた。** 実データに点を 1 つ足して保存し、
  開き直すと修復ダイアログ（形状保持規則の違反）が出ていた。「描いた形を含む面を上位領域の
  既定にする」規則が道具で絞られておらず、点は座標が 1 つなので陸地の上を押せば必ず親が
  付いた ―― 素性欄は面のときしか上位領域の欄を出さないので、**利用者は選んでも見てもいない
  親を付けられていた**。既に壊れたファイルは、開き直して修復の非破壊側（直轄領を作って
  集約化）を 1 回選べば整合する。
- そのほかの粗: 🚫 の吹き出しが「押すと戻せる」と嘘をついていた／やり直して通っても状態行に
  古い断りが残っていた／「未処理だけ」で件数の分母が総数のままだった／幽霊行があると
  「済 N 件」が消えた／**作業のまとまりを作っても未保存の印が立たず、そのまま閉じると
  警告も出ずに消えた**／その場改名が読むだけでもメニューと Ctrl+P に出ていた／増分 2〜4 で
  足したメニュー項目 6 つに説明文が無かった／打ちかけが blur で黙って消えていた／

## 2026-09-06 E2E を 2 系統に分け、並列で回すようにした

E2E は **1 テストにつき Electron を 1 つ起動する**作りで、直列（`workers: 1`）だと全件で
19 分かかっていた。所有者の裁定（2026-09-06）を受けて 2 点を直した。詳細は
`docs/技術方針.md` §2.14。

- **`main` と `explore` の 2 系統に分けた**（`playwright.config.ts` の `projects`）。
  `explore` は探索的なバグ狩りと見た目の記録（`e2e/__bughunt__/` と `e2e/__visual__/`）で、

  必ず回す**。コマンドは `npm run e2e`（main）/ `npm run e2e:explore` /
  `npm run e2e:all`。ビルド込みは `npm run test:e2e`（main）と `npm run test:e2e:all`。
  spec の中身は 1 行も変えていない。
- **ワーカーを複数使うようにした**（`workers: 6`）。`fullyParallel` は false のままなので
  **ファイル単位**の分配で、1 つのファイルの中の順序依存は保たれる。並列にできるのは
  テストどうしが資源を共有していないからで、その 4 点（ワーカーごとの userData ／

## 2026-09-03 利用者に見える名前を gimoza に統一（残件）

2026-08-15 に保存拡張子を `.gimoza` へ改めたとき、**画面に出る名前のほうが取り残されていた**。実機報告「ファイル読み込みに失敗したときのアラートのタイトルが `time-map-app-4` になる」がその露見。

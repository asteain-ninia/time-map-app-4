## 2026-09-03 UI 再設計の下準備（E2E ヘルパー一本化・testid 化・実データ投入口）

UI の全面再設計（`docs/ui-redesign/`）に先立ち、再設計の結果に依存しない準備を 3 つ入れた。アプリの見た目・挙動は変えていない。

- **「面を 1 つ描いて保存する」手順を `e2e/helpers.ts` へ一本化した**。これまで `commitOneFace` を使う spec は 14 本で、残り 28 本が同じ手順（表示専用を抜ける → 追加モード → 面ツール → 頂点クリック → 完了 → 保存 → 選択の再解決を待つ）を直書きしていた。helpers に冪等なモード切替（`leaveViewMode` / `enterAddMode` / `enterEditMode` / `returnToViewMode`）と、面を描く部品（`armAddAreaTool` / `placeVertices` / `drawFace` / `commitFace` / `commitSquareFace` / `commitOneFace`。座標・頂点数・上位領域・名前は引数）を置き、28 本すべてを置き換えた。検証内容と座標は変えていない。探索用の spec が持つ「異常を記録して続行する」版は意味を保つため関数を残し、構える・頂点を打つ部分だけ helpers を使う（残りは現状.md B6）。追加ツールの導線を作り直したとき、直す場所は helpers の 1 箇所になる。
- **E2E がスタイル用のクラス名で要素を探していた 12 箇所を `data-testid` に切り替えた**。src 側は属性を足しただけ（`toolbar-modes` / `tooltip` / `tooltip-bubble` / `timeline-ticks-unit` / `timeline-tick-label` / `anchor-interval-summary-*` / `conflict-row-features` / `policy-choice-option` / `context-menu-item`）。既存の testid は改名していない。メニューのショートカット表示は既存の `menu-accel-*` を使った。撤去済みの時刻ブックマーク UI に対するクラス名での「無いこと」確認は、同趣旨の testid 側の確認が既にあるので落とした。
- **E2E 専用の実データ投入口を足した**。`E2E_TEST=1` で起動したときだけ、レンダラに `window.__E2E_HARNESS__.loadProject(絶対パス)` が生える。経路は D&D と同じ `dropLoadCommand`（未保存ガード → 読込 → 修復判定 → reflect → 保存先の昇格）なので、メニューの「開く」と同じ流れを通る。仕組みは 3 層: main が E2E のときだけ preload の引数に旗を積み（`webPreferences.additionalArguments`）、preload は旗があるときだけ印 `window.timeMapE2E` を公開し、`FileOpsController` はその印があるときだけ登録簿（`src/ui/e2e/harness.ts`）へ登録する。旗と公開名は `src/shell/ipc/e2e-harness.ts` の 1 箇所で決め、両側の単体テストで固定した。本番相当の起動（`E2E_TEST` 未設定）で何も露出しないことは実機で確かめた。IPC の契約（チャネル）は変えていない。
    - 起動引数 `--open-file` ではなく関数にしたのは、テストの途中で何度でも読み込めること、読み込みの完了（reflect まで）を戻り値で待てること、IPC 契約に手を入れずに済むことによる。`window.__E2E__` に同居させなかった理由は現状.md B5。
    - helpers に `loadProject(page, path)` / `launchAppWithProject(path)` を足し、実データを読み込む最初の spec（`e2e/real-data.spec.ts`）を置いた。正準ファイルは一時ディレクトリへコピーしてから開き（開発ガイド §5.48）、地物一覧の件数と、一覧から選んでプロパティが出ることを確かめる。実データが無い環境では skip（置き場は既存のベンチと同じ `DERLE_TMAP_DIR`。未設定ならリポジトリ直下の `derle-import/`）。
- 併せて、直前の「利用者に見える名前を gimoza に統一」がビルドに反映されることを実機で確かめた: スモーク起動が通る、E2E で `page.title()` が `gimoza`、一時 userData を渡さない起動で `app.getPath('userData')` が従来の `%APPDATA%\time-map-app-4` のままで `%APPDATA%\gimoza` が作られない。

## 2026-09-03 利用者に見える名前を gimoza に統一（残件）

2026-08-15 に保存拡張子を `.gimoza` へ改めたとき、**画面に出る名前のほうが取り残されていた**。実機報告「ファイル読み込みに失敗したときのアラートのタイトルが `time-map-app-4` になる」がその露見。

- **ネイティブダイアログのタイトル**: レンダラの `alert()` が出すダイアログのタイトルには Electron が `app.getName()`（既定は package.json の `name` = 開発コードネーム）を使う。`src/shell/main/index.ts` の最初期（ready より前）で `app.setName('gimoza')` を呼ぶようにした。darwin のアプリメニュー（「◯◯について」「◯◯を終了」）も同じ名前を使うので同時に直る。
- **ウィンドウタイトル**（`src/ui/index.html` の `<title>`）と**バージョン情報のアプリ名**（`src/ui/shell/strings.ts` の `ABOUT_STRINGS.appName` / `APP_STRINGS.title`）も gimoza にした。ウィンドウタイトルの実体は `<title>` のほうで、`APP_STRINGS.title` は現在どこからも参照されていない（同じ名前が 2 箇所にある状態なので、その旨をコメントに残した）。
- **設定・診断ログの置き場（userData）は 1 バイトも動かしていない**。`app.getName()` を変えると `app.getPath('userData')` の既定も `%APPDATA%\time-map-app-4` から `%APPDATA%\gimoza` へ移り、FR-117 の診断ログや Electron 自身のキャッシュが別の場所になって「設定が消えた」ように見える。名前は表示だけの問題なのでデータを引っ越す理由がない。**改名の前に解決済みの userData を読み、改名の後に同じ値へ固定し直す**形にした（旧パスを直書きしないのは、E2E とスモークが `--user-data-dir` で渡してくる隔離先を壊さないため）。
- **package.json の `name` と `author` は据え置いた**（利用者には見えない内部識別子。`productName` を足さない理由も現状.md B3 と `src/shell/main/index.ts` のコメントに書いた）。内部識別子 `readTmap` 等と `SCHEMA_VERSION = 'tmap/1'` の据え置きも従来どおり。

## 2026-08-16 実データの取り込み経路を `derle-map-visualizer` へ一本化

アプリ本体のコードは変更していない。実データを作り直す手順と、その道具の置き場所の変更。

- **`derle-import/tools/` の変換一式を `../derle-map-visualizer` へ移した**。従来は「visualizer で抽出 → JSON → `build-tmap.mjs`（Node）で `.gimoza` へ変換」の 2 段構えで、同じ処理が 2 バージョンあった。visualizer 側だけで `.gimoza` を書き出せるようにして一本化した。移植の正しさは、同じ入力から出る `manifest.json` と背景資産が既存データとバイト単位で一致することで確認した。
- **`derle-import/` はデータ置き場になった**。元 SVG と `.gimoza` 本体、および出来上がった `.gimoza` を調べる補助（`diagnose-*.ts` ほか）だけが残る。作り直しかたは `derle-import/README.md` にある。
- **保存形式の制約が 1 つ判明した**: 読み込み側は経度を連続量へ戻すとき隣り合う頂点の差が 180 度を超えると ±360 度ずらすため、**1 辺で経度 180 度以上を渡る形は表現できない**。南極域の全周リングがこれに該当し、書き出し側で長い辺へ中間点を打つ対処を入れた（アプリ側は変更なし）。恒久的な表現限界なので、内容は技術方針.md §6.8 に置いた。
- **実データを作り直した**（`derle-import/derle-world-full-2026-08-16.gimoza` / `derle-world-2026-08-16.gimoza`）。実機で見つかった「島が国の領内に別地物として残る」不具合と、ラベルが隣の国に付く不具合を直したもの。誤って独立した地物になっていた島が親の領内へ収まったぶん、地物の数は従来より減っている。集約は 3 のまま。整合性チェックは不整合ゼロ、実データベンチも通過する。**従来のファイルは上書きしていない**（アプリで編集している可能性があるため、差し替えは利用者の判断に委ねる）。
    - 地物の数を比べるときは `node derle-import/tools/inspect-hierarchy.mjs <ファイル>` の出力を正とし、ここには書かない（§2.6）。同ツールは「履歴の数」と「地物の数」を別々に出す（集約の子は親のスナップショットにも入るため、id で畳んだ地物の数のほうが多くなる）。**どちらの数を見ているかを揃えずに比較しないこと。**

## 2026-08-09 デーレ界実データの取り込みと、そこで露見した描画・性能の欠陥

- **実データの再構築**: 旧開発機にしか無かったデーレ界の地図を本機で作り直し、`derle-import/` に配置した（フル版・間引き版とも整合性チェックは不整合ゼロ）。デーレ共和国・正統ノル王国・ラヴィエンド・ウィル同君王国を集約地物として階層を構成し、集約＝下位領域の和（FR-35）が実データで機能することを確認した。
- **頂点マーカー表示上限の意味を変更（FR-110）**: 「地物の総頂点数」で判定していたため巨大地物ほど編集できなくなる逆転が起きていた。「視野内に描くハンドル数」で数える方式に変え、拡大すれば巨大地物も編集できるようにした。
- **展開された集約地物が自分の領域を描き続けていた（FR-42）**: 集約は自前の形状を持たない（領域は下位領域の和）のに、展開後も親の形が子の真上に重なり、子へのクリックを全部吸っていた。自前形状を持たない集約が展開された場合のみ描画から外すよう修正。
- **性能**: 集約の形状キャッシュが未使用分を捨てていた問題（時刻移動 2,432ms → 51ms）と、下位領域の和を線形に畳み込んでいた問題（二分木状の合併へ変更、初回 2,323ms → 539ms）を解消。
- **ベクター背景地図（FR-03）**: 背景をラスター画像で持つ方式をやめ、SVG のパス定義を保存資産に入れて画面より一回り広い範囲を裏で焼いて貼る方式へ。拡大してもぼやけず、保存ファイルも小さくなる。焼く範囲が画面を覆わず端が消える欠陥を即日修正した。
- **その他**: プリセット出界図の海の色を実データに合わせた。E2E とスモークテストが利用者の実データ領域を共有していたため、一時ディレクトリへ隔離した。

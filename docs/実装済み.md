## 2026-08-16 実データの取り込み経路を `derle-map-visualizer` へ一本化

アプリ本体のコードは変更していない。実データを作り直す手順と、その道具の置き場所の変更。

- **`derle-import/tools/` の変換一式を `../derle-map-visualizer` へ移した**。従来は「visualizer で抽出 → JSON → `build-tmap.mjs`（Node）で `.gimoza` へ変換」の 2 段構えで、同じ処理が 2 バージョンあった。visualizer 側だけで `.gimoza` を書き出せるようにして一本化した。移植の正しさは、同じ入力から出る `manifest.json` と背景資産が既存データとバイト単位で一致することで確認した。
- **`derle-import/` はデータ置き場になった**。元 SVG と `.gimoza` 本体、および出来上がった `.gimoza` を調べる補助（`diagnose-*.ts` ほか）だけが残る。作り直しかたは `derle-import/README.md` にある。
- **保存形式の制約が 1 つ判明した**: 読み込み側は経度を連続量へ戻すとき隣り合う頂点の差が 180 度を超えると ±360 度ずらすため、**1 辺で経度 180 度以上を渡る形は表現できない**。南極域の全周リングがこれに該当し、書き出し側で長い辺へ中間点を打つ対処を入れた（アプリ側は変更なし）。

## 2026-08-15 保存ファイルの拡張子を `.gimoza` へ変更

- アプリの正式名称は **gimoza** であり、`tmap` は開発時のコードネームだった。保存ファイルの拡張子を `.tmap` から **`.gimoza`** に変更し、保存・読込ダイアログのフィルタも `.gimoza` のみとした（`.tmap` は一切受け付けない。後方互換は取らない方針）。
- デーレ界の実データ（`derle-import/derle-world-full.gimoza` / `derle-world.gimoza`）も改名し、整合性チェックが不整合ゼロのままであることを確認した。
- **内部識別子とスキーマ版文字列は据え置いた**（詳細と理由は現状.md B3）。`SCHEMA_VERSION = 'tmap/1'` は保存済みファイルに書き込まれた内部識別子で、変えると既存ファイルが読めなくなるだけのため。据え置く理由は `src/domain/persistence/schema.ts` に、「Tmap = gimoza」であることは `src/shell/io/tmap.ts` の冒頭にコメントとして残した。

## 2026-08-09 デーレ界実データの取り込みと、そこで露見した描画・性能の欠陥

- **実データの再構築**: 旧開発機にしか無かったデーレ界の地図を本機で作り直し、`derle-import/` に配置した（フル版・間引き版とも整合性チェックは不整合ゼロ）。デーレ共和国・正統ノル王国・ラヴィエンド・ウィル同君王国を集約地物として階層を構成し、集約＝下位領域の和（FR-35）が実データで機能することを確認した。
- **頂点マーカー表示上限の意味を変更（FR-110）**: 「地物の総頂点数」で判定していたため巨大地物ほど編集できなくなる逆転が起きていた。「視野内に描くハンドル数」で数える方式に変え、拡大すれば巨大地物も編集できるようにした。
- **展開された集約地物が自分の領域を描き続けていた（FR-42）**: 集約は自前の形状を持たない（領域は下位領域の和）のに、展開後も親の形が子の真上に重なり、子へのクリックを全部吸っていた。自前形状を持たない集約が展開された場合のみ描画から外すよう修正。
- **性能**: 集約の形状キャッシュが未使用分を捨てていた問題（時刻移動 2,432ms → 51ms）と、下位領域の和を線形に畳み込んでいた問題（二分木状の合併へ変更、初回 2,323ms → 539ms）を解消。
- **ベクター背景地図（FR-03）**: 背景をラスター画像で持つ方式をやめ、SVG のパス定義を保存資産に入れて画面より一回り広い範囲を裏で焼いて貼る方式へ。拡大してもぼやけず、保存ファイルも小さくなる。焼く範囲が画面を覆わず端が消える欠陥を即日修正した。
- **その他**: プリセット出界図の海の色を実データに合わせた。E2E とスモークテストが利用者の実データ領域を共有していたため、一時ディレクトリへ隔離した。

## 2026-11-01 ［動かす］で集約地物を引くと、下の州をまとめて動かす

- **裁定**: ［動かす］の道具で集約地物を引いたら、下の州をまとめて動かす。共有頂点は不動。それまでは断って理由を出していた。
- **動き**: その年に居る下位の末端地物を全部（途中の集約地物をたどって）同じベクトルで動かす。外の面・線・点とその年に共有している頂点は動かさず、下位領域どうしだけで共有している頂点は一緒に動かす（この読みは解釈。戻し方は `ui-redesign/README.md` の B-3）。隠している下位領域も動かす。確定したら動かした下位領域の数と動かさなかった共有頂点の数を状態行で言う。動かせるものが無ければ記録せず理由を言う。
- **作り**: 分類は純粋な関数 `planAggregateMove`（`domain/editing/move.ts`）。下書きと確定は同じ計画と同じ `moveVertexSet` を通る（`ui/map/aggregate-move.ts` が (根, 年, 地物) ごとに覚える）。確定は `applyEditProposal` の入口で分かれ、頂点の体を配る既存の `applyMovedVerticesToHistories` と後の年への `carryVertexForwardIn` をそのまま通す。旧座標は全部の系列から引く（自分の系列を持つ下位領域の旧座標は集約地物の錨に無いので、そのままでは後の年に古い座標が残る）。重なりの板・穴と飛び地の断り・半周以上の断り・引いている最中の年の関門・読み込みの間の関門は普通の面の移動と同じ経路に乗る。形が変わるので、確定の関門へ「動く頂点と動かない頂点が混ざる輪」を渡して、伸びた辺を測る。
- **直したもの（別の不具合）**: 面の移動で、頂点を 1 つ共有するだけの隣の系列へ、引いていない頂点の体まで配っていた（`applyMovedVerticesToHistories`）。あとでその頂点を動かすと隣の写しに古い体が残り、読み込みが座標の食い違いと言う形だった。引いている頂点と既に持っている頂点だけを配るようにした。

- **残したこと**: 自己交差と長さ 0 の辺は確定で止まらなかった（同じ日に直した。上の B126）。そのため下の「実データで何が起きるか」は直す前の数字である。ヒットテストは選んでいる集約地物の下位領域の上だけを掴む（穴の中は当たらない）。

## 2026-09-07 UI 再設計 増分 7（歴史の構造編集 — 所属変更・削除・拒否理由）

## 2026-09-06 UI 再設計 増分 5 の手直し（5 本の検証への対応）

設計適合・コード反証・実データのバグ狩り・外部審査 2 本の計 5 本が「要修正」を出したので、
指摘を 7 つの群（A〜G）に分けて片付けた。作り直しではない ―― 中核（固定行・再マウント無し・
K-2・鍵の関門・読むだけの地図クリック・道具を持ち替えても選択が残る・全件ゲート）は実機で
成立していた。詳細と対応表は `docs/ui-redesign/進捗/増分5.md` §12。

**所有者の裁定と司令塔の決定**（所有者は覆せる）:

- 裁定: モード排他は崩す（鍵＋道具 1 段）／読むだけでも地図クリックで**選べる・読める・
  直せない**／道具を持ち替えても選択を捨てない／表示条件を変えても選択は外さない。
- 決定 (1) **鍵はアプリバーの右端 96px の固定枠へ戻す**（左レールから外す。レールの縦あふれと
  鍵の文字欠けの根だった）。(2) 地図内のズーム・縮尺・頂点の候補一覧は**増分 6 で置く**。
  (3) 手順のある 5 道具の **Esc の階段は今回揃える**。(4) 測る（測量）は別の軸のまま残すが
  **オプションバーを使う**。(5) ナイフ・穴あけの新地物の素性入力は、追加の道具と同じ
  **右パネルの「新規の姿」**へ。

**A 入力の持ち主と下書きの保護**

- **作図中の右クリックが下書きを壊し視点を飛ばす**のを直した（実データで再現。重症度 4）。
  右クリックは**メニューを開くが選択は変えない** ―― 昇格が背後の地物を選び、それを見張って
  いた追加の道具が下書きごと捨てていた。判定は「畳んだ持ち主」ではなく **生の「下書きを
  持っているか」**を見る（素性入力中は持ち主が `text` になって下書きが隠れるため）。
- **素性を入力している局面で Escape が誰にも受けられていなかった**のを直した。道具側は
  「文字の欄なら素通り」で降り、大域側は焦点の関門で落ちていた。いまは Escape だけ道具が
  受け、打ちかけのある欄では 1 度確認する。**利用者自身の Escape で出ている確認は、
  もう一度の Escape で「捨てる」**にした（旧版は「このままにする」だったので、押すたびに
  板が開いては閉じるだけで永久に素の状態へ戻れなかった）。
- **道具の持ち替えと鍵の開け閉めでも、確定できる打ちかけは黙って捨てない**。年・一覧の
  選択と同じ形で確認を出し、「このままにする」で道具（鍵）が元へ戻る。
- **鍵盤の持ち主の穴を塞いだ**: 吸着 ▾ を共通の器へ載せ替えて開閉を報せる／標準メニューの
  開閉を報せ、Escape を捕捉段で受ける／結合の選択板・継承先の板・新地物の素性入力・
  捨てる前の確認を**「下書き」ではなく「モーダル」**として数える／つまみ
  （`input[type=range]`）に焦点があるあいだ大域の打鍵を止め、Escape で抜けられるようにする／
  「まだ誰も持っていない」を地図が載る前に出す／板が開いていて打鍵が止まったときは
  **その板を閉じる**という次の一手つきで理由を出す。
- **測量を入り切りすると内部の状態が壊れる**のを直した（画面は「選ぶ」なのに内部は「追加」）。
  `activeTool` を書くところは `mode` の導出と必ず一組にした。
- **読むだけでは頂点・辺中点を掴ませない**（描く条件と掴める条件を同じ入力で決める）。
  見えていない頂点が選ばれず、Escape の階段も 1 段増えない。
- **頂点の選択を捨てる条件**を「直前が頂点の道具だったか」から「**掴める道具から出るか**」へ。
  「選ぶ」「動かす」で掴んだ頂点が、ナイフや追加の道具へ持ち越されなくなった。
- **クリックかドラッグかを、離した位置でも測り直す**（移動の見本が 1 つも届かない押下が
  クリック扱いになっていた）。

**C オプションバーの所有権と対象欄**

- **手順の道具を後ろ→前に持ち替えると次の一手が消える**のを直した。「降りたら空へ」を
  **後片付け関数**へ移すと、React が「全部の後片付け → 全部の押し込み」の順に走らせるので、
  木の位置に依らず正しい順になる。
- **読むだけでも選んでいる地物の名前を対象欄に出す**（裁定の「読める」の前半）。
  ナイフ・輪郭・穴あけは**自前の対象を持つ道具**に分類し、掴んでいない地物の名前を出さない。
- **測るがオプションバーを使う**（道具名「📏 測る」・対象・次の一手・確定欄［測量を終える］）。
  レールの表記も「測量モード」から「📏 測る」へ（画面から「モード」の語を落とす）。
- 常設の設定部品が毎レンダー登録し直されるのをやめた（報せ口を id ごとに使い回す）。

**B 手順のある 5 道具の Esc の階段と確定**（司令塔の決定 (3)(5)）

- **Escape を 1 段ずつにした**（設計書 §D.4.1）。5 道具とも Escape 1 回で「手順の対象」
  「元からの選択」「道具」の三段をまとめて捨てており、結ぶ・所属変更では **道具が掴んだ
  のではない元からの選択**まで消えていた。いまは「下書きの点列をまとめて捨てる →
  対象を離す（道具は持ったまま）→ 頂点 → 地物 → 道具を降りる」の 1 段ずつで、
  対象も下書きも無いときは大域の階段へ譲る。
- **確定後のふるまいを揃えた**。ナイフだけが確定後に道具を降りていた（続けて分けたい人は
  毎回選び直すことになる）。5 道具とも道具を持ったまま次の対象待ちへ戻る。
- **案内・断り・確定を全部オプションバーへ**。ナイフの拒否板が地図クリックを奪っていたのと、
  所属変更の案内が地図上端の黒帯と二重に出ていたのを直した。「手順 n/m」を対象欄へ。
- **［最上位へ（所属を外す）］に確認を入れた**（押した瞬間に確定していた）。
- **ナイフ・穴あけの新地物の素性入力を右パネルの「新規の姿」へ移した**（司令塔の決定 (5)）。
  地図の中央の板を消し、追加の道具と同じ口で受ける。同じ作業に置き場を 2 通り持たない。

**D シェルの寸法と畳み**

## 2026-09-06 E2E / スモークのウィンドウを表示しないようにした（PC のフォーカスを奪わない）

E2E を回すと Electron のウィンドウが次々と前面へ出て、**テストのあいだ PC で他の作業が
できなかった**（所有者の困りごと）。描画はもともとオフスクリーンなのに、`ready-to-show` で
**無条件に** `show()` を呼んでいたのが原因。詳細は `docs/技術方針.md` §2.14、教訓は
開発ガイド §5.66。

- **旗（`E2E_TEST` / `SMOKE_TEST` / `E2E_OFFSCREEN`）が立っているときは `show()` を呼ばない**
  ようにした。`show: false` のままなので画面に出ず、フォーカスも奪わない。判定は Electron を
  import しない純粋関数（`src/shell/main/headless-window.ts`）に置き、**オフスクリーンで描くか
  どうかの判定と同じ 1 か所**から読む（条件が 2 つに割れて片方だけ直る事故を防ぐ）。単体テストで
  「旗ありなら出さない・旗なしなら出す」を固定した。
- **本番の挙動は変えていない。** 旗が無ければ従来どおり `ready-to-show` で `show()` する。
- **「奪っていない」を数で確かめた。** 旗が立っているあいだはウィンドウを前面に出さない、を
  目で見て言うのではなく、**前面のウィンドウが何のプロセスかを一定間隔で記録して数える**形で
  確かめた（検出手段は開発ガイド §5.66）。直す前は E2E を 1 周回すあいだに前面が何度も
  Electron へ移っていたが、直した後はスモークも探索も含めて**一度も移らない**。ウィンドウを
  出す仕事が消えたぶん、E2E の所要時間も短くなった。実測した回数と割合は開発ガイド §5.66 に
  検出手段の例として置いてある。

## 2026-09-06 E2E を 2 系統に分け、並列で回すようにした

E2E は **1 テストにつき Electron を 1 つ起動する**作りで、直列（`workers: 1`）だと全件で
19 分かかっていた。所有者の裁定（2026-09-06）を受けて 2 点を直した。詳細は
`docs/技術方針.md` §2.14。

- **`main` と `explore` の 2 系統に分けた**（`playwright.config.ts` の `projects`）。
  `explore` は探索的なバグ狩りと見た目の記録（`e2e/__bughunt__/` と `e2e/__visual__/`）で、
  **消していない** ―― 毎回の検査から外しただけで、**増分の受け入れ時と手直しの後には
  必ず回す**。コマンドは `npm run e2e`（main）/ `npm run e2e:explore` /
  `npm run e2e:all`。ビルド込みは `npm run test:e2e`（main）と `npm run test:e2e:all`。
  spec の中身は 1 行も変えていない。
- **ワーカーを複数使うようにした**（`workers: 6`）。`fullyParallel` は false のままなので
  **ファイル単位**の分配で、1 つのファイルの中の順序依存は保たれる。並列にできるのは
  テストどうしが資源を共有していないからで、その 4 点（ワーカーごとの userData ／
  実データは 1 本ずつの写し ／ E2E 用の環境変数は子プロセス限定 ／ スクショ名は spec ごと）
  を技術方針へ明文化した。
- **実測して決めた**（2026-09-06、ビルド済みの `out/` を使用。いずれも 1 件も落ちず、
  やり直しも 0）。分ける前は全部を直列で回しており、毎回の検査だけを取り出した結果、
  **待ち時間は桁が 1 つ変わった**。ワーカーを 4 から 6 へ増やした差は小さく、
  **一番長い 1 ファイルが下限**なのでそれ以上は増やしても縮まない。
  実測の数値そのものは `docs/ui-redesign/進捗/増分5.md` §13 の表へ移した
  （機械で測れる値を恒久文書へ手書きしない＝開発ガイド §2.6）。

  （`snapshotPathTemplate`）。Playwright の既定のままだと `projects` を足した瞬間に
  既存のベースラインが全部行方不明になる。書式は既定から `{-projectName}` だけを抜いた形に

  **リポジトリの外（ドライブ直下）へ書き出された**。開発ガイド §5.65 に教訓化した。

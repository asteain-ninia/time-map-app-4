## 2. 既知の不具合・制限（機能欠陥ではないと判断したもの）

- **L1: 経度±180度の継ぎ目に関するコーナーケースの繰越**。`.autopilot/SEAM-AUDIT.md §5` の C5 / C11 / C12 / C13 / C14（M10 部分）/ C15。いずれも 360度を超える幅・複数周回・極端なパン量・契約違反の座標といった通常の編集では到達しない入力か、防御層の強化・UI 仕様の合意を要する項目。重大な根本原因は解決済み。
- **L2: 海岸線のように頂点が密な地物を大量選択したまま動かすと 1 フレーム 27ms 程度かかる**（描画予算 16.6ms 超過）。複数頂点の同時移動における集合デルタ拘束の計算量による。拘束の意味論を壊さずに速くする方法が未検討。
- **L3: 外部レビューで指摘され、不実装と決めたもの**。展開処理の CPU 有界性、1GiB 境界の扱い、自己解凍形式の ZIP。いずれも敵対的に細工されたファイルでしか到達せず、ローカル単一利用者のオフラインツールには不相応な堅牢化と判断した。

## 4. 技術負債

- **B1: `src/ui/App.tsx` が 4,500 行超**。合成ルートとして肥大しており、境界での分割が望ましい（優先度低）。
- **B2: 頂点マーカーの分類器（`domain/selection/visual.ts`）のマーカー側が描画へ未結線**。地物側（点線アウトライン）は結線済み。現在アクティブ地物の頂点表示はハンドル経路が担っており機能上の欠落はないが、同じ判定が2箇所にある状態が続いている。
- **B3: コード内部の名前が旧コードネーム `tmap` のまま残っている**（2026-08-15 の拡張子変更に伴う意図的な据え置き）。アプリの正式名称は **gimoza** であり、`tmap` は開発初期のコードネーム。保存ファイルの拡張子は `.gimoza` に統一済みだが、次の2つは**意図的に変えていない**。
    - **内部識別子**（`readTmap` / `buildTmap` / `saveTmap` / `TmapContents` / `ExtractedTmap` / `ReadTmapResult`、ファイル名 `src/shell/io/tmap.ts` など）。外から見えない呼び名にすぎず、改名しても利用者の得るものが無い一方で差分だけが広範囲に及ぶため。`src/shell/io/tmap.ts` の冒頭に「Tmap = gimoza（同じものを指す）」と明記してある。
    - **保存データ内部のスキーマ版文字列 `SCHEMA_VERSION = 'tmap/1'`**（`src/domain/persistence/schema.ts`）。この値は保存済みファイルのマニフェストに literal として書かれており、版が完全一致しない manifest は仕様上 INCOMPATIBLE として拒否される（マイグレーションはやらない方針）。変更すると既存ファイルが一律で読めなくなるだけなので据え置く。理由は同ファイルのコメントにも記載済み。

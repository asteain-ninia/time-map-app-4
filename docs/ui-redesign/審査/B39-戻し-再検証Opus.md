## 重さ 3（受け入れ前に直す）

### 3-1. 子を「ここで終わる」にしたあと親の境を直した形で、勧められる修復が親の直しを黙って戻し、隣を除外する

- **何が起きるか**（ドメイン、画面と同じ修復の関数で再現。探針 F・F2）: 0 年に親（100×100）。100 年に親の中へ子を描く。300 年に子を「ここで終わる」。500 年に親の東の帯（20×100）を手放す（親の境を直す。F2 では隣 Q がその帯を受け取る）。保存して開き直す。
    - 1 枚目の板は「100 年: 末端なのに下位領域」1 行。勧められる「直轄領を生成」を押すと解けず、2 枚目が出る: 「300 年: 子の並びの食い違い」「500 年: 末端なのに下位領域」「500 年: P 直轄領 と Q の重なり」×2（選択肢は「一方を除外」だけ）「共有頂点の座標の食い違い」×2。
    - 2 枚目も勧められたまま押すと読み込めるが、**隣 Q が読み込みから消え**、500 年以降の親は **手放したはずの帯を取り戻して 10,000 に戻る**（直す前の記録は 8,000）。隣が居ない F でも、500 年以降の親は 8,000 → 10,000 で、**親の境の直しが黙って消える**。
    - 1 枚目で「そのまま残す」を選べば何も変わらずに開ける（これは今回の改善）。ただし勧められる道は害を出し、2 枚目まで来るともう「残す」には戻れない（2 枚目の重なりの行には除外しか無い）。
- **原因**: 修復は 100 年の片で分け残しを作り、その記録の終わりに親の片の **書かれた終わり**（終わりなし）を写す。親の 500 年の錨は子が居ないので作り替えられず、分け残しは 300 年に子が居なくなったあとも、500 年の親の記録を越えて古い形（100×100 − 子）のまま続く。500 年では「分け残しを子に持つ末端」になって 2 回目の修復が走り、親は 2 つの分け残しを子に持つまとめ役になる。分け残しは元の頂点 id を引き継いでいるので、500 年に動かした角とも「座標の食い違い」になる。
    - `splitLeafAtChildBoundaries` の注記は「子が居なくなる年では割らない（割ると、その後ろの片だけ親が末端に戻り、分け残しと重なる）」としているが、重なるのは分け残しの終わりが区切られていないからで、割らないことで別の形（親の後ろの記録の上に分け残しが居残る）になっている。
- **いつからか**: 子を親と同じ年（0 年）に描いた形（F2s）でも結果は同じなので、**修復の分け残しに終わりが無いことは前からある**（`docs/現状.md` の B92）。今回の直しの前は、年を変えて子を描いた F2 は開き直しが止まり、開く道は「親を除外」だけだった。今回、止まらずに開けるようにした結果、**いちばんふつうの描き方（年を進めて子を描く → 子を終わらせる → 後で親の境を直す）からも、勧められたまま押すと隣が消える道に届くようになった**。前回の 3-2（親が手放した土地が戻る）・3-3（開き直しで子が消える）と同じ結果なので、同じ重さにする。
- **B92 の記述の訂正**（司令塔に効く情報）: `docs/現状.md` の B92 が挙げる形（親が後ろの年でまとめ役になっている）は、いまは解ける（探針 E2 で検査が空）。修復が 1 本の分け残しの系列に年ごとの錨を作り、前の錨が次の錨で区切られるからである。本当に起きるのは **親の次の錨より前に子が居なくなる形**（その先の親の錨は作り替えられず、分け残しだけが続く）。
- **直し方の向き**（src を触れないので確かめていない。見込み）: (a) 子が居なくなる年でも親の錨を割る（割った後ろの片は子が居ないので末端のまま）。(b) 修復が作る分け残しの各区間の終わりを「書かれた終わりと、親のその片の次の錨の始まりの早いほう」にする（B92 の直し方。1 か所）。両方そろえば、F・F2 は 100〜300 年だけ 親 →［子, 直轄領］、300 年からは元の末端の親に戻り、500 年の親の直しも隣もそのまま、2 枚目の板も出ない見込み。下の 2-1 も同じ直しで消える見込み。E2E に「年を変えて子を描く → 子を終わらせる → 親の境を直す → 保存 → 開き直しで勧められるまま 1 枚」を足す。

## 指摘

### 3-1 穴を斜めに横切る線で、穴の辺の切り口が隣（島）へ渡らず、境目に T 字のつなぎ目が黙って残る（手直しで入った退行）

- **重症度**: 3
- **場所**:
  - `src/domain/knife/split-geometry.ts:1194-1204`（各片から穴を `difference` で差し引く）
  - `src/domain/knife/split-geometry.ts:1358-1423` `computeEdgeCuts`（隣へ渡す切り口を、**引いた線の区間 a→b** と穴の辺の交点で求める）
  - `src/domain/editing/apply-proposal.ts:653-654`（切り口の座標に片の頂点が無ければ、その切り口を黙って捨てる）
- **仕組み**: 外周の切片は、線の端 a→b と外周の交点を格子へ丸めた点 P・Q を端に持つ。片は P→Q を辺に持ち、穴との交点は集合演算（`difference`）が **P→Q の上で** 求める。
  一方 `computeEdgeCuts` は **a→b の上で** 穴の辺との交点を求める。P・Q は a→b から最大で格子の半分ずれているので、斜めの線では 2 つの交点が **隣り合う別の格子点**（1×10⁻⁷°）に丸まることがある。
  すると適用の段で「切り口の座標に片の頂点が無い」となって切り口が捨てられ、島の環には点が入らない。片の側には点があるので、島の辺の上に片の頂点が乗った T 字のつなぎ目になる。
  水平・垂直の線では P→Q が a→b と同じ直線上に残るので起きない。手直しの単体（`split-geometry.holes.test.ts:158-178`「切り口の点は両側の片に同じ座標で入る」）は水平線で、しかも片どうしを比べるだけで `edgeCuts`・隣とは比べていない。E2E ③ は西の腕だけを切り、島の穴を横切らない。だからどの検査にも掛からなかった。
- **再現と数字**:
  1. 小さな形（探針 `synthetic.probe.test.ts` の (A)）: 正方形 [0,10]² に斜めの四角の穴、ほぼ対角の 2 点線 40 本。穴の辺の切り口 80 点のうち **片の頂点に無いもの: 手直し後 12・手直し前（`3566f04` の split-geometry）0**。ずれはどれも 1.00×10⁻⁷°。
     例: 線 (-1.0026,-1.1958)→(11.1514,11.2862) で、`edgeCuts` は (6.4909483, 6.4999767)、片の頂点は (6.4909484, 6.4999767)。
  2. 実データ 3000 年（探針 `holes.probe.test.ts`）: 穴のある 31 地物の穴の中心を通る斜めの線（6 方向・まっすぐ／折れ線／端が穴の中）1,278 本。
     **片の新しい頂点が、隣と共有の辺の上で、引いた線の上にあるのに `edgeCuts` に無いもの: 手直し後 265 本（切片の経路 840 本の約 3 割）・手直し前 0 本**（同じ線・同じ数え方）。
  3. 実データで本物の確定（U13。探針 `pipeline.probe.test.ts`）: 8 つの海域で確定は **断られずに通り**、片と島の間に T 字のつなぎ目が残る。
     例: トランツィ湾の海域02 ×トランツィ湾の島02（T 字 2）、トゥインク小海の海域01 ×セクエンロ狭海の島07（T 字 8）、トルエホニエ ×クシダ狭海の島01（T 字 4）、ジアーラ ×ジアーラ内不明国（T 字 2）。
- **内容**: 依頼で見るよう言われた「共有頂点（隣との境界）」の約束（FR-95）が、穴のある海域で斜めの線を引くと約 3 割で崩れる。画面ではずれが 1 cm ほどで見えず、整合の検査も確定を止めない。
  あとで島の頂点を動かすと、島の辺だけが動いて片の点が取り残され、すき間か重なりが生まれる（未確認。仕組みからの推測）。所有者の原則「削除以外でデータが勝手に変わるのは良くない」に当たる。手直しの前の経路（遠い枠までの切り抜き）は、切り抜きの辺が a→b そのものだったので一致していた。
- **直し方の案**（どちらも未確認。先に試すのは①）:
  1. **隣へ渡す切り口を、片に実際にできた点から作る**。元の辺の途中（格子 2 つ分以内）に乗っている片の新しい頂点を、その辺の切り口として `edgeCuts` に入れる。切り口と片の頂点が同じ出どころになるので、ずれようがない。
  2. 穴との交点を `computeEdgeCuts` と同じ求め方（a→b と格子へ丸めた辺）で求めて切片の折れ線に先に差し込み、そのあとで `difference` に掛ける。ただし集合演算がその点を辺の上の点と見なすかは確かめる必要がある。
  - **固定の検査**: 斜めの線で島（別の地物）と共有の穴を横切り、本物の U13 で確定する（`split-preservation.test.tsx` と同じ組み立て）。島がその切り口の頂点 id を参照し、T 字が無いことを確かめる。
    探針 (A) をそのまま単体にできる（「`edgeCuts` の各点が片の頂点にある」）。

### 1-1 穴が片の中で土地を囲むと、1 つの片が 2 つの多角形（飛び地）になる

- **重症度**: 1（データは欠けない。所有者に伝えておくこと）
- **根拠**: 探針 `synthetic.probe.test.ts` の (B)。外周 [0,20]×[0,10]、U の字の穴、y=6 の線が穴の両腕を横切ると、下の片は「本体」と「U の内側の土地 [8,12]×[4,6]」の 2 つの多角形になる。面積は保たれ、穴は穴のまま。実データでも 1,266 本中 394 本で、どこかの片が 2 つ以上の多角形になる（手直し前は延長の切り込みもあって 691 本）。
- **内容**: 「境界を 2k 回横切れば k+1 片」は外周を横切る回数で数える。穴があると、つながっていない部分が同じ片にまとまることがある。所有者が §11.5 の 1（片を全部別の地物にしてよいか）を決めるときの材料になる。
- **直し方の案**: 直さなくてよい。§11.5 の 1 の質問に 1 文足す（「穴があると、1 つの片が飛び地を持つことがある」）。

### (2) `cutsBeyondLine`

- 延長が面に触れたかを、延長の 2 本の区間と面の全部の環の辺で見ている（`split-geometry.ts:394-407`・`:1232`）。延長の経路で引いた線の外に切り込みができるのは延長の区間の上だけ（枠の辺は面の外接矩形の外にある）なので、「切ったのに立たない」経路は見当たらない。
- 実データ: 上の 1,278 本で、引いた線の外に新しい頂点ができた 329 本はすべて立っていた。実装者の探針でも、外周が自分に接する面の 77 本はすべて立つ。触れただけで切っていないときにも立つのは記録どおり（立ちすぎの側なので問題ない）。
- 画面: 継承先の板（`knife-beyond-line-note`）と、名前を入れる段の次の一手の先頭に出る（`KnifeToolController.tsx`。単体で固定済み）。

### (3) 既定の継承先・Escape・穴あけの幕・E2E の読み口

- 既定の継承先: `useKnifeTool` は `largestPieceIndex` で選び、Escape の「継承先を選び直したか」も同じ `largestPieceIndex` と比べている。2 つがずれることは無い。赤い枠は今までどおり `smallestPieceIndex`。
- Escape: 前回の反証の探針 `knife-esc.probe.test.tsx` の E2（名前を打つ → 幕を押す → Escape）を当て直すと、**今は聞く板が出る**（前回は確認なしに捨てていた）。
- 穴あけの幕: 名前入力の段で入力の橋が `data-locked="true"` で残り、左クリックは受け止めて理由を出す。ホイールと中ボタンは通す。Escape も中身で見る。
- `getLeafReport`: `registerE2eHarnessAction` で登録し、`isE2eHarnessEnabled`（起動引数 `--tmap-e2e-harness` で preload が橋を出したときだけ真）で守られる。ほかの観測と同じ仕組みで、本番には出ない。

### (4) 取り消し・やり直し・保存→開き直し

実データの穴のある海域 8 つと延長の経路 2 本を U13 で確定（`pipeline.probe.test.ts`）。取り消しは保存形式の文字列が確定前と一致、やり直しは確定直後と一致、保存→開き直しも一致（10 本すべて）。

手直しの単体 `split-preservation.test.tsx`（単純な U の字＋東隣）も通る。

## 指摘

### 1.［重症度 3］選んでいる頂点を最寄りより優先する規則が、一覧から選んだ直後のドラッグだけでなく **すべての押下**（右クリック・Shift+クリック・ドラッグ）にかかる。右クリックした頂点ではなく、前に選んでいた頂点が消える

- **場所**: `src/ui/map/mount/hit-test.ts:197-240`（`hitTester.hitTest` 全体を `preferSelectedVertex(…, s.selection, …)` で包んでいる）、
  `src/ui/map/vertex-candidates.ts:280`（`preferSelectedVertex`。選択がどう作られたかを見ない）、
  使う側 `src/ui/map/PointerDispatcher.ts:235`（押下は左右どちらも同じ `hitTest`）→ `:317`（右ボタンはその当たりで `contextMenu.request`）→ `hit-test.ts:487`（`promoteHit` がその当たりを選択に書く）。
- **再現**（`prefer.probe.spec.ts` の 1 本目。E2E で確かめた）:
  1. 合成データの小さな四角（`openVertexCandidatesOnTinySquare`）で候補一覧を出し、1 行目の頂点 X（`syn-0000-v3`）を選ぶ。
  2. 別の隅 Y（`syn-0000-v0`。X から 2.5px）の **真上**（距離 0px）を右クリックする。
  3. 右クリックのあとの選択は **X のまま**（`app-active-vertex = syn-0000-v3`）。メニューの「頂点を削除」→ 確認「頂点 1 個を消します」→ 確定。
  4. **消えたのは X（88.95°S 179.00°W）で、右クリックした Y（89.00°S 179.00°W）は残った。**
  増分 8A より前は、当たり判定は最寄り（Y）を返すので Y が消えていた（コードの読み。旧版は走らせていない。`liveHitTestAt` は 8A で触られておらず、包みが足されただけ）。
- **同じ根から出るほかの症状**:
  - **Shift+クリックで足せない**（2 本目で確かめた）: X を選んだ状態で Y を Shift+クリックすると、当たりが X に書き換わって **X が選択から外れ**、選択は空になる（`app-active-vertex = ""`）。Y を足すつもりの操作が、X を外す操作になる。
  - **ドラッグ**: X を選んだまま、掴める距離の中の Y を押してドラッグすると X が動く（実装者の E2E がまさにこれを「狙いどおり」として固定している）。
    一覧を使わずに **普通のクリックで X を選んだ場合**も同じで、規則は「一覧から選んだ」かどうかを見ていない。
  - **複数の頂点を選んでいるとき（FR-80）**: 矩形や Shift で選んだ集合の 1 つから掴める距離にある、選んでいない頂点を押してドラッグすると、当たりが選択中の頂点に書き換わり、`companionVertexIdsFor` により **選択の集合ぜんぶ** が同じだけ動く（`hit-test.ts` の FR-80 の注記「選択中の頂点を掴めば集合全体が動く」と組み合わせたコードの読みからの推定。**未確認**）。
- **重さ**: 掴める距離は 8〜16px。実データでは ×16 でも隣まで中央値 6.4〜7.0px（設計書 §F.3）なので、密な所では「選んでいる頂点の隣」を狙う場面は日常的に起きる。
  右クリックの「頂点を削除」は、利用者が指した頂点とは別の頂点を消し、確認の文にも **どの頂点か** が出ない。取り消しで戻せるが、気づかなければ黙って別の点が消えたまま保存される。
  所有者の原則（削除以外でデータが勝手に変わるのは良くない）に照らすと「消す対象のすり替え」で、重症度 3 とした。
- **進捗文書との食い違い**: 進捗 §4 の 3「**一覧から選んだ頂点は**、掴める距離の中なら最寄りより優先して掴む」と §2 の書き方は、実装の範囲（選んでいる頂点すべて・すべての押下）より狭い。
  README の B-3 の同じ行も同じ。設計書 §E.1 V9 の経路（クリック → 一覧から選ぶ → ドラッグ）に要るのは、一覧から選んだ直後の左ドラッグ 1 回だけである。
- **直し方の案**:
  - 共有の `hitTest` を包むのをやめ、**左ボタンの編集ドラッグの入口**（`editSession.begin` に渡す当たり）でだけ優先する。右クリック・Shift/Ctrl つきの押下・読むだけのクリックには効かせない。
  - さらに、**一覧から選んだときだけ**立つ使い捨ての印（`selectVertex` で立て、次の押下で必ず消す。世界・年・道具・カメラが替わっても消す）を条件にする。普通のクリックで選んだ頂点や矩形の選択には効かせない。
  - 試験: 「X を一覧で選ぶ → Y の真上を右クリック → メニューの対象は Y」「X を選ぶ → Y を Shift+クリック → 選択は {X, Y}」「矩形で集合を選ぶ → 集合の外の隣を押してドラッグ → 動くのは押した 1 点」を足す。

### 2.［重症度 2］辺の中点のクリックは、隣と共有している辺でも **片側の地物にだけ** 頂点を足す（T 字）。実データの辺の 65% が共有辺

- **場所**: `src/ui/map/edit-session-adapter.ts:446-470`（クリックでも確定する新しい経路）→ `src/ui/map/edit-session-snapshot.ts:105-131`（`addVertexToLeafRing(feature, …)` は押した地物 1 つだけを書き換える）。
  分割には共有辺の途中に頂点を移す仕組み（`apply-proposal.ts` の `sharedEdgeCuts`、FR-95）があるが、頂点を足す経路には無い。
- **再現**（`tjunction.probe.test.ts`。App と同じ組み方で U13 の確定まで通した）:
  A=(0,0)-(10,10) と B=(10,0)-(20,10) が頂点 s1(10,0)・s2(10,10) を共有。A の辺 s1–s2 の中点をクリック（押して動かさずに離す）。
  確定 1 件。**A の輪は `a0, s1, new-1, s2, a3`、B の輪は `s1, b1, b2, s2` のまま。** 新しい頂点 (10,5) は B に入らず、整合の処理も足さない。
- **重さ**: クリックした瞬間は形が変わらない（直線の真ん中に点が増えるだけ）ので、利用者には何の合図も無い。
  あとでその頂点をドラッグすると A の境界だけが動き、B との間に隙間（どちらにも属さない三角形）ができる（FR-30「共有頂点をドラッグすると共有する全形状が連動」を期待した操作が連動しない）。
  実データ（年 3000）では、地物の辺 70,268 本のうち **45,880 本（65.3%）が隣と共有** している。バアカは 601 本中 177 本（29.5%）、小さな領域は多くが 100%。
  ドラッグで足す経路（FR-87）にも元からある振る舞いで 8A が作ったものではないが、8A で **1 回のクリックで黙って起きる** ようになり、踏む機会が大きく増える。
- **直し方の案**: 足す辺が共有辺（両端の頂点を同じ順で引いている隣の地物がある）なら、隣の同じ辺にも同じ id を挿入して共有頂点にする（`apply-proposal.ts` の共有辺途中切断と同じ規則を流用）。
  すぐに直さないなら、共有辺の中点のクリックは断り（「隣と共有している辺です」）にするか、現状.md に B 番号で載せて扱う増分を決める。ドラッグで足す経路も同じ扱いにする（判定を 2 通りにしない）。

### 3.［重症度 2］選ぶ道具でも、境界の近くを押すたびに候補一覧が出て、出ている間は Delete・Ctrl+Z が断られる

- **場所**: `src/ui/map/mount/input.ts:206`（押すたびに `candidateGesture.press`）→ `src/ui/map/vertex-candidates.ts:380`（掴める距離に頂点が 2 つ以上あれば一覧を作る）。
  候補の母集合は `live-hit-test.ts:1407` の `verticesNearPoint`（**いま選んでいる地物に限らず**、描かれているすべての地物の頂点）。
  当たり判定は頂点を先に見る（`live-hit-test.ts:1168` 以降。これは 8A より前から）ので、掴める距離に頂点があれば当たりは必ず頂点になり、そこへ 8A で一覧が重なる。
  つまり「選ぶ」「頂点」「動かす」のどれを構えていても、境界の近くを押すと **頂点が選ばれたうえに一覧が出る**。
- **根拠**:
  - E2E（`prefer.probe.spec.ts` の 4 本目）: 合成の小さな四角の外側 6px（本体の外）を押しても、当たりは最寄りの隅（`syn-0000-v3`）になり、一覧が出た。
  - E2E（`prefer.probe.spec.ts` の 3 本目）: 一覧が出ている間の鍵盤の持ち主は `popover`。Delete を押すと頂点は消えず、状態行に「『削除』はいま使えません。開いている板を閉じてから（Esc）、もう一度押してください。」。進捗 §5 は Ctrl+Z だけを挙げているが、Delete も同じく止まる。
  - 実データ（`density.probe.test.ts`。900×600 の地図、任意の頂点から 0〜60px ずらした所を左クリックしたと仮定）: 一覧が出る割合は 全体表示 66.9%・×4 54.5%・×16 30.3%。
    全体表示では 56.7% が 20 行に収まらず「ほか N 件」になる。
  - したがって「境界の近くの頂点をクリックして選ぶ → Delete」「境界の近くをクリック → Ctrl+Z」が、全体表示では 2 回に 1 回以上「閉じてから」で断られる。データは変わらないが、密な所の主な作業が毎回 1 手増える。
- **直し方の案**（どれか、または組み合わせ）:
  - 一覧が出ている間も Delete・Ctrl+Z・Ctrl+Y は通し、通したら一覧を畳む（一覧は選ぶ補助で、板ではない）。進捗 §5 で司令塔の裁定待ちになっている件に、Delete も含めて判断材料として渡す。
  - 一覧を出す数え方を「**いま選んでいる地物の**頂点が 2 つ以上」に絞る（隣の国の頂点だけが近いときは出さない）か、「頂点」の道具を構えているときだけ出す。

### 4.［重症度 1］［拡大］は、ズームの上限に当たっても印が出ない地物では空振りするのに、文は「拡大すると出ます」のまま

- **場所**: `src/ui/map/handle-cap.ts:104`（上限に当たると止まる）、`:38`（文は常に「拡大すると出ます」）、`src/ui/map/HandleCapNotice.tsx`（ボタンは出たまま）。
- **根拠**: 実データでは起きない。頂点が 2,000 を超える地物はヴィオニア大陸付近の領域01（2,230）だけで、既定のズーム上限 50px/度のとき 900×600 の窓（18°×12°）に入るのは最大 382、1280×800 でも最大 494（`real.probe.test.ts`）。
  ズーム上限を下げた設定や、狭い範囲に頂点を密に描いた地物で起きうる（**未確認**）。
- **直し方の案**: 上限まで寄せても `stillCapped` が真なら、文から「拡大すると出ます」を外し、［拡大］を出さないか押せなくする。

## 確かめて問題が無かったもの

- **一覧から選んだ頂点が古いまま掴まれる経路**（別の地物を選び直す・年を変える・取り消す）: 選択そのものが掃除される。地物を選び直すと頂点の選択は消え（`store.ts` の `setActiveFeature`・U22 の本体クリック）、
  年の変更・取り消し／やり直しでは `revalidateForTime` がその年に無い頂点を落とす。`preferSelectedVertex` は `near()`（いまの世界の候補）に居る頂点しか返さないので、消えた頂点を掴むことは無い。問題は指摘 1 の「範囲が広すぎる」ほうである。
- **一覧が出ている間の右クリック**（地図の別の所）: 一覧は閉じ、メニューは出る（E2E の 3 本目）。右クリックが黙って捨てられることは無い。
- **Escape の階段・他所の押下**: `use-dismissable` に寄せてあり、地図の押下でも `press` が先に畳む。実装者の K-2 の走査と単体試験で見ている。
- **辺の中点のクリックのあとに一覧が残らないか**: 確定でドメインが替わると `watchCandidateStaleness` が保留中の候補を捨てる（`input.ts` で `dispatcher.pointerUp` → `candidateGesture.release` の順）。
- **矩形の枠の後始末**: 地図から出たら `pointerLeave` → `abortAll` → `selection.cancel` で消える。Escape・道具の持ち替えも同じ口を通る。
- **押すたびの費用**: 一覧の「共有の相手」の索引（`vertexCitersFor`）は、実データで冷えた 1 回 20ms、2 回目以降 0.04ms。ドメインが替わるたびに 1 回作り直すが、固まる量ではない。
- **［拡大］と世界の東西端**: ヴィオニア大陸付近の領域01 は経度 360° いっぱいに広がる（外接 360.0°×30.6°）が、［拡大］は地物の頂点を動かない点にして寄るので、実装者の実データの E2E で印が出ることを見ている。上限に当たれば止まる（`zoomUntilHandlesShow` の `next.zoom > cam.zoom`）。

### #2【重症度 2（経路が見つかれば 3）】読み込みの修復の既定「各地物に自分の年表を作って残す」が、すでに一部の年だけ自分の系列を持つ地物の記録を黙って捨てる

- 再現（探針 `orphan.probe.test.ts`、記録 `orphan.log`）: 持ち主 O の居ない歴史の 1000 年の錨に c と d が居る。c は 1200 年からの自分の系列も持っている。

  だが **c の 1000〜1200 年の記録が消える**（修復後、1000 年に c が居ない）。d は残る。
- 内容: 居候のうち「同じ id の系列がすでにある」ものは起こさず、そのあと孤立した歴史を丸ごと落とすので、その系列が覆っていない年の記録が失われる。

### #3【重症度 2】削除の束を「錨の始まりの時刻」だけで組む穴 —— 関係の無い削除で連邦が丸ごと消え、保存できなくなる

  - H1a: b の連邦入りを 1250 年へ直す → a を消す → F は 1250 年から b を持つのに系列ごと消え、b は消えた F を指す（保存が止まる）。

  ただし削除がそれを **「連邦を丸ごと消す＋保存できない」へ増幅する**。影響の板は F を「自動で消える」と数えるので黙ってはいないが、無関係な Z を消すのに連邦が消える理由は利用者に分からない。

  少なくとも、剪定で系列ごと消すまとめ役を指す子の `parentId` は、どの束でも外す（保存が止まる形を作らない）。

### #6【重症度 2・増分 7 以前から】頂点を揃える修復は、年をまたいで全部の錨を 1 つの座標へ揃え、正しく動かした頂点の記録を巻き戻す

- 場所: `src/domain/persistence/repair.ts:472-520`（`reconcileVertexCoordinate`）
- 再現（`vertex.probe.test.ts`、記録 `vertex.log`）: A の角 a2 は 1000 年 (10,10)・1500 年 (12,12)（`vertex-carry-forward.ts` の注記どおり、同じ頂点 id が年で別の場所を指すのは正常な形）。
  1500 年に B との共有頂点 a1 だけが食い違う。修復を当てると「解決」と出るが、**食い違っていない a2 の 1500 年の座標まで (10,10) へ戻る**。
- 内容: 司令塔の問い「使われている版を正、に変えたことが別の不具合を生まないか」への答え: **この変更が新しく生んだ不具合は見つからなかった**。
  新しい規則が変えるのは「最初に見えた版がどの地物にも使われていないとき」だけで、上の巻き戻しは旧規則でも同じ結果になる（どちらも 1000 年の版が最初）。
  ただし、修復は時刻ごとに検出した食い違いを **時刻を見ずに全錨で**揃えるので、もともと「削除以外でデータが変わる」形である。既定の修復の見直し（裁定 (b)）の範囲として報告する。
  なお、使われていない版も時刻ごとの頂点の束では後勝ちで画面の形を決めうるので、「使われていない版は座標の根拠にならない」という注記は厳密には正しくない（画面で見えていた形と修復後の形が変わりうる）。重さは 1 相当。
- 直し方の案: 正とする版の選び方を「その食い違いが出た時刻に効いている錨のうち、使っている版」にし、書き換えも **その時刻に効いている錨だけ**に限る。

## 確かめて問題が無かったもの

- **V14 (a) を実データで**: 開く → 保存 ×2 → 以前の保存から開く → 行 → 未保存の確認 → 開く。アプリバー・タイトルに「世代から復旧・保存先は未確定」、自動保存は待機、Ctrl+S は名前を付けて保存へ落ち、世代も元のファイルも書き換わらない（A1・C1・D4・G1 の途中で毎回確認）。
- **② 取り消し**: 地物を 1 つ消して保存 → 消す前の世代へ戻す → 「元に戻す: 不可」、Ctrl+Z ×3 でも地物数は 775 のまま（消したあとの状態は蘇らない）。未保存の印も付かない（G1、写真 `shots\G1-01-after-undo.png`）。
- **④ 保存して開き直す**: 戻す → プロジェクト名を変える → Ctrl+S（名前を付けて保存で rescued.gimoza）→ 起動し直して開く → 名前が残っている。保存後は自動保存が効く状態になり、rescued.gimoza 側に世代ができる（D4）。
- **id の照合**: `openBackup` を直に叩いて、世代のパス・数・物・`'__proto__'`・空文字・一覧を作り直す前の id は、すべて読まずに断られた。返る行の鍵は `id, savedAtMs, byteSize, featureCount, sourceName` の 5 つでパスを含まない（D5）。
- **V12 の④**: ［適用］はその場で効き（D1 の保存で世代数が変わる）、ふつうに書ける環境では再起動後も残る（G2 の前半）。
- **一覧の板の大きさ**: 100 行でも板の中で縦に流れ、［やめる］は画面内（B1）。

## 総合判定: **revise**

重症度 3 が 2 件ある。

- 3-1 は、世代を開くための確認の途中で、利用者が選んだ世代そのものが消える。所有者の原則に反し、取り返せない。主プロセスで「一覧で渡した世代は刈り取らない」を 1 つ足せば直る。
- 3-2 は、増分の題目（壊れたときに戻せる）の一番素直な場面で世代に辿れず、しかも「無い」と言う。設計にも書かれていない場面なので、直し方（失敗したファイルを一覧の対象として覚える／別のファイルの世代を選ばせる）は司令塔か所有者の判断が要る。

重症度 2 のうち 2-1・2-2・2-3 は、どれも「世代や元のファイルが黙って消える・上書きされる」型なので、3-1 と一緒に直すのがよい。
2-4 は取り込みで本体の並びが勝てば既定は直るはずだが、固定する検査を取り込みと同時に足すこと。

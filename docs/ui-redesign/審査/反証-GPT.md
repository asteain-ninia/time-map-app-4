## 0. 結論

P3「時間軸中心」と「編集時刻の一本化」という方向は妥当である。`PropertyPanel.tsx:296` → `edit-intent.ts:75` → `App.tsx:3041-3064` → `anchor-series.ts:452-486` の経路、および `applyPastEdit` が同時刻なら差し替え、なければ有効な姿を引き継いで新しい錨を作ることも確認できた。

しかし、現状の設計書のままでは次の理由で成立しない。

1. 「読むだけ」の鍵と既存の `canEdit(mode)` が状態機械上で接続されておらず、K-6 を守れない。
2. V6 の親変更とプロパティ保存が、既存の別々の編集経路を一つの操作として扱っている。
3. V8 の複数地物の所属変更は、単一対象しか受け取らない現在の UI フックにつながらない。
4. V14 のバックアップ一覧・復元には新しい main/preload/IPC 境界が必要だが、実装計画から丸ごと落ちている。
5. 5 万錨について速さを規定したのはレールの canvas だけで、そこから開く錨表は全件 DOM 描画のままである。
6. V1、V2、V4、V5、V9、V11、V12、V13、V15にも、手順の矛盾または未定義箇所がある。
7. 実装増分3・4が、増分5で初めて作るオプションバーを先に使用しており、依存関係図どおりには独立出荷できない。

severity 3 以上が複数あるため、verdict は `revise` とする。

所有者裁定との関係は次のとおり。

- モード削減そのものは裁定1に適合する。問題は削減後の権限表現である。
- 錨レーンを選択中の1地物だけに限った点、自分で置く栞を戻していない点は裁定2に適合する。
- ただし5万錨の「レールから一覧へ進んだ後」が無制限で、裁定2(b)を画面全体としては満たさない。
- 削除方針のN-3は、現行方式と拒否方式の具体例、推奨、方針中立の器まで書かれており、裁定3への回答として概ね合格である。

## 2. K-1〜K-9、U-*、T-*の反証

### B-01 K-6の自己申告は誤り

設計は鍵を独立した軸Xとしながら、内部 `mode` を「面・線・点ならadd、それ以外はedit」とだけ導出している（`02-設計書.md:555-575`）。この式には鍵が閉じている状態の `View` がない。

一方、既存の権限判定は `mode !== EDIT_MODE.View` だけである（`src/ui/shell/permissions.ts:24-25`）。設計どおりなら「読むだけ」で選ぶ道具を持っていると `mode=edit` となり、`canEdit` は真になる。

さらに、`EDITING_COMMANDS` には削除がすでに入っている（`permissions.ts:35-42`）。設計書A.1と実装計画増分1の「削除を集合へ加える」は現状認識が誤っている（`02-設計書.md:75`、`03-実装計画.md:57`）。本当の抜け道は、プロパティ欄の削除ボタンがコマンド有効判定を通らず `onDeleteFeature` を直接呼ぶことにある（`PropertyPanel.tsx:437-445`）。

同様にプロパティ入力は各部品が `mode !== View` を個別に判定している（同 `326-329,364-388`）。「一つの関門をそのまま使う」という自己申告はソースと一致しない。

- severity: **4**
- 修正: `editingLocked` または `canMutate` を独立した権限軸にし、導出式を `locked ? View : addTool ? Add : Edit` とする。全ての変更経路を同じ能力オブジェクトまたはコマンド関門へ通し、メニュー、キー、右クリック、地図ドラッグ、道具、プロパティ保存、削除を表形式で全検査する。

### B-02 K-2の対象部品が漏れている

J.1は新しい地図内部品をズームと縮尺の2つだけと数えている（`02-設計書.md:1177-1179`）。しかしV9にはクリック位置の脇に出る頂点候補一覧がある（同 `802`）。これは押せる地図上部品であり、K-2の検査対象である。

分割の番号札、吸着表示、測量線の右クリック対象、道具の対象表示も含め、固定部品だけでなく一時的に現れる部品の一覧が必要である。「2つだけ」という前提の `elementFromPoint` テストでは事故を防げない。

- severity: **4**
- 修正: 地図上に現れる全固定・一時部品を台帳化し、外枠、操作可能矩形、`pointer-events`、`mapOverlay`所属を定義する。状態ごとに地図上の格子点を `elementFromPoint` で走査する。

### B-03 K-5と時刻変更時の下書き

D.2は時刻が変わっても図形の下書きを保持し、「記録する年」だけ変える（`02-設計書.md:590`）。1500年で描き始め、途中でレールを1200年へ動かすと、同じ下書きが無確認で1200年の地物になる。

文字入力には破棄確認を足すのに（同 `701-702`）、より大きな変更である図形下書きの記録年変更には確認がない。時間中心設計の安全性と矛盾する。

- severity: **3**
- 修正: 下書き中はレールを無効にして理由を出すか、「1500年で始めた描きかけを捨てて1200年へ移動しますか」と確認する。下書きを別の年へ黙って移さない。

### B-04 U-5とfocusOwnerの優先順位が矛盾する

Escの階段は「下書き → 手順対象 → ダイアログ」の順である（`02-設計書.md:637-653`）。一方、`focusOwner` 表ではモーダルが開いていればEscはモーダルを閉じる（同 `657-664`）。

下書きの上に確認ダイアログが出た状態でEscを押すと、階段どおりなら背後の下書きを変更し、focusOwnerどおりならダイアログを閉じる。両方は実装できない。

- severity: **3**
- 修正: 見た目の最前面を優先し、モーダル → 文字入力・ポップオーバー → 道具の下書き → 頂点選択 → 地物選択 → 道具解除の順に統一する。

### B-05 U-18を無裁定で3択へ変えている

U-18は一覧を1枚とし、「現在時刻／通史」を切り替える裁定である（`01-現状分析.md:607`）。設計は「この年に変わったもの」を第3の母集団として追加し、自己点検では趣旨に適合するとしている（`02-設計書.md:451,1208`）。

世界全体の錨を軸から落とした代替は必要だが、直接裁定された2択を3択へ増やすことは自動的な適合ではない。

- severity: **3**
- 修正: 「この年に変わったもの」を現在時刻側の絞り込み条件として置くか、所有者の明示裁定を取る。

### B-06 U-25/U-26は適合確定ではない

960〜1119pxでは中心経度を1ボタンに畳み、入力部品を下向きポップオーバーに入れる（`02-設計書.md:284-289,1215-1216`）。U-26は地図に重ねず上部の帯へ置くという直接裁定である（`01-現状分析.md:616`）。設計自身も文字どおりなら違反すると認めている。

- severity: **2**
- 修正: 幅だけで決まる非地図行を確保するか、32px帯内で横方向に開く。所有者裁定までは「適合」としない。

### B-07 markedFeaturesの時刻変更後の再検証がない

D.2は時刻変更時にアクティブ地物だけを存在確認し、マーク集合は保持する（`02-設計書.md:582-591`）。別の年に存在しない地物IDをマークしたまま連邦化・結合を実行できる。

- severity: **3**
- 修正: 時刻、プロジェクト、削除、絞り込みの変更時にマーク集合を再検証し、外れた件数と理由を状態行へ出す。

### B-08 T-*と視覚回帰の扱い

計画は「各増分の終わりでテストを全部緑にする」としつつ（`03-実装計画.md:11-15`）、視覚回帰4枚を増分8まで無効化する（同 `28`）。無効にした検査を「緑」とは呼べない。特に増分4・5は画面構造そのものを変えるので、ここで回帰検査を外すと独立出荷の根拠がなくなる。

- severity: **3**
- 修正: 各増分で意図的に変わる基準画像だけを同じ増分で更新し、無関係な画像は継続実行する。一時無効化する場合は、その増分を出荷可能と数えない。

### B-09 技術方針の正本が更新対象にない

`docs/技術方針.md:239-240` は「保存時の編集時刻は選択中の錨の開始時刻」と明記している。設計案Aを採るとここが逆になるが、増分2の変更対象に技術方針・要件裁定記録がない（`03-実装計画.md:109`）。

- severity: **2**
- 修正: N-2裁定後、FR-57とFR-84の優先関係、技術方針§6.4、開発ガイドの編集時刻契約を同じ増分で更新する。

### 適合と判断できる項目

- K-1: Electron標準メニューを復活させない。
- K-3: 選択有無に依存しない固定枠という方針は適合する。
- K-4: 道具入力を `mapOverlay` に限定する。
- K-7: 判断メッセージを無関係な操作で消さない方針。
- K-8: 単一起動・終了ガードを維持する。ただしV14も同じ未保存ガードへ通す必要がある。
- K-9: 錨表示、束、マーク、レール表示範囲を保存形式へ足していない。
- U-3: 「錨」を維持している。
- U-4、U-6、U-10〜U-16、U-19〜U-24、U-27〜U-30: 本文上は維持されている。

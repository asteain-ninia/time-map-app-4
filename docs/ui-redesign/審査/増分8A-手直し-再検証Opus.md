- **根拠**（実データ＋App と同じ組み方。探針 `anchors.probe.test.ts`。場合 1・2 は記録 `anchors2.log`、対照の錨ごとの座標は 1 回目の記録 `anchors.log`（A＝area-002・B＝area-032 の組。同じ T 字も出ている））:

  - 場合 1: 3500 年で B の（共有でない）頂点を少し動かす（B にだけ 3500 年の錨ができる）→ 3000 年で共有辺の中点をクリック。

  - 場合 2: 逆に A にだけ 3500 年の錨がある場合は、3600 年で **A `v49→v48`／B `v48→nv→v49`**（向きが逆の T 字）。動かすと同じく裂ける。

  - 単体の 192 行の 1 本は、A が錨 1 つ（0 年から先ずっと）・B が 50 年に錨、という形で、60 年に「A には new-1 があり B には無い」ことを確かめている。これは場合 1 の T 字そのものを正しい状態として固定している。注記の「押した地物の後ろにも無いので揃う」は、押した地物が隣と同じ年に後ろの錨を持っているときにしか成り立たない。

- **内容**: 削除ではないのに、後ろの年の境界の形が利用者の知らないうちに食い違う（所有者の原則「削除以外でデータが勝手に壊れない」に反する側）。見ている年では何も見えないので、気づくのは後ろの年を開いたときになる。
- **直し方の案**: 頂点の移動の引き継ぎ（`applyVertexCarryForward`／`carryVertexForwardIn`）と同じ考え方で、**挿入も後ろへ引き継ぐ**。T より後ろの錨（押した地物の錨も、隣の錨も）のうち、まだ a と b が続けて並んでいて、足した id を引いていない輪には同じ位置へ入れ、その辺が無くなった錨で止める。
  - クリックで足した頂点は辺の上にあるので、後ろの年の形は 1 つも変わらない（記録された歴史を壊さない）。
  - ドラッグで足した頂点は後ろの年の形も変えるが、それは共有頂点の移動の引き継ぎが今すでにしていることと同じである。
  - 合わせて、1637 行の注記と 192 行の単体を直す（「後ろの年でも、両側が同じ頂点を引く」を確かめる形へ。場合 1・場合 2 の両方）。
  - 引き継ぎを入れないと決めるなら、少なくとも注記と単体の名前を事実に合わせ、`docs/現状.md` に B 項目で残すこと。

### 重 2-2 押した地物が同じ辺を 2 つの輪で引いているとき、もう片方の輪に入らない

- **場所**: `src/domain/editing/apply-proposal.ts:1683-1686`（`takes` が `f.id !== editedFeatureId` と `!featureReferences(f, insertedId)` で、**地物ごと**に外している）
- **根拠**（探針 `edgeinsert.probe.test.ts`・`detail.probe.test.ts`、記録 `edgeinsert.log`）:
  実データ 3000 年で、同じ地物の中で 2 回引かれる辺が 29 本ある（すべて area-053 の穴どうし。例: 穴 h8 と穴 h9 が辺 v23827–v23828 を共有）。
  area-053 を選んで穴 h8 のこの辺の中点をクリックすると、足した頂点は h8 にだけ入り、**h9 には入らない**（クリック 18 件・ドラッグ 18 件で同じ。抽出の偏りで件数は多めに出ている）。
  隣の飛び地（穴に対応する子の地物）のほうは、別の地物なので正しく入る。結果として area-053 の穴 h9 だけが真っすぐのまま残り、足した頂点をあとで動かすと、h9 と飛び地の境界が食い違う。
- **内容**: 重 2-1 と同じ種類の T 字が、押した地物の中に残る。起きるのは「隣り合う穴（＝隣り合う飛び地）の境目を、親の側から押したとき」に限られるので狭い。
- **直し方の案**: 外す判定を地物単位から**輪単位**へ。押した地物も対象に含め、「その輪がまだ a と b を続けて並べている」ときに入れる。押した輪はもう a と b が並んでいないので `edgeIndexFor` が自然に飛ばし、二重には入らない。`featureReferences` で地物ごと外している所も同じ理由で輪単位にできる（吸着が共有に変わった先の id を、隣が別の輪で既に引いている場合）。単体に「穴どうしが辺を共有する親の、片方の穴の辺に足す」を 1 本足す。

### 重 1-1 ±360° の複製の上で中点をクリックすると、経度が ±180° の外のまま保存される

- **場所**: `src/ui/map/edge-click.ts:43-49`
- **根拠**（`edgeinsert.probe.test.ts` の click+360、`detail.probe.test.ts`）: 複製の上（+360°）でのクリック 82 件のうち 81 件で、足した頂点の経度が 538 などの値で保存された（隣の輪にも同じ体が入る）。手直し前から、**辺からドラッグして足す経路でも複製の上なら 354 のまま保存される**（同じ探針で確認）。一方、既存の頂点のドラッグは複製の上で掴んでも元の巻き（−5.78）へ戻して保存する。
- **内容**: 描画の層は連続の経度を扱える作り（`render/vtransform.ts` の注記）で、確定の関門も通るので、壊れた所は見つけていない（**未確認**: 書き出し・吸着の座標比較など、±180° の内側を前提にした所が残っていないか）。ただ、実データには ±180° の外の頂点が 1 つも無いので、編集の経路によって新しい形のデータが生まれる。
- **直し方の案**: 足した頂点は「辺の始点の巻き」へ寄せて保存する（始点の経度＋最短の差）。確定の関門は押した点と比べるので、関門へ渡す前に巻きを戻すか、関門の比較を最短の差で行う。頂点のドラッグ（畳んで保存）と揃える。急がない。

### (3) ドラッグ中の Escape

- 窓の捕捉段で Escape を聞く所は、ほかに右クリックのメニュー（地図・時刻レール）とメニューバーがある。地図の聞き取りは「進行中の選択・編集の押下があるときだけ」取り消して食べ、無ければ何もしない（`mount/input.ts:273-279`）。板を開いたまま地図を押すと、押した時点で鍵盤の持ち主が板から地図へ移る（板は閉じた扱いになる。探針で確認。板の要素そのものが消えたかは見ていない）。右クリックのメニュー・メニューバーを開いたまま押下を続ける場面は試していない（**未確認**）。
- 探針 `escape.probe.spec.ts`（記録 `e2e-escape-probe.log`。3 本とも通過）:
  - 深さ ▾ の板を開いたまま頂点を押す → 押した時点で鍵盤の持ち主は地図に移る。ドラッグ中の Escape 1 回目は取り消しだけ（選択は残る）、押したままの 2 回目は階段の 1 段目（頂点の選択を外す）へ進む。離しても何も確定せず、そのあとの Escape は地物の選択を外す。
  - 矩形選択の途中で Escape → 枠は捨てられ選択は変わらない。離したあとの Escape 2 回で頂点 → 地物の順に外れる（階段は 1 回 1 段のまま）。
  - 一覧の絞り込み欄に打ってから地図の頂点を押す → 焦点は欄から外れ、Escape はドラッグの取り消しに使われ、欄の文字は残る。
- 既存の Escape を使う spec（`inc5-shell`・`edit-handles`・`edit-drag-preview`・`fr80-multi-vertex-drag`・`context-menu`・`snap-share-fixes`・`display-filter`・`depth-control`）を単独で流し、69 本すべて通った（`--workers=2`）。
- 階段を奪う場面は見つからなかった。押下の記録が何かの理由で残ったままになると、次の Escape を 1 回だけ食べる作りではある（**未確認**: 残る経路は見つけていない。地図の外へ出たら `pointerLeave` で全部捨てる）。

### (4) 経度 180° 近くの中点

## (2) 手直しが新しく入れたものは別の不具合を生んでいないか

### 指摘 1（重症度 2）始点を置いた途中で線を消すと、Ctrl+Z が効かず、画面の案内どおり Esc を押した直後の Ctrl+Z が関係のない編集を取り消す

**場所**
- `src/domain/survey/survey-state.ts:224`（`cancelDraft` が下書きを取りやめたときに `forgetRemovedSurveyLine` で覚えを捨てる）
- `src/ui/shell/useShortcuts.ts:167-181`（下書き中は大域の打鍵が止まり、`tool-drawing` の持ち主では断りも出さない）
- `src/ui/survey/SurveyToolController.tsx:123-134`（下書き中の Esc → `surveyCancelDraft`）
- `src/ui/survey/strings.ts:101`（下書き中の次の一手「もう一度クリックして終点を指定してください（**Esc で測るのをやめます**）。」）

**再現（E2E 探針 Q3。実物で確認済み）**
1. 面 A・B を描く → 「📏 測る」→ 線を 1 本測る。
2. 次の測量の始点を 1 つ置く（下書きあり）。
3. 既にある線を右クリック →「この線を消す」。状態行「測量の線を消しました［戻す］」。
4. `Ctrl+Z` → **何も起きない**（線 0 本・地物 2 件・［戻す］は残る。下書き中で大域の打鍵が止まっている。断りも出ない）。
5. 次の一手の案内どおり `Esc` → 下書きが消え、**同時に覚えが捨てられて［戻す］も消える**（文だけ残る）。
6. もう一度 `Ctrl+Z` → **線は戻らず、地物が 2 件 → 1 件**、状態行「元に戻しました: 地物の追加」。

**内容**
- 反証 #2 と同じ「線を戻すつもりの Ctrl+Z が、関係のない直前の編集を取り消す」が、**下書き中に線を消したときの、いちばん自然な立て直しの手順**（Ctrl+Z が効かない → 案内の Esc → もう一度 Ctrl+Z）でそのまま起きる。
- 手直しの記録（§12.2 の 3）は「始点を置いた途中は Ctrl+Z は何も起こさない ―― ［戻す］で戻す」としているが、［戻す］は Esc を押した瞬間に消える。また Ctrl+Z が黙って何もしないので、利用者が［戻す］に気づく前に Esc を押す流れは起きやすい。
- 範囲そのもの（「次の測量の操作で捨てる」）は依頼書の指示どおりで、`cancelDraft` を「測量の操作」に数えたのは実装者の判断（README B-3 に戻し方つき）。ただし **下書きの取りやめは線を 1 本も増やさない** ので、覚えを捨てて守るもの（新しく測った線と、戻した古い線の取り違え）が無い。
- 被害は Ctrl+Y で戻せ、状態行も何が戻ったかを言うので重症度 3 ではない。

**直し方の案**
- (a) いちばん小さい: `cancelDraft` で覚えを捨てない（`survey-state.ts:224` の `forgetRemovedSurveyLine` を外し、`withDraftDiscarded` だけにする）。点を置く・クリア・測るの入り切り・持ち替えでは従来どおり捨てる。単体 `survey-state.test.ts` の「下書きの取りやめで捨てる」の期待と、設計書 §E.1 V15・README B-3 の「下書きの取りやめ」を直す。E2E に「始点を置いた途中で線を消す → Esc → Ctrl+Z で線が戻る・地物は減らない」を足す。
- (b) (a) に加えるなら: 下書き中の Ctrl+Z が覚えのあるときは線を戻す（止めている間の通す集合に条件つきで入れる）。ただし下書き中の打鍵の割り振りに触るので、Esc の階段と一緒に決める増分（B64 と同じ置き場）でよい。

### 指摘 2（重症度 1）`U` で測るを終えると覚えが捨てられ、直後の Ctrl+Z は地物の取り消しになる

- 再現（Q4）: 線を消す → `U`（焦点は本文。効いて測るを終える）→ `Ctrl+Z` → 地物 2 → 1、線は戻らない。［戻す］は `U` の時点で消える。
- 「測るの入り切りで捨てる」は依頼書の「測量の操作・道具の持ち替えで捨てる」の範囲内で、記録どおりの動き。指摘 1 ほど反射的な流れではないので 1 に留める。指摘 1 を (a) で直すなら、同じ理由（線を増やさない）で `disableSurveyMode` も捨てない形にするかを一緒に決めるとよい（未確認: 所有者の好み）。

### 指摘 3（重症度 1）状態行の［戻す］を押すと焦点が状態行に残り、`U` が効かなくなる

- 根拠（コードを読んだだけ。未実行）: ［戻す］は `button` で、押すと焦点が `.statusbar` の中に移る。`focusIsOnMap` は `.map-area`・`.toolbar`・本文だけを「地図」とみなすので、地図を一度押すまで `U` は黙って効かない（打鍵も飲まない）。
- 設計書 §I.2 の近似（§12.2 の 6）の範囲内の動きで、オプションバーのボタンを押したあとも同じ。直すなら［戻す］の `onClick` の最後で `blur()` する程度。8E の見た目・打鍵の点検へ。

### runUndo の分岐で確かめたこと（問題なし）

- **地物の取り消しを飲み込む場面**: 編集の経路はすべて `recordCommand` → `applyCommandResult`（`App.tsx:1367-1390`）を通り、そこで覚えを捨てる。取り消し／やり直しは `applyUndoRedoResult`、道具の持ち替え・鍵の切り替えは `setActiveTool`・`setMode`、読み込み／新規は `survey: initialSurveyState()`（`store.ts:1546`・`2343`）。`forgetRemovedSurveyPatch` は各 `set()` の最後に展開されるが、どの差分も `survey` を別に書いていないので上書きの食い合いは無い。**編集を挟んだのに覚えが残る経路は見つからなかった。**
- 残るのは記録どおりの「捨てない」場面（選択・パン・時刻の移動のあとの Ctrl+Z は線を戻す）で、そのときも状態行に「測量の線を戻しました」が出る。
- `EditUndo` の `canRun` が覚えで「可」になっても、読むだけでは `resolveCommandEnabled`（`permissions.ts:96-100`）が編集のコマンドとして先に閉じるので、メニューが「可」に見えて押せない食い違いは起きない。
- 線を戻したあとの Ctrl+Y は従来どおり地物のやり直し（取り消しの記録には触っていない）。

### 二重クリックの飲み込み（メニューの全項目）で確かめたこと（問題なし）

- Q5・V・W（実物）: 項目を押した直後（14〜37ms）に **同じ場所で右クリック** → メニューは開く（右ボタンの押下は見張りを解くだけ）。項目を押した直後に **20px 離れた左クリック** → 測量の点が置かれ、続く 1 点で線が測れる。**同じ場所でも 650ms 後** の左クリックは始点になる。鍵盤（Enter）で押した項目の直後の右クリックも開く。反証の P4（二重クリック）はいまは線 0 本・始点なし。
- 参考（指摘ではない）: 最初の Q5 は、項目のクリックの直後に **メニューが閉じ切る前に** 右クリックを送ったため開かなかった。これは手直し前からある「メニューが開いているあいだの右クリックは閉じるだけ」（`App.tsx:2709-2717` の段階7 の設計）によるもので、飲み込みは右ボタンを止めない（`MapContextMenu.tsx` の `onDown` は `button !== 0` なら見張りを解くだけ、`contextmenu` は止める対象に無い）。閉じ切るのを待てば 0ms でも開く（W1・V1）。
- 未確認: 項目が開いた板のボタンが、押した項目から 4px 以内に来る配置。影響の板は画面の中央に出るので、実際には起きにくい。

### `U` の焦点の関門で確かめたこと

- 関門は `useShortcuts` の通常の経路だけにあり、入力欄・止めている間の経路より後。メニューの項目から選べば焦点に依らず効く。`.toolbar`（左のレール）・`.map-area` の class は実在する。E2E の「時刻レールのボタンに焦点があると効かない」は通過。押しっぱなしの 2 打目は `preventDefault` して走らせない（`Ctrl+Z` の押しっぱなしは対象外）。

## 総合判定: **revise**（小さい）

重 3（線の上の右クリックの相手）は塞がり、重 2 も素直な流れでは塞がった。GPT の 5 件の直しはどれも妥当で、新しく入れたボタン・焦点の関門・二重クリックの飲み込みに別の不具合は見つからなかった。

ただし **指摘 1（重症度 2）**: 始点を置いた途中で線を消すと Ctrl+Z が効かず、画面の案内どおり Esc を押した直後の Ctrl+Z が関係のない編集を取り消す ―― 反証 #2 と同じ形が、いちばん自然な立て直しの手順で残っている。原因は `cancelDraft` が覚えを捨てることで、捨てて守るものが無いので 1 行で直せる（直し方の案 (a)）。依頼書の「測量の操作で捨てる」を文字どおりに読めば記録どおりの動きなので、司令塔が依頼書の文言を優先するなら、accept にして 8E へ申し送る扱いでもよい。私は「線を消した直後の Ctrl+Z を地物の取り消しへ流さない」という依頼の目的を優先して revise とした。

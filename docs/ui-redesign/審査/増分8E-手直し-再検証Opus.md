### 3-1. 選択を外す・居ない年へ動くと覚えだけが消え、そのあと ON → OFF と往復すると打った色と透過が消える（重症度 3）

  3. (a) 1000 年（面が居ない年）へ動く、または (b) 地図の空いた所を押して選択を外す → 「打ちかけ」の確認が出る →［残す］で元へ戻る。色の欄は `#123456` のまま。
  4. ［自動配色を許可］を入れて、すぐ外す。
  5. 結果: 通常表示色が `#4e79a7`（地図にいま塗られている自動配色の色）、透過が 0.7 に戻る。**打った `#123456`・0.3 は黙って消える**。

## 5. 縦横比の補正の画素の保全（重点 5） — `aspect-pixels.probe.spec.ts`

`padImageToTarget`（`basemap-aspect.ts:139-165`）と同じ手順を、アプリの renderer（Electron の Chromium）の中で走らせ、出てきた PNG を node で解いて元の画素と比べた（30×20 → 40×20、余白は左右 5 画素）。

| 元の PNG | 元と違う画素 | 最大差 | 余白 |
| --- | --- | --- | --- |
| 不透明・色空間の印なし（手直しの E2E と同じ型） | 0 / 600 | 0 | 全部透明 |
| 不透明・gAMA 1/2.2（sRGB 相当） | 0 / 600 | 0 | 全部透明 |
| 16 ビット・不透明 | 0 / 600（8 ビットへ落ちる。上位 8 ビットは同じ） | 0 | 全部透明 |
| 半透明（α=1〜254 を散らす） | **450 / 600** | **124**（α が小さい画素ほど色が崩れる。α=1 の色は 0,0,0 になる） | 全部透明 |
| 不透明・gAMA 1.0 | **600 / 600** | **72**（色空間の変換が画素へ焼き込まれ、gAMA の印は落ちる） | 全部透明 |

### 1-2. 半透明の画素と色空間の印つきの画像は、補正で画素が変わる（重症度 1）

- 場所: `src/ui/file-ops/basemap-aspect.ts:149`（`createImageBitmap` を既定の設定で呼ぶ）・`:157`（2D の canvas に描いて書き出す）
- 内容: 不透明でふつうの画像は 1 画素も変わらない（手直しの E2E のとおり）。半透明の画素は 2D の canvas が α を掛けた値で持つので、α の小さい画素の色が崩れる。gAMA・色の印つきの画像は、変換した色が画素に焼き込まれる（地図に描いたときの見た目はほぼ同じ）。背景の世界地図で半透明・色の印つきの画像は多くないので、重症度 1 とした。板の文「画像そのものは縮めません」は寸法の話としては正しい。
- 直し方の案: `createImageBitmap(blob, { premultiplyAlpha: 'none', colorSpaceConversion: 'none' })` で変換を減らす（2D の canvas が α を掛けて持つことは避けられないので、完全に守るなら PNG の行を直接並べ替える）。少なくとも進捗の「画素を保つ」の言い方を「不透明な画像では」に絞る。

## 7. 重点ごとの答え（まとめ）

1. **G-14**: 正当な編集を誤って断る場面は、実データ（壊さないまま 6,206 回＋縁の 640 回、壊してから 2,720 回）では 0 件。環の id が変わる操作（分ける・結ぶ・くり抜く・重なり解決・取り消し・やり直し）でも誤って断らない。誤って断るのは「完全に外の穴・飛び地を戻す途中」だけ（2-1）。新しい破損を通す場面は見つからなかった（同じ組の同じ種類の違反がさらに悪くなる場合だけは通るが、これは決め事どおり）。
2. **自動配色の覚え**: 選択を外す・居ない年へ動く →［残す］→ ON → OFF で、打った色と透過が消える（3-1、重症度 3）。
3. **詳細パネル**: まとめ役の子・深さで畳まれた地物・錨表での年の移動とも、裁定どおりに開閉する。指摘なし。
4. **ホイール**: 400 ms のまとまり・脇の文の消え方とも期待どおり。文の数字の細かい点だけ（1-1）。
5. **縦横比の補正**: 不透明でふつうの画像は 1 画素も変わらない。半透明・色の印つきは変わる（1-2）。

## 2. 指摘

### 2-1. 頂点の削除が関門で断られても、何も言わない（重症度 2）

- 場所: `src/ui/vertex-delete.ts:279`（`if (result.status !== PROCESS_STATUS.Committed) return; // Rejected: keep selection.`）、`src/ui/App.tsx:4253-4257`（削除の確認の［消す］）、`src/ui/ring-hierarchy-gate.ts:43`（文）

  8E はドラッグの経路（`hit-test.ts:420` → `announceEditRejectionRef`）にだけ理由を出す口を足しており、進捗 §2 の「断ったとき…黙って元へ戻るだけだったので、理由を状態行へ出す口を足した」は削除の経路では成り立っていない。

### 2-2. 断った理由が「どの面・どの年が壊れるか」を言わない（重症度 2）

### 2-3. まとめ役の子の詳細パネルは、関係のない編集のたびに閉じる（重症度 2・8E 以前から・画面では未確認）

### 2-4. 縦横比の「補正」は背景の絵を地物に対してずらすのに、板の文がそれを言わない（重症度 2）

- 場所: `src/ui/file-ops/basemap-aspect.ts:95-96`（`explainCorrectable`）、`:117-144`（`padImageToTarget` は中央に置いて周りを透明にする）、`src/ui/file-ops/basemap-replace.ts`（範囲 `meta` は現行のまま）

  一方、板の文は「画像の足りない側に余白を足して 2:1 にします（**画像そのものは縮めません**）」で、画素の話としては正しいが、地図の上での位置が変わることは読み取れない。差し替えは取り消しの対象でもない（`replaceBaseMap` は履歴に入らない。8E 以前から）。

- 直し方の案: 文を「補正すると、画像は地図の中央に寄せて描かれ、端に何も無い帯ができます。いまの地物とは位置が合わなくなることがあります。このまま使うと、地図いっぱいに引き伸ばして描きます。」のように **地図の上で何が起きるか** で書く。裁定で引き伸ばしを既定にするなら、2:1 に近い画像（例: 4096×2100）では補正を勧めない形もある。

## 3. 重点ごとの答え

### (1) G-14 の誤った拒否・見逃し

- 正当な編集を誤って断る場面: **見つからなかった**。実データの頂点移動 6,206 回・縁に据えたドラッグ 640 回で 0 件、合成の重なり解決の差し引き 3 形も通った。
  分ける・結ぶ・くり抜くは関門が掛かっていないので、誤って断ることもない。取り消し・やり直しは状態をまるごと入れ替える命令で、関門を通り直さないので、やり直しで断られることもない。
- 壊れた形を通す場面: 実データでは 0 件。通るのは「前から壊れていた面」（1-1）と、関門が掛かっていない分ける・結ぶ・くり抜くの結果（未確認）だけ。
- 速さ: 確定 1 回で最大 53 ms（実データ）。
- 確かめていないこと: 穴が親と頂点を共有している（穴が外周に頂点で接している）ときの、その共有頂点のドラッグ（探針 `clamp` では除いた。関門の通り道は同じ）。

### (2) 縦横比の補正で既存の地図がずれないか

地物の座標・保存・開き直しはずれない（2-4 の根拠）。ずれるのは背景の絵と地物の重なり方で、それを板の文が言わない（2-4）。

### (3) 詳細パネルの 3 契機

削除・年の移動・開き直しの直しは、コードの上では筋が通っている（年は現在時刻の購読、開き直しは `projectLoadNonce`）。ただし前からある掃除の穴で、まとめ役の子のパネルは関係のない編集で閉じる（2-3）。

### (4) 「描きかけを捨てますか」の直しが、打ちかけを黙って捨てるようになっていないか

- 追加の道具: 止まっている間（`ConflictPaused`）を打ちかけと数えなくしたことで捨て方が変わる経路は、**重なり解決の［キャンセル］と［適用］の後の構え直しだけ**である。重なり解決の板の背面は画面全体を覆い（`.app-shell__overlay` の `inset: 0` の中の `conflict-backdrop`）、鍵盤も板が持つ（`App.tsx:2876` の `modalOwnsKeyboard`）ので、止まっている間に道具の持ち替え・年の移動・選択の変更は起きない。
  ［キャンセル］では止まっていた 4 頂点と打った名前が捨てられる（8E 以前から同じ）。以前は「描きかけの頂点 4 個を捨てました」、いまは「重なりの解決をやめました。止まっていた編集は記録していません。」で、**黙ってはいない**。「捨てた」と言わなくなった点は文言の総点検（8E 後半）で見ればよい。
- B76（分ける・穴あけ・輪郭の道具）: **コードを読んだ限り起きない**。分けるは名前を入れる局面（`EnteringProperties`）から確定するので止まっている間の分断線の数は 0、くり抜くは止まっている間 `DRILL_FLOW.ConflictPaused` なので数は 0、輪郭（穴の追加・削除）は確定に素の ports（重なりの検出が空）を使うので止まること自体が無い。結ぶ・所属変更は共通の見張り（`useDraftSwitchGuard`）を使っていない。B76 はこの理由で閉じてよい（画面では未確認）。

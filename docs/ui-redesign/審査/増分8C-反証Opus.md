## 指摘

### 指摘 1（重症度 3）線の上で右クリックすると、メニューの地物の項目が「押した地物」ではなく「いま選んでいる別の地物」に向く

**場所**
- `src/ui/map/live-context-menu-port.ts:168-180`（線に当たったら昇格しない）
- `src/domain/context-menu/compose.ts:239-251`（メニューの相手は `selection.activeFeature`。押した点 `hit` は相手を決めない）
- `src/ui/add/host-ports.ts:536-545`（重ね順: 地物 → 測量の線 → **編集の把手（頂点・辺）** → 道具の下書き）
- `src/ui/App.tsx:2089-2119`（「この年に終わったことにする」は確認の板なしで即実行）

**再現（E2E 探針 P1・P3、単体探針 P1-unit）**
1. 面 A（探針A）と面 B（探針B）を描く。B を確定した直後なので B が選ばれている。
2. 「📏 測る」で A の中を横切る線を 1 本測る。
3. 線から 3px の **A の上**を右クリックする。
   - メニューは「この線を消す」「測量を終える」に続いて **B 向けの項目**がそのまま並ぶ:
     `この年に終わったことにする / 全部の年から消す / プロパティ編集 / この年に錨を作る / 分割 / 所属を変える / 結合 / 対象に加える / この地物を非表示 / この地物を強調 …`
   - 選択は B のまま（A は引き上げられない）。項目の文字はどの地物かを言わない。
4. P1:「全部の年から消す」を押す → 影響の板は「『探針B』を全部の年から消します」と言い、確定すると **B が消えて A が残る**（一覧 2 件 → 1 件、残りは「探針A」）。
5. P3: 10 年へ移ってから同じ手順で「この年に終わったことにする」を押す → **確認の板は出ず**、状態行に「『探針B』は10年で終わったことにしました。」。A を押したつもりで B の存続期間が変わる。
6. 対照 P1b: 線から 60px 離れた A の上を右クリックすると、従来どおり A が選ばれる。**線の 8px の帯の中だけ**相手が入れ替わる。

単体探針でも同じ連鎖を確かめた（`hit.probe.test.ts`）:
- 本体の当たり（A）＋線 → 昇格 0 回、メニューの相手は B、項目は `endHere,delete,editProperties,…`。
- **頂点の当たり（A の頂点 va）＋線** → 昇格 0 回、相手は B と **B の選択頂点 vb**、項目は `deleteVertex,…`。
  つまり頂点を直している最中に、線の近くの A の頂点を右クリックして「頂点を削除」を押すと、B の頂点が消える。

**内容**
- 実装者の判断（README B-3 の 1 行目）の根拠は「線は地物より上に描かれていて、押した相手は線」だが、
  **頂点・辺の把手は測量の線より上に描かれている**（`host-ports.ts:542-545`）。把手を押した右クリックでは根拠が成り立たない。
- 本体の場合も、押した相手が線だというなら、**押していない B に対する項目を同じメニューに並べる理由が無い**。
  右クリックの昇格は、まさにこの取り違えを防ぐために入ったもの（`hit-test.ts:462-465` の注記「bughunt5 HOLE-2 —
  後に続く 削除 が別の地物の頂点を誤って相手にした」）で、8C はその型を線の帯の中だけ開け直している。
- 被害は「削除以外でデータが変わる」型（終わり・分割・所属変更の構え・頂点の削除）。Ctrl+Z 1 回で戻り、状態行と削除の板は B の名前を言うので
  気づく手掛かりはあるが、終わりの操作には確認が無く、B が画面外にあると見落としやすい。
- 測量の線は測るのを終えても残る（FR-15）ので、測ったあと線を消さずに編集を続けると、地図のあちこちに「右クリックの相手がずれる帯」が残る
  （全体表示の 1280px なら 1 本あたり幅およそ 5° の帯が 2 本）。
- 現状.md の B65 で ①「測っている間は右クリックでも引き上げない」を選ぶと、この取り違えが測っている間の地図全体へ広がる。B65 の裁定とあわせて決めるべき。

**直し方の案**（どれも小さい）
- (a) **線に当たったときのメニューは線の項目と「見る」側の項目だけにする**（地物の編集・表示制御の項目を出さない）。「押した相手は線」と言い切るなら、
  これがいちばん筋が通る。`MapContextMenu` の `open` で `surveyLineIds` が空でなければ `model` を `null` にするだけで済み、器の形は変わらない。
- (b) **把手（頂点・辺）の当たりは線より優先する**（描かれている順に合わせる）。`probeSurveyLines` を `hit.kind` が頂点・辺のときは呼ばない。
- (a)+(b) を勧める。どうしても線の上で地物の項目も出したいなら、(c) 線に当たっても従来どおり押した地物を引き上げる（線の項目は先頭に残す）のほうが、
  「押していない地物が相手になる」よりずっと安全。
- 検査: 「B を選んだまま線の上の A を右クリック → 地物の項目が出ない（または A が相手）」と「頂点の把手の上の右クリックは線より把手が勝つ」を固定する。

### 指摘 2（重症度 2）線を右クリックで消した直後の Ctrl+Z が、関係のない直前の編集を取り消す

**場所**: `src/ui/state/store.ts:1858-1862`（取り消しの記録に触らない）、`src/ui/App.tsx:1490-1497`（Ctrl+Z はドメインの取り消し）

**再現（E2E 探針 P2）**
面を 2 つ描く → 線を 1 本測る → 右クリック「この線を消す」→ 間違えたと思って `Ctrl+Z`。
結果: 線は **0 本のまま**、地物は **2 件 → 1 件**、状態行「元に戻しました: 地物の追加」。

**内容**
線を消すのを取り消しの対象にしないこと自体（実装者の判断 5）は、［測量結果をクリア］と揃っていて筋が通る。困るのは、**消した直後に人が反射で押す Ctrl+Z が、
線ではなくドメインの直前の編集へ届く**こと。直前の編集が別の年・画面の外にあれば、何が戻ったのかは状態行の 1 行でしか分からない。
［クリア］はオプションバーのボタンで意図して押すが、右クリックのメニューは地物の編集項目と同じ板に並んでいる（指摘 1）ので、「編集を 1 つしたつもり」で
Ctrl+Z を押す流れが起きやすい。これは「Ctrl+Z で元に戻らない瞬間」であり、同時に「別のデータが変わる瞬間」でもある。Ctrl+Y で戻せるが、その間に別の編集をすると戻せなくなる。

**直し方の案**
- (a) 線を消したら状態行に「測量の線を 1 本消しました」と ［戻す］ を出す（直前に消した 1 本だけを覚えておけば足りる。保存はしない）。
- (b) 測量の操作だけを積む小さな取り消しの記録を作り、測っている間は Ctrl+Z をそちらへ回す（大きい。8E 以降）。
- 少なくとも (a)。設計書 V15 の「取り消し: 線ごとに消せる」は「消す操作を取り消せる」とは別の話なので、どちらにするか所有者に確かめる価値がある。

### 指摘 3（重症度 1）2 本以上のときの項目と地図の線が結び付かない

**場所**: `src/ui/survey/survey-menu.ts:31-47`、`src/ui/map/MapContextMenu.tsx:345-361`

交差点で出る「1,234km の線を消す」「1,201km の線を消す」は距離でしか言い分けておらず、項目に指を載せても地図の線は強調されない。
読み取りに出ているのは最後に測った 1 本の距離だけなので、ほかの線の距離を利用者は覚えていない。選び違えると取り消せず（指摘 2）、測り直すしかない。
実装者が裁定に回した「同じ距離に丸まる 2 本」はこの特殊な場合。**直し方**: 項目に指を載せたあいだ、その測量の 2 本を太く描く（`drawSurvey` の style を 1 本だけ変える）。

### 指摘 4（重症度 1）「この線を消す」を二重クリックすると、2 回目が地図へ落ちて測量の始点が置かれる

**再現（E2E 探針 P4）**: 測っている間に線を右クリック → 項目を二重クリック → 線は消え、次の一手が「もう一度クリックして終点を指定してください」になる（始点が置かれた）。
始点が置かれると大域の打鍵が止まるので、続けて `U` を押しても効かない。器の性質（項目を押すとすぐ閉じる）で 8C 固有ではないが、測っている間は 2 回目が測量の入力になるので目立つ。
**直し方**: メニューが閉じた直後の数百 ms は、測量の入力層の左クリックを捨てる（または項目を押したときの `pointerdown` から同じ指の `click` までを飲む）。

### 指摘 5（重症度 1）`U` の押しっぱなしで「測る」と「終える」が交互に切り替わる（未確認）

**場所**: `src/ui/shell/useShortcuts.ts:125-188`（`e.repeat` を見ていない）、`src/ui/App.tsx` の `ToolsSurvey` の登録（切り替え）
コードからの推測で、実機では確かめていない。`U` は「持つ／終える」の切り替えなので、キーリピートの回数の偶奇で最後の状態が決まる。始点を置いた途中ではないので下書きは失われないが、
どちらで止まったかが毎回違う。**直し方**: 切り替えのコマンドは `e.repeat` のとき走らせない。

### 指摘 6（重症度 1）始点を置いた途中は `U` が黙って効かない

実装者が進捗 §2 に書いているとおりで、規則（下書き中は大域の打鍵を止める）には従っている。ただ打鍵の説明（`strings.ts` の `tools.survey`「もう一度押すと測るのを終えます」）と食い違い、
押しても理由が出ない（無言の失敗）。**直し方**: 測量の下書き中は `ToolsSurvey` を `alwaysAllowed` に入れる（測量の道具は自分で `U` を使っていないので二重にならない）。

### 指摘 7（重症度 1）線を消す道が右クリックしか無い

鍵盤だけでは 1 本だけ消せない（右クリックのメニューを鍵盤で開く経路が無い）。V15 の範囲外なので申し送りでよい。

## 総合判定

**revise**

当たり判定そのものは描画と食い違いが無く、純関数・器への足し方・検査もよくできている。ただし指摘 1 は「押していない地物の存続期間や形が変わる」経路で、
しかも以前に直した取り違え（HOLE-2）と同じ型を線の帯の中だけ開け直している。直しは小さい（線に当たったら地物の項目を出さない＋把手は線より優先）ので、
取り込み前に直すことを勧める。指摘 2 は状態行の［戻す］で足りる。重症度 1 は申し送りでよい。

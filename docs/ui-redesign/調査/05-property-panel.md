# 05 プロパティ欄と地物情報の編集（現状調査）

対象: `src/ui/property/*`, `src/ui/coloring/*`, `e2e/sidebar-property.spec.ts`, `e2e/detail-document.spec.ts`。
方法: ソース読解 ＋ 実機観察（`_electron.launch` によるヘッドレス起動、1280×800、E2E_TEST=1）。
スクリーンショットは `docs/ui-redesign/調査/shots/05-*.png`（末尾に一覧）。

用語の言い換え（この文書では日常語を使う）:

- **歴史の錨** = ある時刻における地物の状態まるごとの記録（名前・色・形・親子関係を含む一式）。以下「錨」。
- **存続期間** = その錨がいつからいつまでを担当するか（開始・終了）。
- **編集対象の錨** = 保存ボタンを押したときに書き込まれる先の錨。

### 2.1 保存の契機は 3 系統に分かれている

1. **「保存」ボタン**（基本情報＋スタイル＋境界色）— まとめて 1 つの取り消し単位。
2. **詳細文書の「保存」ボタン** — 別の取り消し単位。
3. **存続期間の「反映」「継続中にする」「この錨を削除」** — 押した瞬間に確定。ボタンを押した=保存。

同じ画面に「押さないと保存されないもの」と「押した瞬間に確定するもの」が混在している。

### 2.2 保存が成功しても何も出ない

`BasicInfoForm.handleSave` は成功時に `setMessage(null)` するだけで、成功メッセージを出さない（`BasicInfoForm.tsx:139-156`）。
値が変わっていないときも黙って何もしない（変更なしガード、同 148-151 行）。実測でも保存後にメッセージ要素は 0 個（`save-message-count = 0`）。
唯一の手応えは、地図と「一覧」タブの名前が変わること（実測: 一覧が `["デーレ共和国"]` に変わる）。

失敗時だけ赤枠なしの文言が出る。例:
`保存に失敗しました: 開始年・終了年は ±100万年 の整数で入力してください（小数・範囲外は保存できません）。`（`messages.ts:121-122`, `PropertyPanel.tsx:290-292`）

### 2.3 「編集モードでないと編集できない」の実際

- 表示専用モードでは**地図クリックで地物を選べない**（実測: クリックしても `app-active-feature` は空）。「一覧」タブの行からなら選べる。
- そのとき出る注意書き: `表示モードです。編集するには編集モードに切り替えてください。`（`messages.ts:43`）
- 入力欄はすべて `disabled`。ただし実測で **「地物を削除」だけ `disabled: false`**（表示専用モードでも削除できる）。
  `PropertyPanel.tsx:440-447` は削除ボタンだけ編集可否の判定を通していない。

## 3. 歴史の錨（一覧・選択・追加・削除・時間軸との連動）

### 3.1 一覧と選択

- 「歴史の錨」見出しの右に **リスト表示 / 時間バー表示** の切替ボタン（FR-60）。
- リスト表示の 1 行は `開始 → 終了` だけ。選択中の行に「編集対象」バッジが付く（`AnchorList.tsx:99-104`）。
- 実測の行テキスト: `0年→継続中` / `1000年→継続中編集対象`（`shots/05-i-two-anchors.png`）。

### 3.2 選択すると現在時刻が動く（FR-84 どおり）

錨の行を押すと、その錨の**開始時刻へアプリ全体の現在時刻が同期する**（`PropertyPanel.tsx:269-275`）。
実測: 現在時刻 1000年 の状態で `0年` の行を押す → タイムライン表示が `0年` に変わり、編集対象バッジも 0年 の行へ移った。

そして**このとき入力中の未保存の下書きが警告なく消える**。
実測: 名前欄に `未保存の名前` と入れた状態で別の錨行を押すと、名前欄は空に戻った（下書き破棄）。
実装上も、編集対象（地物×錨）が変わると下書きを作り直す（`BasicInfoForm.tsx:126-133`、`DetailDocumentSection.tsx:69-77`）。
同じことは**タイムラインを動かして有効な錨が切り替わったとき**にも起きる。

### 3.3 錨を「追加」する手段はプロパティ欄に無い

- 錨の追加ボタンは存在しない（`AnchorList.tsx` に追加系の UI なし。`錨を追加` 等の文字列は全ソースに無い）。
- 錨が増えるのは**形を変える編集を、既存の錨と違う時刻で行ったとき**だけ。
  形状系の編集は現在時刻を編集時刻にする（例: `src/ui/vertex-delete.ts:261` の `ports.getTime()`）ので、`applyPastEdit` が新しい錨を差し込む（`src/domain/anchor-series.ts:483-487`、FR-57）。
- 一方、**属性・スタイル・詳細文書の保存は「編集対象の錨の開始時刻」を編集時刻にする**（`PropertyPanel.tsx:279-303`）。
  したがって **名前や色をいくら別の時刻で編集しても、新しい錨は絶対に生まれない**。既存の錨が上書きされる。
- 実測でも、年1000で頂点を1つドラッグした瞬間に錨が 1 → 2 件になった。

### 3.4 削除

- 「この錨を削除」は各行の折りたたみ（`存続期間を編集`）の中。確認ダイアログは無く、押した瞬間に確定。
- 錨が 1 件しかないときは無効化される（`AnchorList.tsx:203`）。

### 3.5 「開始年 / 終了年」が二重にあり、意味が違う

| | 場所 | 意味 | 実データでの値 |
|---|---|---|---|
| A | 基本情報の「開始年 / 終了年」 | その錨のスナップショットに入るただの数値。**地物の出現・消滅を一切動かさない** | 775 件すべて `0 / 9999` |
| B | 錨の「存続期間」（開始・終了） | 実際に地物が地図に出る／消える時刻 | 689 本の錨列すべて `0年 → 継続中`（`end: null`） |

A が飾りであることは実装コメントにも明記されている:
`App.tsx:3126` 「editing 開始年/終了年 only stored cosmetic snapshot attributes — they never drove the actual anchor interval」。
実データ（`derle-import/derle-world-full-2026-08-16.gimoza`）では A=9999、B=継続中 と食い違ったまま入っている。
画面上はほぼ同じ言葉が縦に並ぶので、どちらを触れば「1500年に滅びる」を表せるのか読み取れない。

### 3.6 時間バー表示は現状ほぼ機能していない

| 事象 | 実測値 | 原因 |
|------|--------|------|
| 軸がサイドバーからはみ出す | 軸幅 **480px** に対しパネルの表示幅は **203px**。軸の右端は画面座標 **x=1552**（ウィンドウ幅 1280 の外） | `AnchorTimeBar.tsx:37` の固定値 `DEFAULT_TIMEBAR_PIXELS = 480`。レイアウトから幅を測る処理はどこにも無い（`pixelLength` を渡す呼び出し元が存在しない） |
| 表示範囲が地物の錨だけで決まる | 錨 1 件（0年・継続中）の地物で軸が `0年1月1日 〜 0年12月31日` になる | `AnchorTimeBar.tsx:39-47, 84-93` の「終了なしなら開始＋365日」。プロジェクトのタイムライン範囲（0〜10000年）とは無関係 |
| 終了なしの錨が重なる | 錨が 2 件（0年・1000年、どちらも終了なし）だと、両方の帯が右端まで伸びて重なる | `timebar.ts:163-164`（`end === null` → 軸の右端まで） |
| ラベルはほぼ出ない | 帯が軸の 8% 未満だと開始年ラベルを描かない | `timebar.ts:65` `LABEL_MIN_OCCUPANCY = 0.08` |

実測スクリーンショット `shots/05-h-timebar.png` では、軸が黒い帯 1 本に見えるだけで情報が読めない。

## 4. 詳細文書（マークダウン）の編集手順

1. 編集モードで地物を選ぶ。
2. 「詳細文書」の見出し下にある **閲覧 / 編集** トグルの「編集」を押す。
3. 現れた textarea（8 行固定、`rows={8}`）に Markdown を生テキストで書く。プレビューは同時に見られない。
4. その下の **「保存」** を押す（基本情報の「保存」とは別物）。

観測できた挙動:

- 保存は 1 回の取り消し単位になる（`e2e/detail-document.spec.ts` が Ctrl+Z / Ctrl+Y の往復を実機で固定している）。
- 「閲覧」に戻すと **未保存の下書きがそのまま整形表示される**（`DetailDocumentSection.tsx:141-143` が `editable ? draft : baseline`）。
  実測: `未保存の下書きです` と入れて「閲覧」に切り替えると、その文字が表示され、**保存ボタンは画面から消える**（`detail-doc-save` の個数 = 0）。保存済みかどうか画面から区別できない。
- その状態で別の錨・別の地物へ移ると、下書きは警告なく消える（実測: 錨切替後は `詳細文書はまだありません。`）。
- 対応する記法は markdown-it の標準＋DOMPurify の許可リスト（見出し・強調・リスト・表・リンク・画像・引用・コード）。`<script>` 等は除去（`markdown.ts:39-62`、FR-116）。
- 上限は 100,000 文字（`src/domain/feature.ts:157`）。超過時は保存前に理由つきで拒否（`messages.ts:164-168`）。
- **画像は表示できない**。`assetResolver` に常に null を返す実装が渡っているため、参照は「画像を表示できません」の壊れ画像になる（`App.tsx:3195`／現状.md R6）。添付を追加する UI も無い。
- 実データ 775 件のうち詳細文書を持つものは **0 件**（`.gimoza` 内 manifest を直接集計）。つまりこの機能はまだ一度も実運用されていない。

## 5. スタイル・自動配色

### 5.1 項目と権限

- 「自動配色を許可」チェックが **唯一の権限スイッチ**。ON の間は 通常表示色・選択表示色・両方の透過スライダーが読み取り専用になり、`自動配色 ON のため色は自動決定されます（閲覧のみ）。` が出る（`style-section.ts:24-31, 45-51`、FR-102）。
- チェックを外すと**保存前に**その場で色欄が解放される（下書きの値から権限を導くため）。ただし確定は「保存」を押すまで。
- 境界色だけはこの権限の外にあり、しかも `type="text"` の手打ち（`BasicInfoForm.tsx:234-251`）。カラーピッカーが 2 つとテキスト欄 1 つが並ぶ形になっている。

### 5.2 「使用パレット」は実質的に効かない

二重に効かない。

1. **選択肢が 1 個しかない。** 実測で `<select>` の option は `["default"]` のみ。
   合成ルートが `paletteThemes` を渡していないため（`SidebarContent.tsx:357-372` に該当プロパティ無し）、`BasicInfoForm.tsx:96-98` の「その地物の現在のテーマだけを並べる」既定にフォールバックしている。
   そもそもアプリ全体でテーマは 1 つしか定義されていない（`SettingsDialog.tsx:45` `PALETTE_THEME_OPTIONS = [DEFAULT_PALETTE_THEME]`、`src/domain/coloring/palette.ts:33`）。
2. **保存しても配色に使われない。** 自動配色エンジンが読むパレットはプロジェクト設定（`uiSettings.project.defaultPaletteTheme` / `customPalette`）であって、地物ごとの `paletteTheme` ではない（`src/ui/coloring/recolor-binding.ts:55-59`）。
   `feature.color.paletteTheme` は保存・読込されるだけで、読み手が存在しない（`grep` で domain/persistence 以外の参照なし）。

### 5.3 自動配色の対象と既定

- 自動配色されるのは **末端地物（面）だけ**（`recolor-binding.ts:82-92`）。点・線・集約は対象外だが、スタイルセクション自体は点・線でも表示される（実測: 線を選んでも通常表示色・選択表示色・透過が出る）。FR-102 は「面情報の」と書いている。
- 新規追加した面は `autoColorEnabled = true` 固定（`src/ui/add/AddPropertyForm.tsx:29-30`）。プロジェクト設定の `newAreaAutoColorDefault` は読まれていない。
  そのため追加直後は色欄がすべて灰色で、手で色を決めるには「自動配色を許可を外す→保存」が要る。
- 実データ 775 件は全件 `autoColorEnabled = false`（手動色）。実機で「ハルナ君主国」を選ぶと `自動配色を許可 いいえ`、塗り `#8fb8dd`、境界 `#4a4a4a` が入っていた（実測）。つまり実運用データでは自動配色は一切働いておらず、色欄は最初から解放されている。
- 再配色は構造が変わったコミットに便乗して 1 つの取り消し単位に入る（`recolor-binding.ts:138-162`、FR-100/FR-101）。

## 6. R1（線の長さ）と R5（種別ラベル）の確認

### R1: 面積は出るが線の長さは出ない —— 再現確認済み

- 面を選ぶと `面積 122,140,762.79 km²` が出る（実測、`shots/05-d-property-populated.png`）。
- **線を選ぶと面積行も長さ行も出ない。** 実測のラベル列挙は
  `基本情報 / 名前 / 開始年 / 終了年 / スタイル / 通常表示色 / 選択表示色 / 色情報 / 境界色 / 歴史の錨 / 詳細文書` のみ（`area-row` 要素も無い）。
- `domain/geo/geodesy.ts` の `lineLengthKm` を呼ぶ非テストコードは全ソースに存在しない（`grep` 結果はテスト 2 ファイルのみ）。

### R5: 種別ラベルの入力欄が無い —— 再現確認済み、しかも実データには値が入っている

- プロパティ欄にも詳細パネルにも種別ラベルの欄は無い（実測の `innerText` 全文に該当なし）。

## 8. 再設計に効く問題点（優先度つき・すべて根拠つき）

### 高

1. **1 画面に収まらない。** 面を 1 件選ぶだけで縦 1169px、見えるのは 436px。保存ボタンが初期表示に入らない（§7）。
2. **未保存の下書きが黙って消える。** 錨行のクリック（＝現在時刻の移動）やタイムライン操作で編集対象の錨が変わると、名前・色・詳細文書の下書きが警告なく破棄される（実測、`BasicInfoForm.tsx:126-133`）。錨を見比べようとしただけで入力が消える。
3. **「開始年 / 終了年」が二重にあり、片方は飾り。** 基本情報の年は地物の出現・消滅を動かさない（`App.tsx:3126`）。実データでは 9999 と「継続中」が食い違ったまま（§3.5）。
4. **錨を意図的に増やす手段が無い。** 「1500年の時点の名前を変える」は、先に形を触って錨を作らない限り不可能（§3.3）。
5. **保存の契機が 3 系統に割れている。** ボタンで確定するもの／押した瞬間に確定するものが同居（§2.1）。
6. **保存成功のフィードバックが無い。** 押しても画面が変わらないので、押したのか、変更が無かったのか、失敗したのか区別できない（§2.2）。
7. **表示専用モードでも「地物を削除」が押せる。** 他の入力は全部無効なのに削除だけ通る（実測）。

### 中

8. **時間バー表示が読めない。** 軸幅 480px 固定でサイドバー（203px）からはみ出し、範囲は錨から自動決定（錨 1 件だと 1 年幅）、終了なしの帯は重なる（§3.6）。
9. **「使用パレット」が二重に無効。** 選択肢 1 個、しかも保存しても配色に使われない（§5.2）。
10. **色の入力形式がバラバラ。** 塗り・選択色はカラーピッカー、境界色はテキスト手打ち、しかも境界色だけ自動配色の権限外（§5.1）。
11. **詳細文書の「閲覧」が未保存の下書きを表示し、その状態では保存ボタンが消える**（§4）。保存済みか未保存かが画面から分からない。
12. **地物の素性が見えない。** 種別・種別ラベル・親（所属先）・子の数・ID がプロパティ欄に一切出ない。実データは全件に種別ラベルを持っている（§6）。
13. **横スクロールが常時発生。** 幅 220px のサイドバーに 2 段組のフィールドセットを入れているため（実測 243px > 203px）。

### 低

14. **錨の行に見出しが無い。** `0年 → 継続中` が並ぶだけで、その錨で何が変わったのか（名前が変わった/形が変わった）が分からない。
15. **「歴史の錨」の見出しが 2 行に折り返す**（切替ボタンに押されるため、`shots/05-f-interval-editor-open.png`）。
16. **存続期間エディタが折りたたみの中**にあり、しかも開くと錨セクションだけで 591px になる。
17. **点・線にもスタイルセクション（塗り色・選択色）が出る**が、自動配色の対象は面だけ（§5.3）。
18. **地物を選んでもプロパティタブへ自動で切り替わらない**（要件定義書 §7.4 で明示的に非採用、545 行）。「一覧」タブで選んだ直後は結果が見えない。

## 10. 確かめられなかったこと

- **編集モードで実データを触ったときの保存の手応え**。実データは読み込んだ直後が表示専用モードのため、実データ上での「保存」押下までは踏んでいない（保存の挙動は手で作った地物で確認した）。
- **集約地物を選んだときのプロパティ欄**。実データにも集約地物は 3 件しかなく、実機で選ぶところまで踏めなかった。面積は集約でも出る実装（子の和集合、`SidebarContent.tsx:325-341`）だが、子が無い集約は面積行そのものが出ない（同 336-341）。
- **錨が 5 件以上ある地物での一覧の見え方**。実データは全件 1 件なので、多錨時の縦の伸び方は 2 件からの外挿（1 行あたり約 60px、存続期間を開くと 1 件あたり約 440px 増）。
- **保存失敗時の表示の実物**。年の範囲外などを実機で踏ませていない（文言はコードから引用）。
- **頂点選択だけの状態（アクティブ地物なし）でのプロパティ欄**。所有者から地物を引く経路は結線済み（`SidebarContent.tsx:288-291`）だが、実機での見え方は未撮影。

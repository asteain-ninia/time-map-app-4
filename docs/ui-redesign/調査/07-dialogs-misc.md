### 2.3 挙動（実機で確認）

- **拒否バナー**: 保存を押すと日本語の理由がダイアログ上部の赤い枠に並ぶ。実測例:
  「赤道長は 0 より大きい値を入力してください。」「扁平率は 0 以上 1 未満の値を入力してください。」（shot `07-settings-error.png`）。
  ただし**問題のある入力欄自体には何の印もつかない**。項目が 17 個ある画面で「どの欄のことか」は文言から推測するしかない。
- **保存ボタンの位置**: フッターはスクロール領域の内側にあり、900px 高では初期表示で画面外。エラーを直したあと、また下までスクロールして押す必要がある。
- **離脱経路**: キャンセル／Esc／暗幕クリックはいずれも下書きを破棄して閉じる（実機確認済み）。
- **タブ切替では下書きが残る**（プロジェクト名に入力 → アプリ全体タブ → 戻ると値が残っていた）。
  これ自体は妥当だが、`SettingsDialog.tsx:7` の冒頭コメントは「タブ切替を含むすべての離脱経路で下書きを破棄する」と書いており、**コメントが実装と食い違っている**。

### 2.4 再設計時に効いてくる観察

- ラベルと入力欄が横並びで、ラベルの長さがそのまま入力欄の開始位置になるため、**縦のラインが全く揃わない**（shot 参照）。
- 「プロジェクト設定」のタブに、世界のかたち（赤道長・扁平率）／時間の範囲／地図の見た目（グリッド・ベースマップ）／配色 が
  区切りなしで一列に並んでいる。小見出しもグループ枠も無い（カスタムパレットの `fieldset` のみ例外）。

### 3.2 初見の利用者に理解できるかの批評

**理解できる点**
- 「確定を一時停止しています」で、いま何が起きているか（自分の編集がまだ確定していない）は伝わる。
- 手順が 1〜5 の番号つきで、しかも「適用」「ミニマップ」という画面上の実物を名指ししている。
- 「未指定 n 件」「未指定／指定済み」で、あと何をすればよいかが数で分かる。
- 「適用」が押せない理由がフッターに常時書いてある（無効ボタンの理由を隠していない）。

**理解できない・危うい点**

1. **凡例に色見本がない（致命的）**。ミニマップは緑=優先／青=調整後に残る／赤=重なり（`preview.ts:59-69`）と塗り分けるのに、
   凡例は `list-style: none` の裸のテキスト 3 行（`conflict.css:167-172`）。色と語の対応づけが読み手の推測任せになっている。
   さらに**選択前は両方の面が同じ灰色**（`neutral: #9e9e9e`）で描かれるので、「どちらがどっち」が画面から一切分からない。
2. **地物名の代わりに内部 ID が出る**。追加フォームは名前空欄のまま確定できるため、実機では行も選択肢も `f-5-4 ／ f-b-a` になった。
   `consistency-binding.ts:266-273` が「名前が空なら ID を出す」と決めており、コメントも「名前なしの面が既定（追加フォームは空名で確定する）」と認めている。
   **世界地図を編集していて突然 `f-b-a` を残すか `f-5-4` を残すか選べと言われる**のは、初見どころか慣れた利用者でも判断できない。
3. **「末端地物」という語がいきなり出る**。帯・行の「種類」列・使い方の 2 行目、いずれも説明なしでこの語を使う。
   一般の利用者にとって「末端」は業務用語であり、「これ以上分割されていない、いちばん下の領域」といった言い換えが要る。
   （要件定義書の用語だが、UI にそのまま出す必然性はない。）
4. **「残す」と「削られる」の非対称が説明不足**。「もう一方は重なり分が差し引かれます」とはあるが、
   削られる側は**消えるのではなく形が変わって残る**ことが、選択前の画面からは読み取れない。凡例の「調整後に残る領域」が
   それを言っているのだが、これも色見本がないので届いていない。
5. **「時刻」列の意味が不明**。行の先頭に `0年` とだけ出る。これが「この重なりが起きている作中時刻」であることは列見出し「作中時間」でしか示されず、
   重なりが 1 件だけのときは列見出しと値の対応も分かりにくい。
6. **「キャンセル」の結果が書かれていない**。押すと編集そのものが破棄される（描いた面が消える）が、画面上にその予告はない。
   「適用」の隣に同じ大きさで並んでいるので、押し間違いの代償が大きい。
7. **使い方ガイドの表示制御が離れている**。「今後表示しない」を押すと、以後は「使い方を表示」という小さなボタンに変わるが、
   再表示の恒久設定は**設定ダイアログのアプリ全体タブ**（「重なり解決画面の使い方を表示する」）にある。同じことを 2 か所で切り替えられる。

### 3.3 良い設計として引き継ぎたいもの

- 背面を確実に止める暗幕（`conflict.css` の backdrop がポインタを捕まえる）とフォーカストラップ。編集の途中で止まっている状態が視覚的にも入力的にも明確。
- 拒否されたときに「選択し直す」で編集を捨てずにやり直せる（行き止まりを作らない）。
- 「なぜ押せないか」を無効ボタンの脇に常時書く方式。

### 4.2 実データ（775 地物）で測った結果

| クエリ | ヒット数 | 備考 |
| --- | --- | --- |
| デーレ | 1 | |
| 共和国 | 5 | |
| ト | 40 | |
| **国** | **663** | パネルの `scrollHeight` = 22,798px（表示高 824px）。約 28 画面ぶん |
| **0** | **689** | 開始年・終了年が属性として検索対象なので、**数字 1 文字でほぼ全件**が「属性に一致」で並ぶ |

**問題点**

1. **件数が出ない・上限がない・並び順がない**。663 件が母集合の順（＝描画順）でそのまま縦に並ぶ。
   絞り込む手段も、ページ送りも、名前順ソートも無い。
2. **数字の検索が壊れている**。年（`String(source.attributes.startYear)` / `endYear`、`HelpToolsController.tsx:302-310`）を
   属性の検索対象に入れているため、「0」「1」といった 1 文字で全件近くが一致する。利用者から見ると「なぜこれが出るのか」が説明できない。
3. **どの属性に一致したのか分からない**。行は「属性に一致」としか出さない。実測で「スン属性に一致」（種別ラベルが「国」だった）のような、
   名前を見ても理由が分からない行が並ぶ。
4. **説明文は検索されていない**。ヘルプ文とプレースホルダは「説明」を検索対象だと言うが、母集合を組み立てる
   `buildSearchCorpus` は `description: ''` で固定（`HelpToolsController.tsx:312-314`。コメントも
   「説明は描画レコードに載っていない。この画面は名前＋属性一致で FR-113 を満たす」と認めている）。

## 7. ファイル操作系ダイアログ（`src/ui/file-ops/`）

### 7.1 未保存の変更があります — shot `07-unsaved-full.png`

| 位置 | 文言 |
| --- | --- |
| タイトル | 未保存の変更があります（右上に × ボタン） |
| 本文 | 変更が保存されていません。どうしますか？ |
| ボタン | ［保存して続行］［保存せずに続行］［キャンセル］ |

**問題点**

1. **器が他のダイアログと違う**。設定・検索・重なり解決が暗幕付き中央モーダルなのに対し、これは
   `DraggablePanel` に載った小さなパネルで、**背景を暗くしない**。初期位置は `x:360, y:220` の固定値
   （`UnsavedWarningDialog.tsx:35`）。1440×900 では地図の左寄りに小さく浮くだけで、**視線を集めない**。
   背後の地図・サイドバー・追加ツールの操作パネルがそのまま見えているので、「いま操作が止まっている」ことが伝わらない。
2. **何をしようとして止まったのかが書かれていない**。新規作成なのか、他のファイルを開こうとしたのか、アプリを閉じようとしたのかで
   「保存せずに続行」の意味は変わるのに、文言は 3 経路とも同一。
3. **どのファイルの話かも書かれていない**。プロジェクト名も保存先パスも出ない。
4. 3 つのボタンが同じ見た目で横 1 列。破壊的な「保存せずに続行」が中央にあり、区別がない。

### 7.2 読み込みデータの不整合（修復） — 実機での再現には壊れたファイルが要るため、コード読解のみ

| 位置 | 文言 |
| --- | --- |
| タイトル | 読み込みデータの不整合 |
| 導入 | 読み込んだデータに次の不整合が見つかりました。各項目の修復方法を選んでください。 |
| 各行 | `<種類ラベル>（対象: <名前 or ID>）` ／ `ID: ...` ／ `作中時刻: n` or `時間範囲: a 〜 b` ／ 詳細 ／ 修復方法のラジオ |
| ボタン | ［読み込みを中止］［修復して読み込む］（全行を選ぶまで無効） |
| 解消しなかったとき | 選択した修復ではすべての不整合を解消できませんでした。別の方法を選んでください。 |
| 2 度目も駄目なとき | 不整合を解消できなかったため、読み込みを中止しました。データは変更されていません。 |

**問題点**

1. **各行の `<legend>` に、ダイアログ冒頭の長い説明文がそのまま再利用されている**（`RepairDialog.tsx:142-144` が
   `REPAIR_STRINGS.intro` を legend に使用）。`.repair-row__options-legend` には CSS が無く隠されてもいないので、
   「読み込んだデータに次の不整合が見つかりました。各項目の修復方法を選んでください。」が**行の数だけ画面に繰り返される**。
2. **語彙が内部実装のまま**。種類ラベルは「リング階層（領土と穴の入れ子関係・包含）の不整合」「集約と下位領域の和の不一致」
   「時間（錨列）の矛盾」など（`repair-flow.ts:75-87`）、修復方法は「集約地物の下位領域一覧（childIds）を、各地物の親参照（parentId）に
   合わせて再構築します。」（`domain/persistence/repair.ts:105-127`）。**`childIds` / `parentId` という識別子が利用者向け文面に露出している**。
3. **選択肢が 1 つしかない不整合が大半**。11 種類のうち 9 種類は修復方法が 1 つだけで、
   そのうち 7 種類は「〜を読み込みから除外します」系（`repair.ts:139-186`）。事実上選択肢がないのにラジオボタンで選ばせる形になっている。
4. 各行に必ず `ID: f-xx-yy` を出す。設計上は追跡のためだが、名前があるときは冗長。

### 7.3 失敗通知は `window.alert`

これを置き換えられる」と将来送りを明言）。実際には**OS 標準の警告ボックス**が出る。アプリ内の通知面が存在しない。
文言も `FILE_OPS_STRINGS`（`file-ops/strings.ts:43-52`）に「ファイルの読み込みに失敗しました。」等の短い定型が並ぶだけで、
どのファイルか・次に何をすればよいかは伝えない。

## 10. 再設計への含意（提案）

1. **表示制御を一覧から独立させる**。サイドバーの下に積むのをやめ、常に見える場所（タブ、または折りたたみ式の上段）へ。
   §5.1 の 28,519px は「実データで使えない」ことの証拠として十分。
2. **重なり解決の凡例に色見本を入れ、地物名を必ず出す**。名前が空なら「（名前なしの面・3番目に追加）」のような
   人間が識別できる呼び名を生成する。ID をそのまま出すのは最後の手段にする。
   併せて「末端地物」を言い換える（例:「これ以上分かれていない領域」）。
3. **モーダルの器を 1 つに統一する**。未保存警告と修復も暗幕付き中央モーダルへ。特に未保存警告は
   「何をしようとして止まったか」「どのファイルか」を文面に入れる。
4. **アプリ内の通知面を作る**（`window.alert` の置き換え）。`FileOpsController` の `notify` ポートは既に差し替え可能な形になっている。
5. **検索を作り直す**。件数表示・上限（または仮想スクロール）・名前優先の並び・一致箇所の明示。
   年を属性の全文検索対象から外すか、「年で絞る」を別の条件欄にする。説明文を本当に検索するか、
   ヘルプ文から「説明」を削るかを決める。
6. **設定ダイアログをグループ分けする**。世界の形／時間／地図の見た目／配色／編集の挙動、といった小見出しを入れ、
   ラベル位置を揃え、拒否理由を該当欄の下に出す。**自動保存（間隔・世代数）をアプリ全体タブに足す（R7）**。
7. **診断情報にログを繋ぐ**。既にロガーは動いているので、表示側だけの作業。
8. **ヘルプの「バージョン情報」の表示名を gimoza にする**。内部名 `tmap` の据え置き（B3）は妥当だが、
   利用者に見える文字列は別の話。バージョン `0.0.0` をどうするか（採番するか、表示をやめるか）も決める。
9. **ショートカット一覧から重複行を消し**、ツール操作の打鍵も載せる。

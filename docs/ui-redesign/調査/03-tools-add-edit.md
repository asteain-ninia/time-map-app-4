## 1. 全体像 — モードとツールの並び

起動直後は **表示専用モード**。編集系のモードトグルは表示専用のあいだ `disabled`
（`src/ui/shell/Toolbar.tsx:52-66`）なので、**まず「表示専用」を押して抜ける**必要がある。
抜けると既定で **編集モード**に着地する（`src/ui/shell/useShell.ts:55-60`）。

左のツールバーは上から「表示専用 / 追加モード / 編集モード」の 3 ボタン、その下に
現在のモードのツールが並ぶ（`src/ui/shell/tools.ts:32-49`）。

| モード | 並ぶツール（表示名） | ツール ID |
| --- | --- | --- |
| 表示専用 | （なし） | — |
| 追加モード | 点を追加 / 線を追加 / 面を追加 | `add.point` `add.line` `add.area` |
| 編集モード | 選択 / 頂点編集 / 地物移動 / ナイフ（分割） / 所属変更 / 結合 / 穴・飛び地 / 穴あけ | `edit.select` `edit.vertex` `edit.move` `edit.knife` `edit.reparent` `edit.merge` `edit.ring` `edit.drill` |

表示名は `src/ui/shell/strings.ts:59-72`（`TOOL_LABELS`）、ホバー時の吹き出しは
同 `TOOLTIPS`（`src/ui/shell/strings.ts:170-180`）。モードトグルには吹き出しが**無い**
（HB-16 のユーザー決定、`Toolbar.tsx:35-38`）。

### 1.1 編集モードのツールは 3 つが実質「飾り」

| ツール | 押すと何が変わるか | 根拠 |
| --- | --- | --- |
| 選択 | **何も変わらない**。`TOOL_ID.EditSelect` を読む実装がツール定義以外に存在しない | `grep TOOL_ID.EditSelect` の結果は `src/ui/shell/tools.ts` のみ |
| 頂点編集 | 右クリックメニューの分類が `ShapeEdit` になるだけ。頂点の掴み・移動・追加・削除は**ツール未選択でも同じように動く** | `src/ui/map/context-menu-adapter.ts:64-76`。E2E も無選択で頂点を掴んでいる（`e2e/fr80-multi-vertex-drag.spec.ts:133-160`） |
| 地物移動 | これを押しているときだけ、**選択済みアクティブ地物**の塗り部分ドラッグが地物まるごと移動になる | `src/ui/App.tsx:1259-1262`（`featureMoveAllowed`） |

つまり編集モードの実効ツールは「地物移動 / ナイフ / 所属変更 / 結合 / 穴・飛び地 / 穴あけ」の
6 つで、「選択」「頂点編集」は押しても押さなくても同じである。にもかかわらず
**ツールを押した瞬間に選択が消える**（次項）ので、押すと損をする。

### 1.2 ツールを押すと選択が消える（全ツール共通）

`setActiveTool` は既定で**選択状態を破棄する**契約になっている
（`src/ui/state/store.ts:319-335`。コメント: 意図的なツール切替が古い選択文脈を持ち越してはならない）。

実測（`obs-edit2.mjs`）: 面を選択してハンドル 8 個が出ている状態で「頂点編集」を押すと
`handle` プリミティブが **8 → 0**。編集モードに入る操作そのものでも選択は消える
（`obs-edit.mjs`: 追加保存直後は `app-active-feature=f-5-4`、編集モードに入ると空）。

これは「面を選んでから、その面に穴を開けるツールを起動する」という自然な順序を
**必ず破る**（穴・飛び地ツールの中でもう一度その面をクリックし直すことになる）。

### 1.3 キーボードでモード／ツールは切り替えられない

キーバインドは `STANDARD_MENUS` から機械的に生成される（`src/ui/shell/default-keymap.ts:9-25`）。
宣言されているのは以下だけで、**モード切替もツール選択も一切キーに割り当てられていない**
（`src/ui/shell/menu.ts:70-152`）。

Ctrl+N / Ctrl+O / Ctrl+S / Ctrl+Shift+S / Ctrl+Z / Ctrl+Y（別名 Ctrl+Shift+Z） /
Delete / Escape / Ctrl+= / Ctrl+- / Ctrl+Home / Ctrl+F

## 2. 点 / 線 / 面を追加する

### 2.1 共通の流れ

`表示専用を抜ける → 追加モード → ツール → 地図をクリックして頂点を置く → 確定 → プロパティ入力 → 保存`

確定に必要な最小頂点数（`src/domain/add/session.ts:46-55`）: 点 1 / 線 2 / 面 3。
足りないあいだ「確定」ボタンは `disabled`（実測: 線 1 頂点で押せない）。

### 2.2 手順書（クリック数・キー数つき）

起動直後（表示専用）からの最短手順。**キー入力は名前欄のみ**（任意）。

| # | 操作 | 点 | 線(2頂点) | 面(4頂点) | 画面に出るもの |
| --- | --- | --- | --- | --- | --- |
| 1 | 左上「表示専用」をクリック | 1 | 1 | 1 | 編集モードに着地。ツール欄が編集用に入れ替わる |
| 2 | 「追加モード」をクリック | 2 | 2 | 2 | ツール欄が「点を追加 / 線を追加 / 面を追加」に入れ替わる |
| 3 | ツールをクリック | 3 | 3 | 3 | 地図の**下中央**に操作パネルが出現（後述）。カーソルが crosshair |
| 4 | 地図をクリックして頂点を置く | 4 | 4-5 | 4-7 | 橙の頂点マーカーと折れ線。カーソルまでの追従線 |
| 5 | 「点を確定」/「線を確定」/「面を閉じて確定」 | 5 | 6 | 8 | 地図中央に「新規地物のプロパティ」ダイアログ |
| 6 | 名前を入力（任意、キー入力） | — | — | — | — |
| 7 | 「保存」をクリック | 6 | 7 | 9 | 地物が確定。**同じツールのまま新しい空セッションが自動で始まる** |
| **合計** | | **6 クリック** | **7 クリック** | **9 クリック** | モード/ツール切替は 3 回 |

保存後の再武装は `AddToolController.tsx:207-214` の効果（`phase===Idle && session===null` なら `start`）。
実測でも保存直後の `data-phase` は `drawing` に戻り、頂点数は 0。

**追加した年代を直すなら、ここからさらに 3〜4 操作が必要**（§6 参照）。

### 2.3 追加中に出るもの（文言は全文）

地図の**下中央**に白い枠（`.add-tool__controls`、`src/ui/shell/shell.css:991-1006`）。
中身は 3 ボタン + チェックボックス（`AddToolController.tsx:484-522`、文言は `src/ui/add/strings.ts:22-40`）。

| 要素 | 文言 | 無効になる条件 |
| --- | --- | --- |
| 確定ボタン | 点: `点を確定` / 線: `線を確定` / 面: `面を閉じて確定` | 頂点数が最小未満 |
| 取消ボタン | `直前の頂点を取り消す` | 頂点 0 個 |
| 中止ボタン | `追加をキャンセル` | 常に押せる |
| チェックボックス | `グリッドスナップ` | — |
| エラー行（赤） | 下記のとおり | 発生時のみ |

プロパティ入力（`AddPropertyForm.tsx`、`.add-property-form` は**地図の中央**に出て下の図形を隠す）:

- 見出し `新規地物のプロパティ`
- `名前`（テキスト 1 個。autoFocus）
- `親領域`（**面のときだけ**出る。既定 `親なし（最上位領域へ）`、その下に現在時刻に存在する面が並ぶ）
- ボタン `保存` / `追加をキャンセル`

拒否・停止時の文言（`src/ui/add/strings.ts:44-63`）:

| 状況 | 文言 | 出方 |
| --- | --- | --- |
| 面が自己交差 | `面の輪郭が自己交差しています。交差しない形状にしてください。` | パネル内の赤い行。**頂点は残ったまま**（実測: `data-phase` は `drawing` のまま） |
| 頂点不足 | `頂点が足りません。確定には{n}個以上の頂点が必要です。` | **画面に出せない**。確定ボタンが `disabled` なので到達不能 |
| 空間競合 | `空間的な競合が見つかりました。競合解決を行ってください。` | 中央に `role="status"` の 1 行（今回の観察では未到達） |
| 内部エラー | メッセージ + `（問題が続く場合は開発者へ報告してください）` | 中央に赤字 + `追加をキャンセル` ボタン（未到達） |
| 親が消えた | `選択していた親領域が現在時刻では存在しないため、親選択を解除しました。` | **どこにも表示されない**。定数はあるが描画側の参照が無く、親は黙って外れる（`useAddTool.ts:265-273`） |

### 2.4 キー操作（追加中のみ）

`AddToolController.tsx:232-255`。文字入力欄にフォーカスがあるときは素通しする。

| キー | 効果 | 実測 |
| --- | --- | --- |
| Escape | 追加を中止 | 頂点 0 に戻るが **ツールは押されたまま**、パネルも出たまま（`data-phase` は `drawing`） |
| Ctrl+Z | 直前の頂点を取り消す | 4 → 3 に減った。頂点 0 で押すと追加そのものが終わる |

「追加をキャンセル」ボタンも同じ（実測: 押すと頂点 0、`tool-add.area` の `aria-pressed` は `true` のまま）。

### 2.5 実測で分かった追加ツールの穴

1. **面を描いている最中、閉じる辺が描かれない**（`shots/03-12-面-4頂点描画中.png`）。
   最後の頂点からカーソルへの線しか出ないので、確定後にどんな形になるかが見えない。塗りも出ない。
2. **点ツールで 2 回目をクリックすると 1 点目が黙って移動する**（頂点数は 1 のまま）。
   仕様どおり（`src/domain/add/session.ts:186-189`）だが、画面上の説明は無い。
3. **プロパティ入力ダイアログが地図の中央に出て、いま確定した形を隠す**
   （`shots/03-14-面-プロパティフォーム-親領域あり.png`）。形を見ながら名前を決められない。
4. **1 辺で経度 180 度以上を渡る形を描けてしまい、警告も出ない**。
   実測（`obs-ring.mjs`）で幅約 199 度の四角を描いたところ、塗りが内外反転して描画された
   （`shots/03-33`, `03-34`）。これは保存形式の恒久的な表現限界（`docs/技術方針.md` §6.8）だが、
   **UI 側に検知も注意書きも無い**。地図幅 940px が 360 度なので、既定ズームでは
   横 470px を超える 1 辺で踏む。

## 3. 頂点を動かす

### 3.1 手順

編集モードでは**ツールを何も選ばない状態が既定の編集状態**。ハンドルは
**アクティブ地物**か**選択頂点の所有地物**に対してだけ描かれる。

| # | 操作 | クリック数 | 出るもの |
| --- | --- | --- | --- |
| 1 | 「表示専用」をクリック（編集モードに着地） | 1 | — |
| 2 | 地図で面の**塗り部分**をクリック | 2 | 白丸（頂点ハンドル）と水色の四角（辺の中点ハンドル）が出る |
| 3 | 白丸を押す→動かす→離す | 3（ドラッグ 1 回） | ドラッグ中は橙のプレビュー輪郭。離すと確定（Ctrl+Z 1 回で戻る） |

頂点を**直接**クリックしてもよい。その場合アクティブ地物は空のまま「頂点選択」だけが立ち、
所有地物が**シアンの点線**で囲まれる（FR-82、`e2e/edit-handles.spec.ts:186-240`）。

### 3.2 ハンドルの見た目と当たり判定

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| 頂点ハンドル | 半径 5px の白い丸、枠 `#0a66c2` 幅 1.5px | `src/render/edit-handles-layer.ts:111-120` |
| 共有頂点 | 塗りが琥珀 `#ffd54a` | 同 116-118 |
| 選択中の頂点 | 外周にシアン `#00e5ff` のリング（隙間 3px・幅 2px） | 同 123-126 |
| ドラッグ中の頂点 | 外周に橙 `#ff8a00` のリング（隙間 5.5px・幅 2.5px） | 同 128-130 |
| 辺の中点ハンドル | 半径 3.5px の水色 `#bde3ff` の四角 | 同 112-121 |
| 掴める距離 | **画面上 8px**（ズーム非依存） | `src/ui/map/live-hit-test.ts:162-163` |
| 当たり判定の優先順 | 頂点 → 辺の中点（アクティブ地物のみ） → 点/線 → 面の塗り | 同 37-47, 1082-1140 |

**5px の丸を 8px 以内で掴む**という設計なので、頂点が密な地物では隣の頂点を掴む事故が起きる。
辺の中点ハンドルは頂点ハンドルとサイズ差 1.5px・形（丸／四角）だけの違いで、
実測スクリーンショット（`shots/03-21-編集-面を選択しハンドル表示.png`）では区別がほぼ付かない。

### 3.3 ハンドルの表示上限

`vertexMarkerCap` 既定 **2000**（`src/ui/state/settings.ts:255-263`）。
地物の（視野内の）頂点数がこれを超えると、頂点ハンドルも辺ハンドルも**まとめて 0 個になる**
（先頭 N 個を出すのではなく全部消える。`src/ui/map/active-feature-handles.ts:785-823`）。
選択済み・ドラッグ中の頂点だけは上限の対象外。
視野が分かるときは「視野内の個数」に上限が掛かるので、拡大すれば編集できるようになる。

## 4. 頂点を追加する / 削除する

### 4.1 追加（辺の中点ハンドルを**ドラッグ**）

| # | 操作 | 出るもの |
| --- | --- | --- |
| 1 | 編集モードで面の塗りをクリック（=アクティブ地物にする） | ハンドル一式。辺の中点ハンドルは**アクティブ地物にしか出ない**（`live-hit-test.ts:1131-1140`） |
| 2 | 水色の四角を押す→動かす→離す | 新しい頂点がその位置に挿入される |

実測（`obs-edit2.mjs`）: 頂点ハンドル **4 → 5**、新頂点は `lon 0 / lat 72.77`。

**クリックしただけでは何も起きない**（実測: ハンドル数 4 のまま、頂点選択も立たない）。
辺ヒットは必ずドラッグ操作（`EDIT_TOOL.EdgeAdd`、`src/ui/map/edit-session-adapter.ts:252-262`）で、
移動量ゼロは「操作なし」として捨てられる（`src/domain/editing/drag-session.ts:16-18`）。
画面上の説明は無い。

### 4.2 削除

| 経路 | 手順 | クリック/キー数 |
| --- | --- | --- |
| Delete キー | 頂点をクリック → `Delete` | 1 クリック + 1 キー |
| 右クリック | 頂点を右クリック → `頂点を削除` | 2 クリック |
| メニューバー | 「編集」→「削除」 | 2 クリック |

実測（`obs-edit2.mjs`）: 頂点ハンドル **5 → 4**。確認ダイアログは無い。

右クリックメニューは頂点が選ばれているかで項目が入れ替わる
（`src/domain/context-menu/compose.ts:273-279`）。**頂点選択があるときは「削除」が消えて
「頂点を削除」になる**ので、地物まるごと削除の誤爆はしない設計。

頂点で右クリックしたときの実測メニュー（`shots/03-26-編集-頂点で右クリック.png`）:

```
頂点を削除
プロパティ編集
分割
所属変更
結合            ← グレーアウト（「結合には2つ以上の対象が必要です。…」）
この地物を非表示
この地物を強調
表示専用モード切替
```

文言の出どころは `src/domain/context-menu/items.ts:71-82`。
**「頂点を追加」も「穴・飛び地」もメニューに無い。**

頂点を消しすぎると閾値で地物ごと消える（線 2 点未満 / リード 3 点未満 / 領土 0 で面削除。
`src/ui/vertex-delete.ts:14-18`）。事前の警告は無い。

## 5. 複数頂点を選ぶ

### 5.1 二通り

| やり方 | 手順 | 実測 |
| --- | --- | --- |
| Shift+クリック | 頂点を Shift 押しながらクリックすると集合に足す／外す（トグル） | `src/domain/selection/reducer.ts:183-186, 251-262` |
| 矩形（ラバーバンド） | **何も無い所**を押してドラッグ、離した時点で矩形内の頂点を選ぶ。Shift 併用で追加 | `src/ui/map/live-selection-port.ts:14-25` |

選ばれた頂点はシアンのリングが付く（`shots/03-25-編集-矩形選択後.png` で北側 2 頂点にリング）。
選択したうち 1 つを掴んでドラッグすると、選択集合ぜんぶが同じベクトルで動き、
Ctrl+Z 1 回でまとめて戻る（FR-80、`e2e/fr80-multi-vertex-drag.spec.ts`）。

### 5.2 実測で分かった穴

1. **矩形が画面に描かれない。** ドラッグ中のフレームを観測しても、確定前後で描画プリミティブが
   まったく増えない（`handle:8 label:29 shape:1 line:0 preview:0` が押下前・ドラッグ中・確定後で同一）。
   `shots/03-24-編集-矩形選択ドラッグ中.png` を見ても、どこを掃いているかは画面から分からない。
   レンダラ側にも矩形を描く層が無い（`src/render/` に該当なし）。
2. **矩形は 1 地物ぶんの頂点しか取れない。** 2 つの地物にまたがった場合、
   「最初に見つかった所有者」の頂点だけが選ばれ、他方は無視される
   （`src/ui/map/live-hit-test.ts:884-892`）。「最初」はデータの内部順であって、
   利用者から見て予測できない。
3. **いま何個選んでいるかを示す表示がどこにも無い。** サイドバーにも状態バーにも件数は出ない。
   `app-active-vertex` は先頭 1 個の ID しか持たない観測用の隠し要素（`src/ui/App.tsx:3625-3646`）。

## 6. 追加後にプロパティ欄で直さないと使い物にならない項目（R10 の実測）

`docs/現状.md` R10 の内容を実機で確認した（`obs-r10.mjs`、`shots/03-16`, `03-17`）。

手順: 直接ジャンプで **1500 年**へ移動 → 追加モード → 面ツール → 4 点 → 確定 →
名前「1500年に作った面」→ 保存 → サイドバー「プロパティ」タブ。

読み取った `基本情報` の入力値:

| 欄 | 値 | 期待 |
| --- | --- | --- |
| 名前 | `1500年に作った面` | ○ |
| **開始年** | **`0`** | 1500 のはず |
| **終了年** | **`0`** | 未指定／継続中のはず |
| 自動配色を許可 | チェック ON | — |
| 通常表示色 | `#4e79a7` | 追加フォームが渡した `#90caf9` は**使われていない** |
| 通常表示色 透過 | `0.7` | — |
| 選択表示色 | `#78a7d9` | 同上（渡した `#ffb300` は使われない） |
| 境界色 | `#0d47a1` | フォームの既定がそのまま入る |

- 年代が 0 固定なのは `src/ui/add/AddPropertyForm.tsx:33-34`（`DEFAULT_START_YEAR = 0` /
  `DEFAULT_END_YEAR = 0`）が現在時刻を見ていないため。
- 色は `AddPropertyForm.tsx:29-32` で `createColorInfo(true, …)` = **自動配色 ON** で作るので、
  そのあと自動配色が上書きする。つまり**フォームが渡す色は最初から意味がない**。
- 一方で「歴史の錨」欄は `1500年 → 継続中` と正しく 1500 年に立っている。
  つまり**「錨の時刻」は正しく、「基本情報の開始年/終了年」だけが 0** という二重表示になっている。
  利用者から見ると年が 2 か所にあって片方だけ嘘をつく。
- 種別ラベル（国・州など）の欄は追加フォームにもプロパティ欄にも無い（R5）。

**追加のあと必ず必要になる後始末**（面 1 個あたり）:
プロパティタブへ切替（0〜1 クリック）→ 開始年を入力 → 終了年を入力 → 「保存」を押す
= **3〜4 操作**。9 クリックで作った面に、さらに毎回これが乗る。

## 7. 穴・飛び地を足す / 消す

ツール `edit.ring`（表示名「穴・飛び地」、吹き出し「面に穴や飛び地を追加、または穴・領土リングを削除します」）。

### 7.1 追加の手順（実測: 7 クリック）

| # | 操作 | 画面 |
| --- | --- | --- |
| 1 | 「表示専用」をクリック（編集モードに着地） | — |
| 2 | 「穴・飛び地」をクリック | 地図**上中央**に黒い帯で `穴 / 飛び地を編集する面をクリックで選択してください。`、**下中央**に操作パネル |
| 3 | 対象の面の**塗り部分**をクリック | 帯が `穴 / 飛び地の頂点をクリックで追加してください（面の内側なら穴、外側なら飛び地。3 点以上で確定できます）。` に変わる |
| 4-6 | 頂点を 3 回以上クリック | 青緑の折れ線。「リングを確定」が押せるようになる |
| 7 | 「リングを確定」をクリック | 確定。帯は **手順 2 の文言に戻る**（対象面は保持されない） |

穴になるか飛び地になるかは **1 クリック目の位置**で自動判定される
（塗りの内側＝穴、外側または既存の穴の中＝飛び地。`src/domain/ring-edit/auto-mode.ts:36-45`）。
**いまどちらを作っているかの表示は無い。** 確定するまで結果が分からない。

下中央の操作パネル（`src/ui/ring-edit/strings.ts`、`RingEditToolController.tsx:325-374`）:

| 要素 | 文言 | 備考 |
| --- | --- | --- |
| サブモード切替 | `リング削除モードへ` / `リング追加モードへ` | 常時表示 |
| 確定 | `リングを確定` | 3 頂点未満は `disabled`（`useRingEditTool.ts:595`） |
| 取消 | `最後の頂点を取り消す` | 頂点 0 で `disabled` |
| スナップ | `グリッドにスナップ` | 追加ツールの `グリッドスナップ` と**別名・別状態** |
| 中止 | `キャンセル` | — |

拒否文言（`src/ui/ring-edit/strings.ts:47-77`）:

| 状況 | 文言 | 実測 |
| --- | --- | --- |
| 面以外をクリック | `面が見つかりませんでした。編集する面の塗りつぶし部分をクリックしてください。` | 出た（`shots/03-31`） |
| 末端地物でない | `末端地物を選択してください。` | — |
| 3 点未満 | `リングには 3 点以上の頂点が必要です。` | 確定ボタンが無効なので到達しにくい |
| 領土が見つからない | `穴を作成できる領土が見つかりませんでした。領土の内側をクリックしてください。` | — |
| 階層が壊れる | `リングの階層構造が不正になるため、この形状は確定できません。` | — |
| 対象が消えた | `対象のリングが見つかりませんでした。` | — |

キー: Escape = 中止、Ctrl+Z = 最後の頂点を取り消す（`RingEditToolController.tsx:205-231`）。

### 7.2 削除の手順（実測: 4 クリック、確認なし）

| # | 操作 | 画面 |
| --- | --- | --- |
| 1 | 「穴・飛び地」をクリック | — |
| 2 | 「リング削除モードへ」をクリック | 帯が `穴 / 領土リングを削除する面をクリックで選択してください。`。パネルから確定・取消・スナップが消え、`リング追加モードへ` と `キャンセル` だけになる |
| 3 | 面の**塗り部分**をクリック | 帯が `削除する穴 / 領土リングの内側をクリックしてください。` |
| 4 | 消したいリングの内側をクリック | **その場で削除。確認ダイアログ無し**（`useRingEditTool.ts:499-514`）。帯は手順 2 の文言に戻る |

同じ「クリック」でも 3 と 4 で当たり判定の規則が違う（3 は穴を透過する通常のヒットテスト、
4 は面自身のリング包含判定）。見た目は同じ地図面なので、区別は文言だけに委ねられている。

「領土リング」も消せるので、最後の領土を消すと面ごと消える可能性がある。事前警告は無い。

### 7.3 中止の挙動が追加ツールと逆

穴・飛び地の `キャンセル` / Escape は **ツールごと解除する**（`setActiveTool(null)`、
`RingEditToolController.tsx:156-166`）。追加ツールの `追加をキャンセル` は**ツールを押したまま**下書きだけ捨てる。
同じ「キャンセル」でも結果が違う。

| 場所 | 表示名 | 状態の持ち主 |
| --- | --- | --- |

## 9. 再設計に直結する発見

### 9.1 【最重要】新規追加では既存頂点に吸着しない＝隣接国の境界を共有して描けない

`AddToolController` は `resolveProximity`（近接する既存頂点）と `isInsideTerminal`
（末端地物の内側か）を任意ポートとして受け取るが、**合成ルート `src/ui/App.tsx:3259-3270` は
どちらも渡していない**（`grep` の結果、実装コード側の供給元はゼロ。テストのみ）。
結果として追加中は `resolveProximity?.(raw) ?? null` が常に null になり、
`resolveSnap` はグリッドか生座標しか返さない（`useAddTool.ts:216-231`）。

実測（`obs-share.mjs`）: 面 A の右辺と面 B の左辺を**まったく同じ画素**でクリックして 2 国を作り、
編集モードで A の右上角を上へドラッグしたところ、

- A の頂点: `lat 38.298 → 61.277`
- B の対応する頂点: `lat 38.298` のまま（動かない）
- 境界が裂けた（`shots/03-61-Aの角をドラッグ後-Bは連動するか.png`）

つまり**同じ場所をクリックしても頂点は共有されない**。ハンドルの色も白（共有なら琥珀）。

一方、**編集モードで頂点をドラッグして近づけて離すと共有化される**。実測（`obs-share2.mjs`）:
B の角を A の角の 30px 手前で離したところ、A 側の頂点が B の位置へ引き寄せられて一致した
（A の頂点 `lon -61.277 → -49.787` = B の離した位置）。スナップ距離の既定は 50px
（`src/ui/state/settings.ts:255-256`）。

**現状で隣接国を正しく作るには、「B を適当に描く → 編集モードに移る → B の境界頂点を 1 個ずつ
A の頂点へドラッグして離す」を頂点の数だけ繰り返すしかない。** 国境を扱うアプリとして
これは致命的な工数で、「実運用に踏み切れない」の主要因である可能性が高い。

同じ理由で FR-29（must、「末端地物追加時に他の末端地物の内部には頂点を設置できない」）も
実際には効いていない。なお仮に配線しても、拒否は `return current` の**無反応**で
理由の表示が無い（`useAddTool.ts:227-230`）。

### 9.2 矩形選択が見えない

§5.2 のとおり、ドラッグ中に矩形が一切描かれない（描画層そのものが無い）。
「どこを掃いたか」「何個取れたか」が最後まで分からない。

### 9.3 ツールを押すと選択が消える／編集モードに入っても消える

§1.2 のとおり。特に「面を選ぶ → 穴・飛び地ツール → もう一度同じ面を選ぶ」は毎回発生する。

### 9.4 「選択」「頂点編集」は押しても何も変わらないのに、押すと選択が消える

§1.1。8 個並ぶツールのうち 2 個が無効果、1 個（地物移動）だけが排他条件を持つ、という
不揃いな状態。ツールバーの見た目からは区別できない。

### 9.5 辺の中点ハンドルはクリックでは反応しない

§4.1。「頂点を足したいのでクリックした → 何も起きない」は最も踏みやすい無反応。
右クリックメニューにも「頂点を追加」は無いので、ドラッグを知らないと機能に到達できない。

### 9.6 実データでは頂点ハンドルが密すぎて 1 個も選べない

実データ（Derle 689 地物）を読み込んで編集モードで地図をクリックした実測（`obs-real2.mjs`）:

| クリック位置 | 選ばれたもの | 描かれたハンドル数 |
| --- | --- | --- |
| 中央 | なし | 0 |
| 左上寄り | 頂点（地物本体ではない） | 184 |
| 右下寄り | 頂点 | 612 |
| 左下 | 地物 `area-036`（ナイー共和国） | 30 |
| 右上 | 頂点（別地物） | 1736 |

- 世界全体表示では 8px の当たり判定に必ず頂点が入るので、**面を選んだつもりが頂点選択になる**。
- 1736 個のハンドルは輪郭を埋め尽くし、青い塊にしか見えない
  （`shots/03-72-実データ-選択-840x226.png`）。この状態で狙った 1 頂点を掴むのは不可能。
- 上限 2000 を超えるとハンドルが全部消える（§3.3）ので、
  「密すぎて選べない」→「拡大する」→「上限を割って出る」という運用が前提になっているが、
  その説明は画面に無い。

### 9.7 操作パネルが地図の下中央を占有し、ツールごとに文言と押し方が違う

追加 / 穴・飛び地 / ナイフ / 結合 / 所属変更が**すべて地図の下中央**に白い箱を出す
（`shell.css:988-991` のコメントが「どのツールの確定ボタンも同じ場所」と明言）。
そのぶん地図の下端が常に隠れる。文言は「確定」「リングを確定」「面を閉じて確定」とばらばらで、
穴・飛び地では横幅が足りず `リング削除モ／ードへ`・`最後の頂点を／取り消す`・`グリッドに／スナップ`・
`キャン／セル` と 2 行に折り返す（`shots/03-33-穴飛び地-3頂点配置.png`）。

### 9.8 定義だけあって画面に出ない文言

`ADD_STRINGS.parentClearedNotice`（親が消えたときの通知）は参照元が無く、
親選択は黙って外れる。`shapeRejectionMessage` の頂点不足文も、
確定ボタンが `disabled` なので到達できない。

## 11. 確かめられなかったこと

- 空間競合の一時停止（`add-conflict-paused`）と内部エラー（`add-rejected`）の実画面。
  今回の観察では到達しなかった。文言はコードから引用した。

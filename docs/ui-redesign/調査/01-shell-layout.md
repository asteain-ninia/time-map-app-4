## 1. 画面の骨格（何がどう並んでいるか）

### 1.1 構造の定義

骨格は 1 個の CSS グリッド 1 枚で、4 行 ×（主行だけ 3 列）。定義は `src/ui/shell/shell.css:54-136`、組み立ては `src/ui/shell/AppShell.tsx:100-146`。

```
┌───────────────────────────────────────────────────────────────────────┐
│ 1行目 .app-shell__menubar   ← 高さ auto（中身しだいで伸びる）              │
│  ┌─ .menubar (左, 固定 318px) ─┬─ .app-shell__topbar (右, 残り全部) ─┐ │
│  │ ファイル 編集 表示 ツール ヘルプ  │ 経度シフト／階層深度／グリッド／測量  │ │
│  └───────────────────────────┴──────────────────────────────────┘ │
├───────────────────────────────────────────────────────────────────────┤
│ 2行目 .app-shell__main   ← 1fr（残り全部を取る）                          │
│ ┌──────────┬───────────────────────────────────┬──────────────┐ │
│ │ 左ツールバー  │ 中央 地図セル                          │ 右サイドバー    │ │
│ │  120px 固定  │  1fr（可変）                           │  220px 固定    │ │
│ │ モード3 + ツール│ canvas + 入力層 + 地図内オーバーレイ         │ タブ2 + パネル  │ │
│ └──────────┴───────────────────────────────────┴──────────────┘ │
├───────────────────────────────────────────────────────────────────────┤
│ 3行目 .app-shell__timeline  ← 高さ auto（中身しだい。上限 40vh）           │
├───────────────────────────────────────────────────────────────────────┤
│ 4行目 .app-shell__statusbar ← 高さ auto（実測 28px 固定）                 │
└───────────────────────────────────────────────────────────────────────┘
```

- グリッド定義: `grid-template-rows: auto 1fr auto auto` / `grid-template-columns: 1fr`（`shell.css:63-65`）。
- 主行の列: `grid-template-columns: var(--shell-toolbar-w) 1fr var(--shell-sidebar-w)` = `120px 1fr 220px`（`shell.css:61-62, 93`）。
- 最小サイズ: `.app-shell { min-width: 800px; min-height: 600px; overflow: hidden; }`（`shell.css:69-72`）。Electron 側の `minWidth/minHeight` と同じ定数を共有（`src/ui/shell/window-config.ts`, `src/domain/window-constants.ts`）。
- **前面レイヤは 2 段ある**（`AppShell.tsx:129-144`, `shell.css:653-700`）:
  - `.app-shell__overlay` … シェル全体を覆う。`pointer-events:none`、子だけが入力を取る。モーダル・詳細パネル・右クリックメニュー・各コントローラ（ファイル操作／ヘルプ／設定／競合解決）がここ。
  - `.map-area__overlay` … 地図セルの中だけを覆う。追加・ナイフ・結合・所属変更・穴飛び地・穴あけ・測量の 7 つの入力ブリッジがここ（`App.tsx:3239-3379`）。かつては全シェル側にあり、上部バーやタイムラインのクリックを奪っていた（`shell.css:943-966` に経緯が残っている）。

行の高さ = `149.2px 221.6px 201.2px 28px`。主行の列 = `120px 480.6px 220px`。

| 領域 | x | y | 幅 | 高さ |
|---|---|---|---|---|
| ウィンドウ全体 | 0 | 0 | 800 | 600 |
| メニューバー行 | 0 | 0 | **820.6** | **149.2**（上部バーが 4 段） |
| 主行 | 0 | 149.2 | 820.6 | **221.6** |
| ├ 地図セル | 120 | 149.2 | **480.6** | **221.6** |
| └ 右サイドバーのセル | 600.6 | 149.2 | 220.8 | 221.6（**右端 21.4px が窓外**） |
| タイムライン行 | 0 | 370.8 | 820.6 | **201.2** |

**横にはみ出して切れている**: `.app-shell` は幅 800（`clientWidth 800`）だが中身は 820.6（`scrollWidth 821`）。`overflow:hidden` なのでスクロールバーも出ず、右端 20.6px は**到達不能**になる。実測でサイドバーの「プロパティ」タブ文字、上部バーの「測量モード」「フォーカス解除」、タイムラインの右端ラベル「10000年」が切れている（`01-shell-800x600-view.png`）。

原因は算術的にはっきりしている。`.menubar` が `flex-shrink:0` で 318px を譲らず（`shell.css:192-194`）、上部バーの最小内容幅が 502.6px（`.global-depth__focus` が `flex-wrap:nowrap` + `white-space:nowrap`、`shell.css:852-859`）。318 + 502.6 = 820.6 が 1 行目の最小幅になり、それがグリッド列幅 `820.6px` としてシェル全体に効く。

### 1.5 800×600・編集モードでのツールバー

編集モードのツールバー（モード 3 + ツール 8）の中身は **460.4px** 高。800×600 のツールバーセルは **221.6px** しかないので、`scrollHeight 460 / clientHeight 222` で内部スクロールになる。最後のツール「穴あけ」の下端は **y=602**、つまりウィンドウ（600px）の外。8 個中 5 個が初期表示で見えない。

### 1.6 領域の面積比

| ウィンドウ | 地図セル | 地図が窓に占める面積 | 縦のクローム合計（ヘッダ＋タイムライン＋ステータス） | 横の固定クローム（120+220） |
|---|---|---|---|---|
| 1600×1000 | 1260×716.8 | **56.4%** | 283.2px（高さの 28.3%） | 340px（幅の 21.3%） |
| 1280×800 | 940×489.6 | **45.0%** | 310.4px（高さの 38.8%） | 340px（幅の 26.6%） |
| 800×600 | 480.6×221.6 | **22.2%** | 378.4px（高さの 63.1%） | 340px（幅の 42.5%） |

さらに 1600×1000 のスクリーンショットで見ると、地図セル 1260×716.8 のうちベースマップ（2:1 の世界図）が描かれているのは縦 465px 程度で、**セル高さの約 35% が上下の灰色の余白**になっている。地図が実際に見えている面積は上表よりさらに小さい。

### 1.7 レイアウトが「窓幅で動く」仕組みと、その副作用

- 1 行目は `auto` 高さで、上部バーが `flex-wrap: wrap`（`shell.css:165-179`）。窓が狭いほど段数が増え、ヘッダが高くなり、`1fr` の主行（＝地図）がその分縮む。実測で **1600→54px、1280→81.2px、800→149.2px**、つまりヘッダだけで最大 95px 動く。
- 過去に「選択の有無で上部バーの幅が変わり、折り返しが変わって地図セルが 28px 飛ぶ」不具合があり、その対策として **個別フォーカス群を常に固定幅で出しっぱなしにして無効化する**方式が採られている（`GlobalDepthControl.tsx:77-88`、`shell.css:840-868`）。結果として「深掘り対象なし」「フォーカス深度」「縦方向領域を強調」「フォーカス解除」の 4 部品が、起動直後から常に灰色で 400px 弱を占め続ける。
- タイムライン行は `auto`＋`max-height:40vh`（`shell.css:122-132`）だが、中身の高さが **どの窓サイズでも 201.2px で一定**。つまり縦が狭いほど相対的に地図を圧迫する（800×600 では地図 221.6px に対しタイムライン 201.2px でほぼ同じ高さ）。

## 4. サイドバーの「一覧」「プロパティ」タブ

### 4.1 切替の仕組み

- 器は `Sidebar.tsx:45-105`。`useState` でどちらか一方の `active` を持ち、両方の `<section role="tabpanel">` を常に DOM に出したまま非アクティブ側に `hidden` を立てる（`:91-103`）。つまり**非表示側の中身も毎回レンダリングされている**（実測でも非アクティブ側の部品が rect 0×0 で 13 個列挙された）。
- 初期タブは `initialSection`（`Sidebar.tsx:49`）で既定は **プロパティ**。`App.tsx` は `initialSection` を渡していない（`grep` で該当なし）ので常に既定のまま。実測の起動直後もプロパティタブだった。
- **タブの状態は Sidebar の内部 state で、外から切り替える API が無い。** そのため右クリックメニューの「プロパティ編集」は、`document.getElementById('sidebar-tab-properties')` を引いて `.click()` を呼ぶという DOM 直叩きで切り替えている（`App.tsx:2353-2362`）。コメントに「タブ状態の明示 API はシェル変更なのでバックログ」と残っている。再設計でタブ状態をどこに置くかは決め直す論点。
- 左右矢印キーでタブを移動できる（`Sidebar.tsx:56-65`、`a11y/tablist` の `nextTabForArrow`）。ただし `tabIndex` のローミングは実装されておらず、2 つのタブが両方 Tab の停留点になる。
- 地物を選んでもプロパティタブへ自動で切り替わらない。これは要件で意図的な非目標（要件定義書 §7.4「サイドバー折りたたみ／選択時のプロパティタブ自動切替」）。サイドバーの折りたたみ・幅変更も同じく非目標かつ未実装。

### 4.2 「一覧」タブの中身

`SidebarContent.tsx:180-192` が `listContent` として 2 つを縦に積む。

1. **統合一覧**（`UnifiedListSection`, `:536-667`）

- 濃紺 `#2f3a4a` はメニューバー行とステータスバーの 2 か所。メニューバー行の右半分（上部バー）は同じ濃紺の上に**白いボタンと灰色の既定ボタンが並ぶ**ので、メニューとは別世界の道具箱に見える。
- 薄灰 `#eceef1` は左ツールバーとサイドバーのタブ帯。
- 白 `#ffffff` はサイドバー本体とタイムライン帯。地図セルだけ背景色を持たず、body の `#f4f5f7` が透ける（ベースマップの上下の余白がここ）。
- 影は `.menubar__items` / `.draggable-panel` / `.context-menu` / `.add-tool__controls` の 4 か所だけ。`.context-menu` と `.draggable-panel` は変数を使わず `#fff / #888` を直書き（`shell.css:664-669, 927-935`）。

### 5.5 余白

- ツールバー `padding: 8px 6px`、グループ間 `gap: 10px`、ボタン間 `gap: 4px`（`shell.css:256-273`）。
- サイドバーのパネル `padding: 10px`、リスト行の間 `gap: 2px`（`:332-337, 378-385`）。
- タイムライン `padding: 8px 12px`、コントロール群 `gap: 12px`（`:480-511`）。
- ステータスバー `padding: 3px 10px`。
- 上部バーは `gap: 8px` と `row-gap: 2px`（`:165-179, 723-734`）。
4px / 6px / 8px / 10px / 12px / 16px が場所ごとに任意に使われており、8 の倍数などの体系にはなっていない。

## 6. 再設計に効く所見（事実からの解釈）

以下は上の実測から導いた解釈であり、意見を含む。

1. **既定サイズ 1280×800 で、地図は窓面積の 45% しかない。** 縦のクロームが 310px（38.8%）、うちタイムラインだけで 201px。タイムラインの高さがどの窓サイズでも一定なので、縦の狭い環境ほど地図が潰れる。地図が主役の道具としては配分が逆になっている。

2. **上部バーの折り返しが窓幅で地図を動かす。** 1600 で 2 段 54px、1280 で 3 段 81px、800 で 4 段 149px。窓を横に伸ばしただけで地図の上端が最大 95px 動く。過去の「選択で 28px 飛ぶ」問題を「常時無効の部品を出しっぱなしにして幅を固定する」方法で塞いだ結果（`GlobalDepthControl.tsx:77-88`）、起動直後から灰色の部品が 400px 弱を占め続ける構造になっている。折り返す帯に道具を置くという方針自体を見直す価値がある。

3. **最小サイズ 800×600 でレイアウトが破綻する。** 中身が 820.6px あってウィンドウ 800px からはみ出し、`overflow:hidden` なのでスクロールもできず右端 20.6px が到達不能（サイドバーのタブ文字・測量モード・フォーカス解除が切れる）。加えて編集モードでは 8 個のツールのうち 5 個が窓の下（最後のツールの下端 y=602）。FR-114 の「最小 800×600」は数値としては守られているが、実際には使えない。

4. **表示制御パネルが一覧の下に積まれていて、実データでは届かない。** 775 件の一覧の下、約 28,500px スクロールした先（実測 y=28518.8）。空プロジェクトですら下端が切れている。FR-113 の表示制御は「実装済みだが到達できない」状態にある。

5. **一覧はフラットな名前の羅列で、775 件を 220px 幅で 1 列に並べているだけ。** 階層も、検索以外の絞り込みも、並べ替えも無い（`SidebarContent.tsx:559-620`）。docs/現状.md の R9 と一致。実データを開いた瞬間に破綻するのはここ。

6. **モード切替 3 ボタンの意味が読み取れない。** 「表示専用」は押されている状態で押すと**編集モードへ着地する**（`useShell.ts:50-63`。実測: 800×600 で「表示専用」を 1 回押した直後 `view=false, edit=true`）。ボタンのラベルは「表示専用」なのに、押した結果は「編集モードになる」。さらに「編集モード」をもう一度押すと表示専用に戻る（`useShell.ts:40-48`）。3 つのボタンが 3 状態のラジオでもトグルでもない中間の挙動をしている。しかもアプリは**起動直後は表示専用**なので、最初にやることが「表示専用を解除する」という否定形の操作になる。

7. **今どういう状態なのかが画面から読めない。** ステータスバーの中身はカーソル座標 1 個だけ。ウィンドウタイトルは常に `time-map-app` で、開いているファイル名も未保存の印も出ない（`projectDirty` はストアにあるが誰も表示しない）。現在のモード・ツール・選択件数・縮尺も、押されているボタンの色以外に手掛かりが無い。

8. **地図の上に何も無い。** ズーム、縮尺、方位、現在座標、全体表示への復帰といった地図の基本操作が、すべてメニューかキーボードか上部バーに散っている。地図セルの中に常設のコントロールは 0 個。一方で右クリックは何もない場所では 1 項目しか出さない（実測 137×35px）。

9. **ボタンの見た目が 3 系統に割れている。** 設計変数どおりのもの、ブラウザ既定のまま（グリッド・測量モード・未指定・ジャンプ・年月日入力）、独自色（グリッドの ON は `#1565c0`）。「押されている」青が 2 色あり、隣り合う「グリッド」と「測量モード」ですら枠のスタイルが違う。クリック対象の高さも 13px〜54px に散る。変数の器はあるので、統一そのものは高コストではない。

10. **キーボードだけでは操作できない部分が多い。** メニューバーは Alt でも矢印キーでも操作できず（`MenuBar.tsx` に該当処理なし）マウス専用。サイドバーのタブは矢印キーに対応しているがローミング tabindex が無い。左ツールバーのツールにはショートカットが 1 つも割り当てられていない（`menu.ts:70-153` にツール系のコマンド ID 自体が無い）。

## 7. 確かめられなかったこと

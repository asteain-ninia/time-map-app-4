# C 操作数分析（KLM）とタスク分析

対象: gimoza（time-map-app-4）の現行 UI。
やったこと: 頻出タスク 25 件を階層的タスク分析で手順に割り、現 UI での最短手順を操作単位（K/P/B/H/M/スクロール）で数え、KLM で所要時間を推定した。
根拠は把握フェーズの報告書 01〜12 と、今回あらためて実施したヘッドレス起動での実測。**ソース・ビルド・git は一切変更していない。**

この文書は次工程が読む生データである。

## 0. 調べ方と、使ったモデル

### 0.1 実測

ビルド済み `out/` を Playwright の `_electron.launch` でヘッドレス起動（`E2E_TEST=1` / 一時 userData / `--disable-gpu --no-sandbox --disable-software-rasterizer`、`e2e/helpers.ts:49-90` の `launchApp()` と同条件）。
ウィンドウは main 側の `setContentSize(1280, 800)` で**アプリの既定サイズ**に固定（`src/shell/main/index.ts:170-172`）。
実データは `derle-import/derle-world-2026-08-16.gimoza`（間引き版・地物 775 件）を、`#app-shell` へ合成 `drop` を投げる経路（`src/ui/file-ops/FileOpsController.tsx:824-836`）で読み込ませた。読込は実測 0.84 秒。

観察スクリプトは scratchpad 配下の `klm-obs.mjs` / `klm-obs2.mjs` / `klm-obs3.mjs` / `klm-obs4.mjs`、集計は `klm-calc.mjs`。
今回撮ったスクリーンショットは `docs/ui-redesign/調査/shots/C-01`〜`C-09`。

### 0.2 KLM の演算子と数値

Card, Moran & Newell の標準値を使う。時間は「熟練していない一般利用者」寄りに寄せた。

| 記号 | 意味 | 秒 |
|---|---|---|
| K | キーを 1 つ打つ（修飾キーも 1 K） | 0.28 |
| P | マウスで目標へ位置決めする | 1.10 |
| B | マウスボタンを押す／離す（片方で 1 B） | 0.10 |
| H | 手をキーボードとマウスの間で移す | 0.40 |
| M | 心の準備（次に何をするか決める） | 1.35 |

派生:

- **クリック 1 回 = P + 2B = 1.30 秒**（位置決めを含む）
- **ドラッグ 1 回 = P + B + P + B = 2.40 秒**
- **スクロール**は KLM の標準演算子に無いので拡張する。**ホイール 1 ノッチ ≒ 100px、1 ノッチ 0.10 秒**とし、スクロール領域へ手を運ぶ P を 1 回加える。これは Chromium の既定のホイール量に合わせた仮定であり、正確な実測ではない（§8）。

**M（心の準備）の置き方**は、標準の規則 0〜4 をそのまま適用すると解釈の幅が大きいので、この文書では次の簡略規則に固定した。**この規則は推定の前提であり、絶対値ではなくタスク間の比較に使うこと。**

> モード／ツールを選ぶ前・地図上で対象を狙う前・文字列を打ち始める前・取り返しのつかない確定を押す前に、それぞれ M を 1 つ置く。連続した同種の操作（頂点を 4 つ続けて置く等）はまとめて M 1 つとする。

### 0.3 数えたもの

タスクごとに以下も記録した。

- **モード／ツールの切替回数**（表示専用⇄編集⇄追加、左ツールバーのツール選択）
- **サイドバーのタブ切替回数**（一覧⇄プロパティ）
- **スクロール量**（px。実測値）
- **確認ダイアログ・モーダルの回数**
- **ネイティブ（OS）ダイアログの有無**（KLM では測れないので別枠）

## 1. 先に結論

1. **どのタスクも「準備」が本体より高い。** 起動直後は表示専用モードで、地図クリックでは何も選べない（`docs/ui-redesign/調査/05-property-panel.md` §2.3）。だから「国を 1 つ見る」だけで**モード切替 1 回＋タブ切替 1 回**が要り、7.95 秒かかる（T03）。本体である「地図で国をクリックする」は 1.30 秒しかない。

2. **今回の実測で「順序を間違えると全部やり直し」が確定した。** 実データを読み込んで一覧から地物を選び、そのあと「表示専用」を押して編集モードへ入ると、**選択が消える**（実測: `app-active-feature` が `area-002` → 空）。だから正しい最短手順は「先にモードを変えてから探す」であり、直感的な順序（探してから編集モードへ）は必ず一度失敗する。`src/ui/state/store.ts:1399-1401`（`setMode` は選択を全消しする）。

3. **一番重いのは、実際の主作業である「既存データの手直し」の反復。** 仮名の地物 1 件を改名して保存するのに **24.7 秒**（2 件目以降・1 件あたり）。実データには仮名が 220 件以上あり（`11-real-data.md` §1.5）、**純粋な操作時間だけで約 91 分**。名前を考える時間は含んでいない。

4. **その 24.7 秒のうち 13.0 秒（53%）は、作業そのものではない移動である。** 内訳はタブ切替 2 回（5.3 秒）、絞り込み欄の打ち直し（3.0 秒）、プロパティ欄の上下スクロール 2 回（3.3 秒）、その他。名前を打つ操作は 2.2 秒しかない。

5. **プロパティ欄のスクロール位置は地物を替えても残る**（実測: 別の地物を選んでも `scrollTop` が 600 のまま、名前欄は画面外）。つまり 1 件目で保存ボタンまで下げたスクロールが 2 件目の名前欄を隠すので、**反復するほどスクロールが 1 回から 2 回に増える**。

6. **表示制御パネルは 36.4 秒。うち 28.6 秒が純粋なスクロール**（実測 offsetTop 28,546px／表示高 453px＝63 画面ぶん）。KLM 上は「到達できる」が、これは事実上の到達不能である。

7. **4 つのタスクは操作数が数えられない（＝実行不可能）。** 連邦化・自治化（新しい上位領域を作る所属変更、R2/R3）、種別ラベルの入力（R5）、自動保存の間隔変更（R7）、集約地物をまとめて所属変更する（FR-48）。

8. **削減余地は大きく、しかも安い。** タブ自動切替・保存ボタンの固定・Enter での確定・追加時の年代引き継ぎ、この 4 つだけで主要タスクが 2〜4 割短くなる。一覧の行でその場改名できれば 220 件の campaign は **91 分 → 31 分**になる（§6）。

## 4. タスクごとの手順と、そこで見つかった摩擦

### 4.1 T01 「1500 年へ飛ぶ」— 7.8 秒。**Enter が効かない**のが 36%

手順: 年欄をクリック → Ctrl+A → `1500` → **マウスへ手を戻して「ジャンプ」を押す**。

- **Enter は効かない**（今回あらためて実測: 年欄で Enter を押しても現在時刻は `0年` のまま。「ジャンプ」を押して初めて `1500年` になった）。`06-timeline.md` §2 と一致。
- この 1 点で **2.77 秒（36%）**を損している。H（手を戻す）＋M（狙いを定める）＋クリックが丸ごと不要になる操作だからである。
- 代替経路は無い。スライダーは **1px ≒ 8 年**（`06-timeline.md` §6.2）で年を狙えず、目盛りはクリックできず、ホイールも効かない。時間を動かすキーボードショートカットは 1 つも定義されていない（`src/ui/shell/menu.ts:70-153`）。

### 4.2 T02／T03 「探して選ぶ」— タブ切替が毎回 2 回

**今回の実測でわかった重要な事実**（`klm-obs.mjs` の OBS2）:

| 観察 | 実測 |
|---|---|
| 起動直後のサイドバーのタブ | **プロパティ**（`sidebar-tab-properties` の `aria-selected=true`） |
| 一覧で行をクリックした後のタブ | **一覧のまま**（`sidebar-tab-properties` は `aria-selected=false`） |

つまり「探す」は一覧タブ、「見る」はプロパティタブなので、**1 件見るたびに タブ切替が 2 回（一覧へ→プロパティへ）入る**。1 回 2.65 秒（M＋クリック）なので 5.30 秒。T02 の 12.5 秒の **42%** がタブの往復である。

これは要件定義書 §7.4 で「選択時のプロパティタブ自動切替」が意図的な非目標とされている結果（`09-docs-and-rulings.md` §2.1）。**非目標の再検討候補として最上位**に置くべきである。

T03（地図から選ぶ）は表示専用では成立しない。`05-property-panel.md` §2.3 の実測どおり、表示専用モードでは地図クリックで地物を選べない。読むだけでも編集モードに入る必要があり、**読むつもりで編集できる状態になる**という危険を伴う。

### 4.3 T07／T07r 「名前を直して保存する」— 主作業。**24.7 秒／件**

最短手順（今回の実測で確定した順序）:

| # | 操作 | 秒 | 備考 |
|---|---|---:|---|
| 1 | 「表示専用」を押す（＝編集モードへ着地） | 2.65 | **これを先にやらないと、後で選択が消える** |
| 2 | 「一覧」タブ | 2.65 | |
| 3 | 絞り込み欄をクリックして名前の一部を打つ | 4.45 | 4 文字想定 |
| 4 | 行をクリック | 2.65 | 選択される。タブは切り替わらない |
| 5 | 「プロパティ」タブ | 2.65 | |
| 6 | 名前欄をクリック → Ctrl+A → 打ち直す | 5.29 | 6 文字想定 |
| 7 | 保存ボタンまでスクロール（**469px**） | 1.60 | 初期表示では画面外 |
| 8 | 「保存」 | 1.30 | **成功しても画面は何も変わらない** |
| | **合計** | **25.11** | |

**実測で裏を取ったもの**:

- 手順 1 を後回しにすると壊れる: 一覧から `area-002` を選んだ状態で「表示専用」を押すと、`app-active-feature` が **空になる**（`klm-obs.mjs` OBS4）。`src/ui/state/store.ts:1399-1401`。
- プロパティ欄の寸法（1280×800・実データ・編集モード）: 表示 **203×436px**、中身 **1124px**、横方向は内容 243px ＞ 表示 203px で**常時横スクロールバー**（`klm-obs2.mjs`）。
- 各ブロックの位置（パネル内 offsetTop、`klm-obs4.mjs`）:

  | ブロック | offsetTop | 初期表示（0〜436px）で見えるか |
  |---|---:|---|
  | 詳細表示 | 128 | 見える |
  | 名前 | 253 | 見える |
  | 開始年 | 307 | 見える |
  | 終了年 | 361 | 見える |
  | 自動配色を許可 | 541 | **見えない** |
  | 通常表示色 | 652 | 見えない |
  | 境界色 | 830 | 見えない |
  | **保存** | **873** | **見えない**（469px スクロール） |
  | 歴史の錨 | 941 | 見えない |
  | 存続期間を編集 | 1042 | 見えない |
  | 詳細文書 | 1094 | 見えない |
  | 地物を削除 | 約 1206 | 見えない |

- **保存しても何も出ない**（実測: 保存直後にメッセージ要素 0 個、ウィンドウタイトルは `time-map-app` のまま）。`05-property-panel.md` §2.2 と一致。

**2 件目以降がさらに重くなる理由**（今回の新発見）:

プロパティ欄の `scrollTop` は**地物を選び直しても保持される**（実測: 600 のまま／名前欄 offsetTop 253 は画面外）。
つまり 1 件目で保存ボタンまで下げた位置がそのまま残り、2 件目では

1. 名前欄まで**上へ**スクロールする（1.70 秒）
2. 名前を直す
3. 保存ボタンまで**下へ**スクロールする（1.60 秒）

の 2 回のスクロールが要る。よって 2 件目以降は **24.72 秒／件**。モード切替が要らなくなった分（−2.65）を、増えたスクロール（＋1.70）と絞り込みの打ち直し（＋0.56）でほぼ食い潰す。

**規模に掛けるとこうなる**（`11-real-data.md` §1.5）:

| 対象 | 件数 | 現状の所要（操作時間のみ） |
|---|---:|---:|
| 「〇〇付近の領域NN」型の仮名 | 220 | **約 91 分** |
| 「〇〇の島NN」型の仮名 | 323 | 約 133 分 |
| デーレ共和国の「???州」 | 10 | 約 4 分 |
| 合計（仮名 600 件超） | 600+ | **約 4 時間** |

名前を考える時間も、どれが未処理かを思い出す時間も含んでいない。**「実運用に踏み切れない」という所有者の感覚は、この数字と整合する。**

### 4.4 T09 「面を追加して名前と年代を付ける」— 39.4 秒。**うち 17.2 秒が後始末**

追加そのもの（9 クリック＋名前）は 22.3 秒。そのあと必ず必要になる後始末が **17.2 秒（44%）**ある。

後始末が要る理由は `03-tools-add-edit.md` §6 と `06-timeline.md` §4.4 のとおり、**追加フォームが年代を聞かず、開始年／終了年が 0 固定**だから（`src/ui/add/AddPropertyForm.tsx:33-34`）。5080 年で追加しても「開始年 0／終了年 0」になる。

さらに:

- **追加フォームが渡す色は最初から意味がない**（`autoColorEnabled=true` で作るので自動配色が上書きする。`AddPropertyForm.tsx:29-32`）。
- **種別ラベルの欄が無い**（R5）ので、後始末してもラベルは付けられない。
- 面を描いている最中に**閉じる辺が描かれない**（`03-tools-add-edit.md` §2.5-1）ので、確定するまでどんな形になるか分からない。

### 4.5 T04／T05 「頂点をいじる」— 数字は小さいが、実データでは成立しない

KLM 上は 9.1 秒と軽い。しかし実データでは次の壁がある。

- 掴める距離は **画面上 8px 固定**、頂点ハンドルの半径は 5px（`src/ui/map/live-hit-test.ts:162-163`、`src/render/edit-handles-layer.ts:111-120`）。
- 今回の実測: 世界全体表示で実データの面を選ぶと、ハンドルは **88〜156 個**（`klm-obs2.mjs` / `klm-obs3.mjs`）。`03-tools-add-edit.md` §9.6 では最大 1736 個が観測されている。
- したがって現実の手順には**拡大が入る**。Ctrl+= を 4 回で **＋4.4 秒（+48%）**（T04b）。
- **辺の中点ハンドルはクリックでは何も起きない**（ドラッグ必須、`03-tools-add-edit.md` §4.1）。KLM では数えられないが、知らない人は必ず一度空振りする。

### 6.3 実作業（220 件の改名）で見た削減効果

いちばん量のある A1（仮名の改名）で、施策の効きを積み上げるとこうなる。

| 状態 | 1 件あたり | 220 件 |
|---|---:|---:|
| **現状** | 24.72 秒 | **91 分** |
| ＋S-1（タブ自動切替）＋S-2（保存ボタン固定） | 18.77 秒 | **69 分**（−24%） |

## 8. この分析の限界（確かめられなかったこと・前提）

1. **M（心の準備）の置き方は §0.2 の簡略規則による推定**であり、Card らの規則 0〜4 を厳密に適用したものではない。秒数の絶対値は当てにならない。タスク間の比と内訳の比率を使うこと。
2. **スクロールの時間モデル（1 ノッチ 100px・0.10 秒）は仮定**である。実機のホイール量を計測していない。T19 の 28.6 秒は「桁として 30 秒級」という主張であって、秒単位の精度は無い。
3. **視覚探索の時間を入れていない。** 775 行の一覧から目で 1 行を探す、773 件のプルダウンから 1 件を探す、663 件の検索結果から選ぶ、といった探索は KLM の対象外。**現 UI の実際の負担はこの分ぶん、確実に大きい。**
4. **OS のダイアログ**（ファイルを開く／保存する／カラーピッカー／ベースマップ画像の選択）は測っていない。T08 と、保存先が未確定なときの T18 はその分が上乗せされる。
5. **エラーからの復帰を数えていない。** 「拡大しないと頂点が掴めない」「同じ地物を 2 回クリックして対象が外れる」「辺の中点をクリックしても無反応」といった空振りは、実運用では相当な割合で起きるはずだが、最短手順には含めていない。
6. **タッチ・ペン入力は未検証。**
7. **1600×1000 など広い窓での再計測をしていない。** プロパティ欄が広くなればスクロール量は減る（`01-shell-layout.md` §1.2 では表示高 680px）。ただし中身 1124px は変わらないので保存ボタンは依然として画面外に近い。
8. **集約地物を選んだときのプロパティ欄の寸法**を測っていない（実データの集約は 3 件のみ）。
9. **錨が複数ある地物での T25 の手数**は測れていない。実データは全件 1 錨（`11-real-data.md` §1.7）。錨が増えると錨セクションが 1 行約 60px、存続期間を開くと 1 件あたり約 440px 伸びるので（`05-property-panel.md` §10）、スクロール量はさらに増える。

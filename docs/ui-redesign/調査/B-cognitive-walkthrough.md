# B 認知的ウォークスルー — 初見の利用者が 1 手ずつ何につまずくか

対象: ビルド済み `out/` の gimoza を実際に操作して、要件定義書 §2.2 の利用シーンと `docs/ui-redesign/調査/11-real-data.md` §3 のシナリオから 5 つを選び、**初めて触る人になったつもりで 1 手ずつ**辿った記録。
ソース・ビルド・git はいっさい変更していない。

この文書は完成した提案ではなく、**次の工程が読む生データ**である。事実（実測値・スクリーンショット・ファイル:行）と、そこから導いた解釈を分けて書く。

## 0. 調べ方

- `e2e/helpers.ts:49-90` の `launchApp()` と同じ条件で Playwright の `_electron.launch` によるヘッドレス起動（`E2E_TEST=1` / 一時 userData / `--disable-gpu` / `--no-sandbox` / `--disable-software-rasterizer`）。ウィンドウは **1280×800**（`src/shell/main/index.ts:170-172` の既定サイズ）。
- 実データは `derle-import/derle-world-2026-08-16.gimoza`（間引き版・地物 775 件）を、`#app-shell` へ合成 `drop` イベントを流して読み込ませた（`src/ui/file-ops/FileOpsController.tsx:831-841`。ネイティブダイアログを使わない唯一の口。手順は `11-real-data.md` §5.2 に同じ）。
- **クリックは `data-testid` で行ったが、「初見の人がそこを見つけられるか」の判定はスクリーンショットの見た目だけで行った。** testid でしか掴めない部品は「見つからない」と判定している。
- 確定の有無は `window.__E2E__`（`src/ui/App.tsx:711-760`）の `getDrawnFeatureCount` / `getPrimitiveCounts` と、隠し観測マーカー（`app-active-feature` ほか）で裏を取った。これは**利用者には見えない**ので、判定④（前進が分かるか）では常に「見えない情報」として扱う。
- **ネイティブの保存ダイアログを開く操作（Ctrl+S / ファイル→保存）は一度も実行していない。** 読み込んだ実データファイルを書き換える危険があるため。保存まわりは「未保存警告ダイアログ」を経由して観察した。
- 観察スクリプトは scratchpad の `blib.mjs` / `w1.mjs` / `w2.mjs` / `w3.mjs` / `w3b.mjs` / `w3c.mjs` / `w4.mjs` / `w5.mjs`。
- スクリーンショット 46 枚は `docs/ui-redesign/調査/shots/B-*.png`（§7 に一覧）。

### 0.1 判定の枠組み

各手について、認知的ウォークスルーの 4 問を立てる。

| 問 | 中身 |
| --- | --- |
| ① | **正しい操作が思いつくか**（今やりたいことに対して、次に何をすべきかを利用者が思いつくか） |
| ② | **その操作部品が見つかるか**（画面上に見えているか、探して届くか） |
| ③ | **それが正しい部品だと分かるか**（ラベル・状態表示から、それが求める操作だと判断できるか） |
| ④ | **結果のフィードバックで前進が分かるか**（押した後、目的に近づいたと分かるか） |

いずれかが No の手を「失敗した手」とし、原因を 5 つに分類する。

| 記号 | 分類 | 意味 |
| --- | --- | --- |
| **見** | 見えない | 部品・情報が画面に存在しない、または到達不能な位置にある |
| **意** | 意味が分からない | 部品はあるがラベル・文言から何をするか読み取れない／専門語 |
| **順** | 順序が分からない | 先に別のことをしないと進めないのに、それが示されない |
| **応** | フィードバックが無い | 押した結果が画面に現れない、または誤った表示のまま |
| **阻** | モードに阻まれる | モード・ツール・タブの状態が操作を無効化する／状態を破棄する |

40 の失敗手は、原因で束ねると **31 種類**になる（§7 に全一覧）。その分類別の内訳:

| 分類 | 件数 | 代表例 |
| --- | ---: | --- |
| **見** 見えない | 13 | 種別ラベル欄が無い／集約の子に錨欄が無い／一覧が階層を出さない／時間軸に錨の印が無い／未保存の印が無い |
| **応** フィードバックが無い | 9 | 所属変更を確定しても何も言われない／保存しても何も出ない／一覧で選んでも地図に出ない |
| **阻** モードに阻まれる | 5 | 編集モードに入ると選択が消える／ツール中は Ctrl+Z が止まる／表示専用では地図が押せない |
| **意** 意味が分からない | 3 | 「表示専用」を押すと編集モードになる／「開始年」と「錨」のどちらが本物か読めない |

**「見えない」と「フィードバックが無い」で 31 件中 22 件（71%）**を占める。つまり今のつまずきは *操作できない* のではなく、**必要な情報が画面に無い／操作した結果が読めない**ことに集中している。これは `11-real-data.md` §2 の「性能は問題になっていない（読み込み 2.2 秒・選択 1〜2ms）」という実測とも整合する。

### 2.2 W1 の所見

1. **「最初の 1 手」が否定形になっている。** 起動直後は表示専用で、編集を始めるための唯一の入口が「表示専用」というラベルのボタンで、押すと**編集モード**に着地する（`src/ui/shell/useShell.ts:50-63`）。「追加したい」と思った人が最初に押すべきボタンが「表示専用」だと推測できる根拠は画面上に無い。
2. **追加フォームが名前しか聞かないのに、年は錨として 1500 年に記録されている。** つまり *正しい値はデータに入っているのに、画面はそれと矛盾する 0 を見せている*。「開始年 0」を見た利用者は、正しい錨のほうを 0 に直してしまう危険がある。
3. **確定後のフォームが自分の描いた形を覆う。** 名前を決めるときに形が見えない。
4. **保存の手応えが無く、ツールが再武装して同じパネルが残る**ので、「保存が効いたのか」「まだ描いている途中なのか」が区別できない。

### 3.2 W2 の所見

1. **「地図を見ていて、この国は何？」という最も自然な導線が、閲覧中は完全に塞がっている。** 表示専用では地図クリックが無効（§7.4-4 の非目標）、右クリックも 1 項目。読むために編集モードへ入る必要がある。
2. **一覧で選んだのに地図に出ない**、という状態が実データでは普通に起きる。選択したものが描画対象外なら深度を自動で上げる、といった手当が無い。
3. **同じ「探す」が 2 つあり、母集団が違う**（一覧＝全 775 件 / 検索＝描かれている 689 件）。同じ語で結果が食い違う。
4. 実データが全件持っている**種別ラベル（州・島国など 10 種・775 件）は画面に出ないのに検索には効く**（`11-real-data.md` §1.4・§4）。見えないもので検索がヒットする。
5. 副次的な観察: **絞り込みで行が 1 件になると、その下の「地物の表示制御」パネルが画面内に現れる**（`B-w2-06`）。裏を返すと、775 行のときはこのパネルが `offsetTop = 28,546px`（実測）にあり届かない。「絞り込んだときだけ設定が触れる」という予測できない挙動になっている。

## 8. 横断して見えた 6 つの構造

事実の並べ替えから導いた解釈（意見を含む）。

### 8.1 画面が「今どうなっているか」を 1 か所も持っていない

W1〜W5 のすべてで、次のどれも画面に常設されていない。

| 知りたいこと | 現在の表示 |
| --- | --- |
| 今どのモードか | 押されているボタンの色だけ |
| 今どのツールか | 同上 |
| 何を選んでいるか（件数・名前） | プロパティ欄が地物 1 件のときだけ名前を出す。ツールの対象は文字にならない |
| 今どのファイルか | **無し**（タイトルは `time-map-app` 固定） |
| 未保存かどうか | **無し**（診断ダイアログの中だけ） |
| 今どの年を編集しているか | 時間帯中央の太字。ただし保存が効く年（錨の開始時刻）とは別でありうる |
| 縮尺・ズーム | **無し** |

ステータスバーは 28px あるのに **カーソル座標 1 項目しか出していない**（`src/ui/shell/StatusBar.tsx:15-24`）。ここが空いていることが、W2-1・W4-6・W4-8・W5-8 の失敗の共通原因になっている。

### 8.2 「成功した」と言わないので、成功したかどうかが分からない

追加の保存（W1-12）、属性の保存（`05-property-panel.md` §2.2）、所属変更の確定（W3-8）、結合・穴あけの確定（`04-tools-topology.md` §1-3）— **成功時は例外なく無言**。エラーだけが赤字で出る。§7.4-3 が禁じているのは「数秒で自動消滅するトースト」であって、**消えない状態表示は禁じられていない**（`09-docs-and-rulings.md` §2.1 #3 と同じ結論）。

### 8.3 選択が 3 か所で独立に消える／食い違う

| 契機 | 何が起きるか | 根拠 |
| --- | --- | --- |
| モードを変える | 選択が全消し | `store.ts:1399-1401`、W3-4 / W4-2 で実測 |
| ツールを選ぶ | 選択が全消し | `store.ts:1405-1414`、W3-5 |
| ツールが対象を掴む | サイドバーには反映されない（「地物が選択されていません。」のまま） | W3-6 で実測 |

結果として **「一覧で探す → 編集する」という所有者の主導線（`12-bug-history.md` T3）が、必ず 1 回は振り出しに戻る。**

### 8.4 同じものを指す表示が 2 つあって食い違う

| 対 | 食い違いの中身 | 出た手 |
| --- | --- | --- |
| 基本情報の「開始年/終了年」 ↔ 歴史の錨の存続期間 | 追加直後は 0/0 と 1500年→継続中。実データでは 0/9999 と 0年→継続中 | W1-13 |
| 一覧（775 件） ↔ 検索（689 件） | 「アアウェン州」が一覧で 1 件・検索で 0 件 | W2-10 |
| 一覧の選択 ↔ 地図の描画 | 選んだのに地図に描かれない（深度 0） | W2-7 |
| ツールの対象 ↔ サイドバーの選択 | 対象を掴んでいるのに「選択されていません」 | W3-6 |

### 8.5 集約の子が「歴史を持てない」ことが、中核作業を丸ごと止めている

W3 の 3 手目で作業が止まり、その後は「操作はできるが確認できない」状態に落ちた。実データでは該当する地物が 86 件（デーレ共和国 60・正統ノル王国 14・ラヴィエンド・ウィル同君王国 12。`11-real-data.md` §1.3）。

**再設計の前に決めるべき論点**: 集約の子を選んだとき、

- (a) 親の錨を編集する画面を出すのか、
- (b) 子に自分の錨を生やすのか、
- (c) 「この地物の歴史は親（デーレ共和国）が持っています」と明示して親へ誘導するのか。

現状はどれでもなく、**欄そのものが消える**。

### 8.6 ガイド帯が状態機械の一部を隠している

W3-7 のガイド「新しい上位領域とする地物をクリックで選択してください。」は、その場にある 2 つの出口（親を選ぶ／最上位へ外す）のうち片方しか述べない。同種の観察は `04-tools-topology.md` §5-C にもある。**ガイド帯は「今の段階の指示」を出しているが、「今どの段階にいるか」と「ここから出る道が何本あるか」は出していない。**

## 10. 確かめられなかったこと

- **保存の実行**（Ctrl+S / ファイル→保存）。ネイティブダイアログが開き、読み込み元の実データファイルを書き換える危険があるため一度も実行していない。したがって「保存後にどういう表示になるか」は未観察。
- **要件 §2.2-4「重なりを解消する」の認知的ウォークスルー**。`07-dialogs-misc.md` §3 が同種の批評を済ませているため本稿では扱っていない。ただし FR-118 が名指しで「競合解決ダイアログの初回ユーザー向けガイド」を要求している以上、**初見の人による通し観察は別途価値がある**。
- **集約の子に「自分の錨」を生やす手段がドメイン側にあるのか**。W3 では所属変更を通した結果として親に錨が生えたことまでしか確認していない（`11-real-data.md` §8 の未確認事項と同じ）。
- **W3 で記録した独立が、保存して読み直したあとも保たれるか**。保存を実行していないため未確認。
- **実データで頂点を実際にドラッグしたときの応答**（`docs/現状.md` L2 の 1 フレーム 27ms）。W4 ではハンドルの掴みにくさまでで、ドラッグの確定までは行っていない。
- **マウスホバー時のツールチップ・フォーカスリングの見え方**。ヘッドレスのオフスクリーン描画では再現していない。
- **「時間軸に錨の印を出すこと」が §7.4-1（時刻ブックマークの非目標、D32 のユーザー決定）に抵触するかどうか**。`06-timeline.md` §8-1 と同じく、ユーザーの裁定が要る論点として残す。

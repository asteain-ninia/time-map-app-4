# 06 タイムラインと時間入力 — 現状調査

対象: `src/ui/timeline/*`、`src/domain/time/*`、時間まわりの e2e。
調査日: 2026-09-03。ソース・ビルドとも無変更（読むだけ）。
実機観察は `out/` の既存ビルドを Playwright の `_electron.launch` でヘッドレス起動して行った（ウィンドウ 1280×800）。

この文書では内部の言い回しを日常語に置き換えている。

- 「歴史の錨（アンカー）」＝ ある地物の「この時点からの姿」を記録した1枚のスナップショット。地物ごとにこれが時間順に並ぶ（＝錨の列）。
- 「粒度」＝ その時刻が年までか、年月までか、年月日までか。
- 「現在時刻」＝ 地図が今どの年を描いているか、を決めている時刻。実世界の時計とは無関係。

### 1.3 目盛りの中身

`generateTicks`（`time-display.ts:202-224`）が 1/2/5×10ⁿ の刻みから目標本数 10 に近いものを選ぶ。既定範囲 0〜10000 年では 1000 年刻みで 0年…10000年 の 11 本（実測）。

- 目盛りは**表示専用**。クリックしてもその年へ飛ばない（実測: 5000年の目盛りをクリック→現在時刻は変わらず）。
- 目盛りは刻み値の倍数から始まるので、範囲の左端に目盛りが立たないことがある（最小年 −3000 にすると最初の目盛りは 紀元前2000年 で、左端の 紀元前3000年 には目盛りが無い。実測）。

### 1.4 タイムライン上に無いもの

- 錨（各地物の「この時点からの姿」）の位置を示す印は**一切ない**。イベントマーカー（時刻のしおり）は 2026-06-21 にユーザー判断で撤去済み（`.autopilot/DECISIONS.md:134-137` の D32、要件定義書 §7.4 で非目標に明記、`e2e/ux-cluster.spec.ts:216-219` が「存在しないこと」を固定している）。
- 現在時刻はステータスバーにも上部バーにも出ない。時間帯の中央の太字だけが唯一の表示。

## 2. 時刻を変える方法（5通り）と、その手順・キー

すべての経路が `store.setCurrentTime` の一箇所に集まる（`useTimeline.ts:69-92`、`store.ts:1416-1448`）。

| # | 方法 | 手順 | キー操作 | 到達できる精度（実測） |
|---|---|---|---|---|
| 1 | スライダーをドラッグ | つまみを掴んで左右 | ― | **1px ≒ 8年**（1256px÷10000年）。中央+1px=5008年、+2px=5016年、+5px=5040年、+10px=5080年 |
| 2 | スライダーをキーで動かす | 一度クリック（＝フォーカス）してから | ←/→ ＝約1年、PageUp/PageDown ＝10%（＝1000年）、Home/End ＝両端 | →1回で「0年」→「0年12月31日」、もう1回で「1年12月31日」 |
| 3 | 前へ／次へ | ステップ単位（年/月/日）を選んでボタンを押す | ― | 常に1単位。長押しで 350ms 後から 120ms 間隔の連打（`useLongPress.ts:11-12`）。実測 1.5秒押しっぱなしで 10 年進む |
| 4 | 直接ジャンプ | 年（必要なら月・日）を打って**「ジャンプ」ボタンを押す** | **Enter は効かない**（実測: 年欄で Enter を押しても現在時刻は動かず、ボタンを押して初めて動いた） | 年月日ちょうど |
| 5 | 錨を選ぶ | サイドバーのプロパティ欄の錨一覧、または一覧タブの履歴表示で行をクリック | ― | その錨の開始時刻へ即座に同期（`PropertyPanel.tsx:272`、`SidebarContent.tsx:613`） |

補足（すべて実測）:

- **マウスホイールは時間帯の上でも効かない。**
- **時間を動かすキーボードショートカットは存在しない。** `src/ui/shell/menu.ts` の5メニュー（ファイル/編集/表示/ツール/ヘルプ）に時間関連の項目は1つも無い。上表 #2 のキーは HTML の `input[type=range]` の標準動作で、フォーカスしたときだけ効く。
- 再生: ▶再生 を押すと 100ms 間隔のタイマーで進む（`playback.ts:37`）。1倍＝1年/秒（実測: 2000年で開始して2秒後に2002年）。範囲の端に着くと自動停止し、ボタンが「再生」に戻る（実測: 10000年1月1日 で一時停止ボタンが消えた）。**逆再生のボタンは無い**（`usePlayback` は `direction=-1` を受け取れるが、`Timeline.tsx:30` が渡していない）。

## 3. 紀元前と「月日未指定」の扱い

### 3.1 紀元前

- 内部は天文年（0年が存在し、負の数がその前）。`calendar.ts:20-27`。
- 表示は `formatYear`（`time-display.ts:53-56`）が `年 < 0` を「紀元前N年」に変換。変換は1箇所に集約されている。
- **入力側に紀元前のトグルは無い。年の欄にマイナス付きで打つ**（実測: `-300` と入力→中央の表示が「紀元前300年」、`06-timeline-bce.png`）。画面上にこの規約の説明は無い。
- 既定の時間範囲は 0〜10000 年なので、**そのままでは紀元前へ行けない**。`-300` を入れて「ジャンプ」を押すと**エラーも警告も出さずに「0年1月1日」になる**（実測）。範囲外はクランプされるだけ（`useTimeline.ts:71`→`clampToRange`）。
- 設定でタイムライン最小年を −3000 にすると到達できるようになり、目盛りも「紀元前2000年 / 0年 / 2000年 …」に変わる（実測、`06-timeline-range-bce.png` / `06-timeline-bce.png`）。

### 3.2 月・日の未指定

- 時刻の型は「年だけ／年月／年月日」の3種類を型として区別する（`time-point.ts:20-35`）。未指定は 0 埋めではなく「値が無い」状態として持つ。
- 表示も指定された粒度だけを出す（`formatTimePoint`、`time-display.ts:78-87`）。年だけなら「1500年」。なぜ月日が出ないかは**マウスを乗せたときのツールチップ**でしか説明されない（「月日は未指定です（指定された年のみ表示しています）」`time-display.ts:97-106`。HB3-3 のユーザー裁定 `.autopilot/DECISIONS-HB3.md:11`）。
- 入力欄は月・日それぞれに「指定／未指定」トグルがある。日は月が未指定のあいだ押せない（`YearMonthDayInput.tsx:203-214`）。
- 計算するときだけ 1月1日 で補う（`time-point.ts:74-83`）。補完値が保存されることはない。
- **粒度は上がる方向にしか動かない。** 実測した昇格経路:
  - スライダー・再生は常に年月日を返す（`fractionToTime` / `advancePlayback`）。→ スライダーを1回触ると「1500年」は「5080年12月31日」になる。
  - 範囲外ジャンプのクランプも年月日に上げる（`clampToRange`→`completeOf`、`time-display.ts:233-251`）。実測: 「0年」表示が「0年1月1日」に変わった。
  - ステップは単位に応じて上がる（実測: 1501年 →[月+1]→ 1501年2月 →[日+1]→ 1501年2月2日 →[年+1]→ 1502年2月2日）。年に戻しても月日は残る。
  - 戻す唯一の手段は、直接ジャンプで月・日を「未指定」に戻して再ジャンプすること。

## 4. 現在時刻が編集にどう効くか（錨との関係）

### 4.1 3つの時刻がある

| 何の時刻か | どこで決まるか | 出典 |
|---|---|---|
| **地図が描いている時刻** | 現在時刻。各地物の錨の列から「その時刻で有効な錨」を解決して描く（FR-71） | `App.tsx:2376` ほか `resolveDisplayFor(s.domain, s.currentTime, …)` |
| **形を編集したときに錨が打たれる時刻** | **現在時刻** | 追加=`useAddTool.ts:301`、各ツール=`App.tsx:3277 / 3299 / 3320 / 3345 / 3368` の `anchorTime: () => store.getState().currentTime` |
| **名前・色・存続期間を保存したときに効く時刻** | **選択中の錨の開始時刻**（現在時刻ではない） | `PropertyPanel.tsx:296` `buildEditIntent(feature, selectedEntry.start, values)` |

3つ目が独立している理由はコードにも明記されている（`App.tsx:1939-1941`「property-edit (editTime = selected anchor start) … commit at a time that can differ from the view time」）。錨を明示的に選んでいない場合は、現在時刻で解決される錨が自動的に対象になる（`PropertyPanel.tsx:253-258`）。

### 4.2 逆向きの連動

錨を選ぶと現在時刻がその錨の開始時刻へ飛ぶ（`PropertyPanel.tsx:266-274`、`SidebarContent.tsx:606-615`。どちらも `TIME_CHANGE_SOURCE.AnchorSync`）。つまり「錨を選ぶ＝時間を動かす」であり、時間帯の表示は錨選択の下流にある。

### 4.3 現在時刻を動かすと選択が外れることがある

`setCurrentTime` は時刻の反映と同時に、選択中の地物・頂点がその時刻に存在するかを再判定して外す（`store.ts:1416-1448`）。時間を動かしただけでプロパティ欄が空になるのはこのため。

### 4.4 追加時に現在時刻が使われないところ

- 図形の錨は現在時刻に打たれるが、**追加フォームは年代を一切聞かず、基本情報の「開始年／終了年」は 0/0 固定**（`AddPropertyForm.tsx:33-34, 53-58`）。docs/現状.md の R10。
- 実測（`06-timeline-property-after-add.png`）: 現在時刻 5080年12月31日 で面を1枚追加した直後のプロパティ欄には
  - 基本情報 → 開始年 **0** ／ 終了年 **0**
  - 存続期間（錨の区間）→ **5080年12月31日 → 継続中**

  という**別々の「いつからいつまで」が同じ画面に同時に出る**。地図の表示・存在判定を支配しているのは後者（錨の区間）で、前者は所属変更の候補判定などに使われる属性（`domain/affiliation/candidates.ts:58-66`）。

| 反映 | `deriveTimelineState`（`store.ts:616-670`）が `timelineMin/Max` を作り直し、範囲外になった現在時刻を**無言でクランプ**する |

**FR-66 の「アプリ全体または」の側は未実装。** アプリ全体設定タブに時間範囲の欄は無い（`settings/strings.ts` の `APP_FIELD_STRINGS` は スナップ距離・FPS・頂点マーカー上限・アンドゥ上限・重なり解決ガイドの5項目のみ）。docs/現状.md の R1〜R10 にも載っていない欠落。

### 実データとの噛み合わせ（重要）

`derle-world-full-2026-08-16.gimoza` を展開して数えた結果:

- 地物 689 件、錨は 1 件ずつ計 689 件。
- **すべての錨の開始時刻が「0年」（粒度＝年のみ）、終了は全件 null（＝継続中）。**
- 属性の開始年/終了年は 0 / 9999。

つまり **10000 年幅のタイムラインに対し、実データは 0 年の 1 点にしか存在しない**。スライダーの左端 1px 未満に全データが集中している状態で、時間軸を動かしても表示は何も変わらない。時間軸 UI は「これから歴史を刻む」ための道具として設計されているが、現時点の実データにはまだ刻まれていない。

## 6. 使いにくいと考えられる点（根拠つき）

以下は「事実（実測・コード）」＋「そこから考えられる不便」の形で書く。不便の側は意見。

### 6.1 場所を食いすぎている

- 事実: 帯は 200px、ウィンドウ 1280×800 で画面の 25.1%、900×700 では 28.7%。地図は 490px しか残らない。うち直接ジャンプが 70px。
- 事実: 帯の高さは窓を縮めても変わらない（`shell.css:122-131` は `max-height:40vh` の上限だけで下限縮小の仕組みが無い）。
- 意見: 地図編集アプリで下辺に常時 200px は重い。年を打つ欄（1日に数回しか使わない）が最も背が高いのは配分として逆。

### 6.2 マウスでは年を狙えないのに、キーボードの導線も無い

- 事実: 1256px に 10000 年なので **1px ≒ 8年**（実測: +1px で 5008年、+10px で 5080年）。
- 事実: 年を正確に指定する唯一の道は直接ジャンプだが、**Enter で確定できない**（実測）。必ずマウスで「ジャンプ」ボタンを押す。
- 事実: 時間を動かすキーボードショートカットはメニュー定義に1つも無い（`menu.ts` の5メニュー）。
- 意見: 「1500年の状態を見たい」という最頻の操作が、欄をクリック→数字を打つ→ボタンをクリック の3ステップになっている。

### 6.3 スライダーを触ると日付が汚れ、元に戻せない

- 事実: スライダー／再生は必ず年月日の値を返すため、「1500年」だった現在時刻が「5080年12月31日」のような値になる（実測）。
- 事実: 12月31日 が頻出するのは、位置→日数の丸め（`fractionToTime` の `Math.round`）が年境界の1日手前に落ちることがあるため。
- 事実: 年のみへ戻すには直接ジャンプで月・日を「未指定」に戻して再ジャンプするしかない。
- 意見: 実データは全錨が年のみ（前節）。年単位でしか意味の無い世界で、操作するたびに「12月31日」が付いて回るのは、値が壊れたように見える。

### 6.4 直接ジャンプの入力が、他の操作で毎回消える

- 事実: `Timeline.tsx:103-106` は現在時刻を `key` にして入力欄を作り直している。時刻が別経路で変わるたびに欄が丸ごと再生成される。
- 事実（実測）: 再生中に年欄へ「123」と打つと、値は「1」しか残らず**フォーカスも外れる**（`document.activeElement` が入力欄でなくなる）。再生は毎秒10回時刻を書くので、打つそばから欄が作り直される。
- 事実（実測）: 停止中でも、打ちかけの「4321」を残したまま「次へ」を押すと欄は現在時刻で上書きされる（「2」になった）。
- 意見: これは「入力欄が現在時刻の鏡である」という設計の副作用だが、利用者からは入力が食われるバグに見える。

### 6.5 「指定／未指定」トグルの意味が読めない

- 事実: ボタンの文字は**現在の状態**（`draft.monthSpecified ? '指定' : '未指定'`、`YearMonthDayInput.tsx:192`）。押すと反対の状態になる。
- 事実: 読み上げ名は状態に関わらず常に「直接ジャンプ 月 未指定」（`:182`）で、`aria-pressed` だけが状態を持つ。
- 意見: 「指定」と書かれたボタンを押すと欄が灰色になる（未指定になる）ため、動作が予測できない。チェックボックスか「月を使う」のような動作名にすべき箇所。

### 6.6 範囲外ジャンプが無言で握り潰される

- 事実（実測）: 既定範囲 0〜10000 年で `-300` を入れて「ジャンプ」を押すと、エラー表示なしで「0年1月1日」になる。
- 事実: 入力の妥当性検証（`ymd-draft.ts` / `validate.ts`）は暦としての妥当性と ±100万年しか見ておらず、タイムライン範囲は検証の対象外。範囲への押し込みは `useTimeline.ts:71` の別工程。
- 意見: 打った年と違う年に飛ぶのに理由が出ないのは、入力を無視されたのと区別がつかない。

### 6.7 紀元前が「使えるかどうか」すら画面から分からない

- 事実: 紀元前は年欄にマイナスを打つしかなく、画面にその説明が無い。
- 事実: 既定範囲では紀元前に入れず、入ろうとすると 6.6 の無言クランプになる。
- 意見: 架空世界の歴史を扱うアプリで「紀元前」が要件（FR-65）にあるのに、到達手段が隠れている。

### 6.8 再生が実用にならない

- 事実: 1倍＝1年/秒（`playback.ts:27-28` と実測で一致）。既定の 10000 年を通しで再生すると **1倍で約2時間47分、最速の10倍でも約17分**。
- 事実: 逆再生は無い（`Timeline.tsx:30`）。速度は 0.1〜10 倍の6段階固定。
- 意見: 範囲の広さと速度の刻みが噛み合っていない。「範囲全体を N 秒で流す」のような指定でないと使えない。

### 6.9 目盛りが押せない・ホイールが効かない

- 事実（実測）: 5000年の目盛りをクリックしても現在時刻は変わらない。スライダー上でホイールを回しても変わらない。
- 事実: 目盛りは `<span>` で、クリック処理を持たない（`Timeline.tsx:65-89`）。
- 意見: 目盛りが見えていて押せないのは、押せると思って押した人を必ず一度は空振りさせる。

### 6.10 見出しが無く、右端で文字が重なる

- 事実（実測）: 数値表示は3つの裸の数字（`0年` / `2年3月15日` / `10000年`）で、「最小」「現在時刻」「最大」といった見出しが無い。中央が現在時刻だと分かるのは太字だけ。
- 事実（実測）: 「単位: 年」のキャプション（x 1233〜1268）と右端の目盛りラベル「10000年」（x 1231〜1268）が縦横とも重なっている。`06-timeline-band.png` で目視でも確認できる。
- 意見: どちらも一見して直せる粗だが、時間帯が「作りかけ」に見える主因になっている。

### 6.11 エラーで帯が伸び、地図が跳ねる

- 事実（実測）: 入力エラーの一行が入ると帯が 200→220px になり、地図がその分縮む。
- 意見: 打ち間違えるたびに地図の縮尺位置がずれる。エラーは高さを変えない場所（重ねる／固定行）に置くべき。

### 6.12 錨がどこにあるか時間軸から見えない

- 事実: タイムライン上に錨の印は無い（イベントマーカーは D32 で撤去、要件でも非目標）。
- 事実: 錨の一覧はサイドバーのプロパティ欄と一覧タブの履歴表示にしかない（FR-84 / FR-111）。
- 意見: 「非目標」とされたのは**しおり（自由に置く印）**であって、**既に存在する錨を時間軸上に見せること**とは別。1000本の目盛りの中でどこに変化点があるのか分からないまま 8年/px のスライダーを引くのは当てずっぽうになる。ここは要件の再確認が要る（下の未確認事項に回す）。

### 6.13 スライダーにフォーカスしたままだと、他のショートカットが暴発する

- 事実: フォーカス保護（`focus-guard.ts:39-47`）は文字入力系の `<input>` だけを対象にしており、`range`（スライダー）は意図的に対象外。
- 事実（実測）: スライダーにフォーカスした状態で **Ctrl+Z を押すとドメインの取り消しが走る**（追加した地物が消え、一覧が1件→0件になった）。**Escape を押すと選択が解除される**（プロパティ欄が「地物が選択されていません。」になった）。Delete はこの条件では発火しなかった。
- 意見: スライダーは一度クリックすればフォーカスが残る。時間を合わせた直後の Ctrl+Z が「時間操作の取り消し」ではなく「直前の編集の取り消し」になるのは、意図と結果が食い違う典型。

### 6.14 「今どの時刻を編集しているか」が現在時刻と一致しないことがある

- 事実: 形の編集は現在時刻に錨を打つが、名前・色・存続期間の保存は選択中の錨の開始時刻に効く（§4.1）。
- 事実: 画面上の手掛かりは錨一覧の行に付く「編集対象」バッジ（`property/messages.ts:51`）だけで、時間帯側には何も出ない。
- 意見: 時間帯の中央に出ている年と、保存が実際に効く年が違いうるのに、時間帯にはその表示が無い。

### 6.15 追加時に年代を聞かないので、2つの年代が食い違ったまま残る

- 事実（実測、§4.4）: 5080年で追加した面のプロパティ欄に「開始年 0／終了年 0」と「存続期間 5080年12月31日→継続中」が同時に出る。
- 事実: docs/現状.md R10 が同じ問題を挙げている（「1500年の時点で追加しても年代は 0 年になる」）。
- 意見: 時間軸を動かして編集する、という使い方の入口でいきなり時間が無視される。時間帯の再設計と同時に潰さないと、時間軸を使う動機そのものが崩れる。

### 6.16 ステップが 1 単位固定

- 事実: ステップ値は常に 1（`step.ts` / FR-68 が「ステップ値は常に 1 単位」と規定）。10年・100年 単位で送る手段は長押しの連打しかない（1.5秒で10年、実測）。
- 意見: 10000 年幅に対して 1 年ステップと 8年/px のスライダーの2択しかなく、中間（10年/100年）が抜けている。

## 8. 未確認・確かめられなかったこと

1. **錨の位置を時間軸上に見せることが、撤去済みの「時刻ブックマーク」（D32）に該当するのかどうか。** 要件定義書 §7.4 の非目標は「重要な出来事を時間軸へ印として置き、そこへ飛ぶ機能」と書かれており、自分で置くしおりを指しているように読める。既存の錨を印として描くことが許されるかは、ユーザーに確認が要る。
2. **既定 10000 年という範囲が、デーレ界の歴史にとって妥当な広さなのか。** 実データは全部 0 年に集まっており（§5）、どの年代幅で歴史を刻むつもりなのかが分からない。範囲が例えば 0〜2000 年なら、スライダーの分解能の問題（8年/px）はかなり緩和される。
3. **基本情報の「開始年／終了年」と、錨の「存続期間」を今後も両方見せるのか。** 前者が何のためにあるのか（所属候補の判定以外の用途があるか）を追い切れていない。時間帯の再設計より先に決めておかないと、時刻表示の意味が二重になる。
4. **Delete がスライダーフォーカス時に発火しなかった理由。** Ctrl+Z と Escape は発火したので、Delete だけ別の条件（頂点選択の有無など）で止まっている可能性が高いが、そこまでは追っていない。
5. **実データ（689 地物）を読み込んだ状態でスライダーをドラッグしたときの描画の重さ。** 空のプロジェクトでしか操作していないため、再生やドラッグの体感速度は未計測。

UI 全面再設計のための調査資料。**所有者が実際にアプリを動かして踏んだ不具合・使いにくさ**だけを集め、
内部造語を日常語に言い直して並べ直したもの。次の工程が読む生データとして書いている。

読んだ資料: `.autopilot/HUMAN-BUGS.md` / `HUMAN-BUGS-2.md` / `HUMAN-BUGS-3.md` / `HUMAN-BUGS-3-DIAGNOSIS.md` /
`HB-16.md` / `DECISIONS-HB3.md` / `DECISIONS.md`(D54〜D57) / `STATE.md`(要確認リスト・進捗ログ) /
`BUGHUNT-QUEUE.md`(UI 関連のみ) / `git log`(450 コミット) / `お手紙-ファイル図鑑屋より-2026-08-16.md` /
`docs/現状.md` / `docs/実装済み.md` / ソース内に残された報告コメント。

用語の言い直し（この文書では日常語のほうを使う）:

| 内部の呼び方 | この文書での言い方 |
| --- | --- |
| 錨 / アンカー / 錨列 | その地物の「歴史の節目」。ある年に形や名前が変わった記録の並び |
| 集約地物 / アグリゲート | 子をまとめた上位の地物（例: デーレ共和国）。自分では形を持たず、子の合計が形になる |
| リーフ / 末端地物 | 子を持たない、実際に形を持つ地物 |
| 結線 / 未結線 | 機能はあるが画面のボタンから呼ばれていない状態 |
| degrade | 条件が悪いときに機能を静かに落とすこと |
| 表示解決 / displayControl | いまの深さ設定で「どの地物を描くか」を決める仕組み |
| 滑り / スナップ / 共有頂点 | 頂点を隣の線に沿って滑らせる・吸い付かせる・2地物で1点を共有する |

## 2. 傾向 — 所有者はどう使おうとしているか

証拠つきで読み取れること。

### T1. 実データを丸ごと開いて、その上で編纂する

ベンチマークの対象がずっと実データ（722地物 / 99,314頂点）である（`src/ui/map/derle-benchmark.test.ts`、
`STATE.md` 2026-07-12）。所有者の報告も「結合が重たい」「時刻移動が重い」と**実データ規模で初めて出る**もの。
おもちゃの3地物では一度も報告が出ていない。

> 所有者の指示: 「本体の最適化をGO」「**国境線の情報量を落とすくらいなら本体最適化**」（`STATE.md` 2026-07-12）

→ 情報量を減らす方向の妥協を明確に拒否している。再設計でも「重いから間引く」は選択肢に入らない。

### T2. 階層（国 → 州 → 郡）を作りながら、見る深さを切り替えたい

「表示する階層のレベルを変更する UI なくないですか?」が実機報告として出ており、所属変更・結合・
所属の付け替えに関する報告が HB3-15/16、「所属変更で地物消失」、`4a1653f`（展開した集約が子を覆って
クリックを奪う）と繰り返し出ている。実データにも集約が4つ（デーレ共和国・正統ノル王国・ラヴィエンド・
ウィル同君王国）ある。

→ 階層操作は所有者の主業務。にもかかわらず `docs/現状.md` R2/R3 で
**「新しい上位領域を作る」が今も UI から選べない**（＝用語集が定義する連邦化・自治化が実行できない）。

### T3. 一覧から探して飛ぶ、を主要な導線にしている

「一覧に検索が欲しい」「地物一覧にも視点移動が欲しい」「地物一覧と錨一覧ってほぼ同一では」の3件が
同じ日に出ている。地図をパンして目で探すのではなく、**名前から辿りたい**。

→ しかし `docs/現状.md` R9 のとおり一覧は**今もフラットな名前の羅列**で、
子を数十個持つ集約（デーレ共和国など）を一覧から辿れない。T2 とセットで最大の未解決点。

### T4. 呼び名と表示にこだわる（架空世界の一貫性）

「アンカー」→「錨」、「aggregate って何? 日本語で」、地球の地名の全廃。いずれも機能ではなく**語**の報告。
UI 言語は日本語のみという前提と併せて、**画面に出る言葉は世界観の一部**として扱われている。

### T5. 見た目の可読性を機能と同列に扱う

面ラベルが見えない（HB3-26）、地物は透けていてほしい（HB3-13）、グリッド間隔を 0.1° まで（HB3-23）、
時間バーの目盛りが読めない（HB-11/13）、背景地図の白帯・南北ズレ・端が消える。
**地図が正しく読めることが編纂作業そのもの**なので、可読性の不具合は機能不全と同じ扱いになっている。

## 3. 傾向 — どこで躓きやすいか（摩擦の型）

報告を原因ではなく**踏み方**で束ね直すと6つになる。再設計はこの6つを潰す設計にするのが筋。

### F1. 「機能はあるのに画面から呼べない」— 全期間で最頻

- 第1回の4件すべて（`.autopilot/HUMAN-BUGS.md` 末尾の総括）
- 第3回の診断の結論: 「ロジックは純粋関数として実装済みかつテスト通過済みであり、ほぼ全ての HB3 不具合は
  『実装が無い』のではなく『合成ルート・入力層・描画への配線が欠落』という結線層の問題に収斂する」
  （`.autopilot/HUMAN-BUGS-3-DIAGNOSIS.md` §1）
- 2026-07-12 の全数監査で**実装済みなのに UI から呼ばれない機能を12件**捕捉（`docs/実装済み.md`）
- 2026-07-02 の監査で**必須要件6件が実質落ちていた**（穴・飛び地の追加、リング削除と交互構造の再編、
  穴あけによる新地物生成、面積表示、共有頂点の視覚区別、頂点ハンドル削除）
- そして**今も `docs/現状.md` R1〜R10 の 10 件が同じ型**（うち must が3件）

→ 再設計の第一級の判定基準は「機能があるか」ではなく「**画面のどこから何クリックで届くか**」。

### F2. 「今どの状態か」が画面から読めない

- 起動時に見るだけモードで、抜け方が分からずツールが全部灰色（HB-4）
- 分割が終わってもナイフのボタンが押された表示のまま（HB3-17）
- ナイフや所属変更で選んだ対象に色が付かない（HB3-6/15/18）
- 結合で2つ目を選んでも確定ボタンが有効にならない（HB3-16）
- 選んだ頂点にハイライトが無い（2026-07-25 のスクショ検証）

→ **モードとツールと選択という3つの状態**が同時に走っていて、画面がそれを表していない。

### F3. カーソルと結果が一致しない

HB-6（ズームの中心）、HB-7（頂点が置かれる位置）、HB3-4（ドラッグに付いてこない）、

すべて「**触った場所と起きたことがずれる**」型。座標変換の根はすでに一本化されたが、
「掴む的（ハンドル）を描く」「掴んでいる間の見た目を出す」は後から足された機能で、
再設計では最初から前提に置くべきもの。

### F4. 何かが地図の上に重なって、クリックを奪う（3回、別々の原因で再発）

| 時期 | 何が奪ったか | 出典 |
| --- | --- | --- |

このうち 2026-07-13 のものは**選択状態によって上部バーの高さが 28px 変わり、選択のたびに地図が上下する**

→ 再設計では「地図の上に浮かせる」を**原則禁止**にできるかを先に決めるべき。
実際 `4730334` は経度シフトを通常のバーへ移して「構造的に横取りが起こり得ない」状態にしている。

### F5. 同じ操作なのに置き場所・言葉・見た目が揃っていない

### F6. 見た目そのもの

HB-3（無スタイル）、HB-5（スクロールバー）、HB3-25（年操作バーの折り返し）、HB3-26（ラベル不可視）、

## 5. 再設計に効く要約

1. **UI から届くか、が唯一の合否**。「実装はある」は 2026-06〜08 の全報告を通じて一度も反論にならなかった（F1）。
   新しい画面案は、FR ごとに「どのボタンから何クリックで届くか」を書けなければ未完成とみなすべき。
2. **今どの状態か**（モード・ツール・選択・ツールの対象）を1箇所で読めるようにする（F2）。
   現在は「見るだけ／追加／編集」のモードと、その中のツールと、選択とが別々に表示されている。
3. **地図の上に浮かせない**（F4）。3回、別々の原因で操作が奪われた。通常のバー・パネルに置けば構造的に起きない。
4. **一覧を階層表示にする**（R9）＋**新しい上位領域を作れるようにする**（R2/R3）。
   所有者の主業務（階層編纂）と主導線（一覧から探す）が、いま両方とも塞がっている。
5. **追加フォームで年代・色・種別を聞く**（R10/R5）。いま 1500 年に地物を足しても年代は 0 年になる。
6. **確定・取消の置き場と見た目を本当に1つにする**（4.2-D）。位置は揃ったが見た目は6通りある。
7. **見た目そのものが一度も着手されていない**（4.4）。装飾は「最後に足すもの」として計画に明示的に入れる。
8. **回帰テストの作り直しを見積もりに入れる**。人間バグ1件につき実操作の E2E が1本ずつ足されており
   （`e2e/` 配下に spec ファイル 52 本・実行 130 件）、画面を作り替えると testid ごと総取り替えになる。
   ただし**「何を守るか」の一覧としては最良の資産**なので、捨てずに移植する前提で読むべき。

## 0. 先に読むところ

試用して分かったことを、**実運用で最初にぶつかる順**に並べる。詳細は §2 の試用ログ、根拠はすべて実測値かスクリーンショット。

1. **「州の歴史」は記録されるが、州の画面からは一切見えない。** 1200 年でアアウェン州の国境を動かすと、変更はちゃんと 1200 年の錨として保存される。ただしその錨は**親のデーレ共和国に付く**。アアウェン州のプロパティ欄には「歴史の錨」の欄そのものが最後まで出ない（実測 §2.9）。所有者の中核作業「州が独立した／割譲された」を、州を見ながら管理する手段が無い。
2. **選んだものが地図に出ない。** 一覧から「アアウェン州」を選ぶと視点はそこへ飛ぶのに、地図には州が 1 つも描かれず、画面に出ている国名は隣の「正統ノル王国」だけ（`shots/E-trial-A04-select-aawen-map.png`）。階層深度を 1 に上げて初めて見える。一覧・地図・検索の 3 つが別々の母集団を見ている。
3. **編集を始めると選択が消える。** 一覧でバアカを選んでから編集に入ると、選択が空になって探し直しになる（実測 §2.4）。しかも編集に入るボタンの名前は「表示専用」で、隣の「編集モード」を押すと編集から**抜ける**。
4. **所属変更で「州を別の国へ」は事実上できない。** 地図クリックは常に末端地物しか拾わないので、正統ノル王国を親にしたくても実際に親になるのはその子の「南ケナ地方」。確定すると無言で「南ケナ地方 直轄領」が 1 件増え（775→776 件）、階層が 1 段深くなった結果**南ケナ州が地図から消える**（`shots/E-trial-C05-after-confirm.png`）。成功したという合図は一つも無い。
5. **一覧が 775 行フラットで、縦 29,086px＝42.8 画面ぶん。** その一番下（28,428px 地点）に「地物の表示制御」パネルが埋まっている。並べ替えも階層も無く、改名しても行の位置は元のまま（挿入順）なので、直した／直していないの区別が付かない。
6. **実データの頂点密度では頂点編集が成り立たない。** バアカ（601 頂点）を全体表示で選ぶと、隣のハンドルまでの距離は中央値 3.46px、**81% が 5px 未満**。さらに 2,000 頂点を超える地物（ヴィオニア大陸付近の領域01・2,230 頂点）は**ハンドルが 1 つも出ず、理由も画面に出ない**。
7. **成功の合図がどこにも無い。** 保存しても、所属変更しても、分割しても、改名しても、画面は無言。ウィンドウ名は最後まで `time-map-app` で、どのファイルを開いているのかも分からない。それでいて Ctrl+S は確認なく `derle-world-full-2026-08-16.gimoza` を上書きする。
8. **速度は問題ではない。** 読み込み 1.8〜2.2 秒、保存 1.17 秒、階層深度の切り替え 46 ms、一覧の絞り込み 63〜110 ms。重いのは所属変更の確定（2.8 秒）と分割の確定（2.6〜3.1 秒）だけ。**使いづらさは速さではなく、置き場と言葉と合図の問題**という 11 番の結論を、実際に手を動かしても追認した。

### 2.2 一覧の絞り込みは速い / 一覧の縦は長い

| 項目 | 実測 |
| --- | ---: |
| 絞り込み「ア」→ 225 行 | 101 ms |
| 絞り込み「アル」→ 42 行 | 77 ms |
| 絞り込み「アルラ」→ 19 行 | 63 ms |

ただし**絞り込みで行が 1 件まで減ると表示制御パネルが画面に現れる**（`shots/E-trial-A07-aawen-depth1.png` の右側）。到達できるかどうかが絞り込みの結果次第で変わるのは、置き場所としておかしい。

| --- | ---: | --- |

### 2.7 州を別の国へ所属変更する

やろうとしたこと: 南ケナ州（デーレ共和国の子）を正統ノル王国へ移す（11 番の S8「割譲」に相当）。

| 手 | 操作 | 期待 | 実際 |
| ---: | --- | --- | --- |
| 1-3 | 深度を 1 にし、一覧でデーレ共和国を選んで視点を合わせる | 州が見える | 見える（`shots/E-trial-C01-fit-derle-depth1.png`） |
| 4 | 「表示専用」を押して編集モードへ | — | 選択は消える |
| 5 | 「所属変更」ツールを押す | — | ガイド「所属を変更する地物をクリックで選択してください。」。ボタンは 4 つで確定系 3 つは無効（`shots/E-trial-C02-reparent-start.png`） |
| 6 | 南ケナ州をクリック | 南ケナ州が対象になる | なった（`reparent-target = area-016`）。ただし**名前はどこにも出ない**。地図上の細い桃色の輪郭だけが手掛かり |
| 7 | 正統ノル王国の領土をクリック | 正統ノル王国が新しい上位領域になる | **ならない**。拾われたのはその子の「南ケナ地方」（`reparent-parent = area-014`）。地図クリックは常に末端地物しか拾わない（`src/ui/live-lookup.ts:383`）。集約地物を親に選ぶ手段が画面に無い |
| 8 | 「所属変更を確定」を押す | 割譲が記録される | 2,793 ms かけて確定。**成功メッセージなし**。ガイドは初期文に戻り、ツールは次の対象待ちで居座る（`shots/E-trial-C05-after-confirm.png`） |

確定後に起きたことを数えると:

- 地物が **775 → 776 件**に増えた。増えたのは **「南ケナ地方 直轄領」**。名前を聞かれることも、確認されることも、報告されることもなかった（現状.md R4 を実データで再現）。
- 階層深度の上限が **「1 / 1」→「1 / 2」** に変わった。その結果、深度 1 のままの地図から**南ケナ州が消えた**（`shots/E-trial-C04-parent-picked.png` と `C05` を見比べると、南ケナ付近の州境が無くなっている）。利用者から見れば「確定したら州が消えた」。
- 南ケナ州のプロパティ欄は、所属変更の前も後も**「歴史の錨」欄が無いまま**。1200 年に割譲した、という記録を州の側から確認する手段は無い。

要するに、**このアプリの中心にあるはずの「割譲」を、実データで最後まで通すことはできなかった**。できたのは「州を、別の国の一地方の下にぶら下げる」ことだけ。現状.md R2（新しい上位領域を作れない）に加えて、**既存の集約を親に指定することすらできない**というのが実測の結論。

### 2.8 ナイフで分割する

アルラーク国（1,706 頂点）を対象に 2 通り試した。

**失敗した 1 回目（東西に切る）**

| 手 | 操作 | 実際 |
| ---: | --- | --- |
| 1 | ナイフを選ぶ | ガイド「分割する末端地物を選択してください。」 |
| 2 | アルラーク国をクリック | ガイド「分断線を引いて対象面を貫いてください。」 |
| 3-4 | 国をまたぐ**まっすぐな 2 点の線**を引く | 頂点 2 個 |
| 5 | 「分断線を確定」 | 3,065 ms 後に赤帯で拒否: **「分断線が自己交差しています。交差しないように引き直してください。」**（`shots/E-trial-E05-knife-inheritor.png`） |

引いたのは点 2 つの直線で、自己交差しようがない。コードを見ると、この文言は `src/domain/knife/split-geometry.ts:635` で **「切片の中点がどの断片にも入っていない」** ときにも使い回されている。凹んだ形の国を横切ると起きる。**利用者は、していないことを咎められ、直しようのない指示（交差しないように引き直せ）を受け取る**。

**成功した 2 回目（南北に切る）**

同じ国を南北に切ったら通った。全部で **8 クリック**。

| 手 | 操作 | 実際 |
| ---: | --- | --- |
| 1 | 対象をクリック | — |
| 2-3 | 分断線の 2 点をクリック | — |
| 4 | 「分断線を確定」 | 2,564 ms 後に「継承先を選択」ダイアログ。「こちらを継承先にする（面 1）」「（面 2）」の 2 択と、小さい方を囲った枠（`shots/E-trial-H01-inheritor.png`） |
| 5 | 面 1 を選ぶ | — |
| 6 | 「継承先を確定」 | ガイド「新規地物のプロパティを入力してください。」 |
| 7 | 名前に「アルラーク南部」と入力 | フォームの入力欄は**名前 1 つだけ**。見出しが「新規地物のプロパティ」と**二重に出る**（`shots/E-trial-H03-newprops.png`） |

つまづきが 2 つ。

- 継承先の 2 択が**「面 1」「面 2」としか呼ばれない**。どちらが元のアルラーク国の名前・色・文書を引き継ぐのか、地図の枠を見て推測するしかない。

| 1-2 | 1200 年へジャンプ | 「1200年」。地図も一覧も変わらない |
| 3-5 | 編集モードにしてバアカを選び直す | 錨は 1 行「0年→継続中」 |
| 6 | 頂点を 1 つ動かす | **錨が 2 行になる**: 「0年→継続中」「1200年→継続中（編集対象）」。面積 3,048,591.93 → 3,052,679.78 km²（`shots/E-trial-D01-edit-at-1200.png`） |
| 7-8 | 0 年へジャンプ | 面積が **3,048,591.93 km² に戻る**。1 頂点だけ位置が違う |

**時間の仕組み自体はちゃんと動く。**「その年に触れば、その年の錨ができる」という設計は実データでも成立していた。再設計で壊してはいけない土台。

ただし見せ方が追いついていない。

- 通史一覧は **689 → 690 件**になったが、増えた行のラベルは「バアカ」。**同じ「バアカ」が 2 行並ぶだけで、どちらが 0 年でどちらが 1200 年か画面に出ない**（`shots/E-trial-D03-history-after-edit.png`）。錨が 10 個に育てば、同じ名前が 10 行並ぶ。
- プロパティ欄の「開始年 0 / 終了年 9999」は 1200 年に移動しても変わらない飾りのままで、錨の「0年→継続中」と食い違ったまま並んでいる（`shots/E-trial-D01-edit-at-1200.png` の右）。

**集約の子（アアウェン州）で試す — ここが核心**

| 手 | 操作 | 実際 |
| ---: | --- | --- |
| 1 | 深度 1・1200 年・編集モードでアアウェン州を選ぶ | 錨の欄は**無い**（`anchor-section` 0 個）。面積 172,352.16 km²。頂点ハンドルは 96 個出る |
| 2 | 頂点を 1 つ動かす | 面積 172,352.16 → **169,694.23 km²**。錨の欄は**やはり出ない** |
| 3 | 一覧（通史）を見る | 690 件。「アアウェン」で絞ると **0 件** |
| 4 | 親のデーレ共和国を選ぶ | 錨が **2 行**: 「0年→継続中」「1200年→継続中（編集対象）」 |
| 5 | 0 年へ戻してアアウェン州を見る | 面積が **172,352.16 km² に戻る**。錨の欄は無いまま |

**結論**: 集約の子の歴史は、**記録されている。ただし親の錨の中に、名前のないスナップショットとして入る**。11 番の報告が「確かめられなかった」とした点への答えがこれ。

問題は 3 つ。

1. 州を見ている限り、自分の歴史が**画面に一切現れない**。1200 年に何をしたのか、州のプロパティ欄からは確認も取り消しもできない。
2. 通史一覧では「デーレ共和国」の行が増えるだけ。**60 ある州のどれをいつ動かしたのかが、名前からは絶対に分からない**。デーレ共和国だけで年代が増えれば「デーレ共和国」が何十行も並ぶ。
3. 州の存続期間（いつ生まれ、いつ消えるか）を州から設定する場所が無い。「南ケナ州は 1200 年に独立して以後デーレ共和国の州ではない」を書く欄が、州の画面に存在しない。

### 2.10 仮名を 1 件だけ本名に直す（実運用の主作業）

実データは 775 件中 600 件超が仮名（11 番 §1.5）。1 件直すのに何手かかるか測った。「アレクリオ大山脈付近の領域24」→「アレクリオ山北公国」。

| 手 | 操作 |
| ---: | --- |
| 1 | 「一覧」タブ |
| 2 | 絞り込みに名前を入力 |
| 3 | 行をクリック |
| 4 | 「プロパティ」タブ |
| 5 | 名前の欄を書き換え |
| （+） | **プロパティ欄を下へスクロール**（保存ボタンは欄の 755.8px の位置にあり、表示高 680.4px の初期表示に入らない） |
| 6 | 「保存」を押す |

**6 手 ＋ スクロール 1 回、実測 4.3 秒。** そのあとに起きたこと:

- 保存されたのに**何のメッセージも出ない**（`save-message` は空）。
- **一覧の絞り込み欄に古い名前が残ったまま「0 / 775件」になる**。改名するたびに一覧が空になって、自分がどこを見ていたか失う（`shots/E-trial-K03-list-after-rename.png`）。
- 「次の未命名へ」といった導線は無い。600 件やるならこの往復を 600 回する。
- 基本情報の入力欄は **名前・開始年・終了年 と 色 4 つだけ**。実データが全 775 件に持っている**種別ラベル（島国・州・領海…10 種）の欄は無い**（現状.md R5 を実データで再確認）。

### 2.11 保存する

保存ダイアログは差し替えて一時フォルダへ書き出した。

| 項目 | 実測 |
| --- | ---: |
| 「名前を付けて保存」→ ファイルが出来るまで（無編集・775 件） | **1,166 ms** |
| 出来たファイル | 2,022,467 bytes |
| 保存後のステータスバー | 「準備完了」（保存前と同じ） |
| 保存後のウィンドウ名 | `time-map-app`（同じ） |
| 未保存であることの表示 | **どこにも無い**（編集を 1 つ入れた状態でも「準備完了」のまま） |

速さは十分。問題は**保存したことも、未保存であることも、画面のどこにも出ない**こと。加えて、ファイルメニューの「保存 Ctrl+S」は**確認なしに読み込み元（`derle-world-full-2026-08-16.gimoza`）を上書きする**。どのファイルを開いているのかが画面に出ないまま上書きだけが効く、という組み合わせは実運用で怖い。

## 3. 速度の実測まとめ

すべてオフスクリーン描画（`--disable-gpu`）での実測なので、実機の GPU 描画より不利な条件。それでも次のとおり。

| 操作 | 実測 | 要件 §5.1 の目安 |
| --- | ---: | --- |
| 実データ読み込み（775 地物） | 1,770〜2,236 ms | 「ある程度長くてよい」→ 余裕 |
| 名前を付けて保存 | 1,166 ms | — |
| 階層深度 0→1（描画 689→772 件） | **46 ms** | — |
| 一覧の絞り込み入力 1 文字 | 63〜110 ms | — |
| 一覧から地物を選ぶ（視点合わせ込み） | 676 ms | — |
| 頂点ドラッグ中のフレーム間隔（バアカ 601 頂点） | 中央 **17.0 ms** / 90% 18.7 ms / 最大 34.5 ms（待機中の基準は 16.6 ms） | 描画予算 16.6 ms |
| 地図パン中のフレーム間隔 | 中央 16.6 ms / 最大 28.7 ms | 同上 |
| **所属変更の確定** | **2,793 ms** | 100 ms |
| **ナイフの切断確定** | **2,564〜3,065 ms** | 100 ms |

- 密な地物（601 頂点）のドラッグでフレームが 16.6 ms を超える割合は 57%、最大 34.5 ms。現状.md L2 の「27 ms 程度」と同じ桁。**引っかかりはあるが破綻はしていない**。
- 一方、**所属変更と分割の確定は 2.5〜3 秒かかり、その間まったく無反応**（進行中の表示が無い）。ここだけは実運用で「固まった」と感じるはず。

## 5. 良かったところ（再設計で壊してはいけない）

- **その年に編集すれば、その年の錨が自動でできる。** 0 年に戻せば元の形に戻る。時間の仕組みそのものは実データでも正しく動いた（§2.9）。
- **速い。** 読み込み 1.8 秒、保存 1.2 秒、階層深度の切り替え 46 ms、一覧の絞り込み 100 ms 以下。速度のための妥協を UI 側でする理由はもう無い。
- **Ctrl+Z が効く。** 頂点を動かしたあと 1 手で戻せた（ツールを持っていないとき）。
- **絞り込みが 1 件になると表示制御が使える。** 中身は動く。置き場所だけの問題。
- **ナイフは南北に切れば 8 クリックで通り、継承先のプレビューも出る。** 手順の骨格は成立している。

## 6. 再現手順

観察スクリプトは `%TEMP%\claude\e--WORKSPACE-time-map-app-4\<session>\scratchpad\E-trial\` に置いた（`lib.mjs` ＋ `A-` 〜 `M-` の各試行）。骨子は次のとおり。

1. `e2e/helpers.ts` の `launchApp()` と同じ引数で `_electron.launch`（`E2E_TEST=1`、`--user-data-dir=一時ディレクトリ`、`--disable-gpu`、`--no-sandbox`、`--disable-software-rasterizer`、`cwd` はプロジェクト直下、`ELECTRON_RUN_AS_NODE` は env から削除）。
2. `[data-testid="app-shell"]` を待つ。
3. `#app-shell` へ `dataTransfer` を差し替えた `dragover` / `drop` を流す。**パスは `/` 区切りで渡す**（`\` のエスケープを 1 つ落としただけで `read-failed` になり、画面には何も出ないので気付けない）。
4. `[data-testid="unified-list-count"]` が `775件` になるのを待つ。
5. 地図上の任意の地物をクリックしたいときは、`.gimoza`（zip）の中の `manifest.json` から領域リングの頂点を読み、多角形の内側でいちばん境界から遠い点を求めておく。そのうえで `window.__E2E__.screenToWorld` を 3 点サンプリングして世界→画面の線形変換を作り、内点を画面座標へ直せば狙った地物を確実にクリックできる（本調査の `points.json` はこの方法で作った）。

観測に使った口:

| 口 | 用途 |
| --- | --- |
| `window.__E2E__.getActiveFeature()` / `getMode()` / `getActiveTool()` | 選択・モード・ツールの実際の状態 |
| `window.__E2E__.getVertexHandlePositions()` | 頂点ハンドルの世界座標（密度の計測・ドラッグ対象の特定） |
| `window.__E2E__.getPrimitiveCounts()` | 描画されたハンドル数（表示上限に掛かったかの判定） |
| `window.__E2E__.getDrawnFeatureCount()` | 深度を変えたときの描画件数 |
| `window.__E2E__.screenToWorld(x, y)` | 世界⇄画面の較正 |
| `requestAnimationFrame` を仕込んだフレーム間隔 | ドラッグ中・パン中の描画の重さ |
| `[data-testid="reparent-target"]` / `reparent-parent` / `knife-cut-count` | `hidden` 属性つきで目には見えないが、DOM からは読める |

保存の実験だけは、メインプロセスで `dialog.showSaveDialog` を一時フォルダのパスを返す関数に差し替えてから「名前を付けて保存」を実行した。これをしないと `Ctrl+S` が `derle-import/` の実データを直接上書きする。

## 7. 確かめられなかったこと

- **錨が 10 個に育ったときの挙動。** 今回作れた錨は 1 地物あたり最大 2 個まで。要件の目標規模（5,000 地物 × 10 錨）での一覧・時間バー・表示解決の挙動は未測定。
- **集約地物そのものをまとめて所属変更する経路。** 地図クリックが末端しか拾わないので入口に到達できず、ドメイン側にその能力があるかは実機操作では確定できなかった（08 番の報告に `parentCreate` / `parentCreateWithTerminal` が UI から未参照とある）。
- **重なり解決（FR-62）に入る経路。** 所属変更・分割とも競合待ちには入らなかった。
- **測量モードと詳細文書**を実データで通す試験（05 番・07 番の報告と範囲が重なるため今回は省いた）。
- **実機（GPU 有効）でのフレーム時間。** 今回はオフスクリーンのソフトウェア描画なので、§3 のフレーム値は「これより悪くなることはない」という上限として読むのが正しい。
- **ナイフの「自己交差」誤判定がどの形でどれだけ起きるか**の網羅。アルラーク国を東西に切った 1 例を確認しただけで、実データ 775 件のうち何件がこの状態になるかは数えていない。

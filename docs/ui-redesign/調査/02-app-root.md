## 0. 先に結論だけ

- App.tsx は **画面部品ではなく「配線盤」** である。自分では絵を描かず、①ストアを作る、②地図描画エンジンを DOM に取り付ける、③11 個のツール部品と 4 個のモーダル系部品をぶら下げる、④メニュー／ショートカットのコマンド実体を登録する、⑤全部の確定操作を 1 本の「元に戻す」記録口に集める、の 5 つをやっている。
- **状態の置き場は 3 層に分かれている**。(a) Zustand ストア（モード・ツール・選択・時刻・カメラ・表示制御・絞り込み・設定）、(b) App の React 状態 14 個（ほぼ全部が「いまキーボードを誰が握っているか」の申告用）、(c) App の ref 24 個（再描画を起こしたくない値と、地図が載るまで空振りする遅延結線）。
- **ツール 11 個のうち、2 個（選択・頂点編集）は押しても実質何も変わらない**。編集モードならツール未選択でも頂点は掴めて動く（§3.3）。
- **キーボードは「グローバル 1 本＋ツールごとに 1 本」の二重構造**で、衝突は `shortcutsSuspended` という OR の羅列（11 項目）で手作業に回避している（§4.3）。ここは新しい画面を足すたびに更新しなければ穴が空く。
- **属性編集で送られるのは 10 項目だけ**。種別ラベル（国・州・郡）は `docs/現状.md` R5 のとおり本当に送られていない（§6.2 で実行経路まで確認）。
- 再設計で危険なのは **地図セルの DOM 構造・地図の再マウント・サイドバーのタブ id・ツール重ね順の 1 枠共有**（§7）。

大きく 3 種類。

**(a) 地図が載るまで空振りする遅延結線**（`onMapMount` の中で代入され、地図の破棄時に null に戻る）

| 行 | ref | 何をする | null のときの挙動 |
| --- | --- | --- | --- |
| 473 | `rendererRef` | 描画エンジン本体 | 描画・座標変換が無害な空振り |
| 484 | `cameraInputRef` | ツールの入力層から中ボタンパン／ホイールを地図へ転送する口 | 空振り |
| 494 | `contextMenuOpenerRef` | 右クリックメニューを開く口 | メニューが出ない |
| 513 / 520 / 529 | `fitCameraToFeatureRef` / `fitCameraToAllRef` / `zoomMapRef` | 選択地物へ寄せる／全体表示／拡大縮小 | メニュー項目が **灰色（無効）になる**（`canRun` が false、`App.tsx:2113-2133`） |

### 2.4 「元に戻す」履歴は App が持っている

ストアではなく `historyRef`（`App.tsx:1891`）。全ての確定は `recordCommand`（`App.tsx:1945-1963`）を通り、そこで

1. 自動色塗り直しを同じ 1 手に合成し（`maybeComposeAutoRecolor`）、
2. 履歴に 1 手として積み、
3. ストアへ結果を書き戻して選択を解決し直す

という順で走る。**アプリ内の全編集経路（追加・分割・結合・所属変更・穴／飛び地・穴あけ・ドラッグ編集・属性編集・存続期間編集・詳細文書・頂点削除・地物削除・共有解除・競合モーダル確定・パレット変更）が例外なくここを通る**。再設計で新しい編集導線を足すときは、必ずこの 1 本に繋ぐ必要がある。

## 3. モードとツールの状態機械

### 3.1 モードは 3 つ、ツールは 11 個

- モード: `view`（表示専用）/ `add`（追加）/ `edit`（編集） — `src/ui/state/session.ts:20-28`
- 追加モードのツール 3 個: 点を追加 / 線を追加 / 面を追加
- 編集モードのツール 8 個: 選択 / 頂点編集 / 地物移動 / ナイフ（分割）/ 所属変更 / 結合 / 穴・飛び地 / 穴あけ
- 対応表は `src/ui/shell/tools.ts:33-53`、日本語ラベルは `src/ui/shell/strings.ts:58-72`

排他性は「ストアがモードを 1 つの値としてしか持てない」ことで担保されている（同時に 2 モードは表現不能）。ツールも `activeTool` 1 個だけ。

**モード切替の導線は 2 系統**:

- ツールバーの 3 ボタン（`src/ui/shell/Toolbar.tsx:40-66`）。表示専用ボタンは往復トグル、追加／編集ボタンは同じものを再度押すと表示専用へ戻る（`useShell.ts:41-49`）。
- 表示メニューの「表示専用モード切替」（`App.tsx:2088-2101`）。表示専用 ⇄ 編集 の往復のみ（追加へは行けない）。

### 3.2 切替時に何が消えるか（リセット契約）

| 操作 | `mode` | `activeTool` | 選択 | ツールの作図中データ | 根拠 |
| --- | --- | --- | --- | --- | --- |
| `setMode(m)` | 変わる | **null に落ちる** | **全消し** | 各ツールが `activeTool` の変化を見て破棄 | `store.ts:1399-1401` |
| `setActiveTool(t)` | 不変 | 変わる | **全消し** | 同上 | `store.ts:1405-1414` |
| `setActiveTool(t, 保持する選択)` | 不変 | 変わる | 保持 | 破棄 | 競合解決後の再武装と右クリックからのツール起動のみが使う（`App.tsx:2335-2352`, `2813-2831`） |
| 測量モード ON | 不変 | **null に落ちる** | 保持 | — | `store.ts:1567-1573` |
| ツールを武装 | — | — | — | 測量モードが **自動で OFF** | `SurveyToolController.tsx:101-105` |
| モード/ツールが変わった瞬間 | — | — | — | 進行中のパン・ドラッグ編集を強制中断 | `App.tsx:1568-1574`（`dispatcher.onModeChange()`） |

**「ツールを切り替えると選択が消える」のが既定**という点は、再設計で最も体感に効く仕様である。たとえば「地物を選ぶ → 分割ツールに持ち替える」を素直にやると選択が消える。右クリックメニューからツールを起動する経路だけが、選択を明示的に持ち越している（`armEditTool`、`App.tsx:2335-2352`）。

### 3.3 ツールの「効き目」の実際 — ここは要注意

コード上で `activeTool` を実際に見ているのは 4 箇所しかない。

| ツール | 実際の効果 | 根拠 |
| --- | --- | --- |
| 選択 `edit.select` | **なし**（押下表示が変わるだけ） | `TOOL_ID.EditSelect` の参照は `tools.ts:40` の一覧登録のみ |
| 頂点編集 `edit.vertex` | **右クリックメニューの品揃えが「形状編集」系になるだけ** | `src/ui/map/context-menu-adapter.ts:68` |
| 地物移動 `edit.move` | 地物本体のドラッグで**丸ごと移動**が許可される（他ツールでは不許可） | `App.tsx:1260-1262` |
| ナイフ / 結合 / 所属変更 / 穴・飛び地 / 穴あけ | それぞれ専用コントローラが起動し、地図を覆う入力層を出す | 各コントローラ（§5） |

その結果:

- **編集モードでツール未選択（null）でも、頂点の選択・ドラッグ・矩形選択・辺の中点追加は全部できる**。編集ハンドルの描画条件は「編集モード かつ 上記 5 ツールでない」なので、null は通る（`App.tsx:874-890`）。
- 「選択」と「頂点編集」はユーザーから見て区別がつかない。再設計ではこの 2 つを統合するか、意味を持たせるかの判断が要る。

### 3.4 入力層の奪い合い

地図の当たり判定・パン・ズームは `onMapMount` で DOM に直接 addEventListener している（`App.tsx:1470-1481`）。取り付け先は 2 つ:

- `[data-testid="map-input-layer"]`（見つからなければキャンバス要素） … pointerdown/move/up/cancel/leave/contextmenu/wheel
- 地図セル `.map-area`（キャンバスの親） … ステータスバーのカーソル座標用の pointermove/leave

ツールが作図中は**その上に透明な入力層をかぶせる**ので、背景のリスナーには届かない。中ボタンパンとホイールズームだけは、ツール側から `mapCameraInput` 経由で同じ配送器へ転送している（`App.tsx:1494-1544`）。

ボタンとモードの対応（`src/ui/map/dispatch.ts:81-84`）:

| モード | パンに使えるボタン | 左ボタンの行き先 |
| --- | --- | --- |
| 表示専用 | 左・中 | パン |
| 追加 | 中のみ | 追加ポート（ただし App は **空実装** を渡している、`App.tsx:1359`。実際の追加入力はツール側の入力層が取る） |
| 編集 | 中のみ | 選択＋ドラッグ編集 |

右ボタンは全モードで常にコンテキストメニュー要求。

### 3.5 測量は第 4 の軸（モードではない）

測量モードは `store.survey` という別スライス。表示専用モードでも使える（上部バーにコントロールがある、`App.tsx:3417`）。確定した測量線は**他のツールの重ね書きや消去に耐えて残る**ため、専用の描画枠を持っている（`App.tsx:1790-1802`）。

- **競合が出たら `setConflictState({...})` でモーダルを出し**、確定すると `onConflictCommitted`（`App.tsx:2938`）→ `recordCommit` → **ツールを null→元 に往復させて下書きだけ捨てる**（`reArmActiveTool`, `App.tsx:2813-2831`）。この往復は `queueMicrotask` を挟む。

## 7. UI 再設計で「ここを動かすと壊れる」結合点

危険度の高い順。

**1. 地図セルの DOM 構造に直接依存している（`App.tsx:594-608`）**
`onMapMount` は「キャンバス取付要素の親の中の `[data-testid="map-input-layer"]`」と「取付要素の親（= 地図セル）」を `querySelector` で探す。見つからないとキャンバス要素そのものへフォールバックし、**エラーも警告も出ないまま**カーソル座標がツール上で消える／入力の取りこぼしが起きる。地図まわりのマークアップを組み替えるなら、この 2 つの前提を先に明示的な props へ移すべき。

**2. 地図を再マウントするとカメラ（表示位置・倍率）が初期化される**
描画エンジンは生成時にカメラを渡されず（`src/ui/add/host-ports.ts:570-572`）、自前の初期カメラ＝全体が入る倍率で起動する（`src/render/canvas2d-renderer.ts:106`）。ストアの `camera` は**エンジン → ストアの一方向の写し**でしかない（`App.tsx:640-660`）。ストアからエンジンへ書き戻す経路は存在しない。したがって **地図をタブや条件付きレンダリングで一度アンマウントすると、戻したときに視点が全体表示へリセットされる**。加えて `zoomMapRef` 等が一度 null になるので、表示メニューの拡大・縮小・全体表示がその瞬間だけ灰色になる（`App.tsx:1671-1673`）。レイアウト変更で地図を出し入れする設計は現状のままでは成立しない。

**3. サイドバーのタブ id に文字列で依存している（`App.tsx:2353-2371`）**
右クリック「プロパティを編集」は `document.getElementById('sidebar-tab-properties')` を探して `.click()` する。見つからないと `console.warn` を出して黙って何もしない。サイドバーを作り替える／タブ構成を変えるなら、この導線が最初に死ぬ。原因はサイドバーがタブの選択状態を自分の中に閉じ込めていて外から切り替える手段が無いことで、その旨は同箇所のコメントに「明示的なタブ状態 API は shell の改修になるので後回し」と書かれている。

**4. ツールの絵の出し先が 1 枠しかない（`App.tsx:1731-1789`）**
ナイフ・結合・所属変更・穴/飛び地・穴あけの 5 ツールは、描画エンジンの **同じ `drawKnife` 枠**に絵を出している。「5 つは排他だから同時には使わない」という前提の上に立っている。2 つのツールを同時に見せる／片方の対象強調を残したまま別ツールに移る、といった再設計をするなら描画枠を分ける改修が要る（測量だけは専用枠を持っている）。

**5. キーボード占有の申告が手作業の OR（`App.tsx:2755-2792`）**
§4.3 のとおり。新しいモーダル・パネル・作図系 UI を足すたびに 3 箇所（`useState`・子への `onXxxChange` prop・OR 式）を同時に直す必要がある。忘れると Ctrl+Z / Delete が貫通する。

**6. ツール切替＝選択の破棄（`store.ts:1405-1414`）**
選択を保ったままツールを持ち替える導線は、右クリック経由（`armEditTool`）と競合解決後の再武装しか無い。「地物を選ぶ → ツールを選ぶ」という自然な操作順を採るなら、この既定を変えるか、全ツール起動を `preserveSelection` 付きに揃える必要がある。

**7. `onMapMount` が 1,100 行の一枚岩（`App.tsx:588-1687`）**
描画・当たり判定・選択・ドラッグ編集・スナップ・右クリック・カメラ・再描画スケジューラ・E2E 観測フック・カーソル座標が 1 つのクロージャに同居し、内側の変数（`ports`, `dispatcher`, `liveEditSession`, `flushRedraw`）を共有している。ここを触る改修は分割から始めないと差分が読めない。

**8. 再描画のトリガが「監視する値の一覧」に依存（`App.tsx:1627-1636`, `src/ui/map/redraw-watch.ts`）**
描画エンジンの各取得口が読む値は、すべて `redrawWatch` の監視集合に載っていなければならない。過去に 2 回（グリッド設定、頂点選択）漏れて「操作しても画面が変わらない」不具合になっている。新しい表示状態を足すときは必ずここも足す。

**9. 履歴の再構成が「プロジェクト参照が変わったか」で判定（`App.tsx:2477-2513`）**
自分が確定したもの以外でプロジェクト参照が変わったら、下敷き地図の差し替え（回数カウンタで判別）なら履歴を温存、それ以外（読み込み・新規）なら履歴を作り直す、という規則。プロジェクトを差し替える新しい導線（例: テンプレート適用、インポート）を作るなら、この判別に載せる必要がある。

**10. コマンドの有効・無効は「登録されているか」で決まる**
未登録のコマンドは灰色になる（`commands.ts:96-101`）。過去に「メニューには載っているのに誰も実体を登録していない」項目が 5 件見つかって塞がれている（削除・表示専用切替・全体表示・拡大・縮小）。新しいメニュー項目を足すときは `menu.ts` と登録側の両方が要る。

**11. ツール入力層は `mapOverlay` スロットに限る（`App.tsx:3239-3252` のコメント）**
画面全体のオーバーレイに戻すと、透明な層が上部バー・タイムラインを覆って操作を奪う不具合が再発する。

**12. 詳細パネルの掃除がプロジェクト参照の変化に依存（`App.tsx:2990-3006`）**
浮遊パネルは、対象地物がプロジェクトから消えたときにストア購読で刈られる。閉じるボタンしか無い設計なので、この購読が切れると「閉じられない透明なパネル」が残る。

# P1 作業の流れ最優先（Jobs-to-be-Done／シナリオ駆動）
執筆: Opus

gimoza の UI を白紙から設計し直す 5 案のうちの 1 案。レンズは**利用者の作業の流れ**。
根拠はすべて `docs/ui-redesign/01-現状分析.md`（以下「現状分析」）の節番号、`ファイル:行`、評価シナリオ番号（V1〜V15）で示す。
これは完成品ではなく、次の工程（案の比較・裁定・実装計画）が読む生データである。

---

## A. 設計思想と、3 論点への立場

### A.0 設計思想（1 段落）

**この道具の利用者は 1 人で、やることは 5 種類の「片付けたい仕事」しかない。だから画面は道具（動詞）ではなく仕事（目的）を単位に組み、どの仕事も「対象を決める → 手を入れる → 次へ」という同じ 3 拍子で終わるようにする。**
現状分析 §2.1 が示すとおり、所有者の主要作業 5 つのうち 4 つが「完了できない」。しかもその原因の大半は機能の欠落ではなく、**手順の途中で画面が別のことを言い出す**ことにある——探す場所と見る場所が排他タブで分かれ（C5）、道具を持つと選択が消え（C9）、確定しても何も言われない（C6）。したがって本案の設計単位は「ボタンの配置」ではなく「1 本の作業が始まってから終わるまで、視線と手がどこを何回往復するか」である。実測で最も量のある反復作業（仮名 220 件の改名、現状 91 分／現状分析 §2 C5）を **19 分**に、最も重要でありながら現在は原理的に不可能な作業（1200 年に州を独立させる／V6）を **14 秒で完了しかつ確認できる**形にすることを、本案の合格ラインに置く。守りとして、地図の面積を 45% → 53%（1280×800）に増やし、**地図と無関係な操作で地図の大きさが変わることを一切なくす**。

### A.1 論点 1 — 追加／編集モードの排他（FR-75）を残すか

**立場: 「排他」は残す。「モードという段」は廃す。ラベルとしての『追加モード／編集モード』ボタンは無くす。**

| 何を | どうする | なぜ |
| --- | --- | --- |
| 排他性 | **残す**。道具は 1 段の列にまとまり、同時に選べるのは常に 1 つ。「面を描く」を選べば「切る」は自動的に外れる | FR-75 の「一方を有効にすると他方が自動的に無効になる」は満たされる |
| 「ツールバーのトグルで切り替える」 | **廃す**。`mode-add` / `mode-edit` に相当する 2 個のボタンは画面から消える | この 2 個が C5・C9 の主犯（押すと選択が全消し・`store.ts:1399-1401`／ラベルと結果が逆・`useShell.ts:50-63`） |
| 「各モードで関連ツール群が表示される」 | **形を変えて残す**。後述の「仕事の段」を選ぶと、その仕事で使う道具だけが道具列に出る（例: 組み替え → 切る・結ぶ・所属・穴/飛び地・穴あけ）。「すべての道具 ▾」で残りにも 1 クリックで届く | 800×600 でツール 8 個中 5 個が窓外に出る問題（§1.2）が構造的に消える |
| 本当のモード | **1 つだけ残す**。ヘッダ帯の右端の「表示専用 ⇄ 編集可」ロック（QGIS の編集セッション相当） | K-6（表示専用では編集経路を一括無効化）を守る唯一の判定点として温存する |

**裁定が要る。** FR-75 は **must** であり、「ツールバーのトグルで切り替える」の部分は本案が満たさない（現状分析 §5.4）。所有者が「設計に囚われるな」と言っている以上、本案は上の形を推す。ただし D56（要件も誤りうる／黙って直さずユーザーへ）に従い、**実装着手前に「FR-75 のうち『排他』だけを残し『モードのトグル』を廃す」ことの可否を所有者に確認すること**。

**「仕事の段」は 2 段目のモードではない。** 現状の 2 段構造（C9）が有害だったのは段が 2 つあることではなく、段を切り替えると (a) 選択が消え（`store.ts:1399-1414`）、(b) Ctrl+Z・Delete・Escape・右クリックが止まり（`App.tsx:2780-2792`）、(c) 押しても何も起きない道具が混ざっていた（選択・頂点編集）ことによる。本案の仕事の段は **選択を一切捨てず、ショートカットを一切止めず、押せば必ず画面の並びが変わる**。この 3 点を D 節で状態機械として固定する。

### A.2 論点 2 — 時間軸に既存の錨の印を描くか

**立場: 描く。ただし 2 層に分け、しおり（自分で置く印）は復活させない。**

| 層 | 何を描くか | 規模への耐性 |
| --- | --- | --- |
| **下層（世界の脈）** | 年ごとの「錨のある地物の件数」を薄い縦棒で。全 5 万錨でも棒は軸の幅（1256px）ぶんしか出ないので破綻しない | 5,000 地物 × 10 錨でも棒の高さが変わるだけ |
| **上層（この地物の節目）** | いま選んでいる地物と、その親・子の錨だけを ● で。存続している期間は帯で。非存在期間（時間的飛び地）は帯の切れ目で | 1 地物あたり 10 錨なら家族込みで最大 100 個前後 |

**新しい保存概念を一切足さない**（K-9 に触れない）。描くのは `anchor-series` に既にあるデータだけである。

**裁定が要る。** §7.4-1 の「時刻ブックマーク」は D32 で所有者本人が撤去を決めたものであり、本案はそれを復活させない（利用者が任意の年に印を置いて名前を付ける機能は作らない）。しかし「既存の錨を軸に描くこと」がその裁定に抵触するかは**読み手の解釈であって所有者の意図ではない**（現状分析 §5.2）。実装着手前に確認すること。あわせて `e2e/ux-cluster.spec.ts:216-219`（栞 UI が存在しないこと）が何を固定しているかを読み直し、「しおりの追加 UI が無いこと」を検査する形に書き換える必要がある（§8.3）。

**描かないと何が困るか（推す理由）**: 実データは全 689 錨が 0 年の 1 点に集中していて、所有者がこれからやる作業のほぼ全部が「歴史を足す作業」である（現状分析 §7.1）。**印が無いまま刻み始めると、刻んだ結果を確認する手段が画面に 1 つも無い**（C2・C6・C8 が同時に効く）。V6 の合格条件③「独立した当人の画面にその事実が現れる」は、軸の印と錨一覧の 2 つが揃って初めて満たせる。

### A.3 論点 3 — 削除の方針（現状分析 §6.3）

**立場: 「拒否」ではなく「予告」に配線する。実際の削除の挙動（全時刻を掃いて参照を掃除してから消す）は変えない。**

- `judgeDeletion` / `isDeletable` / `hasReferencesInAnchor`（`deletion/eligibility.ts`、G-16）は**削除を止める判定**としてではなく、**削除の確認ダイアログに出す「これから何が起きるか」の説明**として結線する。
- 確認ダイアログの文面は 3 行に固定する:
  1. 何を消すか（名前・種別ラベル・面積・錨の本数）
  2. 巻き添えになるもの（「この地物を参照している錨が n 本あります。参照は自動で外れます」「下位領域 m 件は最上位へ移ります」）
  3. 取り消せること（「Ctrl+Z で元に戻せます」）
- **拒否方針を採らない理由**: 現在の実装は掃除してから消す方針で確立しており（`App.tsx:2150-2151` のコメント）、拒否方針に倒すと「消したいのに消せない地物」が生まれ、その解除手順を新たに設計する必要が出る。FR-41 の条文は両方の読み方を許すので（現状分析 §6.3）、**利用者の手数が増えない側**を採る。
- **あわせて直す**: N-03（表示専用モードでも「地物を削除」だけが押せる。`PropertyPanel.tsx:440-447`）。本案では削除も K-6 の一括判定に載せる。
- **N-05 の 3 つ（錨の削除・リングの削除・頂点の削除）にも同じ器の確認を付ける。** 特に「最後の領土リングを消すと面ごと消える」は事前に文で出す。

**裁定が要る**（現状分析 §11-2(c)）。ただし本案の推し方は「判定関数を予告に使う」ので、後から拒否方針へ倒すことも容易である（判定結果の使い先を変えるだけ）。

## B. 画面構成

### B.0 骨格の方針

現状の骨格（左＝道具／中央＝地図／右＝情報／下＝時間）は定石どおりで、現状分析 §9.3 も「作り直しても骨格は変えなくてよい」と書いている。**本案は骨格を変えず、行の数と高さの決まり方だけを変える。**

| 変更 | 現状 | 本案 | 効き |
| --- | --- | --- | --- |
| 上の帯 | メニューバー行 1 行（**高さ auto**。1600 で 54px、1280 で 81.2px、800 で 149.2px） | **ヘッダ帯 1 行・高さ 36px 固定**。折り返さない | 窓幅で地図の上端が最大 95px 動く問題（§1.3）が消える |
| 時間の帯 | 201.2px 固定（窓の 25.1%）。うち 70px が直接ジャンプ欄 | **96px 固定**。3 段（操作 28 / 軸 44 / 目盛り 24） | 地図に 105px 返す |
| 状態の帯 | 28px・カーソル座標 1 項目 | **26px・6 枠**（権限／道具／選んでいるもの／縮尺／座標／知らせ） | C6 がまとめて解ける |
| 右パネル | 220px・排他タブ 2 枚 | **300px・上下 2 区画（台帳／素性）を同時表示**。仕切りはドラッグで動く | C5 の主因が消える。FR-111 の「2 区画」は数として守る |
| 左レール | 120px・モード 3 ＋ ツール 0〜8 | **132px・仕事 5 ＋ 道具 3〜7**（仕事に応じて入れ替わる。全道具へは「すべての道具 ▾」で 1 クリック） | 800×600 でツールが窓外に出なくなる |

### B.3 「窓幅で折り返さない」「上部の帯が選択状態で伸縮しない」の作り方（K-3）

現状の事故は 2 つの別々の原因で起きている。**両方を別の方法で塞ぐ。**

**(1) 選択状態で幅が変わる問題（K-3 の本体）**
現状の守り方は「個別フォーカスの 4 部品を常に固定幅で出しっぱなしにして無効化する」（`GlobalDepthControl.tsx:77-88`）。これが起動直後から灰色のボタンが 400px 弱を占める原因（N-33）。

本案の守り方は **「固定寸法の枠に入れて、中身だけ差し替える」**（E-3 の 2 案目）:

```
ヘッダ帯の「地図の見え方」群は、内部に 3 つの固定枠を持つ
┌ 枠1: 中心経度 200×26（常に同じ幅）┬ 枠2: 深さ 172×26 ┬ 枠3: 切替 80×26 ┐
│ 中心経度 0.0° ◀[▬▬▬]▶ [__°]移動  │ 深さ 0/1 −[▬▬]＋ │ ⊞格子 ⟂測る    │
└─────────────────────┴──────────┴──────────┘
枠2 の中身は選択の有無で差し替わるが、枠の外寸 172×26 は絶対に変わらない
  ・地物を選んでいないとき: 「深さ 0 / 1  − [▬▬] ＋」
  ・地物を選んでいるとき:   「深さ 0 / 1  − [▬▬] ＋  ⤵」  ← 「⤵」が深掘りの入口（24px）
```
- 深掘り（個別フォーカス）の 4 部品はヘッダから降ろし、**選んだ地物の素性欄の中と、右クリックメニューへ移す**（「この地物の家族だけを見る」）。ヘッダに残るのは 24px の入口 1 個だけ。
- 実装上の不変条件を **CSS で機械的に保証する**: 「地図の見え方」群の全枠に `flex: 0 0 <固定px>` と `overflow: hidden` を付け、中身の可視・不可視で外寸が変わり得ない形にする。単体テスト（`AppShell.test.tsx` の後継）で「地物を選ぶ前後でヘッダ帯の `getBoundingClientRect()` が完全一致する」を固定する。

**(2) 窓幅で折り返す問題（§1.3）**
`flex-wrap: wrap` を捨て、**`flex-wrap: nowrap` ＋ 3 段の折り畳み点（ブレークポイント）** にする。**段数は常に 1 段、高さは常に 36px。**

| 窓幅 | ヘッダ帯の中身 | 高さ |
| ---: | --- | ---: |
| 1440 以上 | メニュー 5 ＋ 地図の見え方 3 枠（452px）＋ 文書の素性（世界名・ファイル名・未保存・最終保存）＋ 権限 | **36px** |

### B.4 地図セルの中の常設コントロール（K-2 を前提に）

現状は地図セル内の操作部品が **0 個**（§1.4）。定石 11 が言う最低限（ズーム±・縮尺・全体表示）を入れる。ただし過去 3 回の事故（K-2）があるので**規約とセットでしか入れない**。

### D.3 ショートカットが止まる範囲を狭める

現状は `shortcutsSuspended`（`App.tsx:2780-2792`）が 11 項目の手書き OR で、**道具を選んだだけで Ctrl+Z・Delete・Escape・右クリックが全部止まる**（C9）。所属変更を確定した直後の Ctrl+Z が無反応という最悪の形になっている（報告 04 §3.5）。

| キー／操作 | 止まる条件 |
| --- | --- |
| Escape | **絶対に止めない。** 下書きがあれば下書きのキャンセル、無ければ選択解除（U-5） |
| Ctrl+Z / Ctrl+Y | **下書きが 1 点以上あるときだけ**道具側へ委譲（「いま打った点を取り消す」）。下書きが空なら常にドメインの取り消し。**確定した直後は必ずドメインの取り消しが効く** |
| Delete | 下書きがあるときだけ道具側へ。無ければ選択中の地物／頂点の削除 |
| 右クリック | **絶対に止めない。** 下書き中は「ここで確定／取り消し／この点を消す」の道具用メニューに切り替わる |
| Ctrl+S / Ctrl+O / Ctrl+N | 下書きがあるときは確認を挟んでから実行（現状は無言で止まる） |
| 道具の単一キー | 文字入力欄・textarea・select・contenteditable に焦点があるとき（`focus-guard.ts` の既存判定）＋ **range にも拡張**（C8 のスライダー由来の暴発対策） |

実装は「11 項目の OR」を捨て、**`draftPointCount: number`（下書きが持っている点の数）と `modalOpen: boolean` の 2 つだけ**で決める。道具はこの 2 つを報告する。結合点 #5（キーボード占有の申告が手作業の OR）が 2 変数に縮む。

### D.4 仕事の段ごとの既定

| 仕事 | 道具列 | 台帳の束の既定 | 素性欄の並び | 「次へ」の意味 |
| --- | --- | --- | --- | --- |
| **下見** | 選ぶ／測る／深掘り | いま見えているもの（現在時刻・階層順） | 名前・種別・親・面積/長さ・存続・歴史の要約（読み取り専用の見た目） | 台帳の次の行 |
| **描く** | 面／線／点／選ぶ | 直前に作ったもの（新しい順） | 名前・種別・親・存続（**現在時刻が既定で入る**）＋見た目 | 「続けてもう 1 つ描く」（道具を保ったまま次の作図へ） |
| **整える** | 選ぶ | **未処理の束**（仮名／種別ラベルなし／名前が重複／色が既定のまま から選ぶ） | 名前・種別・親を上に固定＋見た目 | **束の次の未処理**。名前欄に焦点が入った状態で来る |
| **歴史** | 選ぶ | この年に錨がある地物／この地物の錨 | **錨の一覧を最上段に**。次に「この年から変える」、次に名前・種別・親・存続 | 次の錨（＝時間も一緒に動く） |
| **組み替え** | 切る／結ぶ／所属／穴・飛び地／穴あけ／動かす／選ぶ | 選んでいる地物の家族（親・自分・子） | 親・子の一覧・直轄領の有無を上に固定 | 「同じ操作を続ける」（道具を保つ） |

**「次へ」は全部の仕事に必ずある。** これが本案の背骨で、E 節の削減のほとんどはここから来る。台帳の上部に常設する:

```
┌ 300 × 56 ─────────────────────┐
│ 束: [仮名（220 件）        ▾]  [☑未処理だけ] │  ← 30px
│ ◀前へ    3 / 220    次へ▶   Enter で次へ    │  ← 26px
└────────────────────────────┘
```

- 束の種類: いま見えているもの／仮名／種別ラベルなし／名前が重複（12 件）／この年に錨がある／この地物の家族／絞り込みの結果／検索の結果／手で選んだもの。
- 束は**改名しても並びが動かない**（束を作った時点の順序を保つ）。C4 の「改名すると絞り込みが古い名前のまま 0 件になり、見ていた場所を失う」（報告 E §2.10）が構造的に消える。
- 処理済みの行には左端に細い印が付く（V4 の合格条件③）。

## H. 用語と文言の方針

### H.1 基本の 3 原則

1. **所有者が決めた語は変えない。** 「錨」（U-3／E-8）、「点情報／線情報／面情報」「末端地物／集約地物」（U-1）は残す。
2. **語を残したまま、意味が伝わるようにする。** 見出しの語は変えず、その**すぐ下に 1 行の言い換え**を常設する。「語を残すこと」と「意味が伝わること」は別（E-8）。
3. **内部語は画面に出さない。** `f-5-4` / `childIds` / `parentId` / `aggregate` / `leaf` は出さない（U-1・N-30）。「減衰（淡く）表示」「縦方向領域」も画面の言葉としては使わない。

### H.2 初見の人にどう見えるか（3 つの難語）

| 語 | 画面での見え方 | ツールチップ／初回ガイド |
| --- | --- | --- |
| **錨** | 素性欄の折りたたみ見出し: 「**歴史の錨** 2 本」／その下に薄い 1 行「この年からの姿を記録したもの」。行の書き方: 「**1200 年 —** 親が変わった: デーレ共和国 → なし」「**0 年 —** はじめの姿」 | ツールチップ:「歴史の錨とは、『この年からこの姿になった』という記録です。次の錨まで同じ姿が続きます。」／時間の帯の軸の ● にも同じ吹き出し |
| **直轄領** | 所属変更の確認画面: 「**直轄領**『正統ノル王国 直轄領』を作ります」／その下に薄い 1 行「**親が子に分けなかった残りの土地です。**名前は変えられます」 | ツールチップ:「州を作ると、元の国の形のうち州にならなかった部分が余ります。それをひとつの領域として残したものです。」 |
| **深掘り**（個別フォーカス） | 素性欄と右クリックの項目名: 「**この地物の家族だけを見る**（深掘り）」／深さの欄に薄い 1 行「親と子を何段まで見るか」 | ツールチップ:「選んだ地物と、その親・子だけを別の深さで表示します。ほかは今のままです。」 |

### H.3 用語集の 7 操作を画面の言葉として使う（N-31）

用語集が定義する 7 つの所属変更（割譲・帰属・連邦化・独立・直轄化・自治化・解体）が**画面に 1 つも出ていない**。一方、上部バーには最も難しい語（階層深度・個別フォーカス・フォーカス深度・縦方向領域を強調・深掘り対象なし）が最も使わない機能として常時並ぶ。**難しい語と意図を表す語が逆になっている。**

本案は逆転を戻す:

| 場所 | 現状の語 | 本案の語 |
| --- | --- | --- |
| ヘッダ帯（常設） | 階層深度／個別フォーカス／フォーカス深度／縦方向領域を強調／深掘り対象なし | 「**深さ** 0 / 1」の 1 語だけ（残りは素性欄と右クリックへ） |
| 所属変更の 3 択 | 既存の上位領域から選ぶ／最上位へ（2 択） | 「**既存の上位領域から選ぶ**（割譲・帰属・直轄化）」「**新しい上位領域を作る**（連邦化・自治化）」「**最上位へ**（独立）」 |
| 集約の素性欄 | （無し） | 「下位領域 60 件 → **全部を最上位へ移す（解体）**」 |
| 台帳の説明文 | 「現在の年に存在する地物の一覧です。行を選ぶと…」（3 行・約 60px 常設／N-48） | **束の名前と件数がその役目を果たす**ので説明文は常設せず、**空のときだけ**出す（HB3-28 の裁定の趣旨＝説明が要るという判断は正しいので、置き方だけを変える） |

### H.4 同じものに 2 つの名前・近い名前で別のもの（N-29）を整理する

| 統一前 | 統一後 |
| --- | --- |
| 親領域／上位領域 | **上位領域**（用語集の語に揃える）。ただし素性欄の行ラベルは「**親**」の 1 文字で置き、ツールチップで「上位領域」と対応づける |
| 継承先／引き継ぐプロパティ | **元の素性を引き継ぐ** |
| グリッドスナップ／グリッドにスナップ | **格子に合わせる** |
| 一覧・通史／錨一覧 | 台帳の束「**いま見えているもの**」／「**歴史の節目（錨）**」 |
| 深掘り（表示）／穴あけ（新地物生成）／穴・飛び地（形の変更）が隣り合う | 深掘りは道具列から外して素性欄と右クリックへ。道具列には「**穴・飛び地**」と「**穴あけで新しい国を作る**」だけが残り、ラベルで用途が読める |
| 「階層深度」が上部バーと表示制御に 2 つあり片方は畳む・片方は隠す | ヘッダは「**深さ**」（畳む＝描く深さ）、台帳の束は「**階層でまとめる**」（隠す・淡くする）。**置き場所が違うので取り違えない** |
| 「種別で表示」と「種別を強調」が同じ 3 ラベルで縦に並ぶ（N-50） | 台帳の行内の**目のアイコン（見せる／隠す）**と**筆のアイコン（淡く／強調）**。ラベルではなく置き場所で区別 |

### H.5 初回ガイドの方針（FR-118 should）

- **雛形は既にある**。重なり解決の「この画面の使い方」（番号つき手順＋画面上の実物の名指し＋恒久 OFF）は、このアプリで唯一まともに実装されている実例（§9.3）。**同じ器を横展開するのが最も安い。**
- 横展開先は 4 つ: **①所属変更の 3 択**（7 操作のどれをやろうとしているのか）、**②分割の継承先**、**③「この年から変える」を初めて押したとき**（錨の考え方）、**④修復ダイアログ**。
- **空のときの案内**を全パネルに置く: 台帳が 0 件なら「まだ何も描かれていません。左の『描く』から始めます」、素性欄が未選択なら「地図か台帳から 1 つ選ぶと、ここに素性が出ます」（現状は「地物が選択されていません。」の 1 行で 96.7% が空白）。
- **検索の死んだ文言を消す**: ヘルプ文が「名前・説明・属性値で検索します」と言うのに `description` は空文字固定で「説明に一致」は絶対に出ない（N-37）。実態に合わせて書き直す。

### H.6 拒否と成功の文の書き方

| 種類 | 書き方 | 例 |
| --- | --- | --- |
| **拒否** | 「**何ができなかったか** ＋ **なぜか** ＋ **どうすればよいか**」の 3 点セット。該当欄の近くに出す（定石 13） | 「ここには穴をあけられません。**集約地物（下位領域を持つ面）**は形を持たないためです。下位領域のどれかを選んでください。」 |
| **成功** | 「**何が・どうなったか**」を過去形で。**次の同種の操作まで消さない**（K-7・§7.4-3 と両立） | 「南ケナ州: 1200 年の節目を作りました（親: デーレ共和国 → なし）」 |
| **予告** | 取り返しのつかない操作の直前に「**これから何が起きるか**」 | 「アルラーク国（面・1,706 頂点・錨 3 本）を消します。この地物を参照している錨が 2 本あり、参照は自動で外れます。Ctrl+Z で元に戻せます。」 |
| **進行中** | 500ms を超える処理に「**何をしているか**」 | 「所属を変えています…（2.8 秒ほどかかります）」 |

## I. キーボードと右クリックの体系

### I.0 前提

- **Electron 標準メニューは復活させない**（K-1）。自前のメニューバーが唯一の標準操作導線であり、キー体系は自前で完結させる。`Ctrl+0` は使えないので全体表示は `Ctrl+Home` のまま。

### I.2 右クリックの体系

**原則**: 右クリックは**いつでも開ける**（道具を持っている間も。中身が変わるだけ）。**常に無効な項目を出さない**（N-9 の「結合が構造上つねに無効」をやめる）。**右クリックから道具を起動したら対象を引き継ぐ**（現状は引き継がない）。

| 右クリックした場所 | 出る項目 |
| --- | --- |
| **何も無いところ** | 全体表示／ここを中心にする／格子の表示／表示専用 ⇄ 編集可／（下書き中なら）ここで確定・取り消し |
| **末端地物の上** | この地物の素性を見る（素性欄へ焦点）／この年から変える／名前を直す（その場編集）／**切る・結ぶ・所属を変える・穴あけ・穴・飛び地**（対象を引き継いで道具を起動）／この地物の家族だけを見る（深掘り）／隠す・淡くする／削除 |

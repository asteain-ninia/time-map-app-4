# P4 GIS 編集ツールの定石準拠（QGIS／ArcGIS 流）
執筆: GPT 5.6 Sol（外部モデル、読み取り専用実行）／保存と検査: Opus

## A. 設計思想

gimoza を「地図の上に機能を継ぎ足したアプリ」ではなく、**時間を持つ地理情報を編集する単一利用者向け GIS**として再構成する。QGIS／ArcGIS で定着している「編集セッション」「レイヤーと地物」「属性テーブル」「スナップ」「頂点編集」「トポロジ編集」「座標・縮尺・図法を示すステータスバー」という語彙を使い、左で対象を探し、中央で形を直し、右で属性と歴史を読み、下で時刻を動かす。ドメイン層の「編集案→検証→コマンド→履歴」は再利用し、UI は入口と状態の可視化を作り直す（`docs/ui-redesign/01-現状分析.md` §1.6、§9.1、`docs/技術方針.md:65-73`）。

1. **追加／編集モードの排他（FR-75）**  
   現行の「表示専用／追加／編集」の三択は廃止し、QGIS 型の**「編集セッションを開始／終了」1 トグル＋ツール1段**へ置き換える。編集セッション中は地物選択・頂点編集・移動・点追加・線追加・面追加・分割・結合・所属変更を同じ列に並べ、ツールを替えても選択を保持する。編集セッションを閉じていても地物は選択・閲覧できるが、書き換え経路は権限判定の1か所で止める。これは C5・C9 と GIS の定石を直接解く一方、FR-75 must と正面衝突するため、**採用前に所有者裁定が必要**である（`01-現状分析.md` §2 C5/C9、§5.4、`F-comparative-expert.md:63-107`）。

2. **時間軸に既存の錨を描くか**  
   **描く。** 選択中の地物は塗りつぶし菱形、その上位・下位領域に由来する錨は中空菱形、全体は年ごとの密度帯として描く。5万錨を個別表示せず、時間軸の倍率に応じて集約する。これは利用者が任意に置く時刻しおりではなく、既に保存されている地物の状態を可視化するだけで、新しい保存概念は足さない。ただし D32 の意図との切り分けは調査側の解釈なので、**所有者裁定が必要**である（`01-現状分析.md` §5.2、§7.2 V11、`要件定義書.md:181-187`）。

3. **削除の方針**  
   既存実装の「全時刻を調べ、参照を同じ操作内で整理して削除する」を基本方針とする。ただし即時実行せず、削除前に「対象名・影響する錨数・上位／下位領域・自動消滅する集約地物」を表示し、赤い「全時刻から削除」で確定する。削除全体は1回の取り消しで戻せる。G-16 の判定は拒否のためではなく影響説明に使う。`judgeDeletion` の本来の方針は「参照があれば拒否」であり、FR-41 は両方に読めるため、最終方針は**所有者裁定が必要**である（`01-現状分析.md` §6.3、`開発ガイド.md:248-250`）。

### B.3 折り返しと寸法変動を起こさない規則

- 28px、42px、34px、72px、24pxの各行は固定高で、`flex-wrap` を使わない。
- 1280pxでは短い表示名を使うが、アクセシブル名は「点情報を追加」など完全な日本語を保つ。
- 1600pxと1280pxの切替は窓幅だけで決まり、選択、測量、ツール、エラーの有無では変わらない。
- ツール別オプションは34px帯の固定スロット内で差し替える。エラーは帯を伸ばさず、右パネルの該当欄とステータスバーに出す。
- 測量結果、選択名、錨の数は上部に新しい行を生やさない。
- 1280px未満では折り返さず、優先度の低い構造編集ツールを「その他の編集」メニューへまとめる。ブレークポイントは選択状態に依存しない。
- 地図コンテナは常時マウントする。パネル開閉でカメラを初期化しない（内部結合点2、`01-現状分析.md` §4.6）。
- 上記により、選択のたびに地図上端が動いた事故を再発させない（K-3、`01-現状分析.md` §1.3、§4.2）。

```text

          ▼
```

編集セッションとファイル保存は別状態とする。

- 編集セッションを終了しても、確定済みの変更はプロジェクトに残り、未保存なら `●未保存` のまま。
- `Ctrl+S` はファイルへ保存するが、編集セッションを終了しない。
- 読み取り専用でも選択、属性閲覧、時間移動、測量、検索、表示制御はできる。
- 更新コマンドの許可は編集セッション状態の1か所で判定する。個別ボタンごとに権限判定を書かない（K-6）。

### D.3 選択状態

ドメイン上のアクティブ地物は従来どおり0件または1件とする（FR-79）。

| 選択 | 用途 | 他ツールへ持ち越すか |
|---|---|---|
| アクティブ地物 0/1 | 地図・ツリー・属性表・プロパティの同期対象 | 原則保持する。時刻変更で存在しなくなった場合だけ解除する。 |
| 頂点選択集合 | 頂点編集、矩形選択、共有境界編集 | 頂点編集内では保持。他ツールへ移ると捨てる。 |
| 属性表の一括編集対象 | 複数行への属性／表示操作 | アクティブ地物とは別の一時状態。表を閉じる、ファイルを替えると捨てる。 |
| 構造編集の対象集合 | 結合、所属変更、連邦化 | その手順内だけ保持。確定・取消・ツール切替ですべて捨てる。 |
| 選択中の錨 | 既存の錨を直接編集する場合の対象 | 地物選択が変わると捨てる。時刻同期は既存の単一経路を通す。 |

### D.4 保持と破棄

| 操作 | 保持する | 捨てる／再解決する |
|---|---|---|
| ツール切替 | アクティブ地物、カメラ、時刻、スナップ設定、グリッド設定 | 作図点、候補集合、頂点集合、未確定オプション。下書きがあれば先に確認する。 |
| 編集セッション開始 | 選択、カメラ、時刻、表示制御 | 旧ツール下書きは存在しないことを確認。 |
| 編集セッション終了 | 選択、カメラ、時刻、確定済みドメイン変更 | ツール下書き、頂点集合、一括編集対象。 |
| 編集確定 | 結果地物または残存地物を選択、カメラ、時刻 | その作業の下書き。追加・測量は同じツールで次を待ち、構造編集は地物選択へ戻る。 |
| 編集取消 | 元のアクティブ地物、カメラ、時刻 | その作業の下書き全部。 |
| 時刻変更 | カメラ、表示制御、スナップ設定 | 選択は新時刻で再解決。存在しなければ理由を出して解除。未反映フォームは破棄確認。 |
| 新規／開く／復元 | アプリ全体設定 | 選択、時刻、カメラ、全下書き、表の選択、コマンド履歴を新プロジェクト用に再構築。 |
| Escape | 下記の優先順位に従う | モーダル→セル編集→作図→頂点集合→アクティブ地物の順に1段だけ戻る。 |

K-5 との整合は、「一時状態を持ち越さない」だけでなく、**破棄前に未反映内容を利用者へ知らせる**ことで満たす。現状のように錨選択や時間移動だけで文字を黙って消さない（N-04、`01-現状分析.md` §3）。

## E. 評価シナリオ V1〜V15 の操作手順

### E.0 KLMの前提

- B: 0.10秒
- H: 0.40秒

## H. 用語と文言の方針

### H.1 基本原則

- UIは日本語のみとする（FR-115、U-1）。
- 内部ID、`leaf`、`aggregate`、`parentId`、`childIds`は画面に出さない。
- GISの既知語彙は使うが、初出では日本語の意味を併記する。
- ボタンは「対象＋動作」で書く。「保存」のように対象が曖昧な語は「属性変更を反映」「ファイルを保存」と分ける。
- 無効な操作は隠さず、必要な前提が理解に役立つ場合だけ無効表示し、脇に理由を書く。
- 成功、警告、拒否は色だけで区別しない。アイコン、見出し、文を併用する。
- エラー文は「何が起きたか→なぜか→次に何をするか」の順にする。

### H.2 重要語

| 語 | 初見での表示 | ツールチップ／説明 |
|---|---|---|
| 錨 | **歴史の錨** | 「この地物の形・名前・所属などが、この時刻からどうなるかを記録した歴史の節目です。」以後も語は「錨」を維持する（U-3/E-8）。 |
| 直轄領 | **直轄領（上位領域が子に分けなかった残り）** | 「元の領域と下位領域の間に残る部分です。階層の形を一致させるため、自動で地物を作ります。」 |
| 深掘り | **深掘り: 選択地物の階層だけ詳しく表示** | 「選んだ地物につながる上位・下位領域だけ、全体とは別の深さで表示します。」 |
| 編集セッション | **編集を開始／編集を終了** | 「編集を開始すると地物を書き換えられます。終了してもファイル保存はされません。」 |
| スナップ | **吸着（スナップ）** | 「近くの頂点・辺・交点へ正確に合わせます。」 |
| トポロジ編集 | **共有境界を一緒に動かす（トポロジ編集）** | 「隣り合う地物が共有する頂点や辺を、双方で同時に動かします。」 |
| レイヤー | **レイヤーと地物** | 「点・線・面と、国・州などの親子関係を整理して表示します。行を並べ替えて重ね順を変える機能ではありません。」 |
| 投影 | **図法: 正距円筒（固定）** | 「架空世界の経度・緯度を等間隔に表示する方式です。このプロジェクトでは変更できません。」 |
| 集約地物 | 通常画面では **下位領域をまとめる地物** | 詳細ヘルプでのみ「内部では集約地物と呼びます」と補足する。 |
| 末端地物 | 通常画面では **自分の形を持つ地物** | 重なり解決でも「末端地物どうし」とだけ書かない。 |

### H.3 ツールチップ

- 表示まで500ms。ボタンの外側にポータル表示し、`pointer-events:none` とする。
- ボタンを覆ってもクリックを奪わない（N-01、K-2）。
- 1行目は動作、2行目はショートカット、3行目は利用条件。
- 明示ラベルがある編集セッションボタンには、クリックの妨げになるツールチップを付けない。
- 例: 「面情報を追加します／ショートカット: 3／編集セッション中に使用できます」。

### H.4 初回ガイド

初回起動時に全機能を説明する長いツアーは行わない。次の4か所に限定する。

1. 編集セッション開始時: 読み取り専用との違い、保存とは別であること。
2. 初回面追加時: スナップ記号、Enter確定、Escape取消。
3. 初回所属変更時: 既存／新規／最上位の三択と直轄領。
4. 初回重なり解決時: 色付き凡例、残す側、適用結果。

各ガイドは番号付き手順、画面上の実物名、恒久的な「今後表示しない」を持つ。既存の重なり解決ガイドを共通器へ横展開する（`01-現状分析.md` §7.2 V13、§9.3）。

## I. キーボードと右クリックの体系

### I.1 配送規則

- Electron標準メニューは復活させない（K-1）。
- キーマップは1つの宣言からメニュー表示、ヘルプ、実行を生成する。
- 単一文字のツールキーは**地図にフォーカスがあるときだけ**有効。
- `input`、`textarea`、`select`、`contenteditable`、範囲スライダー、属性表セル編集中はツールキーとDeleteを止める。
- Escapeの優先順位は、モーダル→セル下書き→作図下書き→頂点選択→地物選択。
- モーダル中も `Ctrl+Z` を一律停止するのではなく、モーダル自身が許可した操作だけ受ける。
- キーと右クリックは同じコマンドIDへ接続し、別実装を持たない。

## L. リスクと未解決事項

1. **FR-75の裁定**  
   P4の中核である編集セッション1トグルはFR-75 mustを変更する。所有者が否決した場合は、内部に追加／編集の排他状態を残しつつ、利用者には編集セッションと一段ツールだけを見せる互換案が必要になる。ただし二重状態が残るため第一案より保守性が落ちる。

2. **時間軸上の錨表示とD32**  
   既存錨の可視化は保存形式を変えないが、「時刻ブックマーク撤去」の意図と同じに見える可能性がある。利用者が自由に作るしおりは戻さないことを明示して裁定を受ける。

3. **削除方針**  
   「参照を整理して削除」と「参照があれば拒否」のどちらを正にするか未裁定。P4は前者を提案するが、影響説明・赤い確定・1回Undoを必須条件とする。

4. **スナップ許容値**  
   P4の提案値はGISで扱いやすい12pxだが、FR-31 shouldは既定50pxである。実データは頂点間隔中央値3.46pxなので、50pxでは候補が多すぎる。12pxへの変更、倍率別自動調整、50px維持のいずれかを実データで比較する必要がある。

5. **辺・交点スナップの新規実装**  
   現在あるのは既存頂点候補とグリッドの優先解決であり、辺・交点への共有頂点挿入は未実装である（`src/domain/add/snap.ts`）。隣接地物の辺にも同じ頂点を挿入し、ゼロ長辺・自己交差・世界端を検証するドメイン作業が必要。

6. **既存境界をたどる機能**  
   `T`のトレースはQGIS定石として有効だが、対応するドメイン入口がない。増分5の必須範囲は頂点・辺・交点スナップまでとし、トレースはその後の独立増分にしてよい。

7. **トポロジ編集OFFの意味**  
   FR-30は共有頂点の移動を全形状へ反映する。したがってOFF時に片側だけ動かして共有を暗黙解除してはいけない。P4ではOFF時は共有点の単独ドラッグを止め、「共有解除」を明示実行させる。

8. **属性表の一括編集とUndo単位**  
   15件または335件の編集を1操作として戻す複合コマンドが必要。UIから既存コマンドを335回積むだけではFR-73の「単一ユーザーアクション＝単一Undo」を満たさない。

9. **属性表での歴史編集**  
   セル変更が現在時刻の新しい錨になるか、選択済みの既存錨を直すかを必ず明示する。全行へ同時刻の錨を作る場合、重なり競合が複数件同時に出るため、競合解決の一括処理を検証する必要がある。

10. **子の画面に親管理の歴史をどう出すか**  
    実データの州は親の錨内に保存される。P4は前後状態を比較して「当人から見た歴史」を導出表示するが、差分分類をどこまで「独立」「割譲」「改名」と名付けられるかは追加設計が要る。保存データへ出来事種別は足さない。

11. **5万錨の可視化**  
    全錨をDOM要素として置かない。時間区間ごとの密度集約、選択地物だけの個別描画、仮想一覧が必要。現状は1地物2錨までしか実測されていない（`01-現状分析.md` §11-7）。

12. **頂点密度とハンドル上限**  
    ハンドルを単純に間引くと存在する頂点を編集できなくなる。倍率不足時は全ハンドルを止めて理由を出し、拡大後は視野内の全頂点を描く。選択済み頂点とドラッグ中頂点は常に出す（FR-110）。

13. **世界端と180度以上の辺**  
    東西端で分断された大陸の修正は、保存形式の恒久制約を踏む。作図中に180度以上の辺を検出し、中間点追加を案内または自動提案する必要がある（`docs/技術方針.md:272-283`、`01-現状分析.md` N-51）。

14. **分割の穴・飛び地**  
    n分割は穴なし・単一リングに限られる。実データの国でHB3-5が再発する可能性があり、V10を穴・飛び地付き地物でも追加検証する必要がある（`01-現状分析.md` §11-14）。

15. **縮尺表示の定義**  
    架空世界の赤道長とCSS 96dpiから縮尺分母を導出できるが、OS拡大率・ディスプレイ実寸との関係を「概算」とするか、距離バーだけを正とするかを決める必要がある。図法は正距円筒固定で、一般GISのCRS選択UIは持ち込まない。

16. **レイヤーの意味**  
    gimozaにはQGISの独立レイヤー順序がない。「点／線／面」と地物階層を便宜的なレイヤーとして見せるが、ドラッグ並べ替えは提供しない。行のロックは保存しない一時的な誤操作防止に限る。

17. **編集セッションとファイル保存の混同**  
    GIS経験者でも「編集終了＝保存」と誤認しうる。ボタン付近に「編集終了はファイル保存ではありません」を初回表示し、未保存印を残す。

18. **パネル幅と長い日本語名**  
    208pxの左欄では長い名前を1行省略し、種別と親を別列・ツールチップで示す。行高を名前によって変えず、775件でスクロール位置が予測可能な固定高にする。

19. **実機表示の未確認**  
    GPUあり環境、日本語フォント、フォーカスリング、Windows表示倍率、スクリーンリーダーは未確認である（`01-現状分析.md` §11-3）。1600×1000と1280×800の実機視覚回帰が必要。

20. **実データ検証口**  
    正準`.gimoza`を直接開かず、コピーを読み込むE2E専用口を先に用意する。775地物、2230頂点、重複名12件、錨689件のfixtureを回帰に含める（`01-現状分析.md` §7.3）。

21. **性能**  
    データを間引かず、一覧・属性表・錨は表示だけ仮想化する。スナップ候補探索は全頂点走査に戻さず、既存空間索引を使う。5000地物×10錨で、選択100ms以内と描画60FPSを測定する（`要件定義書.md:412-425`、U-24）。

22. **所有者の現在の不満との照合**  
    調査文書は導線上の欠陥を多数示すが、実データ投入後の所有者本人の不満は直接採取されていない（`01-現状分析.md` §11-1）。P4採否前に、V1〜V15のうち実運用開始を最も止めている上位3件を所有者へ確認する。

# 増分 8D — 復旧と設定（V14・V12 の④）

`docs/ui-redesign/03-実装計画.md` §8 の 8D。**壊れたときに戻せる。** 自動保存の間隔と
世代数を変えられる。

保存のたびに保存ファイルの隣へ世代（`<名前>.bak.<時刻>-<連番>`）が残っていたのに、
描画プロセスから一覧する口も戻す口も無かった。自動保存も「5 分・10 世代」で固定のまま、
設定する画面が無かった（`docs/現状.md` の R7）。この増分で両方の口を通し、
**戻した世代そのものを保存先にしない**規則を描画プロセスと主プロセスの両側に置いた。

作業は git worktree（`E:\WORKSPACE\time-map-app-4-8d`、ブランチ `inc8d-2026-10`）で行った。
本体の作業ツリーでは別の実装係が増分 7 の手直し（`src/domain/persistence/repair.ts` を含む）を
しているので、**`repair.ts` の中身には触れず、修復ダイアログは画面の側だけを直した**。

## 2. やったこと（実装計画 8D の中身 1〜5）

### 1 `listBackups()` / `openBackup(id)` の口

- **契約**（`src/shell/ipc/contract.ts`）: チャネル `ListBackups` / `OpenBackup`、型
  `BackupEntry = { id, savedAtMs, byteSize, featureCount, sourceName }`、`LoadResponse` の成功側に
  `restoredFrom?: { sourceName, savedAtMs }`。`TimeMapApi` に `listBackups` / `openBackup`。
- **主プロセス**（`src/shell/main/ipc-handlers.ts`）:
  - `handleListBackups` — 対象は **いまの保存先**、それが未確定なら **世代から戻した元のファイル**。
    どちらも無ければ空。保存先の隣を `listDir` で読み、名前の鍵で新しい順に並べ、大きさと
    地物数を添える（`src/shell/io/backup.ts` の `listBackupGenerations` / `describeBackups`）。
    返す行ごとに **その場限りの id**（`randomUUID`）を振り、id → 実体の表を **丸ごと差し替える**。
    **パスは描画プロセスへ渡さない。**
  - `handleOpenBackup` — **表に載っている id しか受け取らない。** 前の一覧の id・パス・
    文字列でない値はディスクを 1 バイトも読まずに断る（`read-failed`、「その世代は一覧に
    見つかりませんでした。…」）。読めたら普通の読み込みと同じ検証（Zod の境界）を通す。
  - 送り手の検証は既存の口と同じ形（信用しない送り手には空の一覧／`cancelled`）。
    開く側は送り手の id を預け、確定の印が同じ窓から来たかを確かめる。
- **地物数**は、マニフェストのエントリだけを展開して数える（`countFeaturesInTmap`）。
  背景地図や添付は展開しない。**読めない世代は地物数だけ null（画面は「—」）にして行は出す**
  ―― 壊れた世代が 1 つ混ざっていても、ほかの世代から戻れなくしない。一覧を作る間に消えた
  世代は行ごと出さない。
- **preload**（`src/shell/preload/index.ts`）に 2 本を公開し、`preload.test.ts` に契約テストを
  2 件足した（引数の数まで固定。`listBackups` は何も渡せない、`openBackup` は id だけ）。

### 2 復元したファイルを保存先にしない

**両側に同じ規則を置いた**（どちらか一方が壊れても世代は上書きされない）。

- **主プロセス**: 世代から開いた読み込みは、確定の印（`commitLoadedPath`）が届いても
  **`currentPath` を世代のパスにせず未確定へ戻し**、元のファイルを `restoredSource` に覚える。
  次の保存はダイアログに落ち、**既定は元の保存ファイル**（`showSaveDialog(defaultPath)`）。
  保存できたら・別のファイルを開いたら覚え書きは消える。
- **描画プロセス**: 保存文脈を `contextForRestoredBackup` で作る ―― `savePath` も
  `backupTarget` も null なので `needsSaveAs` が真になり、**Ctrl+S は「名前を付けて保存」へ
  落ちる**（上書き確認は出ない）。自動保存も動かない（保存先が無い）。
- **アプリバーとウィンドウタイトル**は「〈元の名前〉（2026-10-03 14:03 の世代から復旧・
  保存先は未確定）」を出す（`restoredFileLabel`）。保存できたら書いた先の名前に戻る。

### 3 世代の一覧の画面（ファイル →「以前の保存から開く」）

- ファイルのメニューに **「以前の保存から開く」**（`file.openBackup`）を足した。打鍵は割り当てない。
- 一覧の板（`src/ui/file-ops/BackupListDialog.tsx`）は **保存した日時・大きさ・地物数** を
  新しい順に並べ、上に「〈元の名前〉を保存したときの世代です」、下に「開いた内容は元の
  ファイルを上書きしません。最初の保存は『名前を付けて保存』になります」と出す。
  **行を押すとその世代を開く**（設計書の手順どおり、別の［開く］を挟まない）。世代が
  無ければ「戻せる世代はまだありません。…」。
- 順序は設計書 §J.4 の #9 のとおり（`openBackupCommand`）: 一覧 → 行 → **①未保存の確認**
  （「開く」と同じ器）→ **②`openBackup`** → 修復が要れば修復 → reflect（**③取り消し履歴は
  プロジェクト参照が変わるので現行どおり捨てられる**）→ **④保存先は確定させない**。
  全体を「開く」「新規」「D&D」と同じ相互排他の中で走らせる。
- 板は `useModalRegistration` で **鍵盤の持ち主を名乗る**（App は `toolModalChange('backup-list')`）。
  `modal-registration.test.tsx` の母集合に `BackupListDialog` を足し、出たら名乗り外れたら
  取り消すことを固定した。

### 4 修復ダイアログの整理（N-22）

`src/ui/file-ops/RepairDialog.tsx` と `repair-flow.ts`（画面の側）だけを直した。

- 各行の見出しに **冒頭の長い説明文を繰り返していた**のをやめた。方法が 2 つ以上ある行だけに
  短い見出し「直し方を選んでください」を付ける。
- **直し方が 1 つしか無い行はラジオを出さず「こう直します: …」と書くだけ。** 何種類が
  1 つきりかは決め打ちせず、**U14 が返した方法の数**で決める（本体で `repair.ts` の選択肢が
  増減しても画面が崩れない）。
- **どの行も最初（おすすめ）の方法を選んだ状態から始める**（`defaultRepairChoices`）。
  読んで［修復して読み込む］を押すだけで済む（V14 の手順 (b)）。
- **内部の語を出さない**: 「ID: f-5-4」の行を消した。名前の無い地物と、名前の欄に ID が
  入っている地物（時間の矛盾は歴史の ID を名前の欄へ入れてくる）は「名前のない地物 N 件」。
  機械向けの符号（`detail`）は日本語にし、知らない符号は出さない。`childIds` / `parentId` を
  含む方法の文（集約の下位領域一覧の作り直し）だけを画面の側で言い換えた
  （`repairOptionText`。**全方法の写像は持たない** ―― 部分的な上書きだけ）。

### 5 自動保存の設定（G-5、FR-108。V12 の合格条件④）

- 設定ダイアログに 3 つ目のタブ **「保存とバックアップ」** を足した: **自動保存の間隔（分）**・
  **残す世代の数**・**［適用］**。［適用］はこの節だけをその場で書き、ダイアログは閉じない。
  ［適用］を押さずにダイアログの［保存］を押しても打った値は書く（範囲外ならこのタブを開いて
  理由を出し、閉じない）。
- **いま世代がいくつ溜まっているか**を出す（「w.gimoza の世代はいま 3 個あります
  （ファイル →『以前の保存から開く』で戻せます）」）。V14 の入口になる。
- 値は **userData の `app-prefs.json`**（アプリ側の設定）に置く。範囲は間隔 1〜120 分、
  世代 1〜100（契約の `AUTO_SAVE_INTERVAL_MINUTES_RANGE` / `BACKUP_GENERATIONS_RANGE` を
  主プロセスの読み込みと設定画面の検証の両方が引く）。
- **主プロセスは書いたその場で自動保存へ効かせ**（`handleWriteAppPrefs` → `applyAutoSaveConfig`）、
  **起動時にも効かせ直す**（`restoreAutoSaveConfig`）。描画プロセスから `configureAutoSave` を
  呼ぶ口は使っていない（§4 の 1）。

## 4. 実装者がその場で決めたもの（配下 README の B-3 へ載せた）

1. **自動保存の設定はアプリ側の設定（userData）に置き、主プロセスが書いたその場と起動時に
   効かせる。** 描画プロセスの `configureAutoSave` は呼ばない（口は残っている）。
   戻し方: `AppSettings` に 2 項目を足して `uiSettings` に保存し、設定の確定と読み込み時に
   `configureAutoSave` を呼ぶ（そのときは `handleWriteAppPrefs` の `applyAutoSaveConfig` と
   `restoreAutoSaveConfig` を外す）。
2. **「保存とバックアップ」は 3 つ目のタブにした**（§3 の表の 4 行目）。
   戻し方: `SettingsDialog.tsx` の `BackupTab` の中身を `AppTab` の末尾の節へ移し、タブを 2 つに戻す。
3. **ダイアログの［保存］でも「保存とバックアップ」の打ちかけを書く**（範囲外ならそのタブを
   開いて留まる）。戻し方: `saveAndClose` から `backup` の分岐を外す（［適用］だけが書く）。
4. **世代から開いた直後は「未保存」にしない**（読み込みと同じく clean）。元のファイルも世代も
   残っているので、閉じても失うものが無い。戻し方: `contextForRestoredBackup` の後で
   ストアの `projectDirty` を立てる（終了時に「保存しますか」が出るようになる）。
   **→ 手直しで、修復してから開いたときだけは未保存で始めるようにした（司令塔の決定。§11）。**
5. **一覧の行は押したら開く**（［開く］ボタンを挟まない）。未保存の確認で［キャンセル］を選んだら
   一覧へは戻らない。戻し方: `BackupListDialog` に選択状態と［開く］を足し、`openBackupCommand`
   で確認のキャンセル時に `choose` をもう一度呼ぶ。
6. **一覧の id は一覧を作るたびに振り直し、前の一覧の id は無効にする**（設定の「保存と
   バックアップ」が世代を数えるときも同じ口を呼ぶので、そのときも振り直される。両方の板が
   同時に開くことは無い）。戻し方: `handleListBackups` で表を差し替えずに足し込む。
   **→ 手直しで、設定の数は別の口（`countBackups`）にし、読み込みの確定・新規でも表を捨てる（§11）。**
7. **修復ダイアログは、どの行も最初の方法を選んだ状態から始める**（方法が複数ある行も）。
   U14 は「並びはおすすめ順で、先頭が既定」と定めている。戻し方: `RepairDialog` の初期値を
   `EMPTY_REPAIR_CHOICES` に戻す（そのときは方法が 1 つの行も初期値を入れないと押せなくなる）。
8. **修復ダイアログの冒頭の文を、挙動に合わせて直した**（「各項目の修復方法を選んでください」
   → 「それぞれの直し方を確かめてください」）。選ばない行ができたので前の文は事実と合わない。
   言い回しの総点検は 8E。戻し方: `REPAIR_STRINGS.intro` を戻す。
9. **機械向けの符号は知っているものだけ日本語にし、知らない符号は出さない。** 名前の欄が
   空・ID と同じ地物は「名前のない地物 N 件」と数で言う。戻し方: `describeInconsistencyDetail` /
   `describeInconsistency` の写像を外し、`detail` と ID をそのまま出す。
   **→ 手直しで、読み込んだプロジェクトから名前を引いて 1 件ずつ呼ぶ形に改めた（§11）。**
10. **間隔は 1〜120 分、世代は 1〜100。** 設計書は範囲を定めていない。0 分（＝止める）は
    入れていない。戻し方: 契約の `AUTO_SAVE_INTERVAL_MINUTES_RANGE` / `BACKUP_GENERATIONS_RANGE`
    を変える（主プロセスの読み込みと画面の検証が同じ値を引く）。
    **→ 手直しで世代の下限を 2 にした（司令塔の決定。§11）。**

## 5. 所有者の裁定が要るもの

- **自動保存を止める（0 分）を選べるようにするか。** いまは 1〜120 分。止めたい人は 120 分に
  するしかない。
- **世代から開いた直後を「未保存」とみなすか**（§4 の 4）。いまは clean なので、開いて
  眺めて閉じても何も聞かれない。

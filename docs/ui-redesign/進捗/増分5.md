## 2. やったこと（4 コミット）

### 5a 固定行のシェル

- 行を固定高にした: **アプリバー 32 / オプションバー 40 / 主行 残り / 時刻レール 据え置き
  （201.2px）/ 状態行 28**。高さの真実源はシェルの CSS 変数 1 か所で、行そのものと中身の
  両方が同じ値を読む。
- `flex-wrap: nowrap` に統一し、入り切らないものは **窓幅だけで決まる畳み**（設計書 §B.4）で
  落とす。中心経度は 1180px 未満でつまみとプリセット、960px 未満で直接入力を落とす ――
  **どの段でも「いまの中心経度が読めて ◀▶ で動かせる」ことは残す。**
- アプリバーを 32px に収めるため、**深さ（＋個別フォーカスの 4 部品）・格子・測量の読み取り**を
  オプションバーの設定欄へ降ろした。測量はアプリバーに入口 1 個だけを残した。
- ポップオーバーの器を `shell/OptionPopover` の 1 つに寄せ、増分 4 の「表示 ▾」もそこを通した。
- 左のレールは 120 → 88px（設計書 §C.3）。

### 5b 鍵と道具 1 段（裁定 1）

- モードの 3 ボタンを廃し、**鍵 1 個（`mode-view` 据え置き）＋道具の 1 段**にした。
- 内部の `mode` は道具から導出する（`shell/tools.ts` の `modeForTool`）。導出は
  **ストアの `setActiveTool`** が通す ―― 道具を構える経路は 4 つあり、呼び出し側で
  `setMode` を並べる形にすると必ずどこかで忘れる（教訓 5.6）。
- **鍵が閉じているあいだは道具を構えられない。** 導出式が `view` を返すだけでは
  `activeTool` が入って道具のコントローラが立ち上がり、K-6 に抜け道ができる。
- 頂点ハンドルの条件を「編集モードのとき」から「**掴める道具のとき**」へ
  （`toolShowsVertexHandles`: 選ぶ・頂点・動かす）。
- **裁定 N-4(A) を実装**: 読むだけでも地図クリックで選べる。左ボタンはパンの割り当ての
  ままで、**動かさずに離したときだけ**選択として解決し直す（左ドラッグのパンを損なわない）。
  あわせて **HB5-4 を覆し**、選択解除（Escape）を `EDITING_COMMANDS` から外した。

### 5c 選択を捨てない・鍵盤の持ち主・Esc の階段

- `setActiveTool` の既定を反転（`docs/現状.md` B28 の解消）。地物の選択は残り、
  **頂点の選択だけ**が「頂点の道具から出るとき」に落ちる（設計書 §D.2）。
- `shortcutsSuspended` の 11 項目の OR を **`focusOwner` の 6 値**へ畳んだ
  （`shell/focus-owner.ts`）。あわせて 2 つ直した。
  - **手順のある 5 道具は「構えている」ではなく「下書きを持っている」ときだけ鍵盤を取る。**
    旧版は構えた瞬間から真で、確定して対象を離したあとも道具を外すまで戻らなかった。
  - **右クリックはダイアログのときだけ止める**（設計書 §D.4 / §I.3 の原則①）。
- Esc の階段（`shell/escape-ladder.ts`）: 大域の `edit.deselect` を「頂点 → 地物 → 道具」の
  1 段ずつに割った。**連打すれば必ず素の状態**。
- 鍵盤の持ち主を隠し観測 `app-focus-owner` に出した（T-2）。

### 5d 確定の列をオプションバーへ

- **探索で見つけた不具合を 1 件直した**（§7.1 の ①）: 重なり競合の板を閉じたあと、
  追加の道具が「下書きを持っている」と名乗り続けて Ctrl+Z が効かなかった。5c で
  手順のある 5 道具に入れた規則（**下書きを持っているときだけ**）を追加の道具にも通した。
- ナイフ・結合・所属変更・輪郭・穴あけの **確定／やめる**を確定欄 176px へ、
  **1 つ戻す／クリア／最上位へ／穴↔飛び地／格子吸着**を設定欄へ移した（`shell/useToolBarChrome`）。
  **testid は 1 つも変えていない**（T-1: 役割で維持。置き場が移っただけ）。
- 案内の文・断り文は **オプションバーの「次の一手」**が出す。`*-guide` / `*-message` は
  観測のミラー（`hidden`）として残した。
- 結果として **地図に重なる押せる DOM 部品は道具の入力ブリッジ 1 枚だけ**になった。
  `e2e/__bughunt__/scene-layout.ts` の「地図の上端・下端に避けるべき帯がある」という
  前提も空にした（この増分でそれが本当に無くなったので）。

## 7. 探索的バグ狩り（実データのコピー）

`e2e/__bughunt__/inc5-explore.spec.ts`（新規）。**実データのコピー**（教訓 5.48）で、
実装計画が名指しした 5 つを掃く。

1. 1 段の道具を**全部順に持ち替えて**、選択が消えないこと
2. どの道具でも **Esc を 4 回押せば素の状態**（道具も選択も空、鍵盤の持ち主は `map`）
3. **確定した直後の Ctrl+Z**（道具を外さずに）
4. **右クリックが道具中でも開く**
5. **ポップオーバーが地図のクリックを奪わない**（開閉の両方で 5×5 の格子走査）

最後に**正準ファイルのサイズと更新時刻**を突き合わせて、コピーしか触っていないことを確かめる。

### 12.2 A 群 — 入力の持ち主と下書きの保護

| # | 指摘 | 直したこと |
| --: | --- | --- |
| A1 | **地図の右クリックが作図中の下書きを黙って壊し、視点を飛ばす**（バグ狩り #1。重症度 4。実データで再現） | 5c で「右クリックはダイアログのときだけ止める」に直した結果、右クリックが **選択を昇格させる**ようになり、それを見張っていた追加の道具が下書きを捨てていた。直し方は「開かない」ではない（§I.3 の原則①）―― **開くが昇格しない**。判定は畳んだ持ち主の値ではなく **生の「下書きを持っているか」**を見る（素性入力中は持ち主が `text` になって下書きが隠れる）。3 点以上で確認板と右クリックメニューが同時に開く件も、これで消えた |
| A2 | **素性入力の局面で Escape が死ぬ**（バグ狩り #3） | 道具側は「文字の欄なら素通り」で降り、大域側は焦点の関門で落ちていた ―― **誰も受けていなかった**。Escape だけは道具が受ける形にし、欄が `data-pristine="true"`（打ちかけ無し）を名乗っていればそのまま「やめる」、打ちかけがあれば 1 度聞く。**利用者自身の Escape で出ている確認は、もう一度の Escape で「捨てる」**（旧版は「このままにする」だったので、押すたびに板が開いては閉じるだけで永久に素へ戻れなかった）。`AddPropertyForm` の名前欄・種別欄に `data-pristine` を名乗らせた（名乗りが無いと常に「打ちかけあり」に倒れる） |
| A3 | **3 点以上の下書きが道具の持ち替え・鍵の開閉で確認なしに捨てられる**（Fable / Opus / GPT の 3 者が一致） | 年・一覧の選択と同じ形にした（`setPendingDiscard({reason:'tool'\|'lock', keep})`）。「このままにする」で道具（と鍵）が元へ戻る。確認の板は **`role="alertdialog"` の本物のモーダル**として数える（バグ狩り #18）。板が出ているあいだは **地図を覆う入力層を外す**（鍵を閉じたのに地図クリックで頂点が置けては K-6 の抜け道になる）。捨てたときは見張りの基準を今へ合わせ直す（進めないと新しい道具のセッションが始まらない） |
| A4 | **鍵盤の持ち主の穴が 6 つ**（Opus ③ / GPT #3〜#6 / Fable F） | ①吸着 ▾ を共通の器（`shell/OptionPopover`）へ載せ替えて開閉を報せる ②標準メニューの開閉を報せ、Escape を **捕捉段**で受けて伝播を止める ③結合の選択板・継承先の板・新地物の素性入力・捨てる前の確認を、**「下書き」ではなく「モーダル」**として別に数える（下書きなら通してよい Ctrl+S が、確認の背後で走っていた） ④つまみ（`input[type=range]`）に焦点があるあいだ大域の打鍵を止める。**「文字を編集できるか」と「大域の打鍵を遮るか」は別の問い**なので述語も別にした ⑤`none`（まだ誰も持っていない）を地図が載る前に出す ⑥板が開いていて打鍵が止まったときは、**「Esc で板を閉じる」という次の一手つきで**理由を出す |
| A5 | **測量経由で内部の状態が壊れる**（Opus ① / Fable C / GPT #1） | 面を描いている最中に測量を入り切りすると「画面は選ぶ・内部は追加」になり、左クリックは追加の経路へ送られるのに受け手が居なかった。`activeTool` を書く場所は **`toolPatch()` 1 本**を通す形にし、`surveyEnable` と `setMode` も通した。不変条件「`mode` は `activeTool` から導いた値と必ず一致する」を、**ストアの操作 56 個を全部並べた表**で走査する（表に無い操作があれば落ちる） |

### 12.13 手直しの申し送り

- **800×600 でレールが縦に収まらない。** 道具 12 個は枠込み 32px でも 442px 必要で、
  その窓では 298.8px しかない。U-8 の下限（30px）を割らずに詰める道が無いので、いまは
  その窓だけ縦に送れる形にしてある。増分 6 で時刻レールが 112px になっても 388px なので
  依然として収まらない。**「800×600 を本当に支えるのか（支えるなら道具を畳むのか）」は
  所有者の裁定が要る。**
- **「手順 n/m」の書式が 5 つの `strings.ts` に同じ形で 5 本ある。** 段数は道具ごとに
  違うので写像表の重複ではないが、**書式そのもの**は `shell/strings.ts` に 1 本置くほうが
  筋がよい。文言をまとめて見直す増分 8E で寄せる。
- **`defaultColor` の prop が分ける・穴あけで死んだ。** 地図の板だったころから
  `AddPropertyForm` は自分の既定色を使っており、板を消した今は型に残るだけである。
  外すには合成ルートと単体の検査台も一緒に触るので、次に同じあたりを触るときに消す。
- **`onModalChange` は所属変更の最上位化の板だけが使っている**（分けるは継承先の板、
  穴あけは 0 個）。素性入力を右パネルへ移したので、そこはもうモーダルではない。
  **口は残してある** ―― 板を足したときに配線を忘れないため。
- **右クリックの中身は「見る」側の項目しか増やしていない。** 設計書 §I.3 の原則①は
  「道具を持っている間も開ける ―― 中身が変わるだけ」と言うが、**道具の局面に応じた項目**
  （「ここで確定」「この点を消す」）はまだ無い。増分 7 以降で足す。
- **GPT #13（右クリックと「どこへでも移動」の関門を実 UI で見ていない）は未対応。**
  `view-only-gate.test.tsx` の ④ は `composeContextMenu` 単体、⑭⑮ は

### 14.2 新しい教訓（開発ガイド §5 へ入れたもの）

| 節 | 何を足したか |
| --- | --- |
| **5.75** | **打鍵を止める関門は、打鍵ごとに書くと必ず 1 つ漏れる ―― 入口 1 か所で止める。** あわせて「**大域を止めた**」と「**道具を止めた**」は別だと明記した。状態行が「効かない」と言いながら効いているのがいちばん悪い壊れ方で、検出は **局面 × 打鍵の総当たり**と、**名乗りと実物の突き合わせ** |
| **5.76** | **器を空へ戻す仕組みを入れたら、押し込む側に「空にされたら押し直す」を持たせる。** 教訓 5.72（代で後片付けを守る）の裏側。持ち直した側は元の中身を知らないので、埋め直せるのは押し込んだ側だけである。購読口は**中身の購読とは別に持つ**（同一性で再レンダーを決める購読では「もともと空だった」場合に通知が飛ばない） |
| **5.77** | **共有の器へ押し込む条件は、自分の state ではなく「店の真実」で決める。** 5.76 を入れた瞬間に別の口から穴が開いた ―― 押し直すということは「降りかけている最中にも押し込む」ことで、そのとき押し込むのは **1 コミット古い自分の姿**である。実測で、分ける → 選ぶ の対象欄が一瞬「手順 1/4（選んでいません）」になり、その直後に自分の後片付けで空になって固まった。**後片付けも「代」ではなく「書いた人」で守る**（押し直すと代は新しくなるので、代では古さを判定できない）。4 つ（代で守る・代で押し直す・店の真実で押し込む・書いた人で片付ける）は**組でしか成立しない** |

## 2. 計画・設計書との食い違い（実物と違っていたこと）

1. **「配線だけで直る可能性がある」は、現物では成り立たなかった**（計画 §3 の冒頭と設計書 §F.1 の C1）。
   このリポジトリで「頂点を共有している」＝ **2 つの地物が同じ `VertexId` を参照している**
   （`editing/apply-proposal.ts` の `applySharePair` / `applyMovedVerticesToHistories`）。ところが
   追加の提案が持つ `AddSnapshot.sharedCandidateIds` は **本番の経路では誰も読んでいない助言データ**で、
   構築しているのはテストだけだった。つまりポートを渡しても、新しい地物は自前の新しい頂点を
   持つだけで、**あとで隣の角を動かしても追随しない**（V2 の合格条件 ② が満たされない）。
   **直し方**: 吸着先の頂点 id を `PlacedVertex.sharedVertexId` として運び、`buildGeometry` が
   **採番せずにその id を使い回す**。`src/domain/add/snap.ts` には手を入れていない（近接候補に
   頂点 id を足すのは UI 層の `AddProximityCandidate` 側で済ませた）。
2. **`add-undo` の置き場**。設計書 §C.4 の確定欄（176px）は［確定］［やめる］の 2 つで、
   ［1 つ戻す］の席が無い。3 つ並べると U-8 の下限（幅 60px 以上）で 176px に収まらないので、
   **設定欄の差し込みとして置いた**（testid は `add-undo` のまま。T-1 を守る）。打鍵 Ctrl+Z は
   従来どおり効く。
3. **`AddPropertyForm` はナイフ・穴あけとも共有している**。設計書は「独立した追加フォームを
   やめる」と書いているが、対象は**追加の道具**である。ナイフの非継承側／穴あけの新地物は
   引き続き地図の上のフォームで入力する（そちらを右パネルへ移すのは、道具の作り直しと
   同じ増分でまとめて扱うのが自然）。ただし **年代が 0 年固定だった欠陥は 3 つとも直した**
   （いま見ている年を継ぐ）。
4. **現状分析 §7.1 の「隣まで中央値 3.46px」は、既定ズームの値ではなかった**（§4）。

## 4. 吸着の許容値 3 案の比較（設計書 §N-6 の裁定材料）

計測: `scripts/measure-snap-tolerance.ts`（実データのコピー `derle-world-full-2026-08-16.gimoza`、
0 年、地物 775 件・頂点 70,268 個。地図セル 940×497 CSS px。乱数の種 20260904）。
**このスクリプトは読み取りしかせず、正準ファイルには一切触れていない**（開発ガイド §5.48）。

### 4.1 まず分かったこと — 「許容値は、どの頂点に付くかを変えない」

いちばん近い頂点は許容値を広げても同じ 1 個なので、**「狙った頂点が最近傍になる割合」は
許容値では 1% も動かない**。動かすのはズームだけである。

| 地物 | ズーム | 隣り合う頂点の距離（中央値） | 狙った頂点が最近傍になる割合（**全案で同じ**） |
| --- | --- | ---: | ---: |
| バアカ（601 頂点） | ×1（全体表示） | 0.44px | 20.0% |
| バアカ | ×4 | 1.75px | 58.5% |
| バアカ | ×16 | 7.00px | 98.9% |
| アルラーク国（1,706 頂点） | ×1 | 0.40px | 18.5% |
| アルラーク国 | ×4 | 1.60px | 53.3% |
| アルラーク国 | ×16 | 6.39px | 98.7% |

> **現状分析 §7.1 の「隣まで中央値 3.46px」は再現しなかった。** 既定ズームでは 0.40〜0.44px、
> ×4 で 1.6〜1.75px である。3.46px は **×8 前後の倍率**で測った値と一致する（0.44 × 8 ＝ 3.5）。
> 数字の出どころが違うだけで、結論（頂点が非常に密で、50px の中に何百個も入る）は変わらない。

**したがって「50px にすれば狙いが当たるようになる」は成り立たない。** 狙いを当てる手は
拡大であって、許容値ではない（V9 の頂点候補一覧＝増分 8A が本来の答え）。

### 4.2 許容値が実際に決めること — 「地図のどれだけが吸着に食われるか」

地図セルの中を無作為に押したとき、**その場所に点を置けず既存の頂点へ持っていかれる**割合。

| 案 | 許容 px | バアカ ×1 | バアカ ×4 | バアカ ×16 | アルラーク ×1 | アルラーク ×4 | アルラーク ×16 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **案A 12px 固定** | 12 | **36.6%** | **23.8%** | **15.1%** | **29.1%** | **30.9%** | **6.0%** |
| 案B 画面倍率連動（dPR 1.25） | 15 | 41.7% | 27.8% | 19.0% | 32.6% | 36.3% | 7.3% |
| 案B 画面倍率連動（dPR 2.0） | 24 | 53.8% | 38.3% | 29.7% | 40.6% | 49.5% | 11.7% |
| 案B' 地図の拡大率に連動（4.60 度固定） | 12 / 48 / 192 | 36.6% | 61.0% | **100.0%** | 29.1% | 71.5% | 56.6% |
| **案C 50px 維持（FR-31 の条文）** | 50 | **72.6%** | **62.5%** | **52.2%** | **53.9%** | **72.7%** | 24.0% |

参考（許容円に入る候補の数の中央値。琥珀の輪や候補一覧が意味を持つかの目安）:

| 案 | バアカ ×1 | バアカ ×4 | バアカ ×16 | アルラーク ×1 | アルラーク ×4 | アルラーク ×16 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 12px | 160.5 | 24.0 | 4.0 | 114.0 | 19.0 | 4.0 |
| 24px | 498.0 | 64.0 | 8.0 | 344.0 | 46.0 | 8.0 |
| 50px | 1,662.5 | 171.0 | 23.0 | 1,272.0 | 119.0 | 20.0 |

### 4.3 決めた既定値と、その理由

**既定 12px（案A）。設定で 1〜50px に変えられる**（`SnapSettings.tolerancePx`）。

1. **50px は地図の半分以上を食う**（52〜73%）。新しい形を描く作業で、押した場所に点が置けない
   確率が半分を超えるのは使い物にならない。しかも §4.1 のとおり、**その代償で得られるものが
   何も無い**（どの頂点に付くかは変わらない）。
2. **案B（画面倍率＝devicePixelRatio に連動）は、このリポジトリの HiDPI 規律と逆を向く。**
   `render/camera.ts` の `Viewport` は「**CSS ピクセルの寸法が世界⇔画面の変換を決め、
   devicePixelRatio は裏のバッファの倍率だけで、変換には入れない**」と定めている。つまり
   **CSS px は既に表示倍率で正規化された単位**であり、そこへ dPR を掛けると
   **高精細な画面ほど吸着が広くなる**（画面上の見た目の大きさが dPR 倍になる）。実測でも
   dPR 2.0 相当で覆われる面積が 12px の 1.4〜1.9 倍になった。採らない。
3. **案B'（地図の拡大率に連動）は論外。** ×16 で 192px になり、バアカでは地図の 100% が
   吸着に覆われた。「拡大したのに自由に描けなくなる」という逆立ちした挙動になる。
4. 12px は **画面上のハンドルの半径 5px** と **掴める距離 8px** の少し外側で、
   「ハンドルを狙って押したつもり」を拾える最小の値である。

**所有者への裁定材料**: §N-6 が聞いているのは「(1) 頂点だけで合格とみなしてよいか」である。
**この増分は (1) だけをやった**。(2)（隣の面の辺の途中に同じ頂点を挿入する）は画面に
灰色＋「まだ使えません」で置いてある。FR-31 の条文の 50px は既定から外したが、
**設定で 50 も選べる**ので条文には触れていない。

## 7. 新しい教訓（開発ガイド §5 へ入れたもの）

- **§5.56 `hidden` 属性は、クラスで `display` を書いた瞬間に効かなくなる。**
  吸着 ▾ のパネルに `display: flex` を書いたせいで、閉じているはずのパネルが画面左上に
  居座り、**一覧タブのクリックを奪った**。K-3 の E2E が「タブが押せない」で捕まえた。
- **§5.57 ファイルを書き換える道具の既定の改行で、生テキストを読む契約テストが落ちる。**
  この作業ツリーは LF と CRLF が混ざっており（`core.autocrlf=true`）、Python の既定の
  書き込みで LF のファイルが CRLF になると、`shell-layout.test.ts` の「CSS の規則が
  見つからない」で落ちる。**git の差分には現れない**ので原因が実装に見える。

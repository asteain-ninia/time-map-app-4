## 5. 設計書・計画との食い違い

1. **K-3 の機械検査の置き場所**。設計書 §B.4 は「**単体テスト**で `map-area` の `getBoundingClientRect()` が完全一致することを固定する」としているが、**jsdom はレイアウトを計算しないので矩形は常に 0 で、中身に関わらず一致して必ず通る**（§O の B-13 が旧案を却下したのと同じ失敗の型が、そのまま「jsdom で測る」にも当てはまる）。実寸の比較は E2E（`e2e/option-bar.spec.ts`）へ置き、CSS の宣言そのものは契約テスト（`src/ui/shell/shell-layout.test.ts`）が読む二段構えにした。教訓 §5.49 に残した。
2. **オプションバーの区画の `flex`**。設計書 §B.4 は「①と②の**全区画**に `flex: 0 0 <固定px>`」と書いているが、同じ設計書 §C.4 の表は「次の一手 1fr」「設定 可変」としていて自己矛盾している。固定幅は 道具名 112 / 対象 240 / 確定 176 の 3 区画に限り、伸縮する 2 区画は `min-width: 0` ＋ `overflow: hidden` で「中身が枠を押し広げられない」ようにした。K-3 が守りたいこと（地図がずれない）はこれで満たされる。
3. **状態行の「元に戻す」枠に操作名を出せない**。設計書 §C.8 / §O の B-24 は「元に戻せます: 南ケナ州の改名（Ctrl+Z）」まで出すとしているが、**いまの `Command.label` は画面に出せる語彙ではない**（ドメイン側は日本語、UI 側の 5 か所は内部の英語）。実機に「元に戻せます: edit」と出たので可否だけに留めた。詳細は現状.md B7。
4. **N-03 の「到達不能だった」は誤りだった**（2026-09-04 訂正）。初版は「モード切替が選択を捨てる（結合点 #6）ので素性欄に地物が出ず、削除ボタンが描かれない＝実アプリでは到達不能」と書いたが、**選択を捨てるのはモードを切り替えたときだけ**である。**表示専用のまま一覧から地物を選べば素性欄に地物が出て、削除ボタンは描かれる**（実データの探索でこの経路を実際に通った）。つまり N-03 は報告どおり実在した。増分 1 で権限の関門に通したのは正しい対応で、理由づけのほうが間違っていた。
5. **壊れた E2E の本数が見積りより多かった**。計画は「E2E 0〜3 ファイル」としていたが、実際は **12 ファイル**。原因は 1 つで、**シェルに行が増えて地図セルが縦に約 74px 縮んだ**こと（**オプションバー 40px ＋ アプリバーの折り返し 34px**。状態行は 28px のままで高さを変えていない）。探索用の spec は「地図セルの中心から固定 px」でクリック座標を作っており、地図に浮くツールの帯（下＝確定ボタンの列、上＝ツールのガイド）に当たって頂点が置けなくなった。`e2e/__bughunt__/scene-layout.ts` はまさにこの事故を**大声で落とす**ために作られていたので、設計どおりに機能した。

### 8.4 E2E の座標修正の方針（74px の増加にどう対応したか）

**何が起きたか**: 増分 1 でシェルに行が増え、地図セルが縦に **約 74px 縮んだ**
（**オプションバー 40px ＋ アプリバーの折り返し 34px**。状態行は 28px のままで、高さは
変えていない。初版は「状態行 22→28px ＋ 折り返し 31px」と書いていたが、内訳の配分が誤り
だった——合計 74px は変わらない）。実測の地図セルは
`{x:120, y:155.2, width:940, height:415.6}`。E2E の探索用 spec は「地図セルの中心から固定 px」で
クリック座標を作っていたので、**地図に浮くツールの帯**に当たって頂点が置けなくなった。帯は 2 つ:

- **下** = 確定ボタンの列（中心 ±270px、`y > 地図下端 - 100`）
- **上** = ツールのガイド帯（中心 ±250px、`y < 地図上端 + 48`。編集ツールを構えているときだけ）

**方針**: 数値を今の地図セルに合わせて当て直すのではなく、**箱から解く**形にする。以後の増分でも
シェルの高さは何度も変わる（増分 5 で個別フォーカスの 4 部品を降ろし、増分 6 で時刻レールを
112px にする）ので、固定 px を足さない。

- `e2e/__bughunt__/scene-layout.ts` に **`maxFeasibleHalf(box, opts)`** と
  **`fitHalf(box, requested, {min, ...})`** を足した。`fitHalf` は「要求した大きさ」と「その箱で
  成り立つ最大」の小さいほうを返し、**下限を割ったら落ちる**（黙って潰れた図形で探索を続けない）。
- `placeSquareScene` の中心の丸めを `Math.round` から **`snapInside`**（整数へ丸めても feasible 帯の
  内側に残る）に替えた。境界ちょうどに解が乗ったとき、丸めで 0.2px 帯へ食い込んで落ちていた。
- 図形どうしの**位相**（重なる／隣接する／入れ子／貫く）は必ず保つ。相似に縮めるときは各中心を
  独立に丸めず、共有辺の座標から左右の中心を導く。
- 本体 spec（`regression` / `knife-preview-north`）は箱の高さの比で座標を決めるようにした。

**この方針を次の増分でも使うこと。** シェルの高さを動かす変更をしたら、まず
`npx playwright test e2e/__bughunt__ e2e/__visual__` を回して `scene-layout` の悲鳴を聞く。

### 10.1 A 群 — 保存の安全（最優先。実機で再現済み）

保存が走る。

| # | 直したこと |
| --- | --- |
| A1 | **上書き確認をモーダルかつ排他にした。** 確認を出している間は 開く・新規・ドラッグ＆ドロップ・もう一度の保存・自動保存を全部止める（ラッチが取れなければ落とす）。単一スロットの `pendingOverwrite` に 2 枚目が入って 1 個目の約束が孤児になる経路も消えた。背景クリックを塞ぐ層 `.file-ops-backdrop` を敷いた（教訓 5.14） |
| A2 | **確認から戻ったら保存先の同一性を検査する。** 確認時の保存先と保存文脈の世代を控え、純粋な判定 `decideSaveAfterConfirm` で突き合わせる。食い違えば書かずに状態行へ「保存先が変わったので中止しました」を出す |
| A3 | **未保存警告の「保存して続行」も上書き確認を通す。** この枝だけが素通りしていた（開く／新規／D&D／×／Alt+F4／OS シャットダウンの 6 経路が通る）。あわせて警告の本文に「保存先: 〈フルパス〉」を出す |
| A4 | **自動保存**: (a) 上書き先を利用者が確認するまで本体ファイルに書かない（保存先が未確定でもネイティブの保存ダイアログを勝手に開かない）(b) 変更が無ければ書かない (c) 成功しても「直前の結果」を書き替えず「最終保存」枠だけ更新する（教訓 5.12）。書いていないことは状態行に「（自動保存は待機中）」として静かに出す |
| A5 | **保存の結末を種別にした**（`saved` / `cancelled` / `destination-changed` / `busy` / `write-failed`）。キャンセルは失敗ではなく中立（新しい色味 `STATUS_TONE.Neutral`）で出し、書き込み失敗は状態行に一本化して `window.alert` の二重通知をやめた |
| A6 | **保存完了の世代ガード。** 保存中に別のプロジェクトを開いたら、その保存の完了で最終保存時刻も「保存しました」も書かない（B を開いた直後に「B は今保存された」と読める表示が出ていた） |
| A7 | **「確認済み」の判定を intent ベースにした。** ネイティブの保存ダイアログを通ったかで決めるので、既に保存先があるプロジェクトからの「名前を付けて保存」も載る |
| A8 | **削除の確認を 3 経路で 1 つにした。** Delete キーと右クリックの「削除」は確認なしで即座に消し、画面にも何も出なかった。3 経路とも同じ `DeleteConfirmDialog`（対象の名前つき）を通し、状態行に「〈名前〉を削除しました」を出す。影響の一覧（道連れになる集約地物・昇格する子）の本格版は増分 7 |
| A9 | **取り消し・やり直し・外部差し替えで素性欄のフォームが同期するようにした。** 同期の鍵に「錨の中身の値の署名」を混ぜる。**Ctrl+Z のあとに再保存すると取り消したはずの名前が復活していた**（BH1-01） |

**誤った挙動を固定していたテストを 2 本直した**: `save-status.test.tsx` の「キャンセルで failure を

### 10.3 C 群 — K-6（読むだけ）

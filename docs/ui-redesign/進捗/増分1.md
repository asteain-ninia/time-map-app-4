## 5. 設計書・計画との食い違い

1. **K-3 の機械検査の置き場所**。設計書 §B.4 は「**単体テスト**で `map-area` の `getBoundingClientRect()` が完全一致することを固定する」としているが、**jsdom はレイアウトを計算しないので矩形は常に 0 で、中身に関わらず一致して必ず通る**（§O の B-13 が旧案を却下したのと同じ失敗の型が、そのまま「jsdom で測る」にも当てはまる）。実寸の比較は E2E（`e2e/option-bar.spec.ts`）へ置き、CSS の宣言そのものは契約テスト（`src/ui/shell/shell-layout.test.ts`）が読む二段構えにした。教訓 §5.49 に残した。
2. **オプションバーの区画の `flex`**。設計書 §B.4 は「①と②の**全区画**に `flex: 0 0 <固定px>`」と書いているが、同じ設計書 §C.4 の表は「次の一手 1fr」「設定 可変」としていて自己矛盾している。固定幅は 道具名 112 / 対象 240 / 確定 176 の 3 区画に限り、伸縮する 2 区画は `min-width: 0` ＋ `overflow: hidden` で「中身が枠を押し広げられない」ようにした。K-3 が守りたいこと（地図がずれない）はこれで満たされる。
3. **状態行の「元に戻す」枠に操作名を出せない**。設計書 §C.8 / §O の B-24 は「元に戻せます: 南ケナ州の改名（Ctrl+Z）」まで出すとしているが、**いまの `Command.label` は画面に出せる語彙ではない**（ドメイン側は日本語、UI 側の 5 か所は内部の英語）。実機に「元に戻せます: edit」と出たので可否だけに留めた。詳細は現状.md B7。
4. **N-03 は実アプリでは元々到達不能だった**。「表示専用でも地物を削除だけが押せる」と報告されていたが、モード切替が選択を捨てる（結合点 #6）ので素性欄に地物が出ず、削除ボタンが描かれない。欠陥は**部品の契約側**に実在し、設計書 §D.2 ★★（鍵を閉めても選択を保つ）が入った瞬間に押せるようになるところだった。先に塞いだ。
5. **壊れた E2E の本数が見積りより多かった**。計画は「E2E 0〜3 ファイル」としていたが、実際は **12 ファイル**。原因は 1 つで、**シェルに行が増えて地図セルが縦に約 74px 縮んだ**こと（オプションバー 40px ＋ 状態行 6px ＋ アプリバーの折り返し 31px）。探索用の spec は「地図セルの中心から固定 px」でクリック座標を作っており、地図に浮くツールの帯（下＝確定ボタンの列、上＝ツールのガイド）に当たって頂点が置けなくなった。`e2e/__bughunt__/scene-layout.ts` はまさにこの事故を**大声で落とす**ために作られていたので、設計どおりに機能した。

### 8.4 E2E の座標修正の方針（74px の増加にどう対応したか）

**何が起きたか**: 増分 1 でシェルに行が増え、地図セルが縦に **約 74px 縮んだ**
（オプションバー 40px ＋ 状態行 22→28px ＋ アプリバーの折り返し 31px）。実測の地図セルは
`{x:120, y:155.2, width:940, height:415.6}`。E2E の探索用 spec は「地図セルの中心から固定 px」で
クリック座標を作っていたので、**地図に浮くツールの帯**に当たって頂点が置けなくなった。帯は 2 つ:

- **下** = 確定ボタンの列（中心 ±270px、`y > 地図下端 - 100`）
- **上** = ツールのガイド帯（中心 ±250px、`y < 地図上端 + 48`。編集ツールを構えているときだけ）

**方針**: 数値を今の地図セルに合わせて当て直すのではなく、**箱から解く**形にする。以後の増分でも
シェルの高さは何度も変わる（増分 5 で個別フォーカスの 4 部品を降ろし、増分 6 で時刻レールを
112px にする）ので、固定 px を足さない。

- `e2e/__bughunt__/scene-layout.ts` に **`maxFeasibleHalf(box, opts)`** と
  **`fitHalf(box, requested, {min, ...})`** を足した。`fitHalf` は「要求した大きさ」と「その箱で
  成り立つ最大」の小さいほうを返し、**下限を割ったら落ちる**（黙って潰れた図形で探索を続けない）。
- `placeSquareScene` の中心の丸めを `Math.round` から **`snapInside`**（整数へ丸めても feasible 帯の
  内側に残る）に替えた。境界ちょうどに解が乗ったとき、丸めで 0.2px 帯へ食い込んで落ちていた。
- 図形どうしの**位相**（重なる／隣接する／入れ子／貫く）は必ず保つ。相似に縮めるときは各中心を
  独立に丸めず、共有辺の座標から左右の中心を導く。
- 本体 spec（`regression` / `knife-preview-north`）は箱の高さの比で座標を決めるようにした。

**この方針を次の増分でも使うこと。** シェルの高さを動かす変更をしたら、まず
`npx playwright test e2e/__bughunt__ e2e/__visual__` を回して `scene-layout` の悲鳴を聞く。

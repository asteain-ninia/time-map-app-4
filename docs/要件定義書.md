# time-map-app-4 要件定義書

本書は time-map-app-4（以下「本アプリ」）の要件を定義する。本書はクリーンルーム文書であり、いかなる既存実装・過去版・他プロダクトにも依存しない。記述する制約・方針はすべて本アプリ自身の要件として定義される。

本書は実装技術（プログラミング言語・フレームワーク・ライブラリ・保存ファイル形式・シリアライズ方式など）には踏み込まない。要件は「何を満たすべきか」を技術非依存で定義し、「どう実現するか」は設計・実装フェーズに委ねる。

---

## 1. 目的とスコープ

### 1.1 目的

本アプリは、歴史を時間軸に沿って網羅的に視覚化・追跡できるデスクトップツールを提供する。歴史的な出来事や勢力の変遷を地図上で管理し、特定の時間における世界の状態（地物の形状・属性・領域の階層関係・存在の有無）を再現・編集できることを中核的な存在意義とする。

利用者は、地図上に点・線・面の地理情報を配置し、それぞれの時間依存の状態を「歴史の錨」として定義することで、任意の時点における地図の姿を再構成できる。

### 1.2 スコープ

本アプリは、通信を必要とせず、オフライン環境で完結して動作するスタンドアロンのデスクトップアプリケーションである。すべての機能はローカル環境で完結し、外部サービスへの接続を前提としない。

スコープに含まれるもの:

- 地図（ベースマップ）の表示と差し替え、無限横スクロール、ズーム・パン・経度シフト
- 点情報・線情報・面情報（ポリゴン）の作成・編集・削除と、距離・長さ・面積の計算
- 面情報の親子関係によるツリー型階層管理（末端地物・集約地物）
- 共有頂点システムと、末端地物同士の空間的排他性のリアルタイム維持
- 歴史の錨による時間依存状態の定義と、時間軸に沿った状態の再現
- 分裂・穴あけ・所属変更・合体などのツリー位相変更操作
- 時間的・空間的整合性維持プロセスと競合解決
- アンドゥ・リドゥ、自動保存・バックアップ
- プロジェクトデータの保存・読み込みと整合性チェック
- 各種設定の編集

スコープに含まれないもの（将来実装。第7章を参照）:

- 独自歴（地球の暦と異なる暦法）のサポート
- UI 文言の差し替え（ユーザーローカライズ）
- セーブデータの後方/前方互換および版間マイグレーション（正式リリースまではスコープ外）

### 1.3 UI 言語方針

本アプリの UI 表示言語は日本語のみとする。英語をはじめとする既存言語への翻訳対応は予定しない。エラーメッセージも日本語で表示し、必要に応じて「開発者へ報告してください」の案内を付与する。（FR-152 を参照）

## 2. ユーザーと利用シーン

### 2.1 想定ユーザー

- **歴史創作者／世界観構築者**: 架空世界の地理・政体・歴史を構築し、勢力の興亡や領域の変遷を時間軸に沿って記録・可視化したい利用者。
- **歴史研究者・教育者・愛好家**: 現実の歴史における国家・領域・出来事の変遷を地図上で整理し、特定時点の世界の状態を確認・提示したい利用者。
- **地図・地理データ作成者**: 点・線・面の地理情報を厳密な空間制約（重なりの禁止、領域の階層的包含）のもとで管理したい利用者。

### 2.2 主な利用シーン

1. **新規プロジェクトの開始**: プリセット地図（出界図）を背景に、点・線・面の地物を配置し始める。任意の地図ファイルをベースマップに差し替える場合もある。
2. **時間を指定した状態の構築**: タイムラインで時刻を選び、その時点の地物の形状・属性・所属を「歴史の錨」として定義する。
3. **歴史の変遷の編集**: 過去・未来の時刻へ移動し、領域の拡大・縮小、国家の分裂・統合、所属（上位領域）の変更などを記録する。
4. **整合性の維持**: 編集により末端地物同士が重なるなどの競合が生じた際、競合解決ダイアログで方針を選んで解消する。
5. **時間軸の走査**: タイムラインスライダーや再生機能で時間を移動し、地図全体の状態が即時に更新される様子を観察する。
6. **保存と回復**: 作成したプロジェクトを保存・読み込みし、自動バックアップにより不測のデータ破損から回復する。
7. **情報の参照と編集**: 地物を選択して属性やマークダウン形式の詳細文書を閲覧・編集する。

## 3. 機能要件

各要件に `FR-NN` 形式の ID と重要度（**must** / **should** / **could**）を付す。重要度の意味は以下のとおり。

- **must**: 本アプリが成立するために必須。
- **should**: 強く望まれるが、必須ではない。
- **could**: あれば望ましい付加価値。

### 3.1 全体方針

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-01 | must | 歴史を時間軸に沿って網羅的に視覚化・追跡できるツールを提供し、歴史的出来事や勢力の変遷を地図上で管理できるようにする。 |
| FR-02 | must | 通信を必要とせず、オフライン環境で完結して動作するスタンドアロンのデスクトップアプリケーションとして動作する。 |

### 3.2 ベースマップと地図表示

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-03 | must | 地図（ベースマップ）を表示し、プリセット地図（出界図）を同梱する。初回起動時・新規作成時・指定地図が読み込めない場合はプリセット地図を表示する。 |
| FR-04 | should | ユーザーが任意の地図ファイルをベースマップとして指定でき、出界図形式に適合しない場合は自動補正を試み、不可能ならエラー通知してプリセット地図にフォールバックする。指定した地図はプロジェクト内にコピー保存する。 |
| FR-05 | must | 地図の図法は正距円筒図法を前提とし、ユーザーが地図の赤道長（km 単位）と扁平率を入力できる。赤道長は距離・線長・面積の物理単位（km / km²）換算の基準として用いる。扁平率は大円距離（FR-14）など測地計算に用いる楕円体補正係数であり、扁平率を 0 とした場合は球面近似（赤道長基準）に一致する。赤道長・扁平率はプロジェクト固有設定（FR-109）として保持し、その変更は距離・面積・大円距離の算出と関連表示へ即時反映する。 |
| FR-06 | must | ベースマップはマウスイベントもテキスト選択も受け付けず、地物操作やパン操作を阻害しない。 |
| FR-07 | must | 横方向の無限スクロールを実現し、地図の東端・西端をまたぐ領域を表示・編集できる。 |
| FR-08 | must | ズームイン・ズームアウト・パン操作をサポートし、世界地図全体から都市内地図レベルまでの広範囲かつスムーズなズームを実現する。 |
| FR-09 | should | 表示モードでは左ボタンまたは中ボタンのドラッグでパン、追加・編集モードでは中ボタンドラッグでパンを行う。全モードでマウスホイールによりカーソル位置中心のズームを行う。 |
| FR-10 | should | ズームレベルを設定で一定範囲に制限できる。デフォルトは最小 1 倍～最大 50 倍、ユーザー設定可能範囲は最小 0.1 倍～最大 10000 倍とする。 |
| FR-11 | should | 起動時の初期表示は中心経度 0 度・中心緯度 0 度・地図全体が表示されるズームレベルとする。 |
| FR-12 | should | ユーザーがボタンやスライダーで地図の表示経度を左右にシフトでき（0度中心／180度中心の切替など）、シフト量はズームレベルに依存し、現在の中心経度を表示する。 |
| FR-13 | should | 10 度間隔を既定とする緯線・経線グリッドを表示し、赤道・0度経線・180度経線を強調表示する。グリッドの ON/OFF 切替、間隔（5/10/15/30 度）、色、不透明度を設定できる。緯度経度ラベルはズームに関わらず一定フォントサイズで表示する。 |

### 3.3 測量モード

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-14 | should | 測量モードを提供し、地図上で 2 点クリックするとその 2 点間の距離（正距円筒図法に基づく距離と大円距離の両方）を計算して表示する。正距円筒距離・大円距離は FR-05 の赤道長を基準に算出し、大円距離はプロジェクト設定の扁平率（FR-05 / FR-109）を楕円体補正として適用する（扁平率 0 は球面近似）。世界端をまたぐ測定線は折り返して表示し分断しない。 |
| FR-15 | could | 測量線は測量モードを解除しても残り、明示的にクリアするまで表示される（保存はされない一時的なもの）。複数同時表示でき、クリアボタンを提供する。大円距離に基づく最短経路の線を描画する。 |
| FR-16 | could | クリックした地点の緯度経度を度分秒形式と十進形式の両方で表示し、一時的なマーカーを表示する。 |

### 3.4 地理情報の表示と地物の種類

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-17 | should | 点・線・面の地物の点の大きさ・線の太さ・名前ラベルは、ズームレベルに関わらず画面上の見た目のサイズが一定になるよう調整する。 |
| FR-18 | must | 点情報（都市・出来事など）を、単一頂点に紐づく位置・プロパティ（名前・説明・年代など）・視覚的表現（アイコン・色・サイズ）とともに表示・管理できる。 |
| FR-19 | must | 線情報（道路・交易路・鉄道など）を、複数頂点のパス・プロパティ・視覚的表現とともに表示・管理し、長さ（km 単位）を計算して表示する。線情報は国境線を表さない。 |
| FR-20 | must | 面情報（国家・領域など）を、閉じたパス（リング構造）で形状定義し、任意数の穴・飛び地およびそれらのネスト構造に対応する。プロパティ・視覚的表現とともに表示し、面積（km² 単位）を計算して表示する。 |

### 3.5 面情報の穴・飛び地・リング構造

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-21 | must | 飛び地は人工的な線で繋がず分離して描画し、すべてのレベルの面情報で飛び地をサポートする。選択・ハイライト等の一時的な視覚効果でも穴領域は常に透過、飛び地は本土同様に独立領域として表示し、恒常表示と異なる輪郭・塗り分けをしない。 |
| FR-22 | must | 面情報に穴（内部の除外領域）や飛び地（同一面情報に属する別外周）を追加・編集・削除できる。穴/飛び地追加ツールは最初のクリック位置（面の内部か外部か）に応じて穴作成モード／飛び地作成モードを自動判定し、最低 3 点で領域を作成する。 |
| FR-23 | must | 穴/飛び地の追加は単一面情報の形状編集であり、新しい独立した面情報を生成しない（くり抜いて新地物を作る場合は穴あけによる新地物生成機能を使う）。 |
| FR-24 | must | リング階層は常に「領土リング→穴リング→領土リング→…」と交互になる不変条件を維持し、穴/飛び地の削除時はこの交互構造を保つよう再編（穴削除時・領土削除時それぞれの子リング付け替え）を行う。これらの削除と再編は単一の編集操作としてアンドゥ／リドゥで完全復元できる。 |
| FR-25 | must | 穴/飛び地の編集時、穴リングは親リング内部に完全包含され境界が交差しない、同じ親を持つ兄弟リング同士が交差しない、飛び地は他の外周リングと重ならない、という制約をリアルタイムに検証する。 |

### 3.6 末端地物の排他性

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-26 | must | 末端地物（形状を持ち下位領域を持たない面情報）同士は地図全体において決して重ならない（境界の接触は重なりに含めない）。これはドメインの基本ルールである。 |
| FR-27 | must | 排他検証は末端地物同士のみを対象とし、集約地物（下位領域を持つ面情報）には直接の排他制約を課さない。検証アルゴリズムは末端地物同士のペア検証のみを行い、集約地物を検証対象から除外する。 |
| FR-28 | must | 末端地物の頂点編集（移動・形状変更）時、他の末端地物の内部へ頂点をドラッグしようとするとエッジで阻まれ、エッジに沿って滑る動作を行う。滑っている境界は視覚的にハイライトし、エッジ間衝突判定により尖った部分を飛び越える動きでも重なりを発生させない。 |
| FR-29 | must | 末端地物追加時（頂点配置中）に他の末端地物の内部には頂点を設置できない。線情報・点情報は面情報と重なってよく、線・点に排他性はない。 |

### 3.7 共有頂点システム

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-30 | must | 複数の面情報や線情報が同じ頂点を共有して境界を連動させる共有頂点システムを提供する。共有頂点は視覚的に通常頂点と区別し、共有頂点をドラッグするとそれを共有する全形状が連動して変化する。 |
| FR-31 | should | 頂点を画面上（スクリーン座標）の距離で他の頂点に近づけると共有頂点化候補になり、近接判定はズームレベルに応じて変化する。デフォルトのスナップ距離は 50px で設定変更可能。スナップされただけで離すと共有頂点化されず通常移動になる。 |
| FR-32 | must | 共有頂点化の参加制限として、同一リング内の頂点同士・同一線形内の頂点同士を同じ共有頂点グループに含めない。共有化や共有頂点移動の結果、ゼロ長エッジ・自己交差・穴飛び地階層の破綻・末端地物同士の重なりが生じる場合は操作を禁止する。 |
| FR-33 | should | 共有頂点にコンテキストメニューから「共有解除」を提供し、解除直後の頂点が即座に再共有化されないよう、ドラッグ開始直後の自動共有化を抑制する（一度スナップ距離外へ離れると抑制が解除される）。 |

### 3.8 面情報の階層構造（ツリーモデル）

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-34 | must | 面情報を親子関係によるツリー構造（複数ルートを持つ森構造）で階層管理する。地物の階層・重ね順はすべて地物自身の親子関係（および派生値である階層深度）から導出し、地物とは独立した順序属性や全体共通の重ね順序は持たない。各ルートは最上位フラグが真で上位領域を持たない。 |
| FR-35 | must | 集約地物は形状属性を保持せず、形状は下位領域の和集合として実行時に算出される。集約地物は直接追加できず、下位領域の追加と所属変更を組み合わせて構成する。集約地物が全下位領域を失うとその時刻以降自動的に消滅する。 |
| FR-36 | must | 末端地物が所属変更フローで下位領域を獲得すると、その時刻から集約地物へ遷移する。元のプロパティ（名称・種別ラベル・属性）は新集約地物へ引き継ぎ、形状属性は破棄する。 |
| FR-37 | must | 末端地物→集約地物の遷移時、元形状と新下位領域の和に差分があれば、差分領域を「直轄領」末端地物として自動生成し新集約地物の下位領域に追加する（差分が空なら生成しない）。差分が地理的に分離する場合は 1 つの末端地物を複数領土リングで表現する。直轄領の既定名称は「<元名> 直轄領」でダイアログで上書き可能。 |
| FR-38 | must | 各面情報は派生値として階層深度を持つ（最上位は 0、子は親 +1）。階層深度は地物自身に保持せず常に親子関係から算出する。階層深度の最大値はツリーごとに異なってよい。 |
| FR-39 | must | 最上位フラグが真であることと上位領域を持たないことは同値で、不一致を許可しない。集約地物の形状はその全直接下位領域の和に厳密一致し内部に隙間を作らない。一方で地図全体としてはどの末端地物にも覆われない無主地を許容する。 |
| FR-40 | should | 各面情報は任意の種別ラベル（例: 国・州・郡・町・連邦）を持てる。種別ラベルは表示専用で整合性検証や階層整合性に関与せず、親が子の種別を強制しない（同一親の下に異種別の子を混在可）。 |
| FR-41 | must | 面情報の削除は、全時刻を通じてその地物への上位/下位領域参照を持つ他地物が存在しないか再編が許容される場合にのみ可能とする。集約地物が下位領域を全て失った場合は自動消滅する。 |

### 3.9 階層深度フォーカスと表示制御

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-42 | should | グローバル階層深度スライダーで全地物を「階層深度≤N」で集約表示でき、省略される階層の地物は自身の集約形状（下位領域の和）として描画する。表示モードの切替は編集・追加モードと干渉しない。 |
| FR-43 | could | 個別フォーカスとして、選択中地物の縦方向に繋がる領域（上位領域すべて・自身・下位領域すべて）だけを別の深度で深掘り表示・強調表示でき、グローバル深度スライダーと併存する。 |

### 3.10 ツリー位相を変える操作（分裂・穴あけ・所属変更・合体）

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-44 | must | 分裂機能として、末端地物をナイフツールで二分割できる。ユーザーがプロパティ引き継ぎ先を指定し、選ばれた側は元の同一性を保ったまま形状変化として続き、もう片方は新規末端地物として生成される。集約地物は直接分割できない。分割後の各末端地物は最低 3 頂点で有効なポリゴンを形成する必要がある。 |
| FR-45 | must | 穴あけによる新地物生成として、末端地物内部に指定した領域を新しい独立した末端地物として生成し、元の末端地物には対応する穴を形成する。新規地物の上位領域は元末端地物の上位領域を初期継承する。 |
| FR-46 | must | 所属変更フローを単一フローとして提供し、割譲・連邦化・独立・帰属・直轄化・自治化など、ツリー位相を変えるあらゆる操作を表現する（操作種別ごとに別 UI を設けない）。新しい上位領域は「既存の面情報から選ぶ」「新規上位領域を作成する」「親なし（最上位領域へ）」から選ぶ。 |
| FR-47 | should | 新規上位領域作成サブフローで、新規上位領域の名称・種別ラベルを入力し、末端で既存最上位を選ぶか新規最上位を作成でき、再帰的に上位領域を積み上げて中間階層を後付け挿入できる。 |
| FR-48 | must | 所属変更の親候補は循環参照を生まないこと（対象地物自身および対象の下位領域すべてに含まれないこと、ただし対象の上位領域は直轄化のため候補に含む）と、存在期間において親領域=下位領域の和を将来満たせる位置にあることを満たす。直接の所属変更は末端地物に限り、集約地物は全下位領域を対象に行う。 |
| FR-49 | should | 飛び地化を許容し、下位領域は地理的に陸続きでない上位領域にも所属できる。この場合、上位領域の形状は分離した全下位領域を包含する複数の独立リングとして導出される。 |
| FR-50 | must | 合体（結合）機能として、複数の面情報を特定の時間に 1 つの結果地物へ統合できる。対象は末端地物・集約地物・両者混在のいずれでもよい。結果地物は新規生成され、結合の主体の同一性は終了する。 |
| FR-51 | must | 結合は対象種別ごとに処理が異なる。末端地物のみ→形状の論理和で 1 つの末端地物（隣接しない場合は飛び地を持つ単一末端地物）。集約地物のみ→直接下位領域を平坦化統合した 1 つの集約地物。末端と集約の混在→集約地物の下位領域に末端地物を加えた 1 つの集約地物（末端地物は同一性を保ち下位領域として継続）。 |
| FR-52 | must | 結合の共通フローとして、結合後の地物の上位領域（既存いずれか／新規作成／最上位）とプロパティ（いずれか引き継ぎ／新規入力）を決定するダイアログを表示する。結合対象は 2 つ以上選択し、対象時間に存在し、互いに上位・下位関係にないことを操作開始前と確定前の両方で検証して違反時は拒否・通知する。 |
| FR-53 | should | 歴史上の特殊な統治形態（連邦・連合、二重君主国、同君連合、共同統治領、占領地、係争地）を、面情報は同一時点で高々 1 つの上位領域に属するというツリー制約を保ったまま、別エンティティ化・属性情報・時間付き所属切替で表現する。専用 UI や専用エンティティ種別は設けない。 |

### 3.11 歴史の錨と時間モデル

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-54 | must | 地物の経時的状態を「歴史の錨」（特定時刻における完全な状態スナップショット: 形状・属性・親子関係・存在状態）で定義する。最初の錨の開始時刻が存在開始、最後の錨に終了時刻を設定すると以降は非存在とする。 |
| FR-55 | must | ある錨で定義された状態は、その開始時刻から同一地物の次の錨の開始時刻直前まで継続する。過去の錨の編集は当該時刻以降に影響するが、未来側の錨の内容を自動的に書き換えず、未来の錨の開始時刻で伝播が遮断される。 |
| FR-56 | must | 同一地物の錨列は開始時刻の昇順で管理し時間的重複を禁止する。錨同士が連続しない非存在期間（時間的飛び地）を許可する。 |
| FR-57 | must | 過去編集時、編集基準時刻は現在選択時刻とする。同時刻の錨があればそれを更新し、なければ編集時刻を開始時刻とする新しい錨を追加する（初期値は編集時刻で有効な錨を引き継ぐ）。 |
| FR-58 | must | ユーザーは選択中の錨の開始時刻・終了時刻を変更でき、時間重複が生じる場合はシステムが錨列を自動再編（分割・短縮・削除）して重複を解消する。再編後は開始時刻昇順・重複なし・各錨の有効期間が正、を満たし、錨列が 0 件になる結果は許可しない。終了時刻は開始時刻より後で、次の未来錨の開始時刻まで（またはそれ以前）かつ次の未来錨の終了時刻より後にはできない。 |
| FR-59 | must | 属性のみの編集でも内部では当該錨の完全状態（形状・属性・所属・親子関係）を一体として扱い、これらの編集は単一の編集案として扱い部分的な確定を許可しない。 |
| FR-60 | could | 歴史の錨の表示を「時間バー表示」（非存在期間を空白として表示し、表示領域の上端/下端時刻を動的表示、ホイールでズーム可能で錨名称ラベルは画面占有率に基づき表示可否判定）と「リスト表示」の二種類で切り替えられる。 |

### 3.12 整合性維持プロセスと競合解決

| ID | 重要度 | 要件 |
|----|--------|------|
| FR-61 | must | ユーザーが錨を追加または編集して確定しようとした際、固定順序（編集案生成→錨の時間整合性検証→空間競合検出→競合解決ダイアログ→解決適用と一括確定）で時間的・空間的整合性維持プロセスを実行する。 |
| FR-62 | must | 空間的オーバーラップ（地図全体の末端地物同士の重なり）が検出された場合、専用の競合解決モーダルダイアログを表示し、編集確定を一時停止する。検出された全競合箇所（作中時間/時間範囲・関連地物名・競合種類）をリスト表示する。 |
| FR-63 | must | ユーザーは各競合箇所をミニマップでのプレビューを参考に解決方針（どちらの地物を優先し、もう一方をブーリアン演算で差分調整するか）を選択する。全競合に方針を指定するまで編集は確定されず、適用後は単一のアンドゥ・リドゥ操作の対象とする。 |

### 3.15 アンドゥ・リドゥと履歴管理

## 4. ドメインモデル概念

本章は本アプリのドメインを技術非依存で定義する。これらは実装方式（データ構造・永続化形式・座標系の内部表現など）に依存しない概念モデルである。

### 4.1 地物

地理的オブジェクトの総称。**点情報**・**線情報**・**面情報**を含む。すべての地物は、その経時的状態を「歴史の錨」によって定義される。

- **点情報**: 単一頂点に紐づく地点を表す（都市・出来事など）。位置・プロパティ・視覚的表現を持つ。排他性を持たない。
- **線情報**: 複数頂点のパスで構成される線形オブジェクト（道路・交易路・鉄道など）。長さ（km）を計算する。国境線は表さず、排他性を持たない。
- **面情報（ポリゴン）**: 閉じたパス（リング構造）で形状を定義するオブジェクト（国家・領域など）。穴・飛び地・ネスト構造に対応し、面積（km²）を計算する。**末端地物**と**集約地物**に分かれる。

### 4.2 頂点・リング・共有頂点

- **頂点**: 地物の形状を定義する点。複数オブジェクトで共有されうる。
- **リング**: ポリゴンの形状（領土または穴）を定義する閉じた頂点配列。**領土リング**と**穴リング**があり、リング階層は常に「領土→穴→領土→…」と交互になる不変条件を持つ。
  - **領土リング**: ポリゴンの領土部分（最外周や飛び地の境界）を定義する。
  - **穴リング**: ポリゴン内部の除外領域を定義する。常に透過扱いで塗りを乗せない。
- **飛び地**: 地理的に分離しているが同じ面情報に属する独立した外周リング。人工的な線で繋がず分離して描画する。
- **ネスト**: リングが他のリングの内部に含まれる階層構造（例: 穴の中の飛び地）。
- **共有頂点**: 複数のオブジェクトで共有される頂点。ドラッグすると共有する全形状が連動する。スクリーン座標での近接スナップにより共有頂点化される。視覚的に通常頂点と区別する。同一リング内・同一線形内の頂点同士は同じ共有頂点グループに含めない。

### 4.3 末端地物・集約地物とツリー階層

面情報は親子関係によるツリー構造（複数ルートを持つ森構造）で階層管理される。階層・重ね順はあくまで地物自身の親子関係（および派生値である階層深度）から派生し、地物とは独立した順序属性や全体共通の重ね順序は持たない。

- **末端地物**: 形状を保持し下位領域を持たない面情報。地理上の実体を担う唯一の単位。**末端地物同士は地図全体において決して重ならない（排他）**。境界の接触は重なりに含めない。
- **集約地物**: 下位領域を持つ面情報。形状属性を保持せず、形状は全直接下位領域の和集合として実行時に算出される。全下位領域を失うとその時刻以降自動消滅する。
- **上位領域 / 下位領域**: ツリーで一段上の親領域が上位領域、一段下の子領域が下位領域。「祖先・子孫」のような単一語は用いず、時間軸の概念との混同を避ける。
- **階層深度**: 対象地物のツリー位置から派生する派生値。最上位（ルート）は 0、子は親の階層深度 +1。地物自身には保持せず常に親子関係から算出する。
- **最上位フラグ**: 真のとき面情報は親領域を持たないツリーのルートとなる。「最上位フラグが真」と「親領域が無い」は同値。
- **種別ラベル**: 面情報に任意で付ける表示用ラベル（例: 国・州・郡・町・連邦）。整合性検証や階層整合性には関与しない。
- **直轄領**: 末端地物→集約地物の遷移時に、元末端地物の形状と新下位領域の和の差分を補うため自動生成される末端地物。親領域=下位領域の和の厳密一致を維持する。既定名は「<元名> 直轄領」。
- **縦方向領域**: 対象地物の上位領域すべて＋自身＋下位領域すべての集合（最上位から末端まで縦方向に繋がる領域）。表示フォーカスの対象範囲として使う説明的概念。

**階層の不変条件**:

1. 「最上位フラグが真」と「上位領域を持たない」は同値で、不一致を許可しない。
2. 集約地物の形状はその全直接下位領域の和に厳密一致し、内部に隙間を作らない。
3. 一方で、地図全体としてはどの末端地物にも覆われない無主地を許容する。

### 4.4 歴史の錨と時間モデル（タイムライン）

- **時間点**: 特定の時点（年／月／日）。年を基本単位とし、月・日は任意の粒度。負の年数は紀元前として解釈・表示する。
- **歴史の錨（アンカー）**: ユーザーが特定の時間において明示的に定義した地物の完全な状態スナップショット（形状・属性・親子関係・存在状態）。ある錨で定義された状態は、その開始時刻から同一地物の次の錨の開始時刻直前まで継続する。過去の編集は当該時刻以降に影響するが、未来の錨自体を自動変更しない。
- **プロパティ（状態スナップショット）**: 特定の時間から有効になる地物の完全な状態スナップショット。形状・属性・親子関係などを含み、歴史の錨として機能する。
- **時間的飛び地（非存在期間）**: ある錨の終了時刻から次の錨の開始時刻までの、地物が存在しない空白期間。地物の消滅と復活を表現する。
- **暦設定**: 時間計算の基礎となる暦法。初期実装はグレゴリオ暦を前提とし、年間日数等に基づき時間操作を換算する。

時間表現は内部で一貫した基準に正規化して処理し、すべての時間比較・期間計算・状態継続判定は正規化表現に基づいて行う。UI では年のみ・年月・年月日の各精度で表示・編集できる。タイムラインは表示対象時間を変更する主要インターフェースであり、時間移動に応じてメインマップ上の全地物の状態が即時更新される。

### 4.5 整合性と編集操作の概念

- **競合**: ユーザーの編集操作の結果、時間的・空間的な不整合が発生する状態。主に末端地物同士の空間的オーバーラップ。
- **衝突判定**: 複数のポリゴン間の重なりを検出する処理。
- **競合解決プロセス**: 競合が検出された際に起動される、ユーザーが解決方針（どちらの地物を優先しブーリアン演算で差分調整するか）を選択するための専用ダイアログと関連処理。
- **エッジ滑り**: 特定時間内の編集時、頂点が他のポリゴンのエッジに当たった際にエッジに沿って移動する動作。末端地物排他をリアルタイムに保つ。
- **データ整合性チェック**: データの参照整合性・内部矛盾などを検出・修復する処理。
- **所属変更フロー**: 面情報のツリー位相を変える操作。割譲・連邦化・独立・帰属・直轄化・自治化を単一フローに統合する。地物数を保ったまま親子関係を変更する（新規上位領域作成サブフローでは新地物が増える）。
- **合体（結合）**: 複数の面情報を特定の時間に 1 つの結果地物へまとめる操作。末端のみ／集約のみ（平坦化）／混在の 3 パターンがあり、結果地物は新規生成され、結合の主体が同一性を終了する。所属変更フローとは別物。
- **アクティブ地物**: ユーザーが地物本体を直接操作して明示的に選択した地物。常に 0 件または 1 件のみ保持される。
- **頂点選択セット / 頂点選択コンテキスト**: 選択中の頂点 ID の集合と、そこから一意に導かれる所有地物。プロパティ表示や補助ハイライトに使用する。

### 4.6 ベースマップ

地図表示の背景となる地図。プリセットの**出界図**を同梱し、正距円筒図法を前提とする。ユーザー指定の地図に差し替え可能で、適合しない場合は自動補正を試み、不可能ならプリセットにフォールバックする。

## 5. 非機能要件

実装技術・アルゴリズム・保存形式は固定せず、以下は達成すべき性能・品質目標として定義する。

### 5.1 性能

| 区分 | 目標 |
|------|------|
| ズーム/パン | 60FPS 以上を維持する。 |
| 選択・編集操作の応答 | 100ms 以内とする。 |
| データロード時間 | ある程度長くてよい（即応性は要求しない）。 |
| 整合性維持プロセス（競合検出・解決） | 計算時間は競合数に応じて変動するが、ユーザーが許容できる範囲（数秒〜数十秒以内）に抑える努力をする。 |

描画・検索の高速化のため、空間インデックス・視野外クリッピング・LOD・描画バッチ処理・高頻度イベントのスロットリング・重い計算の分離などの最適化を行う。具体的なアルゴリズム・実装手法は設計・技術選定に委ね、上記性能目標の達成手段として扱う。

### 5.2 データ規模

- 大規模データ（**5,000 オブジェクト規模、各オブジェクトが平均 10 個の歴史の錨を持つ程度**）でも操作性を維持する。これがデータ規模の目安となる。
- メモリ使用量は**最大 2GB 以内**に抑え、メモリリーク防止対策を実施する。大規模データでは必要に応じた動的読み込み等で効率的に管理する。
- ディスク使用量を管理する（自動バックアップの世代管理=最大 10 世代、保存ファイルの最適化、一時ファイルの適切な管理と削除）。

### 5.3 保存の意図と安全性

- 保存／読込自体は必須機能だが、保存形式（コンテナ形式・シリアライズ形式・拡張子など）は固定せず、設計・技術選定フェーズで選定する。要件としては**保存内容の論理的な完全性**（全地物・全錨・親子関係・最上位フラグ・種別ラベル・設定・ベースマップ）のみを定める。
- 保存形式には**バージョン情報を持つ**こと、読み込み時にバージョンの妥当性を検証し非互換ファイルは警告・拒否すること自体は必要。
- 保存・自動保存はデータ破損を防止する安全な保存メカニズム（バックアップ作成を伴う）で行う。
- 可用性として、設定可能な間隔（デフォルト 5 分）での自動保存を提供し、データ破損時に回復できるバックアップ機構を備える。

#### セーブデータの互換・マイグレーションについて

**セーブデータの後方/前方互換、および版間のデータマイグレーションは正式リリースまでスコープ外とする。** 保存形式にバージョン情報を持ち、読み込み時に妥当性を検証して非互換ファイルを警告・拒否すること自体は必要だが、旧バージョン形式の読み込み互換やマイグレーション機構は作り込まない（旧モデルのファイルは互換性なしとして拒否してよい）。正式リリースに向けては対応が必要となる領域として将来実装（第 7 章）に位置づける。

### 5.4 拡張性

新たなオブジェクトタイプの追加やカスタム属性の定義・管理を容易にする設計とする。プラグイン機構・API フックポイントは将来的な拡張余地として位置づける。

### 5.5 セキュリティ

すべてのユーザー入力のバリデーション・無害化、および外部から読み込むデータの検証・サニタイズを行う。

### 5.6 エラー処理・可用性

すべての例外を適切に捕捉・処理し、ユーザーフレンドリーな日本語エラーメッセージを表示し、エラーログの記録と診断情報を提供する。

### 5.7 言語

UI の表示言語は日本語のみとし、エラーメッセージも日本語で表示する。

### 5.8 テスト容易性

- ドメインの不変条件（末端地物の排他性、リング階層の交互性、集約地物の形状=下位領域の和、最上位フラグと親無しの同値、錨列の昇順・非重複）を機械的に検証できる形で定義し、検証ロジックをテスト可能な単位に分離する。
- 整合性維持プロセス・競合検出・エッジ滑り・所属変更・分割・結合などの複合操作は、入力状態と期待される結果状態を明示できる単位に分け、再現可能なテストとして記述できるようにする。
- 時間計算（正規化・期間判定・状態継続）は副作用のない純粋なロジックとして分離し、境界条件（紀元前、錨境界、非存在期間）を網羅的にテストできるようにする。
- 性能目標（60FPS、応答 100ms、メモリ 2GB、データ規模 5,000 オブジェクト×平均 10 錨）は、計測可能な指標として扱い、検証手段を設ける。

## 6. 用語集

| 用語 | 定義 |
|------|------|
| 地物 | 地理的オブジェクトの総称。点情報・線情報・面情報を含む。経時的状態は歴史の錨によって定義される。 |
| 点情報 | 単一地点を表す地理情報オブジェクト（都市・出来事など）。排他性を持たない。 |
| 線情報 | 複数頂点のパスで構成される線形地理情報オブジェクト。長さ（km）を計算する。国境線は表さず、排他性も持たない。 |
| 面情報（ポリゴン） | 閉じたパス（リング構造）で形状を定義する地理情報オブジェクト。穴・飛び地・ネストに対応し面積（km²）を計算する。末端地物と集約地物に分かれる。 |
| 頂点 | 地理オブジェクトの形状を定義する点。共有頂点として複数オブジェクトで共有しうる。 |
| リング | ポリゴンの形状（領土または穴）を定義する閉じた頂点配列。階層は常に交互（領土→穴→領土→…）になる。 |
| 領土リング | ポリゴンの領土部分（最外周や飛び地の境界）を定義するリング。 |
| 穴リング | ポリゴン内部の除外領域を定義するリング。常に透過扱いで塗りを乗せない。 |
| 飛び地 | 地理的に分離しているが同じ面情報に属する独立した外周リング。人工的な線で繋がず分離して描画する。 |
| ネスト | リングが他のリングの内部に含まれる階層構造（例: 穴の中の飛び地）。 |
| 共有頂点 | 複数のオブジェクトで共有される頂点。ドラッグすると共有する全形状が連動する。 |
| 末端地物 | 形状を保持し下位領域を持たない面情報。地理上の実体を担う唯一の単位。末端地物同士は地図全体において重ならない。 |
| 集約地物 | 下位領域を持つ面情報。形状属性を保持せず、形状は下位領域の和集合として実行時に算出される。 |
| 上位領域 | 対象の面情報の親領域（ツリーで一段上の集約地物）。 |
| 下位領域 | 対象の面情報の子領域（ツリーで一段下の面情報）。 |
| 階層深度 | 対象地物のツリー位置から派生する派生値。最上位は 0、子は親 +1。地物自身には保持しない。 |
| 最上位フラグ | 真のとき面情報は親領域を持たないツリーのルートとなる。「最上位フラグが真」と「親領域が無い」は同値。 |
| 種別ラベル | 面情報に任意で付ける表示用ラベル（例: 国・州・郡・町・連邦）。整合性検証や階層整合性には関与しない。 |
| 直轄領 | 末端地物→集約地物の遷移時に、元末端地物の形状と新下位領域の和の差分を補うため自動生成される末端地物。デフォルト名は「<元名> 直轄領」。 |
| 縦方向領域 | 対象地物の上位領域すべて＋自身＋下位領域すべての集合。表示フォーカスの対象範囲として使う説明的概念。 |
| 時間点 | 特定の時点（年/月/日）。 |
| プロパティ | 特定の時間から有効になる地物の完全な状態スナップショット。形状・属性・親子関係などを含み、歴史の錨として機能する。 |
| 歴史の錨（アンカー） | ユーザーが特定の時間において明示的に定義した地物の状態。この錨から次の錨までは状態が継続する。過去の編集は未来の錨自体を自動変更しない。 |
| 時間的飛び地（非存在期間） | ある錨の終了時刻から次の錨の開始時刻までの、地物が存在しない空白期間。消滅と復活を表現する。 |
| 競合 | ユーザーの編集操作の結果、時間的・空間的な不整合が発生する状態。例: ポリゴンの空間的オーバーラップ。 |
| 競合解決プロセス | 競合が検出された際に起動される、ユーザーが解決方針を選択するための専用ダイアログと関連処理。 |
| 衝突判定 | 複数のポリゴン間の重なりを検出する処理。 |
| エッジ滑り | 頂点が他のポリゴンのエッジに当たった際に沿って移動する動作（特定時間内の編集時）。 |
| データ整合性チェック | データの参照整合性・内部矛盾などを検出・修復する処理。 |
| 暦設定 | 時間計算の基礎となる暦法。初期実装はグレゴリオ暦を前提とする。 |
| 独自歴 | ユーザーが設定した公転・自転周期などに基づく暦法（将来実装予定）。 |
| 所属変更フロー | 面情報のツリー位相を変える操作（割譲・連邦化・独立・帰属・直轄化・自治化を統合）。地物数を保ったまま親子関係を変更する（新規上位領域作成サブフローでは新地物が増える）。 |
| 新規上位領域作成サブフロー | 所属変更フローの選択肢の 1 つ。新規上位領域の名称・種別を入力し、再帰的に上位領域を積み上げ可能。 |
| 割譲 | 対象地物を別の既存上位領域へ移す所属変更フロー操作。新親候補は「既存の面情報から選ぶ」を選択する。 |
| 帰属 | 最上位フラグが真の地物を既存上位領域の下に移す所属変更フロー操作（割譲と同型）。 |
| 連邦化 | 複数の最上位面情報を選び、新規上位領域作成サブフローで新規最上位を作成して下位領域として束ねる所属変更フロー操作（例: 13 国の合衆国化）。 |
| 独立 | 対象地物を「親なし（最上位領域へ）」へ移し最上位フラグを真にする所属変更フロー操作。 |
| 直轄化 | 対象地物を中間集約地物を抜かして、より上位の上位領域へ移す所属変更フロー操作。 |
| 自治化 | 既存の下位領域とその上位領域の間に新規の中間集約地物を挿入する所属変更フロー操作（新規上位領域作成サブフローを使用）。 |
| 解体 | 集約地物配下の全下位領域を「親なし（最上位領域へ）」へ移し、元の集約地物を全下位領域消失で自動消滅させる所属変更フロー操作。 |
| 合体（結合） | 複数の面情報（末端地物・集約地物・混在いずれも）を特定の時間に 1 つの結果地物へまとめる操作。結果地物は新規生成され、結合の主体が同一性を終了する。所属変更フローとは別物。 |
| アクティブ地物 | ユーザーが直接操作するために明示的に選択した地物。常に 0 件または 1 件のみ保持される。 |
| 頂点選択コンテキスト | 頂点選択セットから一意に導かれる地物。プロパティ表示や補助ハイライトに使用する。 |
| ベースマップ（出界図） | 地図表示の背景となる地図。プリセットの出界図を同梱し、正距円筒図法を前提とする。ユーザー指定の地図に差し替え可能。 |

## 7. 将来実装したい機能

以下は本書のスコープ外であり、将来の実装候補として位置づける。

### 7.1 独自歴サポート

ユーザーが地球の暦とは異なる独自の暦法（1 年の日数・1 年の月数・各月の日数など）を設定でき、タイムラインの目盛り・ラベル・すべての時間関連入力/表示を独自歴に合わせて自動調整する。システム内部の時間情報も独自歴に対応可能な形式へ変更する。本書の時間モデル（FR-72 の正規化、FR-67/FR-70 の暦設定経由の時間計算）は、この拡張を見据えて暦設定に依存しない共通ロジックを経由する方針とする。

### 7.2 ユーザーローカライズ

UI 文言を差し替え可能にする仕組み（制作対象世界への没入支援として、架空言語表示などを想定）。ただし英語等の既存言語への翻訳は予定しない。

### 7.3 セーブデータの後方/前方互換および版間マイグレーション

正式リリースまではスコープ外だが、正式リリースに向けては対応が必要となる領域。保存形式のバージョン情報（FR-104）を基礎として、旧バージョン形式の読み込み互換やマイグレーション機構を将来導入する。

### 7.4 意図的に非目標とする UI 演出・操作

以下の UI 演出・操作は本書の**非目標**とする（意図的に対象外であり、実装漏れではない）。中核データ・能力は本編 FR に存置される（例: 世界名/概要は FR-109、地物情報閲覧はサイドバー+詳細パネル）ため、これらは機能の欠落ではなく体験/演出の簡素化・設計方針の帰結である。将来、必要と判断されれば実装候補となる。

- **世界名・概要の常時表示エリア**: 名称/説明は FR-109 の設定で保持・編集可能。メインマップ上への常時表示は行わず設定ダイアログでの確認に一本化。
- **成功/情報の一時トースト（数秒で自動消滅）**: 通知はエラー/警告/確認に限定（教訓: 判断用メッセージは明示的契機まで自動消滅させない）。成功/情報の非侵入トーストは非採用。
- **閲覧モードでのマップ直接クリック→詳細表示**: 情報閲覧はサイドバー一覧→プロパティ/詳細パネルで提供。閲覧モードのマップクリック選択は非採用（マップクリック選択は編集モードのみ）。
- **クリック位置付近へのフォーム/ウィンドウ表示**: 属性編集は固定サイドバー（FR-111）、詳細ウィンドウはドラッグ可能パネル（FR-99）。クリック座標近傍への自動配置は非採用。
- **レベル別（0〜4）関数トレースログ／ユーザー設定可能なログレベル**: ログは FR-117 のエラー/診断に限定。関数呼び出しトレースおよびログレベル設定 UI は非採用。
- **キーボードによる地図パン/全体表示（矢印パン・「0」キー全体表示）**: ズームは Ctrl+= / Ctrl+-、パンはドラッグで提供。矢印キーパン・全体表示への一発復帰キーは非採用（「全体表示へ戻す」コマンドは将来の低コスト改善候補）。
- **OS ファイル関連付け起動読込（.tmap ダブルクリックで開く）**: 読込は メニュー/ショートカット/ドラッグ&ドロップ（FR-105）に限定。OS 関連付け起動は配布パッケージ整備とセットで将来検討。
- **読み込みキャンセル時のフィードバック通知**: 「中止は静かに現状維持」を意図設計（保存/読込/修復のキャンセルは通知せず状態を変えない）。キャンセル成功通知は非採用。
- **サイドバー折りたたみ／選択時のプロパティタブ自動切替**: FR-111 の 3 タブ構成は維持。サイドバーの折りたたみと、地物選択時のタブ自動切替は非採用。
